多個頻道和獨立疊加畫面

在一個停駐面板中閱讀所有聊天，同時選擇每個觀眾疊加畫面顯示哪些平台。

所有指南 1. 在同一工作階段中合併擷取 2. 依平台拆分捲動聊天 3. 拆分選取的訊息 4. 同一平台上的兩個頻道 5. 驗證每個觀眾檢視 6. 在一個瀏覽器分頁中顯示聊天與提醒

1. 在同一工作階段中合併擷取

在 SSN 中新增需要的聊天來源，並確認各來源的一則新訊息都到達同一個未篩選的 直播聊天停駐面板。保留該停駐面板作為操作員檢視。

複製產生的連結以保留工作階段、密碼、版本與伺服器設定。將每個觀眾檢視新增為獨立的 OBS 瀏覽器來源。為 OBS 來源使用易於辨識的名稱，例如 Twitch 聊天 和 YouTube 聊天.

2. 依平台拆分捲動聊天

若要使用捲動聊天，將產生的下列連結複製兩份： dock.html URL。在各自副本後附加下列選項：

觀眾檢視 附加至其停駐面板 URL
Twitch 聊天 &onlyfrom=twitch&hidemenu
YouTube 聊天 &onlyfrom=youtube&hidemenu
Twitch 與 YouTube 合併顯示 &onlyfrom=twitch,youtube&hidemenu
除 Discord 之外的所有來源 &hidefrom=discord&hidemenu

例如，使用預設連線時：

https://socialstream.ninja/dock.html?session=YOUR_SESSION_ID&onlyfrom=twitch&hidemenu

使用 onlyfrom 和 hidefrom 適用於這些頁面。不要假定某個選項（例如 onlytype ）從其他疊加畫面拿來就能在此使用。請使用 youtubeshorts ，在擷取回報該類型時單獨新增。參閱 來源類型.

3. 拆分選取的訊息

若要使用選取的聊天而非捲動聊天，請複製產生的 featured.html 連結，並新增 &onlyfrom=twitch 至一個副本，並新增 &onlyfrom=youtube 至另一個副本。保持操作員停駐面板開啟以選取訊息。

目前精選聊天的 onlyfrom 接受一個來源類型。請勿將上方停駐面板的逗號分隔範例複製至精選聊天的該欄位中。

這會篩選精選頁面接受哪些選取。它不會建立獨立的操作員佇列，且被拒絕的選取不等於清除命令。切換環節時請明確清除精選訊息，以免先前接受的訊息繼續顯示。

4. 同一平台上的兩個頻道

onlyfrom=twitch 選擇的是 Twitch 平台，而非某個特定 Twitch 頻道。頻道名稱與直播標題是中繼資料，不能直接作為 URL 篩選器名稱互換使用。新增 &showchannelname 以顯示來源提供的頻道名稱。

若要使用進階停駐面板篩選， &filtertid=123 接受來源分頁的數字 ID；支援逗號分隔的多個 ID。檢查實際擷取的承載資料以取得其 tid （參見 事件參考 和 指令與 API）。請勿在此使用平台頻道 ID。來源重新開啟時，分頁 ID 可能改變，沒有符合分頁 ID 的來源可能被排除。這是停駐面板選項，並非精選聊天的通用頻道篩選器。

若要完全獨立製作，請使用具有不同工作階段的獨立擷取執行個體／設定檔，並且僅在其中開啟該製作需要的來源。僅為某個疊加畫面設定不同工作階段卻沒有相符的擷取，會使其處於閒置狀態。疊加畫面的 label 用於識別頁面以進行路由；它不是頻道篩選器。

5. 驗證每個觀眾檢視

  1. 使用下列功能向隔離工作階段傳送一則虛構 Twitch 測試訊息與一則虛構 YouTube 測試訊息： 建立測試訊息.
  2. 確認兩者都出現在操作員停駐面板中，且每個捲動疊加畫面只顯示預期來源。
  3. 逐一精選各則訊息並測試清除按鈕。切換平台後檢查所有可見的精選頁面。
  4. 使用您自己連接的每個來源中的真實訊息重複測試，因為合成訊息無法確定實際的來源分頁 ID。

如果檢視空白，請暫時移除篩選器。如果聊天恢復，請檢查確切的來源類型或分頁 ID。如果仍為空白，請使用 工作階段與路由疑難排解。變更 OBS 來源名稱不會更新其儲存的 URL。

6. 在一個瀏覽器分頁中顯示聊天與提醒

使用 合併疊加畫面 ，在一個分頁或一個 OBS 瀏覽器來源中疊合現有疊加畫面 URL。這適合在戶外直播時用手機閱讀聊天。

  1. 將產生的直播聊天停駐面板 URL 貼至底層，並將多平台直播提醒框 URL 貼至頂層。保留兩個連結中的工作階段、密碼與連線選項。
  2. 將 透明 SSN 背景 保持為勾選狀態。為聊天啟用「允許在此圖層上點按與捲動」，為提醒停用此選項，以免提醒阻擋聊天互動。
  3. 選擇 預覽，然後 顯示 QR 碼 並用手機相機掃描。或選擇 複製組合連結 以將結果貼至瀏覽器來源中。組合檢視沒有設定控制項。

最多可新增八個 URL，並使用箭頭按鈕將圖層移至其他圖層的後面或前面。預設情況下，圖層填滿瀏覽器。展開 尺寸與位置 ，以像素設定該圖層的寬度、高度、左側偏移量與頂端偏移量（例如 450）或百分比（例如 100%）。寬度與高度留空時會填滿瀏覽器；偏移量留空時從左上角開始。 重設為全螢幕 會清除該圖層的位置設定。各疊加畫面保留自身內容與設定。

若要在 1920×1080 的 OBS 瀏覽器來源中設定左側聊天欄，請將聊天圖層寬度設為 450，高度設為 1080，左側偏移量設為 0，頂端偏移量設為 0。其他圖層可保持全螢幕。如需將 Hype 放在聊天上方，並將精選聊天向右移，請使用 下方的 OBS 配置方案。瀏覽器尺寸改變時，像素尺寸保持固定；百分比隨瀏覽器寬度或高度變化。

使用可編輯連結重新開啟設定，其中會填入您的 URL 與位置。若要稍後編輯組合連結，請新增 ?edit=1 ，位置在其下列部分之前： #.

您的連結與圖層選項會自動儲存在此瀏覽器中，包括尚未完成的設定。重新開啟 合併疊加畫面 以繼續編輯，或選擇 清除已儲存的設定 以重新開始。在私密瀏覽中，瀏覽器儲存空間可能無法使用或僅暫時存在。

組合連結與 QR 碼包含完整配置與 URL。在桌面端設定，在手機上掃描一次，然後將組合檢視加入書籤。開啟它也會將該設定儲存在手機瀏覽器中。桌面端變更不會自動更新舊連結：編輯後需複製或掃描新連結。此功能不會透過工作階段 ID 同步設定。

請像保護各個疊加畫面連結一樣保護組合連結與 QR 碼。SSN 擷取仍須執行，且手機必須能連線至原始 URL 使用的伺服器。 localhost 或 127.0.0.1 位址指向開啟連結的裝置。過長的 URL 可能超出 QR 碼容量，但仍可複製組合連結。

OBS 方案：左側聊天欄搭配全螢幕效果

此配置不需要 CSS。 每個圖層都有自己的瀏覽器區域。將整個 OBS 瀏覽器來源設為 1920×1080，然後在各圖層的下列設定中使用這些值： 尺寸與位置。僅輸入數字，不要輸入逗號或「px」。依照下列順序新增圖層，從底層開始：

圖層寬度高度左側偏移頂端偏移
1. 即時聊天／停駐面板4501000080
2. Hype 計數器4508000
3. Emoji／表情牆1920108000
4. 精選聊天147010804500
5. NinjaBacker（選用）1920108000

頂端 80 像素保留給 Hype，下方保留寬 450 像素的聊天欄。若希望聊天在 Hype 後方占滿整個高度，請將即時聊天的高度設為 1080 ，頂端偏移量設為 0。其他場景尺寸需要不同的像素值。

  1. 貼上完整的疊加畫面 URL。 從現有瀏覽器來源屬性中複製它們，保留工作階段、密碼、樣式與連線設定。保持 透明 SSN 背景 為勾選狀態。OBS 裁切、變換、濾鏡及其自訂 CSS 欄位不屬於 URL，不會隨之轉移。
  2. 讓 Hype 在此欄中置中。 在其 hype.html URL，設定 align=center （取代既有的 align=left 或 align=right，並移除 alignright （如有））。對於已含下列內容的 URL： ?session=...，附加 &align=center。可選的精簡起始樣式為 &combineall&hidetitle&style=compact&scale=0.75；取代既有值，不要重複新增。如果所選樣式需要更多空間，請增加 Hype 圖層的高度。
  3. 讓精選聊天避開聊天欄。 設定 同時設定 Left = 450 與 Width = 1470：450 + 1470 = 1920。將寬 1920 的圖層向右移 450 會裁掉其右邊緣。精選聊天仍將訊息放在自身區域的底部附近。若要使較短的訊息在該區域內置中，請新增 &center 至其 featured.html URL。如果希望訊息在整個場景中置中，請改用 Left = 0、Width = 1920，以及 &center.
  4. 將 NinjaBacker 放在精選聊天上方。 將其觀眾疊加畫面 URL 貼上為最後一個圖層，並保留既有的從右側進入動畫設定。組合器控制其區域與圖層順序；NinjaBacker 疊加畫面控制其動畫與內部位置。其背景必須透明，網站必須允許嵌入。此選用圖層未包含在四個疊加畫面的範例測試中。
  5. 以 1920×1080 預覽。 傳送一則含 emoji 的測試聊天訊息，從停駐面板精選一則訊息，並在 SSN 中啟用 Hype 資料。僅傳送一般聊天不會選取精選聊天訊息。如果疊加畫面仍為空白，請確認它們能分別正常運作。
  6. 將新的組合連結複製到 OBS。 將該瀏覽器來源本身的寬度設為 1920、高度設為 1080。組合器的預覽尺寸不會設定 OBS 尺寸。讓新來源符合場景大小且不裁切。每次編輯配置後，都要重新複製新的組合連結；舊的 OBS 連結會保留舊配置。

效能： 一個瀏覽器來源仍會執行每個嵌入的疊加畫面及其連線。組合可減少 OBS 來源數量，但不保證降低 CPU 或記憶體使用量。完成後關閉瀏覽器預覽，並在停用舊來源後比較 OBS 效能。M1 macOS／OBS 的效能以及您具體的 NinjaBacker URL 仍需在您的環境中檢查。如果效果更好，也可以將即時聊天獨立保留，只組合其他疊加畫面。

圖層空白或蓋住聊天時

  • 先分別開啟每個原始 URL。提醒通常在事件到達之前保持空白；合併頁面不會擷取新事件。
  • 自動透明支援 dock.html, featured.html, multi-alerts.html，以及 minecraft.html。其他頁面需要各自的透明背景設定。某些外部網站完全禁止嵌入。
  • 透明圖層仍可能擋住點按。請關閉 允許點按與捲動 ，針對聊天上方任何不需要互動的圖層。
  • 行動瀏覽器可能要求先與頁面互動才能播放聲音。如有需要，請為該圖層啟用互動並點按它；瀏覽器自動播放限制仍然適用。在依賴音訊之前，請在實際手機上檢查聲音。
