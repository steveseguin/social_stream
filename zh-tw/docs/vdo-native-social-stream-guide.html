VDO.Ninja 原生應用程式 + Social Stream Ninja

在 VDO.Ninja 原生行動應用程式內接收 Social Stream Ninja 聊天。

此設定的作用

Social Stream Ninja 在電腦上執行，從 Twitch、YouTube、Kick 或其他來源擷取聊天，再將訊息轉送至手機上的 VDO.Ninja 原生應用程式。

手機是接收端，不直接連接 Twitch 或你的聊天平台。

1. 啟動 Social Stream 來源

  1. 在負責收集聊天的電腦上開啟 Social Stream Ninja。
  2. 設定 Social Stream Ninja 工作階段 ID。
  3. 開啟所需平台來源，例如 Twitch、YouTube、Kick 或 TikTok。
  4. 檢查手機前，先確認訊息已出現在 Social Stream 來源視窗或停駐面板中。

可以使用 Twitch WebSocket 來源模式。該模式僅控制 SSN 如何擷取 Twitch 聊天，與手機的 Peer-to-Peer 或 Server 模式互相獨立。

2. 在手機上開啟發佈設定

  1. 開啟 VDO.Ninja 原生應用程式。
  2. 選擇想使用的攝影機、螢幕或麥克風模式。
  3. 在 Publishing Settings 畫面中向下捲動至 Social Stream Ninja Integration。

3. 使用相同的工作階段 ID

啟用 Social Stream，並貼上與電腦上 SSN 完全相同的工作階段 ID。

4. 選擇一種連線模式

手機模式SSN 設定適用情況
點對點（Peer-to-Peer） 使用一般 SSN P2P 輸出。不要僅透過 API 伺服器路由聊天。 建議優先選擇。不需本機伺服器，可透過一般網際網路連線使用。
伺服器 啟用 將聊天訊息傳送到 API 伺服器 ，位置為 SSN Global > Mechanics。 P2P 遭封鎖或不可靠時使用此模式。

不要混用模式。若手機使用 Peer-to-Peer，而 SSN 僅透過 Server 模式傳送，手機將無法接收聊天。若手機使用 Server 模式，但 SSN 未向 API 伺服器傳送聊天，手機也無法接收。

5. 連接並測試

  1. 點選 連接 ，在 VDO.Ninja 原生應用程式中操作。
  2. 傳送一則真實聊天訊息，或使用 SSN 測試訊息。
  3. 查看手機。若手機顯示 Social Stream 未連接（Social Stream not connected），則聊天來源可能仍在運作，但 SSN 到手機的傳輸未連接。

常見失敗情況

症狀實際原因解決方法
SSN 中出現聊天，但手機顯示 Social Stream not connected。 平台來源運作正常，但 SSN 到手機的輸出路徑未連接。 檢查工作階段 ID、連線模式及 SSN 輸出設定。
同一工作階段 ID 在一台電腦上可用，在另一台上不可用。 在 Peer-to-Peer 模式下，SSN 使用工作階段 ID 作為 VDO.Ninja 串流 ID 發佈。同一時間只能有一個 SSN 執行個體發佈該 ID。 關閉或停用第一台電腦上的 Social Stream，再重新啟動第二台電腦上的 SSN；或使用不同的工作階段 ID。
Server 模式始終收不到聊天。 手機正在監聽 SSN API 伺服器頻道，但 SSN 未在該處發佈聊天。 啟用 將聊天訊息傳送到 API 伺服器 ，位置為 SSN Global > Mechanics。
來源視窗顯示聊天，但沒有轉送任何內容。 來源可能處於僅回覆或不擷取模式。 停用 機器人僅回覆（不擷取） 為該來源設定。
遠端手機無法使用本機伺服器模式。 本機伺服器模式僅限電腦或區域網路，通常無法穿過防火牆存取。 使用 Peer-to-Peer，或使用公開 Server 模式並啟用 SSN 的 API 伺服器聊天輸出。

BTTV、7TV 和 FFZ 表情

轉送聊天前，在 SSN 中啟用 BTTV、7TV 或 FFZ 表情選項。SSN 會在訊息到達手機前豐富其內容。

若應用程式版本不算繪內嵌聊天圖片，原生應用程式的聊天顯示可能仍使用圖片表情的備用文字。
