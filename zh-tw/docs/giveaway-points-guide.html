抽獎、票券和點數獎品

初次使用抽獎工具？請先閱讀 你的第一次抽獎：附擷圖的操作指南.

使用一台主機執行抽獎。彈出選單、Stream Deck 和 Event Flow 控制該主機；觀眾顯示頁面展示其已提交的結果。

進行第一次免費抽獎

  1. 在彈出選單中開啟 抽獎選項。將 ID 保持為 default，關鍵字設為 !enter，票價和點數獎品都設為零。
  2. 選擇獲勝者卡片、姓名捲軸或社群轉盤。預覽顯示效果，然後將連結複製到 OBS 瀏覽器來源。
  3. 選擇 開放報名。觀眾在被擷取的聊天中傳送關鍵字即可報名。
  4. 選擇 關閉報名，然後 抽出獲勝者。即使忘記先關閉報名，抽獎也會自動關閉它。
  5. 選擇 新回合 開始另一次抽獎。先前的獲勝者會保留在主機歷程記錄中。

保持 SSN 主機執行，無需與 OBS 瀏覽器來源互動。社群獨立轉盤仍可在沒有下列參數時使用： &managed；點數和遠端控制使用受管理模式。

用 SSN 點數支付的票券

  1. 啟用現有的 忠誠度點數系統 ，位於彈出選單中。這些是 SSN 點數，與 Twitch 頻道點數和各遊戲分數彼此獨立。
  2. 位於 票券和點數獎品，設定每張票的點數和每位觀眾可購買的最大票數。價格為 1 表示每個點數可買一張票。
  3. 開放報名。對於名為下列 ID 的抽獎： friday，觀眾可以用下列指令購買五張票： !ticket friday 5.
  4. 在下列位置檢查參與者： 管理抽獎和歷程記錄。購買成功時，扣款和報名會同時完成。餘額不足時不會產生票券。

購買票券會立即預留點數，因此同一批點數不能同時購買貼圖或參加另一個付費抽獎。開獎會消耗這些點數。 取消並退款 會退回預留點數。在抽獎前移除某位參與者，會退回該參與者的預留。付費回合不能透過「新回合」默默捨棄。

第一份報名後規則即鎖定。關閉／開放可用現有規則暫停或恢復該回合。要變更價格或資格，請取消並建立另一回合。觀眾加入後不能切換錢包，也不能變更在獎池中選擇的一方。

贈送點數

設定 每位獲勝者的點數獎品 和 獎品數量 ，請在開放前設定。每個獎品會向所選觀眾的現有帳號增加指定數量的 SSN 點數。這會創造點數，不會從票券收入或操作員錢包中扣除。總發放量受設定的獎品金額和獲勝人數限制。

多個獎品需逐個抽出。每位確定的獲勝者都會先被記錄，再播放顯示動畫。已完成的抽獎無法透過取消來撤銷已知結果。應透過有意識的主機點數調整來糾正錯誤；變更顯示或重新連線絕不會再次發獎。

帶點數獎勵的遊戲

受管理的數字尋蹤

選擇 數字尋蹤（主播控制），票價為 0、獎品數為 1，並可設定點數獎品。主播選擇 1–100 之間的數字。玩家使用 !guess friday 50，將其中的抽獎 ID 替換為實際值。猜對後會獎勵第一位符合資格的解題者一次；猜錯則為所有人縮小範圍。每位觀眾每五秒可猜一次。

使用受管理的抽獎顯示，或 games/numberhunt.html?session=YOUR_SESSION&managed&giveaway=friday。普通「數字尋蹤」和其他現有遊戲保留原來的本機行為。它們的本機分數和獲勝者標籤不會自動發放 SSN 點數。

擲硬幣獎池

這是一個機率遊戲。選擇 擲硬幣獎池，價格設為 1、結果數設為 1、額外獎品設為 0。觀眾使用下列指令下注： !ticket friday 3 heads 或 !ticket friday 3 tails。兩邊都需要有參與者。關閉報名並開獎：主機會以相同機率選擇正面或反面，不受兩邊下注總額影響。

獲勝觀眾收回自己的下注，並按各自下注比例分享輸方的下注。整數點數分配後的餘數優先分給小數部分最大的份額，若相同則按報名順序決定。不收取費用，也不創造額外點數。例如獲勝方下注為 2 和 1、輸方共 5 點時，8 點獎池分別支付 5 和 3。開獎前取消可為所有人退款。如果一邊沒有人，開獎會被拒絕，此時可取消並退款。

多個抽獎

使用字母、數字、連字號或底線，為每個抽獎設定簡短 ID。觀眾在所有 ID 下的購買共用同一個錢包可用餘額。每個 OBS URL 都包含 &giveaway=ID。購票和猜數字指令會明確指定抽獎。並行的免費抽獎應使用不同關鍵字：含糊的免費關鍵字不會意外同時報名多個抽獎。

彈出選單欄位是設定值。請重新整理或開啟管理器，查看主機實際提交的規則。變更觀眾連結只會變更顯示設定，不會重寫正在執行的回合的票券規則。

OBS 與展示

受管理顯示的預設背景透明。可按需選擇佈景主題面板。卡片、捲軸和社群轉盤共用同一結果和六種配色。減少動態效果的偏好會略過揭曉動畫。轉盤最多預覽 120 個名字；它只是揭曉動畫，不完整代表每張票的中獎機率。實際選擇使用完整的合資格票券池。

重新連線時，顯示頁面會展示已儲存的結果。顯示頁面連線成功並不能告訴 SSN 該 OBS 場景目前是否可見。請保密控制器 URL、工作階段 ID 和備份檔案。

Event Flow

新增 抽獎／票券 ，位於點數動作中。選擇「報名免費抽獎」、「購買票券」、「贈送免費票券」、「關閉報名」、「抽出獲勝者」、「取消並退款」或「查詢狀態」。選擇 ID 和票數；購買獎池下注時選擇正面／反面。該動作使用擷取到的觀眾身分。贈送票券或執行操作員控制前，請使用受信任的觸發器／篩選器。

「購買票券」本身已經花費點數。 不要在它之前放置 Spend Points。失敗會停止相依的後續動作，但不會隱藏原始聊天。結果可在下列位置取得： meta.giveawayControlResult。Event Flow 測試面板會模擬此動作，而不購買真實票券。涉及實際回合變更的端對端測試，請使用獨立的主機／設定檔。

購買資格以動作執行時已提交的餘額為準。不要依賴報名訊息本身賺取最後一個所需點數。原生來源訊息 ID 可提供持久的重播保護；沒有這種 ID 的來源，在跨重新啟動身分識別方面保證較弱。沒有擷取到觀眾／訊息 ID 的一般排程事件，不能代表某人購買。

Stream Deck 與 API

原生外掛包含「開放抽獎」、「關閉抽獎」、「抽獎」、「取消並退款」、「新回合抽獎」和「抽獎狀態」。預設 ID 為 default。將 {"giveawayId":"friday"} 到 value 欄位中，以選擇另一回合。Open 也可接受一個 config 物件；否則，已有回合會保留已提交的規則，新 ID 則使用彈出選單預設值。

使用現有 P2P 連線或已設定的 WebSocket 傳輸。按鍵回報的是 SSN 的回應，不表示 OBS 正在直播。回應逾時時，請先查詢狀態，再嘗試新的抽獎。

{"protocol":2,"action":"buygiveawaytickets","get":"callback-1","value":{"giveawayId":"friday","roundId":"ROUND_ID","operationId":"purchase-123","count":5,"actor":{"chatname":"Avery","type":"youtube","userid":"SOURCE_USER_ID"}}}

操作 ID 識別一項業務操作；回呼 ID 識別一次回應。重試時保留操作 ID。用同一個 ID 搭配不同參數會失敗。有意進行新購買時，請使用新的操作 ID。操作員 API 存取權限可替所提供的參與者消費：不要將其暴露為無需驗證的公開購買表單。

歷程記錄、備份與復原

管理器列出回合、參與者和獲勝記錄。可將獲勝記錄匯出為 JSON，或儲存完整的版本 2 點數／抽獎備份。完整備份一起包含餘額、預留、回合和操作收據。不會向伺服器上傳任何內容。

主機重新啟動後，已儲存的開放回合會變為關閉狀態以供檢查。票券仍保持預留。可按相同規則重新開放、抽獎，或取消並退款。中斷的資料庫交易要麼完整提交，要麼不留下部分購買／派獎。沒有已提交交付確認的貼圖預留，會在逾時後復原。

完整復原可用於 沒有現有餘額或抽獎記錄的全新主機。它會復原整個快照，並保持復原的回合關閉。它拒絕覆寫已有資料的主機。恢復回合前，請先在彈出選單中恢復原始直播／工作階段 ID；復原結果會列出備份中的工作階段。此備份不取代一般彈出選單設定。切勿將舊主機和復原後的主機作為同一經濟系統的兩個獨立權威同時執行。備份是快照，無法包含儲存之後發生的交易。

僅匯入餘額無法復原未結算的預留。當受影響的資金已被預留時，點數重設和手動覆寫會被拒絕。重設點數不會刪除抽獎收據／歷程記錄。餘額屬於目前瀏覽器／應用程式設定檔，回合則按工作階段劃分。不同設定檔／裝置不會自動同步。清除瀏覽器資料可能刪除本機記錄，因此請將備份儲存在該設定檔之外。

選用的伺服器備份／同步是未來功能，不包含在此版本中。此實作不會新增上傳、伺服器憑證、購買的貨幣或提領功能。

出現問題時

  • 沒有報名： 檢查 ID／關鍵字、會員限制、開放狀態和所擷取的平台。機器人、私人、歷史、重播和帶測試標記的報名會被排除。
  • 帳號發生變化： 名稱／身分變化可能導致錢包歸屬不明確。請在主機上檢查；系統絕不會默默合併跨平台帳號。
  • 沒有回應： 確保預期的 SSN 主機正在執行，且主機控制已啟用。重試前請重新整理已提交的狀態。
  • 無法重設／匯入： 先結算或取消已預留的購買。包含未履行義務的備份，請使用完整復原。
  • 未知獎勵： !spend 要求符合已設定的獎勵和價格；不再因為任意獎勵名稱而消耗點數。

逐步復原備份

  1. 保持舊主機停止執行。在新的瀏覽器設定檔中開啟 SSN，並開啟抽獎管理器。
  2. 位於 在全新主機上復原，選擇完整備份。等待復原訊息，並記下其中列出的原始工作階段 ID。
  3. 在彈出選單的 工作階段選項，輸入該原始工作階段 ID。
  4. 返回管理器，選擇抽獎 ID，然後選擇 重新整理。檢查其規則、參與者和獲勝記錄。復原的開放回合會保持關閉以供檢查。
  5. 按相同規則重新開放、抽獎，或選擇 取消並退款 退回預留票券。檢查結果後儲存新的備份。

在 OBS 中，起始瀏覽器來源尺寸使用 1280 × 720。受管理的轉盤會配合剩餘的來源高度。預設背景透明，無需自訂 CSS；所有一般控制項都保留在彈出選單、管理器或 Stream Deck 中。
