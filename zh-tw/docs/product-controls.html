直播商品與觀眾連結

將營利疊加畫面用作 OBS 瀏覽器來源供觀眾觀看。從 SSN、Stream Deck 或 API 操作它。控制停駐面板可單獨使用相同 API；操作員控制項不應出現在觀眾疊加畫面上。

1. 新增商品或支持連結

開啟營利 > 商品與支持連結 > 設定商品與連結。貼上公開 HTTPS 連結並選擇 從連結載入詳情。快速匯入支援公開的 Gumroad、itch.io、Ko-fi、Buy Me a Coffee 與 Fourthwall 頁面。自訂網域、重新導向、私人頁面及沒有公開中繼資料的頁面可能需要手動輸入。現有 Shopify 與 Fourthwall API 匯入選項仍可使用。

檢查標題、圖片、價格、幣別與用途。快速匯入會特意將價格留空。選擇 新增商品或連結，啟用「商品與支持連結」，然後 儲存設定。手動卡片無需商家帳號。

購物、禮物、支持與加入描述連結的用途，不會改變後續付款事件的分類。卡片是儲存的快照；庫存與價格以結帳頁面為準。

2. 控制顯示內容

將現有的商品與支持連結疊加畫面 URL 新增至 OBS。推廣內容使用展示或支持卡片；選擇兩者以同時包含活動提醒。

  • 立即顯示 在已儲存的列上執行時，會固定該商品並覆寫定期卡片排程。
  • 下一個商品 固定下一個已儲存商品。
  • 隱藏商品 隱藏推廣卡片。購買與禮物提醒繼續顯示。
  • 恢復排程 恢復儲存的首個商品或輪播設定。

使用控制項前設定顯示／隱藏秒數。零表示持續到再次變更；1–3600 表示在相應秒數後恢復儲存的排程。即時覆寫會在 SSN 重新啟動時重設。未儲存的列會被標記，且其立即顯示按鈕保持停用，直到儲存設定。狀態顯示選取商品名稱與剩餘秒數；不會聲稱 OBS 正在直播或該來源可見。控制項透過精確的已儲存 URL 識別商品，因此在清單中移動商品不會破壞自動化。

3. 發布一個觀眾連結

開啟顯示選項 > 公開觀眾頁面，並選擇 發布已儲存連結。此操作明確發布所有已儲存的商品／支持連結，包括標題、圖片、價格與用途。分享 複製觀眾連結 給觀眾。商品 QR 碼現在使用此固定頁面，因此疊加畫面輪播後，觀眾仍可找到商品。

儲存的變更與即時控制項會更新同一個 URL。觀眾頁面每 15 秒檢查更新，並標記精選商品。推廣卡片隱藏時，其他連結仍可存取。SSN 離線時，上次發布的目錄仍可存取；頁面顯示儲存時間，精選表示上次儲存的選取或輪播，不證明創作者正在直播。

取消發布 移除頁面；商品 QR 碼恢復為各商品連結。已開啟的觀眾頁面會在下一次成功檢查時清空。之前分享的 URL 會停止載入，直到您再次發布。從同一裝置重新發布會恢復相同 URL。請保留 SSN 裝置設定檔：更新或移除頁面需要其中的私人發布金鑰。

如果 API 無法使用，本機控制項仍可使用。更新失敗會保留上次發布的頁面，並在 SSN 開啟期間重試。彈出選單會回報失敗。發布需要部署選用的 public-shop 服務；無需商店或支付帳號。

Event Flow 與遠端控制

在 Event Flow 中，新增 商品與支持 操作，位於疊加畫面操作群組中。選擇顯示、下一個、隱藏或恢復；可選填精確的已儲存商品 URL 與秒數。使用合適的現有觸發器，例如自己的版主命令，不要允許每則聊天訊息都變更商品。

在 Stream Deck 外掛程式中，從下列分類新增預設命令按鍵： 商品與支持：顯示商品、下一個商品、隱藏商品與恢復商品。顯示包含已儲存商品選擇器；選擇重新整理商品與狀態以載入清單。無法使用的已儲存選取會繼續顯示，不會悄悄更換。您仍可貼上公開商品 URL，或留空以使用目前／首個商品。下一個與隱藏可選填秒數。按鍵等待 SSN 確認本機變更，與公開頁面更新無關。可新增選用的商品狀態按鍵，在按鍵可見時每五秒重新整理選取／隱藏／排程狀態。屬性檢查器與 SSN 顯示完整商品名稱；小型狀態按鍵會截短長名稱。使用現有 P2P 或 WebSocket 連線。

現有的經過驗證的工作階段遠端 API 接受相同控制：

{"action":"commerceControl","command":"show","url":"https://example.com/product","seconds":30}

命令為 show, next, hide 和 resume。省略 URL 可顯示目前／首個商品。必須啟用主持人控制。切勿向觀眾分享私人工作階段／控制 URL；請使用已發布的觀眾連結。

這些操作僅廣播現有的 monetization_update 顯示狀態。它們不會建立贊助、購買、聊天貼文或 Event Flow 付款觸發器。現有的 hasDonation 行為不變。

確認控制何時完成

商品與支持操作會等待 SSN 回覆，再繼續流程。對於一般事件承載資料， meta.commerceControlResult 包含 success ，以及產生的 commerce 控制狀態或 error。失敗會停止該鏈中的後續操作；原始購買或贊助仍可供其他流程與疊加畫面使用。該狀態確認 SSN 的選取、隱藏狀態或排程；OBS 可見性是獨立的。

如果八秒內未收到回覆，操作會回報逾時。控制可能已生效：重試下一個之前，請檢查彈出選單或停駐面板狀態。外部遠端用戶端應使用現有請求／回應協定並檢查傳回結果，而不是將命令已傳送視為成功。

其他效果有各自的回饋。列印熱感應標籤會回報 meta.thermalPrintResult；成功提交工作並不能確認紙張已列印。同步 Webhook 操作可以傳回 HTTP 狀態與回應，並可在失敗時阻止繼續執行。這些是操作結果，不是新的付款事件。參閱 事件參考 了解控制結果契約。
