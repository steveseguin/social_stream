獨立應用程式模式

了解來源視窗、標準模式、WebSocket 模式與 TikTok 預設。

應用程式的用途模式名稱適合使用標準模式的情況適合使用 WebSocket 或 API 模式的情況應用程式中的 TikTok使用 OBS 前要檢查什麼常見解決方式

應用程式的用途

桌面應用程式在一般瀏覽器之外管理 Social Stream 來源視窗。它可協助整理來源並解決一些瀏覽器分頁節流問題。它與 Chrome 不同，不會自動共享 Chrome 登入狀態或 Cookie。

模式名稱

某些來源有多種連線模式。正確模式取決於平台、登入狀態，以及您需要更豐富的事件還是簡單頁面擷取。

模式白話說明適用情況
標準應用程式開啟一般平台／來源頁面並讀取已繪製的頁面。您需要最簡單的可見頁面擷取、登入或手動驗證。
WebSocket/API來源透過平台 API、通訊端或 Social Stream 來源頁面連線。平台支援該模式，且您希望取得更可靠的背景執行或更豐富的事件資料。
輪詢／舊版透過檢查更新來運作的相容路徑，而不是使用首選的即時通訊端路徑。新連接器失敗，或需要平台專用備援方式。
TikTok 自動應用程式選擇最佳 TikTok 路徑，並可能在某條路徑失敗時切換備援。您不確定使用哪種 TikTok 模式。

適合使用標準模式的情況

  • 在能看到直播頁面或彈出聊天時，平台可以正常運作。
  • 網站要求您登入、完成提示驗證，或保持聊天面板可見。
  • 您正在比較應用程式與 Chrome 擴充功能的行為。
  • 您需要最熟悉的排查路徑：開啟頁面、看到聊天、測試停駐面板，然後測試 OBS。

如果平台變更頁面配置、封鎖嵌入式／應用程式瀏覽器、要求驗證碼或將聊天藏在登入之後，標準模式仍可能失敗。

適合使用 WebSocket 或 API 模式的情況

  • 來源明確支援 WebSocket／API 模式。
  • 您希望來源在背景也能更穩定地運作。
  • 您需要一般頁面擷取可能無法提供的事件類別。
  • 您能處理供應商權杖、帳號權限、API 範圍或來源頁面設定。

WebSocket／API 模式不一定更好。如果驗證、權杖、供應商存取或平台 API 失敗，標準模式可能更便於快速測試。

應用程式中的 TikTok

桌面應用程式中的 TikTok 不只有一種模式。疑難排解前，請始終記錄目前啟用的預設。

TikTok 路徑使用情境常見故障點
自動大多數使用者應首先嘗試。應用程式可能切換備援，請檢查狀態文字。
標準擷取可見 TikTok 頁面。登入、驗證碼、重新導向頁面或隱藏聊天。
本機簽署器應用程式原生的讀取與回覆支援路徑。應用程式中的 TikTok 工作階段／Cookie 必須有效。
輪詢／相容通訊端／簽署路徑失敗時的備援方式。資訊不如首選連接器豐富。
代理或自訂簽署進階設定。供應商可用性、API 金鑰、房間 ID 或速率限制。

首次一般嘗試時，新增 TikTok，將預設保留為自動，啟用來源，並觀察應用程式狀態文字。

使用 OBS 前要檢查什麼

  1. 確認應用程式來源已啟用。
  2. 如果平台需要登入，確認來源視窗已登入。
  3. 確認停駐面板透過相同工作階段 ID 收到聊天。
  4. 只有停駐面板正常後，才新增或重新整理 OBS 疊加畫面 URL。
  5. 如果 Chrome 正常但應用程式不正常，請記住應用程式工作階段與 Chrome 工作階段是分開的。

常見解決方式

  • Chrome 已登入但應用程式未登入： 在應用程式來源視窗內登入平台，或使用擴充功能作為擷取方式。
  • 來源顯示作用中，但沒有聊天到達： 檢查模式、來源視窗、直播 URL／使用者名稱與停駐面板工作階段。
  • 應用程式正在使用錯誤的來源檔案： 檢查應用程式使用的是封裝、快取、遠端、beta、穩定版還是本機 Social Stream 資源。
  • TikTok 失敗： 記錄目前預設、狀態文字、應用程式版本，以及來源是否切換至備援模式。
  • OBS 空白： 先測試停駐面板。如果停駐面板為空，問題還不在 OBS。
