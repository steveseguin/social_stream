忠誠度點數和獎勵

抽獎、付費票券、遊戲獎品與復原指南

獎勵參與點數，讓觀眾兌換已核准的獎勵，並備份他們的餘額。

1. 啟用參與點數

  1. 開啟 SSN 的 全域設定與工具 → 點數系統。開啟 啟用忠誠度點數系統.
  2. 先使用 每次參與獲得點數：1 和 參與時間範圍（分鐘）：15，再根據直播需要調整。
  3. 啟用 !points, !leaderboard，以及 !rewards 指令，以啟用相應的聊天回覆。
  4. 保持 SSN 和來源聊天持續擷取。請測試觀眾傳送一則普通訊息，然後檢查 管理使用者點數.

點數獎勵的是擷取到的參與活動，不是靜默觀看時間，也不是每一則訊息。獲獎後，觀眾需要在參與時間範圍結束後再次傳送符合條件的訊息，才能再次賺取點數。連續參與可獲得額外獎勵。在同一時間範圍內重複發訊息，不會重複獲得點數。

2. 檢查和管理餘額

觀眾使用 !points 查看餘額，並使用 !leaderboard 查看排名（需啟用）。回覆需要能向聊天回傳訊息的來源；如果沒有收到回覆，請透過下列方式檢查餘額： 管理使用者點數 ，再判斷是否沒有賺到點數。

!points 顯示可用餘額、已獲得點數、支出及預留點數。 !leaderboard 及忠誠度排行榜會依累計獲得的點數排序並顯示。兌換獎勵會減少可用餘額，而點數排名仍以累計獲得的點數為準。

使用 管理使用者點數 查看特定觀眾和平台，或使用 查看排行榜 查看概覽。帳號以使用者名稱和來源類型為索引鍵：Twitch 與 YouTube 上的相同名字擁有獨立餘額。不要假定觀眾的帳號會自動連結。

3. 提供貼圖獎勵

  1. 在 點數系統 → 貼圖獎勵，啟用貼圖獎勵，並選擇希望提供的貼圖包。根據賺取點數的速度設定合適的價格。
  2. 複製 OBS 瀏覽器來源 連結新增到 OBS，並保持貼圖來源載入。
  3. 在 計時與聊天回覆，設定顯示時間、每位觀眾冷卻時間、每張貼圖冷卻時間和安靜間隔。按需啟用指令回覆。
  4. 讓測試觀眾輸入 !stickers 列出已啟用的貼圖代碼和價格，然後使用 !sticker rocket ，前提是該代碼已啟用且點數足夠。
  5. 宣佈獎勵前，請檢查顯示的貼圖和剩餘餘額。

選擇目錄時即完成核准。 啟用的貼圖會自動兌換，沒有逐次兌換核准佇列。對於自訂圖片或 GIF，由你提供並核准直接 HTTPS 資源 URL。觀眾不能透過貼圖指令提交任意圖片。

處於冷卻中或疊加畫面離線時，請求會被拒絕且不扣點數。如果扣款後顯示傳遞失敗，SSN 會嘗試退款，並回報需要主播糾正的失敗。疊加畫面已連線不代表 OBS 目前正在顯示該場景。

參閱 貼圖包與設定 ，查看預覽、自訂圖片和 GIF 選項。 !stickers 是貼圖目錄指令； !rewards 列出一般的點數獎勵指令。

4. 新增選用的 Event Flow 獎勵

對於自訂動作，請使用現有 Event Flow 編輯器及其 花費點數 動作。在扣款之前設定準確的指令條件，並設定 要花費的金額，並在成功扣除點數後連接付費動作。請在流程中加入冷卻時間。

啟用獎勵前，分別測試餘額不足和餘額充足的情況。自訂動作在收費後失敗，不會自動繼承貼圖系統的傳遞／退款行為。將付費指令連接到媒體或外部動作前，請檢查失敗處理。參閱 Event Flow.

5. 移轉時保留點數

點數儲存在本機瀏覽器／應用程式儲存空間中。與另一台電腦或另一處安裝共用工作階段 ID，不會同步餘額。

  1. 使用 點數系統 → 備份與復原 → 匯出點數 ，並保留 JSON 檔案。
  2. 在目的地安裝中，先匯出已有點數，然後使用 匯入點數 並選擇預期的匯入模式。
  3. 謹慎選擇： 合併 保留較高的點數值； 替換 覆寫現有點數資料。檢查匯入結果，在「管理使用者點數」中抽查觀眾和平台，確認餘額後再恢復獎勵。

將專用的點數匯出檔案與下列備份一同儲存： 設定備份. 重設所有點數 會清空點數帳本；僅在匯出後有意重設時使用。

疑難排解

  • 餘額沒有變化： 檢查擷取、總開關、參與時間範圍和觀眾的平台帳號。
  • 聊天歷史紀錄已停用： 點數取得及點數指令依賴本機訊息資料庫。請參閱 聊天歷史紀錄指南.
  • 貼圖顯示無法使用： 檢查貼圖包／代碼選擇、餘額是否充足、冷卻狀態，以及 OBS 貼圖來源是否已載入。
  • 移轉後點數遺失： 將點數匯出檔案匯入到負責擷取的安裝中；僅有工作階段連結並不等於備份。
