1. 選擇工具

目標 在 SSN 中開啟
讓聊天觀眾投票決定下一項活動 圖形投票 → 投票選項
隨機選擇報名者 候補名單／抽獎，開啟抽獎模式
依佇列順序安排觀眾 候補名單／抽獎，關閉抽獎模式

將該區段產生的連結用作 OBS 瀏覽器來源。保持 SSN 與聊天來源執行，並保留連結中的工作階段、密碼與伺服器選項。 抽獎工具 提供獨立抽獎池，支援得獎卡片、姓名滾輪與社群轉盤展示。使用其抽獎選項面板進行專用抽獎控制；候補名單／抽獎仍可獨立使用。

2. 進行多選項投票

  1. 開啟 圖形投票 → 投票選項。設定 投票類型 為 多選項.
  2. 輸入 我們接下來玩什麼？ 作為問題，並將 Adventure, Puzzle 作為逗號分隔的選項。設定 投票比對 為 僅精確投票.
  3. 將 允許每位使用者多次投票 和 依贊助金額加權投票 關閉，以進行簡單的單次投票。開啟 啟用投票.
  4. 將產生的投票連結複製至 OBS。請觀眾傳送 1 或 2 作為整則訊息傳送。傳送符合的選項文字也可以。
  5. 選擇 結束投票 以關閉投票。在選擇下列操作前記下結果： 重設投票 以開始下一輪。

自由形式投票接受主題標籤投票； 主題標籤可出現在任意位置 允許主題標籤出現在較長訊息內。 儲存目前投票 儲存預設以供重複使用；它不是觀眾投票結果的永久紀錄。除非啟用多次投票，否則同一投票者的重複投票會被忽略。

專用抽獎工具

含螢幕擷取畫面的操作說明請參閱 你的第一次抽獎。開啟 抽獎工具 → 抽獎選項。設定報名關鍵字，選擇整則訊息比對或獨立單字比對，並可選擇僅允許會員報名。點按 開放報名，然後 抽出獲勝者 ，在準備好後執行。抽獎會自動關閉報名。每次抽獎前，您都可以使用相同規則關閉並重新開放報名。 新回合 清空目前抽獎池，將過去結果保留在歷史紀錄中，並保持報名關閉。

選擇 獲勝者卡片, 姓名捲軸，或 社群轉盤，並從六種樣式中選擇一種。預覽使用虛構姓名，不會加入您的工作階段。複製產生的 giveaway.html?session=YOUR_SESSION&managed 連結至 OBS。受管理的觀眾顯示頁面不含操作員控制項或工作階段詳情。樣式與標題屬於連結設定；報名規則屬於主持端設定，在開放報名時套用。

相同 Giveaway ID 的受管理顯示頁面共享主持人的抽獎池與選定得獎者。免費關鍵字報名的中獎機率相同；付費抽獎依票數加權。身分在各平台內透過提供的使用者 ID、使用者名稱或顯示名稱去重；不同平台視為不同身分。關閉重複中獎後，每位得獎者會從目前輪次的合格名單中移除。新輪次允許這些觀眾再次報名。抽獎池最多容納 10,000 名參與者；人數較多時，轉盤展示最多 120 個姓名的樣本，但抽取始終使用完整的合格票池。

保持 SSN 執行。輪次依工作階段分別儲存在本機瀏覽器／應用程式設定檔中。重新啟動會關閉正在開放的輪次以供檢查，但不會將其刪除。重新整理觀眾頁面可收到目前結果。會員限制需要來源提供會員資訊。歷史、重播、私人、機器人以及僅含事件的訊息均被排除。免費報名文字必須符合設定的關鍵字；贊助金額不會改變中獎機率。

API、Stream Deck 與 Event Flow

相同的主持端操作用於彈出選單按鈕、現有 HTTP／WebSocket API 與 Stream Deck。收集報名或抽獎時，無需開啟任何抽獎顯示頁面。在 Event Flow 中，使用 抽獎／票券 操作。參閱 點數與自動化指南 了解付費票券、遊戲獎品與整合。

操作效果
startgiveaway抽取前開放或恢復報名。選用值： {"giveawayId":"default","config":{"keyword":"!enter","match":"exact","membersOnly":false,"removeWinner":true}}。如果沒有明確指定規則，則保留目前輪次規則，或在新一輪中使用彈出選單設定。
closegiveaway關閉報名並保留抽獎池。
drawgiveaway關閉報名並選出一位符合資格的得獎者。抽獎池為空時傳回錯誤。
resetgiveaway建立一個關閉報名的空輪次；將舊輪次及得獎者封存。請先取消／退款未完成的付費預留。
getgiveawaystate讀取報名人數、開放／關閉狀態、報名規則與近期得獎者。

Protocol 2 Stream Deck 請求使用相同的操作名稱，並接收對應的主持端回應。這些回應描述抽獎狀態，不代表 OBS 可見性。省略下列參數，仍可使用舊版獨立社群轉盤： managed；它有自己的本機抽獎池，不受這些主持人操作控制。它的本機儲存空間現在依工作階段與密碼隔離，精確比對指整則訊息，抽取使用安全亂數。

3. 抽出得獎者

  1. 開啟 候補名單／抽獎 → 啟用並自訂。啟用觸發器並設定明確的命令，例如 !join.
  2. 開啟 設為抽獎模式而非佇列模式。將更新後的連結複製至 OBS 瀏覽器來源。
  3. 告知觀眾報名命令及資格規則。如果使用 僅會員可報名，請先檢查來源是否提供會員資訊。
  4. 觀察報名人數增加。選擇 停止報名 ，在報名期結束時執行，然後 選擇得獎者.
  5. 使用 下載名單 以在下列操作前保留報名紀錄： 重設抽獎 清空本輪。

4. 管理觀眾佇列

使用相同的候補名單設定，但關閉抽獎模式並複製更新後的 URL。觀眾使用您設定的命令加入。

按鈕 操作方法
突顯首位報名者 提示下一位觀眾。
移除首位報名者 在該觀眾完成自己的回合後前進。
選擇姓名 隨機選擇，而不是依佇列順序選擇。
停止報名 關閉佇列，不再接受新加入者。
下載名單／重設佇列 儲存 TSV 副本，然後在活動結束時清空報名紀錄。

透過重新加入選項決定已移除的觀眾是否可以再次加入。選用的 候補名單控制命令 僅限版主／主持人／管理員使用者： !wlstop, !wlremove, !wlreset, !wlpick，以及 !wlhighlight。請有意識地啟用這些功能；僅設定觀眾報名命令不會啟用它們。

5. 演練與復原

在下列功能中使用不同的虛構使用者： 測試訊息 以檢查投票與報名行為。同一個人使用兩個平台時，無法可靠地視為同一共享身分。邀請觀眾參與前，請確認結果顯示在 OBS 中。

  • 沒有票數： 檢查是否啟用投票、投票是否已結束、精確比對設定，以及該使用者是否已投票。
  • 沒有報名者： 檢查候補名單觸發器、準確命令、停止報名狀態與僅限會員的限制。
  • 有計數但沒有名單： 抽獎模式顯示抽獎池與得獎者，而不是一般佇列。
  • OBS 顯示不一致： 取代已儲存的 URL，檢查工作階段／密碼，並避免執行單獨設定的重複投票頁面。

有關硬體或 OBS 端按鈕，請參閱 Stream Deck設定 和 OBS控制停駐面板.
