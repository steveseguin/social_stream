事件和提醒相容性

將擷取到的平台事件連接到 Multi Alerts，避免混淆普通聊天、贊助和事件承載資料。

從事件來源開始

Multi Alerts 展示的是 Social Stream 已經擷取到的事件。它本身不會登入 Twitch、Kick、YouTube、TikTok 或其他平台。

  1. 連接並啟用提供該事件的平台來源。
  2. 保持該來源頁面或獨立應用程式的來源視窗作用中。
  3. 在來源、彈出選單、停駐面板和 Multi Alerts URL 中使用相同的 Social Stream 工作階段 ID。
  4. 排查平台連線前，先從提醒疊加畫面的選項中測試它。

預覽成功證明提醒版面配置正常。 這不能證明平台來源有權接收該真實事件。

啟用所需的提醒類型

從 Social Stream 設定中開啟 Multi Alerts 選項。追蹤、訂閱、贊助、Bits 和 raid 都有各自的啟用、樣式、聲音和外觀控制項。拍賣和 Hype Train 提醒需要透過專用選項主動啟用。

  • 使用 提醒排隊 ，適用於可能同時到達多個事件的情況。
  • 事件在停駐面板正常，但在 Multi Alerts 中不正常時，請檢查來源篩選器。
  • 缺少小額贊助或 cheers 時，請檢查最低現金／贊助篩選器。
  • 如果自訂提醒音訊被自動播放規則阻止，請先與瀏覽器頁面互動一次。

真實提醒缺少時

  1. 確認在來源本身的記錄、停駐面板或 API 輸出中收到了該事件。
  2. 確認來源和 Multi Alerts 頁面使用相同的工作階段 ID 和密碼。
  3. 確認該類別已啟用，且未被來源或頻道篩選器排除。
  4. 檢查贊助和 Bits 的最低金額篩選器。
  5. 對於 Twitch 或 Kick，如果聊天正常但受保護的事件不正常，請重新登入。
  6. 讓來源視窗保持作用中，足夠長時間以觀察到真實事件；僅有預覽不算平台的端對端測試。

如果涉及多個裝置或連線模式，請查看 工作階段、密碼與轉送模式.
