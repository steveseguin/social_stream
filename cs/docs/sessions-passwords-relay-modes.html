Relace, hesla, přenos a režimy serveru

Jedna shodná relace propojuje zdroje, doky, překryvy, upozornění a stránky API. Musí se shodovat i příznaky směrování.

Model připojení

  1. Zdroj zachytí chat nebo událost a publikuje je do relace Social Stream.
  2. Dok, překryv vybraných zpráv, Vícečetná upozornění, Event Flow a další stránky se připojují ke stejné relaci.
  3. Pokud je nastaveno heslo, každá připojená stránka musí používat stejné heslo.
  4. Pokud je povoleno serverové směrování, aktivní stránky musí používat nově vygenerované URL s odpovídajícími parametry směrování.
Source → same session ID + password + routing mode → Dock / overlay / API consumer

ID relace a heslo

Otevřít Globální nastavení a nástroje → Možnosti relace pro zobrazení aktuálního ID relace a nastavení volitelného hesla.

HodnotaPravidlo
ID relacePonechte ho stejné, pokud nechcete nahradit všechny URL zdrojů, doků, překryvů a integrací, které ho používají.
HesloVolitelné, ale po nastavení se musí všude shodovat. Po přidání nebo změně zkopírujte nově vygenerované odkazy.
Vygenerovaný odkazPokud odkaz obsahuje heslo nebo jiné citlivé parametry, považujte celý odkaz za soukromý.

Upřednostněte kopírování vygenerovaných URL. Již obsahují aktuální relaci, heslo, verzi stránky a podporované možnosti směrování. Ručně upravené odkazy jsou častou příčinou prázdných stránek.

Povolte záložní serverovou cestu pro čtení a odpovídání

Použijte, pokud se dok nebo sjednocený chat připojí, ale zprávy nepřicházejí, nebo odpovědi selhávají kvůli blokované či nespolehlivé běžné cestě peer-to-peer.

Dva ovládací prvky záložní cesty fungují jako pár: Posílat zprávy chatu na server API (pro externí příjemce) přenáší příchozí chat serverovou cestou, zatímco Dok odesílá své příkazy rozšíření přes server přenáší odpovědi a příkazy doku zpět.

Rychlá metoda

  1. Otevřete nebo obnovte vygenerovaný odkaz doku.
  2. Odešlete umělou testovací zprávu ze Social Stream Ninja.
  3. Pokud se Zapnout záložní server zobrazí toto upozornění, vyberte ho a potvrďte. Social Stream Ninja společně povolí serverovou cestu příchozího chatu i příkazů odpovědí.
  4. Zkopírujte nově vygenerované odkazy doku a překryvů. Znovu otevřete běžná okna prohlížeče a nahraďte všechny uložené URL zdrojů prohlížeče OBS.

Ruční metoda v desktopové aplikaci

  1. Otevřete desktopovou aplikaci Social Stream. V pravém „Zdroje a nastavení“ panelu rozbalte Globální nastavení a nástroje.
  2. Rozbalte Mechanika – připojení a integrace.
  3. Zapněte Posílat zprávy chatu na server API (pro externí příjemce). Jde o cestu příchozího chatu/čtení.
  4. Zapněte Dok odesílá své příkazy rozšíření přes server. Jde o cestu odpovědí/ovládání.
  5. Zkopírujte a znovu otevřete nově vygenerované odkazy. Staré otevřené stránky a uložené URL v OBS se samy neaktualizují.

Nezapínejte všechny serverové možnosti. Povolit vzdálené ovládání API, Povolit doku používat a publikovat přes server API, a dočasná možnost souběžného doručování nejsou pro běžnou záložní cestu čtení a odpovídání potřeba. Souběžné doručování může vytvářet duplicitní zprávy.

Výchozí režim, přenos a režimy serveru API

OvládáníCo měníKdy jej použít
Výchozí odkazy Běžný přenos Social Stream mezi účastníky/relacemi bez přidaného serverového příznaku. Většinu sestav na jednom počítači a běžných sestav OBS.
Povolit vzdálené ovládání rozšíření přes API Povoluje ovládání rozšíření přes HTTP/WebSocket a zpracování příchozích webhooků. Externí aplikace, ovládání Stream Deck/API nebo podporované příchozí webhooky příspěvků.
Povolit doku používat a publikovat přes server API Přidává do stránky server směrování, pokud je podporováno. Postup doku/vybraných zpráv potřebuje vzdálené ovládání serverem API místo běžné cesty.
Odesílat zprávy chatu na server API Směruje zachycený chat k příjemcům serveru API a přidává server2 do podporovaných vygenerovaných odkazů. Dok potřebuje záložní serverovou cestu pro příchozí chat nebo musí chat přijímat Python, Node či jiný externí příjemce WebSocket.
Posílat chat směrovaný přes API i běžnou cestou Dočasné souběžné doručování oběma cestami. Pouze při záměrném přechodu mezi režimy; může duplikovat zprávy.
Příkazy doku přes server Přidává server3 tam, kde je podporováno, aby se příkazy doku vracely přes server. Přímá připojení jsou blokovaná nebo nespolehlivá a příkazy z doku do rozšíření potřebují server.

O projektu localserver

Některé stránky přijímají localserver a používají místní koncový bod WebSocket na ws://127.0.0.1:3000. Přidejte localserverport=PORT pro výběr jiného portu mezi 1024 a 65535. Neplatné nebo vynechané hodnoty bezpečně použijí port 3000. Nové instalace desktopové aplikace Social Stream však spouštějí místní server na portu 3003 a přidávají localserverport=3003 do generovaných odkazů — při ručním psaní URL pro novou instalaci tedy parametr přidejte sami. Tyto parametry přidávejte pouze tehdy, když místní server skutečně běží a daná stránka je podporuje.

Snímky a podrobný postup hostovaného WebSocketu nebo pokročilého místního serveru najdete v Režimy hostovaného WebSocket a místního serveru.

Parametry směrování závisí na konkrétní stránce. server, server2, server3, localserver, a localserverport nemají jednotné chování u všech překryvů. Použijte vygenerovanou URL přesné stránky místo kopírování příznaků z jiného nástroje.

Po změně relace nebo přepínače směrování

  1. Zkopírujte nově vygenerovanou URL doku nebo překryvu.
  2. Zavřete a znovu otevřete aktivní stránky prohlížeče používající starou URL.
  3. Nahraďte URL uložených zdrojů prohlížeče OBS a obnovte jejich mezipaměť.
  4. Pokud se změnilo ID relace nebo heslo, obnovte nebo znovu aktivujte stránky zdrojů.
  5. Odešlete jednu umělou testovací zprávu a před testem výsledného překryvu ověřte, že dorazí do doku.

Kontrola prázdného doku nebo překryvu

  1. Porovnejte úplnou session= hodnotu u zdroje, doku a překryvu.
  2. Zkontrolujte, zda některé URL nechybí aktuální password=.
  3. Zkontrolujte, zda ve staré URL OBS nechybí aktuální příznaky serverového směrování.
  4. Pokud nejsou režimy jasné, odstraňte ručně přidané příznaky směrování a zkopírujte čerstvě vygenerovanou URL.
  5. Nejprve otestujte dok. Pokud přijímá zprávy, pokračujte řešením filtrů událostí a možností URL překryvu.
  6. Viz Řešení problémů s OBS a přehled příkazů a API pro podrobnější kontrolu.
