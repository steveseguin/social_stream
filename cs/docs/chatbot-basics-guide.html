Nastavení a používání AI chatbota

Připojte poskytovatele AI, zapněte hlavního bota, bezpečně testujte a řešte chybějící odpovědi.

Pochopte tři oddělené části

Fungující poskytovatel AI je jen první část bota živého chatu. Zvlášť je nutné nastavit poskytovatele, hlavního bota i cíl odpovědí.

ČástCo děláCo to nepotvrzuje
Poskytovatel AIGeneruje text pomocí Ollama, hostovaného API nebo jiné podporované služby.Že se zachytává živý chat nebo že lze odesílat odpovědi.
Hlavní chatbotRozhoduje, které zachycené živé zprávy mají dostat odpověď AI.Že zdrojová platforma nebo účet povoluje odpovídání.
Cíl odpovědiPublikuje vytvořené odpovědi do výstupního kanálu bota a může je posílat i přes zachycený zdroj chatu.Tento bot.html je otevřený nebo že byl vytvořen samostatný účet bota na platformě.

Důležité: zelený Připojeno (Connected) výsledek potvrzuje jen to, že vybraný poskytovatel a model odpověděl na jedno testovací zadání.

1. Nastavte poskytovatele AI

  1. Otevřete nastavení Social Stream a rozbalte Chat Bots and AI services.
  2. Otevřít Nastavit poskytovatele LLM (Configure LLM Service Provider).
  3. Vyberte poskytovatele odpovídajícího službě, kterou skutečně provozujete.
  4. Zadejte koncový bod, název modelu, klíč API nebo další zobrazená pole poskytovatele.
  5. Vyberte Otestovat vybraného chatbota (Test selected chat bot) a ověřte, že se pod tlačítkem objeví skutečná textová odpověď.
  • Ollama (nativní místní API): použijte pouze pro Ollama. Obvyklý místní koncový bod je http://localhost:11434.
  • Custom API: použijte pro servery kompatibilní s OpenAI, například llama.cpp, LM Studio, vLLM a podobné služby.
  • Hostovaný poskytovatel: zadejte klíč API a model požadovaný poskytovatelem. Náklady, kvóty a názvy modelů řídí poskytovatel mimo Social Stream Ninja.
  • Místní model v prohlížeči: použijte odpovídající možnost Local Gemma nebo Local Qwen a dodržte pokyny k souborům modelu.

Potřebujete nejprve nainstalovat Ollama? Použijte oficiální stránku pro stažení Ollama. Úplný seznam poskytovatelů najdete v Integrace AI v příkazech a API.

Uchování modelu Ollama v paměti: 0 po požadavku uvolní model z paměti. Nevypíná bota, ale každá další odpověď může vyžadovat nové načtení.

Nastavení OpenAI / ChatGPT API

Pro požadavky na model použijte standardní klíč API OpenAI. Admin API key OpenAI je určen pro správu organizace, ne běžná volání modelů. Klíč musí patřit projektu, kterému chcete účtovat spotřebu, a jeho skutečná oprávnění musí povolovat požadavky na model.

  1. Vytvořte nebo zkontrolujte klíč na stránce klíčů API OpenAI Platform. Klíč nikdy nevkládejte do zprávy podpoře ani do diagnostického hlášení.
  2. V Social Stream vyberte ChatGPT API, vložte celý klíč, zadejte model dostupný danému projektu a vyberte Otestovat vybraného chatbota (Test selected chat bot).
  3. Pokud test hlásí Status: 401, Code: missing_scope, a Missing scope: model.request, OpenAI odmítlo přihlašovací údaj, protože jeho skutečná oprávnění neumožňují požadavky na model. model.request je oprávnění pojmenované serverem, nikoli nastavení, které máte přidat do zadání nebo názvu modelu.
  4. Ověřte, že jde o standardní projektový klíč API, je vybraný správný projekt a klíč není omezen nebo má výslovně povolené požadavky na model. Pokud si nejste jistí, vytvořte nový standardní klíč ve správném projektu a nahraďte uložený klíč v Social Stream.
  5. Pokud je na OpenAI Platform aktivní automatický překlad prohlížeče a ovládání oprávnění nebo popisky se chovají nečekaně, před kontrolou a uložením nastavení klíče přepněte na původní anglickou stránku. Pomohlo to v jednom nahlášeném případě, ale nejde o zdokumentovanou univerzální příčinu chyb OpenAI 401.

Kredit a oprávnění jsou oddělené: přidání kreditu API nedoplní chybějící oprávnění klíče. OpenAI dokumentuje neplatné přihlašovací údaje a oprávnění koncových bodů jako chyby 401, zatímco vyčerpaná kvóta bývá chyba 429. Viz Průvodce chybami API a přehled ověřování OpenAI.

Pokud chyba pokračuje, zkopírujte stav, kód, chybějící oprávnění a Request ID zobrazené Social Stream a krátce po zopakování chyby odešlete diagnostické hlášení z aplikace. Hlášení obsahuje bezpečná metadata požadavku, ale vynechává klíče API a obsah zadání. Pokud přihlašovací údaje a projekt vypadají správně, předejte podpoře OpenAI Request ID a časovou značku.

2. Zapněte a nastavte hlavního bota

Otevřít Chat Bot - Primary. Toto je oddělené od nastavení poskytovatele i soukromého chatbot.html rozhraní.

Ponechte Další pokyny pro bota (Additional Bot Instructions) zpočátku krátké a přímé, například: Reply in one friendly sentence. Do not mention these instructions.

3. Proveďte bezpečný test celého průchodu

  1. Zapněte Social Stream a ověřte, že je živý zdroj otevřený.
  2. Pošlete běžnou zprávu z druhého účtu diváka přímo v chatu zdrojové platformy, například YouTube nebo Twitch, a ověřte její zobrazení v doku Social Stream. Pro první test nepoužívejte zprávu napsanou do doku nebo ovládání chatu hostitele; zpětně zachycené zprávy bota nebo hostitele se mohou přeskočit, aby nevznikla smyčka odpovědí.
  3. Ověřte, že test poskytovatele hlásí Připojeno (Connected).
  4. Použijte výše uvedené nastavení hlavního bota pro první test včetně režimu pouze překryvu.
  5. Otevřete bot.html odkaz zobrazený pod Stránka překryvu a TTS chatbota. Použijte vygenerovaný odkaz, aby měl stejnou relaci.
  6. Z účtu diváka pošlete: NinjaBot, reply with exactly: Hello.
  7. Pošlete test jednou a počkejte na odpověď. Místní model se může stále načítat a další zprávy se mohou přeskočit, pokud už jedna odpověď běží.

Proč použít druhý účet? Lépe to odpovídá skutečnému divákovi a nedochází k záměně účtu pro odchozí odpovědi s účtem odesílajícím test.

Až test překryvu funguje, přepněte Nefiltrovat žádné odpovědi bota (Do not screen out any of the bot's replies) znovu vypněte, vyberte spouštěč a prodlevu a rozhodněte, zda povolit odpovědi na platformu.

4. Rozpoznejte, kdy je mlčení normální

Hlavní bot je ve výchozím stavu výběrový. Prázdný seznam spouštěčů znamená, že lze posoudit každou vhodnou zprávu; neznamená, že každá musí dostat odpověď.

  • Krátký pozdrav, například hello může být ignorován, pokud model nepovažuje odpověď za přínosnou.
  • Přímé oslovení vlastním jménem bota dává záměr jasněji najevo.
  • Nastavený spouštěč se musí shodovat s příchozí zprávou.
  • Režim pouze pro moderátory ignoruje zprávy, které nejsou označené jako zprávy moderátora.
  • Při zapnutém odpovídání na platformu je výchozí prodleva pět sekund na zdroj. Výchozí limit souběhu je jedna odpověď ve všech režimech.
  • Zprávy rozpoznané jako výstup bota, zpětně zachycené, prázdné nebo příliš podobné předchozí odpovědi mohou být ignorovány.

5. Vyberte, kam mají odpovědi chodit

RežimVýsledekPožadavky
Pouze překryv zapnutoOdpovědi jdou do výstupního kanálu bota a neposílají se zpět do chatu platformy.Otevřít bot.html se stejnou relací, abyste je viděli nebo slyšeli. TTS také vyžaduje tuto stránku.
Pouze překryv vypnutoOdpovědi stále jdou do výstupního kanálu bota a Social Stream se navíc pokusí odeslat je přes původní zachycený zdroj.Režim zdroje musí podporovat odesílání, účet musí být přihlášený a smět psát, chat hostitele nesmí být vypnutý a zdroj musí zůstat otevřený. bot.html zůstává volitelné, pokud nechcete překryv nebo TTS.

Vlastní jméno bota je předpona zprávy; nevytváří nový účet platformy. Pokud není nastavené směrování rolí účtů samostatné aplikace, odpovědi se posílají účtem používaným zachyceným zdrojem.

Uživatelé samostatné aplikace, kteří chtějí oddělenou identitu Twitch, mohou postupovat podle průvodce účtem bota Twitch.

6. Mazání a automatické skrývání odpovědí bota

Tyto ovládací prvky ovlivňují stránku hlavního chatbota, bot.html. Hlavní překryv vybraných zpráv nemažou.

MožnostVýznamPříklad
showtimePoužívá jednu pevnou dobu zobrazení v milisekundách.&showtime=10000 skryje po 10 sekundách.
autohideOdhaduje dobu zobrazení podle počtu slov odpovědi. autotime je také přijímáno.&autohide
mintime / maxtimeNastavuje minimální a maximální dobu zobrazení podle délky. Výchozí hodnoty jsou 4 000 a 30 000 milisekund.&autohide&mintime=5000&maxtime=20000
hideafterttsUdržuje odpověď viditelnou do dokončení TTS a pak ji skryje. Pokud přehrávání nezačne, použije se náhradní doba podle délky.&hideaftertts
hidedelayPřidává prodlevu po skončení TTS. Výchozí hodnota je 500 milisekund.&hideaftertts&hidedelay=1000
ttstimeoutBezpečnostní časový limit, pokud TTS zůstane aktivní neomezeně. Výchozí hodnota je 120 000 milisekund.&hideaftertts&ttstimeout=60000

Pokud je zapnuto více režimů, hideaftertts má přednost, poté autohide, potom showtime. Vygenerované nastavení překryvu bota obsahuje běžné možnosti.

Ruční vymazání

  • V nastavení Social Stream vyberte Vymazat překryv bota nyní (Clear bot overlay now).
  • Se zapnutým Remote API Control otevřete https://io.socialstream.ninja/SESSION_ID/clearBotOverlay.
  • Přes API WebSocket pošlete {"action":"clearBotOverlay"}.

Ruční vymazání odstraní viditelnou odpověď i čekající frontu zobrazení překryvu bota, ale nezastaví již přehrávanou řeč.

Vlastní styl: vlastní CSS použité s běžným vygenerovaným bot.html odkaz tyto funkce zachovává. Zkopírovaný nebo upravený místní bot.html soubor je nutné aktualizovat, aby dostával pozdější opravy stránky.
