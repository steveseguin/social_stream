Rôle de l’application

L’application de bureau gère les fenêtres sources Social Stream en dehors de votre navigateur habituel. Elle peut faciliter l’organisation des sources et résoudre certains problèmes de ralentissement des onglets. Elle est distincte de Chrome et ne partage pas automatiquement votre connexion ni vos cookies Chrome.

Noms des modes

Certaines sources proposent plusieurs modes de connexion. Le bon mode dépend de la plateforme, de l’état de connexion et de vos besoins en événements détaillés ou en simple capture de page.

ModeExplication simpleÀ utiliser quand
StandardL’application ouvre une page normale de la plateforme/source et lit son contenu affiché.Vous avez besoin de la capture visible la plus simple, d’une connexion ou d’une vérification manuelle.
WebSocket/APILa source se connecte via une API de plateforme, un socket ou une page source Social Stream.La plateforme le prend en charge et vous souhaitez une meilleure fiabilité en arrière-plan ou des données d’événements plus complètes.
Interrogation/Ancien mode (Polling/Legacy)Un mode de compatibilité qui vérifie les mises à jour au lieu d’utiliser la connexion socket en direct privilégiée.Le nouveau connecteur échoue ou une solution de repli propre à la plateforme est nécessaire.
TikTok AutoL’application choisit le meilleur chemin TikTok et peut basculer sur un autre en cas d’échec.Vous ne savez pas quel mode TikTok utiliser.

Quand utiliser le mode Standard

  • La plateforme fonctionne lorsque la page en direct ou le chat détaché est visible.
  • Le site exige une connexion, la validation d’une invite ou le maintien d’un panneau de chat visible.
  • Vous comparez le comportement de l’application à celui de l’extension Chrome.
  • Vous souhaitez le dépannage le plus familier : ouvrir la page, voir le chat, tester le dock, puis OBS.

Le mode Standard peut tout de même échouer si la plateforme change la disposition de sa page, bloque les navigateurs intégrés/les applications, demande un CAPTCHA ou exige une connexion pour afficher le chat.

Quand utiliser le mode WebSocket ou API

  • La source prend explicitement en charge le mode WebSocket/API.
  • Vous souhaitez une source qui fonctionne plus efficacement en arrière-plan.
  • Vous avez besoin de familles d’événements que la capture ordinaire de page n’expose pas forcément.
  • Vous pouvez gérer les jetons du fournisseur, les autorisations du compte, les portées API ou la configuration de la page source.

Le mode WebSocket/API n’est pas toujours préférable. En cas de problème d’authentification, de jetons, d’accès fournisseur ou d’API de plateforme, le mode Standard peut constituer un test plus rapide.

TikTok dans l’application

TikTok dans l’application de bureau ne correspond pas à un seul mode. Notez toujours le préréglage actif avant le dépannage.

Pour un premier essai classique, ajoutez TikTok, laissez le préréglage sur Auto, activez la source et observez le texte d’état de l’application.

Vérifications avant OBS

  1. Vérifiez que la source est activée dans l’application.
  2. Vérifiez que la fenêtre source est connectée au compte si la plateforme l’exige.
  3. Vérifiez que le dock reçoit le chat avec le même identifiant de session.
  4. Une fois le dock fonctionnel, ajoutez ou actualisez l’URL de l’incrustation OBS.
  5. Si Chrome fonctionne mais pas l’application, rappelez-vous que leurs sessions sont distinctes.

Solutions courantes

  • Chrome est connecté, mais pas l’application : connectez-vous à la plateforme dans la fenêtre source de l’application ou utilisez l’extension pour la capture.
  • La source est indiquée active, mais aucun message n’arrive : vérifiez le mode, la fenêtre source, l’URL du direct/le nom d’utilisateur et la session du dock.
  • L’application utilise les mauvais fichiers sources : vérifiez si l’application utilise des ressources Social Stream intégrées, en cache, distantes, bêta, stables ou locales.
  • TikTok échoue : notez le préréglage actuel, le texte d’état, la version de l’application et tout basculement de la source vers un mode de repli.
  • OBS est vide : testez d’abord le dock. S’il est vide, OBS n’est pas encore en cause.
