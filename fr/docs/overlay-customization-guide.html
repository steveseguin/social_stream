Concevez vos propres superpositions de flux social

Téléchargez, personnalisez, connectez et testez les conceptions de superposition locales dans OBS, avec des guides pour chaque famille de superpositions.

Vous pouvez modifier les couleurs, les polices, la mise en page, les illustrations et le mouvement d'une page existante. Le Fichier HTML est la page ; le URL OBS le pointe et fournit les paramètres de session et d'affichage. Pour un petit restyle, utilisez le CSS personnalisé OBS sur la page hébergée. Pour des changements plus profonds, téléchargez la source et exécutez votre propre copie.

Ces guides couvrent les familles de superpositions, y compris leurs thèmes. Choisissez le destinataire pour la fonctionnalité que vous utilisez : une page de discussion, une page de messages sélectionnés et un sondage ne consomment pas tous la même entrée.

Pour une conception prête à l'emploi, commencez par Galerie d’incrustations ou Galerie de modèles. Pour un skin de discussion StreamElements/Streamlabs existant, suivez les guide d'importation. Le code HTML autonome importé possède ses propres instructions d'exportation/configuration.

1. Téléchargez les fichiers réels

  1. Télécharger le ZIP du code bêta, ou ouvrez le dépôt bêta et choisissez Code → Télécharger le code postal.
  2. Extrayez le ZIP dans un dossier que vous pouvez conserver, tel que C:\SSN\social_stream-beta\. Ne modifiez pas l’intérieur de l’archive compressée. Ce sont des fichiers source de page ; la modification d'une copie distincte ne nécessite pas de réinstaller SSN.
  3. Recherchez le fichier indiqué dans le tableau ci-dessus. Dupliquez-le à côté de l'original : par exemple poll.html devient my-poll.html. Pour themes/featured-styles/featured-modern.html, conservez la copie dans themes/featured-styles/.
  4. Ouvrez la copie dans un éditeur de texte/code. Donnez à votre outil d'IA l'accès à ce fichier et aux styles/scripts référencés dont il a besoin. Enregistrer le HTML sous .html, non .html.txt.

Conservez la structure des dossiers extraits. Un seul fichier HTML téléchargé peut charger des scripts, des feuilles de style, des polices, des images, de l'audio ou du JSON à côté. La vue de page de GitHub et la « page de sauvegarde » d'un navigateur ne constituent pas un ensemble complet et fiable. Chaque guide de type identifie les fichiers utiles, mais le dossier entièrement extrait constitue le moyen le plus simple de conserver les dépendances.

social_stream-beta/
    poll.html
    my-poll.html
    currency.js
    js/
    libs/
    shared/
    thirdparty/
    media/
    sources/images/
    themes/
        featured-styles/
            featured-modern.html
            my-featured.html
    docs/
        event-reference.html

Une référence telle que ../../shared/utils/chatHtml.js est relatif à la page qui le charge. Déplacer cette page vers la racine brise le chemin. Copiez également les illustrations et les polices locales dans le projet, puis utilisez des URL relatives. Conservez les versions téléchargées ensemble ; votre copie modifiée ne recevra pas automatiquement les futurs correctifs SSN.

2. Conserver les paramètres de session et de connexion

Démarrez SSN, connectez une source et confirmez que la superposition d'origine fonctionne. Copiez le lien généré complet à partir de l’outil SSN correspondant. La valeur après session= identifie votre session SSN ; il ne s'agit pas d'une chaîne YouTube, d'un nom d'utilisateur Twitch, d'un nom de fichier ou du titre du sondage.

https://socialstream.ninja/poll.html?session=YOUR_SESSION&password=YOUR_PASSWORD&server2

L'exemple utilise des espaces réservés. SSN et la page doivent utiliser la même session réelle et tout mot de passe configuré. Changer le nom du fichier ne change pas la session. Gardez SSN et capturez en cours d'exécution : une superposition reçoit les données ; il ne capture pas le chat de la plateforme par lui-même.

  • ? démarre la requête ; utilisation des paramètres ultérieurs &. Copiez les valeurs au lieu de les retaper. Dans un attribut source HTML, écrivez &amp;; dans le champ URL du navigateur/OBS, utilisez une esperluette ordinaire.
  • Conserver les paramètres de transport : server, server2, server3, les points de terminaison locaux, les étiquettes et les valeurs de version sont spécifiques à la page. N'ajoutez pas d'indicateur de serveur simplement parce qu'une autre superposition le prend en charge.
  • Préserver également les fragments : tout après # peut avoir de l'importance. AI Event Overlay, par exemple, utilise un #aieventauth=... afficher le jeton.
  • Utilisez des espaces réservés dans les exemples partagés. Gardez votre lien de session réel, votre mot de passe et vos jetons d'affichage privés hors des captures d'écran publiques, des référentiels et des exemples d'invites d'IA.

Lorsqu'une copie reste vierge, vérifiez d'abord le lien original généré. Certaines pages demandent des paramètres manquants ; d'autres restent cachés ou redirigés. Fournir explicitement la bonne session évite de s’appuyer sur ces valeurs par défaut spécifiques à la page.

3. Ouvrez votre fichier dans OBS

Ouvrez le HTML édité directement depuis votre ordinateur. Il n'y a aucun serveur à installer ou à démarrer.

  1. Faites glisser votre fichier HTML copié vers Chrome ou Edge. Copiez son adresse complète depuis la barre d'adresse ; ça commence par file:///.
  2. Copiez tout depuis ? dans votre lien de superposition SSN de travail et ajoutez-le à la fin de cette adresse de fichier. Cela conserve votre session, votre mot de passe, d'autres paramètres et tout # fin.
  3. Ouvrez l'adresse combinée dans votre navigateur pour la tester.
  4. Dans OBS, ajoutez une Source navigateur. Laissez Fichier local décochez la case et collez l'adresse complète dans URL. Définissez la largeur et la hauteur de votre conception.

Par exemple, ce lien SSN :

https://socialstream.ninja/poll.html?session=YOUR_SESSION&password=YOUR_PASSWORD&server2

devient cette adresse pour une copie de sondage téléchargée sous Windows :

file:///C:/SSN/social_stream-beta/my-poll.html?session=YOUR_SESSION&password=YOUR_PASSWORD&server2

Utilisez votre adresse de fichier réelle et les paramètres copiés. Sur macOS, l'adresse commence par file:///Users/...; sous Linux, cela commence généralement par file:///home/.... La copie de l'adresse du navigateur gère les espaces et les barres obliques pour vous.

Configurez ceci une fois. OBS enregistre l'adresse avec la source. Conservez le dossier téléchargé au même endroit et laissez SSN et votre source de discussion fonctionner lorsque vous utilisez la superposition. Après avoir enregistré une modification de conception, utilisez Actualiser le cache de la page actuelle dans les propriétés source.

Pourquoi laisser la case Fichier local décochée ? Le champ URL vous permet d'inclure ?session=.... La sélection du code HTML avec le sélecteur de fichiers seul n'ajoute pas ces paramètres.

Facultatif : cochez la case Fichier local avec un lanceur

Le sélecteur de fichiers de OBS choisit un fichier ; il n'ajoute pas vos paramètres de requête générés. Pour un récepteur basé sur une requête non modifié, un petit lanceur local peut accéder à la page modifiée avec les paramètres joints :

  1. Enregistrez ce qui suit sous launch-my-poll.html à côté de my-poll.html.
  2. Remplacez l'URL hébergée par l'espace réservé par votre lien SSN copié complet. Changement ./my-poll.html à votre nom de fichier modifié réel. Gardez le lien à l'intérieur des guillemets, avec des & .
  3. Double-cliquez sur le lanceur pour le tester. Dans OBS, sélectionnez Fichier local et choisissez le lanceur. Il redirige vers la superposition locale avec la requête et le fragment.
<!DOCTYPE html>
<html lang="en">
<meta charset="utf-8">
<title>My local overlay launcher</title>
<p>Opening the local overlay...</p>
<script>
var copiedLink = new URL("https://socialstream.ninja/poll.html?session=YOUR_SESSION");
var localPage = new URL("./my-poll.html", window.location.href);
localPage.search = copiedLink.search;
localPage.hash = copiedLink.hash;
window.location.replace(localPage.href);
</script>
</html>

Pour un thème imbriqué, placez le lanceur à côté de cette copie de thème. Gardez le lanceur privé car il contient votre lien de connexion. Une exportation autonome téléchargée qui intègre déjà sa configuration suit plutôt ses propres instructions d'exportation.

OBS documente ses modes fichier/URL, ses dimensions, son CSS personnalisé et ses contrôles d'actualisation dans le Référence de la source du navigateur.

4. Modifiez la conception ou demandez à l'IA de le faire

Pour une modification CSS uniquement, conservez le lien hébergé et utilisez celui de OBS. CSS personnalisé champ. Cela s'applique uniquement à cette source, donc un navigateur normal ouvrant la même URL n'affichera pas ces remplacements. Pour un fichier HTML modifié, ajoutez des remplacements après ses styles existants ou liez une feuille de style locale après eux. Fournissez votre logo, vos fichiers de polices, les couleurs de votre marque, la taille de la toile et une référence visuelle.

Certaines pages prennent en charge &css= ou &b64css=; le support est par page. poll.html, par exemple, ne lit ni l'un ni l'autre. Vérifiez l'analyseur de la page avant d'utiliser les options d'URL. Une page Web ne peut généralement pas charger une police ou une image arbitraire à partir du disque local d'un autre ordinateur.

Lors de la modification du balisage, conservez les ID/classes référencés par les scripts. Si JavaScript reconstruit un élément à chaque mise à jour, les illustrations permanentes doivent vivre en dehors de cet élément ou être recréées par le moteur de rendu. Copiez une feuille de style/un script partagé et modifiez la référence de votre page si vous souhaitez que la modification n'affecte que votre conception.

Utilisez l'invite spécifique au type dans les guides ci-dessus ou commencez par cette invite générale :

Customize [copied overlay filename] to match [reference/design].
Canvas: [width x height]. Placement: [position]. Colors/fonts: [details].
Use the existing page and its supporting files, rather than replacing its
connection and event logic. Read docs/event-reference.html and the relevant
overlay design guide. Preserve query parameters, session/password, URL
fragments, bridge labels, transport channels, settings, and controls.
Use CSS first. Keep relative paths and package all executable dependencies
locally. Use classic scripts compatible with Chrome 80.

Les guides de type décrivent le véritable déclencheur à préserver. N'acceptez pas une conception qui ne fonctionne que parce qu'elle code en dur des exemples de messages. Conservez une copie du fichier original et comparez l'affichage modifié en utilisant les mêmes entrées de test.

5. Empêcher les discussions entrantes de devenir du code

Les messages, noms, titres, montants, métadonnées et liens multimédias peuvent provenir de téléspectateurs ou de services externes. Désinfectez au point où le moteur de rendu personnalisé les insère. Une chaîne reçue via SSN ne constitue pas une autorisation pour l'exécuter. Utilisez du texte DOM brut pour les champs bruts ; utilisez le désinfectant fourni pour le code HTML pris en charge par le corps du message. Voir Explication de l'OWASP sur les puits sécurisés et la désinfection HTML.

Dans SSN, textonly s'applique uniquement à chatmessage. Lorsque c'est vrai, restituez ce corps sous forme de texte littéral. Sinon, il peut contenir des émoticônes et un formatage autorisé. Afficher les autres champs normaux sous forme de texte ; domaines médiatiques tels que chatimg et contentimg sont des URL/données, pas des extraits HTML.

<!-- Example for a copied page at the repository root. -->
<script src="./libs/objects.js"></script>
<script src="./shared/utils/chatHtml.js"></script>
<script>
function renderChatBody(element, data) {
    var message = String(data.chatmessage == null ? "" : data.chatmessage);
    if (data.textonly) {
        element.textContent = message;
    } else {
        element.innerHTML = SocialStreamChatHTML.sanitize(message);
    }
}
// Names, amounts, titles, and other plain fields use textContent:
// nameElement.textContent = String(data.chatname || "");
</script>

Conserver un désinfectant équivalent existant plutôt que d’en ajouter un deuxième. Pour les fichiers imbriqués, ajustez les chemins de script relatifs. Créez des avatars et des liens avec les propriétés DOM après avoir validé l'URL dans le cadre de la politique média/lien existante de la page. N'interpolez pas de noms bruts dans des chaînes d'attributs ni de couleurs brutes dans un balisage de style ; validez les styles avant de définir des propriétés individuelles. La désinfection HTML ne permet pas d'exécuter une chaîne en toute sécurité en tant que JavaScript ou instruction IA.

Testez le moteur de rendu dans un aperçu isolé

  • Utilisez un nom simple tel que Guest <b>One</b>: les crochets doivent rester du texte.
  • Essayez chatmessage: "<b>Hello</b>" avec textonly: true, alors faux. Le balisage littéral et le contenu formaté autorisé doivent suivre leurs chemins respectifs.
  • Vérifiez une emote prise en charge et un message contenant uniquement une image afin que les modifications de sécurité ne suppriment pas ces fonctionnalités.
  • Demandez à l'IA de tester une sonde inoffensive telle que <img src=x onerror="window.__ssnInjectionProbe=1"> dans le moteur de rendu modifié. Il ne doit pas s'exécuter, définir le marqueur ou laisser des attributs d'événement exécutables. Testez également un lien script-schéma. Exécutez des sondes localement, pas dans le chat public.

Une sonde de passage ne vérifie que les parcours exercés. Gardez les tests concentrés sur les moteurs de rendu et les champs modifiés par la conception.

6. Testez la disposition, la connexion et le OBS séparément

  1. Disposition : utilisent le mode aperçu/démo documenté de la page, lorsqu'il est disponible, ou des échantillons locaux fictifs. Testez les noms/messages longs, les avatars manquants, les données vides et le nombre de lignes attendu.
  2. Livraison SSN : garder SSN actif et utiliser Créer un message de test (Create Test Message) avec la même séance. Le mode d'ingestion habituel de l'API d'extension a besoin contrôle distant de l’extension par API (remote API control of extension) activé. Utilisez une configuration de test isolée ; les tests soumis peuvent déclencher des automatisations configurées.
  3. Le déclencheur réel : présentent un message Dock pour une carte en vedette, envoient un vote pour un sondage, sélectionnent un gagnant pour un cadeau, modifient le texte du téléscripteur pour un téléscripteur ou démarrent un chronomètre pour un chronomètre. Le chat simple n’est pas un test universel.
  4. Capture réelle : confirmer qu'un message/événement source réel atteint la page originale et modifiée. Un événement simulé prouve le rendu, pas la capture de plate-forme.
  5. OBS : vérifiez la source dans sa taille finale, sa transparence, ses animations, son audio, ses polices et sa superposition. Exercice afficher/masquer, effacer/réinitialiser et actualiser. Le navigateur et OBS ont un stockage et des sessions séparés ; la connexion au navigateur ou localStorage n’est pas automatiquement partagée.

Pour les pages qui collectent des données en mémoire, le déchargement ou l'actualisation peuvent perdre leur état. Consultez le guide de type avant d'activer l'actualisation automatique ou l'arrêt lorsqu'il est masqué. Les écrans gérés par l'hôte ont un comportement de récupération différent. Supprimer demo/preview signale avant d'attendre des données en direct.

Fichiers et références utiles pour donner à votre IA

  • docs/event-reference.html: champs canoniques, événements nommés, métadonnées, médias et valeurs de don.
  • docs/customoverlays.md: récepteurs personnalisés et exemples de connexion.
  • Compatibilité des événements et alertes: quels événements/champs une conception peut attendre d'une source.
  • Guide des messages de test et createtestmessage.html: exemples de charges utiles et de modes de livraison.
  • libs/objects.js et shared/utils/chatHtml.js: assainissement de l'affichage packagé.
  • shared/utils/chatBadges.js et shared/utils/contentImage.js: gestion des badges et des images existants.
  • js/transport-dedupe.js, js/local-server-url.js, et shared/overlay-control-transport.js: support de transport existant lors du chargement par votre page.
  • currency.js: préserver hasDonation pour afficher et honorer un USD numérique valide donoValue, dont zéro.
  • Event Flow et Commandes et API: réutiliser les contrôles existants lorsque la conception nécessite un déclencheur.

Donnez la source réelle de la superposition et son CSS/JS référencé ainsi que ces documents. Une référence d'événement à elle seule ne décrit pas l'état de contrôle d'un sondage ni la structure de rendu privée de chaque superposition.

Quand la copie ne fonctionne pas

SymptômeVérifiez
Fichier introuvableFaites glisser à nouveau le code HTML dans votre navigateur et copiez son adresse de fichier actuelle. Vérifiez que le nom du fichier se termine par .html et non par .html.txt.
Script, police ou image manquantConservez la structure des dossiers extraits intacte, avec la copie modifiée à côté de l'original. Vérifiez que toutes les illustrations et polices ajoutées se trouvent dans les dossiers attendus.
Affichage vide ou « en attente »Vérifiez la session, le mot de passe, la requête/fragment complet, l'état d'exécution de SSN, la fonctionnalité activée et l'entrée correspondante. Comparez l'URL générée d'origine.

Le logo disparaît lors de la mise à jourLe moteur de rendu peut remplacer son conteneur. Placez une décoration permanente à l'extérieur ou mettez à jour le modèle de rendu.
L'état est réinitialisé ou les actions se déclenchent deux foisVérifiez les paramètres d'actualisation/déchargement, les instances de sortie/contrôle en double et le comportement de déduplication/état existant de la page.
Cas particulier : pages lisant des fichiers de données séparés

La carte lit les fichiers JSON locaux avec fetch(), qu'un navigateur peut bloquer lors de l'ouverture à partir du disque. Pour un simple restyle de carte, utilisez son lien hébergé avec le CSS personnalisé OBS. Pour une copie HTML modifiée, demandez à votre IA d'inclure les données cartographiques requises dans la page afin qu'elle s'ouvre directement à partir du disque. L'hébergement est une option avancée pour une page qui en a spécifiquement besoin, et non une étape de configuration normale pour ces superpositions.

Arrêtez-vous au moindre problème confirmé. Un restyle ne devrait pas nécessiter de modifier les scripts de capture ou d'inventer de nouveaux champs d'événements. Si vous partagez un fork public, incluez ses actifs de support et excluez les lanceurs privés de ce téléchargement.
