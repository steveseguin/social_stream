Relayer le chat entre plateformes

Configurez un relais volontaire entre Twitch et YouTube, choisissez les expéditeurs et diagnostiquez les messages répétés.

Tous les guides 1. Vérifiez que les deux chats peuvent recevoir des réponses 2. Créez Twitch → YouTube dans Event Flow 3. Ajoutez le sens retour 4. Comprenez les échos 5. Limitez ce que vous relayez Dépannage

1. Vérifiez que les deux chats peuvent recevoir des réponses

Connectez vos chats Twitch et YouTube Live à la même session SSN. Vérifiez qu’ils apparaissent dans le Dock, puis envoyez une réponse manuelle à chacun depuis un message dont l’onglet source est connu. Utilisez vos propres chaînes de test. Une source en lecture seule ne peut pas envoyer de relais.

N’ouvrez que les chats de destination prévus pour cette configuration. Une destination de plateforme peut inclure plusieurs onglets sources admissibles. Si vous utilisez un compte bot Twitch distinct, effectuez Comptes de bot pour les réponses d’abord.

2. Créez Twitch → YouTube dans Event Flow

Ouvrez : Éditeur Event Flow depuis le menu SSN (également lié dans la section d’incrustation Actions). Créez un flux et donnez-lui un nom clair, par exemple Twitch vers YouTube.

  1. Ajoutez un Depuis la source (From Source) comme déclencheur depuis Utilisateur et source (User & Source). Choisissez Twitch comme source.
  2. Ajoutez un Relayer le chat (Relay Chat) et reliez la sortie du déclencheur à l’entrée de l’action.
  3. Sélectionnez cette action. Réglez Destination du relais (Relay Destination) à YouTube, et gardez le modèle de message [{source}] {username}: {message}.
  4. Sélectionnez Enregistrer le flux (Save Flow) et activez le flux enregistré. Gardez SSN actif.
  5. Envoyez un nouveau message normal dans votre chat Twitch de test. Confirmez qu’une seule copie étiquetée arrive dans YouTube.

YouTube Shorts a son propre type de source et sa propre destination. Choisissez YouTube Shorts selon le cas ; ce n’est pas interchangeable avec YouTube.

3. Ajoutez le sens retour

Créez un second flux nommé YouTube vers Twitch: Depuis la source : YouTube → Relayer le chat : Twitch. Enregistrez-le et activez-le. Envoyez un nouveau message de chaque côté et confirmez que chacun produit une seule copie sur l’autre plateforme.

Gardez Relayer tous les messages (DÉCONSEILLÉ !) désactivé avec ces flux, pour qu’un second système de relais ne fasse pas le même travail. Vérifiez aussi si un autre bot ou service multistream relie déjà les chats.

4. Comprenez les échos

Un écho est un message envoyé par SSN puis recapturé dans le chat de destination. Les actions Relay Chat actuelles ignorent automatiquement les échos reconnus. Elles excluent aussi l’onglet d’origine.

Pour masquer l’écho capturé dans le Dock et les incrustations, ajoutez une action Filtre d’échos (Reflection Filter) au début du flux concerné et sélectionnez Tout bloquer (Block All). Autoriser le premier (Allow First) conserve un écho correspondant dans la fenêtre configurée ; Tout autoriser (Allow All) les affiche. Cela contrôle l’affichage après capture, pas la destination du relais.

Les propriétés actuelles de Relay Chat n’ont pas de case « No Reflections ». Utilisez le filtre d’échos séparé pour contrôler l’affichage. Si un service externe réécrit un message relayé, la reconnaissance automatique peut le manquer.

5. Limitez ce que vous relayez

Pour les commandes, ajoutez un Le message commence par (Message Starts With) comme déclencheur réglé sur ! et reliez-le à travers une porte NOT ; combinez ce résultat avec votre condition de source à l’aide de AND avant Relay Chat. Consultez le guide Event Flow pour relier les portes logiques. Testez une ligne normale et une commande.

Si vous préférez le relais global plus simple, utilisez Paramètres et outils globaux → Commandes → Choisir les destinations du relais et entrez twitch,youtube. Une liste vide signifie toutes les destinations admissibles. Cette liste contrôle les destinations, pas les plateformes entrantes pouvant déclencher un relais. Désactivez les deux flux de relais Event Flow avant d’activer cette alternative.

Les champs d’autorisation/blocage des rôles de compte de SSApp, dans la même section Commandes, peuvent limiter les comptes qui envoient les relais. Utilisez le rôle de l’expéditeur prévu ; un rôle sans correspondance peut ne laisser aucune destination admissible.

Dépannage

  • Rien n’est envoyé : retentez une réponse manuelle, vérifiez la connexion et le droit de publier, activez le flux enregistré et contrôlez les restrictions de destination et de rôle.
  • Les messages se multiplient : désactivez d’abord les flux de relais. Recherchez des sources de capture en double, le relais global et des bots externes avant de retester un seul sens.
  • Seul le Dock affiche des doublons : vérifiez la politique d’affichage du filtre d’échos et les paramètres globaux d’écho de Message - Visibilité.
  • Mauvaise destination YouTube : vérifiez YouTube contre YouTube Shorts et fermez les chats admissibles non souhaités.

Les actions Test Flow peuvent envoyer de vrais messages. Utilisez des destinations contrôlées ; un test synthétique ne prouve pas le routage des comptes de la source réelle.
