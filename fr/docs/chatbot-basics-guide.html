Configurer et utiliser le bot de chat IA

Connectez un fournisseur IA, activez le bot principal, testez prudemment et résolvez les réponses manquantes.

Comprendre les trois parties distinctes

Un fournisseur IA fonctionnel n’est que la première partie d’un bot de chat en direct. Le fournisseur, le bot principal et la destination des réponses doivent chacun être configurés.

PartieFonctionCe que cela ne prouve pas
Fournisseur IAGénère du texte avec Ollama, une API hébergée ou un autre service compatible.Que le chat en direct est capturé ou que des réponses peuvent être publiées.
Bot principal de chatDécide quels messages capturés en direct doivent recevoir une réponse IA.Que la plateforme ou le compte autorise les réponses.
Destination des réponsesPublie les réponses générées sur le canal de sortie du bot et peut aussi les envoyer via la source de chat capturée.Ce bot.html est ouvert ou qu’un compte bot distinct a été créé sur la plateforme.

Important : un résultat vert Connecté le résultat confirme seulement que le fournisseur et le modèle choisis ont répondu à un prompt de test.

1. Configurer un fournisseur IA

  1. Ouvrez les paramètres Social Stream et développez Bots de chat et services IA.
  2. Ouvrir Configurer le fournisseur LLM.
  3. Choisissez le fournisseur correspondant au service que vous utilisez réellement.
  4. Renseignez le point de connexion, le nom du modèle, la clé API ou les autres champs affichés pour ce fournisseur.
  5. Sélectionnez Tester le bot de chat sélectionné et confirmez qu’une vraie réponse textuelle apparaît sous le bouton.
  • Ollama (API locale native) : utilisez ceci uniquement pour Ollama. Le point de connexion local habituel est http://localhost:11434.
  • API personnalisée : utilisez ceci pour les serveurs compatibles OpenAI, comme llama.cpp, LM Studio, vLLM et services similaires.
  • Fournisseur hébergé : entrez la clé API et le modèle requis par ce fournisseur. Les coûts, quotas et noms de modèles sont gérés hors de Social Stream Ninja.
  • Modèle local dans le navigateur : utilisez l’option Local Gemma ou Local Qwen correspondante et suivez ses consignes de fichiers de modèle.

Besoin d’installer Ollama d’abord ? Utilisez la page officielle de téléchargement d’Ollama. Pour la liste complète des fournisseurs, consultez Intégration IA dans Commandes et API.

Maintien en mémoire d’Ollama : 0 décharge le modèle après une requête. Cela ne désactive pas le bot, mais chaque réponse suivante peut nécessiter un nouveau démarrage à froid.

Configuration API OpenAI / ChatGPT

Utilisez une clé API OpenAI standard pour les appels de modèles. Une clé Admin est destinée aux points d’administration de l’organisation, pas aux appels ordinaires. La clé doit appartenir au projet à facturer et ses droits effectifs doivent autoriser les requêtes aux modèles.

  1. Créez ou vérifiez la clé dans la page des clés API d’OpenAI Platform. Ne collez jamais la clé dans un message d’assistance ou un rapport de diagnostic.
  2. Dans Social Stream, sélectionnez API ChatGPT, collez la clé complète, indiquez un modèle disponible dans ce projet et sélectionnez Tester le bot de chat sélectionné.
  3. Si le test indique Status: 401, Code: missing_scope, et Missing scope: model.request, OpenAI a rejeté l’identifiant car ses droits effectifs n’incluent pas les requêtes aux modèles. model.request est une autorisation nommée par le serveur, pas un réglage à ajouter au prompt ou au nom du modèle.
  4. Vérifiez qu’il s’agit d’une clé API de projet standard, que le projet voulu est sélectionné et que la clé est sans restriction ou explicitement autorisée à appeler des modèles. En cas de doute, créez une nouvelle clé standard dans le bon projet et remplacez celle enregistrée dans Social Stream.
  5. Si la traduction automatique du navigateur est active sur OpenAI Platform et que les autorisations ou leurs libellés se comportent mal, repassez à la page anglaise d’origine avant de vérifier et d’enregistrer les paramètres de clé. Cela a aidé dans un cas signalé, mais ce n’est pas une cause universelle documentée des erreurs OpenAI 401.

Les crédits et les autorisations sont distincts : ajouter du crédit API ne donne pas une autorisation manquante à la clé. OpenAI documente les identifiants invalides et les permissions des points d’accès comme des erreurs 401, tandis qu’un quota épuisé est normalement une erreur 429. Consultez le guide des erreurs API et référence d’authentification.

Si l’erreur continue, copiez l’état, le code, l’autorisation manquante et le Request ID affichés par Social Stream, puis envoyez le rapport de diagnostic intégré peu après avoir reproduit le problème. Le rapport conserve des métadonnées sûres, sans clés API ni contenu des prompts. Donnez le Request ID et l’horodatage à l’assistance OpenAI si les paramètres de clé et de projet semblent corrects.

3. Effectuer un test complet prudent

  1. Activez Social Stream et confirmez que la source en direct est ouverte.
  2. Envoyez un message normal depuis un second compte spectateur directement dans le chat de la plateforme source, comme YouTube ou Twitch, et vérifiez qu’il apparaît dans le Dock Social Stream. Pour ce premier test, n’utilisez pas un message saisi dans le Dock ou les commandes de chat de l’hôte : les échos de bot ou d’hôte peuvent être ignorés pour éviter les boucles de réponses.
  3. Vérifiez que le test du fournisseur indique Connecté.
  4. Utilisez les réglages de premier test du bot principal ci-dessus, dont le mode incrustation uniquement.
  5. Ouvrez : bot.html lien affiché sous Page d’incrustation et synthèse vocale du bot. Utilisez le lien généré pour conserver la même session.
  6. Depuis le compte spectateur, envoyez : NinjaBot, reply with exactly: Hello.
  7. Envoyez le test une seule fois et attendez. Un modèle local peut encore être en chargement, et les messages suivants peuvent être ignorés pendant qu’une réponse est en cours.

Pourquoi utiliser un second compte ? Cela ressemble davantage à un vrai spectateur et évite de confondre le compte qui envoie les réponses avec celui qui envoie le test.

Une fois le test d’incrustation réussi, remettez Ne filtrer aucune réponse du bot sur désactivé, choisissez un déclencheur et un délai, puis décidez si les réponses vers la plateforme doivent être activées.

4. Savoir quand le silence est normal

Le bot principal est sélectif par défaut. Une liste de déclencheurs vide signifie que chaque message admissible peut être examiné, pas que chaque message doit recevoir une réponse.

  • Une salutation courte comme hello peut être ignorée si le modèle estime qu’une réponse n’ajoute rien.
  • S’adresser directement au nom personnalisé du bot rend l’intention plus claire.
  • Un déclencheur configuré doit correspondre au message entrant.
  • Le mode modérateur uniquement ignore les messages qui ne sont pas marqués comme venant d’un modérateur.
  • Quand les réponses vers la plateforme sont activées, le délai par défaut est de cinq secondes par source. La limite de parallélisme par défaut est une réponse, dans tous les modes.
  • Les messages identifiés comme sortie de bot, échos, messages vides ou trop proches de la réponse précédente peuvent être ignorés.

5. Choisir la destination des réponses

ModeRésultatConditions requises
Incrustation uniquement activéeLes réponses vont sur le canal de sortie du bot et ne sont pas renvoyées au chat de la plateforme.Ouvrir bot.html avec la même session pour les voir ou les entendre. La synthèse vocale nécessite également cette page.
Incrustation uniquement désactivéeLes réponses vont toujours sur le canal du bot, et Social Stream tente aussi de les publier via la source capturée d’origine.Le mode de source doit permettre l’envoi, le compte doit être connecté et autorisé à publier, le chat de l’hôte ne doit pas être désactivé et la source doit rester ouverte. bot.html reste facultatif sauf si vous voulez l’incrustation ou la synthèse vocale.

Le nom personnalisé du bot est un préfixe de message ; il ne crée pas de compte de plateforme. Sauf routage par rôle configuré dans l’application autonome, les réponses sont publiées avec le compte de la source capturée.

Les utilisateurs de l’application autonome voulant une identité Twitch distincte peuvent suivre le guide du compte bot Twitch.

6. Effacer et masquer automatiquement les réponses

Ces commandes concernent la page du bot principal, bot.html. Elles n’effacent pas l’incrustation principale de messages en vedette.

OptionSignificationExemple
showtimeUtilise une durée d’affichage fixe en millisecondes.&showtime=10000 masque après 10 secondes.
autohideEstime la durée d’affichage à partir du nombre de mots de la réponse. autotime est également accepté.&autohide
mintime / maxtimeDéfinit les durées minimale et maximale selon la longueur. Valeurs par défaut : 4 000 et 30 000 millisecondes.&autohide&mintime=5000&maxtime=20000
hideafterttsGarde la réponse visible jusqu’à la fin de la synthèse vocale, puis la masque. Si la lecture ne démarre jamais, une durée basée sur la longueur est utilisée.&hideaftertts
hidedelayAjoute un délai après la fin de la synthèse vocale. Valeur par défaut : 500 millisecondes.&hideaftertts&hidedelay=1000
ttstimeoutDélai de sécurité si la synthèse vocale reste active indéfiniment. Valeur par défaut : 120 000 millisecondes.&hideaftertts&ttstimeout=60000

Si plusieurs modes sont activés, hideaftertts a la priorité, suivi de autohide, puis showtime. Les paramètres du lien généré de l’incrustation du bot proposent les options courantes.

Effacer manuellement

  • Dans les paramètres Social Stream, sélectionnez Effacer l’incrustation du bot maintenant.
  • Avec le contrôle distant par API activé, ouvrez https://io.socialstream.ninja/SESSION_ID/clearBotOverlay.
  • Sur le WebSocket de l’API, envoyez {"action":"clearBotOverlay"}.

L’effacement manuel retire la réponse visible et la file d’affichage en attente du bot, mais n’arrête pas la parole déjà en cours.

Style personnalisé : le CSS personnalisé utilisé avec le lien généré normal bot.html le lien conserve ces fonctions. Un fichier local copié ou modifié bot.html le fichier doit être mis à jour pour recevoir les corrections ultérieures de la page.
