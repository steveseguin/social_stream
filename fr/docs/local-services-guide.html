Comprendre les serveurs et services locaux

Social Stream Ninja utilise plusieurs services locaux différents. Choisissez celui qui correspond à ce que vous souhaitez faire.

1. Activer le serveur local

Cette option du menu Fichier démarre un relais WebSocket prenant en compte les salons et canaux dans l'application de bureau. Les pages Social Stream prises en charge peuvent l'utiliser pour échanger du chat et des commandes sur le même ordinateur. C'est un autre point de terminaison pour le routage serveur propre à chaque page.

Il n'héberge pas le site Social Stream, ne capture pas de plateforme à lui seul et ne fournit pas l'API HTTP d'automatisation. Commencez par le Guide Enable Local Server.

2. API de contrôle local et MCP

Cette API locale de bouclage, à activer, permet aux programmes de l'ordinateur SSApp de gérer les sources et paramètres pris en charge, de lire l'état et les diagnostics, d'inspecter les fenêtres de l'application ou des sources et de suivre les événements capturés. L'adaptateur MCP inclus présente ces opérations comme outils aux clients IA compatibles.

Activez-le sous Fichier > IA locale / Automatisation (File > Local AI / Automation). Il est distinct de Activer le serveur local (Enable Local Server). Consultez le Guide de l'API de contrôle local et de MCP.

3. Serveur domestique ou VPS sans interface

Le mode sans interface exécute l'application de bureau Electron complète en masquant ses fenêtres de sources. Sous Linux, il nécessite toujours un système d'affichage tel que Xvfb. Cela est utile lorsqu'un ordinateur dédié doit continuer à capturer le chat sans moniteur connecté.

Le mode sans interface ne crée pas d'API de contrôle publique. Le contrôle à distance utilise le transport WebRTC ou WebSocket normal de Social Stream. Consultez le guide d'hébergement sans interface.

4. Serveur multimédia local

L'application de bureau le démarre automatiquement lorsque des médias Event Flow locaux sont disponibles. Il sert uniquement les fichiers approuvés via SSApp et certaines ressources d'exécution via un chemin à jeton aléatoire propre au profil.

Ce n'est pas un serveur web ou de fichiers généraliste. Voir Fichiers multimédias pour Event Flow pour choisir entre fichiers locaux, téléversements et hébergement cloud.

Le repli serveur est différent

Des paramètres tels que Envoyer les messages de chat au serveur API et Le Dock envoie ses commandes à l'extension via le serveur choisissent le routage du chat et des commandes. Les options URL générées comprennent server, server2, et server3.

Ces paramètres utilisent normalement le service WebSocket hébergé de Social Stream. Lorsqu'une page prise en charge possède aussi localserver, elle utilise à la place le relais local de l'application de bureau. Voir Sessions, mots de passe, relais et modes serveur pour les commandes de routage.

Utilisez des liens fraîchement générés. Les options de routage sont propres aux pages. Ne copiez pas une option serveur d'une page à l'autre en supposant qu'elle a la même signification.

Autres ports locaux temporaires

Certains flux de connexion et d'association de compte ouvrent brièvement un port de rappel local de bouclage et le ferment à la fin. Ces écouteurs temporaires ne sont pas des serveurs SSN généralistes ni des API d'automatisation.
