Créer des messages de test

Envoyez des messages et événements fictifs contrôlés dans votre session Social Stream.

Fonction de cet outil

Le page Créer un message de test envoie des données Social Stream synthétiques à votre dock, vos incrustations, vos alertes ou votre configuration Event Flow. Utilisez-le pour tester sans attendre un vrai message, don, abonnement, raid, récompense ou autre événement.

Utilisez une session de test lorsque c’est possible. Un message envoyé se comporte comme le trafic entrant de la session et peut déclencher des alertes, des sons, des webhooks, des actions OBS ou d’autres automatisations.

Démarrage rapide avec SSApp ou l’extension

  1. Ouvrez Social Stream Ninja et assurez-vous que le service est actif.
  2. Sous Paramètres et outils globaux → Mécanismes (Mechanics), activez contrôle distant de l’extension par API (remote API control of extension). SSApp utilise le même nom de paramètre.
  3. Copiez votre identifiant de session depuis Social Stream ou depuis le paramètre session= dans l’URL de votre dock ou incrustation.
  4. Ouvrir Créer un message de test (Create Test Message) et saisissez cet identifiant de session.
  5. Laissez Envoyer via (Send Via) défini sur Réception via l’API de l’extension (Extension API ingest) pour les tests ordinaires.
  6. Choisissez un préréglage, ajustez ses champs et sélectionnez Charger le préréglage (Load Preset).
  7. Vérifiez les données JSON, puis sélectionnez Envoyer (Submit).
  8. Vérifiez que l’élément apparaît dans le dock ou l’incrustation cible et que l’automatisation attendue s’exécute.

Vous pouvez inclure la session dans l’URL : createtestmessage.html?session=YOUR_SESSION_ID.

Exemple : un faux message de 1 000 KICKs

Cela crée un seul message de soutien de type Kick d’une valeur de 1 000 KICKs. Cela ne crée pas 1 000 messages distincts.

  1. Choisissez le préréglage Message de chat (Chat Message) .
  2. Définissez Tapez à Kick.
  3. Saisissez un nom et un message de test.
  4. Définissez Montant du don (Has Donation) à 1000 KICKs.
  5. Sélectionnez Actualiser le JSON depuis les champs (Update JSON from Fields), vérifiez le JSON et envoyez-le.

Les données minimales sont :

{
  "type": "kick",
  "chatname": "Test Supporter",
  "chatmessage": "Thanks for the stream!",
  "hasDonation": "1000 KICKs"
}

Utilisez Message de chat (Chat Message) pour cet exemple. Le préréglage Don / Cheer (Donation / Cheer) comprend des champs de cheer propres à Twitch.

Utiliser les préréglages et du JSON personnalisé

Les préréglages fournissent des données de départ pour les cas courants : dons, abonnés, abonnements offerts, raids, récompenses, mises à jour du nombre de spectateurs, nouveaux participants et événements de train.

  • Charger le préréglage (Load Preset) remplace le JSON par le préréglage sélectionné et les valeurs actuelles des champs.
  • Actualiser le JSON depuis les champs (Update JSON from Fields) construit un message de base à partir des champs visibles.
  • Vous pouvez modifier Données JSON (Payload JSON) directement pour tester un champ ou une structure d’événement précis.
  • hasDonation contient le montant de soutien affiché, par exemple 1000 KICKs ou $10.00.
  • N’incluez event que pour tester un véritable événement nommé. Une ligne de chat ordinaire de type don peut utiliser hasDonation seul.

Pour la définition des champs et de véritables exemples de plateformes, consultez la Référence des événements.

Choisir le bon mode d’envoi

Direct vers le canal 1 (Direct to channel 1)Le dock cible a été ouvert avec &server.La cible doit écouter le canal de serveur correspondant.
Direct vers le canal 4 (Direct to channel 4)Tester une cible utilisant &server2, y compris les pages d’événements compatibles.La cible doit écouter le canal de serveur correspondant.

En cas de doute, utilisez Réception via l’API de l’extension (Extension API ingest).

Solutions courantes

  • Rien n’apparaît : vérifiez que la page cible est ouverte et utilise le même identifiant de session.
  • La réception via l’API de l’extension échoue : activez contrôle distant de l’extension par API (remote API control of extension), puis rechargez le dock ou l’incrustation et réessayez.
  • Le mode direct indique un envoi, mais rien n’apparaît : utilisez Extension API ingest sauf si l’URL cible contient le paramètre correspondant &server ou &server2 comme mode.
  • Le mauvais événement se déclenche : examinez les données JSON pour trouver d’éventuels champs restants d’un autre préréglage.
  • Le test Kick se comporte comme Twitch : utilisez le préréglage Chat Message et réglez type et hasDonation comme indiqué ci-dessus.
  • Une automatisation s’exécute plusieurs fois : vérifiez si plusieurs docks, pages d’actions ou instances Event Flow sont ouverts sur la même session.
