Compatibilité des événements et alertes

Connectez les événements de plateforme capturés à Multi Alerts sans confondre le chat ordinaire, les dons et les données d'événement.

Commencez par la source d'événements

Multi Alerts affiche les événements déjà capturés par Social Stream. Il ne se connecte pas lui-même à Twitch, Kick, YouTube, TikTok ni à une autre plateforme.

  1. Connectez et activez la source de plateforme qui fournit l'événement.
  2. Gardez cette page source ou cette fenêtre source de l'application autonome active.
  3. Utilisez le même identifiant de session Social Stream dans la source, la fenêtre, le Dock et l'URL Multi Alerts.
  4. Testez l'incrustation d'alertes depuis ses options avant de résoudre les problèmes de connexion à la plateforme.

Un aperçu réussi prouve que la disposition de l'alerte fonctionne. Cela ne prouve pas que la source de plateforme a l'autorisation de recevoir cet événement en direct.

Mode standard et mode WebSocket

PlateformeCapture standardCapture WebSocket / API
YouTube Messages payants, abonnements, abonnements offerts, mises à jour de spectateurs et quelques événements détectés sur la page. Les événements payants et d'abonnement communs, plus les étapes marquantes des membres, les alertes d'abonnés publics récents et les mises à jour de compteurs prises en charge.
Twitch Récompenses affichées dans le chat, avis d'abonnements offerts, mises à jour de spectateurs et quelques avis propres à la page. EventSub ajoute les nouveaux followers, abonnements, renouvellements, Cheers, raids, récompenses et événements de compteur/d'état pris en charge lorsque le compte et les autorisations le permettent.
Kick Chat et marqueurs légers de page pour les cadeaux, récompenses et mises à jour de spectateurs. Événements officiels de suivi, abonnement, cadeau, utilisation de récompense, KICKs, modération et état du direct après authentification.

Le mode WebSocket est généralement le bon choix pour les alertes déclenchées par des événements. La capture standard reste utile lorsque seul le chat affiché est nécessaire ou que l'authentification est indisponible.

Activez les types d'alertes souhaités

Ouvrez les options Multi Alerts depuis les paramètres Social Stream. Les nouveaux followers, abonnements, dons, bits et raids ont leurs propres commandes d'activation, de style, de son et d'apparence. Les alertes d'enchères et de Hype Train nécessitent l'activation de leurs commandes dédiées.

  • Utilisez Mettre les alertes en file d'attente lorsque plusieurs événements peuvent arriver ensemble.
  • Vérifiez les filtres de source si les événements fonctionnent dans le Dock mais pas dans Multi Alerts.
  • Vérifiez les filtres de montant minimum de dons si de petits pourboires ou Cheers manquent.
  • Interagissez une fois avec la page du navigateur si le son personnalisé de l'alerte est bloqué par les règles de lecture automatique.

Prévisualisez avant de passer en direct

Utilisez les commandes d'aperçu pour vérifier la catégorie sélectionnée, le texte, le montant, les médias, le son, l'animation et le comportement de la file d'attente.

Lorsqu'une alerte réelle manque

  1. Vérifiez que la source a reçu l'événement dans son propre journal, dans le Dock ou dans sa sortie API.
  2. Vérifiez que la source et la page Multi Alerts utilisent le même identifiant et mot de passe de session.
  3. Vérifiez que cette catégorie est activée et n'est pas exclue par les filtres de source ou de chaîne.
  4. Vérifiez les filtres de valeur minimale des dons et des bits.
  5. Pour Twitch ou Kick, reconnectez-vous si le chat fonctionne mais pas les événements protégés.
  6. Gardez la fenêtre source active assez longtemps pour observer un événement réel ; un aperçu seul ne constitue pas un test complet de la plateforme.

Si plusieurs appareils ou modes de connexion sont utilisés, consultez Sessions, mots de passe et modes de relais.
