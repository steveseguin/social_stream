Une mémoire nommée, plusieurs outils

Un Mémoire utilisateur (User Memory) possède un ensemble isolé de personnes. Chaque nœud Remember, Forget, Check, Draw ou Clear sélectionne ce nœud d’état. Créez un autre nœud User Memory pour une liste distincte, par exemple une pour les personnes ayant aimé le direct et une pour les participants au concours.
Turquoise plein : cet événement s’exécute ensuite Violet pointillé : ce nœud utilise cette mémoire

Faites glisser le petit losange violet latéral sur un nœud User Memory, ou choisissez la mémoire par son nom dans les propriétés du nœud. L’opération conserve en interne l’identifiant du nœud d’état. Sélectionner la mémoire met en évidence les opérations liées ; sa suppression avertit avant de rompre les liens.

Configuration

  1. Faites glisser Nœuds d’état → Mémoire utilisateur (State Nodes → User Memory) sur le canevas.
  2. Nommez-la selon la liste qu’elle contient, par exemple Admissibles Heart Me (Heart Me Eligible), A aimé le direct (Liked Stream), ou Participants au tirage (Prize Draw Entrants).
  3. Choisir Cette session de l’application ou Conserver entre les redémarrages (Save across restarts).
  4. Ajoutez les vérifications et actions nécessaires, puis reliez chacune à la mémoire nommée avec son losange latéral ou sa liste déroulante.
  5. Reliez le chemin normal des événements avec les fils turquoise et utilisez Tester le flux (Test Flow) avec deux noms d’utilisateur différents avant le direct.

Opérations disponibles

NœudFonction
Mémoriser l’utilisateur (Remember User)Ajoute une seule fois l’utilisateur de l’événement actuel. Les participations répétées augmentent son compteur de participation sans créer de doublons dans le tirage.
L’utilisateur est mémorisé (User Is Remembered)Déclencheur/vérification renvoyant true lorsque le message actuel appartient à une personne de la mémoire sélectionnée.
Oublier l’utilisateur (Forget User)Retire uniquement l’utilisateur de l’événement actuel.
Choisir un utilisateur au hasard (Pick Random User)Sélectionne un utilisateur unique mémorisé. Peut retirer le gagnant pour l’empêcher de gagner à nouveau.
Effacer tous les utilisateurs (Clear All Users)Vide uniquement l’objet User Memory sélectionné.
Réinitialiser un nœud d’état (Reset State Node)Vide aussi une User Memory lorsque celle-ci est la cible de réinitialisation sélectionnée.
Règle d’identité : les utilisateurs sont identifiés par la plateforme et leur identifiant utilisateur. Le nom affiché sert uniquement de repli. Un événement anonyme ou agrégé sans identité utilisateur est ignoré sans risque.

Recettes pratiques

TikTok Heart Me ou Team Member → ? Synthèse vocale

Utilisez l’événement de cadeau pour mémoriser son expéditeur ; ne transformez pas cette seule ligne de cadeau en rôle permanent de « membre ».

Événement cadeau TikTok + correspondance « Heart Me » → AND → Remember User ···→ [Heart Me Eligible]
? commande + source TikTok + (TikTok Team Member OR User Is Remembered) → AND → Speak Text ? commande + NOT source TikTok → AND ────────────────────────────────→ Speak Text
  • Pour le statut TikTok Team/Fan, choisissez Rôle utilisateur → Membre d’équipe TikTok (User Role → TikTok Team Member). Cette option lit directement les badges/niveaux TikTok entrants ; le réglage d’affichage « treat as members » de Main Chat Overlay n’est pas nécessaire.
  • Les données de cadeaux varient selon le mode de capture. Une configuration courante est Event Type → Other : gift plus Le message contient : Heart Me (Message Contains: Heart Me). Vérifiez la ligne capturée dans Test Flow/Event Reference et utilisez le champ le plus fiable fourni par votre source.
  • Les deux branches exigent toujours le préfixe ?, pour que les autres plateformes parlent pour tout le monde tandis que TikTok reste restreint.

Mémoriser les personnes ayant aimé ou participé

Event Type → Other : liked → Remember User ···→ [Liked Stream]

Cela fonctionne lorsque l’événement capturé de J’aime/participation nomme un utilisateur. Les mises à jour du nombre agrégé de J’aime n’identifient personne et ne peuvent donc pas être mémorisées. Utilisez une mémoire distincte par type de participation pour des vérifications ou tirages indépendants.

Tirage au sort avec participations uniques

Message Starts With !enter → Remember User ···→ [Prize Draw Entrants] Modérateur + Message Starts With !draw → AND → Pick Random User ···→ [Prize Draw Entrants] Modérateur + Message Starts With !resetdraw → AND → Clear All Users ···→ [Prize Draw Entrants]

Activer Retirer l’utilisateur sélectionné (Remove selected user) pour empêcher qu’un gagnant soit tiré deux fois. Pendant une diffusion publique, protégez les commandes de tirage/réinitialisation par une vérification de modérateur, d’administrateur ou d’utilisateur exact.

Réinitialisation et conservation

Manuel

Utilisez Effacer tous les utilisateurs maintenant (Clear All Users Now) dans les propriétés de la mémoire pendant la création/les tests.

Depuis un flux

Utilisez Effacer tous les utilisateurs (Clear All Users) ou le contrôle générique Réinitialiser un nœud d’état (Reset State Node), en sélectionnant la mémoire exacte.

Automatique

Effacez après inactivité, au démarrage ou à l’arrêt de la diffusion. La valeur 0 désactive la réinitialisation après inactivité.

Entre les redémarrages

Les mémoires de session sont vides au démarrage de l’application. Les mémoires sauvegardées sont rechargées jusqu’à l’effacement de cette mémoire précise.

« Tout effacer » a une portée précise : cela désigne tous les utilisateurs de la mémoire sélectionnée, et non tout l’état Event Flow, tous les tirages ou toutes les mémoires de Social Stream Ninja.

Utiliser les sorties de tirage et de participation

Les actions de mémoire ajoutent des champs au message pour permettre leur utilisation par Show Text, Send Message, un webhook ou des actions personnalisées en aval.

Dépannage

Le lien pointillé manqueSélectionnez l’opération et choisissez une cible User Memory, ou faites glisser son losange violet latéral vers la mémoire.
La même personne apparaît deux foisVérifiez si les événements proviennent de plateformes différentes. Plateforme + identifiant utilisateur crée volontairement des identités distinctes.
Un J’aime n’a ajouté personneL’événement ne contenait probablement aucune identité utilisateur. Examinez ses données ; des totaux agrégés ne peuvent pas devenir des participants nommés.
Une mémoire sauvegardée est réapparueUtilisez Clear All Users sur cette mémoire. Modifier un flux ou vider une autre mémoire ne l’efface pas.
Tout le monde peut exécuter la commande de tirage/réinitialisationAjoutez User Role : moderator/admin, ou une vérification exacte de l’animateur, dans une porte AND avant l’action.
