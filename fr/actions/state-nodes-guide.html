Guide pratique des nœuds d’état

Les nœuds d’état donnent une mémoire à Social Stream Ninja. Utilisez-les pour créer des délais, interrupteurs, compteurs, limitations de fréquence, listes de participants et tirages au sort au comportement prévisible.

Vue d’ensemble Interrupteur marche/arrêt (On/Off Switch) Compteur (Counter) Limiteur de fréquence (Rate Limiter) Mémoire utilisateur (User Memory) Solutions types Dépannage

01 · Repères rapides

Les outils d’état comportent un objet qui détient la valeur et des opérations qui la lisent ou la modifient :

Nœud d’état

  • Se trouve sur le canevas.
  • Contient la valeur : ON/OFF, compteur, horodatages ou utilisateurs.
  • Gate, Counter et Rate Limiter peuvent faire partie du chemin normal des événements.
  • User Memory est un point de mémoire partagé référencé par d’autres nœuds.

Action d’état

  • Placée en aval.
  • Lit ou modifie la valeur conservée : activer, ajouter +1, mémoriser, tirer au sort, réinitialiser, etc.
  • Peut se trouver n’importe où dans le flux ; choisissez simplement le nom du nœud correspondant.
Rappel : Ajoutez d’abord le nœud d’état, donnez-lui un nom unique, puis sélectionnez-le dans chaque opération correspondante. Sans ce nœud de base, les actions d’état n’ont rien à modifier.

02 · Interrupteur marche/arrêt (porte)

L’interrupteur est un contrôle booléen. Sur ON, les messages passent ; sur OFF, le flux s’arrête à ce nœud.

Idéal pour

  • Délais entre commandes de chat.
  • Interrupteurs manuels pour activer/désactiver les incrustations.
  • Plages de maintenance, pour suspendre des fonctions pendant les scènes de pause.

Actions principales

  • Set Gate State— basculer sur ON ou OFF.
  • Reset State Node— revenir à la valeur par défaut, généralement ON.

Exemple : délai de 15 secondes

!hello ──▶ Interrupteur (ON ?) ─▶ Envoyer une réponse ─▶ Porte : OFF ─▶ Délai 15 s ─▶ Porte : ON

Étapes de création

  1. Ajoutez l’interrupteur, nommez-le « helloCooldown » et activez-le par défaut.
  2. Reliez votre déclencheur → interrupteur → actions.
  3. Après votre action, ajoutez un nœud Définir l’état de la porte (Set Gate State) (OFF) référençant « helloCooldown ».
  4. Ajoutez un Délai (Delay) (15 secondes).
  5. Ajoutez une autre action Définir l’état de la porte (Set Gate State) (ON) pour « helloCooldown ».

03 · Compteur

Les compteurs conservent des nombres entre les messages. Ils s’incrémentent automatiquement au passage d’un message et leurs valeurs peuvent être ajustées manuellement avec des actions.

Incrément automatique : Chaque passage de données dans le nœud Counter ajoute 1, sauf si vous le suspendez avec l’option « Only count when gate is true ».

Cas d’utilisation

  • Chaque énième participant déclenche un prix.
  • Suivre la progression vers un objectif communautaire.
  • Enregistrer les points échangés via des commandes.

Actions

  • Increment Counter— ajouter ou soustraire des quantités personnalisées.
  • Set Counter Value— passer à un nombre précis.
  • Reset State Node— revenir à la valeur initiale par défaut.

Exemple : célébrer tous les 5 messages

Tout message ─▶ Compteur (nom : hype5) ─▶ Condition (value % 5 === 0 ?) ─▶ Lancer la célébration

Dans le nœud Condition, comparez state.hype5.value ou utilisez simplement l’option intégrée « Trigger when value matches Target » des propriétés du compteur.

04 · Limiteur de fréquence

Le limiteur mémorise les horodatages et refuse les nouveaux événements jusqu’au respect de la fréquence définie.

Utile pour

  • « Seulement cinq participations à la tombola par minute. »
  • « Un appel API toutes les 10 secondes. »
  • « Ignorer les alertes si l’incrustation est déjà occupée. »

Configuration

  • Définissez le nombre maximal d’événements autorisés.
  • Choisissez la fenêtre de temps en secondes.
  • Choisissez de mettre les événements excédentaires en attente ou de les ignorer.
À savoir : Les limiteurs ne se réinitialisent pas automatiquement lorsque vous modifiez le flux. Utilisez Reset State Node si vous avez besoin de repartir de zéro pendant les tests.

05 · Mémoire utilisateur

User Memory détient une liste nommée de personnes uniques. Mémorisez les utilisateurs lors de leur participation, consultez la liste pour les messages suivants, retirez une personne, choisissez un gagnant au hasard ou videz uniquement cette liste.

Idéal pour

  • Admissibilité selon les cadeaux ou les badges.
  • Mémoriser les spectateurs qui ont aimé, participé ou rejoint un concours.
  • Tirages au sort avec participations uniques.
  • Listes distinctes pour les campagnes distinctes.

Opérations

  • Remember User et Forget User.
  • User Is Remembered.
  • Pick Random User.
  • Clear All Users ou Reset State Node.
Déclencheur de participation ──▶ Remember User ······▶ User Memory : Entrants Commande de tirage ───────────▶ Pick Random User ···▶ User Memory : Entrants Commande de remise à zéro ──────────▶ Clear All Users ·····▶ User Memory : Entrants

Les fils turquoise pleins transportent les événements. Les liens violets pointillés indiquent la mémoire partagée utilisée par une opération. Chaque User Memory possède son propre compteur, mode de conservation et règle de réinitialisation ; vider une liste ne touche donc pas les autres.

Consultez le guide dédié Guide User Memory pour des captures vérifiées, un flux de tirage téléchargeable, les conditions TikTok, des exemples de participation et les détails de réinitialisation.

06 · Solutions types

Choisissez un scénario et suivez les étapes.

Délai entre commandes

  1. Interrupteur nommé « commandCooldown ».
  2. Déclencheur → interrupteur → réponse.
  3. Set Gate OFF → Delay → Set Gate ON.
  4. Ajoutez un message de chat « Délai d’attente actif » sur la sortie false si vous le souhaitez.

Cadeaux gratuits limités

  1. Compteur initialisé à 0, cible 3.
  2. Incrémentez après chaque échange.
  3. Quand value ≥ 3, dirigez vers « Désolé, il n’en reste plus ».
  4. Utilisez l’action Reset à la fin de la diffusion.

Interrupteur des spectateurs

  1. Interrupteur nommé « overlayToggle ».
  2. !overlay on commande → Set Gate ON.
  3. !overlay off commande → Set Gate OFF.
  4. Tous les déclencheurs d’incrustation passent par l’interrupteur.

Exemples de schémas de flux

Déclencheur ─▶ Interrupteur (overlayToggle) ─▶ Si ON → Afficher l’incrustation └─false─▶ Informer le modérateur « Incrustation désactivée »
Échange de récompense ─▶ Compteur ticketsSold ├─value < 50 ─▶ Approuver l’échange └─value ≥ 50 ─▶ Refuser et rembourser les points

07 · Dépannage et FAQ

Symptôme Cause probable Solution
L’action Set Gate State ne s’enregistre pas. Aucun interrupteur correspondant n’existe, ou les noms diffèrent. Ajoutez d’abord l’interrupteur et vérifiez que la liste déroulante le référence.
Le compteur n’augmente jamais. Le flux contourne le compteur ou la porte est false. Vérifiez que le fil du déclencheur passe par le compteur et que la sortie de la porte est true.
Le limiteur bloque tout indéfiniment. Fenêtre trop restrictive ou état restant des tests. Assouplissez la limite et ajoutez une action Reset State Node avant de refaire le test.
Une opération User Memory n’a pas de lien pointillé. Aucune mémoire cible n’est sélectionnée. Choisissez la mémoire nommée dans les propriétés de l’opération ou faites glisser son connecteur latéral violet vers la mémoire.
Les boutons de guide ne s’ouvrent pas. Exécution dans l’extension sans mise à jour des ressources web_accessible. Vérifiez que actions/state-nodes-guide.html est bien publié via le manifeste et rechargez l’extension.

Liste de vérification des tests

  • Utilisez l’outil « Send Test Event » d’Event Flow pour simuler des commandes.
  • Pendant les vérifications, raccourcissez temporairement les délais à 2 secondes ou réduisez les cibles des compteurs.
  • Réinitialisez les nœuds d’état entre les tests pour éviter de lire des données périmées.
  • Nommez les branches, par exemple « false → délai actif », pour suivre visuellement le chemin.

08 · Étapes suivantes

Combinez les nœuds d’état avec les autres outils Event Flow :

  • Utilisez des portes logiques AND/OR/NOT avant un interrupteur pour décider qui peut le modifier.
  • Stockez les métadonnées liées à l’état sous meta pour que les incrustations sachent pourquoi une branche s’est déclenchée.
  • Exportez les configurations fonctionnelles comme modèles pour permettre à votre équipe de les réimporter.
Continuez vos essais ! Le nouveau Guide Event Flow complète ce guide pour maîtriser la logique et l’état.
