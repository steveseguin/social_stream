Testnachrichten erstellen

Sende kontrollierte simulierte Nachrichten und Ereignisse in deine Social-Stream-Sitzung.

Was dieses Tool macht

Der Seite „Create Test Message“ sendet künstliche Social-Stream-Nutzdaten an dein Dock, deine Overlays, Benachrichtigungen oder deine Event-Flow-Einrichtung. Teste damit, ohne auf eine echte Chatnachricht, Spende, Mitgliedschaft, einen Raid, eine Belohnung oder ein anderes Ereignis zu warten.

Verwende nach Möglichkeit eine Testsitzung. Eine gesendete Nachricht verhält sich wie eingehender Sitzungsverkehr und kann Benachrichtigungen, Sounds, Webhooks, OBS-Aktionen oder andere Automatisierungen auslösen.

Schnellstart für SSApp oder die Erweiterung

  1. Öffne Social Stream Ninja und stelle sicher, dass der Dienst aktiv ist.
  2. Unter Globale Einstellungen und Werkzeuge → Mechanik, aktiviere Fernsteuerung der Erweiterung über API (remote API control of extension). SSApp verwendet denselben Einstellungsnamen.
  3. Kopiere deine Sitzungs-ID aus Social Stream oder aus dem session= Wert in deiner Dock- oder Overlay-URL.
  4. Öffnen Testnachricht erstellen und gib diese Sitzungs-ID ein.
  5. Lass Senden über gesetzt auf Empfang über die Erweiterungs-API für normale Tests.
  6. Wähle eine Voreinstellung, passe ihre Felder an und wähle Voreinstellung laden.
  7. Prüfe das Nutzdaten-JSON und wähle dann Absenden.
  8. Prüfe, ob der Eintrag im Dock oder Ziel-Overlay erscheint und die erwartete Automatisierung ausgeführt wird.

Du kannst die Sitzung in der URL angeben: createtestmessage.html?session=YOUR_SESSION_ID.

Beispiel: Eine simulierte Nachricht mit 1.000 KICKs

Dies erstellt eine Unterstützungsnachricht im Kick-Stil im Wert von 1.000 KICKs. Es erstellt keine 1.000 einzelnen Nachrichten.

  1. Wähle Chatnachricht Voreinstellung.
  2. Setze Tippe auf Kick.
  3. Gib einen Testnamen und eine Nachricht ein.
  4. Setze Spendenbetrag auf 1000 KICKs.
  5. Auswählen JSON aus Feldern aktualisieren, prüfe das JSON und sende es ab.

Die minimalen Nutzdaten lauten:

{
  "type": "kick",
  "chatname": "Test Supporter",
  "chatmessage": "Thanks for the stream!",
  "hasDonation": "1000 KICKs"
}

Verwende Chatnachricht für dieses Beispiel. Die Spende / Cheer Voreinstellung enthält Twitch-spezifische Cheer-Felder.

Voreinstellungen und eigenes JSON verwenden

Voreinstellungen liefern Ausgangsnutzdaten für häufige Fälle wie Spenden, Abonnenten, verschenkte Abonnements, Raids, Belohnungen, Zuschaueraktualisierungen, erstmalige Chatter und Train-Ereignisse.

  • Voreinstellung laden ersetzt das JSON durch die gewählte Voreinstellung und die aktuellen Feldwerte.
  • JSON aus Feldern aktualisieren erstellt eine einfache Nachricht aus den sichtbaren Feldern.
  • Du kannst Nutzdaten-JSON direkt bearbeiten, wenn du ein bestimmtes Feld oder Ereignisformat testest.
  • hasDonation enthält den sichtbaren Unterstützungsbetrag, etwa 1000 KICKs oder $10.00.
  • Füge nur event ein, wenn du ein echtes benanntes Ereignis testest. Eine normale Chatzeile mit Spende kann hasDonation allein.

Felddefinitionen und echte Plattformbeispiele findest du in der Ereignisreferenz.

Wenn du unsicher bist, verwende Empfang über die Erweiterungs-API.

Häufige Lösungen

  • Nichts erscheint: prüfe, ob die Zielseite geöffnet ist und dieselbe Sitzungs-ID verwendet.
  • Empfang über die Erweiterungs-API schlägt fehl: aktiviere Fernsteuerung der Erweiterung über API (remote API control of extension), lade dann Dock oder Overlay neu und versuche es erneut.
  • Direktmodus meldet „gesendet“, aber nichts erscheint: verwende den Empfang über die Erweiterungs-API, sofern die Ziel-URL nicht das passende &server oder &server2 Modus.
  • Falsches Ereignis wird ausgelöst: prüfe das Nutzdaten-JSON auf übrig gebliebene Felder einer anderen Voreinstellung.
  • Kick-Test verhält sich wie Twitch: verwende die Voreinstellung „Chat Message“ und setze type und hasDonation wie oben gezeigt.
  • Eine Automatisierung läuft mehrmals: prüfe, ob mehrere Docks, Aktionsseiten oder Event-Flow-Instanzen in derselben Sitzung geöffnet sind.
