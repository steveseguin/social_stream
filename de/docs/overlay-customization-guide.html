Laden Sie lokale Overlay-Designs in OBS herunter, passen Sie sie an, verbinden Sie sie und testen Sie sie, mit Anleitungen für jede Overlay-Familie.

Wählen Sie das Overlay aus, das Sie neu gestalten möchten

Laden Sie die Dateien herunter→Ändern Sie das Design→Öffnen in OBS

Sie können die Farben, Schriftarten, das Layout, die Grafik und die Bewegung einer vorhandenen Seite ändern. Die HTML-Datei ist die Seite; die OBS-URL verweist darauf und liefert Sitzungs- und Anzeigeeinstellungen. Für eine kleine Neugestaltung verwenden Sie OBS Custom CSS auf der gehosteten Seite. Für tiefergehende Änderungen laden Sie die Quelle herunter und führen Sie Ihre eigene Kopie aus.

Diese Leitfäden behandeln Overlay-Familien, einschließlich ihrer Themen. Wählen Sie den Empfänger für die Funktion aus, die Sie verwenden: Eine Chat-Seite, eine Seite mit ausgewählten Nachrichten und eine Umfrage verbrauchen nicht alle die gleichen Eingaben.

Für ein fertiges Design beginnen Sie im Overlay-Galerie oder Vorlagengalerie. Befolgen Sie für einen vorhandenen StreamElements/Streamlabs-Chat-Skin die Anweisungen Importanleitung. Der importierte eigenständige HTML-Code verfügt über eigene Export-/Einrichtungsanweisungen.

1. Laden Sie die tatsächlichen Dateien herunter

  1. Beta-Quellcode als ZIP herunterladen, oder öffnen Sie die Beta-Repository und wähle Code → ZIP herunterladen.
  2. Extrahieren Sie die ZIP-Datei in einen Ordner, den Sie behalten können, z C:\SSN\social_stream-beta\. Bearbeiten Sie nicht innerhalb des komprimierten Archivs. Dies sind Seitenquelldateien; Das Bearbeiten einer separaten Kopie erfordert keine Neuinstallation von SSN.
  3. Suchen Sie die in der Tabelle oben gezeigte Datei. Duplizieren Sie es neben dem Original: zum Beispiel poll.html wird zu my-poll.html. Für themes/featured-styles/featured-modern.html, bewahren Sie die Kopie auf themes/featured-styles/.
  4. Öffnen Sie die Kopie in einem Text-/Code-Editor. Gewähren Sie Ihrem KI-Tool Zugriff auf diese Datei und die benötigten referenzierten Stile/Skripte. HTML speichern unter .html, nicht .html.txt.

Behalten Sie die extrahierte Ordnerstruktur bei. Eine einzelne heruntergeladene HTML-Datei kann Skripte, Stylesheets, Schriftarten, Bilder, Audio oder JSON daneben laden. Der Seitenaufruf von GitHub und die „Seite speichern“ eines Browsers sind kein zuverlässiges Komplettpaket. Jeder Typführer identifiziert nützliche Dateien, aber der vollständig extrahierte Ordner ist die einfachste Möglichkeit, Abhängigkeiten beizubehalten.

social_stream-beta/
    poll.html
    my-poll.html
    currency.js
    js/
    libs/
    shared/
    thirdparty/
    media/
    sources/images/
    themes/
        featured-styles/
            featured-modern.html
            my-featured.html
    docs/
        event-reference.html

Eine Referenz wie ../../shared/utils/chatHtml.js ist relativ zu der Seite, die es lädt. Durch das Verschieben dieser Seite ins Stammverzeichnis wird der Pfad unterbrochen. Kopieren Sie auch lokale Grafiken und Schriftarten in das Projekt und verwenden Sie dann relative URLs. Bewahren Sie heruntergeladene Versionen zusammen auf; Ihre bearbeitete Kopie erhält zukünftige SSN-Korrekturen nicht automatisch.

2. Behalten Sie die Sitzungs- und Verbindungseinstellungen bei

Starten Sie SSN, schließen Sie eine Quelle an und bestätigen Sie, dass das Original-Overlay funktioniert. Kopieren Sie die vollständig generierter Link aus dem entsprechenden SSN-Tool. Der Wert danach session= identifiziert Ihre SSN-Sitzung; Es handelt sich nicht um einen YouTube-Kanal, einen Twitch-Benutzernamen, einen Dateinamen oder den Titel der Umfrage.

https://socialstream.ninja/poll.html?session=YOUR_SESSION&password=YOUR_PASSWORD&server2

Das Beispiel verwendet Platzhalter. SSN und die Seite müssen dieselbe tatsächliche Sitzung und jedes konfigurierte Passwort verwenden. Durch das Ändern des Dateinamens wird die Sitzung nicht geändert. Halten Sie SSN und Capture am Laufen: Ein Overlay empfängt Daten; Der Plattform-Chat wird nicht selbst erfasst.

  • ? startet die Abfrage; Nachfolgende Einstellungen verwenden &. Kopieren Sie Werte, anstatt sie erneut einzugeben. Schreiben Sie in ein HTML-Quellattribut &amp;; Verwenden Sie im URL-Feld browser/OBS ein gewöhnliches kaufmännisches Und.
  • Transporteinstellungen beibehalten: server, server2, server3Lokale Endpunkte, Beschriftungen und Versionswerte sind seitenspezifisch. Fügen Sie kein Server-Flag hinzu, nur weil ein anderes Overlay es unterstützt.
  • Bewahren Sie auch Fragmente auf: alles danach # kann wichtig sein. AI Event Overlay verwendet beispielsweise eine private #aieventauth=... Anzeige-Token.
  • Verwenden Sie Platzhalter in freigegebenen Beispielen. Halten Sie Ihren echten Sitzungslink, Ihr Passwort und Ihre privaten Anzeigetokens von öffentlichen Screenshots, Repositorys und Beispielen für KI-Eingabeaufforderungen fern.

Wenn eine Kopie leer bleibt, überprüfen Sie zuerst den ursprünglich generierten Link. Auf einigen Seiten werden fehlende Einstellungen angezeigt. andere bleiben verborgen oder leiten um. Durch die explizite Bereitstellung der richtigen Sitzung wird vermieden, dass man sich auf diese seitenspezifischen Standardeinstellungen verlässt.

3. Öffnen Sie Ihre Datei in OBS

Öffnen Sie den bearbeiteten HTML-Code direkt von Ihrem Computer. Es muss kein Server installiert oder gestartet werden.

  1. Ziehen Sie Ihre kopierte HTML-Datei in Chrome oder Edge. Kopieren Sie die vollständige Adresse aus der Adressleiste. es beginnt mit file:///.
  2. Alles kopieren von ? weiter in Ihrem funktionierenden SSN-Overlay-Link und fügen Sie ihn am Ende dieser Dateiadresse hinzu. Dadurch bleiben Ihre Sitzung, Ihr Passwort, andere Einstellungen usw. erhalten # Ende.
  3. Öffnen Sie die kombinierte Adresse in Ihrem Browser, um sie zu testen.
  4. Erstelle in OBS eine Browserquelle. Lass Lokale Datei deaktivieren und die vollständige Adresse einfügen URL. Legen Sie die Breite und Höhe für Ihr Design fest.

Zum Beispiel dieser SSN-Link:

https://socialstream.ninja/poll.html?session=YOUR_SESSION&password=YOUR_PASSWORD&server2

wird zu dieser Adresse für eine heruntergeladene Umfragekopie unter Windows:

file:///C:/SSN/social_stream-beta/my-poll.html?session=YOUR_SESSION&password=YOUR_PASSWORD&server2

Verwenden Sie Ihre tatsächliche Dateiadresse und die kopierten Einstellungen. Bei macOS beginnt die Adresse mit file:///Users/...; Unter Linux beginnt es normalerweise mit file:///home/.... Durch das Kopieren der Browseradresse werden Leerzeichen und Schrägstriche für Sie erledigt.

Richten Sie dies einmal ein. OBS speichert die Adresse mit der Quelle. Behalten Sie den heruntergeladenen Ordner am selben Ort und lassen Sie SSN und Ihre Chat-Quelle laufen, wenn Sie das Overlay verwenden. Verwenden Sie nach dem Speichern einer Designänderung Cache der aktuellen Seite aktualisieren in den Quelleigenschaften.

Warum sollte die Option „Lokale Datei“ deaktiviert bleiben? Das URL-Feld ermöglicht die Einbindung ?session=.... Wenn Sie den HTML-Code allein mit der Dateiauswahl auswählen, werden diese Einstellungen nicht hinzugefügt.

Optional: Verwenden Sie das Kontrollkästchen „Lokale Datei“ mit einem Launcher

Die Dateiauswahl von OBS wählt eine Datei aus; Ihre generierten Abfrageeinstellungen werden nicht hinzugefügt. Für einen unveränderten abfragebasierten Empfänger kann ein kleiner lokaler Launcher mit den angehängten Einstellungen zur bearbeiteten Seite navigieren:

  1. Speichern Sie Folgendes unter launch-my-poll.html neben my-poll.html.
  2. Ersetzen Sie die gehostete Platzhalter-URL durch Ihren vollständig kopierten SSN-Link. Veränderung ./my-poll.html zu Ihrem tatsächlich bearbeiteten Dateinamen. Behalten Sie den Link in Anführungszeichen, mit normal & Zeichen enthält.
  3. Doppelklicken Sie auf den Launcher, um ihn zu testen. Wählen Sie in OBS aus Lokale Datei und wählen Sie die Launcher Mit. Es leitet mit der Abfrage und dem Fragment zum lokalen Overlay weiter.
<!DOCTYPE html>
<html lang="en">
<meta charset="utf-8">
<title>My local overlay launcher</title>
<p>Opening the local overlay...</p>
<script>
var copiedLink = new URL("https://socialstream.ninja/poll.html?session=YOUR_SESSION");
var localPage = new URL("./my-poll.html", window.location.href);
localPage.search = copiedLink.search;
localPage.hash = copiedLink.hash;
window.location.replace(localPage.href);
</script>
</html>

Bei einem verschachtelten Theme platzieren Sie den Launcher neben dieser Theme-Kopie. Halten Sie den Launcher privat, da er Ihren Verbindungslink enthält. Ein heruntergeladener eigenständiger Export, der seine Konfiguration bereits einbettet, folgt stattdessen seinen eigenen Exportanweisungen.

OBS dokumentiert seine Datei-/URL-Modi, Abmessungen, benutzerdefiniertes CSS und Aktualisierungssteuerelemente im Browser-Quellenreferenz.

4. Ändern Sie das Design oder beauftragen Sie die KI damit

Für eine reine CSS-Änderung behalten Sie den gehosteten Link bei und verwenden Sie OBSs Eigenes CSS Feld. Es gilt nur für diese Quelle, sodass ein normaler Browser, der dieselbe URL öffnet, diese Überschreibungen nicht anzeigt. Hängen Sie für eine bearbeitete HTML-Datei Überschreibungen nach den vorhandenen Stilen an oder verknüpfen Sie ein lokales Stylesheet dahinter. Geben Sie Ihr Logo, Schriftartdateien, Markenfarben, Leinwandgröße und eine visuelle Referenz an.

Einige Seiten unterstützen &css= oder &b64css=; Die Unterstützung erfolgt pro Seite. poll.htmlliest sich zum Beispiel weder. Überprüfen Sie den Parser der Seite, bevor Sie URL-Optionen verwenden. Eine Webseite kann im Allgemeinen keine beliebige Schriftart oder ein beliebiges Bild von der lokalen Festplatte eines anderen Computers laden.

Behalten Sie beim Ändern des Markups die von Skripten referenzierten IDs/Klassen bei. Wenn JavaScript bei jedem Update ein Element neu aufbaut, muss sich das permanente Bildmaterial außerhalb dieses Elements befinden oder vom Renderer neu erstellt werden. Kopieren Sie ein freigegebenes Stylesheet/Skript und ändern Sie die Referenz Ihrer Seite, wenn Sie möchten, dass sich die Bearbeitung nur auf Ihr Design auswirkt.

Verwenden Sie die typspezifische Eingabeaufforderung in den oben genannten Anleitungen oder beginnen Sie mit dieser allgemeinen Eingabeaufforderung:

Customize [copied overlay filename] to match [reference/design].

Die Typhandbücher beschreiben den eigentlichen Auslöser, der beibehalten werden muss. Akzeptieren Sie kein Design, das nur funktioniert, weil es Beispielnachrichten fest codiert. Bewahren Sie eine Kopie der Originaldatei auf und vergleichen Sie die bearbeitete Anzeige mit denselben Testeingaben.

5. Verhindern Sie, dass eingehender Chat zu Code wird

Nachrichten, Namen, Titel, Beträge, Metadaten und Medienlinks können von Zuschauern oder externen Diensten stammen. Bereinigen Sie sie an der Stelle, an der sie vom benutzerdefinierten Renderer eingefügt werden. Eine über SSN empfangene Zeichenfolge stellt keine Berechtigung zur Ausführung dar. Verwenden Sie einfachen DOM-Text für einfache Felder. Verwenden Sie das gepackte Desinfektionsmittel für den unterstützten HTML-Code des Nachrichtentexts. Siehe OWASPs Erklärung zu sicheren Senken und HTML-Bereinigung.

In SSN, textonly gilt nur für chatmessage. Wenn dies wahr ist, rendern Sie diesen Text als wörtlichen Text. Andernfalls kann es Emotes und erlaubte Formatierungen enthalten. Andere normale Felder als Text rendern; Medienbereiche wie z chatimg und contentimg sind URLs/Daten, keine HTML-Schnipsel.

<!-- Example for a copied page at the repository root. -->
<script src="./libs/objects.js"></script>
<script src="./shared/utils/chatHtml.js"></script>
<script>
function renderChatBody(element, data) {
    var message = String(data.chatmessage == null ? "" : data.chatmessage);
    if (data.textonly) {
        element.textContent = message;
    } else {
        element.innerHTML = SocialStreamChatHTML.sanitize(message);
    }
}
// Names, amounts, titles, and other plain fields use textContent:
// nameElement.textContent = String(data.chatname || "");
</script>

Behalten Sie ein vorhandenes gleichwertiges Desinfektionsmittel bei, anstatt ein zweites hinzuzufügen. Passen Sie bei verschachtelten Dateien die relativen Skriptpfade an. Erstellen Sie Avatare und Links mit DOM-Eigenschaften, nachdem Sie die URL gemäß der bestehenden Medien-/Link-Richtlinie der Seite validiert haben. Interpolieren Sie keine Rohnamen in Attributzeichenfolgen oder Rohfarben in Stilmarkierungen. Validieren Sie Stile, bevor Sie einzelne Eigenschaften festlegen. Durch die HTML-Bereinigung ist die Ausführung einer Zeichenfolge als JavaScript oder als KI-Anweisung nicht sicher.

Testen Sie den Renderer in einer isolierten Vorschau

  • Verwenden Sie einen einfachen Namen, z Guest <b>One</b>: Die Klammern sollten Text bleiben.
  • Probiere chatmessage: "<b>Hello</b>" mit textonly: true, dann falsch. Wörtliches Markup und zulässige formatierte Inhalte sollten ihren jeweiligen Pfaden folgen.
  • Überprüfen Sie ein unterstütztes Emote und eine Nur-Bild-Nachricht, damit Sicherheitsänderungen diese Funktionen nicht entfernen.
  • Lassen Sie die KI eine harmlose Sonde testen, z <img src=x onerror="window.__ssnInjectionProbe=1"> im geänderten Renderer. Es darf nicht ausgeführt werden, keine Markierung setzen oder ausführbare Ereignisattribute hinterlassen. Testen Sie auch einen Skript-Schema-Link. Führen Sie Sonden lokal aus, nicht im öffentlichen Chat.

Eine vorbeifahrende Sonde überprüft nur die ausgeübten Pfade. Konzentrieren Sie sich bei den Tests auf die Renderer und Felder, die durch das Design geändert wurden.

6. Testen Sie Layout, Verbindung und OBS separat

  1. Layout: Verwenden Sie den dokumentierten Vorschau-/Demomodus der Seite, sofern verfügbar, oder fiktive lokale Beispiele. Testen Sie lange Namen/Nachrichten, fehlende Avatare, leere Daten und die erwartete Anzahl von Zeilen.
  2. SSN Lieferung: SSN aktiv halten und verwenden Testnachricht erstellen mit derselben Sitzung. Der übliche Erweiterungs-API-Aufnahmemodus ist erforderlich Fernsteuerung der Erweiterung über API (remote API control of extension) aktiviert. Verwenden Sie einen isolierten Testaufbau; Eingereichte Tests können konfigurierte Automatisierungen auslösen.
  3. Der eigentliche Auslöser: Stellen Sie eine Dock-Nachricht für eine vorgestellte Karte bereit, senden Sie eine Abstimmung für eine Umfrage, wählen Sie einen Gewinner für eine Verlosung aus, ändern Sie den Tickertext für einen Ticker oder starten Sie einen Timer für einen Timer. Einfacher Chat ist kein universeller Test.
  4. Echte Aufnahme: Bestätigen Sie, dass eine tatsächliche Quellnachricht/ein tatsächliches Quellereignis die ursprüngliche und bearbeitete Seite erreicht. Ein Scheinereignis beweist das Rendern und nicht die Plattformerfassung.
  5. OBS: Überprüfen Sie die Quelle auf ihre endgültige Größe, Transparenz, Animationen, Audio, Schriftarten und Ebenen. Übung „Einblenden/Ausblenden“, „Löschen/Zurücksetzen“ und „Aktualisieren“. Der Browser und OBS verfügen über separate Speicher und Sitzungen; Browser-Login oder localStorage wird nicht automatisch geteilt.

Bei Seiten, die Daten im Speicher sammeln, kann es beim Entladen oder Aktualisieren zu Statusverlusten kommen. Überprüfen Sie die Typanleitung, bevor Sie die automatische Aktualisierung oder das Herunterfahren bei Ausblenden aktivieren. Vom Host verwaltete Displays weisen ein unterschiedliches Wiederherstellungsverhalten auf. Entfernen demo/preview Flags, bevor Live-Daten erwartet werden.

Nützliche Dateien und Referenzen für Ihre KI

  • docs/event-reference.html: kanonische Felder, benannte Ereignisse, Metadaten, Medien und Spendenwerte.
  • docs/customoverlays.md: Kundenspezifische Empfänger und Anschlussbeispiele.
  • Kompatibilität von Ereignissen und Meldungen: welche Ereignisse/Felder ein Design von einer Quelle erwarten kann.
  • Anleitung für Testnachrichten und createtestmessage.html: Beispielnutzlasten und Liefermodi.
  • libs/objects.js und shared/utils/chatHtml.js: Desinfektion verpackter Displays.
  • shared/utils/chatBadges.js und shared/utils/contentImage.js: vorhandenes Badge- und Bildhandling.
  • js/transport-dedupe.js, js/local-server-url.js, und shared/overlay-control-transport.js: vorhandene Transportunterstützung beim Laden durch Ihre Seite.
  • currency.js: bewahren hasDonation zur Anzeige und Anerkennung eines gültigen numerischen USD donoValue, einschließlich Null.
  • Event Flow und Befehle und API: Vorhandene Steuerelemente wiederverwenden, wenn das Design einen Auslöser benötigt.

Geben Sie die tatsächliche Overlay-Quelle und das referenzierte CSS/JS sowie diese Dokumente an. Eine Ereignisreferenz allein beschreibt nicht den Kontrollstatus einer Umfrage oder die private Rendering-Struktur jedes Overlays.

Wenn die Kopie nicht funktioniert

SymptomPrüfe
Datei nicht gefundenZiehen Sie den HTML-Code erneut in Ihren Browser und kopieren Sie die aktuelle Dateiadresse. Stellen Sie sicher, dass der Dateiname auf .html und nicht auf .html.txt endet.
Skript, Schriftart oder Bild fehlenBehalten Sie die Struktur des extrahierten Ordners bei, wobei die bearbeitete Kopie neben dem Original liegt. Überprüfen Sie, ob sich alle hinzugefügten Grafiken und Schriftarten in den erwarteten Ordnern befinden.
Leere oder „wartende“ AnzeigeÜberprüfen Sie die Sitzung, das Passwort, die vollständige Abfrage/das vollständige Fragment, den Betriebsstatus von SSN, die aktivierte Funktion und die passende Eingabe. Vergleichen Sie die ursprünglich generierte URL.
Funktioniert im Browser, anders in OBSÜberprüfen Sie Breite/Höhe, altes benutzerdefiniertes CSS, Schriftartenverfügbarkeit, Caching und verschiedene Browserspeicher. Nach dem Speichern aktualisieren.
Logo verschwindet bei AktualisierungDer Renderer kann seinen Container ersetzen. Platzieren Sie eine dauerhafte Dekoration außerhalb oder aktualisieren Sie die Rendering-Vorlage.
Statusrücksetzungen oder Aktionen werden zweimal ausgelöstÜberprüfen Sie die Aktualisierungs-/Entladeeinstellungen, doppelte Ausgabe-/Kontrollinstanzen und das vorhandene Deduplizierungs-/Statusverhalten der Seite.
Sonderfall: Seiten, die separate Datendateien lesen

Die Karte liest lokale JSON-Dateien mit fetch(), die ein Browser beim Öffnen von der Festplatte blockieren kann. Für eine einfache Neugestaltung der Karte verwenden Sie den gehosteten Link mit OBS Custom CSS. Bitten Sie Ihre KI für eine bearbeitete HTML-Kopie, die erforderlichen Kartendaten in die Seite aufzunehmen, damit sie direkt von der Festplatte geöffnet wird. Beim Hosting handelt es sich um eine erweiterte Option für eine Seite, die es speziell benötigt, und nicht um einen normalen Einrichtungsschritt für diese Overlays.

Stoppen Sie beim kleinsten bestätigten Problem. Eine Neugestaltung sollte keine Änderung von Capture-Skripten oder die Erfindung neuer Ereignisfelder erfordern. Wenn Sie einen öffentlichen Fork teilen, schließen Sie dessen unterstützende Assets ein und halten Sie private Launcher von diesem Upload fern.
