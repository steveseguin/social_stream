Memoria utenti (User Memory)

Memorizza partecipanti unici, controllali nei messaggi successivi, estrai un vincitore casuale e azzera esattamente l'elenco desiderato, senza trasformare un ruolo della piattaforma in uno stato globale permanente.

Una memoria con nome, molti strumenti

Un Memoria utenti (User Memory) gestisce un insieme isolato di persone. Ogni nodo Remember, Forget, Check, Draw o Clear seleziona quel nodo di stato. Crea un altro nodo User Memory quando ti serve un elenco separato, ad esempio uno per chi ha messo Mi piace alla diretta e un altro per chi è entrato nel giveaway.
Verde acqua continuo: questo evento viene eseguito dopo Viola tratteggiato: questo nodo usa quella memoria

Trascina il piccolo rombo viola laterale su un nodo User Memory oppure scegli la memoria per nome nelle proprietà del nodo. Internamente, l'operazione memorizza l'ID del nodo di stato. Selezionando la memoria vengono evidenziate tutte le operazioni collegate; eliminandola compare un avviso prima di interrompere quei collegamenti.

Configuralo

  1. Trascina Nodi di stato → Memoria utenti (State Nodes → User Memory) nell'area di lavoro.
  2. Assegnagli un nome che descriva l'elenco gestito, ad esempio Idonei Heart Me, Mi piace alla diretta, oppure Partecipanti all'estrazione.
  3. Scegli Questa sessione dell'app oppure Salva tra i riavvii.
  4. Aggiungi i controlli e le azioni necessari, poi collega ciascuno alla memoria con nome usando il rombo laterale o il menu a discesa.
  5. Collega il normale percorso degli eventi con fili verde acqua e usa Prova flusso (Test Flow) con due nomi utente diversi prima di andare in diretta.

Operazioni disponibili

NodoCosa fa
Ricorda utente (Remember User)Aggiunge una sola volta l'utente dell'evento corrente. Partecipazioni ripetute aumentano il conteggio di partecipazione dell'utente senza aggiungere voci duplicate all'estrazione.
L'utente è memorizzato (User Is Remembered)Un trigger/controllo che restituisce true quando il messaggio corrente appartiene a una persona presente nella memoria selezionata.
Dimentica utente (Forget User)Rimuove solo l'utente dell'evento corrente.
Scegli utente casuale (Pick Random User)Seleziona un utente unico memorizzato. Può facoltativamente rimuovere il vincitore per impedirgli di vincere di nuovo.
Cancella tutti gli utenti (Clear All Users)Svuota solo l'oggetto User Memory selezionato.
Ripristina nodo di stato (Reset State Node)Svuota anche una User Memory quando è la destinazione di ripristino selezionata.
Regola di identità: gli utenti sono identificati da piattaforma più ID utente. Il nome visualizzato viene usato solo come ripiego. Un evento anonimo o aggregato senza identità utente viene ignorato in sicurezza.

Ricette pratiche

TikTok Heart Me o Team Member → ? TTS

Usa l'evento regalo per ricordare il mittente; non provare a trasformare la singola riga regalo in un ruolo permanente di “membro”.

Evento regalo TikTok + corrispondenza “Heart Me” → AND → Remember User ···→ [Idonei Heart Me]
comando ? + sorgente TikTok + (TikTok Team Member OR User Is Remembered) → AND → Speak Text comando ? + NOT sorgente TikTok → AND ────────────────────────────────→ Speak Text
  • Per lo stato TikTok Team/Fan, scegli Ruolo utente → Membro del team TikTok (User Role → TikTok Team Member). Legge direttamente i dati in arrivo di badge/livello TikTok; non serve l'impostazione di visualizzazione “treat as members” del Main Chat Overlay.
  • I payload dei regali variano in base alla modalità di acquisizione. Una configurazione comune è Tipo di evento → Altro: gift (Event Type → Other: gift) più Il messaggio contiene: Heart Me (Message Contains: Heart Me). Controlla la riga acquisita in Test Flow/Event Reference e usa il campo più chiaro fornito dalla sorgente.
  • Entrambi i rami richiedono comunque il prefisso ?, così sulle altre piattaforme la voce funziona per tutti, mentre TikTok resta limitato.

Ricorda chi ha messo Mi piace o ha partecipato

Event Type → Other: liked → Remember User ···→ [Mi piace alla diretta]

Funziona quando l'evento acquisito di Mi piace/partecipazione identifica un utente. Gli aggiornamenti aggregati del conteggio dei Mi piace non identificano una persona e quindi non possono essere memorizzati. Usa una memoria separata per ogni tipo di partecipazione se vuoi controlli o estrazioni indipendenti.

Estrazione con una partecipazione per utente

Message Starts With !enter → Remember User ···→ [Partecipanti all'estrazione] Moderatore + Message Starts With !draw → AND → Pick Random User ···→ [Partecipanti all'estrazione] Moderatore + Message Starts With !resetdraw → AND → Clear All Users ···→ [Partecipanti all'estrazione]

Attiva Rimuovi utente selezionato quando i vincitori non devono essere estratti due volte. In una diretta pubblica, proteggi i comandi di estrazione/azzeramento con un controllo moderatore, amministratore o utente esatto.

Azzeramento e persistenza

Manuale

Usa Cancella subito tutti gli utenti (Clear All Users Now) nelle proprietà della memoria durante creazione/test.

Da un flusso

Usa Cancella tutti gli utenti (Clear All Users) oppure il generico Ripristina nodo di stato (Reset State Node), selezionando la memoria esatta.

Automatica

Svuota dopo un periodo di inattività, all'avvio o all'arresto della diretta. Il valore 0 disattiva l'azzeramento per inattività.

Tra i riavvii

Le memorie di sessione partono vuote con l'app. Le memorie salvate vengono ricaricate finché quella specifica memoria non viene svuotata.

“Cancella tutti” ha un ambito limitato: significa tutti gli utenti nella memoria selezionata, non tutto lo stato Event Flow, ogni estrazione o ogni memoria in Social Stream Ninja.

Usa gli output di estrazione e partecipazione

Le azioni di memoria aggiungono campi al messaggio, così le azioni successive Show Text, Send Message, webhook o personalizzate possono usarli.

Risoluzione dei problemi

Manca la linea tratteggiataSeleziona l'operazione e scegli una destinazione User Memory oppure trascina il rombo viola laterale al nodo centrale della memoria.
La stessa persona compare due volteControlla se gli eventi provengono da piattaforme diverse. Piattaforma + ID utente creano intenzionalmente identità separate.
Un Mi piace non ha aggiunto nessunoProbabilmente l'evento non aveva un'identità utente. Esamina il payload dell'evento; conteggi aggregati non possono diventare partecipanti con nome.
Una memoria salvata è ricomparsaUsa Clear All Users su quella memoria. Modificare un flusso o svuotare una memoria diversa non la cancella.
Chiunque può eseguire il comando di estrazione/azzeramentoAggiungi User Role: moderator/admin (oppure un controllo esatto dell'utente conduttore) a una porta AND prima dell'azione.
