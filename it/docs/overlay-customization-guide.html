È possibile modificare i colori, i caratteri, il layout, la grafica e l'animazione di una pagina esistente. Il File HTML è la pagina; il URL OBS lo indica e fornisce le impostazioni di sessione e visualizzazione. Per un piccolo restyling, utilizza OBS CSS personalizzato sulla pagina ospitata. Per modifiche più profonde, scarica il sorgente ed esegui la tua copia.

Queste guide coprono le famiglie di overlay, compresi i relativi temi. Scegli il destinatario per la funzione che utilizzi: una pagina di chat, una pagina di messaggi selezionati e un sondaggio non consumano tutti lo stesso input.

Per una progettazione già pronta, iniziare in Galleria degli overlay oppure Galleria dei template. Per una skin di chat StreamElements/Streamlabs esistente, segui il file guida all'importazione. L'HTML autonomo importato ha le proprie istruzioni di esportazione/configurazione.

1. Scaricare i file effettivi

  1. Scarica il codice beta in ZIPo aprire il file archivio beta e scegli Codice → Scarica ZIP.
  2. Estrai lo ZIP in una cartella che puoi conservare, ad esempio C:\SSN\social_stream-beta\. Non modificare all'interno dell'archivio compresso. Questi sono file di origine della pagina; la modifica di una copia separata non richiede la reinstallazione di SSN.
  3. Trovare il file mostrato nella tabella sopra. Duplicalo accanto all'originale: ad esempio poll.html diventa my-poll.html. Per themes/featured-styles/featured-modern.html, conservare la copia themes/featured-styles/.
  4. Aprire la copia in un editor di testo/codice. Concedi al tuo strumento AI l'accesso a quel file e agli stili/script di riferimento di cui ha bisogno. Salva HTML con nome .html, no .html.txt.

Conserva la struttura delle cartelle estratte. Un singolo file HTML scaricato può caricare accanto ad esso script, fogli di stile, caratteri, immagini, audio o JSON. La visualizzazione della pagina di GitHub e la "pagina di salvataggio" del browser non sono un pacchetto completo affidabile. Ogni guida ai tipi identifica i file utili, ma la cartella estratta completa è il modo più semplice per conservare le dipendenze.

social_stream-beta/
    poll.html
    my-poll.html
    currency.js
    js/
    libs/
    shared/
    thirdparty/
    media/
    sources/images/
    themes/
        featured-styles/
            featured-modern.html
            my-featured.html
    docs/
        event-reference.html

Un riferimento come ../../shared/utils/chatHtml.js è relativo alla pagina che lo carica. Lo spostamento della pagina alla radice interrompe il percorso. Copia anche la grafica e i caratteri locali nel progetto, quindi utilizza gli URL relativi. Mantieni insieme le versioni scaricate; la tua copia modificata non riceverà automaticamente le future correzioni SSN.

2. Conservare le impostazioni di sessione e connessione

Avvia SSN, collega una sorgente e verifica che l'overlay originale funzioni. Copia il collegamento generato completo dal relativo strumento SSN. Il valore dopo session= identifica la tua sessione SSN; non è un canale YouTube, un nome utente Twitch, un nome file o il titolo del sondaggio.

https://socialstream.ninja/poll.html?session=YOUR_SESSION&password=YOUR_PASSWORD&server2

L'esempio utilizza i segnaposto. SSN e la pagina devono utilizzare la stessa sessione effettiva e l'eventuale password configurata. La modifica del nome file non modifica la sessione. Mantieni SSN e acquisisci in esecuzione: un overlay riceve i dati; non acquisisce da solo la chat della piattaforma.

  • ? avvia la query; utilizzo delle impostazioni successive &. Copia i valori invece di ridigitarli. In un attributo di origine HTML, scrivi &amp;; nel campo browser/URL OBS utilizzare una normale e commerciale.
  • Conserva le impostazioni di trasporto: server, server2, server3, gli endpoint locali, le etichette e i valori della versione sono specifici della pagina. Non aggiungere un flag del server solo perché un altro overlay lo supporta.
  • Conserva anche i frammenti: tutto dopo # può avere importanza. AI Event Overlay, ad esempio, utilizza un private #aieventauth=... token di visualizzazione.
  • Utilizzare i segnaposto negli esempi condivisi. Mantieni il collegamento della sessione reale, la password e i token di visualizzazione privati ​​fuori da screenshot pubblici, repository ed esempi di prompt AI.

Quando una copia rimane vuota, controlla prima il collegamento generato originale. Alcune pagine richiedono impostazioni mancanti; altri rimangono nascosti o reindirizzati. Fornire la sessione corretta evita esplicitamente di fare affidamento su tali impostazioni predefinite specifiche della pagina.

3. Apri il file in OBS

Apri l'HTML modificato direttamente dal tuo computer. Non è necessario installare o avviare alcun server.

  1. Trascina il file HTML copiato in Chrome o Edge. Copia il suo indirizzo completo dalla barra degli indirizzi; inizia con file:///.
  2. Copia tutto da ? in poi nel collegamento in sovrapposizione SSN funzionante e aggiungilo alla fine dell'indirizzo del file. Ciò mantiene la sessione, la password, altre impostazioni e qualsiasi altra cosa # fine.
  3. Apri l'indirizzo combinato nel tuo browser per testarlo.
  4. In OBS, aggiungi una Sorgente browser. Lascia File locale deselezionato e incollare l'indirizzo completo in URL. Imposta la larghezza e l'altezza del tuo design.

Ad esempio, questo collegamento SSN:

https://socialstream.ninja/poll.html?session=YOUR_SESSION&password=YOUR_PASSWORD&server2

diventa questo indirizzo per una copia del sondaggio scaricata su Windows:

file:///C:/SSN/social_stream-beta/my-poll.html?session=YOUR_SESSION&password=YOUR_PASSWORD&server2

Utilizzare l'indirizzo file effettivo e le impostazioni copiate. Su macOS l'indirizzo inizia con file:///Users/...; su Linux di solito inizia con file:///home/.... La copia dell'indirizzo del browser gestisce gli spazi e le barre per te.

Configuralo una volta. OBS salva l'indirizzo con la sorgente. Mantieni la cartella scaricata nello stesso posto e mantieni SSN e la sorgente della chat in esecuzione quando utilizzi l'overlay. Dopo aver salvato una modifica al progetto, utilizzare Aggiorna cache della pagina corrente nelle proprietà della fonte.

Perché lasciare il file locale deselezionato? Il campo URL ti consente di includere ?session=.... La selezione dell'HTML solo con il selettore file non aggiunge tali impostazioni.

Facoltativo: utilizzare la casella di controllo File locale con un launcher

Il selettore file di OBS sceglie un file; non aggiunge le impostazioni della query generata. Per un ricevitore basato su query non modificato, un piccolo launcher locale può accedere alla pagina modificata con le impostazioni allegate:

  1. Salvare quanto segue con nome launch-my-poll.html accanto a my-poll.html.
  2. Sostituisci l'URL ospitato segnaposto con il collegamento SSN completamente copiato. Cambiare ./my-poll.html al nome del file effettivamente modificato. Mantieni il collegamento tra virgolette, con ordinario & .
  3. Fare doppio clic sul launcher per testarlo. In OBS, seleziona File locale e scegli il lanciatore. Reindirizza all'overlay locale con la query e il frammento.
<!DOCTYPE html>
<html lang="en">
<meta charset="utf-8">
<title>My local overlay launcher</title>
<p>Opening the local overlay...</p>
<script>
var copiedLink = new URL("https://socialstream.ninja/poll.html?session=YOUR_SESSION");
var localPage = new URL("./my-poll.html", window.location.href);
localPage.search = copiedLink.search;
localPage.hash = copiedLink.hash;
window.location.replace(localPage.href);
</script>
</html>

Per un tema nidificato, posiziona il launcher accanto alla copia del tema. Mantieni il launcher privato perché contiene il tuo collegamento di connessione. Un'esportazione autonoma scaricata che incorpora già la propria configurazione segue invece le proprie istruzioni di esportazione.

OBS documenta le modalità file/URL, le dimensioni, i CSS personalizzati e i controlli di aggiornamento nel Riferimento alla sorgente del browser.

4. Cambia il design o chiedi all'IA di farlo

Per una modifica solo CSS, mantenere il collegamento ospitato e utilizzare OBS CSS personalizzato campo. Si applica solo a quella fonte, quindi un normale browser che apre lo stesso URL non mostrerà tali sostituzioni. Per un file HTML modificato, aggiungi le sostituzioni dopo gli stili esistenti o collega un foglio di stile locale dopo di essi. Fornisci il tuo logo, file di caratteri, colori del marchio, dimensioni della tela e un riferimento visivo.

Alcune pagine supportano &css= oppure &b64css=; il supporto è per pagina. poll.html, ad esempio, non legge nessuno dei due. Controlla il parser della pagina prima di utilizzare le opzioni URL. Una pagina Web generalmente non può caricare un carattere o un'immagine arbitraria dal disco locale di un altro computer.

Quando si modifica il markup, conservare gli ID/classi a cui fanno riferimento gli script. Se JavaScript ricostruisce un elemento a ogni aggiornamento, la grafica permanente deve vivere all'esterno di quell'elemento o essere ricreata dal renderer. Copia un foglio di stile/script condiviso e modifica il riferimento della tua pagina se desideri che la modifica influisca solo sul tuo design.

Utilizza il prompt specifico del tipo nelle guide sopra oppure inizia con questo prompt generale:

Le type guide descrivono il vero fattore scatenante da preservare. Non accettare un design che funziona solo perché codifica in modo rigido i messaggi di esempio. Conserva una copia del file originale e confronta la visualizzazione modificata utilizzando gli stessi input di test.

5. Evita che la chat in arrivo diventi codice

Messaggi, nomi, titoli, importi, metadati e collegamenti multimediali possono provenire da spettatori o servizi esterni. Sanifica nel punto in cui il renderer personalizzato li inserisce. Una stringa ricevuta tramite SSN non è autorizzata a eseguirla. Utilizza testo DOM semplice per campi semplici; utilizzare il disinfettante in pacchetto per l'HTML supportato del corpo del messaggio. Vedi Spiegazione di OWASP sui safe sink e sulla sanificazione dell'HTML.

In SSN, textonly si applica solo a chatmessage. Se vero, rendi quel corpo come testo letterale. Altrimenti potrebbe contenere emoticon e formattazione consentita. Renderizza altri campi normali come testo; campi multimediali come chatimg e contentimg sono URL/dati, non snippet HTML. Sono supportati anche

<!-- Example for a copied page at the repository root. -->
<script src="./libs/objects.js"></script>
<script src="./shared/utils/chatHtml.js"></script>
<script>
function renderChatBody(element, data) {
    var message = String(data.chatmessage == null ? "" : data.chatmessage);
    if (data.textonly) {
        element.textContent = message;
    } else {
        element.innerHTML = SocialStreamChatHTML.sanitize(message);
    }
}
// Names, amounts, titles, and other plain fields use textContent:
// nameElement.textContent = String(data.chatname || "");
</script>

Mantenere un disinfettante equivalente esistente anziché aggiungerne un secondo. Per i file nidificati regolare i percorsi relativi degli script. Crea avatar e collegamenti con proprietà DOM dopo aver convalidato l'URL nella politica sui media/link esistente della pagina. Non interpolare nomi grezzi in stringhe di attributi o colori grezzi in markup di stile; convalidare gli stili prima di impostare le singole proprietà. La sanificazione HTML non rende una stringa sicura da eseguire come JavaScript o un'istruzione AI.

Testare il renderer in un'anteprima isolata

  • Utilizzare un nome semplice come Guest <b>One</b>: le parentesi devono rimanere testo.
  • Prova chatmessage: "<b>Hello</b>" con textonly: true, quindi falso. Il markup letterale e il contenuto formattato consentito dovrebbero seguire i rispettivi percorsi.
  • Controlla un'emoticon supportata e un messaggio di sola immagine in modo che le modifiche alla sicurezza non rimuovano tali funzionalità.
  • Chiedi all'IA di testare una sonda innocua come <img src=x onerror="window.__ssnInjectionProbe=1"> nel renderer modificato. Non deve essere eseguito, impostare il marcatore o lasciare attributi di eventi eseguibili. Testare anche un collegamento allo schema di script. Esegui le sonde localmente, non nella chat pubblica.

Una sonda passante verifica esclusivamente i percorsi esercitati. Mantieni i test concentrati sui renderer e sui campi modificati dalla progettazione.

6. Testare separatamente layout, connessione e OBS

  1. Disposizione: utilizzare la modalità anteprima/demo documentata della pagina, ove disponibile, o esempi locali fittizi. Testa nomi/messaggi lunghi, avatar mancanti, dati vuoti e il numero di righe previsto.
  2. Consegna SSN: mantieni SSN attivo e usa Crea messaggio di prova con la stessa sessione. È necessaria la normale modalità di acquisizione dell'API di estensione controllo API remoto dell'estensione abilitato. Utilizzare una configurazione di test isolata; i test inviati possono attivare automazioni configurate.
  3. Il vero fattore scatenante: inserire un messaggio nel Dock per una carta in primo piano, inviare un voto per un sondaggio, selezionare un vincitore per un omaggio, modificare il testo del ticker per un ticker o avviare un timer per un timer. La chat semplice non è un test universale.
  4. Cattura reale: conferma che un messaggio/evento di origine effettivo raggiunge la pagina originale e modificata. Un evento simulato dimostra il rendering, non l'acquisizione della piattaforma.
  5. OBS: controlla la fonte nelle sue dimensioni finali, trasparenza, animazioni, audio, caratteri e livelli. Esercizio mostra/nascondi, cancella/reimposta e aggiorna. Il browser e OBS hanno archiviazione e sessioni separate; l'accesso al browser o localStorage non viene condiviso automaticamente.

Per le pagine che raccolgono dati in memoria, lo scaricamento o l'aggiornamento può far perdere lo stato. Controlla la guida ai tipi prima di abilitare l'aggiornamento automatico o lo spegnimento quando nascosto. I display gestiti dall'host hanno un comportamento di ripristino diverso. Rimuovi demo/preview flag prima di aspettarsi dati in tempo reale.

File e riferimenti utili per fornire la tua intelligenza artificiale

  • docs/event-reference.html: campi canonici, eventi denominati, metadati, media e valori delle donazioni.
  • docs/customoverlays.md: ricevitori personalizzati ed esempi di collegamento.
  • Compatibilità di eventi e avvisi: quali eventi/campi un progetto può aspettarsi da una fonte.
  • Guida al messaggio di prova e createtestmessage.html: esempi di carichi utili e modalità di consegna.
  • libs/objects.js e shared/utils/chatHtml.js: sanificazione display confezionato.
  • shared/utils/chatBadges.js e shared/utils/contentImage.js: gestione dei badge e delle immagini esistenti.
  • js/transport-dedupe.js, js/local-server-url.js, e shared/overlay-control-transport.js: supporto di trasporto esistente quando caricato dalla tua pagina.
  • currency.js: preservare hasDonation per visualizzare e onorare un USD numerico valido donoValue, compreso zero.
  • Event Flow e Comandi e API: riutilizzare i controlli esistenti quando il progetto necessita di un trigger.

Fornire la fonte effettiva dell'overlay e il relativo CSS/JS di riferimento, nonché questi documenti. Un riferimento a un evento da solo non descrive lo stato di controllo di un sondaggio o la struttura di rendering privata di ogni overlay.

Caso speciale: pagine che leggono file di dati separati

La mappa legge i file JSON locali con fetch(), che un browser può bloccare durante l'apertura da disco. Per un semplice restyling della mappa, utilizza il collegamento ospitato con OBS Custom CSS. Per una copia HTML modificata, chiedi alla tua IA di includere i dati della mappa richiesti nella pagina in modo che si apra direttamente dal disco. L'hosting è un'opzione avanzata per una pagina che ne ha specificatamente bisogno, non un normale passaggio di configurazione per questi overlay.

Fermati al più piccolo problema confermato. Un restyling non dovrebbe richiedere la modifica degli script di acquisizione o l'invenzione di nuovi campi evento. Se condividi un fork pubblico, includi le sue risorse di supporto e mantieni i lanciatori privati ​​fuori da quel caricamento.
