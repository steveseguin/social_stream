Spiegazione dei server e servizi locali

Social Stream Ninja usa diversi servizi locali. Scegli quello che corrisponde a ciò che vuoi fare.

1. Abilita server locale

Questa opzione del menu File avvia nell'app desktop un relay WebSocket che tiene conto di stanze e canali. Le pagine Social Stream supportate possono usarlo per scambiare chat e comandi sullo stesso computer. È un endpoint alternativo per l'instradamento server specifico della pagina.

Non ospita il sito Social Stream, non acquisisce autonomamente una piattaforma e non fornisce l'API HTTP di automazione. Inizia dalla guida ad Abilita server locale.

2. API di controllo locale e MCP

Questa API loopback facoltativa consente ai programmi sul computer SSApp di gestire sorgenti e impostazioni supportate, leggere stato e diagnostica, esaminare finestre dell'app o delle sorgenti e seguire gli eventi acquisiti. L'adattatore MCP incluso presenta queste operazioni come strumenti ai client IA compatibili.

Abilitalo sotto File > IA locale / Automazione (Local AI / Automation). È separato da Abilita server locale. Vedi la Guida all'API di controllo locale e a MCP.

3. Server domestico headless o VPS

La modalità headless esegue l'app desktop Electron completa con le finestre sorgente nascoste. Su Linux richiede comunque un sistema di visualizzazione come Xvfb. È utile quando un computer dedicato deve continuare ad acquisire la chat senza monitor collegato.

La modalità headless non crea un'API di controllo pubblica. Il controllo remoto usa il normale trasporto WebRTC o WebSocket di Social Stream. Vedi la guida all'hosting headless.

4. Server multimediale locale

L'app desktop lo avvia automaticamente quando sono disponibili media locali Event Flow. Serve solo file approvati tramite SSApp e risorse di runtime selezionate, attraverso un percorso con token casuale per profilo.

Non è un server web o file generico. Vedi File multimediali per Event Flow per scegliere tra file locali, caricamenti e hosting cloud.

Il server alternativo è diverso

Impostazioni come Invia messaggi chat al server API e Il dock invia i comandi all'estensione tramite server scelgono come instradare chat e comandi. I parametri URL generati includono server, server2, e server3.

Queste impostazioni usano normalmente il servizio WebSocket ospitato di Social Stream. Quando una pagina supportata ha anche localserver, usa invece il relay locale dell'app desktop. Vedi Sessioni, password, relay e modalità server per i controlli di instradamento.

Usa link appena generati. I parametri di instradamento sono specifici della pagina. Non copiare un parametro server da una pagina all'altra presumendo che abbia lo stesso significato.

Altre porte locali temporanee

Alcuni flussi di accesso e collegamento account aprono brevemente una porta di callback loopback e la chiudono alla fine. Questi listener temporanei non sono server SSN generici né API di automazione.
