Создать тестовые сообщения

Отправляйте контролируемые вымышленные сообщения и события в свою сессию Social Stream.

Что делает этот инструмент

Это Страница создания тестового сообщения отправляет искусственные данные Social Stream в ваш док, оверлеи, оповещения или Event Flow. Используйте его для проверки, не дожидаясь реального сообщения чата, пожертвования, членства, рейда, награды или другого события.

По возможности используйте тестовую сессию. Отправленное сообщение ведёт себя как входящий трафик сессии и может запускать оповещения, звуки, вебхуки, действия OBS и другую автоматизацию.

Быстрый старт для SSApp или расширения

  1. Откройте Social Stream Ninja и убедитесь, что сервис активен.
  2. В разделе Global settings and tools («Общие настройки и инструменты») → Механика, включите удалённое управление расширением через API. В SSApp настройка называется так же.
  3. Скопируйте ID сессии из Social Stream или из session= значение в URL дока или оверлея.
  4. Открыть Создать тестовое сообщение и введите этот ID сессии.
  5. Оставьте Способ отправки (Send Via) со значением Приём через API расширения (Extension API ingest) для обычной проверки.
  6. Выберите предустановку, измените её поля и нажмите Загрузить предустановку (Load Preset).
  7. Проверьте Payload JSON и нажмите Отправить (Submit).
  8. Убедитесь, что элемент появился в доке или целевом оверлее и ожидаемая автоматизация выполнилась.

Сессию можно указать в URL: createtestmessage.html?session=YOUR_SESSION_ID.

Пример: одно вымышленное сообщение на 1 000 KICKs

Создаёт одно сообщение поддержки в стиле Kick стоимостью 1 000 KICKs. Это не создаёт 1 000 отдельных сообщений.

  1. Выберите Сообщение чата (Chat Message) предустановку.
  2. Установите Введите на Kick.
  3. Введите тестовое имя и сообщение.
  4. Установите Сумма пожертвования (Has Donation) на 1000 KICKs.
  5. Выберите Обновить JSON из полей (Update JSON from Fields), проверьте JSON и отправьте.

Минимальные данные:

{
  "type": "kick",
  "chatname": "Test Supporter",
  "chatmessage": "Thanks for the stream!",
  "hasDonation": "1000 KICKs"
}

Используйте Сообщение чата (Chat Message) для этого примера. Предустановка Пожертвование / Cheer содержит поля Cheer, специфичные для Twitch.

Предустановки и собственный JSON

Предустановки дают начальные данные для типичных случаев: пожертвований, подписчиков, подарочных подписок, рейдов, наград, обновлений числа зрителей, новых участников чата и событий поезда поддержки.

  • Загрузить предустановку (Load Preset) заменяет JSON выбранной предустановкой и текущими значениями полей.
  • Обновить JSON из полей (Update JSON from Fields) создаёт простое сообщение из видимых полей.
  • Вы можете редактировать JSON данных (Payload JSON) напрямую при проверке конкретного поля или структуры события.
  • hasDonation содержит отображаемую сумму поддержки, например 1000 KICKs или $10.00.
  • Включайте только event при проверке настоящего именованного события. Обычная строка чата с пожертвованием может использовать hasDonation самостоятельно.

Определения полей и реальные примеры платформ смотрите в Справочник событий.

Решение частых проблем

  • Ничего не появляется: убедитесь, что целевая страница открыта и использует тот же ID сессии.
  • Приём через API расширения не работает: включите удалённое управление расширением через API, затем перезагрузите док или оверлей и попробуйте снова.
  • Прямой режим сообщает об отправке, но ничего не появляется: используйте Extension API ingest, если в целевом URL нет соответствующего &server или &server2 режим.
  • Срабатывает неверное событие: проверьте Payload JSON на оставшиеся поля другой предустановки.
  • Тест Kick ведёт себя как Twitch: используйте предустановку Chat Message и задайте type и hasDonation как показано выше.
  • Автоматизация выполняется несколько раз: проверьте, не открыто ли несколько доков, страниц действий или экземпляров Event Flow в одной сессии.
