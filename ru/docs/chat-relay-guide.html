Пересылка чата между платформами

Настройте пересылку между Twitch и YouTube, выберите отправителей и найдите причины повторяющихся сообщений.

Все руководства 1. Убедитесь, что оба чата могут принимать ответы 2. Создайте пересылку Twitch → YouTube в Event Flow 3. Добавьте обратное направление 4. Разберитесь с отражёнными сообщениями 5. Ограничьте пересылаемые сообщения Устранение неполадок

1. Убедитесь, что оба чата могут принимать ответы

Подключите чаты Twitch и YouTube Live к одному сеансу SSN. Убедитесь, что оба видны в док-панели, затем вручную ответьте в каждый из них на сообщение с известной исходной вкладкой. Используйте собственные тестовые каналы. Источник захвата только для чтения не может отправлять пересылаемые сообщения.

Для этой настройки держите открытыми только нужные чаты назначения. Направление на платформу может включать несколько подходящих исходных вкладок этой платформы. Если используете отдельную учётную запись бота Twitch, сначала выполните Учётные записи ботов для ответов в первую очередь.

2. Создайте пересылку Twitch → YouTube в Event Flow

Откройте Редактор Event Flow из меню SSN (ссылка также есть в разделе оверлея Actions). Создайте сценарий и дайте ему понятное имя, например Из Twitch в YouTube.

  1. Добавьте From Source («Из источника») триггер из раздела User & Source («Пользователь и источник»). Выберите Twitch в качестве источника.
  2. Добавьте Relay Chat («Переслать в чат») и соедините выход триггера со входом действия.
  3. Выберите это действие. Установите Relay Destination («Направление пересылки») на YouTube, а шаблон сообщения оставьте [{source}] {username}: {message}.
  4. Выберите Save Flow («Сохранить сценарий») и включите сохранённый сценарий. SSN должен оставаться активным.
  5. Отправьте новое обычное сообщение в собственном тестовом чате Twitch. Убедитесь, что в YouTube появилась одна копия с подписью.

У YouTube Shorts отдельный тип источника и отдельное направление. Выбирайте YouTube Shorts там, где это нужно; это направление не взаимозаменяемо с YouTube.

3. Добавьте обратное направление

Создайте второй сценарий с именем Из YouTube в Twitch: From Source: YouTube → Relay Chat: Twitch. Сохраните и включите его. Отправьте новое сообщение с каждой стороны и убедитесь, что каждое создаёт одну копию на другой платформе.

Оставьте Relay all messages (!NOT RECOMMENDED!) («Пересылать все сообщения — НЕ РЕКОМЕНДУЕТСЯ!») выключенным при использовании этих сценариев, чтобы вторая система пересылки не дублировала их работу. Также проверьте, не соединяет ли эти чаты другой бот или сервис мультитрансляции.

4. Разберитесь с отражёнными сообщениями

Отражение — это сообщение, отправленное SSN и затем снова захваченное из чата назначения. Действия Relay Chat автоматически пропускают распознанные отражения. Они также исключают исходную вкладку.

Чтобы скрыть захваченное эхо в док-панели и оверлеях, добавьте Reflection Filter («Фильтр отражений») в начале нужного сценария и выберите Block All («Блокировать все»). Allow First («Разрешить первое») сохраняет одно подходящее отражение в заданном временном окне; Allow All («Разрешить все») показывает их. Это управляет отображением после захвата, а не направлением пересылки.

В текущих свойствах Relay Chat нет флажка «No Reflections». Для управления отображением используйте отдельный Reflection Filter. Если внешний сервис изменяет пересланное сообщение, автоматическое распознавание может его пропустить.

5. Ограничьте пересылаемые сообщения

Для команд добавьте Message Starts With («Сообщение начинается с») триггер со значением ! и подключите его через NOT (НЕ) и объедините результат с условием источника с помощью AND (И) перед Relay Chat. См. Руководство по Event Flow по соединению логических элементов. Проверьте и обычное сообщение, и команду.

Если вы предпочитаете более простую общую пересылку, используйте Global settings and tools → Commands → Pick relay destinations («Общие настройки и инструменты → Команды → Выбрать направления пересылки») и введите twitch,youtube. Пустой список означает все подходящие направления. Этот список определяет, куда отправляются сообщения, а не какие входящие платформы могут запускать пересылку. Перед включением этого варианта отключите пару сценариев пересылки Event Flow.

Поля разрешения и блокировки ролей учётных записей SSApp в том же разделе Commands позволяют ограничить учётные записи, отправляющие пересылки. Используйте роль, назначенную нужному отправителю; несовпадающая роль может исключить все подходящие направления.

Устранение неполадок

  • Ничего не отправляется: снова попробуйте ответить вручную, проверьте вход и право отправки сообщений, включите сохранённый сценарий и проверьте ограничения направлений и ролей учётных записей.
  • Сообщения множатся: сначала отключите сценарии пересылки. Проверьте дублирующиеся источники захвата, общую настройку Relay all и внешних ботов пересылки, прежде чем снова проверять одно направление.
  • Дубликаты видны только в док-панели: проверьте правила отображения Reflection Filter и общие настройки эха в разделе Message - Visibility.
  • Неправильный чат назначения YouTube: проверьте, выбран ли YouTube или YouTube Shorts, и закройте лишние подходящие чаты.

Действия Test Flow могут отправлять настоящие сообщения. Используйте контролируемые направления; синтетическая проверка не подтверждает правильный выбор учётной записи для реального источника.
