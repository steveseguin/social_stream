Описание локальных серверов и сервисов

Social Stream Ninja использует несколько разных локальных сервисов. Выберите тот, который подходит вашей задаче.

1. Включение локального сервера

Этот пункт меню File запускает внутри настольного приложения ретранслятор WebSocket с поддержкой комнат и каналов. Совместимые страницы Social Stream могут обмениваться через него чатом и командами на одном компьютере. Это альтернативная конечная точка для серверной маршрутизации конкретных страниц.

Он не размещает сайт Social Stream, не захватывает платформу самостоятельно и не предоставляет HTTP API автоматизации. Начните с руководства по включению локального сервера.

2. Локальный API управления и MCP

Этот включаемый по желанию локальный API позволяет программам на компьютере с SSApp управлять поддерживаемыми источниками и настройками, читать состояние и диагностику, просматривать окна приложения и источников и следить за захваченными событиями. Встроенный адаптер MCP предоставляет эти операции совместимым ИИ-клиентам как инструменты.

Включите в разделе File > Local AI / Automation. Он независим от Включить локальный сервер. См. Руководство по локальному API управления и MCP.

3. Домашний сервер или VPS без интерфейса

Режим без интерфейса запускает полное настольное приложение Electron со скрытыми окнами источников. В Linux всё равно нужна графическая среда, например Xvfb. Это удобно, когда отдельный компьютер должен постоянно захватывать чат без подключённого монитора.

Режим без интерфейса не создаёт общедоступный API управления. Для дистанционного управления используется обычное подключение Social Stream через WebRTC или WebSocket. См. руководство по размещению без интерфейса.

4. Локальный медиасервер

Настольное приложение запускает его автоматически, когда доступны локальные медиа Event Flow. Он отдаёт только файлы, разрешённые через SSApp, и выбранные служебные ресурсы по пути со случайным токеном, отдельным для каждого профиля.

Это не универсальный веб-сервер или файловый сервер. См. Медиафайлы для Event Flow для выбора между локальными файлами, загрузками и облачным размещением.

Резервное подключение через сервер — отдельная функция

Настройки, такие как Отправлять сообщения чата на API-сервер и Док-панель отправляет команды расширению через сервер определяют маршруты чата и команд. Среди создаваемых флагов URL есть server, server2, и server3.

Обычно эти настройки используют размещённый WebSocket-сервис Social Stream. Если поддерживаемая страница также содержит localserver, она использует локальный ретранслятор настольного приложения. См. Сеансы, пароли, ретрансляция и серверные режимы о настройках маршрутизации.

Используйте заново созданные ссылки. Флаги маршрутизации зависят от страницы. Не переносите серверный флаг на другую страницу в предположении, что он означает то же самое.

Другие временные локальные порты

Некоторые процессы входа и привязки аккаунтов ненадолго открывают локальный порт обратного вызова и закрывают его после завершения. Эти временные слушатели не являются универсальными серверами SSN или API автоматизации.
