Важно: подключение API OpenAI не связывает SSN с существующим текстовым или голосовым диалогом ChatGPT. API OpenAI ведёт собственное состояние диалога.

Вариант 1: помощник ChatGPT в браузере (экспериментальный)

Это наиболее подходящий вариант, если вы уже пользуетесь ChatGPT в Chrome и не хотите использовать API-ключ. SSN может захватывать новые текстовые сообщения со страницы с типом источника openai, как обычный источник чата.

Захват разговора с ChatGPT

  1. Установите и включите расширение Social Stream Ninja для Chrome.
  2. Во всплывающем меню включите необязательную функцию ChatGPT источник.
  3. Открыть https://chatgpt.com/ и перезагрузите страницу после включения источника.
  4. Откройте док-панель SSN с тем же сеансом.
  5. Отправьте новое сообщение в ChatGPT. Новые сообщения пользователя и ChatGPT должны появиться в док-панели; существующая история намеренно пропускается.

Отправка чата трансляции в открытую вкладку ChatGPT

  1. Проводите проверку на закрытой трансляции или трансляции по ссылке и в обычном текстовом диалоге ChatGPT.
  2. В разделе Управление, включите Пересылка всех сообщений.
  3. Установите Выберите направления пересылки на openai чтобы захваченные сообщения зрителей отправлялись только во вкладку ChatGPT.
  4. Оставьте вкладку ChatGPT открытой. Новые ответы возвращаются в SSN как openai сообщения.
  5. Используйте звук ChatGPT или озвучивание текста и вывод в оверлей SSN, чтобы передавать эти ответы в эфир.

Экспериментально: элементы управления веб-страницы могут меняться, пересылка всех сообщений может переполнить диалог, а голосовой режим ChatGPT может не принимать вставленный текст так, как обычная текстовая страница. Используйте фильтры или тестовую трансляцию, прежде чем отправлять каждое сообщение зрителей.

Используйте провайдера, если SSN должен создавать ответы, модерировать сообщения, переводить чат, искать сведения в базе знаний или создавать оверлеи.

  2. Открыть Настроить провайдера языковой модели (Configure LLM Service Provider) и выберите провайдера, которым вы действительно пользуетесь.

  4. Выберите Проверить выбранного чат-бота. Результат Connected подтверждает только то, что провайдер ответил на тестовый запрос.
  5. Включите отдельную функцию, которая должна его использовать: Primary bot, Private bot, соведущего, модерацию, перевод, RAG или конструктор.

Вариант 3: голосовой ИИ-соведущий

Соведущий создан именно для сценария «разговаривать с ИИ, который одновременно видит чат трансляции». Звук вашего микрофона и выбранные сообщения чата поступают в один сеанс соведущего, а ответ может прозвучать в эфире.

  1. Открыть cohost.html?session=YOUR_SESSION.
  2. Выберите голосового провайдера или провайдера реального времени либо языковую модель, настроенную во всплывающем окне SSN.
  3. Явно выберите микрофон и Голосовой ответ (Audio Response), затем нажмите Запустить соведущего (Start Co-host).
  4. При использовании OpenAI Realtime оставьте для Live Chat режим Только контекст — отвечать по запросу если хотите, чтобы ИИ запоминал последние сообщения зрителей, не перебивая. Выберите Вопросы и упоминания или Каждое сообщение (Every message) для автоматических голосовых ответов; эти режимы не отправляют сообщения в чат платформы.
  5. Для OpenAI Realtime захватывайте в OBS звук браузера или приложения с соведущим и используйте cohost-overlay.html?session=YOUR_SESSION для аватара на сцене и облачка речи. Оверлей не получает тот же голосовой поток WebRTC. Если поддерживается, выберите виртуальный аудиокабель в списке устройств вывода соведущего; &forcetts намеренно добавляет отдельный голос оверлея.
  6. Дополнительные инструменты управления трансляцией по умолчанию отключены. Включите Spotify, список разрешённых сцен OBS или управление выделенным сообщением во всплывающем окне SSN, затем активируйте те же инструменты в разделе Управление трансляцией через соведущего (Co-host Stream Controls) на странице соведущего.
  7. Чтобы уменьшить задержку OpenAI, выберите модель Mini, уровень рассуждений Low и смену реплик Fast. Full quality и более высокий уровень рассуждений могут улучшить сложные ответы ценой большей задержки и стоимости API; Fast может прерывать естественные паузы. Diagnostics показывает измеренную задержку до первого вывода.
  8. Передача видео с камеры и демонстрация экрана в OpenAI необязательны; по умолчанию выбран режим Без видео (No Video). Если выбран этот вариант, SSN отправляет один текущий кадр с каждым прямым голосовым или текстовым запросом. Это не непрерывный видеопоток; передача кадра может увеличить стоимость API и задержку.
  9. Оставьте текстовый пузырь видимым или добавьте субтитры, чтобы зрители могли следить за разговором и без звука.

OpenAI Realtime использует ключ проекта OpenAI, указанный в разделе ChatGPT API во всплывающем окне SSN. Обычный ключ остаётся в фоновом процессе расширения SSN или настольного приложения, который создаёт краткосрочный клиентский секрет Realtime для страницы соведущего. Затем звук микрофона и голос ИИ передаются через WebRTC. Ответы ограничены 512 выходными токенами, а раздел Diagnostics показывает суммарное использование и задержку. SSN проверяет сеансы без активности и восстанавливает прерванные соединения; после восстановления снова применяются инструкции и настройки производительности, но предыдущий голосовой диалог восстановить нельзя. Это создаёт сеанс соведущего SSN; существующий диалог на сайте ChatGPT или в настольном приложении ChatGPT не перехватывается.

Вариант 4: основной бот для чата трансляции

Основной бот анализирует полученные сообщения зрителей и может отвечать в оверлее, озвучивать ответы или отправлять их обратно в чаты поддерживаемых платформ.

  1. Настройте и проверьте провайдера ИИ.
  2. Включите Основной ИИ-бот для чата.
  3. Настройте слова-триггеры, ограничение доступа модераторами, частоту запросов, историю и инструкции для модели.
  4. Для безопасной первой проверки включите Ответы бота отправляются ТОЛЬКО на страницу оверлея бота.
  5. Открыть bot.html?session=YOUR_SESSION и включите озвучивание текста, если ответы должны произноситься вслух.
  6. Отключайте режим вывода только в оверлей лишь после проверки, что целевая платформа поддерживает отправку сообщений.

Ответы на платформах обычно отправляются от имени учётной записи, в которую выполнен вход. Для отдельного имени используйте специальную учётную запись бота YouTube, Twitch или Kick, если такая возможность поддерживается.

Вариант 5: бот для личного общения

chatbot.html — личный помощник и страница для проверки запросов. Включите Приватный интерфейс чат-бота (Chat Bot - Private Interface), откройте страницу со своей сессией и используйте настроенного провайдера языковой модели.

Личный бот работает отдельно от основного бота для чата трансляции и пока не использует его набор данных RAG или другую историю чата.

Решение частых проблем

  • Подключение есть, но ответа на реальные сообщения нет: включите основного бота или нужную функцию ИИ; сама по себе настройка провайдера не запускает обработку чата.
  • Соведущий видит чат, но молчит: Режим Context only специально ждёт, пока стример спросит о чате. Для автоматических ответов выберите Questions and mentions или Every message.
  • Браузерный источник ChatGPT не передаёт сообщения: разрешите захват ChatGPT, перезагрузите chatgpt.com, затем проверьте на новой реплике, а не на старой истории.
  • Бот пропускает большинство сообщений: проверьте слова-триггеры, режим «только модераторы», ограничения частоты запросов и указание модели отвечать выборочно.
  • Текст появляется, но звука нет: убедитесь, что страница, создающая озвучивание, открыта и OBS захватывает её звук.
  • Бот не может отправлять сообщения: проверьте поддержку отправки сообщений на платформу, состояние входа, разрешения учётной записи и ограничения частоты запросов.
