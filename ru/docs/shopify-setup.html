Показывайте товары и покупки Shopify.

Shopify в Social Stream Ninja

Продвигайте общедоступные товары с изображениями, ценами, читаемыми ссылками и QR-кодами. Получайте подписанные уведомления об оплаченных заказах как покупка оповещения в ленте активности, множественных оповещениях и Event Flow. Продвижение товаров работает независимо от платёжных оповещений.

Подключите покупки · Импорт товаров · Оверлеи OBS · Проверяйте безопасно · Ограничения и устранение неполадок

Доступность: автоматические оповещения требуют развёрнутого и включённого приёмника Shopify в API SSN. Если он недоступен, сохранение настроек сообщает об ошибке и не включает Shopify. Импорт общедоступных товаров и ручное продвижение независимы. Это руководство описывает код интеграции; для подтверждения работы сервиса всё ещё нужна проверка с настоящим продавцом.

Подключите оплаченные покупки

  1. В Shopify откройте Settings → Notifications → Webhooks. Найдите секрет подписи для вручную созданных вебхуков. Это не токен Storefront.
  2. В SSN откройте Монетизация → Покупки Shopify → Настройка. Введите постоянный your-store.myshopify.com домен и секрет подписи вебхука. Включите покупки Shopify и нажмите Сохранить настройку.
  3. Нажмите Скопировать URL приёмника. В Shopify создайте вебхук с событием Оплата заказа, формат JSONи этот URL приёмника. Выберите поддерживаемую стабильную версию API вебхуков; интеграция разработана для контракта заказов 2026-07.
  4. Сохраните вебхук Shopify. Оставляйте SSN включённым для обработки покупок. Перед приёмом данных заказа приёмник проверяет HMAC исходного тела и совпадение магазина.

Секрет подписи хранится зашифрованным на приёмнике SSN и очищается из поля после сохранения. Отдельный приватный ключ чтения остаётся на устройстве. Ни один ключ не входит в ссылки OBS или зрительские QR-коды. Shopify использует отдельный приёмник; старый переключатель удалённого управления API не нужен.

Созданный URL означает сохранение конфигурации, а не получение данных от Shopify. Статус различает ожидание, проверенный тест, пропущенное событие и полученную покупку. Для смены магазина сначала отключите подключение. Выключение Shopify приостанавливает локальную обработку; отключение удаляет приёмник и очередь событий. При отключении удалите соответствующий вебхук Shopify.

Импортировать общедоступный товар

  1. Введите свой myshopify.com домен в настройках Shopify. Для импорта товаров не нужно включать оповещения или вводить секрет подписи.
  2. Разверните Импортировать товар, вставьте общедоступный URL товара и нажмите Загрузить данные товара.
  3. Если доступ без токена не возвращает товар, укажите публичный токен Storefront. Его можно создать через канал Headless в Shopify. Опубликуйте товар в этой витрине и Online Store. Не вставляйте токен Admin API или приватный токен Storefront.
  4. SSN открывает существующий Товары и ссылки поддержки редактор с названием, изображением, ценой и канонической публичной ссылкой Shopify. Проверьте их и нажмите Добавить товар или ссылку, включите каталог и Сохранить настройку.

Импорт считывает по одному товару через Storefront API. Токен необязателен, используется только для этого запроса и затем очищается. Канонический URL Online Store из Shopify становится публичной ссылкой, включая собственный домен, если Shopify его возвращает. Недоступные товары и товары без публичной ссылки Online Store исключаются.

Цена заполняется только при совпадении минимальной и максимальной цены вариантов товара. Иначе поле остаётся пустым; указывайте конкретную цену вручную только если она точно описывает предложение. Импорт — снимок данных, а не постоянная синхронизация остатков и цен. Проверяйте сведения при изменениях магазина. Всегда можно добавить товар вручную.

Используйте существующие оверлеи

В разделе Ссылка оверлея для, выберите Товары и ссылки поддержки. Используйте Только витрина товаров для изображений, цен и QR-кодов, Только карточка поддержки для небольшой постоянной или периодической ссылки магазина либо Только оповещения об активности для покупок. Скопируйте каждую нужную ссылку OBS в отдельный источник «Браузер», начав с 800 × 600.

Укажите в необязательном фильтре источника оповещений shopify для показа только активности Shopify в общем торговом оверлее. Для этого включите товары и ссылки поддержки. Существующие множественные оповещения и лента активности получают покупки Shopify независимо от каталога.

Карточки товаров ведут на общедоступные страницы товаров. Используйте Копировать публичную ссылку чтобы отправить кликабельный адрес в чат, и проверьте QR-код телефоном при итоговом размере трансляции. Оповещение о покупке никогда не берёт QR-код или изображение случайного товара из чередования. Вебхуки заказа не дают надёжных URL изображений товаров, поэтому оповещения текстовые; импортированные рекламные карточки могут показывать изображения.

В Event Flow выберите тип события purchase и задайте фильтр источника или типа shopify. Сравните meta.commerce.orderTotal для правил по стоимости заказа и проверьте meta.commerce.currency перед сравнением сумм. Это покупки: событие hasDonation или donoValue не создаётся, а цели пожертвований не увеличиваются. Надпись «Подарок» на рекламной карточке не меняет классификацию заказов. Доставка другому человеку не доказывает подарок автору.

Безопасный предпросмотр и проверка

Показать пример открывает изолированный пример оверлея без подключения к сеансу. Он не запускает Event Flow, не меняет суммы и не проверяет платёж.

Заказы Shopify с явной отметкой test: true подтверждаются и показываются как тесты в статусе приёмника без оповещений и действий покупки. Также пропускаются отсутствующие тестовые флаги, неоплаченные и частично оплаченные заказы, отмены, нулевые суммы и устаревшие или неверные временные метки. Для сквозной проверки используйте магазин разработки. Образец из админ-панели без надёжного тестового флага не следует отправлять в действующий поток наград; безопасная проверка вида доступна в предпросмотре SSN.

Что проверено без магазина

Изолированные тесты проверяют настоящую HTTP-доставку подписанного JSON с Unicode, подменённые подписи, повторную доставку, изоляцию тестовых заказов, точность валюты, слишком большие запросы, удаление приватных данных клиентов и восстановление после отключения через настоящее приложение SSApp. Эти проверки не создают заказы и не требуют аккаунта продавца.

Рабочий приёмник Shopify остаётся отключённым до проверки доставки из настоящего магазина. Ручное продвижение товаров работает независимо. Примеры вебхуков Shopify CLI помогают проверить обработку данных, но не проверяют подписки или повторные попытки и всё равно требуют учётных данных приложения. См. Ограничения доставки и устранение неполадок

  • Приёмник недоступен: the SSN API operator must deploy and enable the Shopify receiver. Do not use the legacy unsigned session webhook URL as a substitute.
  • Ожидание события: проверьте событие Order payment, JSON, точный URL приёмника, совпадение постоянного домена магазина и секрет подписи этого вебхука. Вебхук собственного приложения использует его секрет, а не секрет ручных уведомлений.
  • Подписанное событие пропущено: интеграция требует полностью оплаченного заказа с положительной суммой, test: false и подписанное тело updated_at за последние семь дней с допуском пяти минут в будущем. Оплата не выводится из создания заказа, исполнения или остатков.
  • SSN был отключён: принятые события хранятся в очереди до семи дней. Перезапустите SSN для продолжения. Статус и ожидающая обработка переживают перезапуск приёмника. Хранилище ограничено; если надёжно сохранить данные невозможно, сервис просит Shopify повторить доставку.
  • Дубликаты: приёмник исключает повторы по магазину и заказу, даже если идентификаторы доставок Shopify различаются. Записи дедупликации хранятся семь дней. SSN сохраняет обработанные идентификаторы до подтверждения. Сбой между внешним действием и сохранением всё же может повторить действие; для значимой автоматизации добавьте собственную защиту от повторного выполнения.
  • Нет имени покупателя: это намеренно. SSN исключает имена клиентов, электронную почту, адреса, заметки к заказу, пользовательские свойства позиций, URL оплаты и исходные идентификаторы заказов. Общедоступные названия товаров остаются обычным текстом.
  • Возвраты или изменения заказа: это лента текущих оповещений, а не система учёта или исполнения заказов. Возвраты, отмены и изменения сумм не отменяют прежние оповещения. Сверка истории заказов и автоматическое удаление товаров не предусмотрены.
