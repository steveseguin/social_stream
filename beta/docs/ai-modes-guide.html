Two Different Meanings of “ChatGPT”

Important: connecting the OpenAI API does not attach SSN to an existing ChatGPT web or voice conversation. OpenAI's API manages its own conversation state.

Option 1: ChatGPT Browser Companion (Experimental)

This is the closest option when you already use ChatGPT in Chrome and do not want an API key. SSN can capture new text turns from the page as source type openai, just like it captures a chat source.

Capture a ChatGPT Conversation

  1. Install and enable the Social Stream Ninja Chrome extension.
  2. In the popup, enable the opt-in ChatGPT source.
  3. Open https://chatgpt.com/ and reload the page after enabling the source.
  4. Open the SSN Dock with the same session.
  5. Send a new ChatGPT message. New User and ChatGPT turns should appear in the Dock; existing history is intentionally ignored.

Send Live Chat Into the Open ChatGPT Tab

  1. Test with a private or unlisted stream and a regular ChatGPT text conversation.
  2. Under Management, enable Relay all messages.
  3. Set Pick relay destinations to openai so captured viewer messages go only to the ChatGPT tab.
  4. Keep the ChatGPT tab open. Its new replies return to SSN as openai messages.
  5. Use ChatGPT audio or SSN TTS/overlay output to put those replies on stream.

Experimental: web-page controls can change, relay-all can flood a conversation, and ChatGPT Voice mode may not accept injected text like the regular text page. Use filters or a test stream before sending every viewer message.

Option 3: Voice AI Cohost

The cohost is designed for the exact “talk to AI while it also sees live chat” workflow. Your microphone and selected live-chat messages feed the same cohost session, and the response can be spoken on stream.

  1. Open cohost.html?session=YOUR_SESSION.
  2. Select a voice/realtime provider or the LLM configured in the SSN popup.
  3. Explicitly select your microphone and Audio Response, then press Start Co-host.
  4. With OpenAI Realtime, leave Live Chat on Context only - answer when asked when you want the AI to remember recent viewer messages without interrupting. Choose Questions and mentions or Every message for spoken automatic replies; these modes do not post into platform chat.
  5. For OpenAI Realtime, capture the audio from the co-host browser/app in OBS and use cohost-overlay.html?session=YOUR_SESSION for the stage avatar and speech bubble. The overlay does not receive the same WebRTC voice stream. Use the co-host output-device selector for a virtual cable when supported; &forcetts deliberately adds a separate overlay voice.
  6. Optional stream tools are off by default. Enable Spotify, an allowlist of OBS scene names, or featured-chat control in the SSN popup, then arm the same tools under Co-host Stream Controls on the co-host page.
  7. For lower OpenAI latency, choose the Mini model, Low reasoning, and Fast turn-taking. Full quality and higher reasoning can improve difficult answers at greater delay and API cost; Fast turn-taking can interrupt natural pauses. Diagnostics shows measured first-output latency.
  8. OpenAI camera and Screen Share input is optional and defaults to No Video. When selected, SSN sends one current image with each direct spoken or typed request; it is not a continuous video stream and can add API cost and latency.
  9. Keep the speech bubble visible, or provide captions, so viewers do not need to hear the AI voice to follow the conversation.

OpenAI Realtime uses the OpenAI project key configured under ChatGPT API in the SSN popup. The standard key stays in the SSN extension/Desktop background, which creates a short-lived Realtime client secret for the co-host page. Microphone and AI voice audio then travel over WebRTC. Replies are capped at 512 output tokens and Diagnostics shows cumulative usage and latency. SSN checks quiet sessions and reconnects failed transports; a recovered session reapplies its instructions and performance settings but cannot restore the previous spoken conversation. This creates an SSN cohost session; it does not take over an existing conversation in the ChatGPT website or ChatGPT desktop app.

Option 4: Primary Live-Chat Bot

The Primary bot evaluates captured viewer messages and can answer in an overlay, through TTS, or back into supported platform chats.

  1. Configure and test an AI provider.
  2. Enable the Primary AI chat bot.
  3. Choose trigger words, moderator-only behavior, rate limits, history, and prompt instructions.
  4. For a safe first test, enable Bot replies ONLY go to the bot overlay page.
  5. Open bot.html?session=YOUR_SESSION and enable TTS if replies should be spoken.
  6. Only disable overlay-only mode after confirming the destination platform supports posting.

Platform replies normally use the signed-in account. For a separate identity, use a dedicated YouTube, Twitch, or Kick bot account where supported.

Common Fixes

  • Connected, but no live reply: enable the Primary bot or the specific AI feature; provider setup alone does not process chat.
  • Cohost sees chat but stays quiet: Context only intentionally waits for the streamer to ask about chat. Switch to Questions and mentions or Every message for automatic replies.
  • ChatGPT browser source is silent: enable the ChatGPT opt-in, reload chatgpt.com, and test with a new turn instead of existing history.
  • Bot skips most messages: check trigger words, moderator-only mode, rate limits, and the model's instruction to reply selectively.
  • Text appears but no sound: confirm the TTS-producing page is open and OBS is capturing that page's audio.
  • Bot cannot post: check platform send-back support, login state, account permissions, and rate limits.
