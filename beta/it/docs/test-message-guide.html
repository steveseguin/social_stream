Crea messaggi di prova

Invia messaggi ed eventi fittizi controllati alla tua sessione Social Stream.

Cosa fa questo strumento

Il pagina Crea messaggio di prova invia payload Social Stream sintetici al dock, agli overlay, agli avvisi o alla configurazione Event Flow. Usalo per provare senza aspettare un vero messaggio chat, una donazione, un abbonamento, un raid, una ricompensa o un altro evento.

Usa una sessione di prova quando possibile. Un messaggio inviato si comporta come traffico in arrivo nella sessione e può attivare avvisi, suoni, webhook, azioni OBS o altre automazioni.

Avvio rapido per SSApp o l'estensione

  1. Apri Social Stream Ninja e assicurati che il servizio sia attivo.
  2. Sotto Impostazioni globali e strumenti → Meccanismi, attiva controllo API remoto dell'estensione. SSApp usa lo stesso nome per l'impostazione.
  3. Copia il tuo ID di sessione da Social Stream oppure da session= nell'URL del dock o dell'overlay.
  4. Apri Crea messaggio di prova e inserisci quell'ID di sessione.
  5. Lascia Invia tramite impostato su Acquisizione tramite API dell'estensione (Extension API ingest) per i test normali.
  6. Scegli un preset, modifica i campi e seleziona Carica preset (Load Preset).
  7. Controlla il JSON del payload, poi seleziona Invia (Submit).
  8. Verifica che l'elemento compaia nel dock o nell'overlay di destinazione e che venga eseguita l'automazione prevista.

Puoi includere la sessione nell'URL: createtestmessage.html?session=YOUR_SESSION_ID.

Esempio: un messaggio fittizio da 1.000 KICKs

Questo crea un singolo messaggio di sostegno in stile Kick del valore di 1.000 KICKs. Non crea 1.000 messaggi separati.

  1. Scegli il preset Messaggio chat (Chat Message) .
  2. Imposta Scrivi a Kick.
  3. Inserisci un nome e un messaggio di prova.
  4. Imposta Contiene donazione (Has Donation) a 1000 KICKs.
  5. Seleziona Aggiorna JSON dai campi (Update JSON from Fields), verifica il JSON e invialo.

Il payload minimo è:

{
  "type": "kick",
  "chatname": "Test Supporter",
  "chatmessage": "Thanks for the stream!",
  "hasDonation": "1000 KICKs"
}

Usa Messaggio chat (Chat Message) per questo esempio. Il preset Donazione / Cheer include campi cheer specifici di Twitch.

Usare preset e JSON personalizzato

I preset forniscono un payload iniziale per casi comuni come donazioni, abbonati, abbonamenti regalo, raid, ricompense, aggiornamenti degli spettatori, utenti alla prima chat ed eventi train.

  • Carica preset (Load Preset) sostituisce il JSON con il preset selezionato e i valori attuali dei campi.
  • Aggiorna JSON dai campi (Update JSON from Fields) crea un messaggio di base dai campi visibili.
  • Puoi modificare JSON del payload direttamente quando provi un campo o una struttura di evento specifici.
  • hasDonation contiene l'importo di sostegno visibile, ad esempio 1000 KICKs oppure $10.00.
  • Includi event solo quando stai provando un vero evento con nome. Una normale riga chat con donazione può usare hasDonation da solo.

Per le definizioni dei campi e gli esempi reali delle piattaforme, consulta il Riferimento degli eventi.

Soluzioni ai problemi comuni

  • Non compare nulla: verifica che la pagina di destinazione sia aperta e usi lo stesso ID di sessione.
  • L'acquisizione tramite API dell'estensione non riesce: attiva controllo API remoto dell'estensione, poi ricarica il dock o l'overlay e riprova.
  • La modalità diretta indica inviato, ma non compare nulla: usa Extension API ingest, a meno che l'URL di destinazione non abbia il valore corrispondente &server oppure &server2 .
  • Si attiva l'evento sbagliato: controlla nel JSON del payload eventuali campi rimasti da un altro preset.
  • Il test Kick si comporta come Twitch: usa il preset Chat Message e imposta type e hasDonation come mostrato sopra.
  • Un'automazione viene eseguita più volte: controlla se sono aperti più dock, pagine di azione o istanze di Event Flow sulla stessa sessione.
