투표, 경품 추첨, 참가 대기열

첫 경품 추첨: 스크린샷이 있는 단계별 안내

경품 추첨, 유료 참가권, 게임 경품, 복구 가이드

채팅 투표를 진행하고 당첨자를 뽑거나 다음에 참여할 시청자의 순서를 정하세요.

모든 가이드 1. 도구 선택 2. 객관식 투표 진행 3. 당첨자 추첨 4. 시청자 대기열 운영 5. 연습 및 복구

1. 도구 선택

목표 SSN에서 열기
채팅으로 다음 활동 투표 그래픽 투표 → 투표 옵션 (Graphical Poll → Poll Options)
참가자 무작위 선택 대기 목록 / 당첨자 추첨 (Wait List / Winner Draw), 당첨자 추첨 모드 활성화
대기열 순서로 시청자 참여 대기 목록 / 당첨자 추첨 (Wait List / Winner Draw), 당첨자 추첨 모드 비활성화

해당 섹션에서 생성한 링크를 OBS 브라우저 소스로 사용하세요. SSN과 채팅 소스를 켜 두고 링크의 세션, 비밀번호, 서버 옵션을 유지하세요. 경품 추첨 도구 는 당첨자 카드, 이름 릴, 커뮤니티 휠 표시 방식의 별도 참가자 목록을 제공합니다. 전용 추첨 제어에는 Giveaway Options 패널을 사용하세요. 대기 목록 / 당첨자 추첨도 별도로 계속 사용할 수 있습니다.

2. 객관식 투표 진행

  1. 열기 그래픽 투표 → 투표 옵션 (Graphical Poll → Poll Options)를 여세요. 다음을 설정하세요: 투표 유형 (Poll Type) 대상: 객관식 (Multiple Choice).
  2. 입력할 내용: 다음에는 무엇을 할까요? 를 질문으로 입력하고 Adventure, Puzzle 를 쉼표로 구분한 선택지로 입력하세요. 설정할 항목: 투표 일치 방식 (Vote Matching) 대상: 정확한 투표만 (Exact vote only).
  3. 유지: 사용자당 복수 투표 허용 (Allow multiple votes per user) 그리고 후원 가중 투표 (Donation-weighted voting) 를 끄면 간단한 1인 1표 투표가 됩니다. 켤 항목: 투표 활성화 (Enable Poll).
  4. 생성된 투표 링크를 OBS에 복사하세요. 시청자에게 다음을 보내게 하세요: 1 또는 2 를 메시지 전체로 보내게 하세요. 선택지 텍스트와 일치해도 됩니다.
  5. 선택: 투표 종료 (End Poll) 로 투표를 마감하세요. 결과를 기록한 뒤 다음을 선택하세요: 투표 초기화 (Reset Poll) 로 다음 라운드를 시작하세요.

자유 형식 투표는 해시태그 투표를 받습니다. 해시태그 위치 무관 (Hashtag anywhere) 는 더 긴 메시지 안의 해시태그를 허용합니다. 현재 투표 저장 (Save Current Poll) 는 재사용할 프리셋을 저장합니다. 시청자 결과의 영구 기록은 아닙니다. 복수 투표를 활성화하지 않으면 같은 투표자의 반복 투표는 무시됩니다.

전용 경품 추첨 도구

스크린샷이 포함된 단계별 안내는 다음을 참고하세요: 첫 경품 추첨. 열기: 경품 추첨 도구 → 경품 추첨 옵션 (Giveaway Tool → Giveaway Options)를 여세요. 참가 키워드를 설정하고 메시지 전체 일치 또는 개별 단어 일치를 선택하세요. 원하면 회원만 참가하게 제한할 수 있습니다. 다음을 클릭하세요: 참가 접수 시작, 그다음은 당첨자 추첨 을 준비되면 선택하세요. 추첨하면 참가 접수가 자동으로 닫힙니다. 추첨 전에는 같은 규칙으로 접수를 닫았다가 다시 열 수 있습니다. 새 라운드 는 현재 참가자 목록을 지우고 이전 결과를 기록에 보관하며 참가 접수를 닫아 둡니다.

선택: 당첨자 카드, 이름 릴, 또는 커뮤니티 룰렛및 여섯 스타일 중 하나를 선택하세요. 미리 보기는 가상 이름을 사용하며 세션에 참여하지 않습니다. 생성된 다음 링크를 복사하세요: giveaway.html?session=YOUR_SESSION&managed 링크를 OBS에 넣으세요. 관리형 시청자 화면에는 운영자 제어나 세션 정보가 없습니다. 스타일과 제목은 링크 설정이며 참가 규칙은 접수를 열 때 적용되는 진행자 설정입니다.

같은 Giveaway ID의 관리형 표시 화면은 진행자의 참가자 목록과 선택된 당첨자를 공유합니다. 무료 키워드 참가는 확률이 같으며 유료 추첨은 티켓 수에 따라 선택 확률이 달라집니다. 제공된 사용자 ID, 사용자 이름 또는 표시 이름으로 플랫폼 내 중복 신원을 제거하며 서로 다른 플랫폼은 별개 신원입니다. 반복 당첨을 끄면 각 당첨자는 현재 라운드의 추첨 대상에서 제거됩니다. 새 라운드에서는 다시 참가할 수 있습니다. 참가자 목록은 최대 10,000명을 보관합니다. 인원이 많으면 휠에는 최대 120명의 이름만 예시로 표시하지만 선택에는 항상 자격이 있는 전체 티켓 목록을 사용합니다.

SSN을 실행 상태로 유지하세요. 라운드는 로컬 브라우저/앱 프로필에 세션별로 저장됩니다. 다시 시작하면 검토를 위해 열린 라운드가 닫히지만 지워지지는 않습니다. 시청자 페이지를 새로고침하면 현재 결과를 받습니다. 회원 제한에는 멤버십 정보를 제공하는 소스가 필요합니다. 과거, 재생, 비공개, 봇, 이벤트 전용 메시지는 제외됩니다. 무료 참가 텍스트는 설정한 키워드와 일치해야 하며 후원 금액은 확률을 바꾸지 않습니다.

API, Stream Deck 및 이벤트 흐름

같은 진행자 동작을 팝업 버튼, 기존 HTTP/WebSocket API, Stream Deck에서 사용합니다. 참가자를 모으거나 추첨하기 위해 경품 추첨 표시 화면을 열어 둘 필요는 없습니다. 이벤트 흐름에서는 다음을 사용하세요: 경품 추첨 / 참가권 동작입니다. 참고: 포인트 및 자동화 가이드 에서 유료 티켓, 게임 상품, 통합을 확인하세요.

동작효과
startgiveaway추첨 전에 참가 접수를 열거나 재개합니다. 선택적 값: {"giveawayId":"default","config":{"keyword":"!enter","match":"exact","membersOnly":false,"removeWinner":true}}입니다. 명시적인 규칙이 없으면 기존 라운드의 규칙을 유지하거나 새 라운드에 팝업 설정을 사용합니다.
closegiveaway참가 접수를 닫고 참가자 목록을 유지합니다.
drawgiveaway참가 접수를 닫고 자격이 있는 당첨자 한 명을 선택합니다. 참가자 목록이 비어 있으면 오류를 반환합니다.
resetgiveaway참가 접수가 닫힌 빈 라운드를 만들고 이전 라운드와 당첨자를 기록에 보관합니다. 먼저 미완료 유료 예약을 취소/환불하세요.
getgiveawaystate참가자 수, 접수 열림/닫힘 상태, 참가 규칙, 최근 당첨자를 읽습니다.
{"action":"drawgiveaway","get":"draw-1"}

Protocol 2 Stream Deck 요청은 같은 동작 이름을 사용하며 요청과 연결된 진행자 응답을 받습니다. 이 응답은 OBS 표시 여부가 아닌 경품 추첨 상태를 설명합니다. 이전 독립 실행형 커뮤니티 휠도 계속 사용할 수 있습니다. 생략할 옵션: managed를 생략하면 됩니다. 자체 로컬 참가자 목록이 있으며 이 진행자 동작으로 제어되지 않습니다. 로컬 저장소는 이제 세션과 비밀번호별로 구분되고 정확히 일치는 메시지 전체를 뜻하며 추첨에는 안전한 난수가 사용됩니다.

3. 당첨자 추첨

  1. 열기 대기 목록 / 당첨자 추첨 → 활성화 및 사용자 지정 (Wait List / Winner Draw → Enable and customize)를 여세요. 트리거를 활성화하고 다음처럼 명확한 명령을 설정하세요: !join.
  2. 켜기: 대기열 대신 당첨자 추첨 모드로 설정 (Configure as winner-draw mode instead of queue)를 켜세요. 업데이트한 링크를 OBS 브라우저 소스에 복사하세요.
  3. 시청자에게 참가 명령과 자격 규칙을 알려 주세요. 다음을 사용한다면 회원만 참가 가능를 사용한다면 소스가 멤버십 정보를 제공하는지 먼저 확인하세요.
  4. 참가자 수가 늘어나는지 확인하세요. 다음을 선택하세요: 참가 접수 중지 (Stop entries) 를 참가 기간이 끝나면 선택한 뒤 당첨자 선택 (Select winner).
  5. 사용: 목록 다운로드 (Download list) 로 참가자 목록을 보관한 뒤 추첨 초기화 (Reset draw) 로 라운드를 지우세요.

4. 시청자 대기열 운영

같은 대기 목록 설정을 사용하되 당첨자 추첨 모드를 끄고 업데이트한 URL을 복사하세요. 시청자는 설정한 명령으로 참가합니다.

버튼 할 일
맨 위 항목 강조 다음 시청자에게 주의를 모읍니다.
맨 위 항목 제거 해당 시청자의 차례가 끝나면 다음으로 진행합니다.
이름 선택 대기열 순서 대신 무작위로 선택합니다.
참가 접수 중지 (Stop entries) 새 참가자가 들어오지 못하도록 대기열을 닫습니다.
목록 다운로드 / 대기열 초기화 TSV 사본을 저장한 뒤 활동이 끝나면 참가자 목록을 지웁니다.

재참가 옵션으로 제거된 시청자가 다시 참가할 수 있는지 선택하세요. 선택 사항인 대기 목록 제어 명령 는 관리자/진행자/운영자에게만 허용됩니다: !wlstop, !wlremove, !wlreset, !wlpick, 그리고 !wlhighlight입니다. 이 명령들은 직접 활성화해야 합니다. 시청자 참가 명령만으로 활성화되지 않습니다.

5. 연습 및 복구

서로 다른 가상 사용자를 다음에서 사용하세요: 테스트 메시지 에서 투표 및 참가 동작을 확인하세요. 한 사람이 두 플랫폼을 사용해도 하나의 공유 신원이라고 확실히 볼 수는 없습니다. 시청자를 초대하기 전에 결과가 OBS에 나타나는지 확인하세요.

  • 투표가 없음: 투표 활성화, 투표 종료 여부, 정확히 일치 설정, 해당 사용자의 기존 투표 여부를 확인하세요.
  • 참가자가 없음: 대기 목록 트리거, 정확한 명령, 참가 접수 중지 상태, 회원 전용 제한을 확인하세요.
  • 숫자만 있고 목록이 없음: 당첨자 추첨 모드에서는 일반 대기열 대신 참가자 목록과 당첨자를 표시합니다.
  • OBS와 결과가 다름: 저장된 URL을 교체하고 세션/비밀번호를 확인하며 개별적으로 설정된 중복 투표 페이지를 실행하지 마세요.

하드웨어 또는 OBS 쪽 버튼은 다음을 참고하세요: Stream Deck 설정 그리고 OBS 제어 도크.
