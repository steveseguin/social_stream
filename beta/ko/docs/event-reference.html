캡처 설정, 필터 및 페이로드 규칙
중요: 사용 가능한 이벤트는 소스, 권한, 캡처 설정에 따라 달라집니다. 도크 또는 강조 메시지 오버레이에서 이벤트로 표시된 행을 숨기려면 다음을 추가하세요: &hideevents 또는 &hideallevents. 선택한 이벤트를 숨기려면 다음을 사용하세요: &filterevents=subscription_gift,new_follower,gifted. 이 필터는 다음을 가진 유료 행도 숨길 수 있습니다: event; 이벤트 표식이 없는 일반 후원 행은 이벤트 필터와 일치하지 않습니다. 다른 메시지 필터는 계속 적용됩니다.
캡처 방식 선택: YouTube, Twitch, Kick의 경우, WebSocket 모드 는 일반적으로 더 폭넓은 이벤트를 지원합니다. 표준 DOM 캡처는 페이지에 실제로 렌더링된 행과 카드를 읽습니다. YouTube Super Chat, Super Sticker, Jewel 선물은 두 모드 모두 캡처 경로가 있습니다. 다른 선물, 팁, 멤버십 이벤트는 소스마다 다릅니다. 지원 경로와 필수 설정은 플랫폼 표를 참조하세요.
자동화를 만들고 있나요? 다음을 확인하세요: Event Flow 가이드 에서 이 이벤트 페이로드를 사용자 지정 트리거, 알림, 작업 흐름에 사용하는 방법을 알아보세요. 가이드에는 다음이 포함되어 있습니다: 템플릿 변수 참고 문서 에서 텍스트 형식을 확인하세요. 선물 금액, 연속 선물 계산, 편집 가능한 게임 예제는 게임과 보상 만들기.
페이로드 구조: 후원형 채팅 행은 다음을 사용해야 합니다: hasDonation 및 선택적 donoValue. 다음은 설정하지 마세요: event: "donation" 를 일반 채팅/팁 행에 값이 있다는 이유만으로 설정하지 마세요. 구체적인 이벤트 이름은 실제 플랫폼 동작이나 유료 항목 유형에만 사용하세요. 예: superchat, supersticker, gift, 또는 jeweldonation. 사용: meta 는 소비자가 실제로 필요로 하며 기존 필드로 담을 수 없는 추가 구조화 데이터에만 사용하세요.

필드 개요

data 는 여기서 메시지 객체를 뜻하며 추가할 별도 래퍼가 아닙니다. 채팅 행과 메타데이터 전용 이벤트는 구조가 다릅니다. 카운터 및 상태 스냅샷은 다음을 생략할 수 있습니다: chatname/chatmessage. 플랫폼 표에서, 메시지 는 일반 채팅 행을 설명하며 문자 그대로의 다음이 아닙니다: event: "message".

필드 구조 사용법
data.type 문자열 오버레이, 필터, Event Flow가 사용하는 소스 식별자. Instagram은 실시간 채팅을 다음으로 유지합니다: instagramlive 및 라이브가 아닌 댓글을 다음으로 유지합니다: instagram. 참고: 소스 유형 가이드 에서 변형, 일반 소스, 발신 라우팅을 확인하세요.
data.chatname 문자열 Source-provided display name used by message processing and non-overlay outputs. A configured user display-name alias may replace this value only in copied dock and overlay transport payloads. The opt-in Show display name (username) setting appends the username when a source supplies both names and they differ, ignoring capitalization, for example 알렌 (allenhklee). These copies retain the source name in meta.sourceDisplayName for moderation matching. Custom aliases take priority; username remains the account login.
data.username 문자열 사용 가능한 경우 소스 사용자 이름입니다. 별칭이 적용된 도크 또는 오버레이 페이로드는 원래 값을 보존하기 위해 이 필드를 추가할 수 있습니다: chatname 를 사용자 동작에 사용하며 표준 메시지는 바뀌지 않습니다.
data.userid 문자열 플랫폼별 사용자 식별자. 사용자 동작은 다음보다 이 값을 우선합니다: username 그리고 chatname.
data.platform문자열(선택 사항)일부 통합은 다음과 함께 이를 포함합니다: type. 여러 소스 어댑터는 이를 생략합니다. 사용: type 를 소스 라우팅에 사용합니다.
data.id문자열 | 숫자(선택 사항)메시지 또는 이벤트 식별자. 의미는 소스와 전송 방식에 따라 달라지므로 항상 플랫폼 고유 관리 ID라고 가정하지 마세요. 사용: meta.messageId 는 어댑터가 삭제 동기화용으로 제공하는 경우.
data.donoValue숫자(선택 사항)소스가 제공하는 숫자형 USD 환산값으로 추정값도 포함합니다. 유효한 값(0 포함)은 currency.js 변환보다 우선합니다. 없으면 소비자는 hasDonation과 소스 맥락으로 USD를 추정합니다. 원래 금액과 단위는 hasDonation과 기존 제공자 메타데이터에 유지합니다.
data.chatbadges배열 | 문자열(선택 사항)배지 이미지 URL 또는 배지 객체(type: "img" 포함: src, type: "svg" 포함: html, 또는 type: "text" 포함: text). 릴레이는 텍스트 배지의 원래 라벨을 선택적 필드에 유지합니다: rawText 및 이스케이프된 다음을 생성합니다: text 를 이전 오버레이용으로 제공합니다. 이후 릴레이 과정에서는 다음을 다시 생성하세요: text 출처: rawText; 다음은 이스케이프하지 마세요: text 를 다시 처리하지 마세요. 현재 렌더러는 다음을 표시합니다: rawText 가 있으면 문자 그대로 표시하고, 없으면 기존 인코딩 텍스트 처리를 유지하세요. 이는 표현 방식 필드이며 HTML 렌더링 권한이 아닙니다. 이전 소스는 배열 대신 단일 HTML 문자열을 보낼 수 있습니다. 배지를 표시하는 오버레이는 두 형식을 모두 받고, 발신자가 이전 확장 프로그램이어도 배지 HTML과 URL을 로컬에서 안전하게 정리합니다. 유효하지 않은 배지가 채팅 또는 멤버십 메시지 표시를 막아서는 안 됩니다.
data.event 문자열 | 불리언 시스템 활동의 식별자(예: viewer_update, subscription_gift, giftpurchase). 일반 채팅에서는 비워 두거나 false로 유지해야 오버레이가 시스템 알림과 대화 텍스트를 구분할 수 있습니다.
data.chatmessage 문자열 메시지 본문. 안전하게 정리된/렌더링 가능한 HTML은 다음일 때만 포함할 수 있습니다: data.textonly 가 false인 경우.
data.textonly 불리언 다음에만 적용됩니다: data.chatmessage. true 는 다음을 렌더링하라는 뜻입니다: chatmessage 를 일반 텍스트로 취급하고 문자 그대로의 태그와 엔터티처럼 보이는 텍스트를 보존하세요. 해당 본문을 디코딩하거나 HTML 정리하거나 서식 태그를 추가하지 마세요. 이벤트 스타일은 표시 요소에 적용하세요. false 의 의미: chatmessage 에는 안전하게 정리된/렌더링 가능한 HTML이 들어갈 수 있습니다. 플래그가 없는 이전 메시지는 그 HTML 동작을 유지합니다. 다른 일반 필드는 일반 텍스트이며 다음 같은 미디어 필드는 예외입니다: chatimg 그리고 contentimg. 일반 필드를 표시할 때는 다음을 사용하세요: textContent, 또는 HTML 템플릿을 구성할 때 한 번 이스케이프하세요. 내용을 제거하거나 반복해서 디코딩하지 마세요.
data.contentimg 문자열(선택 사항) 콘텐츠 이미지 또는 지원되는 미디어 URL. 확장 프로그램과 데스크톱 앱에서는 선택적으로 활성화하는 allowExternalGifs 설정은 메시지 텍스트 또는 HTML 링크의 첫 번째 직접 HTTP(S) GIF 링크로 빈 필드를 채웁니다. 메타 규칙

오버레이 제어 전송은 캡처된 채팅/이벤트와 별개입니다. 업데이트된 수신기는 다음을 사용합니다: ssnControl 전송 봉투에 전달 식별자를 포함합니다: id, 강조 표시 target, 선택적 답장 채널과 스냅샷 클라이언트 ID. 기존 강조 표시 본문은 그대로 유지됩니다. 공개 기능 제어는 채널 7을 사용하며 Actions는 채널 6을 유지합니다. Poll 및 Map 상태에는 호스트의 다음이 포함됩니다: epoch, revision 그리고 reset 표식을 사용합니다. Timer, Ticker, Spotify는 다음을 사용합니다: ssnState 에 epoch와 revision을 포함합니다. 이 표식은 호스트 상태를 설명하며 복원된 투표/채팅 기록이 아닙니다. 소스는 캡처된 메시지에 제어 봉투 필드를 추가해서는 안 됩니다. 수신 확인은 동작 완료나 OBS 표시를 입증하지 않습니다. 참고: 이전 상태 에서 지원 기능, 답장 협상, 재연결 제한을 확인하세요.

Phrase Guess는 기본 기능을 사용합니다: {response: text} 요청을 server2 채팅 답장에 사용하며 {action: "phraseGuessResponse", value: {type: "bot", chatname: name, chatmessage: text}} 는 도크 전용 공지에 사용합니다. 호스트는 수신 server3 메시지를 활성화해야 하며 호스트 제어를 끄면 이 요청도 차단됩니다. 도크 공지는 다음을 포함한 일반 봇 채팅 행으로 전달됩니다: textonly: true, 캡처 소스의 채팅 입력창으로 보내지 않습니다. 레거시 API 모드는 기존 명령 형식을 유지합니다.

  • AI 무대 오버레이 명령은 다음을 사용합니다: { action: "aiOverlay", target, meta } 또는 도크가 제어하는 공동 진행자 재생은 다음을 사용합니다: { action: "cohostOverlay", target, meta }; 다음과 같은 모든 명령 세부 정보는 유지하세요: command, text, emotion, avatar, 그리고 tts 내부: meta.
  • 플랫폼이 여러 카운터를 함께 제공하면 명시적 키가 있는 구조화 객체를 권장합니다(meta.viewer_count, meta.follower_count), 문자열에 여러 의미를 덧씌우지 마세요.
  • 커머스 오버레이는 다음 아래의 스냅샷 객체를 사용해야 합니다: meta (예: auction_update 그리고 commerce_update), 임의의 최상위 필드는 사용하지 마세요.

YouTube 구독자 알림(new_follower)

Social Stream은 이제 다음을 사용해 새 YouTube 구독자를 감지할 수 있습니다: myRecentSubscribers API 엔드포인트. Streamlabs 구독자 알림과 비슷하게 작동합니다.

작동 방식:

  • 5분마다 YouTube API에서 최근 구독자를 폴링합니다
  • 새 구독자를 감지하기 위해 이미 본 구독자를 localStorage에 기록합니다
  • 전송: new_follower 이벤트에 구독자의 이름, 아바타, 채널 ID를 포함합니다
  • 구독자 알림 메시지는 기본적으로 비활성화됩니다. 활성화하면 다음의 현재 번역 문자열을 사용합니다: alert-just-subscribed
  • 기본적으로 신규 구독자가 세 명을 초과하는 연속 수신을 묶어 재연결 시 오버레이나 Event Flow가 과도하게 실행되지 않게 합니다
  • 확장 프로그램 설정에서 WebSocket 모드를 활성화해야 합니다

제한 사항(Social Stream의 제한이 아닌 YouTube API 제한):

  • 보장된 전달 지연 시간 없음 – SSN은 5분마다 폴링하지만 API가 지연되거나 불완전한 결과를 반환할 수 있습니다. 고정된 4시간 범위에 의존하지 마세요.
  • 공개 구독만 – 구독 목록을 비공개로 설정한 구독자는 알림을 발생시키지 않습니다. YouTube에서 구독은 기본적으로 비공개입니다.
  • 채널 소유자만 – 본인이 소유하고 인증한 채널의 구독자 알림만 받을 수 있습니다.
  • API 할당량 사용량 – 폴링마다 API 1단위를 사용합니다. 5분 간격이면 하루 약 288단위를 사용합니다(기본 일일 할당량 10,000단위 중).

SSApp WebSocket 캡처는 연속 선물이 확정된 뒤 같은 필드를 제공하며 다음을 포함합니다: count 는 호환성을 위해 유지됩니다. 선물을 전달할 때마다 후원 스위치를 확인하며 TikTok 후원을 끄면 다음이 제거됩니다: hasDonation 그리고 donoValue 를 유지하면서 선물 이벤트와 메타데이터도 보존합니다. 음성 읽기는 이 식별 정보로 업데이트를 합치고 최대 10분 동안 완료된 중복을 억제하며(크기가 제한된 캐시), TikTok 선물을 발신자, 수량, 선물 이름으로 읽습니다. 이전 페이로드는 기존 연속 선물 ID와 메시지 텍스트로 대체하며 선물 텍스트만으로 식별 정보를 추론하지 않습니다. TikTok 선물 음성은 UI 언어와 별개로 선택된 음성 읽기/음성 언어를 사용합니다. 알림 동사는 영어, 스페인어, 포르투갈어, 프랑스어, 독일어, 이탈리아어, 네덜란드어로 현지화됩니다. 다른 언어는 영어 동사 없이 발신자, 수량, 선물 이름만 사용합니다. 간단한 음성 읽기도 이 중립 형식을 유지합니다. 선물 이름은 플랫폼이 제공한 그대로 유지합니다. 선물 카탈로그나 채팅 메시지를 자동 번역하거나 방송 언어를 추론하지 않습니다.

이 연속 선물 업데이트에서 개수와 후원 라벨은 누적값입니다. 1, 2, 3은 선물 여섯 개가 아니라 세 개를 뜻합니다. 총액을 집계하는 소비자는 해당 연속 선물 ID에서 이미 본 최댓값보다 증가한 부분만 더해야 합니다. 표준 캡처는 기존 선물 클래스와 현재 이미지/개수 행을 지원하며 둘 다 다음을 유지합니다: event: "gift" 그리고 hasDonation. 가격을 알 수 없으면 표시를 위해 선물 개수/이름을 유지하고 선물당 코인 하나를 기준으로 USD를 추정합니다. 소스가 제공한 donoValue 가 우선합니다. 렌더링된 선물 메타데이터는 다음을 제공할 수 있습니다: coinsPerGift 또는 diamondsPerGift 를 선물 표나 기본값이 필요하기 전에 우선 사용합니다. 표준/TikFinity 코인 추정과 SSApp 기본 다이아몬드 추정은 각각 기존의 서로 다른 환산을 사용하며, 어느 쪽도 현금 지급액을 보장하지 않습니다.

payment_failed 실시간 결제 실패 WebSocket 알림이 도착합니다. 동일하게 사용 가능한 구매자, 상품, 식별자 필드에 다음을 포함합니다: meta.paymentStatus: "failed". 다음만 있는 경우: product.purchaserUserId 가 구매자를 식별하면 다음을 채웁니다: userid 를 판매/결제 이벤트에 포함하며 구매자 이름은 비어 있습니다. 다른 경매나 이전 경매에서 구매자를 추론하지 않습니다.
payment_succeeded 실시간 결제 성공 WebSocket 알림이 도착합니다. meta.paymentStatus: "succeeded", 해당 알림이 제공한 구매자, 상품, 주문 ID, 기타 허용된 필드와 함께 전달됩니다. 이는 별도의 결제 이벤트로 유지되며 다음을 다시 발생시키지 않습니다: purchase 또는 후원이 아닙니다. 이전 판매가 제공했더라도 누락된 필드는 비우거나 생략합니다.

경매/커머스 표시 업데이트는 계속 DOM 기반 스냅샷입니다. Event Flow에서 개별 WebSocket 이벤트를 일치시키려면 다음을 사용하세요: 이벤트 유형(고급), 선택: 사용자 지정 이벤트, 정확한 이름을 입력하세요. 라벨에는 다음을 사용할 수 있습니다: **{username}**\n{subtitle} 에 선택한 텍스트 가중치를 적용합니다. 조건은 다음을 비교할 수 있습니다: meta.paymentStatus 포함: failed. 다음 항목: 가져올 수 있는 Whatnot 라벨 예시 를 사용할 수 있습니다. 기존 방송 이벤트 캡처 설정은 계속 적용됩니다.

추가 선택 필드: meta.catalogProductId (패킷의 product.productId), meta.parentProductId (product.parentId), meta.transactionType (Whatnot 판매 유형, 변경 없음), 그리고 meta.placeOrderErrorReason (Whatnot이 제공한 주문/결제 오류 코드). 이 상품 참조는 카탈로그 또는 상위 등록 상품을 설명하며 주문 ID를 대체하지 않습니다. 재고 수량을 구매 수량으로 취급하지 않습니다.

결제 성공 자동화에는 다음을 설정하세요: 이벤트 유형(고급) 트리거를 다음으로 설정하세요: 사용자 지정 이벤트: payment_succeeded, 소스를 Whatnot으로 필터링하세요. 기존 조건과 템플릿은 해당 이벤트의 다음을 사용할 수 있습니다: userid, chatname, subtitle 그리고 meta.orderId 를 직접 사용합니다. 알림에 필요한 세부 정보가 있으면 기억된 구매가 필요하지 않습니다.

경매가 끝나거나 상품이 판매됨으로 표시되어도 결제 성공이 확인되는 것은 아닙니다. 이 알림은 결제된 다음 이벤트로 전송되지 않습니다: purchase 이벤트이며 후원 금액을 설정하지 않습니다. 성공 이벤트는 다음을 수신한 경우에만 전송됩니다: payment_succeeded 알림에만 반응하며 캡처는 결제 완료를 폴링하거나 판매에서 추론하지 않습니다. 다른 paymentStatus values are forwarded only when explicitly supplied in a captured packet. Missing identifiers are omitted; a product ID alone may cover multiple sales, so use a supplied order/auction ID to correlate notifications. Capture does not remember purchases or match payment updates; any such workflow must be explicitly configured in Event Flow. Repeated commerce notifications with the same native event timestamp/ID are suppressed across overlapping channels and reconnects, within a 2,000-event cache. Packets without a native event identity use a brief duplicate window. Raw order/payment objects are not forwarded.

Monetization eBay 판매자 연결에는 설정된 SSN eBay 서비스와 판매자 OAuth 동의가 필요합니다. 아래의 eBay Live 캡처는 독립적입니다. 샌드박스 모드는 샌드박스 등록 상품 URL을 사용하고 구매자에 'eBay Sandbox buyer' 라벨을 붙이며 메시지 앞에 'Sandbox test purchase:'를 넣습니다. 샌드박스 구매는 동일한 구매 계약을 유지하며 테스트 중 활성화된 알림/채팅 동작을 실행할 수 있습니다. 구현된 결제 계약은 다음을 전송합니다: event: "purchase", 포함: type 그리고 platform 설정값: ebay. 선택한 상품과 일치하는 결제 완료 주문이 필요합니다. id 는 안정적인 불투명 주문 항목 식별자입니다; chatname 는 'eBay buyer'이고, chatmessage 는 일반 텍스트입니다(textonly: true), subtitle 는 상품 이름이며 선택적 contentimg 는 해당 이미지입니다. meta.ebayPurchase 포함: itemId, itemName, quantity, 공개 url. 구매자 식별 정보, 배송 데이터, hasDonation 또는 donoValue 가 포함됩니다. 이는 결제를 입증하지 않는 스크래핑 경매 또는 재고 업데이트와 다릅니다.

구현: sources/websocket/vpzone.js

Joystick

구현: sources/joystick.js, sources/inject/joystick-ws.js, 그리고 sources/websocket/joystick.js

  • 일반 Joystick 2.0 웹사이트 소스는 로그인된 다음에서 실행됩니다: /u/<channel>/chat 페이지에서 실행됩니다. 페이지의 다음을 읽습니다: ChatChannel, WhisperChatChannel, EventLogChannel, 그리고 SystemEventChannel Action Cable 프레임을 사용하며 Electron 및 재연결 상황에서는 렌더링된 행으로 대체합니다.
  • 웹사이트 채팅 메시지는 YouTube, Twitch, Kick과 같은 주요 필드를 사용합니다. 플랫폼 고유의 id, chatname, chatmessage, chatimg, chatbadges, nameColor, membership, mod, private, username/userid, 그리고 timestamp 는 Joystick이 제공하는 경우 포함됩니다. 소켓에 사용자 이름 색상이 없으면 렌더링된 행이 같은 값을 제공합니다: nameColor 필드를 색상 지원 도크에서 사용합니다.
  • 웹사이트에서 메시지를 수정하면 일치하는 도크 행을 교체합니다. 삭제, 음소거, 차단은 플랫폼 고유 ID 또는 사용자 이름으로 일치하는 행을 제거합니다.
  • 별도 WebSocket 소스는 Joystick 봇 자격 증명을 사용합니다(client_id + client_secret); 웹사이트 소스는 로그인한 페이지 세션을 사용합니다.
  • 인증 위치: https://joystick.tv/api/oauth/authorize, 그런 다음 다음에서 토큰을 교환/갱신합니다: https://api.joystick.tv/api/oauth/token.
  • 연결 대상: wss://api.joystick.tv/cable 에 연결하고 다음을 구독합니다: GatewayChannel.
  • 선택적 OAuth 토큰 교환은 다음과 같은 도우미 엔드포인트에 사용됩니다: https://api.joystick.tv/api/users/stream-settings.
  • 별도 봇 자격 증명 소스는 다음을 전송하지 않습니다: viewer_update. 로그인한 웹사이트 소스는 아래 설명처럼 페이지 소켓이 시청자 수를 제공하면 이를 전송합니다.
이벤트 발생 시점 페이로드 참고 사항
message Joystick ChatMessage, BotMessage, new_message, bot_message, event_bot_message, pvp_message, 귓속말. 일반 채팅에는 다음이 없습니다: event. 플랫폼 고유 ID는 최상위 필드에 들어갑니다: id 그리고 meta.messageId; 역할과 비공개 상태는 기존 최상위/배지 필드를 사용합니다.

무시되는 내부 알림 ChatMessageReceived, 장치 상태, 팁 목표/PvP/서브마라톤 상태처럼 매핑되지 않은 위젯 새로고침. 이는 Social Stream 이벤트가 아닌 전송 또는 페이지 상태 알림입니다. 임의로 만든 다음 이벤트로 변환하지 않습니다: snake_case 이벤트 이름을 만들지 않습니다. 실제 ChatChannel/new_message 행은 유일한 채팅 페이로드로 유지됩니다.

XP Sync

구현: sources/xpsync.js

  • 채팅 행은 표준 페이로드 필드와 다음을 사용합니다: type: "xpsync", 작성자, 메시지, 아바타, 이미지 및 인라인 SVG 배지, 이름 색상, 멤버십, 관리자/회원/봇 플래그, 플랫폼 고유 메시지 UUID를 다음으로 포함합니다: id 는 사용 가능한 경우.

  • 시청자 수가 활성화되면 상시 채팅 도크는 다음을 전송합니다: event: "viewer_update" 를 XPSync 페이지가 이미 로드한 라이브 동영상 수에서 가져오고 XPSync 라이브 페이지 업데이트로 새로고침합니다. 별도 SSN 자격 증명은 필요하지 않습니다.

  • 계정 자체 활동 피드를 다음으로 폴링합니다: POST /api/v1/news/inbox/ 약 45초마다 모든 Instagram 페이지에서 폴링합니다. 첫 폴링은 중복 제거 집합만 채우므로 이전 기록을 재생하지 않습니다. 항목의 중복 제거 기준: tuuid.

  • 모든 활동 피드 이벤트는 다음을 사용합니다: type: "instagram"; 실시간 채팅은 다음으로 유지됩니다: type: "instagramlive". 좋아요 이벤트는 일반 백그라운드 경로를 사용합니다. 백그라운드는 전용 Reactions Overlay에 사본 하나를 보낸 뒤 다음 조건에서만 기본 채팅/이벤트 피드에 포함합니다: capturelikeevent 가 활성화된 경우이며 TikTok 및 MeetMe와 일치합니다. hideevents 및 사용자 지정 이벤트 필터는 모든 위치에서 이를 차단합니다. 받은편지함 이벤트는 로그인한 계정에 속하므로 다른 사람의 라이브를 시청하는 동안 숨겨집니다(두 방식 모두: /<user>/live/ 페이지와 스토리 뷰어의 라이브. 소유권은 프로필별로 확인하며 조회 실패 후 다시 시도합니다). 본인의 라이브와 모든 비라이브 페이지에서는 전송됩니다. 활성 Instagram 탭 하나가 한 번에 계정 받은편지함을 폴링하며 로그인된 경우에만 폴링합니다.

hasDonation 는 유료 후원의 호환성 신호로 유지되며 다음을 포함합니다: donoValue 에 제공되거나 추정된 USD 값을 담습니다. 선물과 기여는 이 필드를 유지합니다. 모금 완료는 기여를 이중 계산하지 않도록 둘 다 생략합니다. 일반 상품 판매는 eBay 계약을 유지하며 기본적으로 둘 다 생략합니다. 스토어, 위시리스트 URL 또는 실물 상품에서 선물 의도를 추론하지 마세요. 소스가 크리에이터 선물임을 명시하지 않는 한 구매자 또는 다른 수신자를 위한 구매는 판매로 유지됩니다.

선택적 공유 meta.commerce 필드: recipient (creator, buyer, other), itemType (physical, digital, service), quantity (양수 상품 수량), currency (ISO 통화), goalAmount (기본 통화 단위의 모금 목표이며 새 수입이 아님), 그리고 orderTotal (알려진 기본 통화 단위의 결제 완료 주문 총액; 후원 수입이 아닌 커머스). 알 수 없는 정보는 생략하세요. 상품 이름은 다음에 유지하세요: subtitle, 이미지는 다음에: contentimg, 후원 참여자 텍스트는 다음에: chatmessage. 기존 제공자 메타데이터도 계속 사용할 수 있습니다. Throne은 수신자와 통화, 완료 시 goalAmount를 제공하며 eBay는 수량을 제공합니다. 두 제공자 모두 상품 유형을 추측하거나 비공개 수신자 정보를 노출하지 않습니다.

활동 피드는 후원 참여자 텍스트가 없어도 이 이벤트들을 표시합니다. Multi-Alerts는 선물과 기여에 후원 표시 방식을 사용하며 금전적 값이 없는 별도 Gift Fully Funded 알림도 포함합니다. 구매에는 기본적으로 활성화된 별도 Purchase 카테고리가 있으며 다음을 포함합니다: purchasestyle, purchasesound, purchaseaccent, 그리고 disablepurchases URL 제어를 사용합니다. 구매 알림은 후원 총액을 변경하지 않습니다.

Event Flow는 Event Type 및 Other Event 트리거에서 이 이벤트 이름들을 제공합니다. Donation 트리거는 여전히 다음을 검사합니다: hasDonation; Gift Sub 트리거는 멤버십 의미를 유지합니다. Compare Property는 다음 같은 중첩 경로를 받습니다: meta.commerce.recipient. 동작 템플릿은 다음을 받습니다: {meta.commerce.quantity} 그리고 {meta.commerce.currency}, 기존의 다음과 함께: {donation}, {subtitle}, 그리고 {meta}. 중첩 경로는 대소문자를 구분하며 누락된 값은 빈 내용으로 표시됩니다. 프로토타입 탐색은 금지됩니다.

크리에이터 커머스 웹훅 및 홍보 오버레이

meta.monetization.commerce 위치: monetization_update 에는 enabled, qr, position, display(first/cycle), seconds 및 공개 items 배열이 들어 있습니다. 각 항목에는 name, url, image, 선택적 amount(모르면 null), currency, purpose(shop/gift/support/membership)가 있습니다. 진행자가 입력한 홍보 정보이며 결제 증거가 아닙니다. 항목 추가나 수정은 후원 또는 구매 이벤트를 발생시키지 않습니다. 일반 오버레이는 다음을 사용합니다: mode=commerce; view=both|showcase|card|alerts 는 홍보와 활동을 분리합니다. 선택적 style, scale, cardevery, cardfor, onlytype URL 매개변수가 표시를 제어합니다. 기존 제공자 모드도 view와 일정 제어를 받습니다. 참고: 설정 가이드.

Throne 선물 이벤트

선택적으로 활성화하는 Monetization 통합은 다음을 포함한 서명된 Throne 이벤트를 전달합니다: platform 그리고 type 설정값: throne. 세 가지 모두 안정적인 전달 식별자를 사용합니다: id, 일반 텍스트 chatname, chatmessage 포함: textonly: true, 상품 이름은 다음에: subtitle, 선택적 HTTPS 썸네일은 다음에: contentimg.

이벤트의미후원 금액 / 순위
gift구매된 선물hasDonation 및 USD donoValue; +1 선물 순위
giftcontribution선물을 위한 기여기여 금액만 반영하며 순위는 오르지 않음
giftfunded공동 모금 선물 완료아니요 hasDonation 또는 donoValue, 이전 기여가 중복 계산되지 않게 합니다; +1 선물 순위

meta.throne 포함: itemName, creator (공개 사용자 이름), completed, currency 및 기본 통화 단위의 amount. 다음의 경우: giftfunded, 금액은 새 수입이 아니라 목표를 나타냅니다. 익명 선물 제공자는 다음으로 유지됩니다: Anonymous; 완료된 공동 선물은 다음을 사용합니다: Community. 비공개 결제 및 배송 필드는 전달하지 않습니다.

monetization_update 스냅샷에는 다음도 포함됩니다: meta.monetization.throne: enabled, username, url, qr, position, rank, 그리고 gifts. 이 스냅샷에는 웹훅 URL이나 수신 자격 증명이 없습니다.

진행자 음성 명령(데스크톱 미리보기)

Event Flow의 내가 다음과 같이 말하면... 트리거는 SSApp의 신뢰할 수 있는 로컬 마이크 명령을 받습니다. 내부 동작 맥락은 다음을 사용합니다: chatname: "Host", type: "hostvoice", 인식한 문구는 다음에: chatmessage, 그리고 textonly: true. 이는 수신 플랫폼 이벤트나 새 채팅 전송 방식이 아닙니다. 채팅으로 이 필드를 보내도 음성 트리거가 활성화되지 않습니다.

업데이트된 데스크톱 빌드, 명시적 마이크 시작, 테스트 모드 이후 동작 활성화가 필요합니다. 참고: 미리보기 설정 및 검증 상태.

상품 표시 제어

기존 monetization_update 스냅샷에는 다음이 포함될 수 있습니다: meta.monetization.commerce.live: 저장된 일정에는 null, 또는 {mode: "show" | "hide", url?: "https://...", until: 0 | epochMilliseconds}. Show는 저장된 정확한 상품 URL과 일치시킵니다. 상품이 없으면 카드가 표시되지 않습니다. until이 양수면 만료 후 저장된 일정으로 돌아가며, 0이면 변경하거나 SSN을 다시 시작할 때까지 지속됩니다. Hide는 홍보를 숨기며 유료 활동 알림은 숨기지 않습니다.

commerce.viewerURL 는 게시된 읽기 전용 상점 URL 또는 빈 문자열입니다. 있으면 홍보 QR 코드가 이곳으로 연결됩니다. SSN 세션이나 게시 키는 포함하지 않습니다. 상품은 다음에 유지됩니다: commerce.items. 표시 제어, 가져오기, 게시로는 후원/구매 이벤트가 발생하지 않습니다. 참고: 상품 제어 에서 Event Flow 및 원격 API 사용법을 확인하세요.

Event Flow의 commerceControl 동작은 직접/Chrome 응답을 최대 8초 기다립니다. 일반 이벤트 페이로드에서는 이벤트를 보존하고 다음을 추가합니다: meta.commerceControlResult: {success: true, commerce: controlState} 또는 {success: false, error: "..."}. 기존 숫자, 배열 또는 기타 객체가 아닌 다음의 경우: meta, 메타데이터는 바뀌지 않으며 진단은 다음으로 반환됩니다: commerceControlResult 를 대신 동작 결과에 반환합니다. 제어가 실패하면 원래 결제 이벤트를 억제하지 않고 해당 체인의 후속 동작을 중지합니다. 시간 초과가 제어 미적용을 입증하지는 않습니다. Next 같은 상대 명령을 재시도하기 전에 상태를 확인하세요. 성공은 로컬 선택/숨김/일정 상태를 확인하며 OBS 표시나 공개 페이지 동기화를 확인하지 않습니다.

이름이 지정된 Stream Deck / API 작업 흐름

다음 항목: 이름이 지정된 작업 흐름 트리거 는 다음을 포함한 내부 Event Flow 메시지를 생성합니다: type: "api", event: "workflow_trigger", chatname: "Stream Deck / API", 비어 있는 chatmessage, 그리고 textonly: true. 해당 항목의 meta.workflow 객체에는 트리거 이름과 호출자가 제공한 JSON 값이 들어 있습니다: data 객체를 사용합니다. 다음 같은 템플릿으로 값을 읽으세요: {meta.workflow.data.minutes}. 저장되고 활성화되었으며 해당 트리거와 명시적으로 일치하는 흐름만 평가합니다. 이는 수신된 시청자/채팅 이벤트가 아니며 채팅으로 브로드캐스트되지 않습니다. 이 필드를 채팅에 복사해도 지정된 트리거가 활성화되지 않습니다.

NinjaChatter 시청자 파일럿

실험적인 페어링 확장 프로그램 커넥터는 다음을 포함한 표시 전용 행을 보냅니다: type: socialstreamchat, platform: ninjachatter, 그리고 textonly: true. meta.ninjachatter 에 담는 값: origin: audience, 설명용 provider, 공개 room ID. 이 행은 플랫폼 답장, 봇, Event Flow 트리거, 포인트를 거치지 않습니다. 제공자가 표시된다고 승인된 것은 아닙니다. 기존 NinjaChatter 소스 캡처에는 다음이 포함됩니다: meta.ninjachatter.room 를 방별 중복 억제에 사용합니다.

Cheer는 별도의 인증된 요청 및 결과 경로를 사용하며 특수 채팅 명령을 사용하지 않습니다. 고정 사전 설정은 기존 Actions 오버레이의 다음을 전송합니다: show_text 메시지를 3초 동안 표시합니다. 수신은 전송 수락을 뜻하며 OBS 표시가 검증되었다는 뜻은 아닙니다. 시청자 페이로드로 임의 동작을 선택할 수 없습니다. 파일럿은 NinjaChatter에서 기본적으로 꺼져 있으며 새 비공개 페어링 경계가 검증될 때까지 Electron은 기존 릴레이를 유지합니다.

커머스 배정 보드 및 최근 판매

기존 monetization_update 이벤트(type/platform: socialstream)에는 다음도 포함됩니다: meta.monetization.boards. 해당 항목의 board 포함: title, style (spots/teams), columns (1–20), visible, 최대 120개의 spots. 각 칸에는 문자열 형식의 다음이 있습니다: id, 일반 텍스트 label, status (available/claimed/revealed) 및 result (일반 텍스트, 공개 전에는 비어 있음). 배정과 공개는 진행자가 입력한 표시 상태이며 구매 증명이나 무작위 배정이 아닙니다.

boards.sales 에는 최근 기록을 최대 100개 담습니다: id, title, 선택적 amount (알 수 없으면 null), currency, quantity, source, 그리고 at (기록 시점의 Unix 밀리초). automatic 는 수집을 활성화하며, salesVisible 는 표시를 제어하며 revision 는 변경 시 증가합니다. 자동 수집은 다음만 받습니다: purchase 이벤트를 Shopify, eBay 판매자, Fourthwall, Ko-fi, Buy Me a Coffee에서 받으며 비공개/테스트 이벤트는 제외합니다. 경매 메타데이터, 팁, 선물, 칸 배정을 구매로 취급하지 않습니다. 자동 기록은 상품 가격을 주문 총액, 등록 가격, 후원 금액으로 대체하지 않습니다. 수동 기록은 다음을 사용합니다: source: "Host confirmed".

상태는 이 설치 환경의 비공개 수익화 저장소에 유지됩니다. 공개 스냅샷에는 전달 중복 제거 ID, 구매자 식별 정보, 비밀 값이 포함되지 않습니다. 명시적으로 표시된 판매에는 제거용 이벤트 ID가 유지됩니다. 환불은 진행자가 제거해야 합니다. 구매 중복 ID는 별도로 최대 2,000개까지 기억하며 표시 기록을 지운 뒤에도 유지됩니다. 기존의 getCommerceState 응답에는 다음이 포함됩니다: commerce.boards; commerceControl 는 다음에 문서화된 보드/판매 명령을 받습니다: 보드 가이드. 수동 수정은 업데이트된 상태를 브로드캐스트하지만 구매 이벤트, 후원 총액, 유료 보상을 만들지 않습니다. 호스트 스냅샷이 35초 동안 없으면 오버레이가 숨겨집니다.

판매자 작업 흐름 추가 사항: commerce.boards.board.id 는 보드 세대를 식별합니다. 수동 saleAdd 는 다음을 제공할 수 있습니다: boardId 그리고 spotId 를 사용해 판매 기록과 칸 배정을 원자적으로 수행합니다. 최근 기록에 남아 있는 중복 연결 판매는 거부됩니다. saleRemove 포함: reopenSpot: true 는 보드 세대가 여전히 일치하는 경우에만 해당 칸을 해제합니다. 공개 판매 항목에는 이 운영자 연결 필드가 없습니다. 선택적 platform 를 수동 판매에 설정하면 필터링용 소스가 유지되며 source: "Host confirmed" 는 확인 방식을 식별합니다. amount 는 해당 항목의 총액이며 다음을 포함합니다: quantity. eBay 결제 완료 주문 어댑터의 meta.ebayPurchase.quantity 는 유지됩니다.

salesSettings.auctionSource 는 Whatnot 또는 eBay Live 상품 도우미를 활성화합니다. 제어 응답의 commerce.auction 에는 마지막으로 캡처된 다음에서 source, title, priceText, status, at만 들어 있습니다: auction_update, 또는 null. 5분 후 만료되며 소스 변경, 유휴 스냅샷, 재시작 시 지워집니다. 도우미는 운영자 전용으로, 영구 저장되지 않고 시청자 브로드캐스트에도 포함되지 않습니다. 입찰자/낙찰자 식별 정보는 버립니다. 소스 스크립트와 경매 이벤트 페이로드는 바뀌지 않습니다. 초안을 복사해도 결제가 확인되거나 판매가 생성되지는 않습니다.

Event Flow audio controls

The Actions overlay accepts actionType: "play_audio" 포함: audioUrl, volume (0–1), and optional audioPlayback: "queue" 또는 "interrupt". Omitting the playback option keeps overlapping playback. Local media continues to use sourceType: "local", localAssetId, 그리고 localAssetName. Queue mode holds up to 30 waiting clips with a two-minute limit per clip; interrupt mode replaces that queue's current clip and clears its waiting items.

actionType: "stop_audio" stops Flow Actions audio clips and clears the sound queue. These are overlay control messages, not source chat events or proof that OBS output was heard. Event Flow resolves a configured random sound set to one audio URL before sending the action. See Event Flow setup.
