플랫폼 간 채팅 릴레이

Twitch와 YouTube 사이에 필요한 릴레이를 설정하고 발신자를 선택하며 반복 메시지를 진단하세요.

모든 가이드 1. 두 채팅 모두 답장을 받을 수 있는지 확인 2. Event Flow에서 Twitch → YouTube 만들기 3. 반대 방향 추가 4. 반향 메시지 이해하기 5. 릴레이 대상 메시지 제한하기 문제 해결

1. 두 채팅 모두 답장을 받을 수 있는지 확인

Twitch와 YouTube Live 채팅을 같은 SSN 세션에 연결하세요. 두 채팅이 도크에 나타나는지 확인한 다음, 소스 탭을 알 수 있는 메시지에서 각각 수동 답장을 보내세요. 본인의 테스트 채널을 사용하세요. 읽기 전용 캡처 소스는 릴레이를 보낼 수 없습니다.

이 설정에는 의도한 대상 채팅만 열어 두세요. 플랫폼 대상에는 해당 플랫폼의 여러 사용 가능한 소스 탭이 포함될 수 있습니다. 별도의 Twitch 봇 계정을 사용한다면 먼저 다음을 완료하세요: 답장용 봇 계정 를 먼저 완료하세요.

2. Event Flow에서 Twitch → YouTube 만들기

다음을 여세요: Event Flow 편집기 를 SSN 메뉴에서 여세요(Actions 오버레이 섹션에도 링크가 있습니다). 흐름을 만들고 다음처럼 알아보기 쉬운 이름을 지정하세요: Twitch에서 YouTube로.

  1. 추가: 소스 기준(From Source) 트리거를 다음에서 추가하세요: 사용자 및 소스(User & Source). 소스로 Twitch를 선택하세요.
  2. 추가: 채팅 릴레이(Relay Chat) 동작을 추가하고 트리거 출력을 동작 입력에 연결하세요.
  3. 해당 동작을 선택하세요. 설정: 릴레이 대상(Relay Destination) 대상: YouTube, 메시지 템플릿은 다음으로 유지하세요: [{source}] {username}: {message}.
  4. 선택: 흐름 저장(Save Flow) 그리고 저장한 흐름을 활성화하세요. SSN을 계속 실행하세요.
  5. 본인의 Twitch 테스트 채팅에 새 일반 메시지를 보내세요. 라벨이 붙은 사본 하나가 YouTube에 도착하는지 확인하세요.

YouTube Shorts는 자체 소스 유형과 대상이 있습니다. 선택: YouTube Shorts 를 필요한 경우 선택하세요. YouTube와 서로 바꿔 쓸 수 없습니다.

3. 반대 방향 추가

다음 이름의 두 번째 흐름을 만드세요: YouTube에서 Twitch로: From Source: YouTube → Relay Chat: Twitch. 저장하고 활성화하세요. 양쪽에서 각각 새 메시지를 보내 플랫폼 간 사본이 하나씩 생성되는지 확인하세요.

유지: 모든 메시지 릴레이(!권장하지 않음!) 는 이 흐름들을 사용할 때 꺼 두어 두 번째 릴레이 시스템이 같은 작업을 하지 않게 하세요. 다른 봇이나 멀티스트리밍 서비스가 이미 채팅을 연결하고 있는지도 확인하세요.

4. 반향 메시지 이해하기

반향 메시지는 SSN이 보낸 뒤 대상 채팅에서 다시 캡처된 메시지입니다. 현재 Relay Chat 동작은 인식된 반향 메시지를 자동으로 건너뜁니다. 원래 메시지가 나온 탭도 제외합니다.

캡처된 반향 메시지를 도크와 오버레이에서 숨기려면 다음을 추가하세요: 반향 필터(Reflection Filter) 동작을 해당 흐름 앞부분에 추가하고 다음을 선택하세요: 모두 차단(Block All). 첫 번째 허용(Allow First) 는 설정된 시간 범위 안에서 일치하는 반향 메시지 하나를 유지합니다. 모두 허용(Allow All) 는 이를 표시합니다. 이 설정은 캡처 후 표시를 제어하며 릴레이 전송 위치를 제어하지 않습니다.

현재 Relay Chat 속성에는 'No Reflections' 확인란이 없습니다. 표시 제어에는 별도의 Reflection Filter를 사용하세요. 외부 서비스가 릴레이된 메시지를 바꾸면 자동 인식이 놓칠 수 있습니다.

5. 릴레이 대상 메시지 제한하기

명령을 처리하려면 다음을 추가하세요: 메시지 시작 문자열(Message Starts With) 트리거를 다음으로 설정하세요: ! 그리고 다음을 거쳐 연결하세요: NOT 게이트를 거치게 하고 다음으로 그 결과와 소스 조건을 결합하세요: AND 를 Relay Chat 앞에 두세요. 참고: Event Flow 가이드 에서 논리 게이트 연결을 확인하세요. 일반 문장과 명령을 모두 테스트하세요.

더 간단한 전체 릴레이를 대신 선택한다면 다음을 사용하세요: Global settings and tools → Commands → Pick relay destinations 그리고 다음을 입력하세요: twitch,youtube. 목록을 비워 두면 가능한 모든 대상으로 보냅니다. 이 목록은 대상을 제어하며 릴레이를 시작할 수 있는 수신 플랫폼을 정하는 것이 아닙니다. 이 대안을 활성화하기 전에 양방향 Event Flow 릴레이를 비활성화하세요.

같은 Commands 섹션에 있는 SSApp 계정 역할 허용/차단 필드로 릴레이를 보낼 계정을 제한할 수 있습니다. 의도한 발신자에게 지정한 역할을 사용하세요. 역할이 일치하지 않으면 사용 가능한 대상이 없을 수 있습니다.

문제 해결

  • 아무것도 전송되지 않음: 수동 답장을 다시 시도하고 로그인/게시 권한을 확인한 다음 저장된 흐름을 활성화하고 대상 및 계정 역할 제한을 확인하세요.
  • 메시지가 계속 늘어남: 먼저 릴레이 흐름을 비활성화하세요. 캡처 소스 중복, 전체 Relay all, 외부 릴레이 봇을 확인한 뒤 한 방향을 다시 테스트하세요.
  • 도크에서만 중복 표시됨: Reflection Filter 표시 정책과 전체 Message - Visibility 반향 설정을 확인하세요.
  • 잘못된 YouTube 대상으로 전송됨: YouTube와 YouTube Shorts를 구분해 확인하고 의도하지 않은 사용 가능 채팅을 닫으세요.

Test Flow 동작은 실제 메시지를 보낼 수 있습니다. 직접 관리하는 대상을 사용하세요. 가상 테스트로 실제 소스의 계정 라우팅까지 확인할 수는 없습니다.
