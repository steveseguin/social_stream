경품 추첨, 참가권, 포인트 경품

무료 추첨을 진행하거나 SSN 포인트로 티켓을 판매하거나 포인트를 상금으로 지급하세요.

모든 가이드 무료 추첨 티켓 포인트 상금 게임 여러 추첨 OBS 표시 Event Flow Stream Deck 및 API 백업 문제 해결
추첨이 처음인가요? 다음으로 시작하세요: 첫 경품 추첨에서 스크린샷을 포함한 안내를 볼 수 있습니다.

5단계로 무료 추첨 진행

  1. 팝업에서 다음을 여세요: 경품 추첨 옵션. ID는 다음으로 유지하세요: default 로 정하고 키워드를 다음으로 설정하세요: !enter. 티켓 가격과 포인트 상금은 다음 값으로 두세요: 0.
  2. 다음을 선택하세요: 당첨자 카드, 이름 릴, 또는 커뮤니티 룰렛. 미리 본 뒤 링크를 OBS에 다음 소스로 추가하세요: 브라우저 소스.
  3. 클릭: 참가 접수 시작. 시청자는 채팅에 키워드를 입력해 응모합니다.
  4. 클릭: 참가 마감, 그다음은 당첨자 추첨. 잊어도 추첨하면 응모가 닫힙니다.
  5. 클릭: 새 라운드 로 다시 추첨하세요. 이전 당첨자는 기록에 남습니다.
Social Stream Ninja를 계속 실행하세요. 이 동작으로 추첨됩니다. OBS 소스 안을 클릭할 필요는 없습니다.

이전 독립형 커뮤니티 휠은 다음을 &managed 를 링크에서 빼면 작동합니다. 포인트와 원격 제어에는 관리형 링크가 필요합니다.

SSN 포인트로 티켓 판매

  1. 다음을 켜세요: 참여 포인트 시스템 를 팝업에서 켜세요. Twitch 채널 포인트가 아닌 SSN 포인트입니다.
  2. Giveaway Options에서 다음을 여세요: 참가권 및 포인트 경품를 여세요. 다음을 설정하세요: 티켓당 포인트 그리고 시청자당 최대 응모권 수.
  3. 클릭: 참가 접수 시작. 추첨 이름이 다음과 같다면 friday일 때 시청자는 다음으로 티켓 5장을 삽니다: !ticket friday 5.
  4. 다음에서 응모자를 확인하세요: 경품 추첨 및 기록 관리.
이 상황일 때…포인트는…
시청자가 티켓을 구매함보류되어 다른 곳에 쓸 수 없습니다.
시청자의 잔액이 부족합니다:차감되지 않고 티켓도 없습니다.
당첨자를 뽑을 때사용됩니다.
클릭할 때: 취소 및 환불모두에게 반환됩니다.
추첨 전에 시청자 한 명을 제거할 때해당 시청자에게 반환됩니다.
첫 응모 후에는 규칙이 잠깁니다. 규칙을 바꾸려면 취소하고 반환한 뒤 새 회차를 시작하세요. New round는 유료 회차를 버리지 않습니다. 닫았다 다시 여는 것은 일시 중지일 뿐입니다.

포인트 경품 지급

  1. 응모를 열기 전에 다음을 설정하세요: 당첨자당 포인트 경품 그리고 경품 수.
  2. 평소처럼 응모를 여세요.
  3. 한 명씩 추첨하고 각 당첨자의 포인트에 상금을 더합니다.

상금 포인트는 새로 만들어지며 티켓 판매에서 가져오지 않습니다. 최대 지급은 상금 × 상금 개수입니다.

끝난 추첨은 취소할 수 없습니다. 실수는 시청자 포인트를 수동으로 조정하세요. 표시를 다시 연결해도 상금을 두 번 지급하지 않습니다.

포인트 보상이 있는 게임

Number Hunt(숫자 찾기)

  1. 유형을 다음으로 설정하세요: Number Hunt(진행자 제어), 티켓당 포인트 0, 그리고 경품 수 1. 원하면 포인트 상금을 추가하세요.
  2. Social Stream이 1~100의 비밀 숫자를 고릅니다.
  3. 참가자는 다음으로 추측합니다: !guess friday 50 (자신의 추첨 ID 사용).

틀리면 모두의 추측 범위가 좁아집니다. 처음 맞힌 사람이 이기며 시청자마다 5초에 한 번 추측할 수 있습니다.

추첨 표시 또는 다음을 사용하세요: games/numberhunt.html?session=YOUR_SESSION&managed&giveaway=friday. 일반 게임은 SSN 포인트를 지급하지 않습니다.

Coin Flip Pot

  1. 유형을 다음으로 설정하세요: Coin Flip Pot, 티켓당 포인트 1, 경품 수 1, 그리고 당첨자당 포인트 경품 0.
  2. 시청자는 다음으로 베팅합니다: !ticket friday 3 heads 또는 !ticket friday 3 tails.
  3. 응모를 닫고 추첨하세요. 베팅 금액과 관계없이 앞뒤 확률은 50대50입니다.

승자는 자기 베팅을 돌려받고 패자의 베팅을 베팅 비율대로 나눠 받습니다. 수수료나 새 포인트는 없습니다. 예를 들어 승자가 2와 1, 패자가 5를 걸면 총 8포인트를 5와 3으로 나눕니다.

양쪽에 참가자가 있어야 추첨됩니다. 추첨 전에 취소하면 모두에게 반환합니다.

남는 한 포인트의 배분 방법

남는 포인트는 소수 부분이 큰 사람부터 주며 같으면 먼저 응모한 사람에게 줍니다.

여러 추첨을 동시에 진행

  • 각각 짧은 다음 값을 정하세요: 경품 추첨 ID (영문자, 숫자, -, _)를 사용하고 다음을 추가하세요: &giveaway=ID 를 해당 OBS 링크에 추가하세요.
  • 티켓과 추측 명령에는 추첨 이름을 지정합니다. 예: !ticket friday 5.
  • 무료 추첨마다 다른 키워드를 사용하세요. 같은 키워드로 두 곳에 응모되지는 않습니다.
  • 모든 티켓은 해당 시청자의 하나의 포인트 잔액에서 사용됩니다.
팝업은 새 회차를 설정합니다. 진행 중인 회차의 실제 규칙은 관리자에서 확인하세요. OBS 링크를 수정해도 외형만 바뀝니다.

OBS 표시 화면

  • 다음을 사용하세요: 1280 × 720 Browser Source로 추가하세요. 다음을 선택하지 않으면 배경은 투명합니다: 테마 패널.
  • 휠에는 최대 120명의 이름을 표시하지만 당첨자는 모든 티켓에서 뽑습니다.
  • 다시 연결하면 저장된 결과를 표시합니다. 동작 줄이기 설정에서는 애니메이션을 건너뜁니다.
  • Social Stream은 OBS 장면이 방송 중인지 알 수 없습니다.
비공개로 유지할 항목: 제어 링크, 세션 ID, 백업 파일.

Event Flow

  1. 추가할 항목: 경품 추첨 / 참가권 작업을 사용하세요(포인트 작업 아래).
  2. 동작을 선택하세요: 무료 응모, 티켓 구매, 무료 티켓 지급, 응모 닫기, 당첨자 추첨, 취소 및 반환, 상태 조회.
  3. 추첨 ID와 티켓 수를 선택하세요. 공동 판돈 방식이면 앞면이나 뒷면도 선택하세요.
참가권 구매는 이미 포인트를 사용합니다. 앞에 Spend Points 작업을 넣지 마세요.

메시지를 보낸 시청자 대신 실행합니다. 지급이나 호스트 제어 앞에 신뢰할 수 있는 트리거나 필터를 넣으세요.

Event Flow 자세히 보기
  • 실패하면 종속 작업은 멈추지만 채팅 메시지는 계속 표시됩니다.
  • 결과는 다음에 있습니다: meta.giveawayControlResult.
  • 테스트 패널은 시뮬레이션만 합니다. 실제 테스트는 별도 호스트나 프로필을 사용하세요.
  • 실행 시 잔액을 확인하므로 응모 메시지 자체로 마지막 부족한 포인트를 얻을 수 없습니다.
  • 자체 메시지 ID가 있는 소스에서 중복 방지가 가장 확실합니다.
  • 시청자가 없는 예약 이벤트는 티켓을 구매할 수 없습니다.

Stream Deck 및 API

Stream Deck 플러그인에는 다음이 있습니다: 추첨 열기, 추첨 닫기, 당첨자 추첨, 취소 및 환불, 새 추첨 회차, 그리고 추첨 상태.

  • 사용하는 항목은 default 추첨에서 작동합니다. 다른 추첨에는 다음을 {"giveawayId":"friday"} 를 값 필드에 입력하세요. Open giveaway는 다음도 받습니다: config 객체입니다.
  • 키는 Social Stream의 응답을 확인할 뿐 OBS 표시를 확인하지 않습니다. 시간 초과면 다시 추첨하기 전에 상태를 확인하세요.
API로 티켓 구매 
{"protocol":2,"action":"buygiveawaytickets","get":"callback-1","value":{"giveawayId":"friday","roundId":"ROUND_ID","operationId":"purchase-123","count":5,"actor":{"chatname":"Avery","type":"youtube","userid":"SOURCE_USER_ID"}}}
  • operationId 는 구매를 식별하고 get 는 응답을 식별합니다.
  • 재시도에는 같은 작업 ID를 쓰고 새 구매에는 새 ID를 사용하세요.
호스트 API 권한은 모든 시청자의 포인트를 사용할 수 있습니다. 공개 양식으로 노출하지 마세요.

기록과 백업

경품 추첨 및 기록 관리 에서 회차, 응모자, 당첨자를 보여 줍니다. 다음을 할 수 있습니다: 당첨 기록 내보내기 (JSON) 또는 포인트와 추첨 전체 백업을 저장하세요. 업로드되는 것은 없습니다.

재시작 후 열린 회차가 닫힌 상태로 돌아오며 티켓은 계속 보류됩니다. 다시 열거나 추첨하거나 취소 후 반환하세요.

백업 복원

다음에서만 작동합니다: 새 호스트 를 포인트나 추첨이 없는 상태로 사용하세요.

  1. 이전 호스트를 꺼 두고 새 브라우저 프로필에서 SSN과 추첨 관리자를 여세요.
  2. 다음 항목 아래에서: 새 호스트에서 복구에서 전체 백업을 선택하세요. 메시지를 기다리고 표시된 세션 ID를 적어 두세요.
  3. 팝업의 세션 옵션에서 해당 세션 ID를 입력하세요.
  4. 관리자로 돌아가 추첨 ID를 선택하고 다음을 클릭하세요: 새로고침. 규칙, 응모자, 당첨자를 확인하세요. 복원된 회차는 닫힌 상태입니다.
  5. 다시 열기, 추첨 또는 취소 및 환불. 그다음 새 백업을 저장하세요.
이전 호스트와 복원한 호스트를 동시에 실행하지 마세요. 백업 저장 이후의 내용과 팝업 설정은 포함되지 않습니다.
데이터 저장 위치 자세히 보기
  • 포인트는 이 브라우저나 앱 프로필에 저장되며 다른 곳과 동기화되지 않습니다. 회차는 세션별로 보관됩니다.
  • 브라우저 데이터를 지우면 삭제될 수 있으니 프로필 밖에 백업을 보관하세요.
  • 잔액만 가져와서는 보류된 티켓을 복원할 수 없습니다. 티켓 보류 중에는 포인트 초기화가 차단되며 초기화해도 추첨 기록은 지워지지 않습니다.
  • 확인되지 않은 스티커 구매는 시간 초과 후 보류가 풀립니다.
  • 클라우드 백업이나 현금화는 없습니다. 서버 백업은 추후 추가될 수 있습니다.

문제 해결

문제시도할 방법
시청자가 응모할 수 없음ID, 키워드, 회원 전용, 응모 개방, 플랫폼 캡처 여부를 확인하세요. 봇, 비공개, 오래된, 재전송, 테스트 메시지는 포함되지 않습니다.
시청자 계정이 잘못 표시됨이름 변경으로 지갑 식별이 혼동될 수 있습니다. 호스트에서 확인하세요. 다른 플랫폼의 지갑은 합치지 않습니다.
버튼이 반응하지 않음올바른 SSN 호스트가 실행 중이며 호스트 제어가 켜져 있는지 확인하세요. 재시도 전에 새로 고치세요.
포인트 초기화 또는 가져오기가 안 됨보류된 티켓 구매를 먼저 완료하거나 취소하세요. 보류 티켓이 든 백업은 전체 복구를 사용하세요.
!spend 에 unknown reward가 표시됨가격이 설정된 보상이 필요합니다.
