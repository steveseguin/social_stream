사용자 기억 (User Memory)

중복 없이 참가자를 기억하고 이후 메시지에서 확인하며 무작위 당첨자를 뽑고 원하는 목록만 초기화하세요. 플랫폼 역할을 영구적인 전역 상태로 바꿀 필요가 없습니다.

기억 목록 하나, 여러 도구

다음 항목: 사용자 기억 (User Memory) 상태 노드는 서로 격리된 사용자 집합 하나를 관리합니다. 각 Remember, Forget, Check, Draw, Clear 노드는 해당 상태 노드를 선택합니다. ‘방송 좋아요 참여자’와 ‘추첨 응모자’처럼 별도 목록이 필요하면 다른 User Memory 노드를 만드세요.
청록색 실선: 다음에 실행되는 이벤트 보라색 점선: 이 노드가 해당 기억 목록을 사용함

작은 보라색 측면 마름모를 User Memory 노드로 끌거나 노드 속성에서 기억 목록을 이름으로 선택하세요. 내부적으로 작업은 상태 노드의 ID를 저장합니다. 기억 노드를 선택하면 연결된 모든 작업이 강조되며, 삭제하면 연결이 끊기기 전에 경고합니다.

설정하기

  1. 드래그할 항목: 상태 노드 → 사용자 기억 를 캔버스에 놓으세요.
  2. 관리하는 목록에 맞는 이름을 지정하세요. 예: Heart Me 참가 자격, 방송 좋아요 참여자, 또는 경품 추첨 참가자.
  3. 선택: 현재 앱 세션 또는 재시작 후에도 저장 (Save across restarts).
  4. 필요한 검사와 작업을 추가한 뒤 측면 마름모나 드롭다운으로 각각 이름 있는 기억 목록에 연결하세요.
  5. 청록색 선으로 일반 이벤트 경로를 연결하고 다음을 사용하세요: 흐름 테스트 (Test Flow) 로 방송 전에 서로 다른 사용자 이름 두 개를 테스트하세요.

사용 가능한 작업

노드역할
사용자 기억하기 (Remember User)현재 이벤트의 사용자를 한 번만 추가합니다. 반복 참여는 중복 추첨 항목을 만들지 않고 해당 사용자의 참여 횟수를 늘립니다.
기억된 사용자인지 확인 (User Is Remembered)현재 메시지가 선택한 기억 목록의 사용자에게서 온 경우 true를 반환하는 트리거/검사.
사용자 잊기 (Forget User)현재 이벤트의 사용자만 제거합니다.
무작위 사용자 선택 (Pick Random User)기억된 고유 사용자 한 명을 선택합니다. 원하면 당첨자를 제거하여 다시 당첨되지 않게 할 수 있습니다.
모든 사용자 삭제 (Clear All Users)선택한 User Memory 객체만 비웁니다.
상태 노드 초기화 (Reset State Node)초기화 대상으로 해당 기억 노드를 선택하면 User Memory도 비웁니다.
신원 규칙: 사용자는 플랫폼과 사용자 ID를 조합하여 구분합니다. 표시 사용자 이름은 대체 수단으로만 사용합니다. 사용자 식별 정보가 없는 익명 이벤트나 집계 이벤트는 안전하게 무시합니다.

실용적인 예시

TikTok Heart Me 또는 팀 멤버 → ? 음성 읽기

선물 이벤트로 보낸 사람을 기억하세요. 선물 행 하나를 영구적인 ‘멤버’ 역할로 바꾸려 하지 마세요.

TikTok 선물 이벤트 + ‘Heart Me’ 일치 → AND → 사용자 기억 ···→ [Heart Me 참가 자격]
? 명령 + TikTok 소스 + (TikTok 팀 멤버 OR 기억된 사용자) → AND → 텍스트 읽기 ? 명령 + NOT TikTok 소스 → AND ────────────────────────────────→ 텍스트 읽기
  • TikTok 팀/팬 상태를 확인하려면 선택하세요: 사용자 역할 → TikTok 팀 멤버을 선택하세요. 수신된 TikTok 배지/레벨 데이터를 직접 읽으므로 메인 채팅 오버레이의 ‘멤버로 취급’ 표시 설정은 필요하지 않습니다.
  • 선물 페이로드는 캡처 모드에 따라 다릅니다. 일반적인 설정: Event Type → Other: gift 추가: Message Contains: Heart Me를 사용할 수 있습니다. Test Flow/Event Reference에서 캡처된 행을 확인하고 소스가 제공하는 가장 명확한 필드에 맞추세요.
  • 두 분기 모두 앞의 ?으로 시작해야 합니다. 다른 플랫폼에서는 모두의 메시지를 읽고 TikTok에서만 제한합니다.

좋아요를 누르거나 참여한 사람 기억

Event Type → Other: liked → Remember User ···→ [Liked Stream]

캡처한 좋아요/참여 이벤트에 사용자가 명시되어 있을 때 작동합니다. 전체 좋아요 수 업데이트는 개인을 식별하지 않으므로 기억할 수 없습니다. 별도의 검사나 추첨이 필요하면 참여 유형마다 다른 기억 목록을 사용하세요.

중복 응모 없는 경품 추첨

메시지가 !enter로 시작 → 사용자 기억 ···→ [경품 추첨 참가자] 관리자 + 메시지가 !draw로 시작 → AND → 무작위 사용자 선택 ···→ [경품 추첨 참가자] 관리자 + 메시지가 !resetdraw로 시작 → AND → 모든 사용자 삭제 ···→ [경품 추첨 참가자]

활성화 선택한 사용자 제거 를 사용하면 같은 당첨자가 다시 뽑히지 않습니다. 공개 방송에서는 추첨/초기화 명령에 관리자, 운영자 또는 정확한 사용자 검사를 적용하세요.

참여 + 추첨 예시 흐름 다운로드

초기화 및 저장

수동

사용: 지금 모든 사용자 삭제 (Clear All Users Now) 을 구성/테스트 중 기억 속성에서 사용하세요.

흐름에서

사용: 모든 사용자 삭제 (Clear All Users) 또는 일반적인 상태 노드 초기화 (Reset State Node)에서 정확한 기억 목록을 선택하세요.

자동

비활동 후, 방송 시작 시 또는 방송 종료 시 삭제합니다. 비활동 초기화 값을 0으로 설정하면 해당 초기화를 끕니다.

재시작 간 유지

세션 기억은 앱이 시작될 때 비어 있습니다. 저장된 기억은 해당 기억을 직접 비우기 전까지 다시 로드됩니다.

‘모두 삭제’의 적용 범위: 선택한 기억 목록 안의 모든 사용자를 뜻합니다. 모든 Event Flow 상태, 모든 추첨, Social Stream Ninja의 모든 기억을 뜻하지는 않습니다.

추첨 및 참여 출력 사용

기억 작업은 메시지에 필드를 추가하여 후속 Show Text, Send Message, 웹훅 또는 사용자 지정 작업에서 사용할 수 있게 합니다.

필드의미
userMemoryName선택한 기억 목록의 이름.
userMemoryCount현재 기억된 고유 사용자 수.
userMemoryAddedRemember User가 새로운 고유 사용자를 추가한 경우에만 true.
userMemoryEntryCount해당 사용자가 참여한 횟수.
selectedUser추첨된 사용자의 표시 이름.
selectedUserId, selectedUserSource추첨된 사용자의 고정 ID와 플랫폼.
selectedUserParticipationCount당첨자의 기록된 참여 횟수.
selectedUserReasonRemember User가 저장한 가장 최근의 사유 템플릿.
selectedUserRemoved추첨에서 선택된 당첨자를 제거했는지 여부.

문제 해결

점선이 표시되지 않음작업을 선택하고 대상 User Memory를 고르거나 보라색 측면 마름모를 기억 허브로 끌어 놓으세요.
같은 사람이 두 번 표시됨이벤트가 서로 다른 플랫폼에서 왔는지 확인하세요. 플랫폼 + 사용자 ID는 의도적으로 별개 신원을 만듭니다.
좋아요로 아무도 추가되지 않음이벤트에 사용자 식별 정보가 없었을 가능성이 큽니다. 이벤트 페이로드를 확인하세요. 집계 수치는 이름이 있는 참가자로 변환할 수 없습니다.
저장한 기억 목록이 다시 나타남해당 기억 목록에서 Clear All Users를 사용하세요. 흐름을 바꾸거나 다른 기억 목록을 비워도 지워지지 않습니다.
누구나 추첨/초기화 명령을 실행할 수 있음작업 앞의 AND 게이트에 User Role: moderator/admin 또는 정확한 호스트 사용자 검사를 추가하세요.
