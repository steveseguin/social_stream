連接商店，展示商品。

商品與提醒彼此獨立

使用 營利 ，在 SSN 中推廣公開商品和支持頁面、接收活動，或同時執行兩者。本指南涵蓋 Fourthwall、Ko-fi 和 Buy Me a Coffee。有關 NinjaBacker、Throne、Amazon 和 eBay，請參閱 營利指南.

連接提醒 · Fourthwall · Ko-fi · Buy Me a Coffee · 匯入商品 · OBS 與 QR Code · 疑難排解

連接活動提醒

  1. 開啟 營利 → Fourthwall、Ko-fi 與 Buy Me a Coffee 提醒 並選擇供應商。
  2. 點選 接收器設定。啟用現有的 擴充功能的遠端 API 控制 開關，然後保持 SSN 開啟。
  3. 返回「營利」並點選 複製 webhook URL。將此私人位址貼到下方對應供應商的 webhook 設定中。
  4. 檢查接收器狀態。 接收器已連線 表示 SSN 正在監聽，不表示供應商設定已通過驗證。當經過解析且不重複的供應商事件到達目前執行的應用程式時，「最後事件」一列會更新；重新啟動後會重設。
  5. 使用 預覽範例提醒 ，在單獨的範例頁面中檢查外觀。這不會傳送付款、更新總額、執行 Event Flow 或驗證 webhook 傳遞。

這三個現有的工作階段 URL 端點依賴於 URL 保密；SSN 目前的設定不接受它們的簽章密鑰。它們適合直播提醒，不能作為履約所需的付款證明。請勿公開 webhook 位址，也不要將其用作面向觀眾的 QR Code 目的地。

Fourthwall

  1. 在 Fourthwall 中開啟 設定 → 開發者選項 → Webhooks.
  2. 建立 webhook，並貼上從 SSN 複製的 Fourthwall URL。
  3. 選擇所需的支援事件： ORDER_PLACED, GIFT_PURCHASE, DONATION 和 SUBSCRIPTION_PURCHASED.
  4. 儲存 webhook，並保持 SSN 執行。

訂單顯示為購買，商品贈禮顯示為禮物，新訂閱顯示為會員。為保持相容，普通 Fourthwall 訂單仍保留原有的贊助值。禮物卡兌換訂單不會再次增加預付價值。標記為測試的事件會被略過。

Ko-fi

  1. 開啟 Ko-fi Webhooks.
  2. 將從 SSN 複製的 Ko-fi URL 貼到 Webhook URL，然後儲存／更新。
  3. 保持 SSN 執行。公開小費、會員付款、商店訂單和委託訂單使用同一個連線。

私人付款會被排除。會員付款顯示為會員活動；商店訂單和委託訂單顯示為購買，不增加贊助總額。Ko-fi 不會透過此 webhook 提供會員取消通知。

測試： 先使用 SSN 的獨立範例預覽。Ko-fi 範例付款可能與真實付款相似，若傳送到作用中的接收器，可能觸發提醒、總額更新和動作。請勿在啟用付費獎勵的工作階段中使用供應商測試。

Buy Me a Coffee

  1. 開啟 整合 ，在創作者控制台中選擇 新增 webhook.
  2. 為其命名，並貼上 SSN 的 Buy Me a Coffee URL 作為端點。
  3. 選擇 donation.created, extra_purchase.created, commission_order.created, wishlist_payment.created 和 membership.started ，按需使用。
  4. 儲存並保持傳遞啟用。使用供應商的事件傳遞記錄調查失敗原因。

商店和委託訂單屬於購買。願望清單付款屬於禮物支持。會員開始屬於會員公告，不是單獨確認的扣款。隱藏備註保持隱藏，匿名支持者保持匿名。控制台中標記為下列類型的測試： live_mode: false 會被略過，不產生付款提醒。退款和生命週期更新不會建立付款，也不會沖減已有總額。

匯入 Fourthwall 商品

  1. 在 Fourthwall 的 設定 → 開發者選項，建立一個 Storefront 權杖。請使用店面權杖存取公開商品目錄，不要使用管理 API 金鑰。
  2. 在 SSN 中開啟 商品與支持連結 → 設定商品和連結 → 匯入 Fourthwall 商品.
  3. 貼上公開商品 URL 和權杖，然後點選 載入商品詳細資料.
  4. 檢查已載入的名稱、圖片、價格和公開 URL。確認 URL 與權杖屬於同一個商店，包括使用自訂網域的情況。權杖決定查詢哪個商店的商品目錄。
  5. 選擇「購買」、「贈禮」、「支持」或「加入」，說明觀眾將執行的動作。點選 新增商品或連結，啟用「商品與支持連結」，然後 儲存設定.

此功能透過 Fourthwall 的 Storefront API，每次匯入一個可用的公開商品。權杖僅用於該次請求，之後會被清除，不會儲存或傳送到疊加畫面。不同規格的價格和組合商品價格會留空，以免誤導為固定結帳總額。匯入只是當時的快照：價格、庫存和圖片不會自動重新整理。發生變化時請重新匯入或編輯。目錄最多儲存 20 個項目；再次新增會建立另一個項目。

顯示商品、公開連結和 QR Code

你也可以手動輸入任何網站的公開商品或支持連結，包括 Shopify、Tiltify 或 Patreon。新增圖片 URL 和選填價格，選擇用途，啟用目錄並儲存。新增連結不會連接付款資料來源。

  1. 選擇 商品與支持連結 ；對應的設定項目： 疊加畫面連結：.
  2. 開啟 疊加畫面連結選項。選擇「商品展示」、「支持卡片」、「活動提醒」或組合檢視。
  3. 點選 複製 OBS 連結 並將其貼到 OBS 瀏覽器來源。初始尺寸使用 800 × 600。如需分開的推廣和活動圖層，請為每種檢視分別建立來源。
  4. 使用「顯示選項」固定展示第一個商品或輪播項目。啟用 QR Code，讓觀眾掃描公開目的地位址。使用 複製公開連結 ，該按鈕位於項目旁，方便你自行在聊天中分享其可點選位址。

商品展示會包含所提供的商品圖片；較小的支持卡片會隱藏圖片。活動提醒獨立運作，不會附上無關的輪播商品 QR Code。保持公開連結清楚可讀，並在最終 OBS 版面配置下用手機測試 QR Code。變更 OBS 連結的縮放比例或裁切過緊，可能導致難以掃碼。

對於多重提醒或活動動態，使用它們現有的疊加畫面連結，並保持相同的 SSN 工作階段。這些現有活動疊加畫面不需要啟用商品目錄。通用的「營利」活動檢視則需要啟用目錄。在 Event Flow 中，對於帶有下列欄位的項目，仍使用 Donation 觸發器： hasDonation；購買或禮物完成事件請使用 Event Type。參閱 事件對應.

如果沒有顯示任何內容

  • 接收器已關閉： 啟用擴充功能的遠端 API 控制。其他 API 開關用於不同用途。
  • 已中斷連線： 保持 SSN 開啟並檢查網路存取。此狀態是共用接收器的連線狀態，不是供應商控制台中的傳遞狀態。
  • 未收到事件： 檢查所選供應商、私人 URL 和供應商的傳遞設定。本機預覽成功僅能驗證外觀。
  • 事件被略過： 標記的測試、私人付款、不支援的事件類型或無效金額會被排除。狀態中不會顯示買家詳細資料。
  • 收到事件但沒有疊加畫面： 檢查工作階段／密碼、來源篩選器、事件類別、SSN 規則和 OBS 可見性。購買不是訂閱；大多數購買也不是贊助。
  • 重複內容： 避免同時透過供應商直連和彙整服務傳入同一筆付款。重試去除重複使用供應商的傳遞 ID。
  • 匯入失敗： 檢查商品 slug、Storefront 權杖，以及商品是否公開且可用。仍可手動輸入。

這是直播活動動態，不是訂單帳本。確認付款、退款和履約請使用供應商控制台。 Shopify 現已提供獨立的商品匯入和帶簽章的已付款訂單設定。Tiltify 活動動態和 Patreon 付費會員仍是未來計畫整合的功能。
