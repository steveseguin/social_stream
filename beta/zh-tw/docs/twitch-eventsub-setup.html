Twitch 設定與 EventSub

簡單聊天使用一般頁面擷取；追蹤、訂閱、Bits、獎勵、揪團、Hype Train 及頻道控制則使用 EventSub/WebSocket 模式。

選擇 Twitch 來源模式

模式最適合重要差異
標準 從 Twitch 聊天頁面或彈出頁面擷取基本公開聊天。 讀取頁面公開的內容。操作簡單，但不提供完整 EventSub 事件集。
WebSocket / EventSub 追蹤、訂閱、Bits、獎勵、揪團、直播狀態、Hype Train、管理同步、傳送聊天及頻道詳細資料。 需要 Twitch OAuth。僅在登入帳號、頻道角色、頻道資格及授予的範圍允許時，才會啟用事件。

桌面應用程式設定

  1. 選擇 加入來源 → Twitch（Add source → Twitch）.
  2. 輸入 Twitch 頻道 URL 中使用的登入名稱。對於 twitch.tv/examplechannel，輸入 examplechannel.
  3. 將 WebSocket 保持選取狀態，以使用更豐富的 EventSub 來源。目前應用程式中的 Twitch 預設採用此模式。
  4. 選擇 啟用來源，然後 登入 Twitch.
  5. 授權要求的權限，並保持 Twitch 來源視窗開啟。

瀏覽器擴充功能 EventSub 設定

  1. 安裝並啟用目前版本的 Social Stream Ninja 擴充功能。
  2. 開啟 Twitch EventSub 來源頁面.
  3. 替換 examplechannel 為要監控的頻道登入名稱，修改 URL 中的該值。
  4. 選擇 登入 Twitch 並核准所要求的存取權限。
  5. 保持該頁面開啟。測試警示前，確認 User 與 Channel 欄位正確。
https://socialstream.ninja/sources/websocket/twitch.html?channel=CHANNEL_LOGIN

若使用基本的 Standard 擷取，請開啟一般 Twitch 聊天或彈出聊天頁面，並保持聊天可見。

Twitch 要求的權限

Social Stream 要求具有其支援的控制項及訂閱所需權限的使用者權杖。授予範圍不會讓帳號成為實況主或管理員；Twitch 仍會檢查該帳號在所選頻道中的角色。

權限群組用途
聊天讀取聊天、傳送聊天及列出聊天使用者。
追蹤者與訂閱者追蹤事件、訂閱者事件、贈送訂閱及續訂訊息。
Bits、獎勵與 Hype TrainCheers、自訂頻道點數兌換及 Hype Train 狀態。
管理帳號有權管理該頻道時，支援訊息刪除、封禁/暫時禁言及封鎖同步。
頻道管理讀取/更新標題與分類、讀取/管理廣告及顯示頻道指標。

請參閱 Twitch 官方 範圍參考 和 EventSub 訂閱類型.

目前來源處理的事件

  • 追蹤： new_follower.
  • 訂閱： new_subscriber, resub，以及 subscription_gift.
  • Bits： cheer 並附帶贊助值。
  • 頻道點數： reward.
  • 揪團： raid.
  • 直播與廣告狀態： stream_online, stream_offline，以及 ad_break.
  • Hype Train： hype_train 開始、進度及結束更新。
  • 管理： 在權限允許時更新封禁及訊息刪除。

Twitch 訂閱者事件需要符合資格的 Affiliate/Partner 頻道及實況主存取權限。追蹤和管理訂閱要求登入使用者是實況主或已授權管理員，依事件而定。

事件缺失時首先檢查的事項

  1. 確認來源頁面顯示正確的 使用者 和 頻道.
  2. 保持來源頁面/視窗開啟，並確認聊天連線處於作用中。
  3. 若聊天正常但追蹤/訂閱/獎勵無效，請登出並重新授權，以授予目前所需的範圍。
  4. 確認登入帳號是該頻道的實況主或獲准管理員。
  5. 檢查停駐面板和警示疊加畫面是否使用相同的 Social Stream 工作階段 ID。
  6. 使用彈出選單中的模擬測試訊息或 Multi Alerts 預覽，區分擷取問題與疊加畫面問題。

EventSub 可能多次傳遞同一通知。 Twitch 文件規定至少傳遞一次。Social Stream 內建重複保護，但自訂 API 接收端仍應盡可能依事件/訊息識別碼去除重複。請參閱官方 EventSub 概觀.
