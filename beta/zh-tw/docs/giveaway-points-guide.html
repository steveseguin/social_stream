抽獎、票券和點數獎品

執行免費抽獎、讓觀眾用 SSN 點數買票，或發放點數獎品。

第一次使用抽獎？ 先使用 你的第一次抽獎，其中有螢幕截圖教學。

五步執行免費抽獎

  1. 在彈出選單中開啟 抽獎選項。將 ID 保持為 default ，關鍵字設為 !enter。票價和點數獎品保持為 0.
  2. 選擇一個 獲勝者卡片, 姓名捲軸，或 社群轉盤。預覽後將連結作為以下來源加入 OBS： 瀏覽器來源.
  3. 點選 開放報名。觀眾在聊天輸入關鍵字即可報名。
  4. 點選 關閉報名，然後 抽出獲勝者。（若忘記關閉，抽獎時會自動關閉報名。）
  5. 點選 新回合 以再次抽獎，過去中獎者保留在歷史中。
保持 Social Stream Ninja 執行。 這會執行抽獎，不需要點擊 OBS 來源內部。

舊版獨立社群轉盤仍可運作，只需將 &managed 從連結中移除。點數和遠端控制需要管理型連結。

用 SSN 點數售票

  1. 開啟 忠誠度點數系統 ，位於彈出選單中。這是 SSN 點數，不是 Twitch 頻道點數。
  2. 在 Giveaway Options 中開啟 票券和點數獎品。設定 每張票的點數 和 每位觀眾的票數上限.
  3. 點選 開放報名。對於名為以下名稱的抽獎， friday，觀眾可用以下指令購買 5 張票： !ticket friday 5.
  4. 在以下位置查看報名者： 管理抽獎和歷程記錄.

觀眾沒有足夠的不扣除，也不發票。
抽出中獎者時被消耗。
點擊以下按鈕時 取消並退款退還所有人。
抽獎前移除一名觀眾時退還該觀眾。
首次報名後規則鎖定。 更改規則需取消並退還，再開始新回合。New round 不會捨棄付費回合。關閉再開放只是暫停。

贈送點數

  1. 開放報名前設定 每位獲勝者的點數獎品 和 獎品數量.
  2. 依照平常方式開放報名。
  3. 每次抽一名中獎者，並將獎品加入其點數。

獎品點數是新發放的，不從售票收入扣除。最高發放量為獎品點數 × 獎品數量。

已完成的抽獎無法撤銷。 修正錯誤請手動調整該觀眾點數。重新連線顯示頁面不會重複發獎。

帶點數獎勵的遊戲

數字尋蹤

  1. 把類型設為 數字尋蹤（主播控制）, 每張票的點數 0，以及 獎品數量 1，可按需加入點數獎品。
  2. Social Stream 隨機選擇 1 到 100 的祕密數字。
  3. 玩家用以下指令猜測： !guess friday 50 （使用你的抽獎 ID）。

猜錯會縮小所有人的範圍，首個猜對者獲勝。每位觀眾每五秒可猜一次。

用抽獎顯示頁面或 games/numberhunt.html?session=YOUR_SESSION&managed&giveaway=friday。一般遊戲不會發放 SSN 點數。

擲硬幣獎池

  1. 把類型設為 擲硬幣獎池, 每張票的點數 1, 獎品數量 1，以及 每位獲勝者的點數獎品 0.
  2. 觀眾使用以下指令下注： !ticket friday 3 heads 或 !ticket friday 3 tails.
  3. 關閉報名並抽獎。無論下注多少，正反面機率均為 50/50。

贏家拿回自己的下注，並按下注比例分得輸家的下注。無費用，也無新點數。例：贏家下注 2 和 1，輸家下注 5，總獎池 8 點分為 5 和 3。

兩邊都必須有人，否則拒絕抽獎。抽獎前取消可退還給所有人。

剩餘零散點數如何分配

剩下的點數先給小數份額最大的人，相同則先報名者優先。

同時執行多個抽獎

  • 分別設定簡短的 抽獎 ID （字母、數字、 -, _），並加入 &giveaway=ID 加入它的 OBS 連結。
  • 購票和猜測指令需指明抽獎名稱，例如 !ticket friday 5.
  • 每個免費抽獎使用獨立關鍵字，共用關鍵字不會同時報名兩個抽獎。
  • 所有票都從觀眾同一個點數餘額扣除。
彈出選單設定新回合。目前回合的實際規則請看管理員頁面，編輯 OBS 連結只改變外觀。

OBS 顯示頁面

  • 使用一個 1280 × 720 Browser Source。背景透明，除非選擇 佈景主題面板.
  • 轉盤最多顯示 120 個名字，但中獎者從所有票中抽出。
  • 重新連線後顯示儲存的結果，減少動態效果設定會略過動畫。
  • Social Stream 無法判斷 OBS 場景是否正在直播。

Event Flow

  1. 加入 抽獎／票券 操作（位於點數操作下）。
  2. 選擇操作：免費報名、買票、贈送免費票、關閉報名、抽中獎者、取消並退款、查詢狀態。
  3. 選擇抽獎 ID 和票數。獎池模式還需選正面或反面。
「購買票券」本身已經花費點數。 不要在前面放 Spend Points 操作。

它代表傳送訊息的觀眾操作。發放或主持控制前要放可信的觸發條件或篩選器。

Stream Deck 與 API

Stream Deck 外掛包含： 開放抽獎, 關閉抽獎, 抽出中獎者, 取消並退款, 新抽獎回合，以及 抽獎狀態.

  • 它們使用 default 抽獎。另一個抽獎需把 {"giveawayId":"friday"} 填入值欄位。Open giveaway 也接受 config 物件內。
  • 按鍵確認 Social Stream 已回覆，不代表 OBS 已顯示。逾時後先檢查狀態，再次抽獎。
透過 API 買票 
{"protocol":2,"action":"buygiveawaytickets","get":"callback-1","value":{"giveawayId":"friday","roundId":"ROUND_ID","operationId":"purchase-123","count":5,"actor":{"chatname":"Avery","type":"youtube","userid":"SOURCE_USER_ID"}}}
  • operationId 識別購買； get 識別回覆。
  • 重試保留相同操作 ID，新購買使用新 ID。
主持端 API 權限可花費任意觀眾的點數，切勿作為公開表單開放。

歷史與備份

管理抽獎和歷程記錄 顯示回合、報名及中獎者。你可以 匯出中獎歷史 （JSON），或儲存完整點數與抽獎備份。不會上傳任何內容。

重新啟動後， 原本開放的回合恢復為關閉，票仍被保留。可重新開放、抽獎，或取消並退還。

恢復備份

只適用於 全新主持端 ，其中沒有點數或抽獎。

  1. 保持舊主持端關閉，在新的瀏覽器設定檔中開啟 SSN 和抽獎管理員頁面。
  2. 位於 在全新主機上復原，選擇完整備份，等待提示並記下其中的工作階段 ID。
  3. 在彈出選單的 工作階段選項，輸入該工作階段 ID。
  4. 返回管理員頁面，選擇抽獎 ID 並點擊 重新整理。檢查規則、報名和中獎者。恢復的回合為關閉狀態。
  5. 重新開放、抽獎或 取消並退款。然後儲存新的備份。
切勿同時執行舊主持端和恢復後的主持端。 備份不含儲存後的變更，也不含彈出選單設定。
更多資料儲存位置說明
  • 點數儲存在此瀏覽器或應用程式設定檔中，不與其他地方同步。回合依工作階段儲存。
  • 清除瀏覽器資料可能將其刪除，請把備份保存在該設定檔之外。
  • 僅匯入餘額不能恢復保留中的票。票處於保留狀態時無法重設點數，重設也不會清除抽獎歷史。
  • 未確認的貼紙購買在逾時後解除保留。
  • 沒有雲端備份或提現。以後可能加入伺服器備份。

解決問題

問題試試這個
觀眾無法報名檢查 ID、關鍵字、僅限會員、是否開放報名和平台是否被擷取。機器人、私人、舊的、重播和測試訊息均不計入。
觀眾帳戶看起來不對改名可能影響錢包識別，請在主持端檢查。不同平台不會合併。
按鈕無回應確認正確的 SSN 主持端正在執行，並啟用主持控制。重試前重新整理。
無法重設或匯入點數先完成或取消保留中的購票。包含保留票的備份請使用完整復原。
!spend 提示 unknown reward需要預先設定帶價格的獎勵。
