直播商品與觀眾連結

選擇螢幕展示的商品，並給觀眾一個查看全部商品的連結。

新增商品 即時控制 觀眾連結 Stream Deck 與 Event Flow Remote API 解決問題

五步新增商品

  1. 開啟 Monetization → Products & support links → Set up products and links.
  2. 貼上公開的 https:// 連結並點擊 從連結載入詳情.
  3. 檢查標題、圖片、價格、幣別和 連結用途。價格留白，需要時自行填寫。
  4. 點選 新增商品或連結.
  5. 開啟 商品與支持連結 並點擊 儲存設定.
哪些連結會自動載入？ 公開的 Gumroad、itch.io、Ko-fi、Buy Me a Coffee 和 Fourthwall 頁面。其他連結可能需手動填寫。無需商店帳戶。完整匯入支援 Shopify 和 Fourthwall.

Shop、Gift、Support 和 Join 只是連結標籤，不改變付款統計。卡片是快照，真實價格和庫存以結帳頁面為準。

控制螢幕顯示內容

加入 商品與支持連結 覆蓋層至 OBS（商品展示與提醒 也顯示提醒）。然後使用以下按鈕：

按鈕功能
立即顯示 （在已儲存商品上）忽略排程，立即顯示該商品。
下一個商品顯示下一個已儲存商品。
隱藏商品隱藏商品卡片，但購買和禮物提醒仍顯示。
恢復排程恢復已儲存的輪換設定或首個商品固定顯示。

設定 顯示／隱藏秒數 。 0 表示保持到手動更改；1–3600 表示經過對應秒數後恢復排程。

實用說明
  • 即時修改會在 SSN 重新啟動時重設。
  • Stream Deck 中若儲存的商品不存在，會在按鍵上顯示該狀態，而非悄悄切換。
  • 未儲存商品會被標記，其 立即顯示 按鈕在點擊以下項目之前保持停用： 儲存設定.
  • 狀態顯示所選商品及剩餘秒數，無法判斷 OBS 是否直播或來源是否可見。
  • 商品依確切的已儲存連結定位，因此調整清單順序不會破壞自動化。

想在 OBS 內用按鈕？使用 OBS 商品控制停駐面板。不要把控制介面放到觀眾覆蓋層上。

給觀眾一個連結

  1. 開啟 Display options → Public viewer page.
  2. 點選 發布已儲存連結。這會公開所有已儲存商品的標題、圖片、價格和用途。
  3. 點選 複製觀眾連結 並分享。

商品 QR 碼指向這裡，商品離開螢幕後觀眾仍能找到。儲存和即時控制會更新同一連結。頁面每 15 秒重新整理，標記精選商品，即使卡片隱藏也列出全部商品。

找回相同連結從同一電腦重新發佈。
保留 SSN 設定檔。 其中儲存著更新或刪除頁面所需的私密金鑰。
SSN 離線或伺服器中斷時
  • SSN 關閉時，最後發佈的頁面仍保留，並顯示儲存時間。
  • 「Featured」表示最後儲存的選擇或輪換，不代表正在直播。
  • 伺服器中斷時，SSN 內控制仍可使用。SSN 開啟期間會重試更新，彈出選單顯示錯誤。
  • 發佈需要伺服器上的選用 public-shop 服務，不涉及商店或付款帳戶。

Stream Deck 與 Event Flow

Stream Deck

  1. 新增 預設命令 按鍵，來自 商品與支持：Show product、Next product、Hide products 或 Resume products。
  2. 對於 顯示商品，點選 重新整理商品和狀態 並選擇商品，也可貼上公開連結，或留白使用目前或首個商品。
  3. 對於 下一個 和 隱藏，可按需加入秒數。

選用的 商品狀態 按鍵顯示已選擇、已隱藏或已排程的狀態，每五秒更新，長名稱會縮短。按鍵使用現有 P2P 或 WebSocket 連線，並等待 SSN 確認。

Event Flow

  1. 加入 商品與支持 操作，位於覆蓋層操作群組。
  2. 選擇 Show、Next、Hide 或 Resume，可按需填寫確切的已儲存商品連結和秒數。
  3. 使用可控的觸發條件，例如管理員指令，而非每則聊天訊息。
這些操作只改變顯示內容。 不會建立捐款、購買、聊天發言或付款觸發器。

Remote API（進階）

工作階段遠端 API 接受 show, next, hide，或 resume. 主持人控制 必須開啟。省略 url ，以使用目前或首個商品。

{"action":"commerceControl","command":"show","url":"https://example.com/product","seconds":30}
切勿分享私人工作階段或控制連結。 向觀眾提供觀眾連結。
確認控制何時完成
  • 指令僅傳送現有的 monetization_update 顯示狀態。 hasDonation 行為不變。
  • Products & Support 操作等待 SSN 回覆後才繼續流程。
  • 在事件資料中， meta.commerceControlResult 包含 success ，再加上新的 commerce 狀態或一個 error.
  • 失敗會停止同一操作鏈後面的動作。原始購買或打賞仍會送達其他流程和覆蓋層。
  • 結果確認 SSN 的選擇、隱藏狀態或排程，不確認 OBS 是否正在顯示。
  • 八秒內無回應即逾時。控制可能已經生效，再按 Next 前先檢查彈出選單或控制面板。
  • 外部遠端用戶端應使用請求／回應協定並檢查結果，不能假設送出指令就已成功。
  • 其他操作回報自己的結果：Print Thermal Label 提供 meta.thermalPrintResult （送出工作不等於已列印）；同步 Webhook 操作可回傳 HTTP 狀態和回應，並在失敗時停止。這些是操作結果，不是新的付款事件。

請參閱 事件參考 ，查看完整結果格式。
