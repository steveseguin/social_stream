本機控制API和MCP

讓同一台電腦上的 AI 工具或指令碼檢查和控制 Social Stream Ninja 桌面應用程式。

何時選擇此服務

當 SSApp 電腦上的軟體需要獲准的應用程式和來源控制時，使用本機控制 API。當相容的 AI 用戶端需要將這些控制作為工具使用時，使用隨附的 MCP 轉接器。

這與下列功能不同： 檔案 > 啟用本機伺服器，後者會為 Social Stream 頁面啟動 WebSocket 轉送服務。參閱 本機伺服器和服務說明 ，協助你確定需要哪種服務。

1. 下載一般桌面應用程式

從下列位置安裝目前 Social Stream Ninja 版本： Windows、macOS 或 Linux 下載。下載的應用程式已包含 MCP 支援。無需原始碼儲存庫、Node、Python 或單獨的 MCP 套件。

2. 啟用本機 AI 控制

  1. 開啟 檔案 > 本機 AI / 自動化.
  2. 啟用 本機控制 API ，並讓應用程式重新啟動。
  3. 返回同一選單並選擇 複製 MCP 設定.
  4. 將複製的 JSON 貼到 AI 工具使用的 MCP 設定中，然後重新啟動該工具。

複製的設定包含實際安裝的執行檔路徑、連接埠和平台專用參數。AI 用戶端使用下列參數啟動下載的 Social Stream Ninja 執行檔時，它會啟動本身的輕量 MCP 轉接器： --ssapp-mcp.

3. 讓 MCP 自動探索能力

連線後，MCP 用戶端會自動向 Social Stream Ninja 查詢工具。轉接器讀取執行中應用程式的即時能力，並向 LLM 提供支援的工具結構、應用程式／API 版本和操作說明。代理應先呼叫 capabilities，再呼叫 status，並使用應用程式傳回的穩定來源 ID。

一般 MCP 使用無需擷取網站或安裝技能。使用者只需讓已連線的代理檢查或控制 Social Stream Ninja。

可用的本機控制

  • 列出、檢查、新增、更新和移除來源。
  • 啟動、停止或重新載入一個來源，或篩選出的一組來源。
  • 變更來源可見性、靜音狀態和連線模式。
  • 讀取和更新能力探索傳回的支援全域設定。
  • 讀取應用程式、工作階段、來源、程序、擷取和本機媒體狀態。
  • 追蹤有界的已擷取來源事件，以及可恢復的操作或狀態事件。
  • 擷取並安全檢查支援的來源頁面和 SSApp 自有視窗。
  • 經確認後，執行獲准的頁面、視窗和對話方塊互動。
  • 明確確認後，重新載入或正常關閉應用程式。

以執行中應用程式回報的能力為準。舊版本可能提供較少的控制項。

本機指令碼的直接 HTTP 存取

同一台電腦上的指令碼可不經 MCP 使用回送 API。它僅監聽 127.0.0.1 ，無需權杖。

GET http://127.0.0.1:17777/api/v1/capabilities
GET http://127.0.0.1:17777/api/v1/status
GET http://127.0.0.1:17777/api/v1/events
POST http://127.0.0.1:17777/api/v1/command

請使用應用程式公布的能力，不要假定所有版本都有相同控制項。可複製貼上的 curl 範例涵蓋新增、列出、啟動、檢查和停止來源，請參閱 伺服器 HTTP API 操作指南.

Ubuntu VPS 上的本機 AI

此 API 也可服務於與無頭 SSApp 執行個體執行在同一台 Linux 伺服器上的 AI 工具。請保持繫結至回送位址，並使用下載的 AppImage 作為 MCP 指令。

追蹤 以無頭模式執行 Social Stream Ninja ，瞭解 Xvfb、持久設定檔、啟動指令、systemd 和獨立的遠端控制路徑。其中還包含 Linux AppImage MCP 設定 ，可貼到 VPS 上執行的用戶端中。

選用的代理技能

支援可安裝技能的代理可以 下載完整的 Control Social Stream 技能。你也可以 線上閱讀其說明，其中包含 API 參考 和 版本記錄。該技能提供工作流程指引，但 MCP 連線本身不需要它。

機器可讀的探索連結也列在 llms.txt.

僅限本機

此介面供與 SSApp 執行在同一台電腦上的 AI 和自動化使用。不要將其暴露或透過通道用作雲端遠端控制 API。遠端使用者和 Stream Deck 應使用 Social Stream 現有的 WebRTC 或 WebSocket 連線。本機 API 不提供任意 JavaScript 執行、Cookie、登入機密、不受限的設定或原始檔案系統存取。

完整的端點、指令結構、版本探索和安全界線，請參閱 技術自動化參考.
