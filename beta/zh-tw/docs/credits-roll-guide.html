捲動致謝名單指南

收集參與直播的人，並在直播結束時用捲動致謝名單感謝他們。

結束場景的建議設定

使用 背景收集 ，適用於致謝名單瀏覽器來源僅存在於結束場景，或隱藏時可能被卸載的情況。應用程式或擴充功能會在直播期間收集活動，因此致謝名單頁面無需一直開啟。

  1. 保持 Social Stream Ninja 作用中，並讓正常的聊天來源在整個直播期間持續擷取。
  2. 開啟 捲動致謝名單 → 啟用並自訂.
  3. 選擇顯示樣式並設定 觸發模式 為 背景收集 ，請在直播開始前設定。
  4. 複製更新後的致謝名單連結，在 OBS 的結束場景中將其新增為瀏覽器來源。
  5. 使用 測試致謝名單 ，在瀏覽器來源已載入時確認連線和外觀。
  6. 直播結束時切換到結束場景，讓 OBS 載入或顯示致謝名單來源。
  7. 選擇 開始致謝名單，或觸發 creditsStart ，可透過 Stream Deck 或 API 觸發。
順序很重要： 如果 OBS 在瀏覽器來源隱藏時關閉它，請先顯示結束場景，再選擇 開始致謝名單。「背景」模式仍可收集，但來源必須已連線才能接收開始指令。

選擇正確的觸發模式

模式活動在哪裡收集捲動如何開始最適合的用途
自動在已載入的致謝名單頁面內當 OBS 或瀏覽器使頁面可見時自動開始來源在整個直播期間保持載入
手動在已載入的致謝名單頁面內開始按鈕、Stream Deck 或 API頁面保持載入，但你希望精確控制開始時間
背景收集在 Social Stream 應用程式或擴充功能內開始按鈕、Stream Deck 或 API獨立的結束場景，或直播期間關閉／卸載的來源
在直播前設定模式。 「自動／手動」頁面資料與「背景收集」資料彼此獨立。直播中途切換模式，不會轉移另一種模式已經收集的名字。

四個控制項的作用

控制結果
開始致謝名單播放實際收集的名單。在「自動／手動」模式下，除非啟用了儲存或循環，否則捲動結束時會移除已顯示的項目。捲動期間收到的新活動會保留至下一次播放。背景資料會一直保留，直到重設。
預覽播放目前的真實名單，但不消耗它。可在正式開播前檢查版面配置。
測試致謝名單傳送內建的參與者、會員和贊助者範例。不會新增、取代或清除真實的已儲存名單。
重設已儲存的致謝名單清除已儲存的背景名單，並通知已連線的致謝名單頁面清除其本機名單。

如果 測試致謝名單 提示沒有連接致謝名單來源時，請載入或顯示 OBS 瀏覽器來源後重試。

誰會出現在名單中

致謝名單可識別擷取到的聊天參與者、會員／訂閱和贊助類活動。每個人都需要有帶名字和平台類型的擷取事件；Social Stream 無法列出平台從未回報的沉默觀眾。

  • 參與者： 擷取到訊息或帶名字的活動事件。
  • 會員／訂閱者： 擷取到會員欄位，或支援的訂閱／會員事件。
  • 贊助者： 擷取到帶有贊助值的項目。支援的幣別金額會標準化，用於排序和選用的金額顯示。TikTok 連擊更新只計算同一次連擊內的增量。價格未知的禮物仍會將贈送者列為贊助者，但不會加入猜測的美元金額。TikTok 金幣／鑽石換算屬於估算，不保證實際入帳金額。
  • 身分： 同一個顯示名稱在兩個不同平台上會被視為兩個來源身分。

預設排名規則中，每次擷取到的活動加 1 分，會員加 50 分，標準化後的贊助金額每美元加 100 分。名單分為 VIP 支持者、一般支持者和直播參與者。啟用 優先顯示贊助者 ，即可改用更清楚的「直播贊助者」、「頻道會員」和「直播參與者」分組。

快速設定、篩選器與已儲存資料

  • 循環支持者名單： 會啟用循環、儲存疊加畫面資料、僅支持者篩選、贊助優先和贊助金額顯示。
  • 僅贊助者： 會啟用循環、儲存疊加畫面資料、僅贊助者篩選和贊助金額顯示。
  • 僅包含支持者： 包含贊助者和已識別的會員／訂閱者，但不包含僅參與聊天的人。
  • 僅包含贊助者： 要求擷取到贊助訊號。
  • 在此疊加畫面中儲存致謝名單： 會在重新整理和來源切換時保留「自動／手動」的頁面收集資料，並防止完成一次「開始」播放後消耗名單。
  • 持續循環致謝名單： 會重新開始動畫，並在下一次循環中加入新收集的活動。
背景收集的資料已由應用程式／擴充功能針對目前工作階段儲存。關閉致謝名單頁面後仍會保留，直到使用 重設已儲存的致謝名單 。

OBS 設定詳細資料

  1. 先完成致謝名單選項設定，再複製 URL，以包含所選 URL 參數。
  2. 將該 URL 新增為 OBS 瀏覽器來源。一般的 1920 × 1080 尺寸適合全螢幕樣式。
  3. 使用「自動」或「手動」時，保持來源在整個直播期間載入。在每個場景中重複使用同一個 OBS 來源，比建立互不相關的副本更穩妥。
  4. 使用「背景收集」時，來源可以在直播期間不存在或未載入。只需在傳送「開始」、「預覽」或「測試」前連線即可。
  5. 正式開播前，使用「預覽」或「測試」檢查字體大小、速度、類別、透明度和結束語。
OBS 選項： 「不可見時關閉來源」會停止「自動／手動」收集，因為它們的收集器在頁面中執行。此選項與「背景收集」相容，只要在傳送開始指令前先顯示來源即可。

Stream Deck 與 API 控制

官方 Stream Deck 外掛提供致謝名單的「開始」、「預覽」、「測試」和「重設」動作。同樣的指令也可透過 Social Stream 的遠端控制 API 使用：

操作HTTP 範例
creditsStarthttps://io.socialstream.ninja/SESSION_ID/creditsStart
creditsPreviewhttps://io.socialstream.ninja/SESSION_ID/creditsPreview
creditsTesthttps://io.socialstream.ninja/SESSION_ID/creditsTest
creditsResethttps://io.socialstream.ninja/SESSION_ID/creditsReset

替換 SESSION_ID 為目前作用中的 Social Stream 工作階段。啟用 擴充功能的遠端 API 控制 ，位於「全域設定 → 機制」。致謝名單瀏覽器來源必須已連線，「開始」、「預覽」或「測試」才能顯示在畫面上。

常見問題

  • 測試正常，但真實名單為空： 測試項目是內建的，不能證明已經收集到活動。確認直播前已選擇預期的觸發模式，並且聊天來源正在擷取。
  • 重新開啟設定後沒有控制項： 「手動」和「背景」模式會顯示「開始」和「預覽」。「自動」模式則透過可見性觸發。
  • 沒有連接致謝名單來源： 載入／顯示 OBS 來源，確認使用的是目前複製的 URL 和工作階段，然後重試。
  • 缺少聊天參與者： 「自動／手動」要求致謝名單頁面一直保持載入。獨立的結束場景請使用「背景收集」。
  • 缺少會員或贊助者： 確認平台來源發出了帶名字的會員或贊助事件，並且沒有被「僅贊助者／僅支持者」排除。
  • 一次捲動播放結束後名字消失： 啟用 在此疊加畫面中儲存致謝名單，使用「預覽」，或使用「背景」模式。對於由頁面收集的名單，若未啟用儲存和循環，正常的「開始」執行會消耗已顯示項目。
  • 舊名字仍然保留： 選擇 重設已儲存的致謝名單 ，在下一場直播前執行。背景資料按 Social Stream 工作階段儲存，直到重設。
