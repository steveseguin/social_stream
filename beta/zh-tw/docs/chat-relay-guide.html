在平台之間轉送聊天

有計畫地設定 Twitch 和 YouTube 聊天轉送，選擇傳送帳號，並排查訊息重複問題。

所有指南 1. 確認兩個聊天室都能接收回覆 2. 在 Event Flow 中建立 Twitch → YouTube 轉送 3. 新增反向轉送 4. 瞭解回流訊息 5. 縮小轉送範圍 疑難排解

1. 確認兩個聊天室都能接收回覆

將 Twitch 和 YouTube Live 聊天室連接到同一個 SSN 工作階段。確認兩者都出現在停駐面板中，然後分別選取來源分頁已知的訊息，手動回覆一次。請使用自己的測試頻道。唯讀的擷取來源無法傳送轉送訊息。

此設定中只應開啟預期的目的地聊天室。同一平台的目的地可能包含該平台上多個符合條件的來源分頁。如果使用獨立的 Twitch 機器人帳號，請先完成 用於回覆的機器人帳號 。

2. 在 Event Flow 中建立 Twitch → YouTube 轉送

開啟 Event Flow 編輯器 ，可從 SSN 選單進入（「Actions 疊加畫面」區域也有連結）。建立一個流程，並賦予清楚的名稱，例如 Twitch 轉 YouTube.

  1. 新增一個 來自來源（From Source） 觸發器，位於 使用者與來源。選擇 Twitch 作為來源。
  2. 新增一個 轉送聊天（Relay Chat） 動作，並將觸發器輸出連接到該動作的輸入。
  3. 選擇該動作。將以下選項設為 轉送目的地 為 YouTube，並將訊息範本保持為 [{source}] {username}: {message}.
  4. 選擇 儲存流程 並啟用已儲存的流程。保持 SSN 執行。
  5. 在自己的 Twitch 測試聊天室傳送一則新的普通訊息。確認 YouTube 收到一份帶標籤的副本。

YouTube Shorts 有獨立的來源類型和目的地。請按需選擇 YouTube Shorts ；它與 YouTube 不能互換。

3. 新增反向轉送

建立第二個流程，命名為 YouTube 轉 Twitch: From Source: YouTube → Relay Chat: Twitch。儲存並啟用。從兩端各傳送一則新訊息，確認每則訊息都只在另一平台出現一份副本。

保持 轉送所有訊息（不建議！） 關閉，以免另一個轉送系統重複執行相同動作。也請檢查是否已有其他機器人或多平台直播服務在連接這些聊天室。

4. 瞭解回流訊息

回流訊息是指 SSN 傳送後，又從目的地聊天室擷取到的訊息。目前的 Relay Chat 動作會自動略過已識別的回流訊息，也會排除原始來源分頁。

如需在停駐面板和疊加畫面中隱藏擷取到的回流訊息，請新增一個 回流篩選器（Reflection Filter） 動作，放在相關流程的前段，並選擇 全部封鎖. 允許第一則 會在設定的時間範圍內保留一則符合的回流訊息； 全部允許 會顯示它們。此設定控制擷取後的顯示，不決定轉送目的地。

目前 Relay Chat 的屬性中沒有「No Reflections」核取方塊。請使用獨立的 Reflection Filter 控制顯示。如果外部服務改寫了轉送訊息，自動識別可能無法捕捉到它。

5. 縮小轉送範圍

如需篩選指令，請新增一個 訊息開頭符合（Message Starts With） 觸發器，設為 ! ，將其連接到一個 非（NOT） 邏輯閘；再使用以下邏輯閘將結果與來源條件組合： 且（AND） ，放在 Relay Chat 之前。有關連接邏輯閘的說明，請參閱 Event Flow 指南 。請分別測試普通訊息和指令。

如果改用較簡單的全域轉送，請使用 全域設定與工具 → 指令 → 選擇轉送目的地 並輸入 twitch,youtube。清單留空表示所有符合條件的目的地。此清單控制接收目的地，不限制哪些傳入平台可以觸發轉送。啟用此替代方案前，請先停用 Event Flow 中的雙向轉送。

SSApp 在同一「指令」區域提供帳號角色允許／封鎖欄位，可限制哪些帳號傳送轉送訊息。請使用分配給預期傳送帳號的角色；角色不符可能導致沒有符合條件的目的地。

疑難排解

  • 沒有傳送任何訊息： 重試手動回覆，驗證登入狀態和發言權限，啟用已儲存的流程，並檢查目的地和帳號角色限制。
  • 訊息不斷增多： 先停用轉送流程。檢查重複的擷取來源、全域「轉送所有訊息」和外部轉送機器人，然後再單向重試。
  • 只有停駐面板顯示重複訊息： 檢查 Reflection Filter 的顯示策略，以及全域「訊息 - 可見性」中的回流顯示設定。
  • YouTube 目的地不正確： 檢查 YouTube 與 YouTube Shorts 的選擇，並關閉不需要的、符合轉送條件的聊天室。

Test Flow 動作可以傳送真實訊息。請使用受控的目的地；模擬測試無法證明實際來源的帳號路由正確。
