Build a classic stream bar

Three overlays combine into a familiar stream layout: a fundraising bar along the top, recent events in a corner and running totals along the bottom. Each one is its own Browser Source, so you can use any of them alone.

PieceWhere to turn it onWhat it shows
Fundraiser Banner贊助罐和目標進度條: set Display Style to Fundraiser Banner.A flat bar with the goal title, amount raised and goal on one line. Size the source to about 900 × 40. 預覽

The strip counts donations, subs, bits and follows from the events it receives while it is running, so it does not include anything from before it was added to your scene. Stats, counters and the subathon use the dock feed. To count subscription and follow events, leave 從擴充座中排除警報事件 off. Totals are saved in the browser showing it and survive a refresh. They clear at midnight, or set Reset totals 為 Only with the reset button and use Reset stream stats in the popup. A gifted sub counts once for each sub in the gift, and resubs count as subs. Biggest donation compares USD values and shows the amount as the viewer sent it, so large Bits cheers can take the top spot. Test events you send count too, so reset before going live.

On the banner, fillstart, trackcolor, bartextcolor, barheight 和 bartextsize change its look.

Show the latest and top supporters

The Meta Data Bar's Stats to show also has presets for the labels you see on many channels: the latest follower, sub, tip and Bits, the top gifter and top Bits of the day, and your total subs and followers. Each one fills in from events as they arrive. Before the first event, a label shows a dash.

To choose your own set, edit stats= in the link: latestfollow, latestsub, latesttip, latestbits, latestraid, topgifter, topbits, totalsubs 和 totalfollows work alongside the keys above, and latestfollowlabel=Newest renames one. Latest values and totals carry over midnight; the top lists start again each day. Total subs and followers need a source that reports them, such as Twitch EventSub. 預覽

Count deaths, wins or anything else

In the Meta Data Bar, list each counter as Name|!command, separated by commas, for example Deaths|!death,Wins|!win. Moderators, the host and admins change them from chat. On YouTube, your own channel is not marked as a moderator, so add your name under "Identify the hosts' name" in SSN. Anyone else's message is ignored unless you turn on Allow viewer adds. That lets each viewer add 1 every five seconds; only moderators can set or reset a count.

Type this會發生什麼
!deathAdds one.
!death +3 或 !death -1Adds or removes that many.
!death =10Sets the count.
!death resetBack to zero.

Add rules to let support raise a counter on its own. Owed Pushups|!pushup|sub:15|gift:15 adds 15 for each sub and each gifted sub. You can also use bits (per 100 Bits), tip (per $1) and follow. Counters are saved in the browser showing them and only reset when you ask, and Reset stream stats leaves them alone. 預覽

Run a subathon timer

In the Meta Data Bar, set a Starting time such as 6h, then the minutes each sub, 100 Bits, $1, follow and raid adds. For tiers, list three values: 6,15,40。開啟 Show rules to display them, and set a longest time to limit what support can add. Moderators can still go past it. Time for follows can be farmed by unfollowing and refollowing, so leave that at 0 unless you trust your chat. The Cards style gives a large clock.

The clock waits for you. Press Start in the popup, or have a moderator type !subathon start. Moderators can also use pause, add 30m, remove 10m, set 6h 和 reset. On YouTube, your own channel is not marked as a moderator, so use the popup buttons or add your name under "Identify the hosts' name" in SSN. It keeps running through a refresh, and Reset stream stats does not touch it. Once it reaches zero, new support no longer extends it, but a moderator can use add to bring it back. Support only adds time while the overlay is open, so keep the source active during the event. 預覽

歷史和控制

啟用 刷新後記住可見事件 当其浏览器源重新加载时保持面板填充。历史记录是该浏览器、会话和板名称的本地记录； OBS和你的普通浏览器有单独的存储。保留设置范围为 1 至 168 小时。恢复的行使用当前过滤器，不会重播声音或触发自动化。在多重警报中，此选项需要堆叠。

賦予不同的場景不同的 董事會名稱。彈出指令針對對應的板名稱和表面。發送到斷開連接的覆蓋層的命令不是保存的狀態變更。暫停將新到達的事件保存在最多 500 個事件的堆疊和提要緩衝區中；簡歷顯示它們。如果該緩衝區已滿，則其最早的等待事件將被取代。單一警報模式使用其配置的佇列限制。

插銷 切换最新卡的密码；固定的卡片占据可见的插槽。如果每个插槽都已固定，请取消固定卡以接纳新事件。 移除 刪除最新的卡。 清除 刪除可見事件、等待事件和該板的已儲存歷史記錄。多重警報還提供跳過、靜音、取消靜音和重播功能。重播是顯示操作，而不是新的捐贈或事件流觸發器。

對於私人事件儀表板，啟用 顯示操作員按鈕 固定或删除单独的行。在受众浏览器源中关闭此选项。

連接您想要顯示的事件

两个叠加层都使用您的 SSN 源提供的事件。覆盖样式不会添加平台权限或新的事件订阅。

來源設定和事件報道
Twitch使用 Twitch EventSub 對於您的帳戶有權存取的關注、訂閱、禮物、歡呼和突襲。僅聊天捕獲不會取代 EventSub。
Facebook標準 Facebook 捕獲可以將可見的星星捐款轉化為付費支援行。 Facebook API 聊天捕獲不提供星星數量。對於追蹤者和支持者訂閱，請使用將這些通知傳送至 SSN 的事件提供者； Facebook 聊天擷取本身並不能提供這些功能。
YouTube会员资格、礼物、Super Chats、Super Stickers 和珠宝取决于所选的捕获模式。公共订阅者通知需要其 API 路径。參見 事件相容性.
Kick 和 TikTok使用可用的支援活動的來源進行關注、訂閱或贈送禮物。選擇您要顯示的事件類別；喜歡和加入可以隱藏。
Streamlabs 和 StreamElementsSSN 可以擷取現有的提供者事件來源。連線 SSN 中的提供者並保持其來源處於活動狀態。可用事件取決於提供者連線和來源模式。您可以使用SSN的顯示器，同時保留事件或提示的提供者。
其他 SSN 来源捐贈金額和認可的關注、會員資格、禮物和攻擊事件可以使用相同的顯示。參見 事件參考 對於特定於來源的欄位和支援的操作。

如果缺少真實事件，請先檢查它是否出現在 SSN 的活動來源中。檢查來源連接和事件權限（如果不存在）；檢查覆蓋過濾器和最小數量（如果存在）。

取自 Streamlabs 或 StreamElements

對於 Streamlabs 事件清單的始終可見行為，請使用 顯示多個警報 + 保持警報直至更換 在多重警報中，或在事件中預設的受眾。 可見警報/最大事件 設定計數。歷史記錄選項可在同一瀏覽器中恢復最近可見的卡片。使用類別篩選器和最小值控制項來選擇顯示的支援。

您可以將 SSN 的連結直接加入為 OBS 或 Streamlabs Desktop 中的瀏覽器來源。它不需要 SSN 操作員底座。使用圖庫中的 SSN 樣式，然後調整顏色和間距以適合您的場景。
