讓聊天進入疊加畫面

Lite 從瀏覽器或 OBS 連接支援的聊天來源。使用一般疊加畫面連結時，保持 Lite 在分頁或 OBS 停駐面板中執行。實驗性的獨立 OBS 模式在一個瀏覽器來源中擷取並顯示聊天。

設定 · 僅 OBS 設定 · 來源 · 現有設定 · 疑難排解

1. 設定疊加畫面

  1. 開啟 Lite。工作階段 ID 和疊加畫面 URL 會自動產生，並由此瀏覽器記住。
  2. 連接下列某個來源。使用其 選項 按鈕來設定頻道。
  3. 選擇 複製連結（Copy link）。在 OBS 中新增一個 瀏覽器 來源，並將連結貼到其 URL 欄位。您也可以使用 開啟停駐面板疊加畫面（Open dock overlay） 在瀏覽器中檢查它。
  4. 選擇 傳送測試訊息（Send test message） 在 Lite 中。確認它出現在已開啟的疊加畫面中。訊息僅出現在 Lite 的 Activity 動態中，並不能確認疊加畫面已收到。

如需透明疊加畫面或不同的訊息順序，請開啟以下內容旁邊的選項： 聊天疊加畫面連結（Chat Overlay Link）。變更這些選項後，將更新的 URL 複製至 OBS。

2. 選擇來源

僅使用 OBS 時，請選擇下列兩種工作流程之一。如果擷取在 OBS 中執行，就不需要單獨的桌面瀏覽器分頁。

來源操作方法
YouTube使用 YouTube 登入。Lite 會尋找您的直播。在 Options 中，可以提供 Video ID 或 Live Chat ID 來指定某場直播。預設使用輪詢；可選的串流 API 標記為 Beta。直播必須有可用的即時聊天。
Twitch使用 Twitch 登入。Lite 預設使用您自己的頻道；可在 Options 中設定其他頻道。如果授權過期，請重新登入。
Kick在 Options 中輸入頻道名稱並連接。如果自動查詢失敗，請檢查頻道拼字，然後視需要使用手動聊天室設定。
TikTok此整合目前在標準 Lite 面板中隱藏。它需要相容的 TikTok Chat Reader Proxy；預填位址不保證服務可用。請使用完整應用程式查看可用的 TikTok 擷取選項。

中斷連線 會停止該來源。對於 YouTube 和 Twitch，它會保留登入狀態，讓您可以使用 連接 ，再次操作。 登出（Sign out） 會移除此瀏覽器中儲存的授權。

3. 使用現有 Social Stream 設定

如需向現有停駐面板或疊加畫面提供資料，請開啟 Lite 中的工作階段選項並輸入其工作階段 ID。選擇 儲存工作階段 ID（Save session ID） 或按 Enter。變更 ID 會切換 Lite 傳送訊息的位置；請更新所有應隨之切換的瀏覽器來源 URL。

同一工作階段中，每個頻道僅使用一種擷取方式。同時執行 Lite 和針對相同聊天的擴充功能或桌面擷取可能產生重複訊息。您可以用 Lite 擷取一個頻道，用完整應用程式擷取其他來源。

Lite 產生的連結使用預設工作階段密碼。受密碼保護或使用自訂伺服器的設定可能需要完整應用程式的連接控制項。Lite 不取代完整應用程式的擷取、自動化、管理或疊加畫面自訂控制項。

Activity 的 僅贊助 和 文字轉語音 控制項適用於 Lite 活動檢視。使用其活動彈出視窗時，保持 Lite 主頁面開啟。如果不希望他人加入該工作階段，請將疊加畫面 URL 保密。

完全在 OBS 內執行

選項 A：Lite 停駐面板 + 一般疊加畫面

  1. 開啟 完全在 OBS 內執行 在 Lite 中，並複製 OBS 自訂停駐面板 URL (lite/index.html?view=dock).
  2. 將其新增至 OBS 的 自訂瀏覽器停駐面板。在該停駐面板中登入並設定來源。Source Options 和工作階段設定仍可在那裡存取。
  3. 將停駐面板的一般疊加畫面 URL 複製至 OBS 瀏覽器來源。擷取時保持 Lite 停駐面板載入。該來源只顯示訊息，因此無需單獨登入提供者。

這是最簡單的僅 OBS 工作流程：在停駐面板中擷取，在瀏覽器來源中顯示。關閉停駐面板會停止其擷取。設定完成後不需要桌面瀏覽器。

選項 B：單一擷取與疊加畫面瀏覽器來源（實驗性）

  1. 加入 獨立擷取 + 疊加畫面 URL (lite/index.html?view=overlay）作為 OBS 瀏覽器來源。
  2. 開啟 互動（Interact） 以設定來源。如果已經設定，按 Escape 在 Interact 中按此鍵，以重新開啟設定。登入頁面和設定控制項在此來源中可見，因此請在非直播狀態下設定。
  3. 選擇 顯示疊加畫面（Show overlay）。頁面現在會在透明背景上顯示自己接收的聊天。它不需要另一個 Lite 分頁、停駐面板或轉送連接，也不會向其他工作階段疊加畫面提供資料。
  4. 將 不可見時關閉來源（Shutdown source when not visible） 和 場景啟用時重新整理瀏覽器來源（Refresh browser source when scene becomes active） 關閉，以避免切換場景時中斷擷取。請參閱 OBS 瀏覽器來源屬性.

已儲存的有效 YouTube/Twitch 憑證會在啟動時重新連接。對於 Kick，請啟用 在 OBS 模式下自動重新連接此 Kick 頻道 在其 Options 中。先設定頻道。TikTok 仍保持隱藏。版面配置初始顯示所有訊息並關閉語音，獨立於一般活動檢視中儲存的偏好。

OBS 停駐面板、OBS 瀏覽器來源和桌面瀏覽器可能使用不同的 Cookie/儲存設定檔。不要假定設定停駐面板就會讓獨立瀏覽器來源完成登入。如果無法在 OBS 瀏覽器來源中完成登入，請使用選項 A。原生 OBS 提供者驗證仍需要實際驗證；此模式為實驗性功能。

每個頻道僅使用一個擷取位置。不要讓停駐面板與獨立擷取加疊加畫面來源同時擷取相同頻道。在不同場景重用同一擷取來源時，使用 OBS 的現有來源選項。

疑難排解

疊加畫面是空白的
檢查 Lite 是否仍開啟，以及疊加畫面是否使用相同工作階段 ID。傳送測試訊息。如果測試訊息抵達但直播聊天沒有抵達，請檢查來源狀態和頻道。如果兩者都未抵達，請檢查疊加畫面 URL，以及網路是否封鎖轉送連接。
複製連結遭封鎖
點擊可見的疊加畫面 URL，然後使用鍵盤或裝置的複製選單複製所選文字。
來源閒置或顯示錯誤
檢查其 Options 和錯誤文字。修正設定後重新連接。如果授權已過期，YouTube 和 Twitch 可能需要重新登入。
我看到重複訊息
檢查是否有第二個 Lite 分頁、擴充功能擷取或桌面擷取正在擷取相同頻道和工作階段。僅保留預期的擷取執行。
設定消失了
設定儲存在此瀏覽器的本機儲存空間中。不同瀏覽器、私密視窗或清除網站資料後會使用不同的設定。
