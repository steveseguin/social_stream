ローカルサーバーとサービスの説明

Social Stream Ninjaは、いくつかの異なるローカルサービスを使用します。やりたいことに合うものを選んでください。

1. Enable Local Server

Fileメニューのこのオプションは、デスクトップアプリ内で、ルームとチャンネルを識別するWebSocketリレーを開始します。対応するSocial Streamのページは、同じコンピューター上でチャットやコマンドを交換できます。ページごとのサーバールーティングに使う、別の接続先です。

Social StreamのWebサイトをホストしたり、単独でプラットフォームを取得したり、HTTP自動化APIを提供したりするものではありません。まず次を参照してください： Enable Local Serverのガイド.

2. ローカル制御APIとMCP

任意で有効にするこのループバックAPIにより、SSAppと同じコンピューター上のプログラムが、対応するソースと設定の管理、状態と診断の読み取り、アプリやソースウィンドウの確認、取得イベントの受信を行えます。同梱のMCPアダプターは、これらの操作を対応するAIクライアントにツールとして提供します。

有効にする場所： ファイル > ローカルAI / 自動化（File > Local AI / Automation）で有効にします。これは次とは別です： ローカルサーバーを有効化（Enable Local Server）。参照先： ローカル制御APIとMCPのガイド.

3. ヘッドレスのホームサーバーまたはVPS

ヘッドレスモードは、ソースウィンドウを非表示にして、完全なElectronデスクトップアプリを実行します。Linuxでは、引き続きXvfbなどのディスプレイ基盤が必要です。モニターをつながず、専用コンピューターでチャットを取得し続けたい場合に便利です。

ヘッドレスモードは公開の制御APIを作成しません。リモート操作は、Social Streamの通常のWebRTCまたはWebSocket通信を使用します。参照： ヘッドレスホスティングのガイド.

4. ローカルメディアサーバー

ローカルのEvent Flowメディアが利用可能になると、デスクトップアプリが自動で起動します。SSAppで承認したファイルと、選択された実行時アセットだけを、プロファイルごとにランダムなトークンのパスから配信します。

汎用のWebサーバーやファイルサーバーではありません。参照： Event Flow用のメディアファイル で、ローカルファイル、アップロード、クラウドホスティングのどれを使うか選べます。

サーバーによる代替経路は別の機能

次のような設定： チャットメッセージをAPIサーバーに送信（Send chat messages to API server） および ドックのコマンドをサーバー経由で拡張機能に送信（Dock sends its commands to Extension via server） で、チャットとコマンドの経路を選びます。生成されるURLフラグには次が含まれます： server, server2、および server3.

通常、これらの設定はSocial Streamのホスト型WebSocketサービスを使用します。対応するページに次もある場合： localserverがある場合、代わりにデスクトップアプリのローカルリレーを使用します。参照： セッション、パスワード、リレー、サーバーモード でルーティングの設定を確認できます。

新しく生成したリンクを使用してください。 ルーティングのフラグはページごとに異なります。あるページのserverフラグを別のページへコピーし、同じ意味だと考えないでください。

その他の一時的なローカルポート

一部のサインインやアカウント連携では、一時的にループバックのコールバックポートを開き、処理の終了時に閉じます。これらの一時的な待ち受けは、汎用のSSNサーバーや自動化APIではありません。
