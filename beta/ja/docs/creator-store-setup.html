Fourthwall、Ko-fi、Buy Me a Coffeeのアラートと、QRコード付きの商品を表示します。

アラートを接続 Fourthwall Ko-fi Buy Me a Coffee 商品をインポート 配信に表示する 問題を解決する

5つの手順でアラートを接続する

  1. 開く項目： 収益化 → Fourthwall・Ko-fi・Buy Me a Coffeeのアラート（Monetization → Fourthwall, Ko-fi & Buy Me a Coffee alerts） で、自分の次の項目を選びます： プロバイダー.
  2. クリックする項目： 受信機の設定 で、次を有効にします： 拡張機能のリモートAPI制御（remote API control of extension）.
  3. Monetizationに戻り、次をクリックします： Webhook URLをコピー.
  4. プロバイダーのWebhook設定へ貼り付けます（手順は下記）。
  5. Social Stream Ninjaを動かしたままにします。
動いていますか？ 「Receiver connected」はSSNが受信待機中という意味だけです。最新イベントの行は実際のイベントが届くと更新され、再起動時にリセットされます。
Webhook URLは公開しないでください。 このURLだけがアラートを保護します（署名用シークレットは確認しません）。アラートには使えますが、商品の発送に使う支払い証明にはしないでください。公開したりQRコードに入れたりしないでください。

アラートのサンプルをプレビュー は見た目の確認だけです。合計、Event Flow、Webhookには影響しません。

NinjaBacker、Throne、Amazon、eBayについては、次をご覧ください： 収益化ガイド。Shopifyについては、次を参照してください： Shopifyの設定.

Fourthwall

  1. Fourthwallで次を開きます： 設定 → 開発者向け → Webhook（Settings → For Developers → Webhooks）.
  2. Webhookを作成し、SSNのFourthwall用URLを貼り付けます。
  3. 必要なイベントを選択します（表を参照）。
  4. 保存し、SSNを動かしたままにします。
Fourthwallイベント表示される形式
ORDER_PLACED購入です。従来の設定に合わせ、寄付の値も引き続き加算します。
GIFT_PURCHASEギフトです。
DONATION寄付です。
SUBSCRIPTION_PURCHASED新しいメンバーシップです。

ギフトカード注文の金額を二重加算しません。テストイベントは無視します。

Ko-fi

  1. 開く項目： Ko-fi Webhooks.
  2. SSNのKo-fi用URLを次へ貼り付けます： Webhook URL を選んで保存します。
  3. SSNを動かしたままにします。

公開のチップ、メンバーシップ、ショップ注文、依頼はこの1つのリンクを使います。非公開の支払いは除外します。ショップ注文と依頼は購入として表示され、寄付合計には加算しません。Ko-fiは解約されたメンバーシップを通知しません。

SSNのプレビューで試してください。 Ko-fiのテスト決済は本物と同じに見え、アラート、合計、自動処理を動かすことがあります。有料特典が有効な間は使わないでください。

Buy Me a Coffee

  1. クリエイターの管理画面で次を開きます： 連携（Integrations） を開き、次を選択します： 新しいWebhook（New webhook）.
  2. 名前を付け、SSNのBuy Me a Coffee用URLを貼り付けます。
  3. 必要なイベントを選択します（表を参照）。
  4. 保存し、配信を有効にしたままにします。失敗した場合はその画面の配信履歴を確認してください。
イベント表示される形式
donation.created寄付です。
extra_purchase.created購入です。
commission_order.created購入です。
wishlist_payment.createdギフトへの出資です。
membership.started新しいメンバーシップのお知らせです（別の請求ではありません）。

非公開メモや匿名の支援者は公開しません。管理画面のテスト（live_mode: false）は無視されます。返金で合計は減りません。

Fourthwallの商品をインポート

  1. Fourthwallで次を開きます： 設定 → 開発者向け（Settings → For Developers） で、次を作成します： Storefrontトークン。管理者用APIキーは使わないでください。
  2. SSNで次を開きます： 商品とサポートのリンク → 商品とリンクを設定 → Fourthwallの商品をインポート（Products & support links → Set up products and links → Import a Fourthwall product）.
  3. 商品の公開リンクとトークンを貼り付け、次をクリックします： 商品情報を読み込む（Load product details）.
  4. 名前、画像、価格、リンクを確認します。リンクはトークンと同じショップのものを使ってください。
  5. 目的を選びます：Shop、Gift、Support、Join。
  6. クリックする項目： 商品またはリンクを追加（Add product or link）で、次を有効にします： 商品とサポートのリンク（Products & support links）を選び、次をクリックします： 設定を保存（Save setup）.
取り込みで行うこと
  • 公開され販売可能な商品を1回に1つ読み込みます。
  • トークンで検索対象のショップが決まります。一度使うと消去され、保存もオーバーレイへの送信もされません。
  • バリエーションやセットで価格が異なる場合、価格欄は空欄になります。
  • 取り込み時点の情報です。価格、在庫、画像は自動更新されないため、変更時は再取り込みするか編集してください。
  • 最大20商品を保存できます。同じ商品をもう一度追加すると、別のコピーができます。

商品とQRコードを配信に表示する

Shopify、Tiltify、Patreonなどの公開リンクを手動で追加することもできます。その操作だけでは決済アラートは接続されません。

  1. 次のセクションで： 対象のOBSオーバーレイ：で、次を選択します： 商品とサポートのリンク（Products & support links）.
  2. 開く項目： オーバーレイリンクの設定 で、次を選びます： オーバーレイの表示形式：Product showcase only、Support card only、Activity alerts only、またはShowcase and alerts。
  3. クリックする項目： OBSリンクをコピー をOBSに次のソースとして追加します： ブラウザソース。まず800 × 600で試してください。表示ごとにソースを1つ使います。
  4. 次の場所で： 表示オプションで最初の商品を固定するか順番に切り替え、次を有効にします： QRコードを表示.
  5. 最終的なOBSのレイアウトを表示し、スマートフォンでQRコードを読み取ってください。
QRコードを読み取れませんか？ オーバーレイを縮めすぎたり切り抜きすぎたりしないでください。チャットでリンクを共有するには、次をクリックします： 公開リンクをコピー.
アラート、multi-alerts、Event Flow
  • ショーケースは商品画像を表示します。小型のサポートカードには表示しません。
  • アクティビティのアラートは単独で動き、無関係な商品のQRコードを表示しません。
  • Multi-alertsとアクティビティフィードは、商品一覧なしでも同じセッションで動きます。Monetizationのアクティビティ表示には商品一覧を有効にする必要があります。
  • Event FlowのDonationトリガーは、引き続き次を含む行に対応します： hasDonation。購入や完了したギフトにはEvent Typeを使います。参照： イベントの対応表.

配信中の商品切り替えや、視聴者向けリンクを1つ共有する方法： 配信中の商品操作.

何も表示されない場合

問題試すこと
受信機能がオフオンにする項目： 拡張機能のリモートAPI制御（remote API control of extension）。ほかのAPIスイッチは別の機能です。
切断中SSNを有効にしたまま、ネット接続を確認してください。これはSSNの接続状態で、プロバイダー側の状態ではありません。
イベントが届かない選んだプロバイダー、URL、プロバイダーのWebhook設定を確認します。
イベントが無視されたテスト、非公開決済、非対応イベント、不正な金額は除外されます。
イベントは届いたがオーバーレイに表示されないセッション、パスワード、フィルター、SSNのルール、OBSソースの表示状態を確認してください。大半の購入は寄付ではありません。
アラートが二重に出る同じ支払いをプロバイダーと別のサービスの両方から送らないでください。
取り込みに失敗した商品のリンク、Storefrontトークン、商品が公開され販売可能かを確認します。手動入力もできます。

これはライブのアラート用フィードで、注文記録ではありません。決済、返金、発送はプロバイダーの管理画面を使ってください。TiltifyとPatreonのアラートはまだ対応していません。
