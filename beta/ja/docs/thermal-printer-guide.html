感熱プリンターと配信ラベル

購入、寄付、チャットイベントを、実物のレシート、ステッカー、チケット、受け取りタグに変えます。

設定する 寄付時に印刷する 売上を印刷する Whatnotラベル 用紙を選ぶ ラベルのサイズ アイデア 問題を解決する

6つの手順で設定する

始める前に： Windowsのデスクトップアプリが必要です。通常のWindowsプリンターとして認識されるプリンターを使います。Social StreamはWindowsドライバー経由で印刷し、生のESC/POS、ZPL、メーカーSDKの命令は送信しません。
  1. プリンターをUSBで接続して電源を入れ、Windowsドライバーを入れます。Windowsのテストページを印刷して動作を確認してください。
  2. Social Streamで次を開きます： Global settings and tools → Mechanics - Connections & Integrations → Printer Control.
  3. クリックする項目： プリンターを検索（Find printers）。Windowsに表示される名前でプリンターを選びます。
  4. 次を入力します： 用紙幅（mm）。通常は、 58, 80、または 62.
  5. 次はそのままにします： 固定ラベル長（Fixed label length） の値を 0 にします。型抜きラベルでは、紙が進む方向の長さをmmで入力します。
  6. クリックする項目： 印刷テスト。端が切れる場合は、その側の安全余白を増やして再度試してください。

初期設定の左右2mmの安全余白は、多くの安価な58mmレシートプリンターに合います。実際の印刷領域はドライバーが決めるため、次を 印刷可能領域を使用（Use printable area） を選択したままにしてください。ほかの設定を検証した場合は変更できます。

寄付を受けたらラベルを印刷する

💰 寄付 / 投げ銭（Donation / Tip）最低金額（Minimum Amount）： 10
→
🖨️ 感熱ラベルを印刷（Print Thermal Label）{username}
{donation}
24 pt · 太字 · 中央揃え
  1. 開く項目： Event Flowエディター で新しいフローを作ります。
  2. 次を追加します： 寄付 / 投げ銭（Donation / Tip） トリガーを追加します。次を設定します： 最低金額（Minimum Amount） を、大きい寄付だけ印刷したい場合に設定します。
  3. 追加する項目： 感熱ラベルを印刷（Print Thermal Label） （Integrations内）を選び、トリガーにつなぎます。
  4. 入力するコマンド： {username}、改行、次の値を入力します： {donation}。文字サイズ、太さ、配置、枚数を選びます。
  5. アクションのプリンターと固定長の上書き設定は空欄か、 0。Printer Controlの設定を使います。
  6. クリックする項目： フローをテスト（Test Flow）。名前を付け、次を有効にします： 寄付額（Has Donation）を選び、金額を入力して実行します。実際のラベルが印刷されます。

その他の便利なプレースホルダー： {message}, {source}, {donationAmount}、および {counterValue}。フロー内の前の処理で作った値も使えます。

売上、ギフト、注文番号を印刷する

印刷したいもの…操作
売上使う項目： イベントの種類 付随する値： purchase. 寄付 / 投げ銭（Donation / Tip） に必要なもの： hasDonationだけなので、大半の売上を拾えません。
完了したギフト使う項目： gift または giftfunded。必要ならプロバイダーで絞り込みます。
連続した注文番号追加する項目： カウンター を印刷アクションの前に置きます。

参照先： コマースイベントのフィールド で各売上に含まれる項目を確認できます。

購入者を太字、商品を通常の太さにする

  1. 設定する項目： 太さ → 選択した文字.
  2. ラベルの文字として次を入力します：
**{username}**
{subtitle}
  • 次で囲んだ文字だけが、 ** 太字になります。HTMLやJavaScriptは不要です。
  • 波かっこは1重で使います。売上の商品名が入るのは、 {subtitle}。数量は次に入る場合があります： {meta.commerce.quantity}.
  • 前の処理で次を作る場合、 buyerでは、次を使用します： **{buyer}** を代わりに使います。
  • ShopifyとeBayは購入者名を送信しません。これらには注文カウンターや商品名だけの札を使ってください。
  • All boldやNormalに設定済みのラベルの見た目は変わりません。
フロー作成者向け：印刷結果と購入者番号

アクションは次を追加します： meta.thermalPrintResult.successと、失敗時のエラーやコードを後続の処理へ渡します。成功はWindowsにジョブを送ったという意味で、紙が出た証拠ではありません。再試行前にWindowsの印刷キューを確認し、ラベルの重複を防いでください。

Counterが付けるのは購入ごとの番号で、購入者ごとの番号ではありません。同じ購入者の全購入に同じ番号を付けるには、購入者と番号の対応表を別に用意し、配信開始時にリセットします。User Memoryのreason欄は普通の文字列で、購入者番号のカウンターではありません。

Whatnotの商品ラベル

Whatnotのサンプルフローをダウンロード。購入者名を太字で、商品名と、あれば注文IDを印刷します。支払い失敗時は別の 支払い失敗 ラベルを、その通知に含まれる情報で印刷します。

  1. デスクトップアプリで次を設定します： プリンター制御（Printer Control） を設定し、テスト印刷を実行します。
  2. 開く項目： Event Flowエディターで、次をクリックします： インポート（Import）を選び、ダウンロードしたファイルを開きます。
  3. 選択する項目： Whatnot：商品ラベルと支払い警告。両方の印刷アクションを確認してください。Printer Controlのプリンターとラベル長を使います。
  4. フローを有効にして保存します。取り込み直後は無効です。
  5. Whatnotのソースを開き、配信イベントの取得を有効にしたままにします。
売上ラベルは支払い済みの証明ではありません。 通知が届くたびに印刷します。支払いを待つ、以前のラベルを直す、購入者番号を割り当てるといった処理はしません。ない項目は空欄になります。購入者・商品・注文情報のない失敗通知では、どのラベルに対応するか特定できません。
サンプルフローの動作

使用するのは、 イベントタイプ（高度）（Event Type (Advanced)）→ カスタムイベント（Custom Event） のための product_sold および payment_failedをWhatnotに絞ります。入札やオークション終了通知は印刷しません。参照： Whatnotのイベントフィールド.

用紙を選ぶ

レシートロール

購入伝票、順番券、任意の長さのレシート向けです。固定ラベル長は0にします。

連続ステッカーロール

任意の長さの名前シール向けです。レシート用紙と同様に動きますが、カットはプリンターやドライバー側で行います。

ダイカットラベル

サイズの揃ったバッジや商品ラベル向けです。正確な固定長を設定し、Windowsの印刷設定でも同じ用紙を選んでください。

プリンターの例

プリンター適した用途補足
汎用「POS-58」安価な58mmレシート通常はUSB。名称やドライバーは販売者によって異なります。Social Streamのテストには基本的なPOS-58を使いました。
Epson TM-T20III丈夫なレシートプリンターUSB。80mm用紙、または付属アダプターで58mm。
Brother QL-800ステッカーと名前ラベルUSB。最大62mm、型抜きまたは連続用紙、自動カッター付き。
Brother QL-820NWB共有またはネットワーク接続のラベル印刷所USB、Ethernet、Wi-Fi、Bluetooth。
Zebra ZD220幅広の商品、配送、リストバンド用ラベルUSB。約25〜112mmの用紙。感熱式と熱転写式があります。

これは例で、動作確認済み一覧ではありません。購入前に正確な型番の最新Windowsドライバー、ラベルサイズ対応、通常のWindowsプリンターとして認識されることを確認してください。

固定サイズのラベルを正しく設定する

3 × 1インチのラベル（Munbyn BT320を含む）： 幅を 76.2 mm、固定長を 25.4 mmにします（1インチ側が送り方向の場合）。Windowsの印刷設定でも同じ用紙と向きを選び、文字は12〜14ptから試してください。
ルール理由
用紙が進む向きで測る62 × 29mmのラベルは通常、幅62mm、固定長29mmです。
Windows側の設定も揃えるドライバーの印刷設定で、用紙、向き、隙間／マーク検出、カッターを揃えます。
固定長は変わりません追加の用紙送りは行いません。文字が高すぎると、ドライバーによって切れたり次の用紙にはみ出したりします。
最も長い文字列で試す長い名前、商品オプション、追加の行には、広い領域や小さい文字が必要です。
非常に短いラベルは使えない場合がありますSocial Streamは最低20mmを指定しますが、短いページはドライバーに制限される場合があります。

テスト印刷の左右の線は安全な幅を示します。高さはテスト文に合わせるため、ラベル全体の枠ではありません。

配信のアイデア

  • 壁、小道具、地図、進捗ボードに貼る支援者名のシール。
  • 注文に合わせた物販、依頼、飲み物、受け取りの札。
  • 抽選券。印刷処理の前に頻度制限と参加資格の確認を追加してください。
  • VIPバッジ、チーム選択、チャレンジ券、節目のラベル。
  • 隣にいる制作担当者向けの短いやることリスト。
非公開情報を印刷しないでください。 住所、メール、決済情報、非公開メッセージは印刷しないでください。感熱紙は熱、光、時間で色が薄くなります。

問題を解決する

問題試すこと
プリンターが表示されないWindowsのテストページが印刷できるか確認します。Social Streamを再起動し、Find printersをもう一度クリックしてください。
成功と出るが印刷されないWindowsの印刷キューを開き、一時停止、オフライン、用紙、ドライバー、ポートのエラーを確認してください。
端が切れるUse printable areaを有効にし、その側の安全余白を増やしてください。
余分な白紙が多いレシートは固定長0を使い、下余白と追加の送りを減らします。ラベルは正確な長さを設定してください。
1枚のラベルが2枚に分かれる文章がラベルより高いか、Windowsの用紙サイズが違います。文字量、文字サイズ、行間、余白を減らしてください。
Test Flowが違うプリンターを使うPrint Thermal Labelの処理でプリンターの上書きを選びます。空欄だと、編集画面でのテストはWindowsの既定プリンターを使います。
