Configuration du projet YouTube

Créer un projet Google Cloud pour l’application de bureau SSN autonome sans affaiblir la sécurité de votre clé.

Vue d’ensemble

But de cette configuration

Utilisez cette méthode uniquement si vous souhaitez que l’application de bureau utilise votre propre quota API YouTube à la place du projet partagé par défaut de Social Stream Ninja.

Important : les trois valeurs ci-dessous doivent provenir du même projet Google Cloud:
  • Identifiant client OAuth (OAuth Client ID)
  • Secret client OAuth (OAuth Client Secret)
  • Clé API
Ne confondez pas ces deux champs dans Google Cloud :
  • Origines JavaScript autorisées (Authorized JavaScript origins) doit contenir uniquement l’origine, sans chemin.
  • URI de redirection autorisés (Authorized redirect URIs) doit inclure le chemin complet /sources/websocket/youtube.html .
Étape 1

Créer le projet

  1. Ouvrez Google Cloud Console.
  2. Créez un projet ou choisissez un projet existant dédié.
  3. Activer YouTube Data API v3.
  4. Ouvrez les paramètres de l’écran de consentement OAuth.
  5. Si l’application est en test, ajoutez votre compte Google comme utilisateur de test.
Étape 2

Créer le client OAuth

  1. Créez les identifiants.
  2. Choisir Identifiant client OAuth (OAuth client ID).
  3. Choisissez le type Application Web (Web application).
  4. Ajoutez exactement les origines et URI de redirection indiquées ci-dessous.
Champ Valeur
Origines JavaScript autorisées (Authorized JavaScript origins) http://localhost:8181
http://localhost:8080
URI de redirection autorisés (Authorized redirect URIs) http://localhost:8181/sources/websocket/youtube.html
http://localhost:8080/sources/websocket/youtube.html
Étape 3

Créer la clé API en toute sécurité

  1. Créez une Clé API (API key) dans le même projet.
  2. Ouvrez les restrictions de cette clé.
  3. Sous Restrictions d’API (API restrictions), limitez-la à YouTube Data API v3 uniquement.
  4. N'utilisez pas de restrictions de référent HTTP pour l'application de bureau.

Règle pour l’application de bureau : Les restrictions de référent HTTP concernent les pages de navigateur, pas cette procédure d’authentification locale de l’application de bureau.

Étape 4

Coller les valeurs dans l’application de bureau

  1. Ouvrez la page source YouTube dans l’application de bureau.
  2. Collez le Identifiant client OAuth (OAuth Client ID), Secret client OAuth (OAuth Client Secret), et Clé API.
  3. Cliquez sur Enregistrer.
  4. Déconnectez-vous si nécessaire.
  5. Cliquez sur Se connecter avec YouTube (Sign in with YouTube).
  6. Terminez la connexion Google dans la fenêtre du navigateur externe.
Résultat attendu : si tout correspond, la connexion Google fonctionne et l’application de bureau utilise votre projet YouTube enregistré à la place du projet partagé par défaut.
Sécurité

Protéger les identifiants

  • Traitez le secret client et la clé API comme des informations sensibles.
  • Ne les collez pas dans des captures d’écran, historiques de chat ou rapports de bug.
  • En cas d’exposition accidentelle, remplacez-les ou supprimez-les.
  • Utilisez un projet de test dédié pour vos essais.
  • Supprimez les projets temporaires une fois les tests terminés.
Dépannage

Problèmes courants

  • redirect_uri_mismatch: l’URI de redirection ne correspond pas exactement.
  • invalid_client: l’identifiant client et le secret client ne correspondent pas.
  • quotaExceeded: le quota YouTube du projet de votre clé API est épuisé.
  • Échec de validation du compte : dans les anciennes versions, cela pouvait se produire si OAuth et la clé API provenaient de projets différents.
