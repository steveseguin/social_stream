Statistiques vidéo et débit

Affichez le débit du flux entrant en haut à droite du dock Social Stream Ninja.

Important : SSN ne lit pas automatiquement le débit dans OBS ni sur une plateforme de streaming. Il interroge l’API de statistiques du serveur vidéo recevant votre flux.
UtilitéCompatibilitéUtilisationSi rien n’apparaîtAvancé : protocole, formats et unités

Utilité

Cela donne à l’animateur ou au producteur un petit indicateur de débit en direct dans le dock. Utile lorsqu’OBS, un encodeur mobile ou un autre émetteur publie vers votre propre relais ou serveur de réception.

SSN normalise aussi les données disponibles de latence, tampon, pertes de paquets, durée de fonctionnement, codecs et spectateurs dans un événement de métadonnées video_stats . L’affichage standard du dock montre uniquement le débit.

Compatibilité

  • SRT Live Server / SLS : JSON /stats renvoyant un objet publishers .
  • Belabox Cloud : sa réponse JSON de statistiques de récepteur/relais de type SRT.
  • NGINX RTMP : XML du module d’état NGINX RTMP.
  • Node Media Server : son API JSON de flux, avec une authentification HTTP Basic facultative.
OBS n’est pas une source de statistiques : OBS peut envoyer de la vidéo à un serveur compatible, mais OBS WebSocket et les sources Navigateur SSN ne fournissent pas ces données.

Utilisation

  1. Activez le point d’accès HTTP des statistiques du serveur compatible et vérifiez que l’ordinateur exécutant SSN peut ouvrir son URL.
  2. Dans SSN Paramètres globaux, activez Interrogation des statistiques vidéo (Video stats polling).
  3. Sélectionnez le type de source et saisissez l’URL des statistiques.
  4. Pour SRT ou Belabox, saisissez l’identifiant exact de l’émetteur, par exemple publish/live/feed1. SSN l’utilise automatiquement si la réponse contient un seul émetteur.
  5. Pour NGINX RTMP ou Node Media Server, saisissez l’application et la clé/le nom du flux, par exemple live et feed1.
  6. Ajoutez l’authentification si nécessaire. Le champ de clé API SRT est envoyé comme en-tête complet Authorization . Node Media Server utilise le nom d’utilisateur/mot de passe comme authentification HTTP Basic.
  7. Choisissez un intervalle d’interrogation de 1 à 60 secondes ; cinq secondes par défaut.
  8. Dans les options du dock, activez Afficher les métadonnées de débit si disponibles, en haut à droite (Show bitrate metadata if available; top-right), puis ouvrez ou actualisez le lien du dock.
  9. Commencez à publier la vidéo. Le débit apparaît après une réponse valide indiquant un flux en ligne.

Si rien n’apparaît

  • Vérifiez que les deux options de statistiques vidéo sont activées dans SSN.
  • Vérifiez que le point d’accès répond en moins de cinq secondes et que le type de source et les identifiants de flux correspondent.
  • 127.0.0.1 désigne l’ordinateur exécutant SSN. Utilisez l’adresse locale du serveur s’il s’agit d’un autre appareil.
  • L’affichage disparaît lorsque le flux est hors ligne, que le débit est absent ou nul, ou qu’aucune statistique récente n’arrive pendant environ 130 secondes.

Avancé : protocole, formats et unités

SSN effectue une requête HTTP ou HTTPS GET à l’intervalle configuré, avec le cache désactivé et un délai d’expiration de cinq secondes.

SRT Live Server / SLS et Belabox Cloud

{
  "publishers": {
    "publish/live/feed1": {
      "bitrate": 4500, "rtt": 32.5, "msRcvBuf": 120,
      "mbpsRecvRate": 4.5, "mbpsBandwidth": 12.8,
      "pktRcvDrop": 2, "pktRcvLoss": 1,
      "bytesRcvDrop": 2632, "bytesRcvLoss": 1316, "uptime": 3600
    }
  }
}

bitrate est en Kbps ; le RTT et le tampon de réception sont en millisecondes ; le débit de réception et la bande passante en Mbps ; la durée de fonctionnement en secondes ; les pertes/rejets en nombre de paquets ou en octets.

NGINX RTMP

L’URL doit renvoyer le XML d’état NGINX RTMP. SSN recherche l’application et le flux configurés. Il lit bw_video comme octets par seconde et divise par 1024 pour bitrateKbps. Il lit aussi la durée du direct et les métadonnées facultatives des codecs vidéo/audio.

Node Media Server

SSN demande STATS_URL/APPLICATION/STREAM_NAME. Les champs peuvent être au premier niveau ou dans data.

{ "data": { "isLive": true, "bitrate": 4500, "viewers": 3, "duration": 3600 } }

Le débit est en Kbps, le nombre de spectateurs est un entier et la durée est en secondes.

Événement SSN normalisé

{
  "type": "generic",
  "event": "video_stats",
  "meta": {
    "provider": "srt-live-server", "source": "srt-live-server",
    "label": "SRT", "online": true,
    "updatedAt": "2026-07-13T14:45:00.000Z",
    "bitrateKbps": 4500, "rttMs": 32.5, "bufferMs": 120,
    "summary": "4500 Kbps, 33 ms, 120 ms"
  }
}
ChampUnité/type
bitrateKbpsKbps, nombre entier
rttMs / bufferMsMillisecondes
recvRateMbps / bandwidthMbpsMbps
Champs de pertes/rejetsNombre de paquets ou octets
uptimeSeconds / durationSecondsSecondes
onlineBooléen ; false masque la valeur du dock

Le dock accepte meta.bitrateKbps, avec meta.bitrate et meta.kbps comme valeurs de repli. Les valeurs inférieures à 1000 s’affichent en Kbps arrondis ; les valeurs supérieures en Mbps avec une décimale. L’URL des statistiques, la clé du flux et les identifiants ne sont jamais envoyés aux incrustations.
