让聊天进入叠加层

Lite 从浏览器或 OBS 连接支持的聊天来源。使用普通叠加层链接时，保持 Lite 在标签页或 OBS 停靠面板中运行。实验性的独立 OBS 模式在一个浏览器源中捕获并显示聊天。

设置 · 仅 OBS 设置 · 来源 · 现有设置 · 故障排除

1. 设置叠加层

  1. 打开 Lite。会话 ID 和叠加层 URL 会自动生成，并由此浏览器记住。
  2. 连接下列某个来源。使用其 选项 按钮来设置频道。
  3. 选择 复制链接（Copy link）。在 OBS 中添加一个 浏览器 来源，并将链接粘贴到其 URL 字段。您也可以使用 打开停靠面板叠加层（Open dock overlay） 在浏览器中检查它。
  4. 选择 发送测试消息（Send test message） 在 Lite 中。确认它出现在已打开的叠加层中。消息仅出现在 Lite 的 Activity 信息流中，并不能确认叠加层已收到。

如需透明叠加层或不同的消息顺序，请打开以下内容旁边的选项： 聊天叠加层链接（Chat Overlay Link）。更改这些选项后，将更新的 URL 复制到 OBS。

2. 选择来源

仅使用 OBS 时，请选择下列两种工作流之一。如果捕获在 OBS 中运行，就不需要单独的桌面浏览器标签页。

来源操作方法
YouTube使用 YouTube 登录。Lite 会查找您的直播。在 Options 中，可以提供 Video ID 或 Live Chat ID 来指定某场直播。默认使用轮询；可选的流式 API 标记为 Beta。直播必须有可用的实时聊天。
Twitch使用 Twitch 登录。Lite 默认使用您自己的频道；可在 Options 中设置其他频道。如果授权过期，请重新登录。
Kick在 Options 中输入频道名称并连接。如果自动查询失败，请检查频道拼写，然后按需使用手动聊天室设置。
TikTok此集成目前在标准 Lite 面板中隐藏。它需要兼容的 TikTok Chat Reader 代理；预填地址不保证服务可用。请使用完整应用查看可用的 TikTok 捕获选项。

断开连接 会停止该来源。对于 YouTube 和 Twitch，它会保留登录状态，让您可以使用 连接 ，再次操作。 退出登录（Sign out） 会移除此浏览器中保存的授权。

3. 使用现有 Social Stream 设置

如需向现有停靠面板或叠加层提供数据，请打开 Lite 中的会话选项并输入其会话 ID。选择 保存会话 ID（Save session ID） 或按 Enter。更改 ID 会切换 Lite 发送消息的位置；请更新所有应随之切换的浏览器源 URL。

同一会话中，每个频道仅使用一种捕获方式。同时运行 Lite 和针对相同聊天的扩展或桌面捕获可能产生重复消息。您可以用 Lite 捕获一个频道，用完整应用捕获其他来源。

Lite 生成的链接使用默认会话密码。受密码保护或使用自定义服务器的设置可能需要完整应用的连接控件。Lite 不替代完整应用的捕获、自动化、管理或叠加层自定义控件。

Activity 的 仅打赏 和 文本转语音 控件适用于 Lite 活动视图。使用其活动弹出窗口时，保持 Lite 主页面打开。如果不希望他人加入该会话，请将叠加层 URL 保密。

完全在 OBS 内运行

选项 A：Lite 停靠面板 + 普通叠加层

  1. 打开 完全在 OBS 内运行 在 Lite 中，并复制 OBS 自定义停靠面板 URL (lite/index.html?view=dock).
  2. 将其添加到 OBS 的 自定义浏览器停靠面板。在该停靠面板中登录并配置来源。Source Options 和会话设置仍可在那里访问。
  3. 将停靠面板的普通叠加层 URL 复制到 OBS 浏览器源。捕获时保持 Lite 停靠面板加载。该来源只显示消息，因此无需单独登录提供商。

这是最简单的仅 OBS 工作流：在停靠面板中捕获，在浏览器源中显示。关闭停靠面板会停止其捕获。设置完成后不需要桌面浏览器。

选项 B：单个捕获与叠加层浏览器源（实验性）

  1. 添加 独立捕获 + 叠加层 URL (lite/index.html?view=overlay）作为 OBS 浏览器源。
  2. 打开 交互（Interact） 以配置来源。如果已经配置，按 Escape 在 Interact 中按此键，以重新打开设置。登录页面和设置控件在此来源中可见，因此请在非直播状态下配置。
  3. 选择 显示叠加层（Show overlay）。页面现在会在透明背景上显示自己接收的聊天。它不需要另一个 Lite 标签页、停靠面板或转发连接，也不会向其他会话叠加层提供数据。
  4. 将 不可见时关闭来源（Shutdown source when not visible） 和 场景激活时刷新浏览器源（Refresh browser source when scene becomes active） 关闭，以避免切换场景时中断捕获。请参阅 OBS 浏览器源属性.

已保存的有效 YouTube/Twitch 凭据会在启动时重新连接。对于 Kick，请启用 在 OBS 模式下自动重新连接此 Kick 频道 在其 Options 中。先配置频道。TikTok 仍保持隐藏。布局初始显示所有消息并关闭语音，独立于普通活动视图中保存的偏好。

OBS 停靠面板、OBS 浏览器源和桌面浏览器可能使用不同的 Cookie/存储配置文件。不要假定配置停靠面板就会让独立浏览器源完成登录。如果无法在 OBS 浏览器源中完成登录，请使用选项 A。原生 OBS 提供商身份验证仍需要实际验证；此模式为实验性功能。

每个频道仅使用一个捕获位置。不要让停靠面板与独立捕获加叠加层来源同时捕获相同频道。在不同场景复用同一捕获来源时，使用 OBS 的现有来源选项。

故障排除

叠加层是空白的
检查 Lite 是否仍打开，以及叠加层是否使用相同会话 ID。发送测试消息。如果测试消息到达但直播聊天没有到达，请检查来源状态和频道。如果两者都未到达，请检查叠加层 URL，以及网络是否阻止转发连接。
复制链接被阻止
点击可见的叠加层 URL，然后使用键盘或设备的复制菜单复制所选文本。
来源闲置或显示错误
检查其 Options 和错误文本。修正设置后重新连接。如果授权已过期，YouTube 和 Twitch 可能需要重新登录。
我看到重复消息
检查是否有第二个 Lite 标签页、扩展捕获或桌面捕获正在捕获相同频道和会话。仅保留预期的捕获运行。
设置消失了
设置保存在此浏览器的本地存储中。不同浏览器、隐私窗口或清除网站数据后会使用不同的设置。
