选择模板

每个预览都有示例按钮和“最后收到的数据”检查器。示例是模拟事件，不是购买；预览模式不会加入真实会话。

三步连接模板

  1. 启动 SSN 并连接聊天，确认 Dock 显示聊天和礼物。TikTok 请参见 连接模式.
  2. 打开模板 不带 ?demo，使用会话 ID（设置了密码时也需包含）。
  3. 先在浏览器检查，再将同一链接作为浏览器源加入 OBS，例如设为 1000×800。
https://socialstream.ninja/games/templates/coin-rocket.html?session=YOUR_SESSION&password=YOUR_PASSWORD&clean
  • &clean 隐藏检查器、连接状态和主播按钮。
  • 没有密码？省略 &password=….
  • 在测试版网站上，保留 /beta/ 在以下路径之前： games/.
会话链接请保密。
其他连接路径（WebSocket）

模板默认使用与 SSN 叠加层相同的 iframe 桥接。

  • 托管 WebSocket： 开启 通过服务器将扩展中的消息发送到停靠面板 在 SSN 中启用，再添加 &server2.
  • 本地服务器： 添加 &server2&localserver，或 &localserverport=3000。请参阅 WebSocket 指南.
  • localserver 本身不会启用路径。
  • 旧版的 server 消息流使用不同频道，可能需要 Dock 向其发布。

创建自己的副本并从磁盘运行

无需安装服务器。编辑电脑中的文件，再让 OBS 指向它。

  1. 下载 beta 源代码 ZIP 并解压。
  2. 在原文件旁复制所需模板，例如： games/templates/my-rocket.html.
  3. 保留文件夹结构。模板会加载 js/local-server-url.js，支持目标还会加载 currency.js ，从顶层文件夹加载。图片和音频也需保留原位。
  4. 将 HTML 文件拖进 Chrome 或 Edge，复制 file:/// 地址。
  5. 添加从以下位置开始的全部内容： ? 起的所有内容，从可用的游戏链接复制（会话、密码、传输选项）。
  6. 在OBS中，离开 本地文件 取消勾选，把完整地址粘贴到浏览器源的 URL 领域。
  7. 每次编辑后刷新浏览器源。
file:///C:/SSN/social_stream-beta/games/templates/my-rocket.html?session=YOUR_SESSION&clean

使用真实路径，不要移动解压文件夹。会话是 SSN 连接 ID，不是游戏名称。移除 demo 以接收实时输入。保持 SSN 和采集运行。更多示例： 文件设置指南.

正在编辑已有游戏？ 你可以复制以下任意页面： games/. games.html 和 battle.html 有自己的游戏逻辑。模板规则设置并非共用游戏 API。

如何选择操作所需的金币数量？

先决定衡量什么，再选择数字。

衡量对象读取这里示例
原生单位（金币、Bits、Stars）TikTok meta.coinsPerGift × meta.tiktokGiftCount 存在时使用，否则用 hasDonation 标签，例如 10 coins, 100 bits, 100 Stars.每 10 金币加速一次。
一种特定礼物TikTok meta.giftId 或 meta.giftName及其数量。每份匹配礼物增加一朵花，不论价值多少。
可比较的金额getDonationValueUSD(data) 来自 currency.js.每估算 1 美元增加 10 燃料，25 美元完成目标。
免费操作或会员操作来源实际的 event或聊天命令。关注种下一棵树，新订阅播放动画。

精确值、最低值还是累计余额？

  • 精确值： coins === 10。25 金币的礼物不会触发任何操作。
  • 每次事件最低值： coins >= 10.
  • 累计余额： 是火箭使用的方式。25 金币触发两次加速，剩余 5 金币。

有多个档位？先检查最高档，避免一份礼物触发所有较低档位。

TikTok 金币数不一定已知。 如果只采集到礼物名称、数量或钻石标签，金币火箭会跳过该事件。改用礼物规则或美元模板。不要用美元估值倒除，也不要把钻石当作金币来计算“精确金币”。
更多关于 TikTok 金币、礼物和钻石
  • 观众购买金币并用来送礼，礼物旁显示金币价格。参见 TikTok 关于金币和礼物的说明.
  • 礼物名称、礼物数量、金币和钻石是四种不同的东西。
  • 选择自己的 LIVE 中可用的礼物，公开规则前检查采集数据。
  • 金币值可能来自 SSN 礼物映射。需要准确价格时，请与当前 LIVE 礼物栏对照。
  • 礼物目录和采集方式各不相同，并非每条 TikTok 消息都有金币字段。

各平台发送什么

type 说明来自哪里。 event 存在时说明发生了什么。收到什么取决于采集模式、设置和平台。这里反映 SSN 当前代码，不保证所有账户都收到所有事件。

平台你将获得注意
TikToktype: "tiktok", event: "gift"。捐款采集可能添加 hasDonation 和 donoValue。礼物元数据可能包含 ID、名称、数量、每份礼物的金币和钻石数，以及连送 ID。金币用于买礼物，钻石是创作者奖励。SSApp WebSocket 采集先结算连送再发送；浏览器采集可能发送不断增长的总数。关闭 TikTok 捐款采集可能使礼物没有金额字段。
Twitch欢呼使用 Bits，例如 hasDonation: "100 bits"。API 采集可能发送 event: "cheer" 和 donoValue: 1。聊天采集可能没有事件字段。订阅、赠送订阅、突袭和频道积分是独立事件。普通消息上的订阅徽章不代表新订阅。Twitch Extensions 中的 Bits 属于另一套系统。
Facebook直播聊天中可见的 Stars 行会提供例如 hasDonation: "100 Stars" 和 donoValue: 1，不含 event.评论 API 路径不会从聊天文字读取 Stars。页面采集必须能看到 Stars 行。评论和反应不是付款。
YouTubesuperchat 和 supersticker 在以下字段保留原始货币： hasDonation。礼物使用 jeweldonation 带有 N Jewels，或 1 YouTube Gift ，在金额隐藏时使用。观众花费 Jewels，创作者获得 Rubies。会员和赠送会员是独立事件。Super Thanks 是独立产品，不保证产生聊天事件。

其他来源可能报告打赏、礼物、会员或购买。检查 事件参考 ，然后才加入模板的 isSupport 过滤条件。销售或赠送订阅不自动算作打赏。YouTube 同时发送购买礼物和每位接收人的通知，两者都计数会重复奖励同一礼物。

正确使用 donoValue 和 currency.js

字段功能说明
hasDonation原始标签，例如 €5.00 或 100 bits。向观众展示。
donoValue来源提供的可选美元数值。只要有效（包括零），就优先使用，不再从标签估算。
 
<script src="../../currency.js"></script>
<script>
// From games/templates/: use the existing helper, including its zero handling.
var usd = getDonationValueUSD(data);
// Use usd for your rule; display data.hasDonation for the original amount/unit.
</script>

不要这样做

  • donoValue || convertToUSD(...) ——它会丢弃本应保留的零值。
  • 从以下内容提取数字： chatmessage 来识别付款。
  • 要求必须存在 event === "donation" —— Facebook Stars 和部分 Cheer 没有事件字段。

支持目标模板先筛选支持类型，再调用共享转换器。

SSN 内置估算值
单位估算为
1 个 TikTok 金币$0.01
1 个 TikTok 钻石$0.005
1 个 Twitch Bit 或 Facebook Star$0.01
1 个 YouTube Jewel$0.005
价格未知的 TikTok 礼物每份礼物 1 金币
没有 Jewel 数量的 YouTube 礼物0.01 美元占位值

其他货币使用内置近似汇率，不是实时汇率，仅用于比较支持程度。这不等于观众实际支付、你的收入或可提现金额。采集方式不同，估算可能不同。一金币的回退值不表示该礼物售价一金币。

来源： currency.js 以及 数据格式参考。礼物元数据是可选的；示例不会虚构采集中没有的字段。

同一连送只计一次

TikTok 可能用 1、2、3 的累计数报告连送，这表示三份礼物，不是六份。记住该连送已见过的最大总数，只增加差值。

// All three events refer to the same streak:
// incoming total: 1, 2, 3, 3
// added to game:  1, 1, 1, 0
var newCoins = RewardStarter.increment(data, RewardStarter.coins(data), 'coins');
  • 辅助程序先按 TikTok 群组/发送者/礼物 ID 匹配连送，再按 meta.tiktokGiftStreakId，再使用消息 ID。消息 ID 也用于阻止重复传递。
  • 它不会等待 repeatEnd，因为浏览器采集可能从不发送它。如果只想在连送结束时执行一次，请按连接实际发送的字段另写规则。
  • 只用一条采集路径。同一频道的第二路采集可能使用不同 ID，导致重复计数。
模板的内存限制
  • 最多记住 2,000 个 ID，仅保存在内存中。
  • 重置或刷新会清除这些内存和游戏进度。
  • 没有稳定 ID 的消息无法可靠去重。
  • 火箭按平台和用户 ID 汇总余额，没有 ID 时使用显示名称。同名观众可能共用余额。
  • 需要重启后继续的游戏，请先加入状态保存和重放处理，再用于付费奖励。

无需自定义游戏的奖励

在 Event Flow:

  1. 添加 比较属性.
  2. 设为 donoValue, 大于或等于，以及美元金额。
  3. 连接声音、动画或 OBS 控制等操作。

来源自带数值有效时优先使用，否则使用 SSN 汇率转换。

  • 某个特定 TikTok 礼物： 比较 meta.giftId 或 meta.giftName，并将流程限定为 TikTok 礼物事件。
  • 对以下值进行数字检查： hasDonation 也会转换为美元，不是原始金币检查。金币规则请使用原生元数据或自定义代码。
  • 每条消息分别检查。 这不是累计余额或连送计数器。请使用 状态节点 来实现，或将该逻辑保留在游戏中。

连接付费操作前先测试

  1. 示例按钮。 1→2→3 的连送共增加三份礼物。零值覆盖示例不增加美元金额。价格未知时不增加精确金币数。
  2. 真实来源。 查看真实采集数据，确认礼物名称/ID、数额、单位、数量和事件。示例测试的是规则，不是真实采集。
  3. OBS 场景。 测试重复事件、重连和刷新。需要保留内存中的进度时，不要刷新或关闭浏览器源。
