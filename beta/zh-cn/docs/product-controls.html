直播商品和观众链接

选择屏幕展示的商品，并给观众一个查看全部商品的链接。

添加商品 实时控制 观众链接 Stream Deck 与 Event Flow Remote API 解决问题

五步添加商品

  1. 打开 Monetization → Products & support links → Set up products and links.
  2. 粘贴公开的 https:// 链接并点击 从链接加载详情.
  3. 检查标题、图片、价格、币种和 链接用途。价格留空，需要时自行填写。
  4. 点击 添加商品或链接.
  5. 开启 商品与支持链接 并点击 保存设置.
哪些链接会自动加载？ 公开的 Gumroad、itch.io、Ko-fi、Buy Me a Coffee 和 Fourthwall 页面。其他链接可能需手动填写。无需商店账户。完整导入支持 Shopify 和 Fourthwall.

Shop、Gift、Support 和 Join 只是链接标签，不改变付款统计。卡片是快照，真实价格和库存以结账页面为准。

控制屏幕显示内容

添加 商品与支持链接 覆盖层到 OBS（商品展示与提醒 也显示提醒）。然后使用以下按钮：

按钮功能
立即显示 （在已保存商品上）忽略计划，立即显示该商品。
下一个商品显示下一个已保存商品。
隐藏商品隐藏商品卡片，但购买和礼物提醒仍显示。
恢复计划恢复已保存的轮换设置或首个商品固定显示。

设置 显示／隐藏秒数 。 0 表示保持到手动更改；1–3600 表示经过相应秒数后恢复计划。

实用说明
  • 实时修改会在 SSN 重启时重置。
  • Stream Deck 中若保存的商品不存在，会在按键上显示该状态，而非悄悄切换。
  • 未保存商品会被标记，其 立即显示 按钮在点击以下项目之前保持禁用： 保存设置.
  • 状态显示所选商品及剩余秒数，无法判断 OBS 是否直播或来源是否可见。
  • 商品按准确的已保存链接定位，因此调整列表顺序不会破坏自动化。

想在 OBS 内用按钮？使用 OBS 商品控制停靠面板。不要把控制界面放到观众覆盖层上。

给观众一个链接

  1. 打开 Display options → Public viewer page.
  2. 点击 发布已保存链接。这会公开所有已保存商品的标题、图片、价格和用途。
  3. 点击 复制观众链接 并分享。

商品 QR 码指向这里，商品离开屏幕后观众仍能找到。保存和实时控制会更新同一链接。页面每 15 秒刷新，标记精选商品，即使卡片隐藏也列出全部商品。

找回相同链接从同一电脑重新发布。
保留 SSN 配置文件。 其中保存着更新或删除页面所需的私钥。
SSN 离线或服务器中断时
  • SSN 关闭时，最后发布的页面仍保留，并显示保存时间。
  • “Featured”表示最后保存的选择或轮换，不代表正在直播。
  • 服务器中断时，SSN 内控制仍可使用。SSN 打开期间会重试更新，弹出菜单显示错误。
  • 发布需要服务器上的可选 public-shop 服务，不涉及商店或付款账户。

Stream Deck 与 Event Flow

Stream Deck

  1. 添加 预设命令 按键，来自 商品与支持：Show product、Next product、Hide products 或 Resume products。
  2. 对于 显示商品，点击 刷新商品和状态 并选择商品，也可粘贴公开链接，或留空使用当前或首个商品。
  3. 对于 下一个 和 隐藏，可按需添加秒数。

可选的 商品状态 按键显示已选择、已隐藏或已计划的状态，每五秒更新，长名称会缩短。按键使用现有 P2P 或 WebSocket 连接，并等待 SSN 确认。

Event Flow

  1. 添加 商品与支持 操作，位于覆盖层操作组。
  2. 选择 Show、Next、Hide 或 Resume，可按需填写准确的已保存商品链接和秒数。
  3. 使用可控的触发条件，例如管理员命令，而非每条聊天消息。
这些操作只改变显示内容。 不会创建捐款、购买、聊天发言或付款触发器。

Remote API（高级）

会话远程 API 接受 show, next, hide，或 resume. 主持人控制 必须开启。省略 url ，以使用当前或首个商品。

{"action":"commerceControl","command":"show","url":"https://example.com/product","seconds":30}
切勿分享私有会话或控制链接。 向观众提供观众链接。
确认控制何时完成
  • 命令仅发送现有的 monetization_update 显示状态。 hasDonation 行为不变。
  • Products & Support 操作等待 SSN 回复后才继续流程。
  • 在事件数据中， meta.commerceControlResult 包含 success ，再加上新的 commerce 状态或一个 error.
  • 失败会停止同一操作链后面的动作。原始购买或打赏仍会到达其他流程和覆盖层。
  • 结果确认 SSN 的选择、隐藏状态或计划，不确认 OBS 是否正在显示。
  • 八秒内无响应即超时。控制可能已经生效，再按 Next 前先检查弹出菜单或控制面板。
  • 外部远程客户端应使用请求／响应协议并检查结果，不能假设发送命令就已成功。
  • 其他操作报告自己的结果：Print Thermal Label 提供 meta.thermalPrintResult （发送任务不等于已打印）；同步 Webhook 操作可返回 HTTP 状态和响应，并在失败时停止。这些是操作结果，不是新的付款事件。

请参阅 事件参考 ，查看完整结果格式。
