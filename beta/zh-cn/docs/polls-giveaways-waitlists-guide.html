2. 进行多选项投票

  1. 打开 图形投票 → 投票选项。设置 投票类型 为 多选项.
  2. 输入 我们接下来玩什么？ 作为问题，并将 Adventure, Puzzle 作为逗号分隔的选项。设置 投票匹配 为 仅精确投票.
  3. 将 允许每位用户多次投票 和 按打赏金额加权投票 关闭，以进行简单的单次投票。开启 启用投票.
  4. 将生成的投票链接复制到 OBS。请观众发送 1 或 2 作为整条消息发送。发送匹配的选项文字也可以。
  5. 选择 结束投票 以关闭投票。在选择以下操作前记下结果： 重置投票 以开始下一轮。

自由形式投票接受话题标签投票； 话题标签可出现在任意位置 允许话题标签出现在较长消息内。 保存当前投票 保存预设以供复用；它不是观众投票结果的永久记录。除非启用多次投票，否则同一投票者的重复投票会被忽略。

专用抽奖工具

带截图的操作说明请参见 你的第一次抽奖。打开 抽奖工具 → 抽奖选项。设置报名关键词，选择整条消息匹配或独立单词匹配，并可选择仅允许会员报名。点击 开放报名，然后 抽出获胜者 ，在准备好后执行。抽奖会自动关闭报名。每次抽奖前，您都可以使用相同规则关闭并重新开放报名。 新一轮 清空当前抽奖池，将过去结果保留在历史记录中，并保持报名关闭。

选择 获胜者卡片, 姓名滚轴，或 社群转盘，并从六种样式中选择一种。预览使用虚构姓名，不会加入您的会话。复制生成的 giveaway.html?session=YOUR_SESSION&managed 链接到 OBS。受管理的观众显示页面不含操作员控件或会话详情。样式和标题属于链接设置；报名规则属于主持端设置，在开放报名时应用。

相同 Giveaway ID 的受管理显示页面共享主持人的抽奖池和选定获奖者。免费关键词报名的中奖概率相同；付费抽奖按票数加权。身份在各平台内通过提供的用户 ID、用户名或显示名称去重；不同平台视为不同身份。关闭重复中奖后，每位获奖者会从当前轮次的合格名单中移除。新轮次允许这些观众再次报名。抽奖池最多容纳 10,000 名参与者；人数较多时，转盘展示最多 120 个姓名的样本，但抽取始终使用完整的合格票池。

保持 SSN 运行。轮次按会话分别保存在本地浏览器／应用配置文件中。重新启动会关闭正在开放的轮次以供检查，但不会将其删除。刷新观众页面可收到当前结果。会员限制需要来源提供会员信息。历史、重播、私密、机器人以及仅含事件的消息均被排除。免费报名文字必须匹配配置的关键词；打赏金额不会改变中奖概率。

API、Stream Deck 和 Event Flow

相同的主持端操作用于弹出菜单按钮、现有 HTTP／WebSocket API 和 Stream Deck。收集报名或抽奖时，无需打开任何抽奖显示页面。在 Event Flow 中，使用 抽奖 / 票券 操作。参见 积分与自动化指南 了解付费票券、游戏奖品和集成。

操作效果
startgiveaway抽取前开放或恢复报名。可选值： {"giveawayId":"default","config":{"keyword":"!enter","match":"exact","membersOnly":false,"removeWinner":true}}。如果没有明确指定规则，则保留当前轮次规则，或在新一轮中使用弹出菜单设置。
closegiveaway关闭报名并保留抽奖池。
drawgiveaway关闭报名并选出一位符合资格的获奖者。抽奖池为空时返回错误。
resetgiveaway创建一个关闭报名的空轮次；将旧轮次及获奖者归档。请先取消／退款未完成的付费预留。
getgiveawaystate读取报名人数、开放／关闭状态、报名规则和近期获奖者。

Protocol 2 Stream Deck 请求使用相同的操作名称，并接收对应的主持端响应。这些响应描述抽奖状态，不代表 OBS 可见性。省略以下参数，仍可使用旧版独立社区转盘： managed；它有自己的本地抽奖池，不受这些主持人操作控制。它的本地存储现在按会话和密码隔离，精确匹配指整条消息，抽取使用安全随机数。

3. 抽取获奖者

  1. 打开 候补名单／抽奖 → 启用并自定义。启用触发器并设置明确的命令，例如 !join.
  2. 开启 设为抽奖模式而非队列模式。将更新后的链接复制到 OBS 浏览器来源。
  3. 告知观众报名命令及资格规则。如果使用 仅会员可报名，请先检查来源是否提供会员信息。
  4. 观察报名人数增加。选择 停止报名 ，在报名期结束时执行，然后 选择获奖者.
  5. 使用 下载名单 以在以下操作前保留报名记录： 重置抽奖 清空本轮。

4. 管理观众队列

使用相同的候补名单设置，但关闭抽奖模式并复制更新后的 URL。观众使用您配置的命令加入。

按钮 操作方法
突出显示首位报名者 提示下一位观众。
移除首位报名者 在该观众完成自己的回合后前进。
选择姓名 随机选择，而不是按队列顺序选择。
停止报名 关闭队列，不再接受新加入者。
下载名单／重置队列 保存 TSV 副本，然后在活动结束时清空报名记录。

通过重新加入选项决定已移除的观众是否可以再次加入。可选的 候补名单控制命令 仅限版主／主持人／管理员用户： !wlstop, !wlremove, !wlreset, !wlpick，以及 !wlhighlight。请有意识地启用这些功能；仅设置观众报名命令不会启用它们。

5. 演练与恢复

在以下功能中使用不同的虚构用户： 测试消息 以检查投票和报名行为。同一个人使用两个平台时，无法可靠地视为同一共享身份。邀请观众参与前，请确认结果显示在 OBS 中。

  • 没有票数： 检查是否启用投票、投票是否已结束、精确匹配设置，以及该用户是否已投票。
  • 没有报名者： 检查候补名单触发器、准确命令、停止报名状态和仅限会员的限制。
  • 有计数但没有名单： 抽奖模式显示抽奖池和获奖者，而不是普通队列。
  • OBS 显示不一致： 替换已保存的 URL，检查会话／密码，并避免运行单独配置的重复投票页面。

有关硬件或 OBS 端按钮，请参见 Stream Deck设置 和 OBS控制停靠面板.
