五步发起投票

  1. 打开 图形投票 → 投票选项。设置 投票类型 为 多选项.
  2. 输入问题，例如 我们接下来玩什么？，选项用逗号分隔，例如 Adventure, Puzzle.
  3. 设置 投票匹配 为 仅精确投票。开启 启用投票.
  4. 把投票链接复制到 OBS，观众只需发送 1 或 2 （或选项名称）。
  5. 点击 结束投票 停止投票。记下结果，再点击 重置投票 开始下一轮。

实用说明

  • 每位观众一票。开启 允许每位用户多次投票 进行修改。
  • 自由形式 投票使用话题标签，例如 #yes. 话题标签可出现在任意位置 会统计较长消息中的话题标签。
  • 保存当前投票 保存设置，不保存结果。

进行抽奖

第一次使用？ 你的第一次抽奖 提供带截图的步骤。

  1. 打开 抽奖工具 → 抽奖选项.
  2. 设置 报名关键词，例如 !enter.
  3. 选择一个 获胜者卡片, 姓名滚轴，或 社群转盘，以及六种样式中的一种。
  4. 点击 预览显示，然后将链接作为浏览器源复制到 OBS。
  5. 点击 开放报名。准备好后点击 抽出获胜者.
  • 抽奖会自动关闭报名。
  • 新一轮 清空参与者名单，将旧中奖者保留在历史记录中。报名初始为关闭状态。
  • 每份报名机会相同，捐款不会增加胜算。
  • 除非 允许重复获胜 已开启，否则中奖者不能在同轮中再次中奖。
  • 仅会员可报名 需要平台发送会员信息。
需要付费票券、积分奖品或游戏？ 参阅 抽奖、票券和积分奖品.
更多细节：概率、保存和限制
  • 预览使用虚构名字，不会加入你的会话。OBS 显示页没有控制按钮。
  • 样式和标题存放在链接中，报名规则在开放报名时从弹窗读取。
  • 相同 Giveaway ID 的画面显示同一批参与者和中奖者。
  • 付费票券按票数加权中奖概率。
  • 每人每个平台一份报名。同一人在两个平台参加会算两份。
  • 最多 10,000 份报名。转盘最多显示 120 个名字，但从所有参与者中抽取。
  • 忽略旧消息、重放消息、私密消息、机器人消息和纯事件消息。
  • 各轮次按会话保存在此浏览器或应用配置中。重启会关闭开放中的轮次以供检查，不会删除数据。
通过 API、Stream Deck 或 Event Flow 控制

弹窗、HTTP/WebSocket API 和 Stream Deck 共用这些操作，无需打开显示页。Event Flow 中使用 抽奖 / 票券 (详情).

操作功能
startgiveaway开启或恢复报名。可选值： {"giveawayId":"default","config":{"keyword":"!enter","match":"exact","membersOnly":false,"removeWinner":true}}。没有 config时，保留本轮规则（新轮次使用弹窗设置）。
closegiveaway关闭报名，保留参与者名单。
drawgiveaway关闭报名并抽出中奖者。无人参加时会报错。
resetgiveaway新建一个空的、关闭报名的轮次。旧中奖者进入历史记录。请先退还有偿票券。
getgiveawaystate获取报名人数、开放状态、规则和近期中奖者。
 
{"action":"drawgiveaway","get":"draw-1"}

Stream Deck（协议 2）使用相同名称。其回复反映抽奖状态，不代表 OBS 是否已显示。

旧的独立社区转盘（链接中没有 managed ）保留自己的参与者名单，不响应这些操作。

从候补队列快速抽奖

  1. 打开 候补名单／抽奖 并展开设置。开启触发器并设置命令，例如 !join.
  2. 开启 设为抽奖模式而非队列模式。将更新后的链接复制到 OBS。
  3. 告诉观众加入命令。
  4. 报名结束后点击 停止报名，然后 选择获奖者.
  5. 点击 下载名单 保留参与者，然后 重置抽奖 清除它们。

设置与抽奖相同，但将抽奖模式 关闭。观众用你设置的命令参加。

版主聊天命令

开启 启用候补队列控制命令 让版主、主播和管理员通过聊天控制队列。

!wlstop · !wlremove · !wlreset · !wlpick · !wlhighlight

部分命令接受数字，例如 !wlpick 3 或 !wlremove 2.
