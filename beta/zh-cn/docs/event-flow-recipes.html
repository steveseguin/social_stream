Event Flow 的用途

通过 Stream Deck 按键或 HTTP/WebSocket/P2P API 调用运行自定义工作流.

Event Flow 是高级自动化编辑器。当弹出菜单中的开关无法满足需求时，可用它过滤聊天、触发媒体、转发消息、调用 webhook 或控制 OBS。

开始任何示例前

  1. 使用一个测试平台和一个 Social Stream 会话。
  2. 打开停靠面板，确认能收到聊天。
  3. 打开 actions.html?session=YOUR_SESSION ，适用于示例播放音频、媒体或控制 OBS 的情况。
  4. 正式开播前，使用模拟消息或安全的触发条件测试。
  5. 进行大幅编辑前，先导出一个正常工作的流程。

这是最常见的实用 Event Flow 模式：匹配一个奖励，然后通过 Flow Actions 播放媒体。

完整深入说明： Kick 奖励声音/媒体指南.

常见解决办法

  • 没有反应： 先确认来源事件到达停靠面板。
  • 音频或媒体不播放： 保持 actions.html 使用相同会话保持打开，然后检查 Event Flow 媒体托管指南.
  • OBS 操作失败： 检查 OBS WebSocket v5、端口 4455、密码和权限。
  • 流程触发过于频繁： 添加更严格的平台、事件、关键词或用户过滤器。
