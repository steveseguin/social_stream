五步展示 Shopify 商品

  1. 在 Social Stream Ninja 中，打开 变现 → Shopify 购买 → 设置.
  2. 输入商店地址，例如 your-store.myshopify.com。不需要密钥。
  3. 打开 导入商品，粘贴商品公开链接并点击 加载商品详情.
  4. 检查名称、图片、价格和链接，然后点击 添加商品或链接.
  5. 开启 商品与支持链接 并点击 保存设置.
商品无法加载？ 添加一个 公开 Storefront 令牌 （通过 Shopify 的 Headless 渠道创建，并将商品发布到该渠道和 Online Store）。切勿粘贴 Admin API 或私有令牌。
导入填充的内容
  • 一次加载一个商品。
  • 令牌用于单次请求后清除。
  • 链接使用 Shopify 的公开商店地址，若 Shopify 提供自定义域名也可包含在内。
  • 只有所有款式价格相同时才填入价格，否则留空。请只填写准确价格。
  • 这是快照。价格和库存不会自行更新，商店变化时请核对。
  • 不可用商品，以及没有公开 Online Store 链接的商品，无法导入。
  • 也可随时手动输入商品。

有人购买时收到提醒

尚未启用。 购买提醒需要 SSN 服务器的 Shopify 接收器，实际商店测试通过前保持关闭。在此之前， 保存设置 会报错，但商品展示仍可使用。
  1. 在 Shopify 中进入 设置 → 通知 → Webhooks。找到 Webhook 的 签名密钥。（这不是 Storefront 令牌。）
  2. 在 Social Stream Ninja 中，打开 变现 → Shopify 购买 → 设置.
  3. 输入您的 myshopify.com 地址和签名密钥。
  4. 开启 Shopify 购买 并点击 保存设置.
  5. 点击 复制接收器 URL.
  6. 在 Shopify 创建 Webhook。事件： 订单付款。格式： JSON。URL 为接收器 URL。
  7. 选择稳定 API 版本并保存，SSN 按 2026-07 版本开发。
  8. 保持 Social Stream Ninja 运行。
是否正常工作？ 查看状态行：waiting、test received、event skipped 或 purchase received。拥有接收器 URL 只代表配置已保存。

  • 签名密钥加密保存在 SSN 接收器中。保存后输入框清空。
  • 另一个私有读取密钥保留在本机。
  • 两者都不会放入 OBS 链接或观众 QR 码。
  • 接收器验证 Shopify 签名和商店名后才接受订单。
  • Shopify 使用自己的接收器，无需旧版远程 API 控制开关。

放入 OBS

  1. 位于 OBS 覆盖层适用于，选择 商品与支持链接.
  2. 打开 叠加层链接选项 并选择 覆盖层视图: 仅商品展示 （图片、价格、QR 码）、 仅支持卡片 （小型商店链接），或 仅活动提醒 （购买）。
  3. 点击 复制 OBS 链接。作为以下来源添加到 OBS： 浏览器来源，从 800 × 600 开始，每种视图使用一个来源。
  4. 在最终直播显示尺寸下用手机扫描 QR 码。

购买提醒为什么没有图片？ Shopify 订单没有可靠的图片，因此购买提醒只显示文字，绝不借用商品卡片的图片或 QR 码。
Event Flow 与捐款目标
  • 在 Event Flow 中选择 Event Type purchase 并将来源／类型筛选为 shopify.
  • 订单金额规则请比较 meta.commerce.orderTotal。检查 meta.commerce.currency 。
  • 购买不是捐款，不带有 hasDonation 或 donoValue，捐款目标也不会增加。
  • 商品卡片标为 Gift 不会改变订单统计。寄给其他人不代表它是送给你的礼物。

安全测试

点击 预览示例 查看外观。它不连接你的会话，因此不会运行 Event Flow、改变累计值或验证付款。完整测试请使用 Shopify 开发商店。标记为以下类型的订单 test: true 只显示在状态中，不产生提醒。

谨慎使用 Shopify 管理后台示例。 未明确标为测试的示例，不要发送到会发放奖励的配置。

等待订单和重复订单的处理方式
  • 允许订单时间最多超前五分钟，以容忍时钟偏差。
  • 不会根据订单创建、发货或库存变化推断付款。缺少测试标志的订单会被跳过。
  • 接收器重启后，状态和等待订单仍保留。
  • 存储空间有限。无法安全存储订单时，接收器会要求 Shopify 稍后重发。
  • 按商店和订单识别重复，即使 Shopify 的投递 ID 不同。
  • SSN 先保存已处理的订单，再确认接收。
