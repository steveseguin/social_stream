第一次使用抽奖？ 先使用 你的第一次抽奖，其中有截图教程。

五步运行免费抽奖

  1. 在弹出菜单中打开 抽奖选项。将 ID 保持为 default ，关键词设为 !enter。票价和积分奖品保持为 0.
  2. 选择一个 获胜者卡片, 姓名滚轴，或 社群转盘。预览后将链接作为以下来源加入 OBS： 浏览器来源.
  3. 点击 开放报名。观众在聊天输入关键词即可报名。
  4. 点击 关闭报名，然后 抽出获胜者。（若忘记关闭，抽奖时会自动关闭报名。）
  5. 点击 新一轮 以再次抽奖，过去中奖者保留在历史中。
保持 Social Stream Ninja 运行。 这会执行抽奖，不需要点击 OBS 来源内部。

旧版独立社区转盘仍可工作，只需将 &managed 从链接中移除。积分和远程控制需要管理型链接。

用 SSN 积分售票

  1. 开启 忠诚度积分系统 ，位于弹出菜单中。这是 SSN 积分，不是 Twitch 频道积分。
  2. 在 Giveaway Options 中打开 票券和积分奖品。设置 每张票的积分 和 每位观众的票数上限.
  3. 点击 开放报名。对于名为以下名称的抽奖， friday，观众可用以下命令购买 5 张票： !ticket friday 5.
  4. 在以下位置查看报名者： 管理抽奖和历史记录.

赠送积分

  1. 开放报名前设置 每位获胜者的积分奖品 和 奖品数量.
  2. 按通常方式开放报名。
  3. 每次抽一名中奖者，并将奖品加入其积分。

奖品积分是新发放的，不从售票收入扣除。最高发放量为奖品积分 × 奖品数量。

已完成的抽奖无法撤销。 修正错误请手动调整该观众积分。重新连接显示页面不会重复发奖。

带积分奖励的游戏

数字寻踪

  1. 把类型设为 数字寻踪（主播控制）, 每张票的积分 0，以及 奖品数量 1，可按需添加积分奖品。
  2. Social Stream 随机选择 1 到 100 的秘密数字。
  3. 玩家用以下命令猜测： !guess friday 50 （使用你的抽奖 ID）。

猜错会缩小所有人的范围，首个猜对者获胜。每位观众每五秒可猜一次。

用抽奖显示页面或 games/numberhunt.html?session=YOUR_SESSION&managed&giveaway=friday。普通游戏不会发放 SSN 积分。

抛硬币奖池

  1. 把类型设为 抛硬币奖池, 每张票的积分 1, 奖品数量 1，以及 每位获胜者的积分奖品 0.
  2. 观众使用以下命令下注： !ticket friday 3 heads 或 !ticket friday 3 tails.
  3. 关闭报名并抽奖。无论下注多少，正反面概率均为 50/50。

赢家拿回自己的下注，并按下注比例分得输家的下注。无费用，也无新积分。例：赢家下注 2 和 1，输家下注 5，总奖池 8 分分为 5 和 3。

两边都必须有人，否则拒绝抽奖。抽奖前取消可退还给所有人。

剩余零散积分如何分配

余下积分先给小数份额最大的人，相同则先报名者优先。

同时运行多个抽奖

  • 分别设置简短的 抽奖 ID （字母、数字、 -, _），并添加 &giveaway=ID 添加到它的 OBS 链接。
  • 购票和猜测命令需指明抽奖名称，例如 !ticket friday 5.
  • 每个免费抽奖使用独立关键词，共用关键词不会同时报名两个抽奖。
  • 所有票都从观众同一个积分余额扣除。
弹出菜单设置新轮次。当前轮次的实际规则请看管理器，编辑 OBS 链接只改变外观。

OBS 显示页面

  • 使用一个 1280 × 720 Browser Source。背景透明，除非选择 主题面板.
  • 转盘最多显示 120 个名字，但中奖者从所有票中抽取。
  • 重连后显示保存的结果，减少动态效果设置会跳过动画。
  • Social Stream 无法判断 OBS 场景是否正在直播。

Event Flow

  1. 添加 抽奖 / 票券 操作（位于积分操作下）。
  2. 选择操作：免费报名、买票、赠送免费票、关闭报名、抽中奖者、取消并退款、查询状态。
  3. 选择抽奖 ID 和票数。奖池模式还需选正面或反面。
“购买票券”本身已经花费积分。 不要在前面放 Spend Points 操作。

它代表发消息的观众操作。发放或主持控制前要放可信触发条件或筛选器。

Stream Deck 与 API

Stream Deck 插件包含： 开放抽奖, 关闭抽奖, 抽取中奖者, 取消并退款, 新抽奖轮次，以及 抽奖状态.

  • 它们使用 default 抽奖。另一个抽奖需把 {"giveawayId":"friday"} 填入值字段。Open giveaway 也接受 config 对象内。
  • 按键确认 Social Stream 已回复，不代表 OBS 已显示。超时后先检查状态，再次抽奖。
通过 API 买票 
{"protocol":2,"action":"buygiveawaytickets","get":"callback-1","value":{"giveawayId":"friday","roundId":"ROUND_ID","operationId":"purchase-123","count":5,"actor":{"chatname":"Avery","type":"youtube","userid":"SOURCE_USER_ID"}}}
  • operationId 标识购买； get 标识回复。
  • 重试保留相同操作 ID，新购买使用新 ID。
主持端 API 权限可花费任意观众的积分，切勿作为公开表单暴露。

历史与备份

管理抽奖和历史记录 显示轮次、报名及中奖者。你可以 导出中奖历史 （JSON），或保存完整积分与抽奖备份。不会上传任何内容。

重启后， 原本开放的轮次恢复为关闭，票仍被冻结。可重新开放、抽奖，或取消并退还。

恢复备份

只适用于 全新主持端 ，其中没有积分或抽奖。

  1. 保持旧主持端关闭，在新的浏览器配置文件中打开 SSN 和抽奖管理器。
  2. 位于 在全新主机上恢复，选择完整备份，等待提示并记下其中的会话 ID。
  3. 在弹出菜单的 会话选项，输入该会话 ID。
  4. 返回管理器，选择抽奖 ID 并点击 刷新。检查规则、报名和中奖者。恢复的轮次为关闭状态。
  5. 重新开放、抽奖或 取消并退款。然后保存新的备份。
切勿同时运行旧主持端和恢复后的主持端。 备份不含保存后的变化，也不含弹出菜单设置。
更多数据存储位置说明
  • 积分保存在此浏览器或应用配置文件中，不与其他地方同步。轮次按会话保存。
  • 清除浏览器数据可能将其删除，请把备份保存在该配置文件之外。
  • 仅导入余额不能恢复冻结的票。票处于冻结时无法重置积分，重置也不会清除抽奖历史。
  • 未确认的贴纸购买在超时后解冻。
  • 没有云备份或提现。以后可能加入服务器备份。
