创建测试消息

向 Social Stream 会话发送可控的模拟消息和事件。

此工具的作用

此 创建测试消息页面 将模拟 Social Stream 载荷发送到停靠面板、叠加层、提醒或 Event Flow 设置。用它测试，无需等待真实聊天消息、打赏、会员、突袭、奖励或其他事件。

尽可能使用测试会话。 提交的消息会像传入的会话流量一样运行，可能触发提醒、声音、webhook、OBS 操作或其他自动化。

SSApp 或扩展快速入门

  1. 打开 Social Stream Ninja，并确认服务处于活动状态。
  2. 位于 全局设置和工具 → 工作机制，启用 扩展的远程 API 控制。SSApp 使用相同的设置名称。
  3. 从 Social Stream 或以下位置复制会话 ID： session= 值，位于停靠面板或叠加层 URL 中。
  4. 打开 创建测试消息 并输入该会话 ID。
  5. 将 发送方式（Send Via） 设为 扩展 API 接收（Extension API ingest） 用于普通测试。
  6. 选择预设、调整字段，然后选择 加载预设（Load Preset）.
  7. 检查 Payload JSON，然后选择 提交（Submit）.
  8. 确认项目出现在停靠面板或目标叠加层中，并且预期的自动化已运行。

可以在 URL 中包含会话： createtestmessage.html?session=YOUR_SESSION_ID.

示例：一条模拟的 1,000 KICKs 消息

这会创建一条价值 1,000 KICKs 的 Kick 样式支持消息，不会创建 1,000 条独立消息。

  1. 选择 聊天消息（Chat Message） 预设。
  2. 设置 输入 为 Kick.
  3. 输入测试名称和消息。
  4. 设置 含打赏（Has Donation） 为 1000 KICKs.
  5. 选择 从字段更新 JSON（Update JSON from Fields），检查 JSON 并提交。

最小载荷为：

{
  "type": "kick",
  "chatname": "Test Supporter",
  "chatmessage": "Thanks for the stream!",
  "hasDonation": "1000 KICKs"
}

使用 聊天消息（Chat Message） 用于本示例。 打赏 / Cheer 预设包含 Twitch 专属的 cheer 字段。

使用预设和自定义 JSON

预设为常见情况提供起始载荷，例如打赏、订阅者、赠送订阅、突袭、奖励、观众更新、首次聊天者和列车事件。

  • 加载预设（Load Preset） 使用所选预设和当前字段值替换 JSON。
  • 从字段更新 JSON（Update JSON from Fields） 根据可见字段构建基本消息。
  • 您可以直接编辑 载荷 JSON（Payload JSON） 以测试特定字段或事件结构。
  • hasDonation 携带可见的支持金额，例如 1000 KICKs 或 $10.00.
  • 仅包含 event 当测试真实的命名事件时。普通打赏样式聊天行可以使用 hasDonation 本身。

有关字段定义和真实平台示例，请参阅 事件参考.

选择正确的交付模式

发送方式（Send Via）适用场景必要设置
扩展 API 接收（Extension API ingest）测试普通停靠面板、叠加层、提醒、Event Flow 或 SSApp。相同的会话 ID，以及 扩展的远程 API 控制 已启用。
直接发送到通道 1目标停靠面板打开时使用了 &server.目标必须监听匹配的服务器通道。
直接发送到通道 4测试使用以下设置的目标： &server2，包括兼容的事件页面。目标必须监听匹配的服务器通道。

如果不确定，使用 扩展 API 接收（Extension API ingest）.

常见解决办法

  • 没有内容出现： 确认目标页面已打开，并使用相同会话 ID。
  • Extension API ingest 失败： 启用 扩展的远程 API 控制，然后重新加载停靠面板或叠加层并重试。
  • 直接模式显示已发送，但没有内容出现： 使用 Extension API ingest，除非目标 URL 具有匹配的 &server 或 &server2 模式。
  • 触发了错误的事件： 检查 Payload JSON 是否残留其他预设的字段。
  • Kick 测试表现得像 Twitch： 使用 Chat Message 预设，并设置 type 和 hasDonation 如上所示。
  • 自动化运行不止一次： 检查同一会话是否打开了多个停靠面板、操作页面或 Event Flow 实例。
