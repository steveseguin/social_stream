Memoria de usuarios (User Memory)

Recuerda participantes únicos, compruébalos en mensajes posteriores, sortea un ganador y restablece exactamente la lista deseada, sin convertir un rol de plataforma en un estado global permanente.

Una memoria con nombre, muchas herramientas

Un Memoria de usuarios (User Memory) nodo de estado contiene un conjunto aislado de personas. Cada nodo Recordar, Olvidar, Comprobar, Sortear o Borrar selecciona ese nodo de estado. Crea otro nodo Memoria de usuarios cuando necesites una lista independiente; por ejemplo, una para «dio me gusta a la transmisión» y otra para «entró en el sorteo».
Turquesa continuo: este evento se ejecuta después Morado discontinuo: este nodo utiliza esa memoria

Arrastra el pequeño rombo lateral morado a un nodo Memoria de usuarios o elige la memoria por su nombre en las propiedades del nodo. Internamente, la operación guarda el ID del nodo de estado. Seleccionar la memoria resalta todas las operaciones vinculadas, y eliminarla avisa antes de romper esos enlaces.

Configuración

  1. Arrastra Nodos de estado → Memoria de usuarios al lienzo.
  2. Ponle un nombre que describa su lista, como Elegibles por Heart Me, Les gustó la transmisión, o Participantes del sorteo.
  3. Elige Esta sesión de la aplicación o Guardar entre reinicios (Save across restarts).
  4. Añade las comprobaciones y acciones que necesites y vincula cada una a la memoria con nombre mediante su rombo lateral o menú desplegable.
  5. Conecta la ruta normal de eventos con cables turquesa y utiliza Probar flujo (Test Flow) con dos nombres de usuario diferentes antes de transmitir en vivo.

Operaciones disponibles

NodoQué hace
Recordar usuario (Remember User)Añade una vez al usuario del evento actual. La participación repetida aumenta su contador sin añadir entradas duplicadas al sorteo.
Usuario recordado (User Is Remembered)Un activador/comprobación que devuelve verdadero cuando el mensaje actual pertenece a alguien de la memoria seleccionada.
Olvidar usuario (Forget User)Elimina solo al usuario del evento actual.
Elegir usuario aleatorio (Pick Random User)Selecciona un usuario único recordado. Opcionalmente puede eliminar al ganador para que no vuelva a ganar.
Borrar todos los usuarios (Clear All Users)Vacía solo el objeto Memoria de usuarios seleccionado.
Restablecer nodo de estado (Reset State Node)También vacía una Memoria de usuarios cuando esa memoria es el objetivo de restablecimiento seleccionado.
Regla de identidad: los usuarios se identifican por plataforma e ID de usuario. El nombre visible solo se utiliza como alternativa. Un evento anónimo o agregado sin identidad de usuario se ignora de forma segura.

Recetas prácticas

TikTok Heart Me o miembro del equipo → ? TTS

Utiliza el evento de regalo para recordar al remitente; no intentes convertir esa fila de regalo en un rol permanente de «miembro».

Evento de regalo de TikTok + coincidencia con «Heart Me» → AND → Recordar usuario ···→ [Elegibles por Heart Me]
? comando + fuente TikTok + (Miembro del equipo de TikTok O Usuario recordado) → AND → Leer texto ? comando + NO fuente TikTok → AND ────────────────────────────────→ Leer texto
  • Para el estado de equipo/fan de TikTok, elige Rol de usuario → Miembro del equipo de TikTok. Lee directamente los datos entrantes de insignia/nivel de TikTok; no requiere el ajuste visual «tratar como miembros» de la superposición principal de chat.
  • Los datos de regalos varían según el modo de captura. Una configuración habitual es Tipo de evento → Otro: gift más El mensaje contiene: Heart Me. Confirma la fila capturada en Probar flujo/Referencia de eventos y haz coincidir el campo más claro que proporcione tu fuente.
  • Ambas ramas siguen requiriendo el ?, para que las otras plataformas hablen para todos mientras TikTok permanece restringido.

Recuerda a quienes dieron me gusta o participaron

Tipo de evento → Otro: liked → Recordar usuario ···→ [Les gustó la transmisión]

Esto funciona cuando el evento capturado de me gusta o participación identifica a un usuario. Las actualizaciones agregadas de recuentos de me gusta no identifican a nadie y, por tanto, no pueden recordarse. Utiliza una memoria independiente para cada tipo de participación si quieres comprobaciones o sorteos separados.

Sorteo con una entrada por persona

El mensaje empieza por !enter → Recordar usuario ···→ [Participantes del sorteo] Moderador + El mensaje empieza por !draw → AND → Elegir usuario aleatorio ···→ [Participantes del sorteo] Moderador + El mensaje empieza por !resetdraw → AND → Borrar todos los usuarios ···→ [Participantes del sorteo]

Activa Eliminar al usuario seleccionado cuando los ganadores no deban seleccionarse dos veces. En una transmisión pública, protege los comandos de sorteo/restablecimiento con una comprobación de moderador, administrador o usuario exacto.

Restablecimiento y persistencia

Manual

Usa Borrar todos los usuarios ahora (Clear All Users Now) en las propiedades de memoria durante la creación/prueba.

Desde un flujo

Usa Borrar todos los usuarios (Clear All Users) o el genérico Restablecer nodo de estado (Reset State Node), seleccionando la memoria exacta.

Automático

Borra tras inactividad, al iniciar o al detener la transmisión. Un valor de 0 desactiva el restablecimiento por inactividad.

Entre reinicios

Las memorias de sesión empiezan vacías con la aplicación. Las memorias guardadas se recargan hasta que se borre esa memoria concreta.

«Borrar todos» tiene un alcance limitado: significa todos los usuarios de la memoria seleccionada, no todo el estado de Event Flow, ni todos los sorteos, ni todas las memorias de Social Stream Ninja.

Solución de problemas

Falta la línea discontinuaSelecciona la operación y elige una Memoria de usuarios de destino, o arrastra su rombo lateral morado al nodo central de memoria.
La misma persona aparece dos vecesComprueba si los eventos procedían de plataformas distintas. Plataforma + ID de usuario crea deliberadamente identidades independientes.
Un me gusta no añadió a nadieProbablemente el evento no tenía identidad de usuario. Inspecciona sus datos; los recuentos agregados no pueden convertirse en participantes con nombre.
Volvió a aparecer una memoria guardadaUtiliza Borrar todos los usuarios en esa memoria. Cambiar un flujo o borrar otra memoria no la elimina.
Cualquiera puede ejecutar el comando de sorteo/restablecimientoAñade Rol de usuario: moderador/administrador (o una comprobación exacta del usuario anfitrión) a una puerta AND antes de la acción.
