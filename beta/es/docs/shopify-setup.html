Shopify en Social Stream Ninja

Promociona productos públicos con imágenes, precios, enlaces legibles y códigos QR. Recibe notificaciones firmadas de pedidos pagados como compra alertas en el feed de actividad, Multi-Alerts y Event Flow. La promoción de productos funciona independientemente de las alertas de pago.

Conectar compras · Importar productos · Superposiciones de OBS · Prueba de forma segura · Límites y solución de problemas

Disponibilidad: las alertas automáticas requieren que el receptor de Shopify esté desplegado y activado en la API de SSN. Si no está disponible, Guardar configuración informa de un error y no activa Shopify. La importación de productos públicos y la promoción manual funcionan por separado. Esta guía describe el código de integración; todavía se requiere una prueba con un comerciante real antes de afirmar que se validó el servicio en vivo.

Conectar compras pagadas

  1. En Shopify, abre Configuración → Notificaciones → Webhooks. Localiza el secreto de firma mostrado para los webhooks creados manualmente. Es distinto de un token de Storefront.
  2. En SSN, abre Monetización → Compras de Shopify → Configuración. Introduce tu dominio permanente your-store.myshopify.com dominio y secreto de firma del webhook. Activa las compras de Shopify y haz clic en Guardar configuración.
  3. Haz clic en Copiar URL del receptor (Copy receiver URL). En Shopify, crea un webhook con el evento Pago de pedido (Order payment), formato JSON, y esa URL del receptor. Selecciona una versión estable compatible de la API de webhooks; esta integración se desarrolló con el contrato de pedidos 2026-07.
  4. Guarda el webhook de Shopify. Mantén SSN encendido para procesar compras. El receptor verifica el HMAC del cuerpo original y que la tienda coincida antes de aceptar los datos del pedido.

El secreto de firma se cifra en el receptor de SSN y se borra del campo después de guardar. Una clave privada de lectura independiente permanece en este dispositivo. Ninguna se incluye en los enlaces de OBS ni en los códigos QR para espectadores. Shopify utiliza su receptor específico; no se necesita el antiguo interruptor de control remoto de API.

Una URL generada significa que se guardó la configuración, no que Shopify haya entregado nada. El estado distingue entre espera, prueba verificada, evento omitido y compra recibida. Para cambiar de tienda, primero hay que Desconectar. Desactivar Shopify pausa el procesamiento local; Desconectar elimina su receptor y los eventos en cola. Elimina el webhook correspondiente de Shopify al desconectar.

Importar un producto público

  1. Introduce tu myshopify.com dominio en la configuración de Shopify. No necesitas activar alertas de compra ni introducir un secreto de firma para importar productos.
  2. Despliega Importar un producto, pega una URL pública de producto y haz clic en Cargar detalles del producto.
  3. Si el acceso sin token no permite ver el producto, proporciona un token público de Storefront. El canal Headless de Shopify puede crear uno. Publica el producto en ese escaparate y en la Tienda online. No pegues un token de Admin API ni un token privado de Storefront.
  4. SSN abre el editor existente Productos y enlaces de apoyo con el título, la imagen, el precio y el enlace público canónico que devuelve Shopify. Revísalos y haz clic en Añadir producto o enlace, activa el catálogo y Guardar configuración.

La importación lee un producto a la vez mediante Storefront API. El token es opcional, se utiliza solo para esa solicitud y se borra después. La URL canónica de la Tienda online de Shopify se convierte en el enlace público, incluido un dominio personalizado si Shopify lo devuelve. Se excluyen los productos no disponibles y los que no tengan un enlace público de Tienda online.

Solo se rellena el precio cuando coinciden los precios mínimo y máximo de las variantes del producto. De lo contrario queda vacío; elige tú un precio concreto solo si describe la oferta con precisión. La información importada es una instantánea, no una sincronización continua de inventario o precios. Revísala cuando cambie tu tienda. Siempre puedes introducir los productos manualmente.

Utiliza las superposiciones existentes

En Enlace de superposición para, elige Productos y enlaces de apoyo. Usa Solo escaparate de productos para imágenes, precios y códigos QR, Solo tarjeta de apoyo para un pequeño enlace de tienda permanente o periódico, o Solo alertas de actividad para compras. Copia cada enlace de OBS deseado a una fuente de navegador independiente, empezando por 800 × 600.

Configura el filtro opcional de fuente de alertas como shopify para mostrar solo actividad de Shopify en la superposición genérica de monetización. Activa Productos y enlaces de apoyo para esa vista genérica. Multi-Alerts y el feed de actividad existentes reciben compras de Shopify independientemente del catálogo de productos.

Las tarjetas de productos enlazan a páginas públicas de productos. Utiliza Copiar enlace público para compartir la dirección clicable en el chat, y prueba el código QR desde un teléfono al tamaño final de tu transmisión. Una alerta de compra nunca toma el código QR ni la imagen de un producto de la rotación que no esté relacionado. Los webhooks de pedidos no proporcionan URL fiables de imágenes de productos, así que las alertas de compra usan texto; las tarjetas promocionales importadas pueden mostrar imágenes.

Para Event Flow, elige Tipo de evento purchase y filtra la fuente/tipo por shopify. Compara meta.commerce.orderTotal para reglas basadas en el valor del pedido y comprueba meta.commerce.currency antes de comparar importes. Son compras: no se emite hasDonation o donoValue , y las metas de donaciones no aumentan. Una tarjeta promocional etiquetada como Regalo no cambia la clasificación de los eventos de pedidos. Enviar a otra persona no demuestra que sea un regalo para el creador.

Previsualiza y prueba de forma segura

Vista previa de ejemplo abre una superposición de ejemplo aislada sin conexión a una sesión. Nunca activa Event Flow, cambia totales ni verifica un pago.

Los pedidos de Shopify marcados explícitamente como test: true se confirman y se muestran como pruebas en el estado del receptor, sin alertas ni acciones de compra. También se omiten pedidos sin indicador de prueba, sin pagar o parcialmente pagados, cancelados, con total cero y con fechas antiguas o no válidas. Utiliza una tienda de desarrollo para pruebas completas. Una muestra de administración que no tenga un indicador de prueba fiable no debe enviarse a un flujo activo de recompensas; la vista previa de SSN es la comprobación segura de apariencia.

Qué comprobamos sin una tienda

Las pruebas aisladas cubren entregas HTTP reales con JSON Unicode firmado, firmas manipuladas, entregas duplicadas, aislamiento de pedidos de prueba, precisión de monedas, solicitudes demasiado grandes, eliminación de datos privados de clientes y recuperación tras desconexión mediante el entorno real de SSApp. Estas comprobaciones no realizan pedidos ni requieren una cuenta de comerciante.

El receptor de Shopify en producción sigue desactivado hasta realizar una prueba de entrega desde una tienda real. La promoción manual de productos se puede utilizar de forma independiente. Los webhooks de ejemplo de Shopify CLI pueden ayudar a probar el procesamiento de datos, pero no validan suscripciones ni reintentos y siguen requiriendo credenciales de aplicación. Consulta límites de las pruebas de webhooks de Shopify CLI.

Límites de entrega y solución de problemas

  • Receptor no disponible: the SSN API operator must deploy and enable the Shopify receiver. Do not use the legacy unsigned session webhook URL as a substitute.
  • Esperando un evento: verifica Pago de pedido (Order payment), JSON, la URL exacta del receptor, el dominio permanente coincidente de la tienda y el secreto de firma de ese webhook. El webhook de una aplicación personalizada utiliza el secreto de firma de esa aplicación, no el secreto manual de Notificaciones.
  • Evento firmado omitido: esta integración requiere un pedido con importe positivo y totalmente pagado, test: false y un cuerpo firmado updated_at dentro de los últimos siete días (con cinco minutos de tolerancia para relojes adelantados). No deduce que haya pago a partir de la creación del pedido, su preparación o el inventario.
  • SSN estaba desconectado: los eventos aceptados permanecen en cola hasta siete días. Reinicia SSN para continuar. El estado y las tareas pendientes sobreviven al reinicio del receptor. El servicio tiene almacenamiento limitado y pide a Shopify que reintente cuando no puede guardar el trabajo en cola de forma duradera.
  • Duplicados: el receptor elimina duplicados por tienda/pedido, aunque los ID de entrega de Shopify sean diferentes. Los registros de deduplicación duran siete días. SSN guarda los ID procesados antes de confirmarlos. Un fallo entre una acción externa y ese guardado todavía puede repetir la acción; utiliza tu propia protección de idempotencia para automatizaciones con consecuencias.
  • Falta el nombre del comprador: es intencional. SSN excluye nombres de clientes, correos electrónicos, direcciones, notas de pedidos, propiedades personalizadas de artículos, URL de pago e ID de pedidos sin procesar. Los títulos públicos de productos se mantienen como texto sin formato.
  • Reembolsos o cambios en pedidos: es un feed de alertas en vivo, no un sistema de contabilidad ni de gestión de pedidos. Los reembolsos, cancelaciones y cambios de total no revierten alertas anteriores. No incluye conciliación del historial de pedidos ni eliminación automática de productos.
