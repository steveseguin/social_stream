Explicación de servidores y servicios locales

Social Stream Ninja utiliza varios servicios locales diferentes. Elige el que corresponda a lo que quieres hacer.

1. Activar servidor local

Esta opción del menú Archivo inicia dentro de la aplicación un retransmisor WebSocket que distingue salas y canales. Las páginas compatibles de Social Stream pueden utilizarlo para intercambiar chat y comandos en la misma computadora. Es un endpoint alternativo para el enrutamiento de servidor específico de cada página.

No aloja el sitio web de Social Stream, no captura una plataforma por sí solo ni proporciona la API HTTP de automatización. Empieza por la guía de Activar servidor local.

2. API de control local y MCP

Esta API local opcional permite a los programas de la computadora con SSApp administrar las fuentes y los ajustes compatibles, consultar el estado y los diagnósticos, inspeccionar ventanas de la aplicación o de fuentes y seguir los eventos capturados. El adaptador MCP incluido presenta esas operaciones como herramientas a los clientes de IA compatibles.

Actívalo en Archivo > IA local / Automatización (File > Local AI / Automation). Es independiente de Habilitar servidor local (Enable Local Server). Consulta la guía de API de control local y MCP.

3. Servidor doméstico o VPS sin interfaz

El modo sin interfaz ejecuta la aplicación de escritorio Electron completa con sus ventanas de fuentes ocultas. En Linux sigue necesitando un sistema de pantalla como Xvfb. Resulta útil cuando una computadora dedicada debe seguir capturando chat sin un monitor conectado.

El modo sin interfaz no crea una API de control pública. El control remoto utiliza el transporte WebRTC o WebSocket habitual de Social Stream. Consulta la guía de alojamiento sin interfaz.

4. Servidor multimedia local

La aplicación de escritorio lo inicia automáticamente cuando hay archivos multimedia locales de Event Flow disponibles. Solo sirve archivos aprobados mediante SSApp y determinados recursos de ejecución, a través de una ruta con un token aleatorio por perfil.

No es un servidor web ni de archivos de uso general. Consulta Archivos multimedia para Event Flow para elegir entre archivos locales, subidas y alojamiento en la nube.

La alternativa de servidor es diferente

Ajustes como Enviar mensajes de chat al servidor API y El panel envía sus comandos a la extensión mediante el servidor deciden cómo se dirigen el chat y los comandos. Sus parámetros de URL generados incluyen server, server2, y server3.

Esos ajustes normalmente utilizan el servicio WebSocket alojado de Social Stream. Cuando una página compatible también tiene localserver, utiliza en su lugar el retransmisor local de la aplicación de escritorio. Consulta Sesiones, contraseñas, retransmisión y modos de servidor para los controles de enrutamiento.

Utiliza enlaces recién generados. Los parámetros de enrutamiento dependen de cada página. No copies un parámetro de servidor de una página a otra suponiendo que significa lo mismo.

Otros puertos locales temporales

Algunos procesos de inicio de sesión y vinculación de cuentas abren brevemente un puerto de retorno local y lo cierran al terminar. Estos receptores temporales no son servidores generales de SSN ni API de automatización.
