Crear mensajes de prueba (Create Test Messages)

Envía mensajes y eventos ficticios controlados a tu sesión de Social Stream.

Qué hace esta herramienta

El página Crear mensaje de prueba envía datos sintéticos de Social Stream a tu Dock, superposiciones, alertas o configuración de Event Flow. Úsala para probar sin esperar a un mensaje de chat, donación, membresía, raid, recompensa u otro evento real.

Usa una sesión de prueba cuando sea posible. Un mensaje enviado se comporta como tráfico entrante de la sesión y puede activar alertas, sonidos, webhooks, acciones de OBS u otras automatizaciones.

Inicio rápido para SSApp o la extensión

  1. Abre Social Stream Ninja y asegúrate de que el servicio esté activo.
  2. En Ajustes y herramientas globales → Funcionamiento, activa control remoto de la extensión mediante API (remote API control of extension). SSApp usa el mismo nombre de ajuste.
  3. Copia tu ID de sesión desde Social Stream o desde el session= en la URL del Dock o la superposición.
  4. Abrir Crear mensaje de prueba (Create Test Message) y escribe ese ID de sesión.
  5. Deja Enviar mediante (Send Via) establecido en Entrada por API de extensión (Extension API ingest) para las pruebas normales.
  6. Elige una configuración predefinida, ajusta sus campos y selecciona Cargar configuración predefinida (Load Preset).
  7. Revisa el JSON de datos y luego selecciona Enviar (Submit).
  8. Confirma que el elemento aparezca en el Dock o la superposición de destino y que se ejecute la automatización prevista.

Puedes incluir la sesión en la URL: createtestmessage.html?session=YOUR_SESSION_ID.

Ejemplo: un mensaje ficticio de 1000 KICKs

Esto crea un mensaje de apoyo de estilo Kick por valor de 1000 KICKs. No crea 1000 mensajes separados.

  1. Elige el Mensaje de chat (Chat Message) como configuración predefinida.
  2. Configura Escribe a Kick.
  3. Introduce un nombre y un mensaje de prueba.
  4. Configura Tiene donación (Has Donation) a 1000 KICKs.
  5. Selecciona Actualizar JSON desde los campos (Update JSON from Fields), verifica el JSON y envíalo.

Los datos mínimos son:

{
  "type": "kick",
  "chatname": "Test Supporter",
  "chatmessage": "Thanks for the stream!",
  "hasDonation": "1000 KICKs"
}

Usa Mensaje de chat (Chat Message) para este ejemplo. La configuración Donación / Cheer incluye campos de Cheers específicos de Twitch.

Usar configuraciones predefinidas y JSON personalizado

Las configuraciones predefinidas proporcionan datos iniciales para casos comunes, como donaciones, suscriptores, suscripciones regaladas, raids, recompensas, actualizaciones de espectadores, primeras intervenciones y eventos de tren.

  • Cargar configuración predefinida (Load Preset) sustituye el JSON por la configuración predefinida seleccionada y los valores actuales de los campos.
  • Actualizar JSON desde los campos (Update JSON from Fields) crea un mensaje básico a partir de los campos visibles.
  • Puedes editar JSON de datos (Payload JSON) directamente al probar un campo o una estructura de evento concretos.
  • hasDonation contiene el importe de apoyo visible, como 1000 KICKs o $10.00.
  • Incluye solo event cuando pruebes un evento real con nombre. Una fila de chat normal con donación puede usar hasDonation por sí solo.

Para las definiciones de campos y ejemplos reales de plataformas, consulta la Referencia de eventos.

Soluciones habituales

  • No aparece nada: confirma que la página de destino esté abierta y use el mismo ID de sesión.
  • Falla la entrada por API de extensión: activa control remoto de la extensión mediante API (remote API control of extension), luego recarga el Dock o la superposición y vuelve a intentarlo.
  • El modo directo indica enviado, pero no aparece nada: usa Entrada por API de extensión salvo que la URL de destino tenga el correspondiente &server o &server2 como modo.
  • Se activa el evento equivocado: revisa el JSON de datos por si quedan campos de otra configuración predefinida.
  • La prueba de Kick se comporta como Twitch: usa la configuración Mensaje de chat y establece type y hasDonation como se muestra arriba.
  • Una automatización se ejecuta más de una vez: comprueba si hay varios docks, páginas de acciones o instancias de Event Flow abiertas en la misma sesión.
