หน่วยความจำผู้ใช้ (User Memory)

จดจำผู้เข้าร่วมแบบไม่ซ้ำ ตรวจสอบเมื่อมีข้อความภายหลัง สุ่มผู้ชนะ และรีเซ็ตเฉพาะรายการที่ต้องการ โดยไม่เปลี่ยนบทบาทบนแพลตฟอร์มให้เป็นสถานะส่วนกลางถาวร

วิธีทำงาน ตั้งค่า ตัวอย่างใช้งาน การรีเซ็ตและการเก็บถาวร ผลลัพธ์การสุ่ม

หน่วยความจำชื่อเดียว ใช้ได้กับหลายเครื่องมือ

หนึ่ง หน่วยความจำผู้ใช้ (User Memory) เป็นโหนดสถานะที่เก็บชุดรายชื่อแยกหนึ่งชุด ทุกโหนด Remember, Forget, Check, Draw หรือ Clear จะเลือกโหนดสถานะนั้น สร้างโหนด User Memory อีกอันเมื่อต้องการรายการแยก เช่น อันหนึ่งสำหรับ “กดถูกใจสตรีม” และอีกอันสำหรับ “เข้าร่วมแจกของรางวัล”
เส้นทึบสีเขียวอมฟ้า: เหตุการณ์นี้ทำงานถัดไป เส้นประสีม่วง: โหนดนี้ใช้หน่วยความจำนั้น

ลากจุดข้าวหลามตัดสีม่วงเล็ก ๆ ด้านข้างไปยังโหนด User Memory หรือเลือกหน่วยความจำตามชื่อในคุณสมบัติโหนด ภายในระบบ การดำเนินการจะเก็บรหัสโหนดสถานะไว้ เมื่อเลือกหน่วยความจำ การดำเนินการที่เชื่อมทั้งหมดจะถูกเน้น และเมื่อจะลบจะมีคำเตือนก่อนตัดลิงก์เหล่านั้น

ตั้งค่า

  1. ลาก โหนดสถานะ (State Nodes) → User Memory ลงบนแคนวาส
  2. ตั้งชื่อให้ตรงกับรายการที่หน่วยความจำนั้นเก็บ เช่น ผู้มีสิทธิ์ Heart Me, กดถูกใจสตรีมแล้ว, หรือ ผู้เข้าร่วมสุ่มรางวัล.
  3. เลือก เซสชันแอปนี้ หรือ บันทึกไว้ข้ามการเริ่มใหม่.
  4. เพิ่มการตรวจสอบและแอ็กชันที่ต้องการ แล้วเชื่อมแต่ละรายการกับหน่วยความจำที่มีชื่อ โดยใช้จุดข้าวหลามตัดด้านข้างหรือรายการแบบเลื่อนลง
  5. เชื่อมเส้นทางเหตุการณ์ปกติด้วยเส้นสีเขียวอมฟ้า และใช้ ทดสอบโฟลว์ (Test Flow) ด้วยชื่อผู้ใช้สองชื่อที่ต่างกันก่อนเริ่มไลฟ์

การดำเนินการที่มี

โหนดทำอะไร
จดจำผู้ใช้ (Remember User)เพิ่มผู้ใช้ของเหตุการณ์ปัจจุบันครั้งเดียว การเข้าร่วมซ้ำจะเพิ่มจำนวนครั้งการเข้าร่วมของผู้ใช้นั้น โดยไม่เพิ่มชื่อซ้ำในรายการสุ่ม
ผู้ใช้ถูกจดจำแล้ว (User Is Remembered)ทริกเกอร์/การตรวจสอบที่คืนค่า true เมื่อข้อความปัจจุบันเป็นของคนในหน่วยความจำที่เลือก
ลืมผู้ใช้ (Forget User)นำเฉพาะผู้ใช้ของเหตุการณ์ปัจจุบันออก
สุ่มเลือกผู้ใช้ (Pick Random User)เลือกผู้ใช้หนึ่งคนจากรายชื่อที่จดจำแบบไม่ซ้ำ สามารถเลือกให้นำผู้ชนะออกเพื่อไม่ให้ชนะซ้ำได้
ล้างผู้ใช้ทั้งหมด (Clear All Users)ล้างเฉพาะออบเจ็กต์ User Memory ที่เลือก
รีเซ็ตโหนดสถานะ (Reset State Node)ล้าง User Memory ด้วย เมื่อเลือกหน่วยความจำนั้นเป็นเป้าหมายรีเซ็ต
กฎตัวตน: ใช้แพลตฟอร์มรวมกับรหัสผู้ใช้เป็นคีย์ของผู้ใช้ ชื่อผู้ใช้ที่แสดงใช้เป็นตัวสำรองเท่านั้น เหตุการณ์แบบไม่ระบุตัวตนหรือยอดรวมที่ไม่มีตัวตนผู้ใช้จะถูกข้ามอย่างปลอดภัย

ตัวอย่างการใช้งานจริง

TikTok Heart Me หรือ Team Member → ? TTS

ใช้เหตุการณ์ของขวัญเพื่อจดจำผู้ส่ง อย่าพยายามเปลี่ยนแถวของขวัญหนึ่งแถวให้เป็นบทบาท “สมาชิก” ถาวร

เหตุการณ์ของขวัญ TikTok + ตรงกับ “Heart Me” → AND → Remember User ···→ [Heart Me Eligible]
คำสั่ง ? + แหล่งข้อมูล TikTok + (TikTok Team Member OR User Is Remembered) → AND → Speak Text คำสั่ง ? + NOT แหล่งข้อมูล TikTok → AND ────────────────────────────────→ Speak Text
  • สำหรับสถานะ TikTok Team/Fan ให้เลือก บทบาทผู้ใช้ (User Role) → TikTok Team Member โดยอ่านข้อมูลป้าย/ระดับของ TikTok ขาเข้าโดยตรง ไม่ต้องใช้การตั้งค่าแสดงผล “treat as members” ของ Main Chat Overlay
  • เพย์โหลดของขวัญต่างกันตามโหมดเก็บข้อมูล การตั้งค่าที่พบบ่อยคือ ประเภทเหตุการณ์ (Event Type) → Other: gift พร้อม ข้อความมีคำว่า (Message Contains): Heart Me ตรวจสอบแถวที่เก็บได้ใน Test Flow/Event Reference แล้วจับคู่กับฟิลด์ที่ชัดเจนที่สุดที่แหล่งข้อมูลของคุณให้มา
  • ทั้งสองสาขายังต้องมี ?เพื่อให้แพลตฟอร์มอื่นอ่านเสียงให้ทุกคน ขณะที่ TikTok ยังคงจำกัดไว้

จดจำคนที่กดถูกใจหรือเข้าร่วม

ประเภทเหตุการณ์ (Event Type) → Other: liked → Remember User ···→ [Liked Stream]

วิธีนี้ใช้ได้เมื่อเหตุการณ์ถูกใจ/เข้าร่วมที่เก็บมาระบุผู้ใช้ การอัปเดตจำนวนถูกใจรวมไม่ระบุตัวบุคคล จึงจดจำไม่ได้ ใช้หน่วยความจำแยกสำหรับการเข้าร่วมแต่ละประเภท หากต้องการตรวจสอบหรือสุ่มแยกกัน

สุ่มรางวัลจากรายชื่อไม่ซ้ำ

Message Starts With !enter → Remember User ···→ [Prize Draw Entrants] Moderator + Message Starts With !draw → AND → Pick Random User ···→ [Prize Draw Entrants] Moderator + Message Starts With !resetdraw → AND → Clear All Users ···→ [Prize Draw Entrants]

เปิดใช้ นำผู้ใช้ที่เลือกออก เมื่อไม่ต้องการให้สุ่มผู้ชนะเดิมซ้ำ ในสตรีมสาธารณะ ให้ป้องกันคำสั่งสุ่ม/รีเซ็ตด้วยการตรวจสอบผู้ดูแลแชต ผู้ดูแลระบบ หรือผู้ใช้ที่ระบุ

ดาวน์โหลดโฟลว์ตัวอย่างการเข้าร่วม + การสุ่ม

การรีเซ็ตและการเก็บถาวร

ด้วยตนเอง

ใช้ ล้างผู้ใช้ทั้งหมดตอนนี้ (Clear All Users Now) ในคุณสมบัติหน่วยความจำขณะสร้าง/ทดสอบ

จากโฟลว์

ใช้ ล้างผู้ใช้ทั้งหมด (Clear All Users) หรือแบบทั่วไป รีเซ็ตโหนดสถานะ (Reset State Node) แล้วเลือกหน่วยความจำที่ต้องการให้ตรง

อัตโนมัติ

ล้างเมื่อไม่มีการใช้งาน เมื่อเริ่มสตรีม หรือเมื่อหยุดสตรีม ค่า 0 ปิดการรีเซ็ตเมื่อไม่มีการใช้งาน

ข้ามการเริ่มใหม่

หน่วยความจำระดับเซสชันเริ่มว่างเมื่อเปิดแอป ส่วนหน่วยความจำที่บันทึกไว้จะโหลดกลับมาจนกว่าจะล้างหน่วยความจำนั้นโดยเฉพาะ

“ล้างทั้งหมด” มีขอบเขต: หมายถึงผู้ใช้ทั้งหมดในหน่วยความจำที่เลือก ไม่ใช่สถานะ Event Flow ทั้งหมด ไม่ใช่ทุกการสุ่ม และไม่ใช่ทุกหน่วยความจำใน Social Stream Ninja

ใช้ผลลัพธ์การสุ่มและการเข้าร่วม

แอ็กชันหน่วยความจำเพิ่มฟิลด์ให้ข้อความ เพื่อให้ Show Text, Send Message, เว็บฮุก หรือแอ็กชันกำหนดเองถัดไปนำไปใช้ได้

ช่องข้อมูลความหมาย
userMemoryNameชื่อหน่วยความจำที่เลือก
userMemoryCountจำนวนผู้ใช้ไม่ซ้ำที่จดจำอยู่
userMemoryAddedเป็น true เฉพาะเมื่อ Remember User เพิ่มบุคคลใหม่ที่ยังไม่เคยมี
userMemoryEntryCountจำนวนครั้งที่คนนั้นเข้าร่วม
selectedUserชื่อที่แสดงของผู้ใช้ที่สุ่มได้
selectedUserId, selectedUserSourceรหัสคงที่และแพลตฟอร์มของผู้ใช้ที่สุ่มได้
selectedUserParticipationCountจำนวนครั้งการเข้าร่วมที่บันทึกไว้ของผู้ชนะ
selectedUserReasonเทมเพลตเหตุผลล่าสุดที่ Remember User บันทึก
selectedUserRemovedการสุ่มได้นำผู้ชนะที่เลือกออกหรือไม่

การแก้ปัญหา

เส้นประหายไปเลือกการดำเนินการแล้วเลือกเป้าหมาย User Memory หรือลากจุดข้าวหลามตัดสีม่วงด้านข้างไปยังศูนย์กลางหน่วยความจำ
คนเดียวกันปรากฏสองครั้งตรวจสอบว่าเหตุการณ์มาจากคนละแพลตฟอร์มหรือไม่ แพลตฟอร์ม + รหัสผู้ใช้ตั้งใจให้สร้างตัวตนแยกกัน
การกดถูกใจไม่ได้เพิ่มใครเหตุการณ์นั้นอาจไม่มีตัวตนผู้ใช้ ตรวจสอบเพย์โหลดเหตุการณ์ ยอดรวมไม่สามารถเปลี่ยนเป็นผู้เข้าร่วมที่มีชื่อได้
หน่วยความจำที่บันทึกไว้กลับมาอีกใช้ Clear All Users กับหน่วยความจำนั้น การเปลี่ยนโฟลว์หรือล้างหน่วยความจำอื่นจะไม่ลบหน่วยความจำนี้
ใครก็เรียกคำสั่งสุ่ม/รีเซ็ตได้เพิ่ม User Role: moderator/admin (หรือตรวจสอบผู้ดำเนินรายการตามผู้ใช้ที่ระบุ) ในเกต AND ก่อนแอ็กชัน
