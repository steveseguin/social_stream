แสดงสินค้าและการซื้อจาก Shopify ของคุณ

แสดงสินค้าพร้อม QR และรับแจ้งเตือนเมื่อมีคนซื้อ

แสดงสินค้า แจ้งเตือนการซื้อ เพิ่มใน OBS ทดสอบอย่างปลอดภัย แก้ปัญหา

แสดงสินค้า Shopify ใน 5 ขั้นตอน

  1. ใน Social Stream Ninja เปิด Monetization → Shopify purchases → Setup.
  2. พิมพ์ที่อยู่ร้านค้า เช่น your-store.myshopify.com ไม่ต้องใช้ secret
  3. เปิด นำเข้าสินค้า วางลิงก์สาธารณะของสินค้า แล้วคลิก โหลดรายละเอียดสินค้า.
  4. ตรวจชื่อ รูปภาพ ราคา และลิงก์ แล้วคลิก เพิ่มสินค้าหรือลิงก์.
  5. เปิด สินค้าและลิงก์สนับสนุน แล้วคลิก บันทึกการตั้งค่า.
โหลดสินค้าไม่ได้? เพิ่ม โทเคน Storefront สาธารณะ (สร้างผ่านช่องทาง Headless ของ Shopify แล้วเผยแพร่สินค้าทั้งที่นั่นและ Online Store) ห้ามวาง Admin API หรือโทเคนส่วนตัว
การนำเข้ากรอกอะไรให้
  • โหลดครั้งละหนึ่งสินค้า
  • ใช้โทเคนสำหรับคำขอนั้นครั้งเดียวแล้วล้าง
  • ลิงก์นี้เป็นลิงก์ร้านค้าสาธารณะของ Shopify รวมโดเมนของคุณเองหาก Shopify ให้มา
  • ระบบกรอกราคาเฉพาะเมื่อทุกตัวเลือกสินค้าราคาเท่ากัน มิฉะนั้นจะเว้นว่าง เพิ่มราคาเฉพาะเมื่อถูกต้อง
  • เป็นข้อมูล ณ เวลานั้น ราคาและสต็อกไม่อัปเดตเอง จึงควรตรวจเมื่อร้านค้ามีการเปลี่ยนแปลง
  • นำเข้าสินค้าที่ไม่พร้อมขายหรือไม่มีลิงก์ Online Store สาธารณะไม่ได้
  • คุณพิมพ์ข้อมูลสินค้าเองแทนได้เสมอ

การยืนยันตัวตน Shopify Storefront · คำค้นสินค้า · สร้างโทเคนสาธารณะด้วย Headless

รับแจ้งเตือนเมื่อมีคนซื้อ

ยังไม่เปิดใช้ แจ้งเตือนการซื้อต้องใช้ตัวรับ Shopify บนเซิร์ฟเวอร์ SSN ซึ่งยังปิดอยู่จนกว่าจะผ่านการทดสอบกับร้านค้าจริง ระหว่างนี้ บันทึกการตั้งค่า แสดงข้อผิดพลาด แต่การแสดงสินค้ายังทำงานได้
  1. ใน Shopify ไปที่ Settings → Notifications → Webhooks ค้นหา webhook secret สำหรับลงลายเซ็น (นี่ไม่ใช่โทเคน Storefront)
  2. ใน Social Stream Ninja เปิด Monetization → Shopify purchases → Setup.
  3. ป้อน myshopify.com และ secret สำหรับลงลายเซ็น
  4. เปิด การซื้อจาก Shopify แล้วคลิก บันทึกการตั้งค่า.
  5. คลิก คัดลอก URL ตัวรับ.
  6. ใน Shopify สร้าง webhook เหตุการณ์: การชำระคำสั่งซื้อ (Order payment) รูปแบบ: JSON URL: URL ของตัวรับ
  7. เลือกรุ่น API ที่เสถียรแล้วบันทึก (SSN พัฒนาโดยอิงรุ่น 2026-07)
  8. เปิด Social Stream Ninja ไว้
ทำงานอยู่หรือไม่ ดูบรรทัดสถานะ: waiting, test received, event skipped หรือ purchase received การมี URL ตัวรับหมายถึงบันทึกการตั้งค่าแล้วเท่านั้น
ฉันต้องการ…ทำตามนี้
พักแจ้งเตือนปิด การซื้อจาก Shopify.
หยุดถาวรหรือเปลี่ยนร้านค้าคลิก ยกเลิกการเชื่อมต่อ Shopify (ลบตัวรับและเหตุการณ์ที่รออยู่) ลบ webhook ใน Shopify ด้วย
secret ของคุณเก็บที่ไหน
  • secret สำหรับลงลายเซ็นเก็บแบบเข้ารหัสที่ตัวรับ SSN ช่องจะว่างหลังบันทึก
  • คีย์อ่านข้อมูลส่วนตัวแยกต่างหากเก็บอยู่ในคอมพิวเตอร์นี้
  • ข้อมูลทั้งสองอย่างไม่ถูกใส่ในลิงก์ OBS หรือรหัส QR ของผู้ชม
  • ตัวรับตรวจลายเซ็น Shopify และชื่อร้านค้าก่อนรับคำสั่งซื้อ
  • Shopify มีตัวรับของตัวเอง จึงไม่ต้องเปิดสวิตช์ Remote API Control แบบเก่า

Shopify: สร้างเว็บฮุกด้วยตนเอง · Shopify: ตรวจสอบการส่ง

เพิ่มใน OBS

  1. ใน โอเวอร์เลย์ OBS สำหรับ เลือก สินค้าและลิงก์สนับสนุน.
  2. เปิด ตัวเลือกลิงก์โอเวอร์เลย์ แล้วเลือก มุมมองโอเวอร์เลย์: เฉพาะแสดงสินค้า (รูปภาพ ราคา รหัส QR), เฉพาะการ์ดสนับสนุน (ลิงก์ร้านค้าขนาดเล็ก) หรือ เฉพาะการแจ้งเตือนกิจกรรม (การซื้อ)
  3. คลิก คัดลอกลิงก์ OBS เพิ่มใน OBS เป็น แหล่งเบราว์เซอร์ (Browser Source) เริ่มที่ 800 × 600 ใช้หนึ่งแหล่งภาพต่อหนึ่งมุมมอง
  4. ใช้โทรศัพท์สแกน QR ที่ขนาดจริงที่จะออกสตรีม
ฉันต้องการ…ทำตามนี้
แชร์ลิงก์สินค้าในแชตคลิก คัดลอกลิงก์สาธารณะ ข้างสินค้า
แสดงเฉพาะแจ้งเตือน Shopify ในโอเวอร์เลย์ Monetizationตั้งค่า ตัวกรองแหล่งแจ้งเตือน เป็น shopify ต้องเปิด Products & support links
แสดงการซื้อใน multi-alerts หรือฟีดกิจกรรมไม่ต้องเพิ่มอะไร ระบบรับการซื้อจาก Shopify แม้ไม่มีรายการสินค้า
ทำไมแจ้งเตือนการซื้อไม่มีรูป? คำสั่งซื้อ Shopify ไม่มีรูปภาพที่เชื่อถือได้ แจ้งเตือนจึงมีแต่ข้อความ และจะไม่ยืมรูปหรือ QR จากการ์ดสินค้า
Event Flow และเป้าหมายบริจาค
  • ใน Event Flow เลือก Event Type purchase และกรองแหล่งข้อมูล/ประเภทเป็น shopify.
  • สำหรับกฎตามมูลค่าคำสั่งซื้อ ให้เปรียบเทียบ meta.commerce.orderTotal. ตรวจสอบ meta.commerce.currency ก่อน
  • การซื้อไม่ใช่การบริจาค จึงไม่มี hasDonation หรือ donoValue และเป้าหมายบริจาคจะไม่เพิ่ม
  • การติดป้าย Gift บนการ์ดสินค้าไม่เปลี่ยนวิธีนับคำสั่งซื้อ การส่งให้คนอื่นไม่ได้ทำให้เป็นของขวัญที่ส่งให้คุณ

ทดสอบอย่างปลอดภัย

คลิก ดูตัวอย่าง เพื่อดูรูปลักษณ์ ไม่ได้เชื่อมกับเซสชันของคุณ จึงไม่เรียก Event Flow ไม่เปลี่ยนยอด และไม่ตรวจการชำระเงิน หากต้องการทดสอบครบ ใช้ร้านค้าพัฒนาของ Shopify คำสั่งซื้อที่ระบุว่า test: true แสดงเฉพาะในสถานะ ไม่มีแจ้งเตือน

ระวังข้อมูลตัวอย่างจากแอดมิน Shopify หากไม่ได้ระบุชัดเจนว่าเป็นการทดสอบ อย่าส่งไปยังระบบที่แจกของรางวัล
สิ่งที่ทดสอบแล้วโดยไม่ใช้ร้านค้าจริง

การทดสอบในแอปจริงครอบคลุมข้อความที่ลงลายเซ็นรวมถึงข้อความที่ไม่ใช่อังกฤษ ลายเซ็นถูกแก้ไข การส่งซ้ำ คำสั่งซื้อทดสอบ การปัดเศษสกุลเงิน คำขอขนาดใหญ่ การลบข้อมูลส่วนตัวลูกค้า และการรับข้อมูลย้อนหลังหลังออฟไลน์ ไม่ได้ใช้คำสั่งซื้อจริงหรือบัญชีผู้ค้า

webhook ตัวอย่างของ Shopify CLI ทดสอบการจัดการข้อความได้ แต่ไม่ทดสอบการสมัครรับเหตุการณ์หรือการส่งซ้ำ และยังต้องใช้ข้อมูลยืนยันตัวตนแอป ดู ข้อจำกัดการทดสอบเว็บฮุก Shopify CLI.

แก้ปัญหา

ปัญหาลองวิธีนี้
บันทึกการตั้งค่าแล้วมีข้อผิดพลาดตัวรับยังไม่เปิดบนเซิร์ฟเวอร์ อย่าใช้ URL webhook เซสชันเก่าแทน
สถานะค้างที่ waitingตรวจ webhook: การชำระคำสั่งซื้อ (Order payment), JSON URL ตัวรับที่ตรงทุกตัว myshopify.com และ secret ส่วน webhook ของแอปกำหนดเองใช้ secret ของแอปนั้น
ข้ามกิจกรรมแล้วเฉพาะคำสั่งซื้อที่ชำระเต็ม ยอดมากกว่าศูนย์ และระบุว่า test: false และอัปเดตภายใน 7 วันที่ผ่านมาเท่านั้น คำสั่งซื้อที่ยังไม่ชำระ ชำระบางส่วน หรือยกเลิกจะถูกข้าม
SSN ปิดอยู่ตอนมีการขายคำสั่งซื้อรอได้ถึง 7 วัน เปิด SSN แล้วข้อมูลจะเข้ามา
คำสั่งทำงานสองครั้งป้องกันรายการซ้ำเป็นเวลา 7 วัน แต่หากแอปล่มกลางคำสั่งอาจทำซ้ำได้ เพิ่มการตรวจสอบเองสำหรับระบบอัตโนมัติที่สำคัญ
ไม่แสดงชื่อผู้ซื้อเป็นการตั้งใจ ไม่แสดงชื่อ อีเมล ที่อยู่ หมายเหตุ ช่องข้อมูลกำหนดเอง ลิงก์ชำระเงิน หรือ ID คำสั่งซื้อ
คืนเงินแล้วแต่แจ้งเตือนไม่หายการคืนเงิน ยกเลิก และแก้ไขไม่ย้อนกลับแจ้งเตือน ระบบนี้ไม่ใช่ระบบบัญชี
การจัดการคำสั่งซื้อที่รออยู่และรายการซ้ำ
  • เวลาคำสั่งซื้ออาจล่วงหน้าได้ถึงห้านาทีเนื่องจากนาฬิกาคลาดเคลื่อน
  • ระบบไม่เดาการชำระเงินจากการสร้างคำสั่งซื้อ การจัดส่ง หรือการเปลี่ยนสต็อก หากไม่มีตัวระบุการทดสอบจะข้าม
  • สถานะและคำสั่งซื้อที่รอยังคงอยู่หลังตัวรับรีสตาร์ต
  • พื้นที่เก็บข้อมูลมีจำกัด หากตัวรับเก็บคำสั่งซื้ออย่างปลอดภัยไม่ได้ จะขอให้ Shopify ส่งใหม่ภายหลัง
  • จับรายการซ้ำด้วยร้านค้าและคำสั่งซื้อ แม้ ID การส่งของ Shopify ต่างกัน
  • SSN บันทึกคำสั่งซื้อที่จัดการแล้วก่อนยืนยันรับ

ดู รายละเอียดเหตุการณ์ Shopify และ คู่มือสินค้าและรหัส QR.
