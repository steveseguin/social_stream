แสดงสินค้าและการซื้อจาก Shopify ของคุณ

Shopify ใน Social Stream Ninja

โปรโมตสินค้าสาธารณะด้วยรูป ราคา ลิงก์อ่านง่าย และ QR code รับการแจ้งคำสั่งซื้อชำระแล้วที่ลงลายเซ็นเป็น purchase ในฟีดกิจกรรม multi-alerts และ Event Flow การโปรโมตสินค้าทำงานแยกจากการแจ้งชำระเงิน

เชื่อมการซื้อ · นำเข้าสินค้า · โอเวอร์เลย์ OBS · ทดสอบอย่างปลอดภัย · ข้อจำกัดและการแก้ปัญหา

ความพร้อมใช้งาน: การแจ้งเตือนอัตโนมัติต้องติดตั้งและเปิดตัวรับ Shopify บน SSN API หากไม่มี Save setup จะแจ้งข้อผิดพลาดและไม่เปิด Shopify การนำเข้าสินค้าสาธารณะและโปรโมตด้วยตนเองทำงานแยกได้ คู่มือนี้อธิบายโค้ดเชื่อมต่อ ยังต้องทดสอบกับผู้ค้าจริงก่อนอ้างว่าตรวจบริการจริงแล้ว

เชื่อมการซื้อที่ชำระแล้ว

  1. ใน Shopify เปิด Settings → Notifications → Webhooks หาความลับสำหรับลงลายเซ็นที่แสดงสำหรับเว็บฮุกที่สร้างเอง ค่านี้ต่างจากโทเคน Storefront
  2. ใน SSN เปิด Monetization → Shopify purchases → Setup ป้อนโดเมนถาวรของคุณ your-store.myshopify.com และความลับลงลายเซ็นเว็บฮุก เปิด Shopify purchases แล้วคลิก บันทึกการตั้งค่า.
  3. คลิก คัดลอก URL ตัวรับ ใน Shopify สร้างเว็บฮุกด้วยเหตุการณ์ การชำระคำสั่งซื้อ (Order payment) รูปแบบ JSON และ URL ตัวรับนั้น เลือกเวอร์ชัน API เว็บฮุกแบบเสถียรที่รองรับ การเชื่อมต่อนี้พัฒนาตามรูปแบบข้อมูลคำสั่งซื้อ 2026-07
  4. บันทึกเว็บฮุก Shopify เปิด SSN ไว้เพื่อประมวลผลการซื้อ ตัวรับตรวจ HMAC ของเนื้อหาดิบและร้านที่ตรงกันก่อนรับข้อมูลคำสั่งซื้อ

ความลับลงลายเซ็นเข้ารหัสไว้บนตัวรับ SSN และล้างจากช่องป้อนหลังบันทึก คีย์อ่านส่วนตัวแยกจะอยู่บนอุปกรณ์นี้ ทั้งสองไม่อยู่ในลิงก์ OBS หรือ QR code ผู้ชม Shopify ใช้ตัวรับเฉพาะ ไม่ต้องเปิดสวิตช์ควบคุม API ระยะไกลเดิม

การมี URL ที่สร้างหมายถึงบันทึกการตั้งค่าแล้ว ไม่ใช่ Shopify ส่งอะไรมาแล้ว สถานะแยกการรอ การทดสอบที่ตรวจสอบแล้ว เหตุการณ์ที่ข้าม และการซื้อที่ได้รับ หากเปลี่ยนร้านต้อง Disconnect ก่อน การปิด Shopify หยุดการประมวลผลในเครื่องชั่วคราว ส่วน Disconnect ลบตัวรับและเหตุการณ์ในคิว เมื่อตัดการเชื่อมต่อให้ลบเว็บฮุก Shopify ที่ตรงกันด้วย

นำเข้าสินค้าสาธารณะ

  1. ป้อน myshopify.com ในการตั้งค่า Shopify คุณไม่ต้องเปิดแจ้งซื้อหรือใส่ความลับลงลายเซ็นเพื่อนำเข้าสินค้า
  2. ขยาย นำเข้าสินค้า วาง URL สินค้าสาธารณะ แล้วคลิก โหลดรายละเอียดสินค้า.
  3. หากการเข้าถึงโดยไม่มีโทเคนไม่แสดงสินค้า ให้ใส่ โทเคน Storefront สาธารณะ ช่อง Headless ของ Shopify สร้างให้ได้ เผยแพร่สินค้าไปยังหน้าร้านนั้นและ Online Store อย่าวางโทเคน Admin API หรือโทเคน Storefront แบบส่วนตัว
  4. SSN เปิดตัวแก้ไขเดิม สินค้าและลิงก์สนับสนุน พร้อมชื่อ รูป ราคา และลิงก์สาธารณะมาตรฐานที่ Shopify ส่งมา ตรวจสอบแล้วคลิก เพิ่มสินค้าหรือลิงก์ เปิดแค็ตตาล็อกและ บันทึกการตั้งค่า.

การนำเข้าอ่านครั้งละหนึ่งสินค้าผ่าน Storefront API โทเคนไม่บังคับ ใช้เฉพาะคำขอนั้นและล้างหลังใช้ URL Online Store มาตรฐานของ Shopify จะเป็นลิงก์สาธารณะ รวมโดเมนกำหนดเองเมื่อ Shopify ส่งมา สินค้าที่ไม่พร้อมขายและไม่มีลิงก์ Online Store สาธารณะจะถูกตัดออก

ระบบกรอกราคาเฉพาะเมื่อราคาต่ำสุดและสูงสุดของตัวเลือกสินค้าตรงกัน มิฉะนั้นจะเว้นว่าง เลือกราคาที่ระบุเองเฉพาะเมื่ออธิบายข้อเสนอได้ถูกต้อง ข้อมูลนำเข้าเป็นข้อมูล ณ เวลานั้น ไม่ใช่การซิงค์สต็อกหรือราคาต่อเนื่อง ตรวจอีกครั้งเมื่อร้านเปลี่ยน คุณเพิ่มสินค้าด้วยตนเองแทนได้เสมอ

ใช้โอเวอร์เลย์ที่มีอยู่

ใน ลิงก์โอเวอร์เลย์สำหรับ เลือก สินค้าและลิงก์สนับสนุน ใช้ เฉพาะแสดงสินค้า สำหรับรูป ราคา และ QR code เฉพาะการ์ดสนับสนุน สำหรับลิงก์ร้านเล็ก ๆ ที่แสดงถาวรหรือเป็นระยะ หรือ เฉพาะการแจ้งเตือนกิจกรรม สำหรับการซื้อ คัดลอกลิงก์ OBS ที่ต้องการแต่ละอันลงแหล่งเบราว์เซอร์แยก เริ่มที่ 800 × 600

ตั้งตัวกรองแหล่งการแจ้งเตือนเสริมเป็น shopify เพื่อแสดงเฉพาะกิจกรรม Shopify ในโอเวอร์เลย์สร้างรายได้ทั่วไป เปิด Products & support links สำหรับมุมมองทั่วไปนั้น multi-alerts และฟีดกิจกรรมเดิมรับการซื้อ Shopify แยกจากแค็ตตาล็อกสินค้า

การ์ดสินค้าเชื่อมไปหน้าสินค้าสาธารณะ ใช้ คัดลอกลิงก์สาธารณะ เพื่อแชร์ที่อยู่ที่คลิกได้ในแชต และทดสอบ QR code ด้วยโทรศัพท์ที่ขนาดสตรีมจริง การแจ้งซื้อไม่ยืม QR code หรือรูปจากสินค้าที่หมุนเวียนซึ่งไม่เกี่ยวข้อง เว็บฮุกคำสั่งซื้อไม่มี URL รูปสินค้าที่เชื่อถือได้ จึงใช้ข้อความในแจ้งซื้อ ส่วนการ์ดโปรโมตที่นำเข้าแสดงรูปได้

สำหรับ Event Flow เลือก Event Type purchase และกรองแหล่งข้อมูล/ประเภทเป็น shopify เปรียบเทียบ meta.commerce.orderTotal สำหรับกฎมูลค่าคำสั่งซื้อ และตรวจ meta.commerce.currency ก่อนเปรียบเทียบยอด นี่คือการซื้อ จึงไม่มี hasDonation หรือ donoValue ถูกส่ง และเป้าหมายบริจาคไม่เพิ่ม การ์ดโปรโมตที่ติดป้าย Gift ไม่เปลี่ยนประเภทเหตุการณ์คำสั่งซื้อ การส่งให้บุคคลอื่นไม่ใช่หลักฐานว่าเป็นของขวัญให้ผู้สร้าง

ดูตัวอย่างและทดสอบอย่างปลอดภัย

ดูตัวอย่าง เปิดโอเวอร์เลย์ตัวอย่างแยกโดยไม่เชื่อมเซสชัน ไม่กระตุ้น Event Flow เปลี่ยนยอดรวม หรือยืนยันการชำระเงิน

คำสั่งซื้อ Shopify ที่ทำเครื่องหมายชัดเจนว่า test: true จะได้รับการตอบรับและแสดงเป็นการทดสอบในสถานะตัวรับ โดยไม่มีการแจ้งซื้อหรือแอ็กชัน คำสั่งซื้อที่ไม่มีแฟล็กทดสอบ ยังไม่จ่าย/จ่ายบางส่วน ยกเลิก ยอดรวมศูนย์ หรือเวลาที่เก่าหรือไม่ถูกต้องก็ถูกข้าม ใช้ร้านพัฒนาสำหรับทดสอบครบวงจร ตัวอย่างจากแอดมินที่ไม่มีแฟล็กทดสอบน่าเชื่อถือไม่ควรส่งเข้าเวิร์กโฟลว์รางวัลที่ทำงานอยู่ ตัวอย่าง SSN เป็นวิธีตรวจหน้าตาที่ปลอดภัย

สิ่งที่เราตรวจโดยไม่มีร้าน

การทดสอบแบบแยกครอบคลุมการส่ง HTTP จริงด้วย Unicode JSON ที่ลงลายเซ็น ลายเซ็นที่ถูกแก้ การส่งซ้ำ การแยกคำสั่งซื้อทดสอบ ความแม่นยำสกุลเงิน คำขอขนาดเกิน การลบข้อมูลลูกค้าส่วนตัว และการกู้หลังออฟไลน์ผ่านระบบรัน SSApp จริง การตรวจเหล่านี้ไม่สั่งซื้อและไม่ต้องมีบัญชีผู้ค้า

ตัวรับ Shopify สำหรับใช้งานจริงยังปิดอยู่ระหว่างรอทดสอบการส่งจากร้านจริง การโปรโมตสินค้าด้วยตนเองใช้แยกได้ เว็บฮุกตัวอย่างจาก Shopify CLI ช่วยทดสอบการจัดการเพย์โหลด แต่ไม่ยืนยันการสมัครรับหรือการลองส่งซ้ำ และยังต้องมีข้อมูลรับรองแอป ดู ข้อจำกัดการทดสอบเว็บฮุก Shopify CLI.

ข้อจำกัดการส่งและการแก้ปัญหา

  • ตัวรับใช้ไม่ได้: the SSN API operator must deploy and enable the Shopify receiver. Do not use the legacy unsigned session webhook URL as a substitute.
  • กำลังรอเหตุการณ์: ตรวจ Order payment, JSON, URL ตัวรับที่ตรง โดเมนร้านถาวรที่ตรง และความลับลงลายเซ็นของเว็บฮุกนั้น เว็บฮุกของแอปกำหนดเองใช้ความลับลงลายเซ็นของแอปนั้น ไม่ใช่ความลับจาก Notifications แบบสร้างเอง
  • ข้ามเหตุการณ์ที่ลงลายเซ็น: การเชื่อมต่อนี้ต้องมีคำสั่งซื้อยอดบวกที่จ่ายเต็มแล้ว test: false และเนื้อหาที่ลงลายเซ็น updated_at ภายในเจ็ดวันที่ผ่านมา (ยอมให้เวลาล่วงหน้าห้านาที) ไม่อนุมานการจ่ายเงินจากการสร้างคำสั่งซื้อ การจัดส่ง หรือสต็อก
  • SSN ออฟไลน์อยู่: เหตุการณ์ที่ยอมรับเข้าคิวได้สูงสุดเจ็ดวัน เริ่ม SSN ใหม่เพื่อทำต่อ สถานะและงานค้างอยู่ต่อหลังตัวรับเริ่มใหม่ บริการมีพื้นที่จำกัดและขอให้ Shopify ส่งซ้ำเมื่อไม่สามารถเก็บงานลงคิวอย่างถาวรได้
  • รายการซ้ำ: ตัวรับตัดซ้ำตามร้าน/คำสั่งซื้อ แม้รหัสการส่งของ Shopify ต่างกัน บันทึกตัดซ้ำอยู่เจ็ดวัน SSN บันทึกรหัสที่จัดการแล้วก่อนตอบรับ แต่การล่มระหว่างแอ็กชันภายนอกกับการบันทึกนั้นยังอาจทำให้แอ็กชันซ้ำ ใช้ตัวป้องกันการทำซ้ำของคุณเองสำหรับระบบอัตโนมัติที่มีผลสำคัญ
  • ไม่มีชื่อผู้ซื้อ: เป็นความตั้งใจ SSN ไม่รวมชื่อลูกค้า อีเมล ที่อยู่ หมายเหตุคำสั่งซื้อ คุณสมบัติกำหนดเองของรายการสินค้า URL ชำระเงิน และรหัสคำสั่งซื้อดิบ ชื่อสินค้าสาธารณะยังเป็นข้อความธรรมดา
  • การคืนเงินหรือเปลี่ยนคำสั่งซื้อ: นี่เป็นฟีดแจ้งเตือนสด ไม่ใช่ระบบบัญชีหรือจัดส่ง การคืนเงิน ยกเลิก และแก้ยอดไม่ย้อนการแจ้งเตือนเดิม ไม่มีการกระทบยอดประวัติคำสั่งซื้อหรือลบสินค้าอัตโนมัติ
