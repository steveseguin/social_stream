ส่งต่อแชตระหว่างแพลตฟอร์ม

ตั้งค่าการส่งต่อ Twitch และ YouTube อย่างเจาะจง เลือกผู้ส่ง และวิเคราะห์ข้อความที่ซ้ำ

คู่มือทั้งหมด 1. ตรวจสอบว่าแชตทั้งสองรับคำตอบได้ 2. สร้าง Twitch → YouTube ใน Event Flow 3. เพิ่มทิศทางส่งกลับ 4. ทำความเข้าใจข้อความสะท้อนกลับ 5. จำกัดข้อความที่ส่งต่อ การแก้ปัญหา

1. ตรวจสอบว่าแชตทั้งสองรับคำตอบได้

เชื่อมต่อแชต Twitch และ YouTube Live เข้ากับเซสชัน SSN เดียวกัน ยืนยันว่าทั้งสองปรากฏในแผงด็อก แล้วส่งคำตอบด้วยตนเองไปแต่ละแชตหนึ่งครั้งจากข้อความที่ทราบแท็บต้นทาง ใช้ช่องทดสอบของคุณเอง แหล่งจับข้อมูลแบบอ่านอย่างเดียวส่งต่อข้อความไม่ได้

สำหรับการตั้งค่านี้ เปิดเฉพาะแชตปลายทางที่ต้องการ ปลายทางแบบแพลตฟอร์มอาจรวมแท็บแหล่งข้อมูลที่ใช้ได้หลายแท็บบนแพลตฟอร์มนั้น หากใช้บัญชีบอต Twitch แยก ให้ทำตาม บัญชีบอตสำหรับตอบกลับ ก่อน

2. สร้าง Twitch → YouTube ใน Event Flow

เปิด ตัวแก้ไข Event Flow จากเมนู SSN (มีลิงก์ในส่วนโอเวอร์เลย์ Actions ด้วย) สร้างโฟลว์และตั้งชื่อชัดเจน เช่น Twitch ไป YouTube.

  1. เพิ่ม จากแหล่งข้อมูล (From Source) ตัวเรียกใช้งานจาก ผู้ใช้และแหล่งข้อมูล (User & Source) เลือก Twitch เป็นแหล่งข้อมูล
  2. เพิ่ม ส่งต่อแชต (Relay Chat) แล้วเชื่อมเอาต์พุตของตัวเรียกใช้งานเข้ากับอินพุตของการกระทำ
  3. เลือกการกระทำนั้น ตั้งค่า ปลายทางส่งต่อ (Relay Destination) เป็น YouTube และคงเทมเพลตข้อความเป็น [{source}] {username}: {message}.
  4. เลือก บันทึกโฟลว์ (Save Flow) และเปิดโฟลว์ที่บันทึกไว้ เปิด SSN ให้ทำงานอยู่
  5. ส่งข้อความปกติใหม่ในแชตทดสอบ Twitch ของคุณ ยืนยันว่าสำเนาที่มีป้ายกำกับหนึ่งรายการถึง YouTube

YouTube Shorts มีประเภทแหล่งข้อมูลและปลายทางของตัวเอง เลือก YouTube Shorts ตามความเหมาะสม ซึ่งใช้แทน YouTube ไม่ได้

3. เพิ่มทิศทางส่งกลับ

สร้างโฟลว์ที่สองชื่อ YouTube ไป Twitch: จากแหล่งข้อมูล: YouTube → ส่งต่อแชต: Twitch บันทึกและเปิดใช้ ส่งข้อความใหม่จากแต่ละฝั่งแล้วยืนยันว่าแต่ละข้อความสร้างสำเนาข้ามแพลตฟอร์มหนึ่งรายการ

คงค่า ส่งต่อทุกข้อความ (ไม่แนะนำ!) เป็นปิดเมื่อใช้โฟลว์เหล่านี้ เพื่อไม่ให้มีระบบส่งต่อที่สองทำงานซ้ำ ตรวจสอบด้วยว่ามีบอตอื่นหรือบริการมัลติสตรีมเชื่อมแชตอยู่แล้วหรือไม่

4. ทำความเข้าใจข้อความสะท้อนกลับ

ข้อความสะท้อนกลับคือข้อความที่ SSN ส่งแล้วจับกลับมาจากแชตปลายทาง การกระทำ Relay Chat ปัจจุบันข้ามข้อความสะท้อนกลับที่ตรวจพบโดยอัตโนมัติ และไม่ส่งกลับแท็บต้นทางด้วย

หากต้องการซ่อนข้อความสะท้อนที่จับกลับมาจากแผงด็อกและโอเวอร์เลย์ ให้เพิ่ม ตัวกรองข้อความสะท้อนกลับ (Reflection Filter) ไว้ช่วงต้นของโฟลว์ที่เกี่ยวข้อง แล้วเลือก บล็อกทั้งหมด (Block All). อนุญาตรายการแรก (Allow First) เก็บข้อความสะท้อนกลับที่ตรงกันหนึ่งรายการภายในช่วงเวลาที่กำหนด ส่วน อนุญาตทั้งหมด (Allow All) แสดงข้อความเหล่านั้น ตัวเลือกนี้ควบคุมการแสดงหลังจับข้อมูล ไม่ใช่ปลายทางส่งต่อ

คุณสมบัติ Relay Chat ปัจจุบันไม่มีช่องเลือก “No Reflections” ใช้ Reflection Filter แยกต่างหากเพื่อควบคุมการแสดงผล หากบริการภายนอกแก้ข้อความที่ส่งต่อ ระบบอาจตรวจไม่พบโดยอัตโนมัติ

5. จำกัดข้อความที่ส่งต่อ

สำหรับคำสั่ง ให้เพิ่ม ข้อความขึ้นต้นด้วย (Message Starts With) ตัวเรียกใช้งานที่ตั้งเป็น ! และเชื่อมผ่าน NOT เกต แล้วรวมผลกับเงื่อนไขแหล่งข้อมูลโดยใช้ AND ก่อน Relay Chat ดู คู่มือ Event Flow สำหรับการเชื่อมเกตตรรกะ ทดสอบทั้งข้อความปกติและคำสั่ง

หากเลือกการส่งต่อส่วนกลางที่ง่ายกว่าแทน ให้ใช้ การตั้งค่าและเครื่องมือส่วนกลาง → คำสั่ง → เลือกปลายทางส่งต่อ และป้อน twitch,youtube รายการว่างหมายถึงปลายทางที่ใช้ได้ทั้งหมด รายการนี้ควบคุมปลายทาง ไม่ได้กำหนดว่าแพลตฟอร์มขาเข้าใดเรียกการส่งต่อได้ ปิดคู่โฟลว์ส่งต่อใน Event Flow ก่อนเปิดทางเลือกนี้

ช่องอนุญาต/บล็อกบทบาทบัญชีของ SSApp ในส่วน Commands เดียวกันจำกัดได้ว่าบัญชีใดส่งต่อข้อความ ใช้บทบาทที่กำหนดให้ผู้ส่งที่ต้องการ บทบาทที่ไม่ตรงกันอาจทำให้ไม่มีปลายทางที่ใช้ได้

การแก้ปัญหา

  • ไม่มีข้อความส่งออก: ลองตอบด้วยตนเองอีกครั้ง ตรวจสอบการเข้าสู่ระบบ/สิทธิ์โพสต์ เปิดโฟลว์ที่บันทึกไว้ และตรวจข้อจำกัดปลายทางกับบทบาทบัญชี
  • ข้อความเพิ่มซ้ำหลายรายการ: ปิดโฟลว์ส่งต่อก่อน ตรวจหาแหล่งจับข้อมูลซ้ำ การเปิด Relay all ส่วนกลาง และบอตส่งต่อภายนอก ก่อนทดสอบใหม่ทีละทิศทาง
  • มีข้อความซ้ำเฉพาะในแผงด็อก: ตรวจสอบนโยบายการแสดงผลของ Reflection Filter และการตั้งค่าข้อความสะท้อนใน Message - Visibility ส่วนกลาง
  • ปลายทาง YouTube ไม่ถูกต้อง: ตรวจสอบว่าเป็น YouTube หรือ YouTube Shorts แล้วปิดแชตที่เข้าเงื่อนไขแต่ไม่ต้องการ

การกระทำ Test Flow ส่งข้อความจริงได้ ใช้ปลายทางที่คุณควบคุม การทดสอบจำลองไม่ได้ยืนยันการเลือกเส้นทางบัญชีของแหล่งข้อมูลจริง
