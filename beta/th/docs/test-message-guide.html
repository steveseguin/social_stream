สร้างข้อความทดสอบ

ส่งข้อความและเหตุการณ์จำลองที่ควบคุมได้เข้าสู่เซสชัน Social Stream ของคุณ

เครื่องมือนี้ทำอะไรเริ่มต้นอย่างรวดเร็วสำหรับ SSApp หรือส่วนขยายตัวอย่าง: ข้อความจำลอง 1,000 KICKs หนึ่งข้อความการใช้พรีเซ็ตและ JSON แบบกำหนดเองเลือกโหมดส่งที่เหมาะสมวิธีแก้ปัญหาที่พบบ่อย

เครื่องมือนี้ทำอะไร

ส่วน หน้าสร้างข้อความทดสอบ ส่งเพย์โหลด Social Stream จำลองไปยังแผงด็อก โอเวอร์เลย์ การแจ้งเตือน หรือการตั้งค่า Event Flow ของคุณ ใช้ทดสอบโดยไม่ต้องรอข้อความแชต การบริจาค สมาชิก เรด รางวัล หรือเหตุการณ์จริง

ใช้เซสชันทดสอบเมื่อทำได้ ข้อความที่ส่งจะทำงานเหมือนข้อมูลขาเข้าของเซสชัน และอาจกระตุ้นการแจ้งเตือน เสียง เว็บฮุก แอ็กชัน OBS หรือระบบอัตโนมัติอื่น ๆ

เริ่มต้นอย่างรวดเร็วสำหรับ SSApp หรือส่วนขยาย

  1. เปิด Social Stream Ninja และตรวจสอบว่าบริการทำงานอยู่
  2. ใน การตั้งค่าและเครื่องมือส่วนกลาง → กลไก, เปิดใช้ การควบคุมส่วนขยายจากระยะไกลผ่าน APISSApp ใช้ชื่อการตั้งค่าเดียวกัน
  3. คัดลอก ID เซสชันของคุณจาก Social Stream หรือจาก session= ค่าใน URL ของแผงด็อกหรือโอเวอร์เลย์ของคุณ
  4. เปิด สร้างข้อความทดสอบ แล้วกรอก ID เซสชันนั้น
  5. คงค่า ส่งผ่าน (Send Via) ตั้งเป็น รับผ่าน API ส่วนขยาย (Extension API ingest) สำหรับการทดสอบปกติ
  6. เลือกพรีเซ็ต ปรับฟิลด์ แล้วเลือก โหลดพรีเซ็ต (Load Preset).
  7. ตรวจสอบ Payload JSON แล้วเลือก ส่ง (Submit).
  8. ตรวจสอบว่ารายการปรากฏในแผงด็อกหรือโอเวอร์เลย์เป้าหมาย และระบบอัตโนมัติทำงานตามที่คาดไว้

คุณสามารถใส่เซสชันใน URL ได้: createtestmessage.html?session=YOUR_SESSION_ID.

ตัวอย่าง: ข้อความจำลอง 1,000 KICKs หนึ่งข้อความ

คำสั่งนี้สร้างข้อความสนับสนุนแบบ Kick หนึ่งข้อความที่มีมูลค่า 1,000 KICKs ไม่ได้สร้างข้อความแยกกัน 1,000 ข้อความ

  1. เลือก ข้อความแชต (Chat Message) พรีเซ็ต
  2. ตั้งค่า พิมพ์ เป็น Kick.
  3. กรอกชื่อและข้อความทดสอบ
  4. ตั้งค่า มีการบริจาค (Has Donation) เป็น 1000 KICKs.
  5. เลือก อัปเดต JSON จากฟิลด์ (Update JSON from Fields)ตรวจสอบ JSON แล้วส่ง

เพย์โหลดขั้นต่ำคือ:

{
  "type": "kick",
  "chatname": "Test Supporter",
  "chatmessage": "Thanks for the stream!",
  "hasDonation": "1000 KICKs"
}

ใช้ ข้อความแชต (Chat Message) สำหรับตัวอย่างนี้ โดย บริจาค / Cheer มีฟิลด์ Cheer เฉพาะของ Twitch อยู่ในพรีเซ็ต

การใช้พรีเซ็ตและ JSON แบบกำหนดเอง

พรีเซ็ตให้เพย์โหลดเริ่มต้นสำหรับกรณีทั่วไป เช่น การบริจาค ผู้สมัครสมาชิก การมอบสมาชิก เรด รางวัล การอัปเดตผู้ชม ผู้แชตครั้งแรก และเหตุการณ์รถไฟ

  • โหลดพรีเซ็ต (Load Preset) แทนที่ JSON ด้วยพรีเซ็ตที่เลือกและค่าฟิลด์ปัจจุบัน
  • อัปเดต JSON จากฟิลด์ (Update JSON from Fields) สร้างข้อความพื้นฐานจากฟิลด์ที่มองเห็น
  • คุณสามารถแก้ไข JSON เพย์โหลด (Payload JSON) โดยตรงเมื่อทดสอบฟิลด์หรือโครงสร้างเหตุการณ์เฉพาะ
  • hasDonation เก็บจำนวนการสนับสนุนที่แสดง เช่น 1000 KICKs หรือ $10.00.
  • ใส่เฉพาะ event เมื่อคุณกำลังทดสอบเหตุการณ์จริงที่มีชื่อระบุ แถวแชตแบบบริจาคปกติสามารถใช้ hasDonation เพียงอย่างเดียว

ดูคำอธิบายฟิลด์และตัวอย่างจากแพลตฟอร์มจริงได้ที่ เอกสารอ้างอิงอีเวนต์.

เลือกโหมดส่งที่เหมาะสม

ส่งผ่าน (Send Via)ใช้เมื่อการตั้งค่าที่จำเป็น
รับผ่าน API ส่วนขยาย (Extension API ingest)ทดสอบแผงด็อก โอเวอร์เลย์ การแจ้งเตือน Event Flow หรือ SSApp ตามปกติID เซสชันเดียวกันและ การควบคุมส่วนขยายจากระยะไกลผ่าน API เปิดใช้งานอยู่
ส่งตรงไปยังช่อง 1แผงด็อกเป้าหมายเปิดด้วย &server.เป้าหมายต้องรอรับข้อมูลบนช่องเซิร์ฟเวอร์ที่ตรงกัน
ส่งตรงไปยังช่อง 4ทดสอบเป้าหมายที่ใช้ &server2รวมถึงหน้าเหตุการณ์ที่รองรับเป้าหมายต้องรอรับข้อมูลบนช่องเซิร์ฟเวอร์ที่ตรงกัน

หากไม่แน่ใจ ให้ใช้ รับผ่าน API ส่วนขยาย (Extension API ingest).

วิธีแก้ปัญหาที่พบบ่อย

  • ไม่มีอะไรปรากฏ: ตรวจสอบว่าหน้าเป้าหมายเปิดอยู่และใช้ ID เซสชันเดียวกัน
  • การรับผ่าน API ส่วนขยายล้มเหลว: เปิดใช้ การควบคุมส่วนขยายจากระยะไกลผ่าน APIแล้วโหลดแผงด็อกหรือโอเวอร์เลย์ใหม่และลองอีกครั้ง
  • โหมดส่งตรงระบุว่าส่งแล้วแต่ไม่มีอะไรปรากฏ: ใช้ Extension API ingest เว้นแต่ URL เป้าหมายจะมีค่าที่ตรงกันของ &server หรือ &server2 โหมด
  • เกิดเหตุการณ์ผิดประเภท: ตรวจสอบ Payload JSON ว่ามีฟิลด์จากพรีเซ็ตอื่นหลงเหลือหรือไม่
  • การทดสอบ Kick ทำงานเหมือน Twitch: ใช้พรีเซ็ต Chat Message แล้วตั้ง type และ hasDonation ตามที่แสดงด้านบน
  • ระบบอัตโนมัติทำงานมากกว่าหนึ่งครั้ง: ตรวจสอบว่ามีแผงด็อก หน้าแอ็กชัน หรือ Event Flow หลายชุดเปิดอยู่ในเซสชันเดียวกันหรือไม่
