แจกของรางวัลครั้งแรก: ขั้นตอนพร้อมภาพหน้าจอ

คู่มือแจกของรางวัล ตั๋วแบบเสียเงิน รางวัลเกม และการกู้คืน

จัดโหวตในแชต สุ่มผู้ชนะ หรือจัดระเบียบผู้ชมที่จะเข้าร่วมถัดไป

คู่มือทั้งหมด 1. เลือกเครื่องมือ 2. จัดโพลแบบหลายตัวเลือก 3. สุ่มผู้ชนะ 4. จัดคิวผู้ชม 5. ซ้อมและกู้คืน

1. เลือกเครื่องมือ

เป้าหมาย เปิดใน SSN
ให้แชตโหวตกิจกรรมถัดไป Graphical Poll → Poll Options
สุ่มผู้เข้าร่วม รายการรอ / สุ่มผู้ชนะ โดยเปิดโหมดสุ่มผู้ชนะ
รับผู้ชมตามลำดับคิว รายการรอ / สุ่มผู้ชนะ โดยปิดโหมดสุ่มผู้ชนะ

ใช้ลิงก์ที่สร้างจากส่วนนั้นเป็นแหล่งเบราว์เซอร์ OBS เปิด SSN และแหล่งแชตไว้ และคงค่าเซสชัน รหัสผ่าน และเซิร์ฟเวอร์ของลิงก์ไว้ โหมด เครื่องมือแจกของรางวัล มีรายชื่อแยก พร้อมรูปแบบแสดงการ์ดผู้ชนะ วงล้อเลื่อนชื่อ และวงล้อชุมชน ใช้แผง Giveaway Options สำหรับตัวควบคุมแจกของรางวัลโดยเฉพาะ ส่วน Wait List / Winner Draw ยังใช้แยกได้

2. จัดโพลแบบหลายตัวเลือก

  1. เปิด Graphical Poll → Poll Options ตั้งค่า ประเภทโพล เป็น หลายตัวเลือก.
  2. ป้อน เราควรเล่นอะไรต่อ? เป็นคำถาม และ Adventure, Puzzle เป็นตัวเลือกคั่นด้วยจุลภาค ตั้งค่า การจับคู่โหวต เป็น เฉพาะข้อความโหวตที่ตรง.
  3. คงค่า อนุญาตให้ผู้ใช้โหวตหลายครั้ง และ ถ่วงน้ำหนักโหวตด้วยยอดบริจาค ให้ปิดสำหรับโพลหนึ่งคนหนึ่งโหวตแบบง่าย เปิด เปิดโพล (Enable Poll).
  4. คัดลอกลิงก์โพลที่สร้างไปใส่ใน OBS ขอให้ผู้ชมส่ง 1 หรือ 2 เป็นทั้งข้อความ การส่งข้อความตรงกับตัวเลือกก็ใช้ได้
  5. เลือก จบโพล (End Poll) เพื่อปิดโหวต จดผลก่อนเลือก รีเซ็ตโพล สำหรับรอบใหม่

โพลอิสระรับโหวตแบบแฮชแท็ก แฮชแท็กอยู่ตรงไหนก็ได้ อนุญาตให้แฮชแท็กอยู่ในข้อความที่ยาวกว่า บันทึกโพลปัจจุบัน บันทึกค่าตั้งล่วงหน้าไว้ใช้ซ้ำ ไม่ใช่บันทึกผลผู้ชมถาวร โหวตซ้ำจากผู้โหวตเดิมจะถูกข้าม เว้นแต่เปิดให้โหวตหลายครั้ง

เครื่องมือแจกของรางวัลเฉพาะ

สำหรับขั้นตอนพร้อมภาพหน้าจอ ดู การแจกของรางวัลครั้งแรก เปิด Giveaway Tool → Giveaway Options ตั้งคีย์เวิร์ดเข้าร่วม เลือกให้ตรงทั้งข้อความหรือเป็นคำแยก และเลือกจำกัดเฉพาะสมาชิกได้ คลิก เปิดรับผู้เข้าร่วม, จากนั้น จับผู้ชนะ เมื่อพร้อม การสุ่มจะปิดรับรายชื่ออัตโนมัติ ก่อนสุ่ม คุณปิดและเปิดรับรายชื่อใหม่ด้วยกฎเดิมได้ รอบใหม่ ล้างรายชื่อปัจจุบัน เก็บผลเก่าในประวัติ และคงสถานะปิดรับรายชื่อ

เลือก การ์ดผู้ชนะ, วงล้อชื่อ, หรือ วงล้อชุมชน และหนึ่งในหกสไตล์ ตัวอย่างใช้ชื่อสมมติและไม่เข้าร่วมเซสชันของคุณ คัดลอกลิงก์ที่สร้าง giveaway.html?session=YOUR_SESSION&managed ไปใส่ใน OBS หน้าจอผู้ชมแบบจัดการไม่มีตัวควบคุมผู้ดำเนินรายการหรือรายละเอียดเซสชัน สไตล์และชื่อเป็นการตั้งค่าลิงก์ ส่วนกฎการเข้าร่วมเป็นการตั้งค่าโฮสต์ที่ใช้เมื่อเปิดรับรายชื่อ

หน้าจัดการแสดงผลที่ใช้ Giveaway ID เดียวกันใช้รายชื่อและผู้ชนะที่ผู้ดำเนินรายการเลือกชุดเดียวกัน การเข้าร่วมฟรีด้วยคีย์เวิร์ดมีโอกาสเท่ากัน การสุ่มแบบเสียเงินถ่วงน้ำหนักตามจำนวนตั๋ว ตัวตนจะถูกตัดซ้ำภายในแต่ละแพลตฟอร์มด้วยรหัสผู้ใช้ ชื่อผู้ใช้ หรือชื่อที่แสดงที่ให้มา คนละแพลตฟอร์มถือเป็นคนละตัวตน เมื่อปิดผู้ชนะซ้ำ ผู้ชนะแต่ละคนจะถูกนำออกจากรายชื่อที่มีสิทธิ์ของรอบปัจจุบัน รอบใหม่ให้คนเหล่านั้นเข้าร่วมอีกได้ รองรับผู้เข้าร่วมสูงสุด 10,000 คน วงล้อแสดงตัวอย่างสูงสุด 120 ชื่อเมื่อรายชื่อมีขนาดใหญ่ แต่การเลือกใช้ตั๋วที่มีสิทธิ์ทั้งหมดเสมอ

เปิด SSN ให้ทำงานค้างไว้ รอบต่าง ๆ บันทึกในโปรไฟล์เบราว์เซอร์/แอปในเครื่อง แยกตามแต่ละเซสชัน การเริ่มใหม่จะปิดรอบที่เปิดอยู่เพื่อให้ตรวจสอบ ไม่ได้ลบทิ้ง การรีเฟรชหน้าผู้ชมจะรับผลปัจจุบัน ข้อจำกัดสมาชิกต้องใช้แหล่งข้อมูลที่ให้ข้อมูลสมาชิก ข้อความย้อนหลัง เล่นซ้ำ ส่วนตัว บอต และข้อความเฉพาะเหตุการณ์จะไม่ถูกนับ ข้อความเข้าร่วมฟรีต้องตรงกับคีย์เวิร์ดที่ตั้งไว้ ยอดบริจาคไม่เปลี่ยนโอกาสชนะ

API, Stream Deck และ Event Flow

แอ็กชันโฮสต์ชุดเดียวกันรองรับปุ่มป๊อปอัป HTTP/WebSocket API เดิม และ Stream Deck ไม่ต้องเปิดหน้าจอแจกของรางวัลเพื่อรวบรวมรายชื่อหรือสุ่ม ใน Event Flow ใช้แอ็กชัน แจกของรางวัล / ตั๋ว ดู คู่มือคะแนนและระบบอัตโนมัติ สำหรับตั๋วเสียเงิน รางวัลเกม และการเชื่อมต่อ

การดำเนินการผล
startgiveawayเปิดหรือกลับมารับรายชื่อก่อนสุ่ม ค่าที่เลือกใส่ได้: {"giveawayId":"default","config":{"keyword":"!enter","match":"exact","membersOnly":false,"removeWinner":true}} หากไม่ระบุกฎ ให้คงกฎของรอบเดิม หรือใช้การตั้งค่าป๊อปอัปสำหรับรอบใหม่

resetgiveawayสร้างรอบว่างที่ปิดรับรายชื่อ เก็บรอบเก่าและผู้ชนะไว้ในประวัติ ยกเลิก/คืนเงินการจองแบบเสียเงินที่ค้างอยู่ก่อน
getgiveawaystateอ่านจำนวนผู้เข้าร่วม สถานะเปิด/ปิด กฎการเข้าร่วม และผู้ชนะล่าสุด

คำขอ Stream Deck โปรโตคอล 2 ใช้ชื่อแอ็กชันเดียวกันและรับคำตอบจากโฮสต์ที่เชื่อมโยงกับคำขอ คำตอบเหล่านี้อธิบายสถานะแจกของรางวัล ไม่ใช่การมองเห็นใน OBS วงล้อชุมชนแบบแยกรุ่นเดิมยังใช้ได้โดยไม่ใส่ managed มีรายชื่อในเครื่องของตัวเองและไม่ถูกควบคุมด้วยแอ็กชันผู้ดำเนินรายการเหล่านี้ ตอนนี้พื้นที่จัดเก็บในเครื่องแยกตามเซสชันและรหัสผ่าน การจับคู่ตรงหมายถึงทั้งข้อความ และการสุ่มใช้แหล่งสุ่มที่ปลอดภัย

3. สุ่มผู้ชนะ

  1. เปิด Wait List / Winner Draw → Enable and customize เปิดทริกเกอร์และตั้งคำสั่งให้ชัดเจน เช่น !join.
  2. เปิด ตั้งเป็นโหมดสุ่มผู้ชนะแทนคิว คัดลอกลิงก์ที่อัปเดตไปใส่ในแหล่งเบราว์เซอร์ OBS
  3. แจ้งคำสั่งเข้าร่วมและกฎสิทธิ์ให้ผู้ชมทราบ หากใช้ เฉพาะสมาชิกเท่านั้นที่เข้าร่วมได้ ให้ตรวจสอบก่อนว่าแหล่งข้อมูลให้ข้อมูลสมาชิกมา
  4. ดูจำนวนผู้เข้าร่วมเพิ่มขึ้น เลือก หยุดรับรายชื่อ เมื่อหมดช่วงรับรายชื่อ แล้ว เลือกผู้ชนะ.
  5. ใช้ ดาวน์โหลดรายชื่อ เพื่อเก็บรายชื่อไว้ก่อน รีเซ็ตการสุ่ม ล้างรอบ

4. จัดคิวผู้ชม

ใช้การตั้งค่ารายการรอแบบเดิม แต่ปิดโหมดสุ่มผู้ชนะและคัดลอก URL ที่อัปเดต ผู้ชมเข้าร่วมด้วยคำสั่งที่คุณตั้งไว้

ปุ่ม สิ่งที่ต้องทำ
เน้นผู้เข้าร่วมลำดับแรก เรียกความสนใจไปยังผู้ชมคนถัดไป
นำผู้เข้าร่วมลำดับแรกออก เลื่อนไปคนถัดไปหลังผู้ชมคนนั้นจบคิว
เลือกชื่อ สุ่มเลือกแทนการเรียงตามคิว
หยุดรับรายชื่อ ปิดคิวไม่ให้คนใหม่เข้าร่วม
ดาวน์โหลดรายชื่อ / รีเซ็ตคิว บันทึกสำเนา TSV แล้วล้างรายชื่อเมื่อจบกิจกรรม

ใช้ตัวเลือก rejoin เพื่อกำหนดว่าผู้ชมที่ถูกนำออกกลับเข้าร่วมได้หรือไม่ ตัวเลือกเสริม คำสั่งควบคุมรายการรอ จำกัดเฉพาะผู้ดูแลแชต/ผู้ดำเนินรายการ/ผู้ดูแลระบบ: !wlstop, !wlremove, !wlreset, !wlpick, และ !wlhighlight เปิดสิ่งเหล่านี้อย่างตั้งใจ คำสั่งเข้าร่วมของผู้ชมอย่างเดียวไม่ได้เปิดให้

5. ซ้อมและกู้คืน

ใช้ผู้ใช้สมมติที่ต่างกันใน ข้อความทดสอบ เพื่อตรวจพฤติกรรมการโหวตและเข้าร่วม คนเดียวที่ใช้สองแพลตฟอร์มไม่อาจถือว่าเป็นตัวตนร่วมเดียวกันได้แน่นอน ยืนยันว่าผลปรากฏใน OBS ก่อนเชิญผู้ชมเข้าร่วม

  • ไม่มีคะแนนโหวต: ตรวจ Enable Poll ว่าจบโหวตแล้วหรือไม่ การจับคู่ตรง และผู้ใช้นั้นโหวตแล้วหรือยัง
  • ไม่มีผู้เข้าร่วม: ตรวจทริกเกอร์รายการรอ คำสั่งที่ตรง สถานะหยุดรับรายชื่อ และข้อจำกัดเฉพาะสมาชิก
  • มีจำนวนแต่ไม่มีรายชื่อ: สุ่มผู้ชนะแสดงรายชื่อและผู้ชนะแทนคิวปกติ
  • ผลใน OBS ไม่ตรง: แทนที่ URL ที่บันทึก ตรวจเซสชัน/รหัสผ่าน และหลีกเลี่ยงหน้าโพลซ้ำที่ตั้งค่าแยกกัน

สำหรับปุ่มฮาร์ดแวร์หรือปุ่มฝั่ง OBS ดู ตั้งค่า Stream Deck และ แผงด็อกควบคุม OBS.
