โหมด WebSocket ที่โฮสต์ไว้และ Local Server

ใช้เส้นทาง WebSocket ที่ Social Stream โฮสต์ไว้สำหรับการตั้งค่าส่วนขยาย Chrome และแอปเดสก์ท็อปทั่วไป เรียกใช้เซิร์ฟเวอร์ส่งต่อภายในเครื่องเฉพาะเมื่อจำเป็นจริง ๆ

ควรใช้โหมดใด?เปิดโหมด WebSocket ที่โฮสต์ไว้แฟล็กเซิร์ฟเวอร์ทั้งสามทำอะไรขั้นสูง: ใช้ Local Server ของ SSAppตัวเลือกภายในเครื่องขั้นสูงปัญหาที่พบบ่อยคู่มือที่เกี่ยวข้อง

ควรใช้โหมดใด?

ผู้ใช้ส่วนใหญ่ไม่จำเป็นต้องเปิด Local Server ส่วนขยาย Chrome และการตั้งค่า SSApp ปกติใช้บริการ WebSocket ที่ Social Stream โฮสต์ไว้ได้โดยเปิดสวิตช์เส้นทางด้านล่าง Local Server เป็นตัวแทนขั้นสูงสำหรับเซิร์ฟเวอร์ส่งต่อที่โฮสต์ไว้

โหมดควรใช้เมื่อใด
WebRTC ปกติใช้ค่าเริ่มต้นต่อไปเมื่อแผงด็อกและโอเวอร์เลย์เชื่อมต่อได้ดีอยู่แล้ว ไม่ต้องเพิ่มแฟล็กเซิร์ฟเวอร์
WebSocket ที่โฮสต์ไว้เซิร์ฟเวอร์สำรองปกติสำหรับส่วนขยาย Chrome หรือ SSApp ใช้เซิร์ฟเวอร์ส่งต่อสาธารณะของ Social Stream และไม่ต้องใช้ File > Enable Local Server.
Local Serverสำหรับการใช้งานขั้นสูงเท่านั้น: โฮสต์เซิร์ฟเวอร์ส่งต่อบนคอมพิวเตอร์ SSApp เอง หรือใช้เมื่อเครือข่ายในภูมิภาค องค์กร หรือเครือข่ายที่จำกัดเข้าถึงบริการ WebSocket สาธารณะไม่ได้

เปิดโหมด WebSocket ที่โฮสต์ไว้

  1. เปิดป๊อปอัปส่วนขยาย Social Stream Ninja หรือแผงการตั้งค่าใน SSApp
  2. เปิด Global settings and tools > Mechanics - Connections & Integrations.
  3. เปิดใช้ อนุญาตให้แผงด็อกใช้และส่งข้อมูลผ่านเซิร์ฟเวอร์ API ซึ่งจะเพิ่ม server ลงในลิงก์ที่สร้างขึ้นที่รองรับ
  4. เปิดใช้ ส่งข้อความจากส่วนขยายไปยังแผงด็อกผ่านเซิร์ฟเวอร์ ซึ่งจะเพิ่ม server2 และส่งแชตที่เก็บได้ไปยังแผงด็อก
  5. หากต้องการตอบกลับ ดูแลแชต หรือส่งคำสั่งแหล่งข้อมูลจากแผงด็อกกลับไปยังส่วนขยาย ให้เปิด แผงด็อกส่งคำสั่งไปยังส่วนขยายผ่านเซิร์ฟเวอร์ ซึ่งจะเพิ่ม server3.
  6. คงค่า ทดลอง/ชั่วคราว: ส่งแชตที่กำหนดเส้นทางผ่าน API ไปยังการเชื่อมต่อแผงด็อก/โอเวอร์เลย์ปกติด้วย ไว้ในสถานะปิด เว้นแต่กำลังทดสอบการส่งข้อมูลเพิ่มเติมโดยเฉพาะ
  7. คงค่า การเชื่อมต่อแบบเพียร์ทูเพียร์ผ่านเครือข่ายภายในเท่านั้น ไว้ในสถานะปิดสำหรับการตั้งค่าเซิร์ฟเวอร์ที่โฮสต์ไว้ตามปกติ
  8. คัดลอกลิงก์แผงด็อกและโอเวอร์เลย์ใหม่ แทนที่ URL เก่าที่บันทึกใน OBS แล้วเปิดหน้าเว็บที่กำลังทำงานใหม่

หากแผงด็อกมีตัวเลือก เปิด Server Fallback ทางลัดนี้เปิดเส้นทางสำรองสำหรับแชตและคำสั่งพร้อมกัน ให้เปิดส่วนการตั้งค่านี้แล้วตรวจสอบว่าสวิตช์แรก อนุญาตให้แผงด็อกใช้และส่งข้อมูลผ่านเซิร์ฟเวอร์ API เปิดอยู่ด้วย เพื่อให้ครบทั้งสามเส้นทาง

แฟล็กเซิร์ฟเวอร์ทั้งสามทำอะไร

แฟล็กทิศทางใช้
serverเส้นทางแผงด็อก/APIให้หน้าแผงด็อกและ API ที่รองรับใช้และส่งข้อมูลผ่านเส้นทางเซิร์ฟเวอร์ที่โฮสต์ไว้
server2ส่วนขยายไปยังแผงด็อกส่งข้อความแชตที่เก็บได้ไปยังแผงด็อกผ่านเซิร์ฟเวอร์ที่โฮสต์ไว้
server3แผงด็อกไปยังส่วนขยายส่งการตอบกลับและคำสั่งที่รองรับกลับไปยังส่วนขยาย ไม่จำเป็นสำหรับแผงด็อกที่ใช้ดูอย่างเดียว

ลิงก์แผงด็อกแบบสองทางที่สร้างขึ้นอาจมี:

https://socialstream.ninja/dock.html?session=YOUR_SESSION_ID&server&server2&server3

คัดลอกลิงก์ที่สร้างให้ แทนการเพิ่มแฟล็กในทุกหน้าด้วยมือ แผงด็อก โอเวอร์เลย์ การแจ้งเตือน เกม และหน้าเครื่องมือรองรับเส้นทางต่างกัน

ขั้นสูง: ใช้ Local Server ของ SSApp

Local Server แทนที่ปลายทาง WebSocket สาธารณะที่โฮสต์ไว้ด้วยเซิร์ฟเวอร์ส่งต่อในแอปเดสก์ท็อป Social Stream Ninja ใช้เมื่อต้องการโฮสต์เซิร์ฟเวอร์ส่งต่อเองโดยตั้งใจ หรือเครือข่าย/ภูมิภาคของคุณเข้าถึงเซิร์ฟเวอร์สาธารณะไม่ได้

บริการนี้ใช้ส่งต่อข้อมูล ไม่ใช่โฮสต์เว็บไซต์ บริการนี้ไม่ให้บริการหน้า SSN ไม่เก็บแชตจากแพลตฟอร์มด้วยตัวเอง และไม่เปิด Local Control API

  1. ตั้งค่าสวิตช์เส้นทางผ่านเซิร์ฟเวอร์ที่โฮสต์ไว้ด้านบนให้ครบ ทิศทางของ server, server2 และ server3 ยังเหมือนเดิม
  2. ใน SSApp ให้เลือก File > Enable Local Server เมนูจะแสดงพอร์ตที่เลือกไว้
  3. คัดลอกลิงก์แผงด็อกและโอเวอร์เลย์ใหม่ SSApp เพิ่ม localserver และค่าที่ใช้อยู่ของ localserverport ในหน้าที่รองรับ
  4. แทนที่ URL เก่าที่บันทึกไว้ใน OBS แล้วเปิดหน้าเว็บที่ใช้งานอยู่ใหม่
  5. ส่งข้อความทดสอบจำลอง แล้วทดสอบการตอบกลับหรือคำสั่งแผงด็อกหาก server3 เปิดอยู่

การติดตั้งใหม่โดยทั่วไปใช้ 127.0.0.1:3003 การติดตั้งที่อัปเกรดมาซึ่งเคยใช้พอร์ต 3000 อาจคงพอร์ตเดิมไว้ ลิงก์แผงด็อกภายในเครื่องแบบสองทางที่สร้างขึ้นอาจมี:

https://socialstream.ninja/dock.html?session=YOUR_SESSION_ID&server&server2&server3&localserver&localserverport=3003

สำหรับมินิเกม ให้เปิด ส่งข้อความจากส่วนขยายไปยังแผงด็อกผ่านเซิร์ฟเวอร์ แล้วคัดลอกลิงก์เกมหลังเลือกเกม ลิงก์เกมภายในเครื่องที่มี server2 รับแชตที่เก็บได้จาก SSApp โดยตรง แม้ไม่ได้เปิดแผงด็อก การเปลี่ยนเกมจะคงโหมดภายในเครื่องและพอร์ตไว้

ตัวอย่าง API และเครื่องมือข้อความทดสอบใช้ WebSocket ในโหมดภายในเครื่อง เซิร์ฟเวอร์ส่งต่อภายในไม่รับ URL แบบ HTTP GET, POST หรือเว็บฮุกของ API สาธารณะ ตัวรับเว็บฮุกสาธารณะต้องใช้เซิร์ฟเวอร์ส่งต่อที่โฮสต์ไว้ ส่วนตัวรับที่เชื่อถือได้เฉพาะผู้ให้บริการเป็นบริการแยกต่างหาก

Local Server ไม่ได้ทำให้ทุกฟีเจอร์ทำงานออฟไลน์ได้ รายชื่อรอ Word Cloud คำสั่ง GIF แบบกำหนดเอง คำขอแชตบอตส่วนตัว และบริดจ์ควบคุม AI/ผู้ช่วยดำเนินรายการยังใช้ WebRTC สำหรับการสื่อสารบางส่วนหรือทั้งหมด ไฟล์เว็บไซต์ แชตแพลตฟอร์ม และบริการ AI เสียง เพลง หรือการชำระเงินภายนอกยังอาจต้องเชื่อมต่ออินเทอร์เน็ต

ตัวเลือกภายในเครื่องขั้นสูง

ใช้พอร์ตอื่น

  1. เลือก File > Set Local Server Port.
  2. เลือกพอร์ตที่ว่างในช่วง 1024 ผ่าน 65535.
  3. คัดลอกลิงก์ที่สร้างใหม่เพื่อให้มีค่าใหม่ของ localserverport.
  4. แทนที่ URL ที่บันทึกไว้ใน OBS แล้วเปิดหน้าเว็บที่ใช้งานอยู่ใหม่

การเปลี่ยนพอร์ตนี้ไม่เปลี่ยน Local Control API ที่ 17777 หรือเซิร์ฟเวอร์สื่อภายในเครื่องที่ 3001.

การเข้าถึงผ่าน LAN ที่เชื่อถือได้ (ไม่บังคับ)

File > Allow Local Server Connections from the LAN เปลี่ยนเซิร์ฟเวอร์ส่งต่อจากรับเฉพาะ loopback เป็นรับผ่านอินเทอร์เฟซเครือข่ายของคอมพิวเตอร์ ไคลเอนต์บนอุปกรณ์อื่นต้องเชื่อมต่อไปยังที่อยู่ LAN ของคอมพิวเตอร์ SSApp ไม่ใช่ 127.0.0.1.

โหมด LAN ไม่มีการยืนยันตัวตนหรือการเข้ารหัส ใช้เฉพาะในเครือข่ายส่วนตัวที่เชื่อถือได้ อย่าทำ port forwarding หรือเปิดสู่อินเทอร์เน็ต สำหรับการควบคุมข้ามเครื่องผ่านอินเทอร์เน็ตตามปกติ ให้ใช้การรับส่ง WebRTC หรือ WebSocket ที่โฮสต์ไว้ของ Social Stream

ปัญหาที่พบบ่อย

ปัญหาสิ่งที่ต้องตรวจ
แผงด็อกหรือโอเวอร์เลย์ยังว่างเปล่ายืนยันว่าแหล่งข้อมูลกับหน้าเว็บใช้เซสชันและรหัสผ่านเดียวกัน สำหรับโหมดเซิร์ฟเวอร์ที่โฮสต์ไว้ ให้ยืนยันว่า server และ server2 อยู่ในลิงก์แผงด็อกที่เพิ่งคัดลอก
แชตเข้ามาได้ แต่ตอบกลับไม่ได้เส้นทางขาเข้าและเส้นทางคำสั่งแยกกัน ให้เปิด แผงด็อกส่งคำสั่งไปยังส่วนขยายผ่านเซิร์ฟเวอร์ เพื่อให้ลิงก์มี server3.
WebSocket ที่โฮสต์ไว้เชื่อมต่อไม่ได้เครือข่ายในบางภูมิภาค องค์กร โรงเรียน หรือเครือข่ายที่มีการกรองอาจบล็อกเซิร์ฟเวอร์ส่งต่อสาธารณะ ให้ลองเครือข่ายอื่นก่อน ผู้ใช้ SSApp ขั้นสูงใช้ Local Server แทนได้
ลิงก์ใช้พอร์ต 3000 แต่ SSApp แสดง 3003แทนที่ลิงก์เก่า การติดตั้งใหม่เพิ่ม localserverport=3003 การติดตั้งเก่าอาจตั้งใจใช้พอร์ตเดิม 3000.
Local Server เริ่มทำงานไม่ได้โปรแกรมอื่นอาจใช้พอร์ตนั้นอยู่ เลือกพอร์ตอื่นที่ว่าง เริ่มเซิร์ฟเวอร์ส่งต่อใหม่ แล้วคัดลอกลิงก์ใหม่
เข้าร่วมเกมได้บ้างไม่ได้บ้างคัดลอกลิงก์เกมอีกครั้งหลังเลือกพรีเซ็ต ยืนยันว่าเซสชัน localserverport และเส้นทางแชตขาเข้าตรงกับ SSApp URL ที่บันทึกไว้ใน OBS จะไม่เปลี่ยนโดยอัตโนมัติเมื่อเปิด/ปิด Local Server หรือเปลี่ยนพอร์ต
Event Flows แจ้งข้อผิดพลาดการโหลดเบื้องหลังปัญหานี้เกี่ยวกับไฟล์เว็บไซต์ ไม่ใช่เซิร์ฟเวอร์ส่งต่อแชต ลองโหลดใหม่เมื่อการเชื่อมต่อกลับมา การเปิด/ปิดเซิร์ฟเวอร์ส่งต่อจะคงต้นทางพื้นที่เก็บข้อมูล Event Flow ที่เลือกไว้ แต่การเริ่มแบบออฟไลน์แยกต่างหากยังอาจเปิดหน้าที่มาพร้อมแพ็กเกจซึ่งมีพื้นที่เก็บข้อมูลของตัวเอง
อุปกรณ์ใน LAN เชื่อมต่อไม่ได้ยืนยันว่าเปิดการเข้าถึง LAN ไคลเอนต์ใช้ IP ภายใน LAN ของคอมพิวเตอร์ SSApp และไฟร์วอลล์อนุญาตพอร์ตที่เลือก

คู่มือที่เกี่ยวข้อง

  • ทำความเข้าใจเซิร์ฟเวอร์และบริการในเครื่อง
  • เซสชัน รหัสผ่าน รีเลย์ และโหมดเซิร์ฟเวอร์
  • Local Control API และ MCP
