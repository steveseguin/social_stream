ความเข้ากันได้ของอีเวนต์และการแจ้งเตือน

เชื่อมอีเวนต์แพลตฟอร์มที่จับได้กับ Multi Alerts โดยไม่สับสนระหว่างแชตปกติ การบริจาค และข้อมูลอีเวนต์

เริ่มจากแหล่งอีเวนต์หมวดหมู่ Multi Alertsอีเวนต์แพลตฟอร์มหลักโหมดมาตรฐานกับ WebSocketเปิดประเภทแจ้งเตือนที่ต้องการดูตัวอย่างก่อนถ่ายทอดสดเมื่อการแจ้งเตือนจริงหายไป

เริ่มจากแหล่งอีเวนต์

Multi Alerts แสดงอีเวนต์ที่ Social Stream จับมาแล้ว ไม่ได้เข้าสู่ระบบ Twitch, Kick, YouTube, TikTok หรือแพลตฟอร์มอื่นด้วยตัวเอง

  1. เชื่อมต่อและเปิดใช้แหล่งแพลตฟอร์มที่ให้อีเวนต์
  2. เปิดหน้าแหล่งข้อมูลหรือหน้าต่างแหล่งในแอปแยกให้ทำงานอยู่
  3. ใช้รหัสเซสชัน Social Stream เดียวกันในแหล่งข้อมูล ป๊อปอัป แผงด็อก และ URL ของ Multi Alerts
  4. ทดสอบโอเวอร์เลย์แจ้งเตือนจากตัวเลือกก่อนแก้ปัญหาการเชื่อมต่อแพลตฟอร์ม

ตัวอย่างที่สำเร็จยืนยันว่าเลย์เอาต์แจ้งเตือนทำงาน ไม่ได้ยืนยันว่าแหล่งแพลตฟอร์มมีสิทธิ์รับอีเวนต์สดนั้น

หมวดหมู่ Multi Alerts

หมวดหมู่ชื่ออีเวนต์ที่พบบ่อยหมายเหตุ
ติดตามnew_follower, follow, followedต้องใช้แหล่งที่จับอีเวนต์ติดตามและมีสิทธิ์แพลตฟอร์มที่จำเป็น
การสมัครสมาชิกnew_subscriber, resub, subscription_gift, ชื่อเรียกแทนสมาชิกรวมอีเวนต์ต่ออายุ ของขวัญ และสมาชิกในกรณีที่รองรับ
การบริจาค / ของขวัญsuperchat, supersticker, gift, tip, ชื่อเรียกแทนการบริจาคแถวแชตแบบบริจาคอาจใช้แทนเป็น hasDonation และ donoValue.
บิตcheer, bitsกรองยอดได้ด้วยตัวเลือกบริจาค/เงินขั้นต่ำ
เรดraid, host, redirectการรองรับและชื่อขึ้นอยู่กับแหล่งแพลตฟอร์ม
ประมูลauction_updateการแจ้งเตือนชนะประมูลต้องเลือกเปิดใช้
Hype Trainhype_trainการแจ้งเตือน Hype Train ต้องเลือกเปิดและต้องมีสิทธิ์เข้าถึง Twitch EventSub ที่เหมาะสม

จำนวนผู้ชม ยอดผู้ติดตาม สถานะสตรีม และสถานะช่วงโฆษณาเป็นข้อมูลอัปเดต ไม่ใช่การ์ดแจ้งเตือนปกติ ใช้ เอกสารอ้างอิงอีเวนต์ เมื่อสร้างผู้ใช้ข้อมูล API หรือโอเวอร์เลย์กำหนดเอง

โหมดมาตรฐานกับ WebSocket

แพลตฟอร์มการจับมาตรฐานการจับ WebSocket / API
YouTube ข้อความแบบชำระเงิน สมาชิก ของขวัญสมาชิก อัปเดตผู้ชม และอีเวนต์ที่ตรวจจากหน้าได้จำกัด อีเวนต์ชำระเงิน/สมาชิกร่วม พร้อมเหตุการณ์สำคัญสมาชิก การแจ้งเตือนผู้ติดตามสาธารณะล่าสุด และอัปเดตจำนวนที่รองรับ
Twitch รางวัลที่แสดงในแชต ประกาศสมาชิกแบบของขวัญ อัปเดตผู้ชม และประกาศเฉพาะหน้าบางรายการ EventSub เพิ่มผู้ติดตาม สมาชิก ต่ออายุ cheers เรด รางวัล และอีเวนต์จำนวน/สถานะที่รองรับ เมื่อบัญชีและขอบเขตสิทธิ์อนุญาต
Kick แชตพร้อมตัวระบุจากหน้าแบบเล็กสำหรับของขวัญ รางวัล และอัปเดตผู้ชม อีเวนต์ติดตาม สมัครสมาชิก ของขวัญ แลกรางวัล KICKs ดูแลแชต และสถานะสดอย่างเป็นทางการเมื่อยืนยันตัวตนแล้ว

ปกติโหมด WebSocket เหมาะกับการแจ้งเตือนที่ขับเคลื่อนด้วยอีเวนต์ การจับมาตรฐานยังมีประโยชน์เมื่อต้องการเพียงแชตที่แสดงหรือยืนยันตัวตนไม่ได้

เปิดประเภทแจ้งเตือนที่ต้องการ

เปิดตัวเลือก Multi Alerts จากการตั้งค่า Social Stream การติดตาม สมาชิก บริจาค บิต และเรดมีปุ่มเปิด รูปแบบ เสียง และหน้าตาของตัวเอง การแจ้งเตือนประมูลและ Hype Train ต้องเลือกเปิดด้วยปุ่มเฉพาะ

  • ใช้ เข้าคิวการแจ้งเตือน เมื่อหลายอีเวนต์อาจเข้ามาพร้อมกัน
  • ตรวจตัวกรองแหล่งข้อมูลหากอีเวนต์ทำงานในแผงด็อกแต่ไม่ทำงานใน Multi Alerts
  • ตรวจตัวกรองเงิน/บริจาคขั้นต่ำเมื่อทิปเล็กหรือ cheers หายไป
  • โต้ตอบกับหน้าเบราว์เซอร์หนึ่งครั้งหากเสียงแจ้งเตือนกำหนดเองถูกกฎเล่นอัตโนมัติบล็อก

ดูตัวอย่างก่อนถ่ายทอดสด

ใช้ปุ่มดูตัวอย่างเพื่อตรวจหมวดที่เลือก ข้อความ ยอด สื่อ เสียง ภาพเคลื่อนไหว และพฤติกรรมคิว

เครื่องมือแต่ละตัวใช้ช่องใด

เครื่องมือกฎความเข้ากันได้
Multi Alertsจำแนกค่ามาตรฐาน event ชื่อ ชื่อเรียกแทน, hasDonation, ช่องสมาชิก และค่าที่เลือก meta ค่าเข้าเป็นหมวดร่วม
Event Flowจับคู่ให้ตรงทุกตัวสำหรับ type, event, และช่องที่แหล่งข้อมูลส่ง ใช้เครื่องมือ Test Message ก่อนพึ่งอีเวนต์สด
TTSแถวอีเวนต์ถูกข้ามตามค่าเริ่มต้นเว้นแต่เป็นแบบบริจาค เพิ่ม &readevents เมื่อต้องการให้อ่านข้อความอีเวนต์ที่ไม่ใช่บริจาค แล้วใช้ตัวกรอง TTS ปกติ
โหลทิป / มาตรวัดเป้าหมายโหมดปกติใช้ยอดบริจาค โหมด Hype ให้คะแนนช่องสมาชิก ต่ออายุ และสมาชิกแบบของขวัญได้ด้วย
โอเวอร์เลย์กำหนดเอง / ผู้ใช้ข้อมูล APIใช้ช่องข้อมูลมาตรฐานจากเอกสารอ้างอิงอีเวนต์ รับชื่อเรียกแทนที่บันทึกไว้เฉพาะเพื่อความเข้ากันได้ย้อนหลัง

ใช้ สร้างข้อความทดสอบ เพื่อตรวจอีเวนต์ที่คาดหวังและ ตัวอย่าง Event Flow สำหรับตัวอย่างระบบอัตโนมัติที่ใช้งานได้

หมายเหตุตั้งค่าแพลตฟอร์ม

แพลตฟอร์มสิ่งที่ตรวจเป็นอันดับแรกคู่มือ
Twitchเข้าสู่ระบบด้วยเจ้าของช่องหรือผู้ดูแลที่มีสิทธิ์ และคงการเชื่อมต่อ EventSubตั้งค่า Twitch EventSub
Kickเลือกโหมดแหล่งข้อมูลอย่างตั้งใจและยืนยันตัวตนให้ครบเมื่ออีเวนต์อย่างเป็นทางการที่ต้องการกำหนดไว้ อย่าคาดหวังอีเวนต์เรดอย่างเป็นทางการการตั้งค่าและยืนยันตัวตน Kick
แหล่งอื่นยืนยันว่าแหล่งที่เลือกส่งอีเวนต์ประเภทนั้นจริง ไม่ใช่เฉพาะข้อความแชตเว็บไซต์ที่รองรับ

เมื่อการแจ้งเตือนจริงหายไป

  1. ยืนยันว่าแหล่งได้รับอีเวนต์ในล็อกของตัวเอง แผงด็อก หรือเอาต์พุต API
  2. ยืนยันว่าแหล่งข้อมูลและหน้า Multi Alerts ใช้รหัสเซสชันและรหัสผ่านเดียวกัน
  3. ยืนยันว่าหมวดนั้นเปิดอยู่และไม่ถูกตัวกรองแหล่งข้อมูลหรือช่องตัดออก
  4. ตรวจตัวกรองมูลค่าขั้นต่ำสำหรับบริจาคและบิต
  5. สำหรับ Twitch หรือ Kick ให้เข้าสู่ระบบใหม่หากแชตทำงานแต่อีเวนต์ที่ต้องมีสิทธิ์ไม่ทำงาน
  6. เปิดหน้าต่างแหล่งนานพอให้พบอีเวนต์จริง ตัวอย่างอย่างเดียวไม่ใช่การทดสอบแพลตฟอร์มครบทุกขั้นตอน

หากเกี่ยวข้องหลายอุปกรณ์หรือโหมดเชื่อมต่อ ให้ดู เซสชัน รหัสผ่าน และโหมดรีเลย์.
