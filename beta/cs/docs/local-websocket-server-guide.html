Režimy hostovaného WebSocket a místního serveru

Pro běžné sestavy rozšíření Chrome a desktopové aplikace použijte hostované trasy WebSocket Social Stream. Místní přenos provozujte pouze tehdy, když jej výslovně potřebujete.

Který režim použít?

Většina uživatelů by místní server neměla zapínat. Rozšíření Chrome i běžné sestavy SSApp mohou používat hostovanou službu WebSocket Social Stream zapnutím níže uvedených přepínačů směrování. Místní server je pokročilá náhrada hostovaného přenosu.

RežimKdy jej použít
Běžné WebRTCPokud se dok a překryvy již spolehlivě připojují, ponechte výchozí nastavení. Žádné příznaky serveru nejsou potřeba.
Hostovaný WebSocketBěžný záložní server pro rozšíření Chrome nebo SSApp. Používá veřejný hostovaný přenos Social Stream a nevyžaduje Soubor > Zapnout místní server (File > Enable Local Server).
Místní serverPouze pokročilé použití: hostujte přenos na počítači SSApp nebo jej použijte, když regionální, firemní či omezená síť nedosáhne na veřejnou hostovanou službu WebSocket.

Zapnutí hostovaného režimu WebSocket

  1. Otevřete vyskakovací okno rozšíření Social Stream Ninja nebo panel nastavení v SSApp.
  2. Otevřít Globální nastavení a nástroje > Mechaniky – Připojení a integrace (Global settings and tools > Mechanics - Connections & Integrations).
  3. Zapněte Povolit doku používat a publikovat přes server API. Tím se přidá server do podporovaných vygenerovaných odkazů.
  4. Zapněte Odesílat zprávy z rozšíření do doku přes server. Tím se přidá server2 a přenáší zachycený chat do doku.
  5. Pokud chcete odpovědi nebo příkazy moderování a zdrojů cestující z doku zpět do rozšíření, zapněte Dok odesílá své příkazy rozšíření přes server. Tím se přidá server3.
  6. Ponechte Experimentální/dočasné: odesílat chat směrovaný přes API také do běžných připojení doku/překryvů vypnuté, pokud výslovně netestujete doplňkové doručování.
  7. Ponechte Připojení peer-to-peer pouze přes místní síť vypnuté pro běžné hostované nastavení.
  8. Zkopírujte nové odkazy doku a překryvů, nahraďte staré uložené URL v OBS a znovu otevřete všechny již spuštěné stránky.

Pokud dok nabízí Zapnout záložní server, tato zkratka zapíná záložní trasy chatu i příkazů společně. Otevřete tuto část nastavení a ověřte, že první Povolit doku používat a publikovat přes server API přepínač je pro úplné nastavení tří tras také zapnutý.

Co dělají tři serverové příznaky

PříznakSměrPoužijte
serverTrasa doku/APIUmožňuje podporovaným stránkám doku a API používat a publikovat přes hostovanou serverovou trasu.
server2Z rozšíření do dokuOdesílá zachycené zprávy chatu do doku přes hostovaný server.
server3Z doku do rozšířeníVrací podporované odpovědi a příkazy do rozšíření. Pro dok pouze k zobrazení je volitelné.

Vygenerovaný obousměrný odkaz doku může obsahovat:

https://socialstream.ninja/dock.html?session=YOUR_SESSION_ID&server&server2&server3

Kopírujte vygenerované odkazy místo ručního přidávání příznaků do každé stránky. Podpora směrování se liší mezi dokem, překryvy, upozorněními, hrami a pomocnými stránkami.

Pokročilé: použijte místní server SSApp

Místní server nahrazuje veřejný hostovaný koncový bod WebSocket přenosem běžícím uvnitř desktopové aplikace Social Stream Ninja. Použijte jej, pokud záměrně chcete přenos hostovat sami nebo veřejný server není dostupný z vaší sítě či regionu.

Jde o přenos, nikoli webový hosting. Neposkytuje rozhraní SSN, samo nezachytává chat platforem ani nezpřístupňuje místní ovládací API.

  1. Dokončete výše uvedené nastavení přepínačů hostovaných tras. Stejné server, server2a volitelné server3 směry stále platí.
  2. V SSApp vyberte Soubor > Zapnout místní server (File > Enable Local Server). Nabídka ukazuje vybraný port.
  3. Zkopírujte nové odkazy doku a překryvů. SSApp přidává localserver a aktivní localserverport kde je podporováno.
  4. Nahraďte staré uložené URL v OBS a znovu otevřete aktivní stránky.
  5. Odešlete falešnou testovací zprávu a potom otestujte odpověď nebo příkaz doku, pokud server3 je zapnuté.

Nové instalace běžně používají 127.0.0.1:3003. Aktualizovaná instalace, která již používala port 3000 jej může zachovat. Vygenerovaný místní obousměrný odkaz doku může obsahovat:

https://socialstream.ninja/dock.html?session=YOUR_SESSION_ID&server&server2&server3&localserver&localserverport=3003

Pro minihry zapněte Odesílat zprávy z rozšíření do doku přes server a po výběru hry zkopírujte její odkaz. Místní herní odkazy s server2 přijímají zachycený chat přímo z SSApp, i když není otevřen žádný dok. Změna hry zachovává místní režim a port.

Ukázka API a nástroj testovacích zpráv používají v místním režimu WebSocket. Místní přenos nepřijímá URL HTTP GET, POST ani webhooků veřejného API. Veřejné přijímače webhooků potřebují hostovaný přenos; spolehlivé přijímače konkrétních poskytovatelů jsou samostatné služby.

Místní server nezajistí fungování všech funkcí offline. Pořadník, Mrak slov, vlastní příkazy GIF, požadavky soukromého chatbota a mosty ovládání AI/spolumoderátora stále používají WebRTC pro část nebo celou komunikaci. Soubory webu, chat platforem a externí služby AI, hlasu, hudby nebo plateb mohou nadále vyžadovat internet.

Pokročilé místní možnosti

Použití jiného portu

  1. Vyberte Soubor > Nastavit port místního serveru (File > Set Local Server Port).
  2. Vyberte nepoužitý port v 1024 přes 65535.
  3. Zkopírujte nové vygenerované odkazy, aby obsahovaly nové localserverport.
  4. Nahraďte uložené URL v OBS a znovu otevřete aktivní stránky.

Změna tohoto portu nemění místní ovládací API na 17777 ani místní mediální server na 3001.

Volitelný přístup z důvěryhodné LAN

Soubor > Povolit připojení k místnímu serveru z LAN (File > Allow Local Server Connections from the LAN) mění přenos z naslouchání pouze na místní smyčce na síťová rozhraní počítače. Klient na jiném zařízení se musí připojit k adrese LAN počítače SSApp, nikoli 127.0.0.1.

Režim LAN nemá ověření ani šifrování. Používejte jej pouze v důvěryhodné soukromé síti. Nepřesměrovávejte jeho port ani jej nezpřístupňujte internetu. Pro běžné ovládání mezi počítači přes internet použijte stávající přenos WebRTC nebo hostovaný WebSocket Social Stream.

Běžné problémy

ProblémCo zkontrolovat
Dok nebo překryv zůstává prázdnýOvěřte, že zdroj a stránka používají stejnou relaci a heslo. Pro hostovaný režim ověřte server a server2 jsou v nově zkopírovaném odkazu doku.
Chat přichází, ale odpovědi selhávajíPříchozí trasa a trasa příkazů jsou oddělené. Zapněte Dok odesílá své příkazy rozšíření přes server aby odkaz obsahoval server3.
Hostovaný WebSocket se nepřipojujeRegionální, firemní, školní nebo filtrovaná síť může veřejný přenos blokovat. Nejprve zkuste jinou síť; pokročilí uživatelé SSApp mohou místo toho použít místní server.
Odkaz používá port 3000, ale SSApp ukazuje 3003Nahraďte starý odkaz. Nové instalace přidávají localserverport=3003; starší instalace mohou záměrně zůstat na 3000.
Místní server se nespustíPort může používat jiný program. Vyberte jiný nepoužitý port, restartujte přenos a znovu zkopírujte odkazy.
Připojování ke hře funguje přerušovaněPo výběru předvolby znovu zkopírujte odkaz hry. Ověřte jeho relaci, localserverporta trasa příchozího chatu odpovídají SSApp. Uložené URL v OBS se při přepnutí místního serveru nebo změně jeho portu automaticky nemění.
Event Flow hlásí chybu načítání pozadíTýká se to souborů webu, nikoli přenosu chatu. Po obnovení připojení zkuste načíst znovu. Přepnutí přenosu zachovává vybraný původ úložiště Event Flow; samostatné spuštění offline může stále otevřít přibalené rozhraní s vlastním úložištěm.
Zařízení v LAN se nemůže připojitOvěřte, že je zapnutý přístup z místní sítě, klient používá IP počítače SSApp v místní síti a firewall povoluje vybraný port.
