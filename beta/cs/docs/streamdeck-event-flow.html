Úplný návod k ovládání, gestům a ikonám Stream Deck

Vytvořte tok, který lze vyvolat

Event Flow→Pojmenovaný pracovní postup→Klíč Stream Deck
  1. Pojmenovaný spouštěčStream Deck / API
  2. Podmínky a akceVáš uložený Event Flow
  3. CílFlow Actions, OBS nebo jiná integrace
  1. Otevřít Event Flow z SSN. Vytvořte samostatný tok nebo zvolte šablonu Tlačítko Stream Deck / API .
  2. Přidejte Spustit ze Stream Deck / API ve skupině spouštěčů Stream Deck a API .
  3. Pojmenujte jej intermission. Názvy se porovnávají přesně a rozlišují velikost písmen; použijte krátký výstižný název.
  4. Propojte jeho výstup s Zobrazit text. Nastavte text na Back in five minutes, a vyberte požadovanou dobu a vrstvu.
  5. Uložte tok a poté jej zapněte. Neuložený tok existuje jen v editoru; vypnutý tok nelze vyvolat. Výchozí šablona je záměrně vypnutá, dokud nedokončíte nastavení.
  6. Otevřete svůj Překryv Flow Actions pomocí odkazu vygenerovaného SSN. Pro diváky přidejte tuto URL jako zdroj Prohlížeč v OBS. Samotný editor není překryv.

Toky bez tohoto pojmenovaného spouštěče nelze vyvolat přes API toků. Vyvolání toku nevkládá falešný chat do doku. Stávající události OBS a běžný chat nadále používají své stávající spouštěče.

Tok může kombinovat svůj pojmenovaný spouštěč s filtry pomocí logických uzlů. Nesouvisející automatizace ponechte v samostatných tocích: všechny větve spouštěčů a logiky ve vybraném toku se vyhodnocují s událostí API. Opakované stisky spouštějí samostatné běhy; vložte Omezovač četnosti stavový uzel za spouštěč, pokud chcete prodlevu mezi spuštěními.

Připojte klávesu Stream Deck

  1. Nastavte v pluginu akci Nastavení se svou relací SSN a volitelným heslem. Použijte Otestovat připojení.
  2. Přetáhněte Přednastavený příkaz na klávesu.
  3. Vyberte Toky Event Flow → Spustit tok.
  4. Vyberte Obnovit toky, poté vyberte uložený tok a spouštěč. Klávesa si ukládá ID toku i název spouštěče.
  5. Stiskněte jednou a sledujte překryv Flow Actions. Zaškrtnutí na klávese znamená, že SSN spuštění přijalo.

Výběr toku zachovává i chybějící volby. Po přejmenování, vypnutí, smazání nebo importu toku seznam obnovte a zvolte tok znovu. Tok importovaný jako nový má jiné ID. Pro cílení podle názvu napříč více toky použijte pole Hodnota.

Vlastní příkaz: nastavte Akci na triggerWorkflow, pole Cíl nechte prázdné, zadejte {"trigger":"intermission"} jako Hodnotu a zapněte Čekat na odpověď. Předvolba nabízí výběr s průvodcem a filtrování podle schopností.

Více akcí: každý požadavek toku rychle potvrdí přijetí. Další krok Stream Deck může začít před dokončením zpožděných akcí toku. Pokud záleží na pořadí, vložte řazení a prodlevy přímo do Event Flow.

Předávání vlastních hodnot

V poli Hodnota klávesy nebo v požadavku API:

{
  "trigger": "intermission",
  "flowId": "YOUR_SAVED_FLOW_ID",
  "data": { "name": "Back in five minutes", "minutes": 5 }
}

Nastavte Zobrazit text na {meta.workflow.data.name}. Porovnat vlastnost může číst meta.workflow.data.minutes. Data jsou volitelný objekt JSON; zůstávají v meta.workflow.data a nemohou nahradit identitu události ani udělit oprávnění chatu.

Vynechte flowId pro vyvolání každého zapnutého toku s přesně tímto názvem spouštěče. Více odpovídajících uzlů spouštěče v jednom toku stále vyhodnotí tok jen jednou. Chcete-li spustit pouze jeden tok, ponechte jeho ID z výběru nebo odpovědi vyhledání.

Událost použitá uvnitř vybraného toku obsahuje type: "api", event: "workflow_trigger", chatname: "Stream Deck / API", prázdné chatmessage, a výše uvedená data. Běžný chat, který tato pole napodobí, nemůže aktivovat pojmenovaný spouštěč API.

Příklady API

Nechte SSN zapnuté a spuštěné. Jde o volání vzdáleného ovládání Social Stream; nepoužívají samostatné místní AI/MCP API aplikace SSApp. Skutečné ID relace uchovávejte v soukromí.

Zjistit dostupné spouštěče

{"action":"getWorkflowTriggers","get":"list-1","apiid":"YOUR_SESSION"}

Zpětné potvrzení obsahuje result.payload.triggers:

{"triggers":[{"flowId":"flow-123","flowName":"Intermission","trigger":"intermission"}]}

Spustit pojmenovaný tok

{
  "action": "triggerWorkflow",
  "value": {"trigger":"intermission","flowId":"flow-123","data":{"name":"Back shortly"}},
  "get": "run-1",
  "apiid": "YOUR_SESSION"
}

Pro každý požadavek použijte jedinečný get řetězec. Úspěšné zpětné potvrzení má result.ok: true, result.status: "accepted", a result.payload.matchedFlows. Přijetí znamená, že se zapnutý tok našel a naplánoval. Neznamená to dokončení každé zpožděné akce, webhooku, volání OBS nebo přehrávání médií.

WebSocket

Zapněte vzdálené ovládání rozšíření přes API (remote API control of extension) v SSN. Připojte k wss://io.socialstream.ninja. Připojte se pomocí {"join":"YOUR_SESSION","out":1,"in":2}, poté odešlete výše uvedený požadavek. Kanál 1 přenáší ovládání; kanál 2 přenáší zpětná potvrzení. Pro toky nemusíte zapínat kanál chatu.

HTTP

Zapněte stejné nastavení vzdáleného ovládání API. Před použitím nahraďte zástupnou hodnotu relace:

POST https://io.socialstream.ninja/YOUR_SESSION
Content-Type: application/json

{"action":"triggerWorkflow","value":{"trigger":"intermission","data":{"name":"Back shortly"}}}

Pro jednoduchý pojmenovaný spouštěč můžete také použít GET https://io.socialstream.ninja/YOUR_SESSION/triggerWorkflow/null/intermission. Čtvrtá část cesty může obsahovat JSON zakódovaný do URL pro strukturované hodnoty. Celou hodnotu JSON zakódujte pomocí encodeURIComponent(JSON.stringify(value)). Vlastní odesílací kanály používají ?channel=N.

P2P

Výchozí režim P2P pluginu posílá stejná data přes stávající přenos datovým kanálem VDO.Ninja v SSN. Pro P2P není nutný přepínač hostovaného WebSocket API. Stávající klienti P2P mají tento požadavek posílat přes své zavedené ovládací připojení SSN; místní AI API nemusí být otevřené.

Chyby a kompatibilita

  • WORKFLOW_NOT_FOUND: žádný uložený zapnutý tok neodpovídá spouštěči či ID toku.
  • INVALID_VALUE: chybějící či neplatný spouštěč, chybný JSON, neplatné ID toku nebo data, která nejsou objektem.
  • CONTROL_UNAVAILABLE: SSN nebo vzdálené ovládání hostitele je vypnuté.
  • TARGET_UNAVAILABLE: Event Flow se stále načítá.
  • Starší soubory Social Stream nemusí tyto akce nabízet. Zkontrolujte getCapabilities → ssn.actions.triggerWorkflow a getWorkflowTriggers. Musí být nainstalován nový spouštěč i aktualizovaný plugin; samotné číslo verze SSApp neurčuje vzdáleně načítané soubory Social Stream.

Po ztraceném potvrzení automaticky neopakujte volání měnící stav: tok už mohl začít. Nejprve zkontrolujte jeho výstup. Toto API neposkytuje frontu stavů spuštění.

Gesta časovače a chatu

Časovač: jeden krok otočení standardně mění čas o ±10 sekund; při otáčení držte ovladač stisknutý pro ±1 minutu (6× nastavený krok). Stiskem a uvolněním bez otáčení spustíte či pozastavíte. Klepnutím na displej časovače jej obnovíte; podržte displej pro reset. Samotné podržení fyzického ovladače reset neprovede.

Procházení chatu: otáčejte doleva pro starší chat, doprava pro novější; stiskem ovladače připněte prohlíženou zprávu. Klepnutím na displej zvýrazněte další připnutou zprávu; podržením displeje odepněte prohlíženou zprávu. Nechte výchozí dok otevřený. V režimu WebSocket zapněte přenos chatu na kanálu 4.

Otevřít Nápověda a diagnostika → Návod k ovládání, ikonám a tokům v pluginu pro úplný offline návod, všech pět typů akcí, každou předvolbu a ikonu, chování resetu, výchozí hodnoty a řešení problémů.

Přehled palety Event Flow

Paleta obsahuje 45 spouštěčů, 67 akcí, pět logických a čtyři stavové uzly. Každá položka má vedle symbolu textový popisek. Vyberte uzel pro zobrazení nastavení a požadavků integrace; samotná ikona v paletě nedokládá připojení cíle.

Spouštěče určují, kdy tok začne. Podle potřeby propojte podmínky pomocí AND/OR. Akce se provádějí v pořadí propojení. Stavové uzly uchovávají hodnoty mezi událostmi. Pro prodlevu tlačítka zvolte Omezovač četnosti (THROTTLE), nikoli akci Zpoždění: Zpoždění odloží každé spuštění a nepotlačí opakované stisky.

Filtry zpráv, divácké body a akce zapamatovaných uživatelů potřebují smysluplná data zprávy či uživatele. Tlačítko moderátora vysílání neposkytuje skutečného diváka ani cíl odpovědi do zdroje. Zvolte ovládání moderátora nebo výslovně nastavený cíl; pojmenovaný tok nepoužívejte k vydávání se za diváka.

Podrobné zapojení: viz Průvodce Event Flow, návod ke stavovým uzlům, návod k paměti uživatelů, a Návod k OBS.

Postup při selhání

  1. Nejprve použijte jednoduchý tok Zobrazit text a ověřte jeho výstup.
  2. Uložte a zapněte; obnovte seznam toků Stream Deck. Ověřte název spouštěče i ID toku.
  3. Ověřte, že je SSN zapnuté, připojení je Online a cílový překryv je připojen ke stejné relaci.
  4. Chyby vyhledání a ověření hledejte ve zpětném potvrzení API nebo diagnostice pluginu. Při selhání po přijetí požadavku zkontrolujte cíl a provozní záznamy Event Flow.
  5. Další integrace přidávejte postupně. Před živým použitím otestujte opakované stisky, vypnutý tok a opětovné připojení.

Běžný testovací panel chatu v editoru posílá událost chatu. Nenapodobuje pojmenovaný spouštěč API. Tento spouštěč otestujte přes Stream Deck nebo API, abyste ověřili celou cestu.
