Vysvětlení místních serverů a služeb

Social Stream Ninja používá několik různých místních služeb. Vyberte tu, která odpovídá tomu, co chcete dělat.

1. Zapnout místní server

Tato možnost v nabídce Soubor spouští uvnitř desktopové aplikace přenos WebSocket rozlišující místnosti a kanály. Podporované stránky Social Stream jej mohou použít k výměně chatu a příkazů na stejném počítači. Jde o alternativní koncový bod pro směrování serveru specifické pro stránku.

Nehostuje web Social Stream, samo nezachytává platformu ani neposkytuje HTTP API automatizace. Začněte průvodcem zapnutím místního serveru.

2. Místní ovládací API a MCP

Toto volitelně zapnuté API místní smyčky umožňuje programům na počítači SSApp spravovat podporované zdroje a nastavení, číst stav a diagnostiku, prohlížet okna aplikace nebo zdrojů a sledovat zachycené události. Přibalený adaptér MCP zpřístupňuje tyto operace jako nástroje kompatibilním klientům AI.

Zapněte jej v Soubor > Lokální AI / automatizace (File > Local AI / Automation). Je oddělené od Zapnout místní server (Enable Local Server). Viz průvodce místním ovládacím API a MCP.

3. Domácí server nebo VPS bez grafického rozhraní

Režim bez grafického rozhraní spouští celou desktopovou aplikaci Electron se skrytými okny zdrojů. Na Linuxu stále potřebuje zobrazovací zázemí, například Xvfb. Hodí se, když má vyhrazený počítač nepřetržitě zachytávat chat bez připojeného monitoru.

Režim bez grafického rozhraní nevytváří veřejné ovládací API. Dálkové ovládání používá běžný přenos WebRTC nebo WebSocket Social Stream. Viz průvodce hostingem bez grafického rozhraní.

4. Místní mediální server

Desktopová aplikace jej spouští automaticky, když jsou dostupná místní média Event Flow. Poskytuje pouze soubory schválené přes SSApp a vybrané soubory běhového prostředí pomocí náhodné tokenové cesty pro každý profil.

Není to obecný webový ani souborový server. Viz Mediální soubory pro Event Flow pro výběr mezi místními soubory, nahráváním a cloudovým hostingem.

Záložní server je jiná funkce

Nastavení, například Odesílat zprávy chatu na server API a Dok odesílá své příkazy rozšíření přes server určují směrování chatu a příkazů. Jejich vygenerované příznaky URL zahrnují server, server2, a server3.

Tato nastavení běžně používají hostovanou službu WebSocket Social Stream. Pokud podporovaná stránka také obsahuje localserver, používá místo toho místní přenos desktopové aplikace. Viz Relace, hesla, přenos a režimy serveru pro ovládání směrování.

Používejte čerstvě vygenerované odkazy. Příznaky směrování jsou specifické pro stránku. Nekopírujte příznak serveru z jedné stránky na druhou s předpokladem stejného významu.

Další dočasné místní porty

Některé postupy přihlášení a propojování účtů krátce otevřou port zpětného volání místní smyčky a po dokončení jej zavřou. Tyto dočasné naslouchající služby nejsou obecné servery SSN ani API automatizace.
