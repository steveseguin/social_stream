Connect alerts in 5 steps

These steps connect Fourthwall, Ko-fi and Buy Me a Coffee. For signed membership alerts, follow the Patreon steps below.

  1. Avatud Monetization → Fourthwall, Ko-fi, Buy Me a Coffee & Patreon alerts and pick your Teenusepakkuja.
  2. Klõpsake Receiver setting and turn on remote API control of extension.
  3. Go back to Monetization and click Copy webhook URL.
  4. Paste it into your provider's webhook settings (steps below).
  5. Keep Social Stream Ninja running.
Is it working? “Receiver connected” only means SSN is listening. The last-event line updates when a real event arrives (it resets on restart).
Keep the webhook URL private. For Fourthwall, Ko-fi and Buy Me a Coffee, it is the only lock on these alerts (no signing secret is checked). Patreon uses a signing secret. Fine for alerts, not proof of payment for shipping orders. Never post it or use it in a QR code.

Preview sample alert only shows the look. It doesn't touch totals, Event Flow, or your webhook.

NinjaBacker, Throne, Amazon, and eBay: see the monetization guide. Shopify: see Shopify setup.

Fourthwall

  1. In Fourthwall, open Settings → For Developers → Webhooks.
  2. Create a webhook and paste the Fourthwall URL from SSN.
  3. Tick the events you want (see table).
  4. Save, and keep SSN running.

Gift-card orders don't add their value twice. Test events are skipped.

Ko-fi

  1. Avatud Ko-fi Webhooks.
  2. Paste the Ko-fi URL from SSN into Webhook URL and save.
  3. Keep SSN running.

Public tips, memberships, shop orders, and commissions all use this one link. Private payments are left out. Shop orders and commissions show as purchases and don't add to donation totals. Ko-fi doesn't report cancelled memberships.

Test with SSN's preview. Ko-fi test payments look real and can trigger alerts, totals, and actions. Don't use them while paid rewards are on.

Patreon chat and new pledges

Use Standard capture for chat and connect a webhook for new-pledge alerts. You can use either on its own or both together.

Capture chat

In SSApp, add a Patreon source in Standard mode, sign in with an account that can access the chat, and open the event or chat page. With the browser extension, enable Patreon capture and open that page in your browser. Keep the chat open and SSN on; new messages appear in your dock, while existing history is skipped.

Connect new-pledge alerts

  1. Avatud Monetization → Fourthwall, Ko-fi, Buy Me a Coffee & Patreon alerts, select Patreon, and click Copy webhook URL. In SSApp, your Patreon source's Set up Patreon alerts menu item opens the same panel.
  2. Sign in to the creator account whose pledges you want to receive. Open Patreon webhook settings, create a webhook using the copied URL, and enable New pledge (members:pledge:create).
  3. Copy that webhook's signing secret into SSN's signing-secret field. Turn on Enable Patreon alerts and click Save setup. Keep SSN running and switched on to display incoming pledges; the Patreon chat page does not need to stay open for these alerts.
  4. Open your dock or multi-alerts overlay using the same SSN session and password. Keep subscriber alerts enabled and allow the Patreon source. For automation, use Event Flow's New Subscriber trigger with Patreon selected.

Alerts show new pledges from the time you enable them. The tier and pledge amount appear when Patreon supplies them; hidden names remain Anonymous. Pledges do not increase donation totals. Free memberships, gifts, trials, declined/former memberships, upgrades, cancellations and recurring charges do not generate new-pledge alerts.

Patreon alerts use their own receiver; you do not need to enable remote API control of the extension. To show them in OBS, use your multi-alerts link or the Monetization activity-alert view. Patreon pledge alerts do not require an enabled product showcase.

Closing SSN or turning SSN off keeps pending pledges for up to seven days. Disabling Patreon alerts and saving clears the backlog and stops queuing new pledges. Disconnect removes the receiver; also remove its old webhook in Patreon before creating another connection.

If Patreon reports 401 / Invalid signature, copy the complete signing secret from that same webhook, paste it into SSN, and save again. If SSN remains waiting for an event, check the webhook URL and selected trigger in Patreon. Keep the webhook URL and signing secret private.

Import a Fourthwall product

  1. In Fourthwall, go to Settings → For Developers and create a Storefront token. Don't use an admin API key.
  2. In SSN, open Products & support links → Set up products and links → Import a Fourthwall product.
  3. Paste the product's public link and the token. Click Load product details.
  4. Check the name, image, price, and link. The link must be from the same shop as the token.
  5. Pick a purpose: Shop, Gift, Support, or Join.
  6. Klõpsake Add product or link, turn on Products & support links, and click Save setup.
What the import does
  • It loads one public, available product at a time.
  • The token decides which shop is searched. It's used once, then cleared. It's never saved or sent to overlays.
  • If variants or bundles have different prices, the price is left blank.
  • It's a snapshot. Prices, stock, and images don't update, so import again or edit when they change.
  • You can save up to 20 products. Adding the same one again makes a second copy.

Show products and QR codes on stream

You can also add any public link by hand (Shopify, Tiltify, Patreon, and so on). That doesn't connect payment alerts.

  1. Under OBS overlay for, choose Products & support links.
  2. Avatud Overlay link options and pick an Overlay view: Product showcase only, Support card only, Activity alerts only, or Showcase and alerts.
  3. Klõpsake Copy OBS link and add it to OBS as a Brauseri allikas. Start at 800 × 600. Use one source per view.
  4. sisse Display options, pin the first product or rotate them, and turn on Show QR code.
  5. Scan the QR code with your phone while looking at your final OBS layout.
QR code won't scan? Don't shrink or crop the overlay too much. To share a link in chat, click Copy public link.
Alerts, multi-alerts, and Event Flow
  • The showcase shows the product image. The smaller support card doesn't.
  • Activity alerts work on their own, and never show a QR code from an unrelated product.
  • Multi-alerts and the activity feed work with the same session, with no product list needed. The Monetization activity view needs the product list turned on for other providers; Patreon pledge alerts display independently.
  • In Event Flow, the Donation trigger still covers rows with hasDonation. Use Event Type for purchases or completed gifts. See the event mapping.
