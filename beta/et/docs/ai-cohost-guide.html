Voice co-host in 8 steps

This uses OpenAI Realtime, so you'll need an OpenAI API key. Other options are below.

  1. In the Social Stream popup, pick ChatGPT API, paste your OpenAI project API key, and click Test selected chat bot.
  2. Avage cohost.html link from the popup. Keep that link private.
  3. Select OpenAI Realtime.
  4. Pick the microphone you talk into. Keep Audio Response selected.
  5. Vajutage Start Co-host.
  6. Leave Live Chat on Context only. Ask “What is chat saying?” any time.
  7. In OBS, capture the audio from the co-host page or app. The AI's voice only plays there.
  8. Lisa cohost-overlay.html?session=YOUR_SESSION_ID to OBS as a Browser Source for the avatar and speech bubble.
Want its own audio track in OBS? Pick a virtual cable under Co-host output, if your setup supports it. Keep the speech bubble visible too, so viewers who can't hear can still follow along.
Let it see your screen or camera? Optional. Video starts on No Video. If you pick Screen Share or a camera, OpenAI gets one picture each time you speak or type to it, not a live video. This can add cost and delay.
Privacy: your microphone, any screen or camera you pick, and the chat messages you share go to OpenAI. Viewers can't use chat to make the co-host run tools. The co-host link expires after 12 hours, only works for your session, and is removed from the address bar once the page loads.
More about OpenAI Realtime
  • It's billed to your OpenAI API account. It's separate from chatgpt.com and doesn't join a ChatGPT website or app conversation.
  • Your standard key stays in Social Stream. The co-host page only gets a short-lived pass.
  • You don't need to turn on the Private Chat Bot option for this.
  • Replies are capped at 512 output tokens. Diagnostics shows total token use and how fast replies start.
  • If you talk over it, it stops and drops the unplayed audio.
  • It keeps up to 20 recent chat messages for up to 90 seconds, including donations, memberships, moderator, event, and channel info. Then it forgets them.
  • It reconnects by itself if the connection drops, and starts a fresh session before OpenAI's 60-minute limit. Your instructions and speed settings carry over, but it forgets what was said aloud.

How it uses your chat

Open the co-host page with the same session as Social Stream and it can see your live chat. Choose how under Live Chat.

Let it control your stream

The co-host can play Spotify, switch OBS scenes, or feature a chat message. All are off by default. OpenAI Realtime supports all three. SSN Configured LLM supports Spotify only. Other providers don't support these yet.

  1. In the Social Stream popup, turn on only the tools you want.
  2. For OBS, type the exact scene names it may switch to, separated by commas. Keep actions.html connected to OBS, or use an OBS Browser Source with Full Permissions.
  3. On cohost.html, open Co-host Stream Controls and turn on the same tools.
  4. Ask it out loud, like “switch to BRB”, “feature that last message”, or “clear the featured chat”.
Only you can trigger tools. Viewers can't. It runs one tool per request, and can only pick scenes on your list. Featuring a message needs the Dock open. A “done” reply means the request was sent, not that OBS or the overlay finished it.

How the pages talk (for developers)

Message format and design notes

The Dock and overlay use the normal Social Stream session bridge. Messages are sent as overlayNinja payloads and targeted by label.

Read on Co-host: the Dock sends the chosen message straight to cohost-overlay.html.

Answer / Light Roast: the Dock asks the private chat bot in the background, shows the draft in the Dock, and only sends it to the overlay after you click Speak.

{
  "action": "cohostOverlay",
  "target": "cohost-overlay",
  "meta": {
    "command": "say",
    "text": "The line the avatar should say",
    "speak": true,
    "emotion": "happy"
  }
}
  • For Dock text workflows, the overlay is the picture and optional TTS voice. For the OpenAI voice, capture cohost.html audio separately. The overlay doesn't replay that WebRTC audio.
  • Extra command details go inside meta, so payloads stay predictable for overlays and automations.
