Повний посібник з елементів керування, жестів і значків Stream Deck

Створіть робочий процес, який можна викликати

Потоки подій→Іменований робочий процес→Клавіша Stream Deck
  1. Іменований тригерStream Deck / API
  2. Умови та діїВаш збережений Event Flow
  3. НапрямокFlow Actions, OBS або інша інтеграція
  1. Відкрити Потоки подій із SSN. Створіть окремий потік або виберіть шаблон Кнопка Stream Deck / API .
  2. Додайте Запуск зі Stream Deck / API у групі тригерів Stream Deck і API .
  3. Дайте йому назву intermission. Назви мають точно збігатися й чутливі до регістру; використовуйте коротку зрозумілу назву.
  4. Підключіть її вихід до Показати текст (Show Text). Задайте текст Back in five minutes і виберіть потрібну тривалість та шар.
  5. Збережіть потік, а потім увімкніть його. Незбережений потік існує лише в редакторі; вимкнений потік не можна викликати. Початковий шаблон навмисно вимкнений, доки ви не завершите налаштування.
  6. Відкрийте свій Оверлей Flow Actions через згенероване посилання SSN. Для аудиторії додайте цей URL як браузерне джерело OBS. Сам редактор не є оверлеєм.

Потоки без цього іменованого тригера не можна викликати через API робочих процесів. Виклик робочого процесу не додає вигаданий чат у док. Наявні події OBS і звичайний чат продовжують використовувати свої тригери.

Потік може поєднувати іменований тригер із фільтрами через логічні вузли. Тримайте непов’язані автоматизації в окремих потоках: усі гілки тригерів/логіки вибраного потоку обчислюються з API-подією. Повторні натискання починають окремі запуски; розмістіть Обмежувач частоти (Rate Limiter) вузол стану після тригера, якщо потрібен інтервал очікування.

Підключіть клавішу Stream Deck

  1. Налаштуйте в плагіні дію Налаштування зі своєю сесією SSN і необов’язковим паролем. Використовуйте Перевірити підключення (Test Connection).
  2. Перетягніть Готова команда (Preset Command) на клавішу.
  3. Виберіть Event Flow workflows → Run workflow.
  4. Виберіть Оновити робочі процеси, а потім виберіть збережений потік і тригер. Клавіша зберігає і ID потоку, і назву тригера.
  5. Натисніть один раз і спостерігайте за оверлеєм Flow Actions. Галочка на клавіші означає, що SSN прийняв запуск.

Засіб вибору процесів зберігає відсутні вибори. Після перейменування, вимкнення, видалення або імпорту потоку оновіть і виберіть його знову. Потік, імпортований як новий, має інший ID. Натомість використовуйте поле Value для звернення за назвою до кількох потоків.

Власна команда: установіть Action на triggerWorkflow, залиште Target порожнім, введіть {"trigger":"intermission"} як Value та ввімкніть Чекати на відповідь. Готова команда пропонує покроковий вибір і фільтрування за можливостями.

Мультидії: кожен запит робочого процесу швидко підтверджує прийняття. Наступний крок Stream Deck може початися до завершення відкладених дій потоку. Розміщуйте послідовність і затримки всередині Event Flow, коли порядок важливий.

Передавайте власні значення

У полі Value клавіші або API-запиті:

{
  "trigger": "intermission",
  "flowId": "YOUR_SAVED_FLOW_ID",
  "data": { "name": "Back in five minutes", "minutes": 5 }
}

Задайте для Show Text {meta.workflow.data.name}. Compare Property може читати meta.workflow.data.minutes. Data — необов’язковий JSON-об’єкт; він залишається в meta.workflow.data і не може замінити ідентичність події або надати привілеї чату.

Пропустіть flowId , щоб викликати кожен увімкнений потік із точно такою назвою тригера. Кілька відповідних вузлів тригера в одному потоці все одно обчислюють цей потік лише один раз. Щоб запустити один потік, збережіть його ID із засобу вибору або відповіді виявлення.

Подія всередині вибраного потоку має type: "api", event: "workflow_trigger", chatname: "Stream Deck / API", порожній chatmessage і наведені вище дані. Звичайний чат, який копіює ці поля, не може активувати іменований API-тригер.

Приклади API

Залишайте SSN увімкненим і запущеним. Це виклики дистанційного керування Social Stream; вони не використовують окремий локальний API ШІ/MCP SSApp. Тримайте справжній ID сесії в таємниці.

Виявіть доступні тригери

{"action":"getWorkflowTriggers","get":"list-1","apiid":"YOUR_SESSION"}

Зворотний виклик містить result.payload.triggers:

{"triggers":[{"flowId":"flow-123","flowName":"Intermission","trigger":"intermission"}]}

Запустіть іменований робочий процес

{
  "action": "triggerWorkflow",
  "value": {"trigger":"intermission","flowId":"flow-123","data":{"name":"Back shortly"}},
  "get": "run-1",
  "apiid": "YOUR_SESSION"
}

Використовуйте унікальний get рядок для кожного запиту. Успішний зворотний виклик має result.ok: true, result.status: "accepted", і result.payload.matchedFlows. Прийняття означає, що ввімкнений потік знайдено й заплановано. Це не означає завершення кожної відкладеної дії, вебхука, виклику OBS або відтворення медіа.

WebSocket

Увімкнути віддалене керування розширенням через API у SSN. Підключіться до wss://io.socialstream.ninja. Приєднуйтеся з {"join":"YOUR_SESSION","out":1,"in":2}, а потім надішліть запит вище. Канал 1 передає керування; канал 2 — зворотні виклики. Для робочих процесів канал чату вмикати не потрібно.

HTTP

Увімкніть те саме налаштування дистанційного керування API. Замініть заповнювач сесії перед використанням:

POST https://io.socialstream.ninja/YOUR_SESSION
Content-Type: application/json

{"action":"triggerWorkflow","value":{"trigger":"intermission","data":{"name":"Back shortly"}}}

Для простого іменованого тригера також можна використовувати GET https://io.socialstream.ninja/YOUR_SESSION/triggerWorkflow/null/intermission. Четвертий сегмент шляху може містити JSON із URL-кодуванням для структурованих значень. Закодуйте все значення JSON за допомогою encodeURIComponent(JSON.stringify(value)). Власні канали надсилання використовують ?channel=N.

P2P

Стандартний режим P2P плагіна надсилає ті самі дані через наявний транспорт каналу даних VDO.Ninja SSN. Перемикач розміщеного WebSocket API для P2P не потрібен. Наявні клієнти P2P мають надсилати цей запит через установлене підключення керування SSN; відкривати локальний API ШІ не потрібно.

Помилки та сумісність

  • WORKFLOW_NOT_FOUND: жоден збережений увімкнений потік не відповідає тригеру/ID потоку.
  • INVALID_VALUE: відсутній/неприпустимий тригер, некоректний JSON, неприпустимий ID потоку або data не є об’єктом.
  • CONTROL_UNAVAILABLE: SSN або дистанційне керування ведучого вимкнено.
  • TARGET_UNAVAILABLE: Event Flow ще завантажується.
  • Старіші ресурси Social Stream можуть не оголошувати ці дії. Перевірте getCapabilities → ssn.actions.triggerWorkflow і getWorkflowTriggers. Мають бути встановлені і новий тригер, і оновлений плагін; сам номер версії SSApp не визначає віддалено завантажені ресурси Social Stream.

Не повторюйте автоматично виклик зі зміною стану після втрати підтвердження: робочий процес уже міг початися. Спочатку перевірте його результат. Цей API не надає черги станів виконання.

Жести таймера й чату

Таймер: повертайте на один крок для ±10 секунд за замовчуванням; утримуйте регулятор натиснутим під час обертання для ±1 хвилини (6× налаштованого кроку). Натисніть/відпустіть без обертання для запуску/паузи. Торкніться екрана таймера для оновлення; утримуйте екран , щоб скинути. Саме утримання фізичного регулятора не скидає.

Перегляд чату: повертайте ліворуч для старішого чату, праворуч — для новішого; натисніть регулятор, щоб закріпити переглянуте повідомлення. Торкніться екрана, щоб вибрати наступне закріплене повідомлення; утримуйте екран, щоб відкріпити переглянуте. Тримайте стандартний док відкритим. У режимі WebSocket увімкніть пересилання чату на каналі 4.

Відкрити Help and diagnostics → Controls, icons and workflow guide у плагіні для повного автономного посібника, усіх п’яти типів дій, кожної готової команди/значка, поведінки скидання, стандартних значень і усунення несправностей.

Довідник палітри Event Flow

Палітра містить 45 тригерів, 67 дій, п’ять логічних вузлів і чотири вузли стану. Кожен елемент має текстовий підпис біля символу. Виберіть вузол, щоб побачити налаштування й передумови інтеграції; значок палітри не підтверджує підключення цілі.

Тригери визначають, коли починається потік. За потреби з’єднуйте умови через AND/OR. Дії виконуються в порядку з’єднання. Вузли стану запам’ятовують значення між подіями. Для інтервалу очікування кнопки виберіть Обмежувач частоти (Rate Limiter) (THROTTLE), а не дію Delay: Delay відкладає кожен запуск і не пригнічує повторних натискань.

Розберіться зі збоєм

  1. Спочатку використайте простий потік Show Text і перевірте його результат.
  2. Збережіть і ввімкніть; оновіть список робочих процесів Stream Deck. Перевірте і назву тригера, і ID потоку.
  3. Переконайтеся, що SSN увімкнений, підключення має стан Online, а цільовий оверлей підключений до тієї самої сесії.
  4. Перевірте зворотний виклик API або діагностику плагіна на помилки пошуку/валідації. Для збоїв після прийняття перевірте ціль і журнали виконання Event Flow.
  5. Додавайте інші інтеграції по одній. Перевірте повторні натискання, вимкнений потік і повторне підключення перед використанням наживо.
