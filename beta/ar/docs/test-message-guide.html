إنشاء رسائل اختبار

أرسل رسائل وأحداثًا وهمية مضبوطة إلى جلسة Social Stream.

ما تفعله هذه الأداةبدء سريع لـSSApp أو الإضافةمثال: رسالة وهمية واحدة بقيمة 1,000 KICKsاستخدام الإعدادات المسبقة وJSON المخصصاختيار وضع الإيصال المناسبحلول شائعة

ما تفعله هذه الأداة

إن صفحة إنشاء رسالة اختبار ترسل حمولات Social Stream اصطناعية إلى لوحة الإرساء أو التراكبات أو التنبيهات أو إعداد Event Flow. استخدمها للاختبار دون انتظار رسالة دردشة أو تبرع أو عضوية أو غارة أو مكافأة أو حدث آخر حقيقي.

استخدم جلسة اختبار متى أمكن. تتصرف الرسالة المُرسَلة كحركة واردة إلى الجلسة، وقد تشغّل تنبيهات أو أصواتًا أو خطافات ويب أو إجراءات OBS أو أتمتة أخرى.

بدء سريع لـSSApp أو الإضافة

  1. افتح Social Stream Ninja وتأكد من أن الخدمة نشطة.
  2. ضمن الإعدادات والأدوات العامة → آليات العمل (Mechanics)، فعّل التحكم في الإضافة عن بُعد عبر API. يستخدم SSApp اسم الإعداد نفسه.
  3. انسخ معرّف جلستك من Social Stream أو من قيمة session= في رابط لوحة الإرساء أو التراكب.
  4. افتح إنشاء رسالة اختبار وأدخل معرّف الجلسة ذلك.
  5. اترك الإرسال عبر (Send Via) مضبوطاً على إدخال عبر API الإضافة (Extension API ingest) للاختبار العادي.
  6. اختر إعدادًا مسبقًا وعدّل حقوله، ثم اختر تحميل إعداد مسبق (Load Preset).
  7. راجع Payload JSON، ثم اختر إرسال (Submit).
  8. تأكد من ظهور العنصر في لوحة الإرساء أو التراكب المستهدف ومن تنفيذ الأتمتة المتوقعة.

يمكنك تضمين الجلسة في الرابط: createtestmessage.html?session=YOUR_SESSION_ID.

مثال: رسالة وهمية واحدة بقيمة 1,000 KICKs

ينشئ هذا رسالة دعم واحدة بأسلوب Kick بقيمة 1,000 KICKs. ولا ينشئ 1,000 رسالة منفصلة.

  1. اختر الإعداد المسبق رسالة دردشة (Chat Message) .
  2. اضبط اكتب إلى Kick.
  3. أدخل اسمًا ورسالة للاختبار.
  4. اضبط تتضمن تبرعًا (Has Donation) إلى 1000 KICKs.
  5. اختر تحديث JSON من الحقول (Update JSON from Fields)، وتحقق من JSON، وأرسله.

الحد الأدنى للحمولة هو:

{
  "type": "kick",
  "chatname": "Test Supporter",
  "chatmessage": "Thanks for the stream!",
  "hasDonation": "1000 KICKs"
}

استخدم رسالة دردشة (Chat Message) لهذا المثال. يتضمن الإعداد المسبق تبرع / Cheer ‏(Donation / Cheer) حقول cheer الخاصة بـTwitch.

استخدام الإعدادات المسبقة وJSON المخصص

توفر الإعدادات المسبقة حمولة بداية للحالات الشائعة مثل التبرعات والمشتركين والاشتراكات المهداة والغارات والمكافآت وتحديثات المشاهدين والمشاركين لأول مرة وأحداث القطار.

  • تحميل إعداد مسبق (Load Preset) يستبدل JSON بالإعداد المسبق المحدد وقيم الحقول الحالية.
  • تحديث JSON من الحقول (Update JSON from Fields) يبني رسالة أساسية من الحقول الظاهرة.
  • يمكنك تعديل JSON الحمولة (Payload JSON) مباشرة عند اختبار حقل معين أو بنية حدث محددة.
  • hasDonation يحمل مبلغ الدعم المعروض، مثل 1000 KICKs أو $10.00.
  • أدرج فقط event عندما تختبر حدثًا حقيقيًا مسمّى. يمكن لصف دردشة عادي يحمل تبرعًا استخدام hasDonation وحده.

لتعريفات الحقول وأمثلة المنصات الحقيقية، راجع مرجع الأحداث.

إدخال عبر API الإضافة (Extension API ingest)اختبار لوحات الإرساء أو التراكبات أو التنبيهات أو Event Flow أو SSApp المعتادة.معرّف الجلسة نفسه و التحكم في الإضافة عن بُعد عبر API مفعّلًا.
مباشرة إلى القناة 1فُتحت لوحة الإرساء المستهدفة باستخدام &server.يجب أن يستمع الهدف على قناة الخادم المطابقة.
مباشرة إلى القناة 4اختبار هدف يستخدم &server2، بما فيها صفحات الأحداث المتوافقة.يجب أن يستمع الهدف على قناة الخادم المطابقة.

إذا لم تكن متأكدًا، فاستخدم إدخال عبر API الإضافة (Extension API ingest).

حلول شائعة

  • لا يظهر شيء: تأكد من أن الصفحة المستهدفة مفتوحة وتستخدم معرّف الجلسة نفسه.
  • يفشل الإدخال عبر API الإضافة: فعّل التحكم في الإضافة عن بُعد عبر API، ثم أعد تحميل لوحة الإرساء أو التراكب وحاول مجددًا.
  • يقول الوضع المباشر إن الإرسال نجح لكن لا يظهر شيء: استخدم Extension API ingest ما لم يتضمن الرابط المستهدف معامل &server أو &server2 .
  • يُشغَّل حدث خاطئ: افحص Payload JSON بحثًا عن حقول متبقية من إعداد مسبق آخر.
  • اختبار Kick يتصرف مثل Twitch: استخدم الإعداد المسبق Chat Message واضبط type و hasDonation كما هو موضح أعلاه.
  • الأتمتة تُنفَّذ أكثر من مرة: تحقق مما إذا كانت عدة لوحات إرساء أو صفحات إجراءات أو نسخ Event Flow مفتوحة على الجلسة نفسها.
