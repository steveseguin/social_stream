Przewodnik po doku sterowania OBS

Miej częste elementy sterowania Social Stream wewnątrz OBS, w tym Credits Start, Preview, Test i Reset.

Szybka konfiguracja

  1. W Social Stream Ninja otwórz Ustawienia globalne i narzędzia → Mechanika.
  2. Włącz zdalne sterowanie rozszerzeniem przez API. Pozostaw Social Stream Ninja aktywne podczas transmisji.
  3. Skopiuj identyfikator sesji pokazany w Social Stream Ninja.
  4. W OBS otwórz Doki → Niestandardowe doki przeglądarki.
  5. Nazwij dok Sterowanie Social Stream i użyj tego URL:
https://socialstream.ninja/obs-control-dock.html?session=YOUR_SESSION_ID
  1. Wybierz Zastosuj, zamknij okno ustawień i umieść nowy dok w wybranym miejscu w OBS.
  2. Sprawdź, czy dok pokazuje Połączono. Jeśli URL nie zawierał sesji, wpisz ją w doku i wybierz Zapisz i połącz.

&server nie jest wymagany w adresach URL doku sterowania ani napisów końcowych. Dok sterowania już otwiera własne połączenie sterowania WebSocket. Należące do OBS Ustawienia serwera WebSocket są niezwiązane i mogą pozostać wyłączone.

Jeśli celowo używasz bezpośredniego transportu API dla dock.html, użyj wygenerowanego łącza doku po włączeniu jego ustawienia serwera lub dodaj &server do URL tego doku. To opcjonalne i nie zmienia działania poleceń Credits.

Użycie z napisami końcowymi transmisji

  1. Przed transmisją ustaw Credits Tryb uruchamiania na Zbieranie w tle. Pozwala to aplikacji zbierać rozmówców, członków i darczyńców, gdy źródło przeglądarkowe Credits jest zamknięte.
  2. Dodaj wygenerowany URL Credits do sceny końcowej OBS z tym samym identyfikatorem sesji.
  3. Pod koniec transmisji najpierw przełącz na scenę końcową, aby źródło przeglądarkowe Credits było załadowane i połączone.
  4. Wybierz Uruchom napisy w doku sterowania OBS.
Załaduj przed Start: zbieranie w tle może działać przy zamkniętej stronie Credits, ale Start, Preview i Test potrzebują połączonego źródła przeglądarkowego Credits, aby cokolwiek wyświetlić.

Zobacz Poradnik napisów końcowych aby poznać tryby zbierania, filtry i rozwiązywanie problemów z brakującymi nazwami.

Produkty i linki wsparcia

W Social Stream otwórz Monetization, zapisz i włącz produkty, a następnie wybierz Otwórz dok sterowania OBS. Skopiuj ten prywatny URL sterowania do Custom Browser Docks w OBS. Dla doku tylko z produktami użyj obs-control-dock.html?session=YOUR_SESSION_ID&commerce.

Pozostaw Social Stream włączone i włącz zdalne sterowanie rozszerzeniem przez API zgodnie z opisem powyżej. Dodaj osobny URL nakładki monetyzacji jako źródło przeglądarkowe OBS dla widzów. Dok sterowania jest dla Ciebie; nigdy nie udostępniaj jego URL sesji widzom.

  • Pokaż: wybierz zapisany produkt i przypnij go. Następny: przejdź dalej od bieżącego produktu.
  • Ukryj produkty: ukryj karty promocyjne; alerty aktywności działają dalej. Wznów harmonogram: wróć do zapisanego ustawienia pierwszego produktu lub rotacji.
  • Czas trwania: Show, Next i Hide wracają do zapisanego harmonogramu po tylu sekundach. Użyj 0, aby zachować nadpisanie do kolejnej zmiany.
  • Stan: odświeża się co pięć sekund, gdy ta sekcja jest otwarta. Zgłasza wybór Social Stream, a nie widoczność sceny OBS. Utracone lub niepotwierdzone połączenia wyłączają przyciski produktów do czasu ponownej dostępności stanu.

Dok, okno, Stream Deck i Event Flow współdzielą to samo sterowanie. Edytuj i zapisuj katalog w Social Stream. Zobacz Sterowanie produktami aby poznać konfigurację i automatyzację.

Inne elementy sterowania i wymagane strony

  • Wyróżniony czat: pozostaw zwykły Streaming Chat Dock i nakładkę wyróżnionych wiadomości połączone w tej samej sesji.
  • Zegar: pozostaw stronę Timer połączoną w tej samej sesji, jeśli ma wyświetlać zegar.
  • Lista oczekujących i losowanie: najpierw skonfiguruj listę oczekujących w Social Stream; Reset czyści bieżące wpisy.

Dok automatycznie łączy się ponownie po utracie połączenia API. Zielony Połączono status potwierdza wyłącznie połączenie sterowania; strona docelowa nadal musi być otwarta, gdy polecenie coś wyświetla.

Bezpośrednie przykłady API

Te same przyciski można obsługiwać skryptami przez żądania HTTP GET:

https://io.socialstream.ninja/SESSION_ID/creditsStart
https://io.socialstream.ninja/SESSION_ID/creditsPreview
https://io.socialstream.ninja/SESSION_ID/creditsTest
https://io.socialstream.ninja/SESSION_ID/creditsReset

Zastąp SESSION_ID aktywną sesją Social Stream. Zobacz Polecenia i API lub pełne środowisko testowe API aby zobaczyć więcej akcji.

Rozwiązywanie problemów

  • Potrzebna sesja: użyj dokładnego identyfikatora sesji z Social Stream bez słowa session=.
  • Rozłączono: włącz zdalne sterowanie API, sprawdź aktywność Social Stream i ponownie otwórz dok po zmianie URL.
  • Credits zgłasza, że żadne źródło nie przyjęło polecenia: pokaż scenę końcową, poczekaj na załadowanie jej źródła przeglądarkowego i spróbuj ponownie.
  • Test działa, ale Start jest pusty: Test używa wbudowanych nazw. Wybierz zbieranie Background przed transmisją i sprawdź, czy zwykłe źródła czatu przechwytują.
  • Przycisk Featured Chat nie ma widocznego efektu: sprawdź, czy Streaming Chat Dock i nakładka wyróżnionych wiadomości używają tej samej sesji i są załadowane.
