1. Włącz lokalny serwer

Ta opcja menu File uruchamia w aplikacji komputerowej przekaźnik WebSocket uwzględniający pokoje i kanały. Obsługiwane strony Social Stream mogą wymieniać przez niego czat i polecenia na tym samym komputerze. To alternatywny punkt końcowy routingu serwera właściwego dla strony.

Nie hostuje witryny Social Stream, nie przechwytuje samodzielnie platformy i nie udostępnia API automatyzacji HTTP. Zacznij od Przewodnik włączania lokalnego serwera.

2. Lokalne API sterowania i MCP

To opcjonalne API loopback pozwala programom na komputerze SSApp zarządzać obsługiwanymi źródłami i ustawieniami, odczytywać status i diagnostykę, sprawdzać okna aplikacji lub źródeł oraz śledzić przechwycone zdarzenia. Dołączony adapter MCP przedstawia te operacje jako narzędzia zgodnym klientom AI.

Włącz w Plik > Lokalne AI / Automatyzacja (File > Local AI / Automation). Jest oddzielne od Włącz lokalny serwer. Zobacz Przewodnik po lokalnym API sterowania i MCP.

3. Serwer domowy lub VPS bez interfejsu

Tryb bez interfejsu uruchamia pełną aplikację komputerową Electron z ukrytymi oknami źródeł. Na Linuksie nadal potrzebuje mechanizmu ekranu, takiego jak Xvfb. To przydatne, gdy dedykowany komputer ma nadal przechwytywać czat bez podłączonego monitora.

Tryb bez interfejsu nie tworzy publicznego API sterowania. Zdalne sterowanie używa zwykłego transportu WebRTC lub WebSocket Social Stream. Zobacz przewodnik hostingu bez interfejsu.

4. Lokalny serwer multimediów

Aplikacja komputerowa uruchamia go automatycznie, gdy dostępne są lokalne multimedia Event Flow. Udostępnia tylko pliki zatwierdzone przez SSApp i wybrane zasoby uruchomieniowe przez losową ścieżkę tokenu właściwą dla profilu.

Nie jest ogólnym serwerem WWW ani plików. Zobacz Pliki multimedialne dla Event Flow aby wybrać między plikami lokalnymi, przesyłaniem i hostingiem chmurowym.

Zapasowy serwer to inna funkcja

Ustawienia takie jak Wysyłaj wiadomości czatu do serwera API i Dok wysyła polecenia do rozszerzenia przez serwer wybierają routing czatu i poleceń. Generowane przez nie flagi URL obejmują server, server2 i server3.

Te ustawienia zwykle używają hostowanej usługi WebSocket Social Stream. Gdy obsługiwana strona ma również localserver, używa zamiast tego lokalnego przekaźnika aplikacji komputerowej. Zobacz Sesje, hasła, przekaźnik i tryby serwera dla sterowania routingiem.

Używaj świeżo wygenerowanych łączy. Flagi routingu są właściwe dla stron. Nie kopiuj flagi serwera między stronami, zakładając, że oznacza to samo.

Inne tymczasowe lokalne porty

Niektóre przepływy logowania i łączenia kont na chwilę otwierają port callback loopback i zamykają go po zakończeniu. Te tymczasowe nasłuchy nie są ogólnymi serwerami SSN ani API automatyzacji.
