Konfiguracja i używanie bota czatu AI

Połącz dostawcę AI, włącz głównego bota, bezpiecznie przetestuj i rozwiąż problemy z brakiem odpowiedzi.

Poznaj trzy osobne części

Działający dostawca AI to dopiero pierwsza część bota czatu na żywo. Dostawcę, głównego bota i miejsce odpowiedzi trzeba skonfigurować osobno.

CzęśćCo robiCzego to nie potwierdza
Dostawca AIGeneruje tekst za pomocą Ollama, hostowanego API lub innej obsługiwanej usługi.Że czat na żywo jest przechwytywany lub że można publikować odpowiedzi.
Główny bot czatuDecyduje, które przechwycone wiadomości na żywo powinny otrzymać odpowiedź AI.Że platforma lub konto źródłowe pozwala na wysyłanie odpowiedzi.
Miejsce odpowiedziPublikuje wygenerowane odpowiedzi w kanale wyjściowym bota i może też wysyłać je przez przechwytywane źródło czatu.Że bot.html jest otwarte lub że utworzono osobne konto bota na platformie.

Ważne: zielony Połączono wynik potwierdza tylko, że wybrany dostawca i model odpowiedzieli na jedną instrukcję testową.

1. Skonfiguruj dostawcę AI

  1. Otwórz ustawienia Social Stream i rozwiń Boty czatu i usługi AI.
  2. Otwórz Skonfiguruj dostawcę usługi LLM.
  3. Wybierz dostawcę odpowiadającego faktycznie uruchomionej usłudze.
  4. Uzupełnij adres usługi, nazwę modelu, klucz API lub inne pola danego dostawcy.
  5. Wybierz Przetestuj wybranego bota czatu i sprawdź, czy pod przyciskiem pojawia się prawdziwa odpowiedź tekstowa.
  • Ollama (natywne lokalne API): używaj wyłącznie dla Ollama. Typowy lokalny adres to http://localhost:11434.
  • Własne API: użyj tego dla serwerów zgodnych z OpenAI, takich jak llama.cpp, LM Studio, vLLM i podobnych usług.
  • Dostawca hostowany: wpisz klucz API i model wymagany przez dostawcę. Koszty, limity i nazwy modeli są kontrolowane poza Social Stream Ninja.
  • Lokalny model uruchamiany w przeglądarce: użyj odpowiedniej opcji Local Gemma lub Local Qwen i postępuj zgodnie z instrukcjami plików modelu.

Musisz najpierw zainstalować Ollama? Użyj oficjalnej strony pobierania Ollama. Pełną listę dostawców znajdziesz w Integracja AI w poleceniach i API.

Podtrzymywanie Ollama: 0 usuwa model z pamięci po żądaniu. Nie wyłącza bota, ale każda kolejna odpowiedź może wymagać ponownego zimnego startu.

Konfiguracja OpenAI / ChatGPT API

Do żądań modeli używaj standardowego klucza API OpenAI. Klucz OpenAI Admin API służy do administracji organizacją, nie do zwykłych wywołań modeli. Klucz musi należeć do projektu, który ma być rozliczany, a jego rzeczywiste uprawnienia muszą dopuszczać żądania modeli.

  1. Utwórz lub sprawdź klucz na stronie kluczy API OpenAI Platform. Nigdy nie wklejaj klucza do wiadomości do pomocy ani raportu diagnostycznego.
  2. W Social Stream wybierz ChatGPT API, wklej cały klucz, wpisz model dostępny dla tego projektu i wybierz Przetestuj wybranego bota czatu.
  3. Jeśli test zgłasza Status: 401, Code: missing_scope i Missing scope: model.request, OpenAI odrzuciło dane uwierzytelniające, ponieważ ich rzeczywiste uprawnienia nie obejmują żądań modeli. model.request to uprawnienie wskazane przez serwer, a nie ustawienie do dodania do instrukcji lub nazwy modelu.
  4. Upewnij się, że to standardowy klucz API projektu, wybrano właściwy projekt, a klucz nie ma ograniczeń albo wyraźnie pozwala na żądania modeli. W razie wątpliwości utwórz nowy standardowy klucz we właściwym projekcie i zastąp zapisany klucz w Social Stream.
  5. Jeśli automatyczne tłumaczenie przeglądarki działa na OpenAI Platform, a ustawienia lub etykiety uprawnień zachowują się nietypowo, przed sprawdzeniem i zapisaniem ustawień klucza przełącz stronę na oryginalny angielski. Pomogło to w jednym zgłoszonym przypadku, ale nie jest udokumentowaną uniwersalną przyczyną błędów OpenAI 401.

Środki i uprawnienia to osobne rzeczy: doładowanie API nie przyznaje brakującego uprawnienia klucza. OpenAI opisuje nieprawidłowe dane i uprawnienia endpointu jako błędy 401, natomiast wyczerpany limit zwykle daje błąd 429. Zobacz Poradnik błędów API i dokumentację uwierzytelniania.

Jeśli błąd się powtarza, skopiuj stan, kod, brakujące uprawnienie i Request ID pokazane przez Social Stream, a następnie wyślij raport diagnostyczny z aplikacji niedługo po odtworzeniu problemu. Raport zapisuje bezpieczne metadane żądania, ale pomija klucze API i treść instrukcji. Jeśli dane uwierzytelniające i ustawienia projektu wyglądają poprawnie, przekaż Request ID i czas do pomocy OpenAI.

3. Wykonaj bezpieczny test całej ścieżki

  1. Włącz Social Stream i upewnij się, że źródło transmisji jest otwarte.
  2. Wyślij zwykłą wiadomość z drugiego konta widza bezpośrednio na czacie platformy źródłowej, np. YouTube lub Twitch, i sprawdź, czy pojawia się w doku Social Stream. W pierwszym teście nie używaj wiadomości wpisanej do doku ani sterowania czatem prowadzącego; odbicia wiadomości bota lub prowadzącego mogą być pomijane, aby zapobiegać pętlom odpowiedzi.
  3. Potwierdź, że test dostawcy pokazuje Połączono.
  4. Użyj powyższych ustawień pierwszego testu głównego bota, w tym trybu tylko nakładki.
  5. Otwórz bot.html link pokazany w Strona nakładki i TTS bota czatu. Użyj wygenerowanego linku, aby zachować tę samą sesję.
  6. Z konta widza wyślij: NinjaBot, reply with exactly: Hello.
  7. Wyślij test raz i poczekaj na odpowiedź. Lokalny model może się jeszcze ładować, a kolejne wiadomości mogą być pomijane podczas generowania jednej odpowiedzi.

Dlaczego używać drugiego konta? Lepiej odzwierciedla to prawdziwego widza i zapobiega myleniu konta odpowiedzi wychodzących z kontem wysyłającym test.

Po udanym teście nakładki przełącz Nie odfiltrowuj żadnych odpowiedzi bota ponownie wyłącz, wybierz wyzwalacz i odstęp oraz zdecyduj, czy włączyć wysyłanie na platformę.

4. Dowiedz się, kiedy milczenie jest normalne

Główny bot jest domyślnie wybiórczy. Pusta lista wyzwalaczy oznacza, że może rozważać każdą kwalifikującą się wiadomość; nie oznacza obowiązku odpowiedzi na każdą.

  • Krótkie powitanie, takie jak hello może zostać pominięte, jeśli model nie uzna odpowiedzi za wartościową.
  • Bezpośrednie zwrócenie się do własnej nazwy bota wyraźniej pokazuje intencję.
  • Skonfigurowany wyzwalacz musi pasować do przychodzącej wiadomości.
  • Tryb tylko dla moderatorów pomija wiadomości nieoznaczone jako wiadomości moderatora.
  • Gdy wysyłanie na platformę jest włączone, domyślny odstęp wynosi pięć sekund na źródło. Domyślny limit równoległości to jedna odpowiedź w każdym trybie.
  • Wiadomości rozpoznane jako odpowiedzi bota, odbicia, puste lub zbyt podobne do poprzedniej odpowiedzi mogą zostać pominięte.

5. Wybierz miejsce odpowiedzi

TrybWynikWymagania
Tylko nakładka włączoneOdpowiedzi trafiają do kanału wyjściowego bota i nie są wysyłane z powrotem na czat platformy.Otwórz bot.html z tą samą sesją, aby je zobaczyć lub usłyszeć. TTS również wymaga tej strony.
Tylko nakładka wyłączoneOdpowiedzi nadal trafiają do kanału wyjściowego bota, a Social Stream próbuje też publikować przez oryginalne przechwytywane źródło.Tryb źródła musi obsługiwać wysyłanie, konto musi być zalogowane i mieć prawo publikowania, czat prowadzącego nie może być wyłączony, a źródło musi pozostać otwarte. bot.html pozostaje opcjonalne, chyba że chcesz korzystać z nakładki lub TTS.

Własna nazwa bota jest prefiksem wiadomości; nie tworzy nowego konta platformy. Jeśli nie skonfigurowano kierowania według ról kont w osobnej aplikacji, odpowiedzi są publikowane przez konto używane w przechwytywanym źródle.

Użytkownicy osobnej aplikacji, którzy chcą oddzielnej tożsamości Twitch, mogą skorzystać z poradnika konta bota Twitch.

6. Czyść i automatycznie ukrywaj odpowiedzi bota

Te ustawienia dotyczą strony Primary Chat Bot, bot.html. Nie czyszczą głównej nakładki wyróżnionych wiadomości.

OpcjaZnaczeniePrzykład
showtimeUżywa jednego stałego czasu wyświetlania w milisekundach.&showtime=10000 ukrywa po 10 sekundach.
autohideSzacuje czas wyświetlania na podstawie liczby słów odpowiedzi. autotime również jest akceptowane.&autohide
mintime / maxtimeUstawia minimalny i maksymalny czas wyświetlania zależny od długości. Domyślnie 4000 i 30 000 milisekund.&autohide&mintime=5000&maxtime=20000
hideafterttsPozostawia odpowiedź widoczną do zakończenia TTS, a następnie ją ukrywa. Jeśli odtwarzanie się nie rozpocznie, używa czasu zależnego od długości.&hideaftertts
hidedelayDodaje opóźnienie po zakończeniu TTS. Domyślnie 500 milisekund.&hideaftertts&hidedelay=1000
ttstimeoutLimit bezpieczeństwa, gdy TTS pozostaje aktywny bez końca. Domyślnie 120 000 milisekund.&hideaftertts&ttstimeout=60000

Jeśli włączono kilka trybów, hideaftertts ma pierwszeństwo, następnie autohide, a następnie showtime. Wygenerowane ustawienia nakładki bota udostępniają typowe opcje.

Wyczyść ręcznie

  • W ustawieniach Social Stream wybierz Wyczyść nakładkę bota teraz.
  • Po włączeniu Remote API Control otwórz https://io.socialstream.ninja/SESSION_ID/clearBotOverlay.
  • Przez WebSocket API wyślij {"action":"clearBotOverlay"}.

Ręczne czyszczenie usuwa widoczną odpowiedź i oczekującą kolejkę wyświetlania nakładki bota, ale nie zatrzymuje już odtwarzanej mowy.

Własne style: własny CSS użyty ze zwykłym wygenerowanym bot.html link zachowuje te funkcje. Skopiowany lub zmodyfikowany lokalny bot.html plik trzeba aktualizować, aby otrzymywać kolejne poprawki strony.
