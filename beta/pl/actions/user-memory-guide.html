Pamięć użytkowników (User Memory)

Zapamiętuj unikalnych uczestników, sprawdzaj ich przy późniejszych wiadomościach, losuj zwycięzcę i resetuj dokładnie zamierzoną listę — bez zmieniania roli platformy w trwały stan globalny.

Jedna nazwana pamięć, wiele narzędzi

Element Pamięć użytkowników (User Memory) węzeł stanu przechowuje jeden odizolowany zbiór osób. Każdy węzeł Remember, Forget, Check, Draw lub Clear wybiera ten węzeł stanu. Utwórz kolejny węzeł User Memory, gdy potrzebujesz oddzielnej listy — na przykład jednej dla osób, które polubiły transmisję, a drugiej dla zapisanych do losowania.
Ciągła turkusowa linia: to zdarzenie wykona się następne Przerywana fioletowa linia: ten węzeł używa tej pamięci

Przeciągnij mały fioletowy romb z boku na węzeł User Memory lub wybierz pamięć według nazwy we właściwościach węzła. Wewnętrznie operacja zapisuje identyfikator węzła stanu. Wybranie pamięci podświetla wszystkie powiązane operacje, a usuwanie ostrzega przed zerwaniem tych połączeń.

Skonfiguruj

  1. Przeciągnij State Nodes → User Memory na obszar roboczy.
  2. Nazwij ją zgodnie z przechowywaną listą, na przykład Uprawnieni przez Heart Me, Polubili transmisję lub Uczestnicy losowania nagród.
  3. Wybierz Ta sesja aplikacji lub Zapisuj między uruchomieniami (Save across restarts).
  4. Dodaj potrzebne sprawdzenia i akcje, a następnie połącz każdą z nazwaną pamięcią przez boczny romb lub listę rozwijaną.
  5. Połącz zwykłą ścieżkę zdarzeń turkusowymi przewodami i użyj Testuj przepływ (Test Flow) z dwiema różnymi nazwami użytkowników przed transmisją na żywo.

Dostępne operacje

WęzełCo robi
Zapamiętaj użytkownika (Remember User)Dodaje użytkownika bieżącego zdarzenia raz. Powtarzany udział zwiększa licznik udziału tej osoby bez dodawania zduplikowanych zgłoszeń do losowania.
Użytkownik jest zapamiętany (User Is Remembered)Wyzwalacz/sprawdzenie zwracające true, gdy bieżąca wiadomość należy do osoby z wybranej pamięci.
Zapomnij użytkownika (Forget User)Usuwa tylko użytkownika bieżącego zdarzenia.
Wybierz losowego użytkownika (Pick Random User)Wybiera jednego unikalnego zapamiętanego użytkownika. Opcjonalnie może usunąć zwycięzcę, aby nie wygrał ponownie.
Wyczyść wszystkich użytkowników (Clear All Users)Opróżnia tylko wybrany obiekt User Memory.
Zresetuj węzeł stanu (Reset State Node)Czyści również User Memory, gdy ta pamięć jest wybranym celem resetu.
Zasada tożsamości: użytkownicy są identyfikowani przez platformę i identyfikator użytkownika. Nazwa wyświetlana jest używana tylko awaryjnie. Anonimowe lub zbiorcze zdarzenie bez tożsamości użytkownika jest bezpiecznie ignorowane.

Praktyczne przepisy

TikTok Heart Me lub członek zespołu → ? TTS

Użyj zdarzenia prezentu, aby zapamiętać nadawcę; nie próbuj zmieniać pojedynczego wiersza prezentu w trwałą rolę „członka”.

Zdarzenie prezentu TikTok + dopasowanie „Heart Me” → AND → Zapamiętaj użytkownika ···→ [Uprawnieni przez Heart Me]
? polecenie + źródło TikTok + (Członek zespołu TikTok OR Użytkownik jest zapamiętany) → AND → Wypowiedz tekst ? polecenie + NOT źródło TikTok → AND ────────────────────────────────→ Wypowiedz tekst
  • Dla statusu zespołu/fana TikToka wybierz User Role → TikTok Team Member. Odczytuje bezpośrednio przychodzące dane odznak/poziomu TikToka; ustawienie wyświetlania „treat as members” głównej nakładki czatu nie jest wymagane.
  • Dane prezentów różnią się według trybu przechwytywania. Typowa konfiguracja to Event Type → Other: gift oraz Message Contains: Heart Me. Sprawdź przechwycony wiersz w Test Flow/Event Reference i dopasuj najjednoznaczniejsze pole dostarczane przez źródło.
  • Obie gałęzie nadal wymagają początkowego ?, dzięki czemu inne platformy mówią dla wszystkich, a TikTok pozostaje ograniczony.

Zapamiętuj osoby, które polubiły lub uczestniczyły

Event Type → Other: liked → Zapamiętaj użytkownika ···→ [Polubili transmisję]

Działa to wtedy, gdy przechwycone zdarzenie polubienia/udziału wskazuje użytkownika. Zbiorcze aktualizacje liczby polubień nie identyfikują osoby, więc nie można ich zapamiętać. Użyj oddzielnej pamięci dla każdego rodzaju udziału, jeśli chcesz niezależnych sprawdzeń lub losowań.

Losowanie nagród z unikalnymi zgłoszeniami

Wiadomość zaczyna się od !enter → Zapamiętaj użytkownika ···→ [Uczestnicy losowania nagród] Moderator + Wiadomość zaczyna się od !draw → AND → Wybierz losowego użytkownika ···→ [Uczestnicy losowania nagród] Moderator + Wiadomość zaczyna się od !resetdraw → AND → Wyczyść wszystkich użytkowników ···→ [Uczestnicy losowania nagród]

Włącz Usuń wybranego użytkownika (Remove selected user) , gdy zwycięzcy nie powinni być losowani dwukrotnie. Podczas publicznej transmisji chroń polecenia losowania/resetu sprawdzeniem moderatora, administratora lub dokładnego użytkownika.

Reset i trwałość

Ręcznie

Użyj Wyczyść wszystkich użytkowników teraz (Clear All Users Now) we właściwościach pamięci podczas budowania/testowania.

Z przepływu

Użyj Wyczyść wszystkich użytkowników (Clear All Users) lub ogólnego Zresetuj węzeł stanu (Reset State Node), wybierając dokładnie tę pamięć.

Automatyczne

Czyść po braku aktywności, na początku transmisji lub na końcu transmisji. Wartość 0 wyłącza reset po braku aktywności.

Po ponownych uruchomieniach

Pamięci sesji zaczynają się puste wraz z aplikacją. Zapisane pamięci są wczytywane ponownie, dopóki konkretna pamięć nie zostanie wyczyszczona.

„Wyczyść wszystko” ma określony zakres: oznacza wszystkich użytkowników wewnątrz wybranej pamięci — nie cały stan Event Flow, nie każde losowanie i nie każdą pamięć w Social Stream Ninja.
