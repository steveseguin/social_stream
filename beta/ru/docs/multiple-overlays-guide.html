Несколько каналов и отдельные оверлеи

Читайте все чаты в одной док-панели и выбирайте, какие платформы показывать в каждом зрительском оверлее.

Все руководства 1. Объедините захват в одном сеансе 2. Разделите поток чата по платформам 3. Разделите выбранные сообщения 4. Два канала на одной платформе 5. Проверьте каждый экран для зрителей 6. Чат и оповещения в одной вкладке

1. Объедините захват в одном сеансе

Добавьте нужные чаты-источники в SSN и убедитесь, что новое сообщение из каждого поступает в одну нефильтрованную док-панель Док-панель чата трансляции. Оставьте эту док-панель для управления.

Копируйте созданные ссылки, чтобы сохранить сеанс, пароль, версию и серверные настройки. Добавьте каждый экран зрителей отдельным источником «Браузер» OBS. Давайте источникам понятные имена, например Чат Twitch и Чат YouTube.

2. Разделите поток чата по платформам

Для потока чата создайте две копии своего URL dock.html . Добавьте эти параметры к соответствующим копиям:

Экран для зрителей Добавьте к URL док-панели
Чат Twitch &onlyfrom=twitch&hidemenu
Чат YouTube &onlyfrom=youtube&hidemenu
Twitch и YouTube вместе &onlyfrom=twitch,youtube&hidemenu
Всё, кроме Discord &hidefrom=discord&hidemenu

Например, при подключении по умолчанию:

https://socialstream.ninja/dock.html?session=YOUR_SESSION_ID&onlyfrom=twitch&hidemenu

Используйте onlyfrom и hidefrom для этих страниц. Не считайте, что параметр вроде onlytype из другого оверлея работает здесь. Используйте youtubeshorts отдельно, если захват сообщает этот тип. См. Типы источников.

3. Разделите выбранные сообщения

Для выбранных сообщений вместо потока чата скопируйте свой URL featured.html и добавьте &onlyfrom=twitch к одной копии и &onlyfrom=youtube к другой. Держите операторскую док-панель открытой для выбора сообщений.

Текущий параметр выбранных сообщений onlyfrom принимает один тип источника. Пример док-панели со значениями через запятую нельзя копировать в это поле выбранных сообщений.

Это фильтрует, какие выбранные сообщения принимает страница. Независимые операторские очереди не создаются, а отклонённый выбор не является командой очистки. Явно очищайте выбранное сообщение при смене частей эфира, чтобы прежнее принятое сообщение не оставалось видимым.

4. Два канала на одной платформе

onlyfrom=twitch выбирает платформу Twitch, а не конкретный канал. Названия каналов и трансляций — метаданные, а не взаимозаменяемые имена фильтров URL. Добавьте &showchannelname для показа названий каналов, если источник их передаёт.

Для расширенной фильтрации док-панели &filtertid=123 принимает числовой идентификатор исходной вкладки; поддерживаются значения через запятую. Посмотрите реальные захваченные данные, чтобы получить tid (см. Справочник событий и Команды и API). Не используйте здесь идентификатор канала платформы. Идентификаторы вкладок могут меняться при повторном открытии источников, а источники без подходящего идентификатора могут исключаться. Это параметр док-панели, а не общий фильтр канала для выбранных сообщений.

Для полностью независимых эфиров используйте отдельные экземпляры или профили захвата с разными сеансами и открывайте в каждом только нужные источники. Если задать оверлею другой сеанс без соответствующего захвата, он останется пустым. Параметр оверлея label обозначает страницу для маршрутизации, а не фильтрует канал.

5. Проверьте каждый экран для зрителей

  1. Отправьте вымышленное сообщение Twitch и вымышленное сообщение YouTube в изолированный сеанс с помощью Создавайте тестовые сообщения.
  2. Убедитесь, что оба сообщения видны в операторской док-панели, а каждый оверлей потока чата показывает только нужный источник.
  3. Выведите каждое сообщение и проверьте кнопку очистки. После переключения платформ проверяйте все видимые страницы выбранных сообщений.
  4. Повторите проверку с настоящим сообщением из каждого подключённого источника: синтетические сообщения не подтверждают реальные идентификаторы вкладок.

Если экран пуст, временно уберите фильтр. Если чат вернулся, проверьте точный тип источника или идентификатор вкладки. Если по-прежнему пусто, используйте устранение неполадок сеанса и маршрутизации. Переименование источника OBS не меняет сохранённый URL.

6. Чат и оповещения в одной вкладке

Используйте Объединить оверлеи для наложения существующих URL оверлеев в одной вкладке или источнике «Браузер» OBS. Это удобно для чтения чата на телефоне во время IRL-эфира.

  1. Вставьте созданный URL док-панели чата в нижний слой, а URL Multi-Stream Alert Box — в верхний. Сохраните сеанс, пароль и параметры подключения в обеих ссылках.
  2. Оставьте Прозрачный фон SSN включённым. Включите «Разрешить нажатия и прокрутку на этом слое» для чата и отключите для оповещений, чтобы они не мешали взаимодействию с чатом.
  3. Выберите Предпросмотр, затем Показать QR-код и отсканируйте камерой телефона. Либо выберите Скопировать объединённую ссылку для вставки результата в источник браузера. Объединённый экран не содержит элементов настройки.

Можно добавить до восьми URL и перемещать слои стрелками вперёд или назад. По умолчанию слои заполняют браузер. Разверните Размер и положение у слоя для задания ширины, высоты и отступов слева и сверху в пикселях (например, 450) или процентах (например, 100%). Пустые ширина и высота заполняют браузер; пустые отступы начинаются от левого верхнего угла. Вернуть полноэкранный размер сбрасывает размещение слоя. Каждый оверлей сохраняет своё содержимое и настройки.

Для левой колонки чата в источнике OBS 1920×1080 задайте слою чата ширину 450, высоту — 1080, левый отступ — 0, а верхний отступ — 0. Другие слои могут оставаться полноэкранными. Для Hype над чатом и выбранных сообщений со сдвигом вправо используйте рецепт размещения OBS ниже. Размеры в пикселях остаются фиксированными при изменении окна; проценты зависят от ширины или высоты браузера.

Используйте ссылку редактирования, чтобы открыть настройки с заполненными URL и размещением. Для последующего изменения объединённой ссылки добавьте ?edit=1 перед его #.

Ссылки и параметры слоёв автоматически сохраняются в этом браузере, включая незаконченные настройки. Снова откройте Объединить оверлеи для продолжения редактирования или выберите Очистить сохранённую настройку для начала заново. В приватном режиме хранилище браузера может быть недоступным или временным.

Объединённая ссылка и QR-код содержат полный макет и URL. Настройте на компьютере, отсканируйте телефоном и сохраните объединённый экран в закладки. При открытии настройка также сохраняется в браузере телефона. Изменения на компьютере не обновляют старую ссылку автоматически: после редактирования скопируйте или отсканируйте новую. Эта функция не синхронизирует настройки через идентификатор сеанса.

Храните объединённые ссылки и QR-коды так же приватно, как отдельные ссылки оверлеев. Захват SSN должен продолжаться, а телефон должен иметь доступ к серверам исходных URL. Адрес localhost или 127.0.0.1 указывает на устройство, открывающее ссылку. Очень длинные URL могут превышать вместимость QR-кода; объединённую ссылку всё равно можно скопировать.

Рецепт OBS: левая колонка чата с полноэкранными эффектами

Для этого макета CSS не нужен. Каждый слой — отдельная область браузера. Задайте общему источнику «Браузер» OBS размер 1920×1080, затем укажите эти значения в разделе каждого слоя Размер и положение. Вводите только числа, без запятых и «px». Добавьте слои в следующем порядке, начиная с нижнего:

СлойШиринаВысотаСлеваСверху
1. Чат прямого эфира / док-панель4501000080
2. Счётчик Hype4508000
3. Стена эмодзи и эмотов1920108000
4. Выбранные сообщения147010804500
5. NinjaBacker (необязательно)1920108000

Первые 80 пикселей отведены под Hype, ниже остаётся колонка чата шириной 450 пикселей. Чтобы чат занимал всю высоту позади Hype, задайте ему высоту 1080 , а верхний отступ — 0. Для других размеров сцены нужны другие значения в пикселях.

  1. Вставьте полные URL оверлеев. Скопируйте их из свойств существующих источников браузера, сохранив сеанс, пароль, стили и настройки подключения. Оставьте Прозрачный фон SSN включённым. Обрезка, преобразования, фильтры и поле Custom CSS в OBS не входят в URL и не переносятся.
  2. Разместите Hype по центру колонки. В его hype.html URL задайте align=center (замените существующее align=left или align=right и удалите alignright при наличии). Если URL уже содержит ?session=..., добавьте &align=center. Необязательный компактный начальный стиль — &combineall&hidetitle&style=compact&scale=0.75; заменяйте существующие значения, а не дублируйте их. Увеличьте высоту слоя Hype, если выбранному стилю нужно больше места.
  3. Не перекрывайте колонку чата выбранным сообщением. Установите Левый отступ = 450 и ширина = 1470 вместе: 450 + 1470 = 1920. Если сдвинуть слой шириной 1920 вправо на 450, его правый край обрежется. Оверлей выбранного сообщения по-прежнему размещает его внизу своей области. Чтобы короткие сообщения выравнивались по центру этой области, добавьте &center к его featured.html URL. Чтобы выравнивать сообщения по центру всей сцены, используйте левый отступ 0, ширину 1920 и &center.
  4. Держите NinjaBacker выше выбранных сообщений. Вставьте URL зрительского оверлея последним слоем, сохранив настройку анимации появления справа. Объединитель управляет областью и порядком слоёв; оверлей NinjaBacker управляет своей анимацией и внутренним размещением. Его фон должен быть прозрачным, а сайт должен разрешать встраивание. Этот необязательный слой не входил в проверку примера с четырьмя оверлеями.
  5. Предпросмотр в 1920×1080. Отправьте тестовое сообщение с эмодзи, выберите сообщение в док-панели для показа и включите данные Hype в SSN. Обычный чат сам по себе не выбирает сообщение для вывода. Если оверлей пуст, проверьте его отдельно.
  6. Скопируйте новую объединённую ссылку в OBS. Задайте самому источнику «Браузер» ширину 1920 и высоту 1080. Размер предпросмотра объединителя не задаёт размеры OBS. Впишите новый источник в сцену без обрезки. После каждого изменения макета копируйте объединённую ссылку заново; старый URL OBS сохраняет старый макет.

Производительность: один источник браузера по-прежнему запускает каждый встроенный оверлей и его подключения. Объединение уменьшает число источников OBS, но не гарантирует меньшую нагрузку на процессор или память. Закройте предпросмотр после настройки и сравните производительность OBS с отключёнными старыми источниками. Работу macOS/OBS на M1 и конкретного URL NinjaBacker нужно проверить в вашей системе. При желании оставьте чат отдельно и объедините только остальные оверлеи.

Если слой пуст или закрывает чат

  • Сначала откройте каждый исходный URL отдельно. Оповещения обычно пусты до поступления события; объединение страниц не захватывает новые события.
  • Автоматическая прозрачность поддерживает dock.html, featured.html, multi-alerts.html, и minecraft.html. Другим страницам нужны собственные настройки прозрачности. Некоторые внешние сайты полностью запрещают встраивание.
  • Даже прозрачный слой может перехватывать нажатия. Отключите Разрешить нажатия и прокрутку у любого слоя над чатом, которому не требуется взаимодействие.
  • Мобильный браузер может требовать взаимодействия со страницей перед воспроизведением звука. При необходимости разрешите взаимодействие со слоем и нажмите на него; ограничения автовоспроизведения остаются в силе. Проверяйте звук на самом телефоне.
