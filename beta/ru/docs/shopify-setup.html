Покажите товар Shopify за 5 шагов

  1. В Social Stream Ninja откройте Монетизация → Покупки Shopify → Настройка.
  2. Введите адрес магазина, например your-store.myshopify.com. Секрет не нужен.
  3. Открыть Импортировать товар, вставьте общедоступную ссылку товара и нажмите Загрузить данные товара.
  4. Проверьте название, изображение, цену и ссылку. Затем нажмите Добавить товар или ссылку.
  5. Включите Товары и ссылки поддержки и нажмите Сохранить настройку.
Товар не загружается? Добавьте Открытый токен Storefront (создайте его через канал Headless Shopify и опубликуйте товар там и в Online Store). Никогда не вставляйте токен Admin API или закрытый токен.
Что заполняет импорт
  • За раз загружается один товар.
  • Токен используется только для этого запроса, затем удаляется.
  • Это общедоступная ссылка магазина Shopify, включая собственный домен, если Shopify его предоставляет.
  • Цена заполняется только при одинаковой стоимости всех вариантов. Иначе поле остаётся пустым. Указывайте цену только при её точности.
  • Это снимок данных. Цены и наличие не обновляются автоматически, поэтому проверяйте их при изменениях в магазине.
  • Нельзя импортировать недоступные товары и товары без общедоступной ссылки Online Store.
  • Вместо этого товар всегда можно ввести вручную.

Получайте уведомление о покупке

Пока не включено. Для уведомлений о покупках нужен приёмник Shopify на сервере SSN. Он остаётся выключенным до успешной проверки с настоящим магазином. До тех пор Сохранить настройку показывает ошибку. Показ товаров продолжает работать.
  1. В Shopify перейдите в Settings → Notifications → Webhooks. Найдите для вебхука секрет подписи. (Это не токен Storefront.)
  2. В Social Stream Ninja откройте Монетизация → Покупки Shopify → Настройка.
  3. Введите свой myshopify.com адрес и секрет подписи.
  4. Включите Покупки Shopify и нажмите Сохранить настройку.
  5. Нажмите Скопировать URL приёмника.
  6. Создайте вебхук в Shopify. Событие: Оплата заказа. Формат: JSON. URL: адрес приёмника.
  7. Выберите стабильную версию API и сохраните. (SSN разработан для версии 2026-07.)
  8. Не закрывайте Social Stream Ninja.
Работает ли подключение? Следите за строкой состояния: ожидание, тест получен, событие пропущено или покупка получена. URL приёмника означает лишь, что настройки сохранены.

Где хранится ваш секрет
  • Секрет подписи хранится зашифрованным на приёмнике SSN. После сохранения поле очищается.
  • Отдельный закрытый ключ чтения остаётся на этом компьютере.
  • Ни один из них не попадает в ссылки OBS или QR-коды для зрителей.
  • Перед приёмом заказа приёмник проверяет подпись Shopify и название магазина.
  • У Shopify есть собственный приёмник, поэтому старый переключатель дистанционного управления API не нужен.

Добавьте в OBS

  1. В разделе Оверлей OBS для, выберите Товары и ссылки поддержки.
  2. Открыть Параметры ссылки оверлея и выберите Вид оверлея: Только витрина товаров (изображения, цены, QR-коды), Только карточка поддержки (небольшая ссылка на магазин) или Только оповещения об активности (покупки).
  3. Нажмите Копировать ссылку OBS. Добавьте его в OBS как Источник «Браузер», начав с 800 × 600. Используйте отдельный источник для каждого вида.
  4. Отсканируйте QR-код телефоном при окончательном размере изображения в эфире.

Почему в уведомлениях о покупке нет изображения? В заказах Shopify нет надёжного изображения, поэтому уведомления содержат только текст. Они никогда не берут изображение или QR-код из карточки товара.
Event Flow и цели пожертвований
  • В Event Flow выберите тип события purchase и задайте фильтр источника или типа shopify.
  • Для правил по сумме заказа сравнивайте meta.commerce.orderTotal. Проверить meta.commerce.currency в первую очередь.
  • Покупки не являются пожертвованиями. У них нет hasDonation или donoValue, и цели пожертвований не увеличиваются.
  • Метка «Подарок» на карточке не меняет подсчёт заказов. Доставка другому человеку не делает заказ подарком вам.

Проверяйте безопасно

Нажмите Показать пример для просмотра оформления. Предпросмотр не подключён к вашему сеансу, поэтому не запускает Event Flow, не меняет суммы и не проверяет оплату. Для полной проверки используйте магазин разработки Shopify. Заказы с отметкой test: true отображаются только в состоянии, без уведомлений.

Будьте осторожны с примерами из панели администратора Shopify. Если пример явно не помечен как тест, не отправляйте его в систему, выдающую награды.
Что проверено без настоящего магазина

Тесты в настоящем приложении охватывают подписанные сообщения, в том числе неанглийский текст, подделанные подписи, повторную доставку, тестовые заказы, округление валют, слишком большие запросы, удаление личных данных покупателей и получение накопленных событий после отключения. Реальные заказы и учётная запись продавца не использовались.

Примеры вебхуков Shopify CLI позволяют проверить обработку сообщений, но не подписки на события или повторные попытки, и требуют учётных данных приложения. См. Ограничения проверки вебхуков Shopify CLI.

ПроблемаЧто попробовать
При сохранении настроек появляется ошибкаПриёмник ещё не включён на сервере. Не заменяйте его старым URL вебхука сеанса.
Состояние остаётся «ожидание»Проверьте вебхук: Оплата заказа, JSON, точный URL приёмника, myshopify.com адрес и секрет. Вебхуки собственных приложений используют секрет самого приложения.
Событие пропущеноТолько полностью оплаченные заказы с суммой больше нуля, отмеченные test: falseи обновлённые за последние 7 дней учитываются. Неоплаченные, частично оплаченные и отменённые заказы пропускаются.
SSN был выключен во время продажиЗаказы ожидают до 7 дней. Запустите SSN, и они поступят.
Действие выполнилось дваждыПовторы блокируются на 7 дней, но сбой во время действия может привести к повтору. Для важных автоматизаций добавьте собственную проверку.
Нет имени покупателяТак задумано. Имена, email, адреса, заметки, дополнительные поля, ссылки оформления заказа и ID заказов никогда не показываются.
Возврат не удалил уведомлениеВозвраты, отмены и изменения не отменяют уведомления. Это не бухгалтерский учёт.
Как обрабатываются ожидающие и повторные заказы
  • Время заказа может опережать текущее до пяти минут из-за расхождения часов.
  • Оплата никогда не определяется по созданию заказа, отправке или изменению запасов. При отсутствии тестового флага событие пропускается.
  • Состояние и ожидающие заказы сохраняются при перезапуске приёмника.
  • Объём хранения ограничен. Если приёмник не может безопасно сохранить заказ, он просит Shopify отправить его позже.
  • Повторы определяются по магазину и заказу, даже если ID доставки Shopify различаются.
  • SSN сохраняет сведения об обработанных заказах перед подтверждением.
