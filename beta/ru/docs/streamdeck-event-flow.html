Полное руководство по элементам управления, жестам и значкам Stream Deck

Создайте сценарий, который можно вызвать

Event Flow→Именованный рабочий процесс→Ключ Stream Deck
  1. Именованный триггерStream Deck / API
  2. Условия и действияВаш сохранённый сценарий Event Flow
  3. НазначениеFlow Actions, OBS или другая интеграция
  1. Открыть Event Flow из SSN. Создайте отдельный сценарий или выберите шаблон Кнопка Stream Deck / API .
  2. Добавить Запуск из Stream Deck / API в группе триггеров Stream Deck и API .
  3. Задайте имя intermission. Имена должны совпадать точно, с учётом регистра; выберите короткое описательное имя.
  4. Соедините его выход с Показать текст. Задайте текст Back in five minutes и выберите нужную длительность и слой.
  5. Сохраните сценарий, затем включите его. Несохранённый сценарий существует только в редакторе; выключенный нельзя вызвать. Начальный шаблон намеренно выключен до завершения настройки.
  6. Откройте свой Оверлей Flow Actions по ссылке, созданной SSN. Для показа зрителям добавьте этот URL как источник «Браузер» OBS. Сам редактор оверлеем не является.

Сценарии без этого именованного триггера нельзя вызвать через API сценариев. Вызов сценария не добавляет фиктивный чат в док-панель. Существующие события OBS и обычный чат продолжают использовать свои триггеры.

Сценарий может объединять именованный триггер с фильтрами через логические узлы. Размещайте несвязанные автоматизации в отдельных сценариях: все ветви триггеров и логики выбранного сценария проверяются с событием API. Повторные нажатия создают отдельные запуски; добавьте Ограничитель частоты после триггера, если нужен интервал между запусками.

Подключить клавишу Stream Deck

  1. Настройте в плагине действие Настройка с вашей сессией SSN и необязательным паролем. Используйте Проверить подключение.
  2. Перетащите Готовая команда на клавишу.
  3. Выберите Сценарии Event Flow → Запустить сценарий.
  4. Выберите Обновить сценарии, затем выберите сохранённый сценарий и триггер. Клавиша хранит ID сценария вместе с именем триггера.
  5. Нажмите один раз и посмотрите на оверлей Flow Actions. Галочка на клавише означает, что SSN принял запуск.

Список сценариев сохраняет выбор даже при отсутствии выбранного элемента. После переименования, отключения, удаления или импорта сценария обновите список и выберите сценарий заново. У сценария, импортированного как новый, другой ID. Для обращения по имени к нескольким сценариям используйте поле Value.

Пользовательская команда: задайте для Action значение triggerWorkflow, оставьте Target пустым, введите {"trigger":"intermission"} в качестве Value и включите Ожидать ответ. Предустановка помогает выбрать параметры и отфильтровывает неподдерживаемые возможности.

Мультидействия: каждый запрос сценария быстро подтверждает принятие. Следующий шаг Stream Deck может начаться до завершения отложенных действий сценария. Если порядок важен, задавайте последовательность и задержки внутри Event Flow.

Передать собственные значения

В поле Value клавиши или в запросе API:

{
  "trigger": "intermission",
  "flowId": "YOUR_SAVED_FLOW_ID",
  "data": { "name": "Back in five minutes", "minutes": 5 }
}

Установите текст Show Text равным {meta.workflow.data.name}. Узел Compare Property может читать meta.workflow.data.minutes. Data — необязательный объект JSON; он остаётся в meta.workflow.data и не может заменить идентичность события или предоставить права чата.

Не указывайте flowId для вызова всех включённых сценариев с точно таким именем триггера. Несколько совпадающих узлов триггера в одном сценарии всё равно проверяют этот сценарий только один раз. Чтобы запустить только один сценарий, сохраните его ID из списка выбора или ответа со списком сценариев.

Событие внутри выбранного сценария содержит type: "api", event: "workflow_trigger", chatname: "Stream Deck / API", пустое поле chatmessage и данные выше. Обычный чат с копиями этих полей не может активировать именованный триггер API.

Примеры API

SSN должен быть включён и запущен. Это вызовы удалённого управления Social Stream; они не используют отдельный локальный API ИИ/MCP в SSApp. Держите настоящий ID сессии в секрете.

Найти доступные триггеры

{"action":"getWorkflowTriggers","get":"list-1","apiid":"YOUR_SESSION"}

Ответ содержит result.payload.triggers:

{"triggers":[{"flowId":"flow-123","flowName":"Intermission","trigger":"intermission"}]}

Запустить именованный сценарий

{
  "action": "triggerWorkflow",
  "value": {"trigger":"intermission","flowId":"flow-123","data":{"name":"Back shortly"}},
  "get": "run-1",
  "apiid": "YOUR_SESSION"
}

Используйте уникальную get строку для каждого запроса. Успешный ответ содержит result.ok: true, result.status: "accepted", и result.payload.matchedFlows. Принятие означает, что включённый сценарий найден и поставлен на выполнение. Оно не означает, что все отложенные действия, вебхуки, вызовы OBS или воспроизведение медиа уже завершены.

WebSocket

Включить (Enable) удалённое управление расширением через API в SSN. Подключитесь к wss://io.socialstream.ninja. Подключитесь с {"join":"YOUR_SESSION","out":1,"in":2}, затем отправьте запрос выше. Канал 1 передаёт команды, канал 2 — ответы. Для сценариев включать канал чата не требуется.

HTTP

Включите ту же настройку удалённого управления через API. Перед использованием замените заполнитель сессии:

POST https://io.socialstream.ninja/YOUR_SESSION
Content-Type: application/json

{"action":"triggerWorkflow","value":{"trigger":"intermission","data":{"name":"Back shortly"}}}

Для простого именованного триггера также можно использовать GET https://io.socialstream.ninja/YOUR_SESSION/triggerWorkflow/null/intermission. Четвёртый сегмент пути может содержать JSON со структурированными значениями, закодированный для URL. Кодируйте всё значение JSON с помощью encodeURIComponent(JSON.stringify(value)). Пользовательские каналы отправки используют ?channel=N.

P2P

Режим P2P, используемый плагином по умолчанию, отправляет тот же объект через существующий транспорт каналов данных VDO.Ninja в SSN. Для P2P не нужен переключатель размещённого WebSocket API. Существующие клиенты P2P должны отправлять этот запрос через установленное соединение управления SSN; открывать локальный API ИИ не требуется.

Ошибки и совместимость

  • WORKFLOW_NOT_FOUND: ни один сохранённый и включённый сценарий не соответствует триггеру или ID сценария.
  • INVALID_VALUE: отсутствующий или неверный триггер, некорректный JSON, неверный ID сценария либо данные не в виде объекта.
  • CONTROL_UNAVAILABLE: SSN или удалённое управление ведущего отключены.
  • TARGET_UNAVAILABLE: Event Flow ещё загружается.
  • Старые ресурсы Social Stream могут не объявлять эти действия. Проверьте getCapabilities → ssn.actions.triggerWorkflow и getWorkflowTriggers. Необходимо установить и новый триггер, и обновлённый плагин; номер версии SSApp сам по себе не определяет версию удалённо загружаемых ресурсов Social Stream.

Не повторяйте автоматически изменяющий состояние вызов при потере подтверждения: сценарий мог уже запуститься. Сначала проверьте результат. Этот API не предоставляет очередь состояний выполнения.

Жесты таймера и чата

Таймер: один шаг поворота по умолчанию изменяет время на ±10 секунд; поворачивайте регулятор, удерживая его нажатым для ±1 минуты (6× настроенный шаг). Нажмите и отпустите без поворота для запуска или паузы. Коснитесь экрана таймера для обновления; удерживайте экран для сброса. Одно лишь удержание физического регулятора не сбрасывает таймер.

Просмотр чата: поворачивайте влево для старых сообщений, вправо для новых; нажмите регулятор, чтобы закрепить просматриваемое сообщение. Коснитесь экрана, чтобы выделить следующее закреплённое сообщение; удерживайте экран, чтобы открепить просматриваемое сообщение. Стандартная док-панель должна быть открыта. В режиме WebSocket включите пересылку чата на канале 4.

Открыть Справка и диагностика → Руководство по управлению, значкам и сценариям в плагине: там находится полное автономное руководство, все пять типов действий, все предустановки и значки, правила сброса, значения по умолчанию и устранение неполадок.

Справочник палитры Event Flow

Палитра содержит 45 триггеров, 67 действий, пять логических узлов и четыре узла состояния. У каждого элемента рядом со значком есть текстовая подпись. Выберите узел, чтобы увидеть его настройки и требования к интеграции; значок в палитре не означает, что адресат подключён.

Триггеры определяют, когда начинается сценарий. При необходимости соединяйте условия через AND/OR. Действия выполняются в порядке соединения. Узлы состояния запоминают значения между событиями. Для интервала между нажатиями кнопки выберите Ограничитель частоты (THROTTLE), а не действие Delay: Delay откладывает каждый запуск, но не подавляет повторные нажатия.

  • 🎲 Случайный логический узел — RANDOM
  • 🚫 Проверить нежелательные слова — CHECK_BAD_WORDS
  • 🚦 Переключатель вкл./выкл. — GATE
  • 🔢 Счётчик — COUNTER
  • ⏲️ Ограничитель частоты — THROTTLE
  • 🧠 Память пользователей — USER_MEMORY

Фильтрам сообщений, баллам зрителей и действиям с памятью пользователей нужны содержательные данные сообщения или пользователя. Кнопка ведущего не передаёт ни реального зрителя, ни адресата ответа в исходном чате. Выбирайте управление для ведущего или явно настроенный адресат; не используйте именованный сценарий, чтобы выдавать запрос за действие зрителя.

Подробности соединения узлов — см. Руководство по Event Flow, руководство по узлам состояния, руководство по памяти пользователей, и руководство по OBS.

Разобраться со сбоем

  1. Начните с простого сценария Show Text и проверьте его результат.
  2. Сохраните и включите сценарий; обновите список сценариев Stream Deck. Проверьте и имя триггера, и ID сценария.
  3. Убедитесь, что SSN включён, соединение имеет состояние Online, а целевой оверлей подключён к той же сессии.
  4. Проверьте ответ API или диагностику плагина на ошибки поиска и проверки данных. При сбоях после принятия запроса проверьте целевую систему и журнал выполнения Event Flow.
  5. Добавляйте остальные интеграции по одной. Перед использованием в эфире проверьте повторные нажатия, выключенный сценарий и переподключение.

Обычная тестовая панель чата в редакторе отправляет событие чата. Она не имитирует именованный триггер API. Проверяйте этот триггер через Stream Deck или API, чтобы проверить весь путь.
