Explicação dos servidores e serviços locais

O Social Stream Ninja usa vários serviços locais diferentes. Escolha o que corresponde ao que deseja fazer.

1. Ativar servidor local

Esta opção do menu Arquivo inicia um retransmissor WebSocket que distingue salas e canais dentro do aplicativo. Páginas compatíveis do Social Stream podem trocar chat e comandos no mesmo computador. É um endpoint alternativo para roteamento por servidor específico de cada página.

Ele não hospeda o site Social Stream, não captura uma plataforma sozinho nem fornece a API HTTP de automação. Comece pelo guia de Ativar servidor local.

2. API de controle local e MCP

Esta API opcional de loopback permite que programas no computador do SSApp gerenciem fontes e configurações compatíveis, leiam status e diagnósticos, inspecionem janelas e acompanhem eventos capturados. O adaptador MCP incluído apresenta essas operações como ferramentas para clientes de IA compatíveis.

Ative em Arquivo > IA local / Automação (File > Local AI / Automation). É separado de Ativar servidor local (Enable Local Server). Veja o Guia da API de controle local e MCP.

3. Servidor doméstico ou VPS sem interface

O modo sem interface executa o aplicativo Electron completo com janelas de fontes ocultas. No Linux, ainda precisa de um sistema de exibição como Xvfb. É útil quando um computador dedicado deve continuar capturando chat sem monitor.

O modo sem interface não cria uma API pública de controle. O controle remoto usa o transporte WebRTC ou WebSocket normal do Social Stream. Veja o guia de hospedagem sem interface.

4. Servidor de mídia local

O aplicativo inicia isso automaticamente quando há mídia local de Event Flow. Serve apenas arquivos aprovados pelo SSApp e alguns recursos de execução por uma rota com token aleatório por perfil.

Não é um servidor genérico de web ou arquivos. Veja Arquivos de mídia para Event Flow para escolher entre arquivos locais, uploads e hospedagem na nuvem.

A alternativa de servidor é diferente

Configurações como Enviar mensagens de chat ao servidor da API (Send chat messages to API server) e Dock envia comandos à extensão pelo servidor (Dock sends its commands to Extension via server) escolhem como chat e comandos são roteados. Os parâmetros gerados de URL incluem server, server2, e server3.

Essas configurações normalmente usam o serviço WebSocket hospedado do Social Stream. Quando uma página compatível também tem localserver, ela usa o retransmissor local do aplicativo de desktop. Veja Sessões, senhas, relay e modos de servidor para os controles de roteamento.

Use links recém-gerados. As opções de roteamento são específicas por página. Não copie uma opção de servidor entre páginas supondo que tenha o mesmo significado.

Outras portas locais temporárias

Alguns fluxos de login e vinculação de contas abrem temporariamente uma porta de retorno em loopback e a fecham ao concluir. Esses receptores temporários não são servidores gerais do SSN nem APIs de automação.
