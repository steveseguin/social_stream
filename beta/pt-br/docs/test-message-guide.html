Criar mensagens de teste

O que esta ferramenta faz

O página Criar mensagem de teste envia payloads sintéticos do Social Stream para seu dock, suas sobreposições, seus alertas ou sua configuração do Event Flow. Use para testar sem esperar por uma mensagem real de chat, doação, membro, raid, recompensa ou outro evento.

Use uma sessão de teste sempre que possível. Uma mensagem enviada se comporta como tráfego recebido na sessão e pode disparar alertas, sons, webhooks, ações do OBS ou outras automações.

Início rápido para SSApp ou extensão

  1. Abra o Social Stream Ninja e verifique se o serviço está ativo.
  2. Em Configurações e ferramentas globais → Mecânica, ative controle remoto da extensão por API. O SSApp usa o mesmo nome de configuração.
  3. Copie seu ID de sessão do Social Stream ou do session= na URL do dock ou da sobreposição.
  4. Abrir Criar mensagem de teste e insira esse ID de sessão.
  5. Deixe Enviar via definido como Entrada pela API da extensão para testes normais.
  6. Escolha uma predefinição, ajuste seus campos e selecione Carregar predefinição (Load Preset).
  7. Confira o JSON do payload e selecione Enviar (Submit).
  8. Confirme que o item aparece no dock ou na sobreposição de destino e que a automação esperada é executada.

Você pode incluir a sessão na URL: createtestmessage.html?session=YOUR_SESSION_ID.

Exemplo: uma mensagem fictícia de 1.000 KICKs

Isso cria uma mensagem de apoio no estilo Kick no valor de 1.000 KICKs. Não cria 1.000 mensagens separadas.

  1. Escolha a predefinição Mensagem de chat predefinição.
  2. Defina Digite como Kick.
  3. Digite um nome e uma mensagem de teste.
  4. Defina Tem doação (Has Donation) como 1000 KICKs.
  5. Selecione Atualizar JSON a partir dos campos (Update JSON from Fields), confira o JSON e envie.

O payload mínimo é:

{
  "type": "kick",
  "chatname": "Test Supporter",
  "chatmessage": "Thanks for the stream!",
  "hasDonation": "1000 KICKs"
}

Use Mensagem de chat para este exemplo. A predefinição Doação / Cheer inclui campos de cheer específicos do Twitch.

Usar predefinições e JSON personalizado

As predefinições oferecem um payload inicial para casos comuns, como doações, inscritos, inscrições presenteadas, raids, recompensas, atualizações de espectadores, primeiras mensagens e eventos de trem.

  • Carregar predefinição (Load Preset) substitui o JSON pela predefinição selecionada e pelos valores atuais dos campos.
  • Atualizar JSON a partir dos campos (Update JSON from Fields) monta uma mensagem básica a partir dos campos visíveis.
  • Você pode editar JSON do payload diretamente ao testar um campo ou formato de evento específico.
  • hasDonation contém o valor de apoio visível, como 1000 KICKs ou $10.00.
  • Inclua somente event ao testar um evento real com nome definido. Uma linha normal de chat no estilo doação pode usar hasDonation por si só.

Para definições dos campos e exemplos de plataformas reais, consulte a Referência de eventos.

Direto para o canal 1O dock de destino foi aberto com &server.O destino precisa estar ouvindo no canal de servidor correspondente.

Se estiver em dúvida, use Entrada pela API da extensão.

Correções comuns

  • Nada aparece: confirme que a página de destino está aberta e usa o mesmo ID de sessão.
  • A entrada pela API da extensão falha: ative controle remoto da extensão por API, depois recarregue o dock ou a sobreposição e tente novamente.
  • O modo direto informa que enviou, mas nada aparece: use Entrada pela API da extensão, a menos que a URL de destino tenha o correspondente &server ou &server2 modo.
  • O evento errado é disparado: verifique se o JSON do payload contém campos remanescentes de outra predefinição.
  • O teste do Kick se comporta como Twitch: use a predefinição Mensagem de chat e defina type e hasDonation como mostrado acima.
  • Uma automação é executada mais de uma vez: verifique se vários docks, páginas de ações ou instâncias do Event Flow estão abertos na mesma sessão.
