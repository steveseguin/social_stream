Memória de usuários (User Memory)

Memorize participantes únicos, verifique-os em mensagens posteriores, sorteie um vencedor e redefina exatamente a lista desejada, sem transformar uma função de plataforma em um estado global permanente.

Uma memória nomeada, muitas ferramentas

Um Memória de usuários (User Memory) contém um conjunto isolado de pessoas. Cada nó Memorizar, Esquecer, Verificar, Sortear ou Limpar seleciona esse nó de estado. Crie outro nó Memória de usuários quando precisar de uma lista separada, por exemplo, uma para “curtiu a transmissão” e outra para “entrou no sorteio”.
Verde-azulado sólido: este evento é executado em seguida Roxo tracejado: este nó usa aquela memória

Arraste o pequeno losango roxo lateral até um nó Memória de usuários ou escolha a memória pelo nome nas propriedades do nó. Internamente, a operação armazena o ID do nó de estado. Selecionar a memória destaca todas as operações vinculadas, e excluí-la gera um aviso antes que as ligações sejam rompidas.

Configure

  1. Arraste Nós de estado → Memória de usuários para a área de edição.
  2. Nomeie de acordo com a lista que armazena, como Elegíveis ao Heart Me, Curtiu a transmissão, ou Participantes do sorteio.
  3. Escolha Esta sessão do aplicativo ou Salvar entre reinicializações.
  4. Adicione as verificações e ações necessárias e vincule cada uma à memória nomeada usando o losango lateral ou o menu suspenso.
  5. Conecte o caminho normal de eventos com linhas verde-azuladas e use Testar fluxo com dois nomes de usuário diferentes antes de entrar ao vivo.

Operações disponíveis

NóO que faz
Memorizar usuário (Remember User)Adiciona o usuário do evento atual uma vez. Participações repetidas aumentam a contagem de participação desse usuário sem adicionar entradas duplicadas ao sorteio.
Usuário está memorizado (User Is Remembered)Um gatilho/verificação que retorna verdadeiro quando a mensagem atual pertence a alguém da memória selecionada.
Esquecer usuário (Forget User)Remove somente o usuário do evento atual.
Sortear usuário (Pick Random User)Seleciona um usuário único memorizado. Opcionalmente, pode remover o vencedor para que ele não ganhe novamente.
Limpar todos os usuários (Clear All Users)Esvazia somente o objeto Memória de usuários selecionado.
Redefinir nó de estado (Reset State Node)Também limpa uma Memória de usuários quando ela é o destino de redefinição selecionado.
Regra de identidade: os usuários são identificados pela plataforma e pelo ID de usuário. O nome de usuário exibido é usado apenas como alternativa. Um evento anônimo ou agregado sem identidade de usuário é ignorado com segurança.

Receitas práticas

Heart Me ou membro da equipe do TikTok → ? Síntese de voz

Use o evento de presente para memorizar quem enviou; não tente transformar uma única linha de presente em uma função permanente de “membro”.

Evento de presente do TikTok + correspondência de “Heart Me” → AND → Memorizar usuário ···→ [Elegíveis ao Heart Me]
? comando + origem TikTok + (Membro da equipe TikTok OR Usuário está memorizado) → AND → Falar texto ? comando + NOT origem TikTok → AND ────────────────────────────────→ Falar texto
  • Para status de equipe/fã no TikTok, escolha Função do usuário → Membro da equipe TikTok. Ele lê diretamente os dados de distintivo/nível recebidos do TikTok; a configuração de exibição “tratar como membros” da Sobreposição principal de chat não é necessária.
  • Os payloads de presentes variam conforme o modo de captura. Uma configuração comum é Tipo de evento → Outro: gift além de Mensagem contém: Heart Me. Confirme a linha capturada em Testar fluxo/Referência de eventos e use o campo mais adequado fornecido pela sua fonte.
  • Ambas as ramificações ainda exigem o ?, para que as outras plataformas falem para todos enquanto o TikTok permanece restrito.

Memorizar pessoas que curtiram ou participaram

Tipo de evento → Outro: liked → Memorizar usuário ···→ [Curtiu a transmissão]

Isso funciona quando o evento capturado de curtida/participação identifica um usuário. Atualizações agregadas da contagem de curtidas não identificam uma pessoa e, portanto, não podem ser memorizadas. Use uma memória separada para cada tipo de participação se quiser verificações ou sorteios independentes.

Sorteio com uma entrada por pessoa

Mensagem começa com !enter → Memorizar usuário ···→ [Participantes do sorteio] Moderador + Mensagem começa com !draw → AND → Sortear usuário ···→ [Participantes do sorteio] Moderador + Mensagem começa com !resetdraw → AND → Limpar todos os usuários ···→ [Participantes do sorteio]

Ative Remover usuário selecionado quando os vencedores não devem ser sorteados duas vezes. Em uma transmissão pública, proteja os comandos de sorteio/redefinição com uma verificação de moderador, administrador ou usuário exato.

Redefinição e persistência

Manual

Use Limpar todos os usuários agora nas propriedades da memória durante a criação/os testes.

A partir de um fluxo

Use Limpar todos os usuários (Clear All Users) ou o genérico Redefinir nó de estado (Reset State Node), selecionando a memória exata.

Automático

Limpe após inatividade, no início ou no fim da transmissão. Um valor 0 desativa a redefinição por inatividade.

Entre reinicializações

As memórias da sessão começam vazias com o aplicativo. As memórias salvas são recarregadas até que aquela memória específica seja limpa.

“Limpar todos” tem escopo limitado: significa todos os usuários da memória selecionada — não todo o estado do Event Flow, nem todos os sorteios ou todas as memórias do Social Stream Ninja.

Usar saídas de sorteio e participação

As ações de memória adicionam campos à mensagem para que ações posteriores, como Mostrar texto, Enviar mensagem, webhook ou ações personalizadas, possam usá-los.

Solução de problemas

A linha tracejada não apareceSelecione a operação e escolha uma Memória de usuários de destino, ou arraste seu losango roxo lateral até o núcleo da memória.
A mesma pessoa aparece duas vezesVerifique se os eventos vieram de plataformas diferentes. Plataforma + ID de usuário cria identidades separadas intencionalmente.
Uma curtida não adicionou ninguémO evento provavelmente não tinha identidade de usuário. Inspecione o payload; contagens agregadas não podem se tornar participantes nomeados.
Uma memória salva voltouUse Limpar todos os usuários nessa memória. Alterar um fluxo ou limpar outra memória não a apaga.
Qualquer pessoa pode executar o comando de sorteio/redefiniçãoAdicione Função do usuário: moderador/admin (ou uma verificação exata do usuário anfitrião) em uma porta AND antes da ação.
