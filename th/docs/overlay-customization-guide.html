ออกแบบโอเวอร์เลย์โซเชียลสตรีมของคุณเอง

ดาวน์โหลด ปรับแต่ง เชื่อมต่อ และทดสอบการออกแบบโอเวอร์เลย์ในเครื่อง OBS พร้อมคำแนะนำสำหรับโอเวอร์เลย์แต่ละตระกูล

เลือกประเภทดาวน์โหลดรหัสเซสชันเปิดใน OBSการออกแบบและ AIอินพุตที่ปลอดภัยการทดสอบไฟล์ที่จะให้ AIการแก้ปัญหา

เลือกโอเวอร์เลย์ที่คุณต้องการออกแบบใหม่

ดาวน์โหลดไฟล์→เปลี่ยนการออกแบบ→เปิดใน OBS

คุณสามารถเปลี่ยนสี แบบอักษร เค้าโครง งานศิลปะ และการเคลื่อนไหวของหน้าที่มีอยู่ได้ ที่ ไฟล์ HTML คือหน้า; ที่ URL ของ OBS ชี้ไปที่มันและให้เซสชันและการตั้งค่าการแสดงผล สำหรับการปรับเปลี่ยนเล็กน้อย ให้ใช้ OBS Custom CSS บนหน้าที่โฮสต์ หากต้องการการเปลี่ยนแปลงที่ลึกซึ้งยิ่งขึ้น ให้ดาวน์โหลดซอร์สและเรียกใช้สำเนาของคุณเอง

คำแนะนำเหล่านี้ครอบคลุมตระกูลโอเวอร์เลย์ รวมถึงธีมต่างๆ ด้วย เลือกผู้รับสำหรับคุณสมบัติที่คุณใช้: หน้าแชท หน้าข้อความที่เลือก และการสำรวจความคิดเห็นไม่ได้ใช้อินพุตเดียวกันทั้งหมด

สำหรับการออกแบบสำเร็จรูปให้เริ่มต้นใน แกลเลอรีโอเวอร์เลย์ หรือ แกลเลอรีเทมเพลต. สำหรับสกินแชท StreamElements/Streamlabs ที่มีอยู่ ให้ปฏิบัติตาม คู่มือการนำเข้า. HTML ที่มีอยู่ในตัวเองที่นำเข้ามีคำแนะนำในการส่งออก/ตั้งค่าของตัวเอง

1. ดาวน์โหลดไฟล์จริง

  1. ดาวน์โหลดซอร์ส beta แบบ ZIPหรือเปิด พื้นที่เก็บข้อมูลเบต้า แล้วเลือก รหัส → ดาวน์โหลด ZIP.
  2. แตกไฟล์ ZIP ลงในโฟลเดอร์ที่คุณสามารถเก็บไว้ เช่น C:\SSN\social_stream-beta\. ห้ามแก้ไขภายในไฟล์บีบอัด นี่คือไฟล์ต้นฉบับของหน้า การแก้ไขสำเนาแยกต่างหากไม่จำเป็นต้องติดตั้ง SSN ใหม่
  3. ค้นหาไฟล์ที่แสดงในตารางด้านบน ทำซ้ำข้างต้นฉบับ: ตัวอย่างเช่น poll.html กลายเป็น my-poll.html สำหรับ themes/featured-styles/featured-modern.htmlเก็บสำเนาไว้ themes/featured-styles/.
  4. เปิดสำเนาในตัวแก้ไขข้อความ/โค้ด ให้สิทธิ์เครื่องมือ AI ของคุณเข้าถึงไฟล์นั้นและสไตล์/สคริปต์อ้างอิงที่ต้องการ บันทึก HTML เป็น .htmlไม่ใช่ .html.txt.

คงโครงสร้างโฟลเดอร์ที่แตกออกมาไว้ ไฟล์ HTML ที่ดาวน์โหลดมาเพียงไฟล์เดียวอาจโหลดสคริปต์ สไตล์ชีต แบบอักษร รูปภาพ เสียง หรือ JSON ข้างๆ ไฟล์นั้น การดูหน้าของ GitHub และ "บันทึกหน้า" ของเบราว์เซอร์ไม่ใช่ชุดข้อมูลที่สมบูรณ์ที่เชื่อถือได้ คู่มือแต่ละประเภทจะระบุไฟล์ที่มีประโยชน์ แต่โฟลเดอร์ที่แยกออกมาทั้งหมดเป็นวิธีที่ง่ายที่สุดในการรักษาการอ้างอิง

2. เก็บเซสชันและการตั้งค่าการเชื่อมต่อไว้

เริ่ม SSN เชื่อมต่อแหล่งที่มา และยืนยันว่าโอเวอร์เลย์ดั้งเดิมใช้งานได้ คัดลอก ลิงก์ที่สร้างขึ้นเสร็จสมบูรณ์ จากเครื่องมือ SSN ที่เกี่ยวข้อง ค่าหลัง session= ระบุเซสชัน SSN ของคุณ ไม่ใช่ช่อง YouTube ชื่อผู้ใช้ Twitch ชื่อไฟล์ หรือชื่อของการสำรวจความคิดเห็น

https://socialstream.ninja/poll.html?session=YOUR_SESSION&password=YOUR_PASSWORD&server2

ตัวอย่างใช้ตัวยึดตำแหน่ง SSN และเพจต้องใช้เซสชันจริงเดียวกันและรหัสผ่านที่กำหนดค่าไว้ การเปลี่ยนชื่อไฟล์จะไม่เปลี่ยนเซสชัน ให้ SSN และจับภาพทำงานต่อไป: การซ้อนทับจะได้รับข้อมูล มันไม่ได้บันทึกการแชทบนแพลตฟอร์มด้วยตัวเอง

  • ? เริ่มแบบสอบถาม; การใช้การตั้งค่าภายหลัง &. คัดลอกค่าแทนที่จะพิมพ์ซ้ำ ในแอตทริบิวต์แหล่งที่มา HTML ให้เขียน &amp;; ในฟิลด์เบราว์เซอร์/OBS URL ให้ใช้เครื่องหมายแอมเพอร์แซนด์ธรรมดา
  • รักษาการตั้งค่าการขนส่ง: server, server2, server3ค่าปลายทาง ป้ายกำกับ และเวอร์ชันในเครื่องเป็นแบบเฉพาะหน้า อย่าเพิ่มแฟล็กเซิร์ฟเวอร์เพียงเพราะว่าโอเวอร์เลย์อื่นรองรับ
  • เก็บเศษชิ้นส่วนด้วย: ทุกอย่างหลังจากนั้น # อาจมีความสำคัญ ตัวอย่างเช่น AI Event Overlay ใช้ไพรเวต #aieventauth=... โทเค็นการแสดงผล
  • ใช้ตัวยึดตำแหน่งในตัวอย่างที่แชร์ เก็บลิงก์เซสชันจริง รหัสผ่าน และโทเค็นการแสดงผลส่วนตัวของคุณไม่ให้อยู่ในภาพหน้าจอสาธารณะ พื้นที่เก็บข้อมูล และตัวอย่างพร้อมท์ AI

เมื่อสำเนายังว่างเปล่า ให้ตรวจสอบลิงก์ต้นฉบับที่สร้างขึ้นก่อน บางหน้าแจ้งว่าไม่มีการตั้งค่า ส่วนอื่นๆ ยังคงซ่อนอยู่หรือเปลี่ยนเส้นทาง การระบุเซสชันที่ถูกต้องเป็นการหลีกเลี่ยงการพึ่งพาค่าเริ่มต้นเฉพาะเพจเหล่านั้นอย่างชัดเจน

3. เปิดไฟล์ของคุณใน OBS

เปิด HTML ที่แก้ไขแล้วจากคอมพิวเตอร์ของคุณโดยตรง ไม่มีเซิร์ฟเวอร์ที่จะติดตั้งหรือเริ่มต้น

  1. ลากไฟล์ HTML ที่คัดลอกของคุณไปที่ Chrome หรือ Edge คัดลอกที่อยู่แบบเต็มจากแถบที่อยู่ มันเริ่มต้นด้วย file:///.
  2. คัดลอกทุกอย่างจาก ? เป็นต้นไปในลิงก์โอเวอร์เลย์ SSN ที่ทำงานของคุณ และเพิ่มไปที่ส่วนท้ายของที่อยู่ไฟล์นั้น ซึ่งจะเก็บเซสชั่น รหัสผ่าน การตั้งค่าอื่นๆ และอื่นๆ ของคุณ # สิ้นสุด
  3. เปิดที่อยู่ที่รวมไว้ในเบราว์เซอร์ของคุณเพื่อทดสอบ
  4. ใน OBS เพิ่ม แหล่งเบราว์เซอร์ (Browser Source) คงค่า ไฟล์ในเครื่อง (Local file) ยกเลิกการเลือกและวางที่อยู่แบบเต็มลงไป URL. กำหนดความกว้างและความสูงสำหรับการออกแบบของคุณ

ตัวอย่างเช่น ลิงค์ SSN นี้:

https://socialstream.ninja/poll.html?session=YOUR_SESSION&password=YOUR_PASSWORD&server2

กลายเป็นที่อยู่นี้สำหรับสำเนาการสำรวจความคิดเห็นที่ดาวน์โหลดบน Windows:

file:///C:/SSN/social_stream-beta/my-poll.html?session=YOUR_SESSION&password=YOUR_PASSWORD&server2

ใช้ที่อยู่ไฟล์จริงของคุณและการตั้งค่าที่คัดลอกไว้ บน macOS ที่อยู่เริ่มต้นด้วย file:///Users/...; บน Linux มักจะขึ้นต้นด้วย file:///home/.... การคัดลอกที่อยู่เบราว์เซอร์จะจัดการช่องว่างและเครื่องหมายทับสำหรับคุณ

ตั้งค่านี้เพียงครั้งเดียว OBS บันทึกที่อยู่พร้อมกับแหล่งที่มา เก็บโฟลเดอร์ที่ดาวน์โหลดไว้ในที่เดิม และให้ SSN และแหล่งแชทของคุณทำงานเมื่อใช้โอเวอร์เลย์ หลังจากบันทึกการเปลี่ยนแปลงการออกแบบแล้ว ให้ใช้ รีเฟรชแคชของหน้าปัจจุบัน (Refresh cache of current page) ในคุณสมบัติของแหล่งที่มา

เหตุใดจึงไม่เลือกไฟล์ในเครื่อง? ช่อง URL ให้คุณใส่ได้ ?session=.... การเลือก HTML ด้วยตัวเลือกไฟล์เพียงอย่างเดียวไม่ได้เพิ่มการตั้งค่าเหล่านั้น

ทางเลือก: ใช้ช่องทำเครื่องหมายไฟล์ในเครื่องด้วยตัวเรียกใช้งาน

ตัวเลือกไฟล์ของ OBS เลือกไฟล์ มันไม่ได้เพิ่มการตั้งค่าแบบสอบถามที่คุณสร้างขึ้น สำหรับตัวรับตามการสืบค้นที่ยังไม่ได้แก้ไข ตัวเรียกใช้งานท้องถิ่นขนาดเล็กสามารถนำทางไปยังหน้าที่แก้ไขพร้อมการตั้งค่าที่แนบมาด้วย:

  1. บันทึกสิ่งต่อไปนี้เป็น launch-my-poll.html ข้าง my-poll.html.
  2. แทนที่ตัวยึดตำแหน่ง URL ที่โฮสต์ด้วยลิงก์ SSN ที่คุณคัดลอกไว้ทั้งหมด เปลี่ยน ./my-poll.html เป็นชื่อไฟล์ที่คุณแก้ไขจริง เก็บลิงก์ไว้ในเครื่องหมายคำพูดแบบธรรมดา & อักขระ
  3. ดับเบิลคลิกตัวเรียกใช้งานเพื่อทดสอบ ใน OBS ให้เลือก ไฟล์ในเครื่อง (Local file) และเลือก ตัวเรียกใช้งาน. มันเปลี่ยนเส้นทางไปยังการซ้อนทับในตัวเครื่องพร้อมกับแบบสอบถามและส่วนย่อย
<!DOCTYPE html>
<html lang="en">
<meta charset="utf-8">
<title>My local overlay launcher</title>
<p>Opening the local overlay...</p>
<script>
var copiedLink = new URL("https://socialstream.ninja/poll.html?session=YOUR_SESSION");
var localPage = new URL("./my-poll.html", window.location.href);
localPage.search = copiedLink.search;
localPage.hash = copiedLink.hash;
window.location.replace(localPage.href);
</script>
</html>

สำหรับธีมที่ซ้อนกัน ให้วาง Launcher ไว้ข้างสำเนาธีมนั้น เก็บตัวเรียกใช้งานให้เป็นส่วนตัวเนื่องจากมีลิงก์การเชื่อมต่อของคุณ การส่งออกที่มีในตัวเองที่ดาวน์โหลดซึ่งฝังการกำหนดค่าไว้แล้วจะทำตามคำแนะนำในการส่งออกของตัวเองแทน

OBS บันทึกโหมดไฟล์/URL, ขนาด, CSS ที่กำหนดเอง และการควบคุมการรีเฟรชในรูปแบบ การอ้างอิงแหล่งที่มาของเบราว์เซอร์.

4. เปลี่ยนการออกแบบหรือขอให้ AI ทำ

สำหรับการเปลี่ยนแปลงเฉพาะ CSS ให้เก็บลิงก์ที่โฮสต์ไว้และใช้ OBS CSS แบบกำหนดเอง สนาม. โดยจะใช้กับแหล่งที่มานั้นเท่านั้น ดังนั้นเบราว์เซอร์ปกติที่เปิด URL เดียวกันจะไม่แสดงการแทนที่เหล่านั้น สำหรับไฟล์ HTML ที่แก้ไข ให้เพิ่มการแทนที่ต่อท้ายสไตล์ที่มีอยู่ หรือลิงก์สไตล์ชีทในเครื่องหลังจากนั้น ระบุโลโก้ ไฟล์แบบอักษร สีของแบรนด์ ขนาดแคนวาส และภาพอ้างอิง

รองรับบางหน้า &css= หรือ &b64css=; การสนับสนุนเป็นต่อหน้า poll.htmlเช่น อ่านทั้งสองอย่าง ตรวจสอบ parser ของเพจก่อนใช้ตัวเลือก URL โดยทั่วไปเว็บเพจไม่สามารถโหลดแบบอักษรหรือรูปภาพที่กำหนดเองจากดิสก์ภายในเครื่องของคอมพิวเตอร์เครื่องอื่นได้

เมื่อเปลี่ยนมาร์กอัป ให้คงรหัส/คลาสที่อ้างอิงโดยสคริปต์ไว้ หาก JavaScript สร้างองค์ประกอบใหม่ในการอัพเดตแต่ละครั้ง อาร์ตเวิร์กถาวรจะต้องอยู่นอกองค์ประกอบนั้นหรือสร้างขึ้นใหม่โดยตัวเรนเดอร์ คัดลอกสไตล์ชีท/สคริปต์ที่ใช้ร่วมกัน และเปลี่ยนการอ้างอิงเพจของคุณ หากคุณต้องการให้การแก้ไขมีผลกับการออกแบบของคุณเท่านั้น

ใช้พรอมต์เฉพาะประเภทในคำแนะนำด้านบน หรือเริ่มต้นด้วยพรอมต์ทั่วไปนี้:

คู่มือประเภทอธิบายถึงตัวกระตุ้นที่แท้จริงในการอนุรักษ์ ไม่ยอมรับการออกแบบที่ใช้งานได้เพียงเพราะเป็นฮาร์ดโค้ดข้อความตัวอย่าง เก็บสำเนาของไฟล์ต้นฉบับและเปรียบเทียบการแสดงผลที่แก้ไขโดยใช้อินพุตทดสอบเดียวกัน

5. ป้องกันไม่ให้แชทเข้ามากลายเป็นรหัส

ข้อความ ชื่อ ชื่อเรื่อง จำนวน ข้อมูลเมตา และลิงก์สื่อสามารถมาจากผู้ชมหรือบริการภายนอก ฆ่าเชื้อ ณ จุดที่ตัวเรนเดอร์แบบกำหนดเองแทรกเข้าไป สตริงที่ได้รับผ่าน SSN ไม่ได้รับอนุญาตให้ดำเนินการ ใช้ข้อความ DOM ธรรมดาสำหรับฟิลด์ธรรมดา ใช้เจลทำความสะอาดแบบแพ็กเกจสำหรับ HTML ที่รองรับเนื้อหาข้อความ ดูสิ คำอธิบายของ OWASP เกี่ยวกับอ่างล้างมือที่ปลอดภัยและการฆ่าเชื้อ HTML.

ใน SSN textonly ใช้กับเท่านั้น chatmessage. เมื่อเป็นจริง ให้แสดงส่วนเนื้อหานั้นเป็นข้อความตามตัวอักษร มิฉะนั้นอาจมีอิโมติคอนและการจัดรูปแบบที่อนุญาต แสดงฟิลด์ปกติอื่น ๆ เป็นข้อความ สาขาสื่อเช่น chatimg และ contentimg คือ URL/ข้อมูล ไม่ใช่ข้อมูลโค้ด HTML

<!-- Example for a copied page at the repository root. -->
<script src="./libs/objects.js"></script>
<script src="./shared/utils/chatHtml.js"></script>
<script>
function renderChatBody(element, data) {
    var message = String(data.chatmessage == null ? "" : data.chatmessage);
    if (data.textonly) {
        element.textContent = message;
    } else {
        element.innerHTML = SocialStreamChatHTML.sanitize(message);
    }
}
// Names, amounts, titles, and other plain fields use textContent:
// nameElement.textContent = String(data.chatname || "");
</script>

ใช้น้ำยาฆ่าเชื้อที่เทียบเท่าที่มีอยู่เดิม แทนที่จะเพิ่มอันที่สอง สำหรับไฟล์ที่ซ้อนกัน ให้ปรับเส้นทางสคริปต์แบบสัมพันธ์ สร้างอวตารและลิงก์ด้วยคุณสมบัติ DOM หลังจากตรวจสอบ URL ภายใต้นโยบายสื่อ/ลิงก์ที่มีอยู่ของเพจ อย่าสอดแทรกชื่อดิบลงในสตริงแอตทริบิวต์หรือสีดิบลงในมาร์กอัปสไตล์ ตรวจสอบสไตล์ก่อนตั้งค่าคุณสมบัติแต่ละรายการ การทำความสะอาด HTML ไม่ได้ทำให้สตริงปลอดภัยในการรันเป็น JavaScript หรือคำสั่ง AI

ทดสอบตัวเรนเดอร์ในการดูตัวอย่างแบบแยกส่วน

  • ใช้ชื่อธรรมดา เช่น Guest <b>One</b>: วงเล็บควรยังคงเป็นข้อความ
  • ลอง chatmessage: "<b>Hello</b>" พร้อม textonly: trueจากนั้นเป็นเท็จ มาร์กอัปตามตัวอักษรและเนื้อหาที่จัดรูปแบบที่อนุญาตควรใช้เส้นทางที่เกี่ยวข้อง
  • ตรวจสอบอิโมติคอนที่รองรับและข้อความเฉพาะรูปภาพ เพื่อให้การเปลี่ยนแปลงด้านความปลอดภัยไม่ลบคุณสมบัติเหล่านั้น
  • ให้ AI ทดสอบโพรบที่ไม่เป็นอันตราย เช่น <img src=x onerror="window.__ssnInjectionProbe=1"> ในตัวเรนเดอร์ที่เปลี่ยนแปลง จะต้องไม่ดำเนินการ ตั้งค่าเครื่องหมาย หรือปล่อยให้แอตทริบิวต์ของเหตุการณ์ที่ปฏิบัติการได้ ทดสอบลิงก์โครงร่างสคริปต์ด้วย ดำเนินการตรวจสอบในพื้นที่ ไม่ใช่ในการแชทสาธารณะ

โพรบที่ผ่านจะตรวจสอบเฉพาะเส้นทางที่ออกกำลังกายเท่านั้น ให้การทดสอบมุ่งเน้นไปที่ตัวเรนเดอร์และฟิลด์ที่เปลี่ยนแปลงตามการออกแบบ

6. ทดสอบโครงร่าง การเชื่อมต่อ และ OBS แยกกัน

  1. เค้าโครง: ใช้โหมดแสดงตัวอย่าง/สาธิตที่จัดทำเป็นเอกสารของหน้า หากมี หรือตัวอย่างในพื้นที่ที่สมมติขึ้น ทดสอบชื่อ/ข้อความที่ยาว รูปประจำตัวที่หายไป ข้อมูลว่าง และจำนวนแถวที่คาดหวัง
  2. การส่งมอบ SSN: ให้ SSN ทำงานและใช้งานต่อไป สร้างข้อความทดสอบ ด้วยเซสชันเดียวกัน ความต้องการโหมดการนำเข้า Extension API ตามปกติ การควบคุมส่วนขยายจากระยะไกลผ่าน API เปิดใช้งานแล้ว ใช้การตั้งค่าการทดสอบแบบแยกส่วน การทดสอบที่ส่งสามารถทริกเกอร์ระบบอัตโนมัติที่กำหนดค่าไว้ได้
  3. ตัวกระตุ้นที่แท้จริง: นำเสนอข้อความ Dock สำหรับการ์ดแนะนำ ส่งการโหวตแบบสำรวจสำหรับการสำรวจ เลือกผู้ชนะสำหรับการแจกของรางวัล เปลี่ยนข้อความในสัญลักษณ์สำหรับสัญลักษณ์ หรือเริ่มจับเวลาสำหรับตัวจับเวลา การแชทธรรมดาไม่ใช่การทดสอบสากล
  4. การจับจริง: ยืนยันว่าข้อความ/เหตุการณ์ต้นฉบับไปถึงหน้าต้นฉบับและหน้าแก้ไข เหตุการณ์จำลองพิสูจน์การแสดงผล ไม่ใช่การจับภาพแพลตฟอร์ม
  5. OBS: ตรวจสอบแหล่งที่มาในขนาดสุดท้าย ความโปร่งใส ภาพเคลื่อนไหว เสียง แบบอักษร และเลเยอร์ การออกกำลังกาย แสดง/ซ่อน ล้าง/รีเซ็ต และรีเฟรช เบราว์เซอร์และ OBS มีพื้นที่เก็บข้อมูลและเซสชันแยกกัน การเข้าสู่ระบบเบราว์เซอร์หรือ localStorage จะไม่ถูกแชร์โดยอัตโนมัติ

สำหรับเพจที่รวบรวมข้อมูลในหน่วยความจำ การยกเลิกการโหลดหรือการรีเฟรชอาจสูญเสียสถานะ ตรวจสอบคำแนะนำประเภทก่อนเปิดใช้งานการรีเฟรชหรือปิดเครื่องอัตโนมัติเมื่อซ่อน จอแสดงผลที่โฮสต์จัดการมีพฤติกรรมการกู้คืนที่แตกต่างกัน ลบ demo/preview ตั้งค่าสถานะก่อนที่จะคาดหวังข้อมูลสด

ไฟล์และข้อมูลอ้างอิงที่เป็นประโยชน์เพื่อให้ AI ของคุณ

  • docs/event-reference.html: ช่องมาตรฐาน เหตุการณ์ที่มีชื่อ ข้อมูลเมตา สื่อ และมูลค่าการบริจาค
  • docs/customoverlays.md: ตัวรับแบบกำหนดเองและตัวอย่างการเชื่อมต่อ
  • ความเข้ากันได้ของอีเวนต์และการแจ้งเตือน: เหตุการณ์/ฟิลด์ใดที่การออกแบบสามารถคาดหวังได้จากแหล่งที่มา
  • คำแนะนำข้อความทดสอบ และ createtestmessage.html: น้ำหนักบรรทุกตัวอย่างและโหมดการจัดส่ง
  • libs/objects.js และ shared/utils/chatHtml.js: การฆ่าเชื้อจอแสดงผลแบบบรรจุภัณฑ์
  • shared/utils/chatBadges.js และ shared/utils/contentImage.js: การจัดการตราและรูปภาพที่มีอยู่
  • js/transport-dedupe.js, js/local-server-url.js, และ shared/overlay-control-transport.js: รองรับการขนส่งที่มีอยู่เมื่อโหลดโดยเพจของคุณ
  • currency.js: เก็บรักษา hasDonation สำหรับแสดงและให้เกียรติ USD ที่เป็นตัวเลขที่ถูกต้อง donoValueรวมทั้งศูนย์
  • Event Flow และ คำสั่งและ API: นำการควบคุมที่มีอยู่กลับมาใช้ใหม่เมื่อการออกแบบจำเป็นต้องมีทริกเกอร์

ให้แหล่งที่มาของการซ้อนทับจริงและ CSS/JS ที่อ้างอิง รวมถึงเอกสารเหล่านี้ การอ้างอิงเหตุการณ์เพียงอย่างเดียวไม่ได้อธิบายสถานะการควบคุมของการสำรวจความคิดเห็นหรือโครงสร้างการเรนเดอร์ส่วนตัวของโอเวอร์เลย์ทุกรายการ

แผนที่อ่านไฟล์ JSON ในเครื่องด้วย fetch()ซึ่งเบราว์เซอร์สามารถบล็อกเมื่อเปิดจากดิสก์ สำหรับการปรับรูปแบบแผนที่แบบง่ายๆ ให้ใช้ลิงก์ที่โฮสต์กับ CSS แบบกำหนดเองของ OBS สำหรับสำเนา HTML ที่แก้ไขแล้ว ขอให้ AI ของคุณรวมข้อมูลแผนที่ที่จำเป็นในหน้าเพื่อเปิดจากดิสก์โดยตรง โฮสติ้งเป็นตัวเลือกขั้นสูงสำหรับเพจที่ต้องการมันโดยเฉพาะ ไม่ใช่ขั้นตอนการตั้งค่าปกติสำหรับโอเวอร์เลย์เหล่านี้

หยุดที่ปัญหาที่ได้รับการยืนยันน้อยที่สุด การปรับเปลี่ยนไม่ควรต้องเปลี่ยนสคริปต์จับภาพหรือสร้างฟิลด์เหตุการณ์ใหม่ หากแชร์การ Fork สาธารณะ ให้รวมเนื้อหาที่สนับสนุนและป้องกันไม่ให้ Launcher ส่วนตัวอัปโหลดนั้น
