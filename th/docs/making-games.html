สร้างเกมและรางวัล

เปลี่ยนของขวัญ ยอดสนับสนุน หรือคำสั่งแชตให้เป็นสิ่งที่เกิดขึ้นในไลฟ์

ใช่ เกมของคุณตอบสนองต่อของขวัญ TikTok ได้แม่แบบเล็ก ๆ ที่แก้ไขได้สามแบบเชื่อมแม่แบบกับไลฟ์ปรับแต่งการออกแบบเกมและรันในเครื่องเลือกจำนวนเหรียญสำหรับการกระทำอย่างไร?แต่ละแพลตฟอร์มส่งอะไรลองก่อนเชื่อมกับการกระทำแบบเสียเงิน

ใช่ เกมของคุณตอบสนองต่อของขวัญ TikTok ได้

Social Stream Ninja รับเหตุการณ์แล้วส่งให้หน้าเว็บ JavaScript ของคุณเลือกว่าจะเร่งจรวด ปลูกสวน สร้างศัตรู หรือเพิ่มความคืบหน้าเป้าหมายร่วม คุณกำหนดการกระทำและเกณฑ์ในเกม SSN ไม่สามารถเปลี่ยนราคาของขวัญของแพลตฟอร์มได้

เริ่มที่นี่: ลองแม่แบบทั้งสามจากนั้นเลือกว่ากฎจะใช้ หน่วยแพลตฟอร์ม ตัวระบุของขวัญ หรือ USD โดยประมาณ.

สำหรับการออกแบบภาพใหม่ โปรดดู ปรับแต่งเกมและรันในเครื่อง.

สำหรับเสียง การแจ้งเตือน การสั่ง OBS หรือ webhook ให้เริ่มที่ Event Flowหน้า HTML ที่ปรับเองเหมาะกับกระดานเกมหรือสถานะเกมของคุณ ส่วนเกมสำเร็จรูปดูได้ที่ แกลเลอรีเกม.

แม่แบบเล็ก ๆ ที่แก้ไขได้สามแบบ

ตัวอย่างแต่ละหน้ามีปุ่มจำลองและตัวตรวจข้อมูลล่าสุดที่รับมา ข้อมูลเป็นเหตุการณ์สมมติ ไม่ใช่การซื้อ โหมดตัวอย่างไม่เข้าร่วมเซสชันไลฟ์ของคุณ

  • จรวดเหรียญ: 10 เหรียญ TikTok, 100 Bits ของ Twitch หรือ 100 Stars ของ Facebook ทำให้เร่งหนึ่งครั้ง ยอดที่เหลือสะสมแยกตามผู้ชมและแพลตฟอร์ม แก้ไข COST ใน HTML เพื่อกำหนดยอด
  • เป้าหมายการสนับสนุนร่วมกัน: รวมยอดสนับสนุน USD โดยประมาณจากสี่แพลตฟอร์มเพื่อสร้างฐานดวงจันทร์ แก้ไข GOAL_USD หรือเปลี่ยนตัวแสดงความคืบหน้าเป็นความเสียหาย เชื้อเพลิง หรือตัวจับเวลา
  • สวนของขวัญและเหตุการณ์: ของขวัญ TikTok ที่เลือกเพิ่มดอกไม้ การติดตามที่รับได้เพิ่มต้นไม้ และคำสั่งฟรี !water ในแชตเพิ่มน้ำ ตั้งค่า GIFT_ID ให้เป็น ID ที่รับมา หรือกำหนด GIFT_NAME ให้ตรงกับชื่อจริง “Demo flower” เป็นตัวอย่างสมมติ

เปิดซอร์ส HTML แล้วหา EDIT THIS RULE หรือ EDIT THESE RULESโดย receive(data) คือฟังก์ชันที่เปลี่ยนการกระทำตัวอย่างเป็นตรรกะเกม ฟังก์ชันช่วยเชื่อมต่อและนับอยู่ใน starter.jsส่วนรูปแบบภาพอยู่ใน starter.css.

เชื่อมแม่แบบกับไลฟ์

  1. เปิด SSN และเชื่อมแหล่งแชต ยืนยันว่าแชตและแถวของขวัญ/การสนับสนุนถึง dock การตั้งค่า TikTok ดู โหมดการเชื่อมต่อ.
  2. เปิดแม่แบบโดยไม่มี ?demoโดยระบุ ID เซสชัน SSN และรหัสผ่านเซสชันหากตั้งไว้
  3. ตรวจหน้าในเบราว์เซอร์แล้วเพิ่ม URL เดียวกันเป็น Browser Source ใน OBS เช่น ขนาด 1000 × 800 เพิ่ม &clean เพื่อซ่อนตัวตรวจข้อมูล สถานะการเชื่อมต่อ และปุ่มผู้จัด
https://socialstream.ninja/games/templates/coin-rocket.html?session=YOUR_SESSION&password=YOUR_PASSWORD&clean

หากใช้เว็บไซต์ beta ให้คง /beta/ ไว้ก่อน games/หากไม่ได้ตั้งรหัสผ่านให้ละพารามิเตอร์นั้น และเก็บลิงก์เซสชันเป็นส่วนตัว

การเชื่อมต่อเริ่มต้นใช้สะพาน iframe เหมือนโอเวอร์เลย์ SSN หากต้องการเส้นทางแชตที่รับผ่าน WebSocket แบบโฮสต์ ให้เปิดการตั้งค่า SSN ส่งข้อความจากส่วนขยายไปยังแผงด็อกผ่านเซิร์ฟเวอร์ แล้วเพิ่ม &server2 ดู คู่มือ WebSocket สำหรับการตั้งค่าภายใน แม่แบบยังรับ &server2&localserver และ &localserverport=3000. localserver เพียงอย่างเดียวไม่เปิดเส้นทาง ส่วนแบบเก่า server ใช้ช่องทางต่างกัน และอาจต้องมี dock เผยแพร่ไปยังช่องนั้น

สร้างสำเนาของคุณ

ดาวน์โหลดซอร์ส beta แบบ ZIP และแตกไฟล์ แก้ไขไฟล์ใน games/templates/โดยคงโครงสร้างโฟลเดอร์ไว้ เพราะแม่แบบยังโหลด js/local-server-url.jsส่วนเป้าหมายการสนับสนุนโหลด currency.js จากรากของคลังโค้ด

ลาก HTML เริ่มต้นไปที่ Chrome หรือ Edge แล้วคัดลอก file:/// ที่อยู่ เพิ่มทุกอย่างจาก ? เป็นต้นไปในลิงก์เกม SSN ที่ทำงานของคุณ รวมถึงเซสชันและรหัสผ่านใด ๆ ของคุณ เปิดที่อยู่นั้นในเบราว์เซอร์ของคุณ จากนั้นวางลงในแหล่งเบราว์เซอร์ OBS URL สนามด้วย ไฟล์ในเครื่อง (Local file) ไม่ได้เลือก OBS บันทึกที่อยู่นี้สำหรับครั้งต่อไป

file:///C:/SSN/social_stream-beta/games/templates/coin-rocket.html?session=YOUR_SESSION&clean

ใช้เส้นทางจริงบนคอมพิวเตอร์ของคุณ เก็บโฟลเดอร์ที่แยกออกมาไว้ในที่เดียวกัน ไม่มีเซิร์ฟเวอร์ที่จะติดตั้งหรือเริ่มต้น ดู คู่มือการตั้งค่าไฟล์ สำหรับตัวอย่างเพิ่มเติม

ปรับแต่งการออกแบบเกมและรันในเครื่อง

ใช้สามตัวเริ่มต้นด้านบนสำหรับเกมใหม่ หรือคัดลอกหน้าที่คุณใช้ games/. games.html และ battle.html ยังมีพฤติกรรมการเล่นเกมของตัวเอง; ค่าคงที่กฎของการเริ่มต้นไม่ใช่ API ของเกมสากล

ดาวน์โหลด ZIP ต้นทางแยกออกมา และทำซ้ำ HTML ที่เลือกข้างต้นฉบับ เช่น เก็บ my-rocket.html ใน games/templates/, พร้อม starter.js, starter.css, รูท js/ ผู้ช่วย และรูปภาพหรือเสียงอ้างอิงใดๆ ที่มีอยู่ มอบไฟล์เหล่านั้นให้กับ AI และ docs/event-reference.html.

เปิดสำเนาของคุณโดยตรงจากดิสก์โดยใช้ ขั้นตอนการตั้งค่าไฟล์. ที่อยู่ตัวอย่างสำหรับผู้เริ่มต้นที่แก้ไขคือ:

file:///C:/SSN/social_stream-beta/games/templates/my-rocket.html?session=YOUR_SESSION&clean

ใช้เซสชัน รหัสผ่าน และตัวเลือกการขนส่งของลิงก์ที่สร้างขึ้นจริง ลบ demo สำหรับอินพุตสด; เก็บไว้ clean บนสตาร์ทเตอร์เหล่านี้เพื่อซ่อนเครื่องมือของผู้ปฏิบัติงาน เซสชันนี้เป็น ID การเชื่อมต่อ SSN ไม่ใช่ชื่อเกม เก็บ SSN ไว้และจับภาพทำงาน

ใน OBS ให้ออกไป ไฟล์ในเครื่อง (Local file) ยกเลิกการเลือกและวางที่อยู่ไฟล์แบบเต็มของคุณลงในแหล่งที่มาของเบราว์เซอร์ URL สนาม. หลังจากบันทึกการเปลี่ยนแปลงการออกแบบ ให้รีเฟรชแหล่งที่มาเพื่อโหลด

เลือกจำนวนเหรียญสำหรับการกระทำอย่างไร?

เลือกสิ่งที่จะวัดก่อนเลือกตัวเลข:

กฎอ่านตัวอย่าง
หน่วยของแพลตฟอร์มTikTok meta.coinsPerGift × meta.tiktokGiftCount เมื่อมี หรือค่าที่ระบุชัดเจนใน hasDonation ด้วยป้าย เช่น 10 coins, 100 bits, หรือ 100 Stars.ทุก 10 เหรียญเร่งได้หนึ่งครั้ง
ของขวัญที่เจาะจงTikTok meta.giftId หรือ meta.giftNameพร้อมจำนวนของขวัญที่ตรงกันแต่ละชิ้นเพิ่มดอกไม้หนึ่งดอก ไม่ขึ้นกับมูลค่า USD โดยประมาณ
มูลค่าการสนับสนุนที่เปรียบเทียบกันได้getDonationValueUSD(data) จาก currency.js.ทุก 1 ดอลลาร์โดยประมาณเพิ่มเชื้อเพลิง 10 หน่วย และ 25 ดอลลาร์ทำให้เป้าหมายสำเร็จ
การกระทำฟรีหรือสมาชิกค่าจริงที่แหล่งส่งมาใน eventหรือคำสั่งแชตการติดตามปลูกต้นไม้ ส่วนการสมัครสมาชิกแบบเสียเงินใหม่เล่นภาพเคลื่อนไหว

ตัดสินใจว่าจำนวนของคุณหมายถึง ตรงกันพอดี (coins === 10), ขั้นต่ำต่อเหตุการณ์ (coins >= 10), หรือ ยอดสะสมจรวดใช้ยอดสะสม เช่น 25 เหรียญเร่งได้สองครั้งและเหลือห้าเหรียญ กฎที่รับเฉพาะ 10 เหรียญพอดีจะข้าม 25 เหรียญ หากให้แต่ละเหตุการณ์เลือกได้เพียงหนึ่งการกระทำ ให้ตรวจเกณฑ์สูงสุดก่อนเพื่อไม่ให้ทุกระดับที่ต่ำกว่าทำงานด้วย

ใน TikTok ผู้ชมซื้อเหรียญแล้วใช้กับของขวัญที่แสดงราคาเป็นเหรียญ เลือกของขวัญที่มีใน LIVE ของคุณและตรวจข้อมูลก่อนเผยแพร่กฎ ชื่อของขวัญ จำนวนชิ้น เหรียญ และเพชรเป็นคนละมาตรวัด อย่าหารค่าประมาณ USD เพื่อหา “เหรียญที่แน่นอน” หรือถือว่าจำนวนเพชรเป็นเหรียญ คำอธิบายเหรียญและของขวัญของ TikTok.

หากรับได้เพียงชื่อ/จำนวนของขวัญหรือป้ายเพชร แม่แบบเหรียญจะข้ามเหตุการณ์ถ้าไม่มีข้อมูลกำกับเหรียญที่ชัดเจน ใช้กฎระบุของขวัญหรือแม่แบบ USD โดยประมาณแทน ข้อมูลเหรียญอาจมาจากตารางของขวัญของ SSN ด้วย หากต้องการราคาที่แน่นอนให้เทียบกับถาดของขวัญ LIVE ปัจจุบัน รายการและวิธีรับข้อมูลต่างกัน จึงไม่มีฟิลด์เหรียญสากลที่รับประกันในทุกข้อความ TikTok

แต่ละแพลตฟอร์มส่งอะไร

type ระบุแหล่งข้อมูล; event ระบุการกระทำเมื่อมีฟิลด์นี้ ความพร้อมขึ้นกับโหมดรับข้อมูล การตั้งค่า และสิ่งที่แพลตฟอร์มเปิดเผย ตัวอย่างอธิบายโค้ดปัจจุบันของ SSN ไม่รับประกันทุกเหตุการณ์สำหรับทุกบัญชี

แพลตฟอร์มข้อมูลการสนับสนุนและเหตุการณ์แยกให้ออก
TikToktype: "tiktok", event: "gift"การรับข้อมูลบริจาคอาจให้ค่า hasDonation และ donoValueข้อมูลกำกับอาจมี ID ชื่อ จำนวน เหรียญหรือเพชรต่อของขวัญ และ ID ของชุดส่งต่อเนื่องเหรียญใช้ซื้อของขวัญ ส่วนเพชรเป็นรางวัลของครีเอเตอร์ การรับข้อมูล WebSocket ของ SSApp จะสรุปชุดส่งต่อเนื่องก่อนส่งต่อ แต่เบราว์เซอร์อาจส่งยอดสะสมหลายครั้ง เมื่อปิดการรับข้อมูลบริจาค TikTok เหตุการณ์ของขวัญอาจไม่มีฟิลด์เงิน
TwitchCheers ใช้ Bits เช่น hasDonation: "100 bits"การรับข้อมูลผ่าน API อาจใช้ event: "cheer" และ donoValue: 1การรับแชตจากหน้าที่แสดงผลอาจไม่มีตัวระบุเหตุการณ์การสมัครสมาชิก สมาชิกที่มอบให้ การเรด และแต้มช่องเป็นคนละการกระทำ ป้ายสมาชิกบนข้อความปกติไม่ใช่การสมัครใหม่ Cheers โดยตรงกับ Bits ที่ใช้ในส่วนขยาย Twitch เป็นคนละการเชื่อมต่อ
Facebookแถว Stars ใน Live Chat ที่มองเห็นได้จะให้ข้อมูล เช่น hasDonation: "100 Stars" และ donoValue: 1โดยไม่มี event เป็นตัวระบุAPI ความคิดเห็นไม่อนุมาน Stars จากข้อความ การรับผ่าน DOM ต้องมีแถว Stars ที่มองเห็นได้ ความคิดเห็นและปฏิกิริยาทั่วไปไม่ได้ระบุยอดชำระ
YouTubesuperchat และ supersticker เก็บยอดในสกุลเงินเดิมไว้ใน hasDonationของขวัญใช้ jeweldonation พร้อม N Jewels, หรือ 1 YouTube Gift เมื่อซ่อนยอดเงินผู้ชมใช้ Jewels ซื้อ Gifts ส่วนครีเอเตอร์ได้ Rubies สมาชิกและสมาชิกที่มอบให้เป็นเหตุการณ์แยก ไม่ใช่ Jewels ส่วน Super Thanks เป็นอีกผลิตภัณฑ์ ไม่รับประกันเหตุการณ์บริจาคในแชตสด

แหล่งอ้างอิงของแพลตฟอร์ม: เพชร TikTok; Bits และการสมัครสมาชิก Twitch; ภาพรวม Stars ของ Meta; YouTube Super Chat และ Super Stickers; YouTube Jewels, Gifts และ Rubiesตรวจสอบคำศัพท์เมื่อ 29 กันยายน 2026 โปรดดูเงื่อนไขและความพร้อมใช้งานล่าสุดจากแพลตฟอร์ม

แหล่งอื่นอาจรายงานทิป ของขวัญ สมาชิก หรือการซื้อ ให้ตรวจ เอกสารอ้างอิงเหตุการณ์ ก่อนเพิ่มลงตัวกรองของแม่แบบ isSupport การขายสินค้าหรือมอบสมาชิกไม่ได้เป็นทิปโดยอัตโนมัติ เช่น YouTube แยกการซื้อของขวัญจากการแจ้งผู้รับใช้สิทธิ์ การนับทั้งสองจะให้รางวัลของขวัญเดียวกันสองครั้ง

ใช้ donoValue และ currency.js อย่างถูกต้อง

hasDonation คือป้ายแสดงผลเดิม เช่น €5.00 หรือ 100 bits. donoValue คือยอด USD แบบตัวเลขที่แหล่งอาจระบุมา ให้ใช้ค่าที่ถูกต้องรวมถึงศูนย์ก่อนประมาณจากป้าย และเก็บป้ายเดิมสำหรับแสดงผล

<script src="../../currency.js"></script>
<script>
// From games/templates/: use the existing helper, including its zero handling.
var usd = getDonationValueUSD(data);
// Use usd for your rule; display data.hasDonation for the original amount/unit.
</script>

พฤติกรรมการแปลงที่มีอยู่: ขณะนี้ SSN ประเมินหนึ่งเหรียญ TikTok เป็น 0.01 USD หนึ่งเพชรเป็น 0.005 USD หนึ่ง Twitch Bit หรือ Facebook Star เป็น 0.01 USD และหนึ่ง YouTube Jewel เป็น 0.005 USD ของขวัญ TikTok ที่ไม่ทราบราคาใช้ค่าเริ่มต้นหนึ่งเหรียญต่อชิ้น ส่วนของขวัญ YouTube ที่ไม่มีจำนวน Jewels ใช้ค่าชั่วคราว 0.01 USD ของตนเอง การแปลงสกุลเงินใช้เรตประมาณภายใน ไม่ใช่บริการอัตราแลกเปลี่ยนสด

ตัวเลขเหล่านี้เป็นค่าเปรียบเทียบของ SSN ไม่ใช่นิยามร่วมของเงินที่ผู้ชมใช้ รายได้สุทธิของครีเอเตอร์ หรือยอดถอน วิธีรับต่างกันอาจให้ค่าประมาณต่างกัน โดยเฉพาะค่าแทนหนึ่งเหรียญสำหรับของขวัญ TikTok ที่ไม่รู้จักไม่ได้พิสูจน์ราคาจริง

อย่าใช้ donoValue || convertToUSD(...): เพราะจะทิ้งค่าศูนย์ที่ตั้งใจระบุ อย่าดึงตัวเลขจาก chatmessage เพื่อตรวจการจ่ายเงิน หรือบังคับว่าต้องมี event === "donation": Stars ของ Facebook และ Cheers บางรายการไม่มีตัวระบุเหตุการณ์ แม่แบบเป้าหมายคัดประเภทการสนับสนุนก่อนเรียกตัวแปลงร่วม

ซอร์ส: currency.js และ เอกสารอ้างอิงข้อมูลข้อมูลกำกับของขวัญเป็นข้อมูลเสริม ตัวอย่างจะไม่สร้างฟิลด์ที่ไม่มีในข้อมูลที่รับมา

นับชุดของขวัญเพียงครั้งเดียว

TikTok อาจรายงานยอดสะสม 1, 2, 3 ของชุดเดียวกัน นั่นคือสามชิ้น ไม่ใช่หกชิ้น สำหรับการบวก ให้จำจำนวนหรือยอดสูงสุดที่เคยรับและเพิ่มเฉพาะส่วนต่าง การแจ้งจบที่มียอดเท่าเดิมไม่เพิ่มอะไร

// All three events refer to the same streak:
// incoming total: 1, 2, 3, 3
// added to game:  1, 1, 1, 0
var newCoins = RewardStarter.increment(data, RewardStarter.coins(data), 'coins');

ฟังก์ชันช่วยใช้ ID กลุ่ม/ผู้ส่ง/ของขวัญดั้งเดิมของ TikTok เมื่อมี จากนั้นใช้ meta.tiktokGiftStreakId หรือ ID ข้อความ ID ปกติยังป้องกันการส่งซ้ำ ฟังก์ชันไม่รอ repeatEnd เพราะการรับผ่านเบราว์เซอร์อาจไม่ส่งฟิลด์นี้เลย หากต้องการทำครั้งเดียวหลังจบชุด ต้องมีกฎจบชุดแยกโดยใช้ฟิลด์ที่การเชื่อมต่อส่งจริง

แม่แบบเพื่อการเรียนรู้จำ ID ได้สูงสุด 2,000 รายการในหน่วยความจำ การรีเซ็ตหรือโหลดใหม่ลบความจำและความคืบหน้า ข้อความที่ไม่มี ID คงที่ไม่สามารถตัดซ้ำได้อย่างเชื่อถือได้ และการรับช่องเดียวกันอีกทางอาจใช้ ID ต่างกัน เริ่มด้วยเส้นทางเดียว จรวดแบ่งยอดตามแพลตฟอร์มและ ID ผู้ใช้ หากไม่มี ID จะใช้ชื่อแสดงผล ทำให้ชื่อซ้ำอาจใช้ยอดร่วมกัน เกมที่ต้องบันทึกถาวรควรเพิ่มการเก็บสถานะและจัดการการส่งซ้ำก่อนพึ่งพาการเก็บรางวัลแบบเสียเงินหลังเริ่มใหม่

ให้รางวัลโดยไม่ต้องสร้างเกมเอง

ใน Event Flow ให้ใช้ เปรียบเทียบคุณสมบัติ พร้อม donoValue, มากกว่าหรือเท่ากับและเกณฑ์ USD จากนั้นเชื่อมกับเสียง ภาพเคลื่อนไหว หรือการควบคุม OBS การเปรียบเทียบจะใช้ค่าจากแหล่งข้อมูลก่อนเมื่อถูกต้อง และใช้การแปลงสกุลเงินที่มีอยู่เมื่อจำเป็น

สำหรับของขวัญ TikTok ที่เจาะจง ให้เปรียบเทียบ meta.giftId หรือ meta.giftNameและจำกัดโฟลว์ไว้เฉพาะเหตุการณ์ของขวัญ TikTok การเปรียบเทียบตัวเลขของ hasDonation ก็แปลงเป็น USD ไม่ใช่การเปรียบเทียบเหรียญดิบ ใช้ข้อมูลกำกับดั้งเดิมหรือโค้ดเองสำหรับกฎเหรียญ

เกณฑ์ต่อข้อความต่างจากยอดสะสมหรือตัวนับชุดของขวัญ อย่าถือว่าเกณฑ์ Event Flow จะสะสมและตัดข้อมูลซ้ำเหมือนแม่แบบโดยอัตโนมัติ ให้ใช้ โหนดสถานะ เมื่อโฟลว์ต้องเก็บสถานะ หรือเก็บตรรกะนี้ในเกม

ลองก่อนเชื่อมกับการกระทำแบบเสียเงิน

  1. ใช้ปุ่มตัวอย่าง ชุด 1 → 2 → 3 ต้องเพิ่มมูลค่าเพียงสามของขวัญ ตัวอย่างระบุศูนย์ต้องไม่เพิ่ม USD และราคาที่ไม่ทราบต้องไม่เพิ่มจำนวนเหรียญแบบแน่นอน
  2. เชื่อมแหล่งจริงและตรวจข้อมูลที่รับได้จริง ยืนยันชื่อ/ID ของขวัญ จำนวนเงิน/หน่วย จำนวน และเหตุการณ์ที่กฎต้องการ ตัวอย่างพิสูจน์การทำงานของกฎ ไม่ได้พิสูจน์การรับข้อมูลสดจากแพลตฟอร์ม
  3. ตรวจในฉาก OBS ทั้งเหตุการณ์ซ้ำ การเชื่อมต่อใหม่ และการโหลดใหม่ หลีกเลี่ยงการปิดหรือรีเฟรช Browser Source หากต้องรักษาความคืบหน้าในหน่วยความจำ

เกมที่ไม่มีผู้ดูแลหรือ AFK ต้องเปิด SSN การรับข้อมูลและหน้าเกมตลอดเวลา คอมพิวเตอร์หลับ การเข้าสู่ระบบหมดอายุ หรือการหลุดการเชื่อมต่อจะหยุดการกระทำ แม่แบบไม่ดึงเหตุการณ์ที่พลาดย้อนหลังหรือจัดการเงินคืน การตอบสนองอัตโนมัติไม่ได้ให้สิทธิ์สร้างรายได้จากไลฟ์ที่ไม่มีผู้ดูแล โปรดตรวจนโยบาย LIVE และการสร้างรายได้ปัจจุบันสำหรับรูปแบบของคุณ

หากไม่มีข้อมูลเข้ามา ให้ตรวจ dock ของ SSN ก่อน ตามด้วยเซสชัน/รหัสผ่านและการส่งข้อมูล หากแชตมาแต่ของขวัญไม่ตรง ให้ตรวจข้อมูลและตัวกรองบริจาค/เหตุการณ์ การติดตามและสมาชิกขึ้นกับแหล่งข้อมูล ดู เอกสารอ้างอิงเหตุการณ์รายละเอียดการเชื่อมต่อเพิ่มเติมดูที่ โอเวอร์เลย์ที่ปรับเอง.
