โหมดแอปแยก

เข้าใจหน้าต่างแหล่งข้อมูล โหมด Standard, WebSocket และพรีเซ็ต TikTok

แอปมีไว้เพื่ออะไรชื่อโหมดใช้โหมด Standard เมื่อใช้โหมด WebSocket หรือ API เมื่อTikTok ในแอปสิ่งที่ต้องตรวจก่อน OBSวิธีแก้ปัญหาที่พบบ่อย

แอปมีไว้เพื่ออะไร

แอปเดสก์ท็อปจัดการหน้าต่างแหล่ง Social Stream นอกเบราว์เซอร์ปกติ ช่วยจัดระเบียบแหล่งข้อมูลและแก้ปัญหาแท็บถูกลดการทำงานบางอย่างได้ แอปไม่เหมือน Chrome และไม่แชร์การลงชื่อเข้าใช้หรือคุกกี้ Chrome อัตโนมัติ

ชื่อโหมด

บางแหล่งข้อมูลมีโหมดเชื่อมต่อมากกว่าหนึ่งแบบ โหมดที่เหมาะขึ้นอยู่กับแพลตฟอร์ม สถานะลงชื่อเข้าใช้ และว่าต้องการเหตุการณ์ละเอียดขึ้นหรือแค่เก็บจากหน้าเว็บ

โหมดความหมายแบบง่ายใช้เมื่อ
Standardแอปเปิดหน้าแพลตฟอร์ม/แหล่งข้อมูลปกติและอ่านหน้าที่แสดงผลคุณต้องการวิธีง่ายที่สุดสำหรับเก็บจากหน้าที่มองเห็น ลงชื่อเข้าใช้ หรือยืนยันด้วยตนเอง
WebSocket/APIแหล่งข้อมูลเชื่อมผ่าน API แพลตฟอร์ม ซ็อกเก็ต หรือหน้าแหล่งข้อมูล Social Streamแพลตฟอร์มรองรับ และคุณต้องการให้เบื้องหลังเสถียรขึ้นหรือข้อมูลเหตุการณ์ละเอียดขึ้น
ดึงเป็นระยะ/แบบเก่า (Polling/Legacy)เส้นทางเพื่อความเข้ากันได้ที่ตรวจการอัปเดตเป็นระยะ แทนเส้นทางซ็อกเก็ตสดที่แนะนำตัวเชื่อมต่อใหม่ล้มเหลว หรือต้องใช้ตัวสำรองเฉพาะแพลตฟอร์ม
TikTok อัตโนมัติแอปเลือกเส้นทาง TikTok ที่ดีที่สุด และอาจใช้ตัวสำรองหากเส้นทางหนึ่งล้มเหลวคุณยังไม่แน่ใจว่าจะใช้โหมด TikTok ใด

ใช้โหมด Standard เมื่อ

  • แพลตฟอร์มทำงานเมื่อคุณมองเห็นหน้าไลฟ์หรือแชตแยก
  • เว็บไซต์ต้องให้ลงชื่อเข้าใช้ ตอบคำถามยืนยัน หรือเปิดแผงแชตที่มองเห็นค้างไว้
  • คุณกำลังเปรียบเทียบพฤติกรรมแอปกับส่วนขยาย Chrome
  • คุณต้องการขั้นตอนแก้ปัญหาที่คุ้นเคยที่สุด: เปิดหน้า เห็นแชต ทดสอบแผงด็อก แล้วค่อย OBS

โหมด Standard ยังล้มเหลวได้หากแพลตฟอร์มเปลี่ยนเลย์เอาต์ บล็อกเบราว์เซอร์ฝัง/ในแอป ขอ CAPTCHA หรือซ่อนแชตไว้หลังการลงชื่อเข้าใช้

ใช้โหมด WebSocket หรือ API เมื่อ

  • แหล่งข้อมูลรองรับโหมด WebSocket/API โดยเฉพาะ
  • คุณต้องการแหล่งข้อมูลที่ทำงานเบื้องหลังได้ดีขึ้น
  • คุณต้องการกลุ่มเหตุการณ์ที่การเก็บจากหน้าปกติอาจไม่แสดง
  • คุณจัดการโทเคนผู้ให้บริการ สิทธิ์บัญชี ขอบเขต API หรือการตั้งค่าหน้าแหล่งข้อมูลได้

โหมด WebSocket/API ไม่ได้ดีกว่าเสมอ หากการยืนยันตัวตน โทเคน สิทธิ์ผู้ให้บริการ หรือ API แพลตฟอร์มมีปัญหา โหมด Standard อาจทดสอบได้เร็วกว่า

TikTok ในแอป

TikTok ในแอปเดสก์ท็อปไม่ได้มีโหมดเดียว จดพรีเซ็ตที่ใช้งานอยู่ก่อนแก้ปัญหาเสมอ

เส้นทาง TikTokกรณีใช้งานจุดที่มักเกิดปัญหา
อัตโนมัติตัวเลือกแรกสำหรับผู้ใช้ส่วนใหญ่แอปอาจใช้ตัวสำรอง จึงควรตรวจข้อความสถานะ
Standardเก็บข้อมูลจากหน้า TikTok ที่มองเห็นการลงชื่อเข้าใช้ CAPTCHA หน้าที่เปลี่ยนเส้นทาง หรือแชตที่ซ่อน
ตัวลงลายเซ็นในเครื่อง (Local Signer)เส้นทางอ่านและรองรับการตอบกลับแบบเนทีฟของแอปเซสชัน/คุกกี้ TikTok ในแอปต้องใช้ได้
ดึงเป็นระยะ/ความเข้ากันได้ (Polling/Compatibility)ตัวสำรองเมื่อเส้นทางซ็อกเก็ต/ลงลายเซ็นล้มเหลวข้อมูลไม่ครบเท่าตัวเชื่อมต่อที่แนะนำ
พร็อกซีหรือการลงลายเซ็นกำหนดเองการตั้งค่าขั้นสูงความพร้อมของผู้ให้บริการ คีย์ API รหัสห้อง หรือข้อจำกัดอัตรา

สำหรับการลองครั้งแรกตามปกติ ให้เพิ่ม TikTok คงพรีเซ็ต Auto เปิดใช้แหล่งข้อมูล แล้วดูข้อความสถานะในแอป

สิ่งที่ต้องตรวจก่อน OBS

  1. ยืนยันว่าเปิดใช้แหล่งข้อมูลในแอปแล้ว
  2. ยืนยันว่าลงชื่อเข้าใช้ในหน้าต่างแหล่งข้อมูลแล้ว หากแพลตฟอร์มต้องใช้
  3. ยืนยันว่าแผงด็อกรับแชตด้วยรหัสเซสชันเดียวกัน
  4. หลังแผงด็อกทำงานแล้วเท่านั้น จึงเพิ่มหรือรีเฟรช URL โอเวอร์เลย์ OBS
  5. หาก Chrome ใช้ได้แต่แอปไม่ได้ จำไว้ว่าเซสชันแอปแยกจาก Chrome

วิธีแก้ปัญหาที่พบบ่อย

  • Chrome ลงชื่อเข้าใช้แล้วแต่แอปยังไม่ได้ลง: ลงชื่อเข้าใช้แพลตฟอร์มในหน้าต่างแหล่งข้อมูลแอป หรือใช้ส่วนขยายเป็นเส้นทางเก็บข้อมูล
  • แหล่งข้อมูลบอกว่าทำงานแต่แชตไม่มา: ตรวจโหมด หน้าต่างแหล่งข้อมูล URL ไลฟ์/ชื่อผู้ใช้ และเซสชันแผงด็อก
  • แอปใช้ไฟล์แหล่งข้อมูลผิด: ตรวจว่าแอปใช้ไฟล์ Social Stream ที่แพ็กมา แคช ระยะไกล เบต้า เสถียร หรือในเครื่อง
  • TikTok ใช้ไม่ได้: จดพรีเซ็ตปัจจุบัน ข้อความสถานะ รุ่นแอป และว่าแหล่งข้อมูลสลับเป็นโหมดสำรองหรือไม่
  • OBS ว่าง: ทดสอบแผงด็อกก่อน หากแผงด็อกว่าง ปัญหายังไม่ได้อยู่ที่ OBS

คู่มือที่เกี่ยวข้อง: ตัวช่วยเลือกการตั้งค่าแพลตฟอร์ม.
