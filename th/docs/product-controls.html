สินค้าสดและลิงก์ผู้ชม

ใช้โอเวอร์เลย์สร้างรายได้เป็นแหล่งเบราว์เซอร์ OBS สำหรับผู้ชม ควบคุมจาก SSN, Stream Deck หรือ API แผงด็อกควบคุมใช้ API เดียวกันแยกได้ ตัวควบคุมผู้ดำเนินรายการไม่ควรอยู่บนโอเวอร์เลย์ผู้ชม

1. เพิ่มลิงก์สินค้าหรือสนับสนุน2. ควบคุมสิ่งที่แสดง3. เผยแพร่ลิงก์ผู้ชมหนึ่งลิงก์Event Flow และการควบคุมระยะไกลรู้เมื่อคำสั่งควบคุมเสร็จ

1. เพิ่มลิงก์สินค้าหรือสนับสนุน

เปิด Monetization > Products & support links > Set up products and links วางลิงก์ HTTPS สาธารณะแล้วเลือก โหลดรายละเอียดจากลิงก์ การนำเข้าด่วนรองรับหน้าสาธารณะของ Gumroad, itch.io, Ko-fi, Buy Me a Coffee และ Fourthwall โดเมนกำหนดเอง การเปลี่ยนเส้นทาง หน้าส่วนตัว และหน้าที่ไม่มีเมทาดาทาสาธารณะอาจต้องป้อนเอง ตัวเลือกนำเข้า API ของ Shopify และ Fourthwall เดิมยังใช้ได้

ตรวจชื่อ รูปภาพ ราคา สกุลเงิน และวัตถุประสงค์ การนำเข้าด่วนตั้งใจเว้นราคาว่าง เลือก เพิ่มสินค้าหรือลิงก์, เปิด Products & support links แล้ว บันทึกการตั้งค่า การ์ดที่เพิ่มเองไม่ต้องมีบัญชีผู้ค้า

Shop, Gift, Support และ Join อธิบายวัตถุประสงค์ลิงก์ ไม่ได้เปลี่ยนการจัดประเภทเหตุการณ์ชำระเงินภายหลัง การ์ดเป็นภาพข้อมูลที่บันทึกไว้ หน้าชำระเงินเป็นแหล่งข้อมูลจริงเรื่องสต็อกและราคา

2. ควบคุมสิ่งที่แสดง

เพิ่ม URL โอเวอร์เลย์ Products & support links เดิมใน OBS ใช้ Showcase หรือ Support card สำหรับโปรโมต หรือ Both เพื่อรวมการแจ้งเตือนกิจกรรม

  • แสดงตอนนี้ บนแถวที่บันทึกจะปักสินค้านั้นและแทนตารางแสดงการ์ดเป็นระยะ
  • สินค้าถัดไป ปักสินค้าที่บันทึกไว้ลำดับถัดไป
  • ซ่อนสินค้า ซ่อนการ์ดโปรโมต การแจ้งเตือนการซื้อและของขวัญยังทำงานต่อ
  • กลับไปใช้ตารางเวลา คืนการตั้งค่าสินค้าแรกหรือการหมุนเวียนที่บันทึกไว้

ตั้ง Show/hide seconds ก่อนใช้ตัวควบคุม ค่า 0 มีผลจนกว่าจะเปลี่ยน ค่า 1-3600 จะคืนตารางเวลาที่บันทึกหลังเวลานั้น การแทนที่แบบสดรีเซ็ตเมื่อ SSN เริ่มใหม่ แถวที่ยังไม่บันทึกมีเครื่องหมายและปุ่ม Show now จะปิดจนกด Save setup สถานะระบุสินค้าที่เลือกและวินาทีที่เหลือ ไม่ได้อ้างว่า OBS กำลังไลฟ์หรือแหล่งข้อมูลนี้มองเห็น ตัวควบคุมระบุสินค้าด้วย URL ที่บันทึกตรงทุกตัว การย้ายตำแหน่งในรายการจึงไม่ทำให้ระบบอัตโนมัติเสีย

3. เผยแพร่ลิงก์ผู้ชมหนึ่งลิงก์

เปิด Display options > Public viewer page แล้วเลือก เผยแพร่ลิงก์ที่บันทึก นี่คือการเผยแพร่ลิงก์สินค้า/สนับสนุนที่บันทึกไว้ทุกอันอย่างชัดแจ้ง รวมชื่อ รูปภาพ ราคา และวัตถุประสงค์ แชร์ คัดลอกลิงก์ผู้ชม กับผู้ชม QR code สินค้าจะใช้หน้าถาวรนี้ ผู้ชมจึงยังหาสินค้าได้หลังโอเวอร์เลย์หมุนไปแล้ว

การเปลี่ยนแปลงที่บันทึกและตัวควบคุมสดอัปเดต URL เดียวกัน หน้าผู้ชมตรวจการอัปเดตทุก 15 วินาทีและติดป้ายสินค้าที่เลือกเด่น ลิงก์อื่นยังเข้าถึงได้แม้ซ่อนการ์ดโปรโมต แค็ตตาล็อกที่เผยแพร่ล่าสุดยังเข้าถึงได้เมื่อ SSN ออฟไลน์ โดยแสดงเวลาที่บันทึกไว้ และคำว่า featured หมายถึงการเลือกหรือการหมุนเวียนที่บันทึกล่าสุด ไม่ได้พิสูจน์ว่าผู้สร้างกำลังไลฟ์

ยกเลิกเผยแพร่ ลบหน้า QR code สินค้าจะกลับไปยังลิงก์สินค้าแต่ละอัน หน้าผู้ชมที่เปิดอยู่จะล้างเมื่อการตรวจครั้งถัดไปสำเร็จ URL ที่แชร์ไว้จะโหลดไม่ได้จนกว่าจะเผยแพร่อีกครั้ง การเผยแพร่ใหม่จากอุปกรณ์เดิมคืน URL เดิม เก็บโปรไฟล์อุปกรณ์ SSN ไว้ เพราะต้องใช้คีย์เผยแพร่ส่วนตัวเพื่ออัปเดตหรือลบหน้า

หาก API ใช้ไม่ได้ ตัวควบคุมในเครื่องยังทำงาน การอัปเดตที่ล้มเหลวจะคงหน้าที่เผยแพร่ล่าสุดและลองใหม่ขณะ SSN เปิด ป๊อปอัปรายงานความล้มเหลว การเผยแพร่ต้องติดตั้งบริการร้านค้าสาธารณะเสริมไว้ ไม่เกี่ยวกับบัญชีร้านค้าหรือบัญชีรับชำระเงิน

Event Flow และการควบคุมระยะไกล

ใน Event Flow เพิ่ม สินค้าและการสนับสนุน จากกลุ่มแอ็กชันโอเวอร์เลย์ เลือก Show, Next, Hide หรือ Resume ระบุ URL สินค้าที่บันทึกให้ตรงและวินาทีได้หากต้องการ ใช้ทริกเกอร์เดิมที่เหมาะสม เช่น คำสั่งผู้ดูแลแชตของคุณ แทนการให้ทุกข้อความแชตเปลี่ยนสินค้าได้

ในปลั๊กอิน Stream Deck เพิ่มปุ่ม Preset Command จาก สินค้าและการสนับสนุน: Show product, Next product, Hide products และ Resume products โดย Show มีตัวเลือกสินค้าที่บันทึกไว้ เลือก Refresh products and state เพื่อโหลดรายการ ตัวเลือกที่บันทึกแต่ใช้ไม่ได้จะยังแสดงแทนการเปลี่ยนเงียบ ๆ คุณยังวาง URL สินค้าสาธารณะหรือเว้นว่างเพื่อใช้สินค้าปัจจุบัน/ชิ้นแรกได้ Next และ Hide รับค่าวินาทีเสริม ปุ่มรอ SSN ยืนยันการเปลี่ยนแปลงในเครื่องโดยไม่ขึ้นกับการอัปเดตหน้าสาธารณะ เพิ่มปุ่ม Product State เสริมเพื่อดูผลสถานะเลือก/ซ่อน/ตามตาราง ซึ่งรีเฟรชทุกห้าวินาทีขณะปุ่มมองเห็น ตัวตรวจสอบคุณสมบัติและ SSN แสดงชื่อสินค้าเต็ม ส่วนปุ่มสถานะขนาดเล็กตัดชื่อยาว ใช้การเชื่อมต่อ P2P หรือ WebSocket เดิม

API ควบคุมระยะไกลของเซสชันเดิมที่ยืนยันตัวตนแล้วรับคำสั่งเดียวกัน:

{"action":"commerceControl","command":"show","url":"https://example.com/product","seconds":30}

คำสั่งคือ show, next, hide และ resume ไม่ใส่ URL หากต้องการแสดงสินค้าปัจจุบัน/ชิ้นแรก ต้องเปิดการควบคุมโฮสต์ อย่าแชร์ URL เซสชัน/ควบคุมส่วนตัวกับผู้ชม ให้ใช้ลิงก์ผู้ชมที่เผยแพร่

แอ็กชันเหล่านี้ส่งเฉพาะสถานะแสดงผลเดิม monetization_update ไม่สร้างการบริจาค การซื้อ โพสต์แชต หรือทริกเกอร์ชำระเงิน Event Flow ส่วนเดิม hasDonation ยังทำงานเหมือนเดิม

รู้เมื่อคำสั่งควบคุมเสร็จ

แอ็กชัน Products & Support รอคำตอบจาก SSN ก่อนให้โฟลว์ทำต่อ สำหรับเพย์โหลดเหตุการณ์ปกติ meta.commerceControlResult มี success และผลลัพธ์อย่างใดอย่างหนึ่ง commerce สถานะควบคุม หรือ error ความล้มเหลวจะหยุดแอ็กชันถัดไปในสายงานนั้น แต่การซื้อหรือทิปต้นฉบับยังใช้ได้ในโฟลว์และโอเวอร์เลย์อื่น สถานะยืนยันการเลือก สถานะซ่อน หรือตารางเวลาของ SSN ส่วนการมองเห็นใน OBS แยกต่างหาก

หากไม่มีคำตอบภายในแปดวินาที แอ็กชันจะรายงานหมดเวลา แต่คำสั่งควบคุมอาจทำงานไปแล้ว ตรวจสถานะป๊อปอัปหรือแผงด็อกก่อนลอง Next ซ้ำ ไคลเอนต์ระยะไกลภายนอกควรใช้โปรโตคอลคำขอ/คำตอบเดิมและตรวจผลที่คืน แทนการถือว่าส่งคำสั่งแล้วเท่ากับสำเร็จ

เอฟเฟกต์อื่นมีผลตอบกลับของตัวเอง Print Thermal Label รายงาน meta.thermalPrintResult การส่งงานสำเร็จไม่ได้ยืนยันว่าพิมพ์กระดาษแล้ว แอ็กชัน Webhook แบบรอผลคืนสถานะ HTTP และคำตอบได้ และบล็อกเมื่อผิดพลาดได้ สิ่งเหล่านี้เป็นผลลัพธ์แอ็กชัน ไม่ใช่เหตุการณ์ชำระเงินใหม่ ดู เอกสารอ้างอิงเหตุการณ์ สำหรับรูปแบบผลลัพธ์คำสั่งควบคุม
