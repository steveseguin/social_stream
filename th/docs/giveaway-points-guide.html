การแจกของรางวัล ตั๋ว และรางวัลแต้ม

เพิ่งใช้เครื่องมือแจกของรางวัลหรือไม่? เริ่มที่ การแจกครั้งแรก: คำแนะนำพร้อมภาพหน้าจอ.

ใช้ตัวหลักหนึ่งตัวจัดการจับรางวัล ป๊อปอัป Stream Deck และ Event Flow ควบคุมตัวหลักนั้น หน้าจอผู้ชมแสดงผลที่ยืนยันแล้ว

จัดการแจกฟรีครั้งแรก

  1. ในป๊อปอัป เปิด ตัวเลือกแจกของรางวัล คง ID เป็น default, ตั้งคำสำคัญเป็น !enter, และตั้งราคาตั๋วกับรางวัลแต้มเป็นศูนย์
  2. เลือกการ์ดผู้ชนะ วงล้อชื่อ หรือวงล้อชุมชน ดูตัวอย่างแล้วคัดลอกลิงก์เข้าแหล่งเบราว์เซอร์ OBS
  3. เลือก เปิดรับผู้เข้าร่วม ผู้ชมเข้าร่วมด้วยการส่งคำสำคัญในแชตที่จับข้อมูล
  4. เลือก ปิดรับผู้เข้าร่วม, จากนั้น จับผู้ชนะ การจับผลจะปิดรับด้วยหากลืมปิดก่อน
  5. เลือก รอบใหม่ เพื่อเริ่มจับอีกครั้ง ผู้ชนะก่อนหน้ายังคงในประวัติตัวหลัก

เปิดตัวหลัก SSN ทิ้งไว้ ไม่ต้องโต้ตอบกับแหล่งเบราว์เซอร์ OBS วงล้อชุมชนแบบแยกยังใช้ได้โดยไม่มี &managed; แต้มและการควบคุมระยะไกลใช้โหมด managed

ตั๋วที่ชำระด้วยแต้ม SSN

  1. เปิดตัวเลือกที่มีอยู่ ระบบสะสมแต้ม ในป๊อปอัป แต้มเหล่านี้เป็นแต้ม SSN แยกจากแต้มช่อง Twitch และคะแนนแต่ละเกม
  2. ใน ตั๋วและรางวัลแต้ม, ตั้งแต้มต่อตั๋วและจำนวนตั๋วสูงสุดต่อผู้ชม ราคา 1 หมายถึงหนึ่งตั๋วต่อหนึ่งแต้ม
  3. เปิดรับผู้เข้าร่วม สำหรับการแจกชื่อ friday, ผู้ชมซื้อตั๋วห้าใบด้วย !ticket friday 5.
  4. ตรวจผู้เข้าร่วมใน จัดการการแจกของรางวัลและประวัติ การซื้อสำเร็จหักแต้มและเพิ่มผู้ชมเข้าร่วมพร้อมกัน แต้มไม่พอจะไม่สร้างตั๋ว

การซื้อตั๋วจองแต้มทันที แต้มเดียวกันจึงใช้ซื้อสติกเกอร์หรือเข้ารอบเสียแต้มอื่นไม่ได้ การจับผลใช้แต้มเหล่านั้น ยกเลิกและคืนเงิน คืนแต้มที่จอง การนำผู้เข้าร่วมออกหนึ่งคนก่อนจับคืนแต้มที่จองของคนนั้น รอบเสียแต้มไม่สามารถทิ้งเงียบ ๆ ด้วย New round

กฎล็อกหลังมีผู้เข้าร่วมคนแรก ปิด/เปิดเพื่อพักรอบโดยใช้กฎเดิมได้ หากต้องการเปลี่ยนราคาหรือสิทธิ์ ให้ยกเลิกและสร้างรอบใหม่ ผู้ชมเปลี่ยนกระเป๋าเงินหรือย้ายฝั่งใน pot หลังเข้าร่วมไม่ได้

แจกแต้ม

ตั้งค่า รางวัลแต้มต่อผู้ชนะ และ จำนวนรางวัล ก่อนเปิดรับ แต่ละรางวัลเพิ่มแต้ม SSN ตามจำนวนนั้นให้บัญชีเดิมของผู้ชมที่เลือก เป็นการสร้างแต้ม ไม่ได้ดึงจากรายรับตั๋วหรือกระเป๋าผู้ดำเนินการ ยอดออกแต้มรวมจำกัดตามแต้มรางวัลและจำนวนผู้ชนะที่ตั้ง

หากมีหลายรางวัล ให้จับทีละคน ผู้ชนะแต่ละคนบันทึกยืนยันก่อนภาพเคลื่อนไหวเริ่ม ยกเลิกการจับที่เสร็จเพื่อย้อนผลที่ทราบแล้วไม่ได้ แก้ข้อผิดพลาดด้วยการปรับแต้มจากผู้ดำเนินรายการอย่างตั้งใจ การเปลี่ยนหน้าจอหรือเชื่อมต่อใหม่ไม่มอบซ้ำ

เกมพร้อมรางวัลแต้ม

Number Hunt แบบจัดการจากตัวหลัก

เลือก Number Hunt (ผู้ดำเนินรายการควบคุม), ราคาตั๋ว 0 หนึ่งรางวัล และรางวัลแต้มเพิ่มเติมตามต้องการ ผู้ดำเนินรายการเลือกเลข 1–100 ผู้เล่นใช้ !guess friday 50, โดยแทนรหัสแจกของรางวัล การเดาถูกให้รางวัลผู้แก้ได้คนแรกที่มีสิทธิ์ครั้งเดียว การเดาผิดช่วยจำกัดช่วงให้ทุกคน ผู้ชมแต่ละคนเดาได้หนึ่งครั้งทุกห้าวินาที

ใช้หน้าจอแจกของรางวัลแบบ managed หรือ games/numberhunt.html?session=YOUR_SESSION&managed&giveaway=friday Number Hunt ปกติและเกมเดิมอื่นคงพฤติกรรมในเครื่องเดิม คะแนนในเกมและป้ายผู้ชนะไม่มอบแต้ม SSN อัตโนมัติ

Coin Flip Pot

นี่เป็นเกมเสี่ยงโชค เลือก Coin Flip Pot, ราคา 1 ผลลัพธ์หนึ่งรายการ และรางวัลเพิ่ม 0 ผู้ชมลงแต้มด้วย !ticket friday 3 heads หรือ !ticket friday 3 tails ทั้งสองฝั่งต้องมีผู้เข้าร่วม ปิดรับแล้วจับผล ตัวหลักเลือกหัวหรือก้อยด้วยโอกาสเท่ากัน ไม่ขึ้นกับยอดแต้มแต่ละฝั่ง

ผู้ชมฝั่งชนะได้แต้มเดิมพันคืนและแบ่งแต้มฝั่งแพ้ตามสัดส่วนเดิมพัน แต้มจำนวนเต็มที่เหลือให้ส่วนแบ่งเศษสูงสุดก่อน แล้วใช้ลำดับเข้าร่วมตัดสินเมื่อเท่ากัน ไม่หักค่าธรรมเนียมและไม่สร้างแต้มเพิ่ม หากเดิมพันฝั่งชนะเป็น 2 และ 1 ต่อแต้มแพ้ 5 กองกลาง 8 แต้มจะจ่าย 5 และ 3 ยกเลิกก่อนจับเพื่อคืนทุกคน หากฝั่งหนึ่งว่างจะจับไม่ได้และยกเลิก/คืนได้

การแจกหลายรายการ

ตั้ง ID สั้นให้แต่ละรายการโดยใช้ตัวอักษร ตัวเลข ขีดกลาง หรือขีดล่าง การซื้อของผู้ชมในทุก ID ใช้ยอดกระเป๋าเงินที่ใช้ได้ร่วมกัน แต่ละ URL ของ OBS มี &giveaway=ID คำสั่งตั๋วและเดาระบุการจับรางวัลชัดเจน ใช้คำสำคัญต่างกันสำหรับการแจกฟรีพร้อมกัน คำสำคัญฟรีที่กำกวมจะไม่ทำให้เข้าหลายรายการโดยไม่ตั้งใจ

ช่องป๊อปอัปเป็นค่าตั้งต้น รีเฟรชหรือเปิดตัวจัดการเพื่อตรวจกฎที่ตัวหลักบันทึกยืนยัน การเปลี่ยนลิงก์ผู้ชมเปลี่ยนเฉพาะการแสดงผล ไม่เขียนกฎตั๋วของรอบที่ทำงานใหม่

OBS และการนำเสนอ

พื้นหลัง managed เริ่มต้นโปร่งใส เลือกแผงตามธีมได้หากต้องการ การ์ด วงล้อชื่อ และวงล้อชุมชนใช้ผลเดียวกันกับสไตล์สีหกแบบ การตั้งค่าลดการเคลื่อนไหวข้ามภาพเคลื่อนไหวเปิดผล วงล้อแสดงตัวอย่างสูงสุด 120 ชื่อ เป็นภาพเคลื่อนไหวเปิดผล ไม่ใช่การแทนโอกาสของตั๋วทุกใบครบถ้วน การเลือกใช้กลุ่มตั๋วที่มีสิทธิ์ทั้งหมด

เมื่อเชื่อมต่อใหม่ หน้าจอแสดงผลที่บันทึก การเชื่อมต่อหน้าจอไม่ได้บอก SSN ว่าฉาก OBS นั้นมองเห็นอยู่หรือไม่ เก็บ URL ควบคุม รหัสเซสชัน และไฟล์สำรองเป็นความลับ

Event Flow

เพิ่ม แจกของรางวัล / ตั๋ว จากการกระทำแต้ม เลือก Enter free giveaway, Buy tickets, Grant free tickets, Close entries, Draw winner, Cancel and refund หรือ Query state เลือก ID และจำนวนตั๋ว เลือก heads/tails สำหรับซื้อเข้า pot การกระทำใช้ตัวตนผู้ชมที่จับได้ ใช้ตัวเรียก/ตัวกรองที่เชื่อถือได้ก่อนการให้ตั๋วหรือการควบคุมผู้ดำเนินการ

Buy tickets ใช้แต้มอยู่แล้ว อย่าใส่ Spend Points ก่อนหน้า ความล้มเหลวหยุดการกระทำที่พึ่งพาโดยไม่ซ่อนแชตต้นฉบับ ผลอยู่ใน meta.giveawayControlResult แผงทดสอบ Event Flow จำลองการกระทำนี้โดยไม่ซื้อตั๋วจริง ใช้ตัวหลัก/โปรไฟล์แยกสำหรับทดสอบครบขั้นตอนที่เปลี่ยนรอบจริง

สิทธิ์ซื้อใช้ยอดคงเหลือที่บันทึกยืนยันแล้วตอนการกระทำทำงาน อย่าพึ่งว่าข้อความเข้าร่วมจะได้แต้มสุดท้ายที่ขาดพอดี รหัสข้อความดั้งเดิมของแหล่งช่วยป้องกันการเล่นซ้ำถาวร แหล่งที่ไม่มีรหัสดังกล่าวรับประกันตัวตนข้ามการเริ่มใหม่ได้น้อยกว่า อีเวนต์ตามเวลาทั่วไปที่ไม่มีรหัสผู้ชม/ข้อความที่จับได้ซื้อแทนผู้อื่นไม่ได้

Stream Deck และ API

ปลั๊กอินดั้งเดิมมี Open Giveaway, Close Giveaway, Draw Giveaway, Cancel & Refund, New Giveaway Round และ Giveaway State โดย ID เริ่มต้นคือ default ใส่ {"giveawayId":"friday"} ในช่อง value เพื่อเลือกรอบอื่น Open ยังรับ config ออบเจ็กต์ มิฉะนั้นรอบเดิมคงกฎที่ยืนยันแล้ว และ ID ใหม่ใช้ค่าเริ่มต้นป๊อปอัป

ใช้การเชื่อมต่อ P2P เดิมหรือ WebSocket ที่ตั้งไว้ ปุ่มรายงานคำตอบจาก SSN ไม่ได้อ้างว่า OBS กำลังถ่ายทอดสด หากคำตอบหมดเวลา ให้สอบถามสถานะก่อนลองจับใหม่

{"protocol":2,"action":"buygiveawaytickets","get":"callback-1","value":{"giveawayId":"friday","roundId":"ROUND_ID","operationId":"purchase-123","count":5,"actor":{"chatname":"Avery","type":"youtube","userid":"SOURCE_USER_ID"}}}

operation ID ระบุการดำเนินการทางธุรกิจ ส่วน callback ID ระบุคำตอบ ใช้ operation ID เดิมเมื่อลองซ้ำ การใช้ซ้ำพร้อมพารามิเตอร์ต่างกันจะล้มเหลว ใช้ operation ID ใหม่สำหรับการซื้อใหม่ที่ตั้งใจ การเข้าถึง API ผู้ดำเนินการใช้แต้มแทนผู้กระทำที่ระบุได้ อย่าเปิดเป็นฟอร์มซื้อสาธารณะที่ไม่ยืนยันตัวตน

ประวัติ ข้อมูลสำรอง และการกู้คืน

ตัวจัดการแสดงรอบ ผู้เข้าร่วม และประวัติผู้ชนะ ส่งออกประวัติผู้ชนะเป็น JSON หรือบันทึกข้อมูลสำรองแต้ม/แจกของรางวัลเวอร์ชัน 2 ฉบับสมบูรณ์ ข้อมูลสำรองเต็มมีทั้งยอดคงเหลือ การจอง รอบ และใบรับการดำเนินการ ไม่มีการอัปโหลดไปเซิร์ฟเวอร์

เมื่อเริ่มตัวหลักใหม่ รอบเปิดที่บันทึกจะปิดเพื่อตรวจสอบ ตั๋วยังคงจองแต้มไว้ เปิดใหม่ด้วยกฎเดิม จับผล หรือยกเลิก/คืน ธุรกรรมฐานข้อมูลที่ขาดตอนจะบันทึกครบทั้งหมดหรือไม่ทิ้งการซื้อ/จ่ายบางส่วน การจองสติกเกอร์ที่ยังไม่มีการยืนยันส่งสำเร็จจะกู้คืนหลังหมดเวลา

กู้คืนครบชุดได้บน ตัวหลักใหม่ที่ไม่มียอดคงเหลือหรือระเบียนแจกของรางวัลเดิม กู้ภาพข้อมูลทั้งชุดและคงรอบที่กู้คืนเป็นปิด จะไม่ยอมเขียนทับตัวหลักที่มีข้อมูล คืนรหัสสตรีม/เซสชันเดิมในป๊อปอัปก่อนเล่นรอบต่อ ผลกู้คืนแสดงเซสชันในข้อมูลสำรอง ข้อมูลสำรองนี้ไม่แทนการตั้งค่าป๊อปอัปทั่วไป อย่าเปิดตัวหลักเก่ากับตัวที่กู้คืนให้ต่างฝ่ายต่างจัดการระบบแต้มเดียวกัน ข้อมูลสำรองเป็นภาพ ณ เวลาหนึ่ง จึงไม่มีธุรกรรมหลังเวลาบันทึก

การนำเข้าเฉพาะยอดคงเหลือกู้รายการจองค้างไม่ได้ การล้างแต้มและเขียนทับด้วยตนเองถูกปฏิเสธเมื่อยอดที่เกี่ยวข้องมีการจอง การล้างแต้มไม่ลบใบรับ/ประวัติแจกของรางวัล ยอดคงเหลือเป็นของโปรไฟล์เบราว์เซอร์/แอปนี้ ส่วนรอบแยกตามเซสชัน โปรไฟล์/อุปกรณ์แยกไม่ซิงก์อัตโนมัติ การล้างข้อมูลเบราว์เซอร์อาจลบระเบียนในเครื่อง จึงควรเก็บสำรองนอกโปรไฟล์นั้น

การสำรอง/ซิงก์เซิร์ฟเวอร์เพิ่มเติมเป็นฟีเจอร์อนาคต ไม่อยู่ในรุ่นนี้ การทำงานนี้ไม่เพิ่มการอัปโหลด ข้อมูลรับรองเซิร์ฟเวอร์ เงินที่ซื้อมา หรือการแลกเป็นเงินสด

เมื่อบางอย่างไม่ทำงาน

  • ไม่เข้าร่วม: ตรวจ ID/คำสำคัญ ข้อจำกัดสมาชิก สถานะเปิดรับ และแพลตฟอร์มที่จับ ไม่รวมรายการบอต ส่วนตัว ประวัติ เล่นซ้ำ และระบุว่าทดสอบ
  • บัญชีเปลี่ยน: การเปลี่ยนชื่อ/ตัวตนอาจทำให้ระบุกระเป๋าเงินกำกวม ตรวจบนตัวหลัก ไม่รวมบัญชีข้ามแพลตฟอร์มเงียบ ๆ
  • ไม่ตอบสนอง: ตรวจว่าตัวหลัก SSN ที่ต้องการทำงานและเปิดการควบคุมผู้ดำเนินรายการ รีเฟรชสถานะที่ยืนยันแล้วก่อนลองใหม่
  • ล้าง/นำเข้าไม่ได้: ปิดบัญชีหรือยกเลิกการซื้อที่จองก่อน ใช้การกู้คืนเต็มสำหรับข้อมูลสำรองที่มีภาระค้าง
  • ไม่รู้จักรางวัล: !spend ต้องมีรางวัลและราคาที่ตั้งตรงกัน จะไม่เผาแต้มสำหรับชื่อรางวัลใด ๆ ตามอำเภอใจอีกต่อไป

กู้ข้อมูลสำรองทีละขั้น

  1. หยุดตัวหลักเก่าไว้ เปิด SSN ในโปรไฟล์เบราว์เซอร์ใหม่และเปิดตัวจัดการแจกของรางวัล
  2. ใน กู้บนตัวหลักใหม่, เลือกข้อมูลสำรองฉบับสมบูรณ์ รอข้อความกู้คืนและจดรหัสเซสชันเดิมที่แสดง
  3. ในส่วนของป๊อปอัป ตัวเลือกเซสชัน, ป้อนรหัสเซสชันเดิมนั้น
  4. กลับตัวจัดการ เลือก ID แจกของรางวัล แล้วเลือก รีเฟรช ตรวจสอบกฎ ผู้เข้าร่วม และประวัติผู้ชนะ รอบเปิดที่กู้คืนจะปิดเพื่อตรวจสอบ
  5. เปิดใหม่ด้วยกฎเดิม จับผล หรือเลือก ยกเลิกและคืนเงิน เพื่อคืนตั๋วที่จอง บันทึกข้อมูลสำรองใหม่หลังตรวจผล
