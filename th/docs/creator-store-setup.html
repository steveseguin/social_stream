เชื่อมต่อร้านค้า แสดงสินค้าของคุณ

สินค้าและการแจ้งเตือนแยกจากกัน

ใช้ การสร้างรายได้ ใน SSN เพื่อโปรโมตสินค้าสาธารณะและหน้าสนับสนุน รับกิจกรรม หรือทำทั้งสองอย่าง คู่มือนี้ครอบคลุม Fourthwall, Ko-fi และ Buy Me a Coffee สำหรับ NinjaBacker, Throne, Amazon และ eBay ดู คู่มือการสร้างรายได้.

เชื่อมต่อการแจ้งเตือน · Fourthwall · Ko-fi · Buy Me a Coffee · นำเข้าสินค้า · OBS และ QR code · การแก้ปัญหา

เชื่อมต่อการแจ้งเตือนกิจกรรม

  1. เปิด การสร้างรายได้ → การแจ้งเตือน Fourthwall, Ko-fi และ Buy Me a Coffee แล้วเลือกผู้ให้บริการ
  2. คลิก การตั้งค่าตัวรับ เปิดตัวเลือกที่มีอยู่ การควบคุมส่วนขยายจากระยะไกลผ่าน API สวิตช์ แล้วเปิด SSN ทิ้งไว้
  3. กลับไปที่ Monetization แล้วคลิก คัดลอก URL ของ webhook วางที่อยู่ส่วนตัวนี้ในการตั้งค่า webhook ของผู้ให้บริการตามด้านล่าง
  4. ตรวจสอบสถานะตัวรับ ตัวรับเชื่อมต่อแล้ว หมายถึง SSN กำลังรับฟัง ไม่ได้ยืนยันว่าการตั้งค่าผู้ให้บริการถูกต้อง บรรทัดอีเวนต์ล่าสุดอัปเดตเมื่อแอปที่กำลังทำงานได้รับอีเวนต์ผู้ให้บริการที่อ่านข้อมูลได้และไม่ซ้ำ และเริ่มใหม่เมื่อเปิดแอปใหม่
  5. ใช้ ดูตัวอย่างการแจ้งเตือน เพื่อตรวจหน้าตาในหน้าตัวอย่างแยก ไม่ส่งการชำระเงิน อัปเดตยอดรวม เรียก Event Flow หรือตรวจยืนยันการส่ง webhook

endpoint ที่ใช้ URL เซสชันทั้งสามตัวนี้พึ่งการเก็บ URL เป็นความลับ การตั้งค่า SSN ปัจจุบันไม่รับ signing secret ของบริการเหล่านี้ เหมาะสำหรับการแจ้งเตือนบนสตรีม ไม่ใช่หลักฐานชำระเงินเพื่อจัดส่งสินค้า อย่าเผยแพร่ที่อยู่ webhook หรือใช้เป็นปลายทาง QR สำหรับผู้ชม

Fourthwall

  1. ใน Fourthwall เปิด การตั้งค่า (Settings) → สำหรับนักพัฒนา (For Developers) → Webhooks.
  2. สร้าง webhook และวาง URL ของ Fourthwall ที่คัดลอกจาก SSN
  3. เลือกอีเวนต์ที่รองรับซึ่งคุณต้องการ: ORDER_PLACED, GIFT_PURCHASE, DONATION และ SUBSCRIPTION_PURCHASED.
  4. บันทึก webhook และเปิด SSN ทิ้งไว้

คำสั่งซื้อแสดงเป็นการซื้อ การให้สินค้าของขวัญแสดงเป็นของขวัญ และการสมัครใหม่แสดงเป็นสมาชิก เพื่อความเข้ากันได้ คำสั่งซื้อ Fourthwall ปกติยังมีค่าการบริจาคเดิม คำสั่งซื้อที่แลกบัตรของขวัญไม่เพิ่มมูลค่าที่จ่ายล่วงหน้าซ้ำ อีเวนต์ที่ระบุเป็นการทดสอบจะถูกข้าม

เอกสาร webhook ของ Fourthwall · ดูตัวอย่างการซื้อ

Ko-fi

  1. เปิด Ko-fi Webhooks.
  2. วาง URL ของ Ko-fi ที่คัดลอกจาก SSN ลงใน URL ของ Webhook แล้วบันทึก/อัปเดต
  3. เปิด SSN ทิ้งไว้ ทิปสาธารณะ การชำระสมาชิก คำสั่งซื้อร้านค้า และงานคอมมิชชันใช้การเชื่อมต่อเดียวกัน

ไม่รวมการชำระเงินส่วนตัว การชำระสมาชิกแสดงเป็นกิจกรรมสมาชิก คำสั่งซื้อร้านค้าและงานคอมมิชชันแสดงเป็นการซื้อโดยไม่เพิ่มยอดบริจาค Ko-fi ไม่ส่งการแจ้งเตือนยกเลิกสมาชิกผ่าน webhook นี้

การทดสอบ: ใช้หน้าตัวอย่างแยกของ SSN ก่อน การชำระเงินตัวอย่างของ Ko-fi อาจเหมือนของจริงและเรียกการแจ้งเตือน ยอดรวม และการกระทำได้หากส่งไปยังตัวรับที่ใช้งานอยู่ อย่าใช้การทดสอบของผู้ให้บริการกับเซสชันที่เปิดรางวัลแบบเสียเงิน

เอกสาร webhook ของ Ko-fi · ดูตัวอย่างการสนับสนุน

Buy Me a Coffee

  1. เปิด การเชื่อมต่อ (Integrations) ในแดชบอร์ดครีเอเตอร์แล้วเลือก Webhook ใหม่ (New webhook).
  2. ตั้งชื่อแล้ววาง URL ของ SSN Buy Me a Coffee เป็น endpoint
  3. เลือก donation.created, extra_purchase.created, commission_order.created, wishlist_payment.created และ membership.started ตามต้องการ
  4. บันทึกและเปิดการส่งข้อมูลทิ้งไว้ ใช้ประวัติส่งอีเวนต์ของผู้ให้บริการเพื่อตรวจสอบความล้มเหลว

คำสั่งซื้อร้านค้าและงานคอมมิชชันเป็นการซื้อ การชำระรายการอยากได้เป็นการร่วมสนับสนุนของขวัญ การเริ่มสมาชิกเป็นประกาศสมาชิก ไม่ใช่ยอดเรียกเก็บที่ยืนยันแยกต่างหาก หมายเหตุที่ซ่อนยังคงซ่อน และผู้สนับสนุนนิรนามยังคงนิรนาม การทดสอบจากแดชบอร์ดที่ระบุว่า live_mode: false จะถูกข้ามโดยไม่มีการแจ้งเตือนการชำระเงิน การคืนเงินและการอัปเดตวงจรสถานะไม่สร้างการชำระเงินหรือย้อนยอดรวมเดิม

เอกสาร webhook ของ Buy Me a Coffee · ดูตัวอย่างการร่วมสนับสนุน

นำเข้าสินค้า Fourthwall

  1. ในส่วนของ Fourthwall การตั้งค่า (Settings) → สำหรับนักพัฒนา (For Developers), สร้าง Storefront token ใช้ storefront token เพื่อเข้าถึงแค็ตตาล็อกสาธารณะ ไม่ใช่คีย์ API สำหรับผู้ดูแลระบบ
  2. ใน SSN เปิด สินค้าและลิงก์สนับสนุน → ตั้งค่าสินค้าและลิงก์ → นำเข้าสินค้า Fourthwall.
  3. วาง URL สินค้าสาธารณะและโทเค็น แล้วคลิก โหลดรายละเอียดสินค้า.
  4. ตรวจสอบชื่อ ภาพ ราคา และ URL สาธารณะที่โหลดมา ยืนยันว่า URL เป็นร้านเดียวกับโทเค็น รวมถึงโดเมนกำหนดเอง โทเค็นเป็นตัวกำหนดว่าจะค้นแค็ตตาล็อกของร้านใด
  5. เลือก Shop, Gift, Support หรือ Join เพื่อบอกว่าผู้ชมจะทำอะไร คลิก เพิ่มสินค้าหรือลิงก์, เปิด Products & support links แล้ว บันทึกการตั้งค่า.

การทำงานนี้นำเข้าสินค้าสาธารณะที่พร้อมขายทีละรายการผ่าน Storefront API ของ Fourthwall โทเค็นใช้เฉพาะคำขอนั้น ล้างหลังใช้ ไม่บันทึกหรือส่งไปโอเวอร์เลย์ ราคาที่ต่างกันตามตัวเลือกและราคาชุดจะเว้นว่างเพื่อไม่ให้เข้าใจว่าเป็นยอดชำระคงที่ ข้อมูลนำเข้าเป็นภาพ ณ เวลานั้น ราคา สต็อก และภาพไม่อัปเดตอัตโนมัติ ให้นำเข้าใหม่หรือแก้ไขเมื่อเปลี่ยน แค็ตตาล็อกเก็บได้สูงสุด 20 รายการ การเพิ่มซ้ำจะสร้างอีกหนึ่งรายการ

แสดงสินค้า ลิงก์สาธารณะ และ QR code

คุณป้อนลิงก์สินค้าหรือลิงก์สนับสนุนสาธารณะจากเว็บไซต์ใดก็ได้ด้วยตนเอง รวม Shopify, Tiltify หรือ Patreon เพิ่ม URL ภาพและราคาหากต้องการ เลือกจุดประสงค์ เปิดแค็ตตาล็อกและบันทึก การเพิ่มลิงก์ไม่ได้เชื่อมต่อฟีดการชำระเงิน

  1. เลือก สินค้าและลิงก์สนับสนุน ภายใต้ ลิงก์โอเวอร์เลย์สำหรับ.
  2. เปิด ตัวเลือกลิงก์โอเวอร์เลย์ เลือก Product showcase, Support card, Activity alerts หรือมุมมองรวม
  3. คลิก คัดลอกลิงก์ OBS แล้ววางในแหล่งเบราว์เซอร์ OBS เริ่มที่ 800 × 600 หากต้องการแยกชั้นโปรโมตกับกิจกรรม ให้สร้างแหล่งสำหรับแต่ละมุมมอง
  4. ใช้ Display options เพื่อตรึงสินค้าแรกหรือหมุนรายการ เปิด QR code เพื่อให้ผู้ชมสแกนปลายทางสาธารณะ ใช้ คัดลอกลิงก์สาธารณะ ข้างรายการเพื่อแชร์ที่อยู่ที่คลิกได้ในแชตด้วยตนเอง

ส่วนจัดแสดงมีภาพสินค้าหากระบุไว้ ส่วนการ์ดสนับสนุนขนาดเล็กซ่อนภาพ การแจ้งเตือนกิจกรรมทำงานแยกกันและไม่แนบ QR code ของสินค้าที่หมุนแสดงแต่ไม่เกี่ยวข้อง ให้ลิงก์สาธารณะอ่านได้และทดสอบสแกน QR ด้วยโทรศัพท์ขณะดูเลย์เอาต์ OBS สุดท้าย การเปลี่ยนสเกลในลิงก์ OBS หรือครอปแน่นเกินไปอาจทำให้สแกนยาก

สำหรับ multi-alerts หรือฟีดกิจกรรม ใช้ลิงก์โอเวอร์เลย์เดิมพร้อมเซสชัน SSN เดียวกัน ไม่จำเป็นต้องเปิดแค็ตตาล็อกสินค้าสำหรับโอเวอร์เลย์กิจกรรมเดิมเหล่านี้ ส่วนมุมมองกิจกรรม Monetization ทั่วไปต้องเปิดแค็ตตาล็อก ใน Event Flow ตัวเรียก Donation ยังคงใช้กับแถวที่มี hasDonation; ใช้ Event Type สำหรับการซื้อหรือการให้ของขวัญสำเร็จ ดู การจับคู่อีเวนต์.

หากไม่มีอะไรปรากฏ

  • ตัวรับปิดอยู่: เปิด remote API control of extension สวิตช์ API อื่นมีหน้าที่ต่างกัน
  • ขาดการเชื่อมต่อ: เปิด SSN ไว้และตรวจการเข้าถึงเครือข่าย สถานะนี้คือการเชื่อมต่อตัวรับร่วม ไม่ใช่สถานะส่งข้อมูลในแดชบอร์ดผู้ให้บริการ
  • ไม่ได้รับอีเวนต์: ตรวจผู้ให้บริการที่เลือก URL ส่วนตัว และการตั้งค่าการส่งของผู้ให้บริการ ตัวอย่างในเครื่องที่ทำงานได้ตรวจเฉพาะหน้าตา
  • อีเวนต์ถูกข้าม: ไม่รวมการทดสอบที่ทำเครื่องหมายไว้ การชำระเงินส่วนตัว ประเภทอีเวนต์ที่ไม่รองรับ หรือยอดเงินไม่ถูกต้อง สถานะไม่แสดงรายละเอียดผู้ซื้อ
  • ได้รับอีเวนต์แต่ไม่มีโอเวอร์เลย์: ตรวจเซสชัน/รหัสผ่าน ตัวกรองแหล่งข้อมูล หมวดหมู่อีเวนต์ กฎ SSN และการมองเห็นใน OBS การซื้อไม่ใช่การสมัครสมาชิก และการซื้อส่วนใหญ่ไม่ใช่การบริจาค
  • รายการซ้ำ: หลีกเลี่ยงส่งการชำระเงินเดียวกันทั้งจากผู้ให้บริการโดยตรงและตัวรวบรวม การตัดรายการซ้ำจากการลองส่งใหม่ใช้รหัสการส่งของผู้ให้บริการ
  • นำเข้าไม่สำเร็จ: ตรวจ slug สินค้าและ Storefront token รวมถึงสินค้าต้องเป็นสาธารณะและพร้อมขาย ยังป้อนด้วยตนเองได้

นี่คือกิจกรรมสตรีมสด ไม่ใช่บัญชีคำสั่งซื้อ ใช้แดชบอร์ดผู้ให้บริการเพื่อยืนยันการชำระเงิน คืนเงิน และจัดส่ง ขณะนี้ Shopify มีการนำเข้าสินค้าและการตั้งค่าคำสั่งซื้อที่ชำระแล้วพร้อมลายเซ็นของตัวเอง กิจกรรมแคมเปญ Tiltify และสมาชิก Patreon แบบเสียเงินยังเป็นการเชื่อมต่อในอนาคต
