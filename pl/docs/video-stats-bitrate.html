Statystyki wideo i przepływność

Pokazuj przepływność przychodzącego strumienia w prawym górnym rogu doku Social Stream Ninja.

Ważne: SSN nie odczytuje automatycznie przepływności z OBS ani platformy transmisyjnej. Odpytuje API statystyk serwera wideo odbierającego Twój strumień.

Do czego służy

Daje to prowadzącemu lub producentowi mały bieżący odczyt przepływności w doku. Przydaje się, gdy OBS, mobilny enkoder lub inny nadawca publikuje do Twojego własnego serwera przekaźnikowego lub odbierającego.

SSN normalizuje także dostępne dane opóźnienia, bufora, utraty pakietów, czasu działania, kodeka i widzów do video_stats zdarzenia metadanych. Standardowy odczyt doku pokazuje wyłącznie przepływność.

Zgodność

  • SRT Live Server / SLS: JSON /stats punkt końcowy zawierający publishers obiektu.
  • Belabox Cloud: jego odpowiedź statystyk odbiornika/przekaźnika JSON w stylu SRT.
  • NGINX RTMP: XML z modułu statusu NGINX RTMP.
  • Node Media Server: jego API strumieni JSON, z opcjonalnym uwierzytelnianiem HTTP Basic.
OBS nie jest źródłem statystyk: OBS może wysyłać wideo do zgodnego serwera, ale OBS WebSocket i źródła przeglądarkowe SSN nie dostarczają tych danych.

Jak używać

  1. Włącz punkt końcowy statystyk HTTP zgodnego serwera i potwierdź, że komputer z SSN może otworzyć jego adres.
  2. W SSN Ustawienia globalne, włącz Odpytywanie statystyk wideo.
  3. Wybierz typ źródła i wpisz adres statystyk.
  4. Dla SRT lub Belabox wpisz dokładny identyfikator nadawcy, na przykład publish/live/feed1. SSN automatycznie go używa, gdy odpowiedź zawiera tylko jednego nadawcę.
  5. Dla NGINX RTMP lub Node Media Server wpisz aplikację i klucz/nazwę strumienia, na przykład live i feed1.
  6. Dodaj autoryzację, jeśli jest wymagana. Pole klucza API SRT jest wysyłane jako pełny Authorization nagłówek. Node Media Server używa nazwy użytkownika/hasła jako uwierzytelniania HTTP Basic.
  7. Wybierz odstęp odpytywania od 1 do 60 sekund; domyślnie pięć sekund.
  8. W opcjach doku włącz Pokazuj metadane przepływności, jeśli są dostępne; prawy górny róg, a następnie otwórz lub odśwież link doku.
  9. Rozpocznij publikowanie wideo. Przepływność pojawia się po prawidłowej odpowiedzi wskazującej transmisję online.

Jeśli nic się nie pojawia

  • Potwierdź, że obie opcje statystyk wideo są włączone w SSN.
  • Potwierdź, że punkt końcowy odpowiada w ciągu pięciu sekund, a typ źródła i identyfikatory strumienia są zgodne.
  • 127.0.0.1 oznacza komputer uruchamiający SSN. Gdy serwer jest innym urządzeniem, użyj jego adresu LAN.
  • Odczyt znika, gdy transmisja jest offline, brakuje przepływności lub wynosi ona zero albo przez około 130 sekund nie docierają świeże statystyki.

Zaawansowane: protokół, formaty i jednostki

SSN wykonuje przez HTTP lub HTTPS GET w skonfigurowanym odstępie, z wyłączoną pamięcią podręczną i limitem czasu pięciu sekund.

SRT Live Server / SLS i Belabox Cloud

{
  "publishers": {
    "publish/live/feed1": {
      "bitrate": 4500, "rtt": 32.5, "msRcvBuf": 120,
      "mbpsRecvRate": 4.5, "mbpsBandwidth": 12.8,
      "pktRcvDrop": 2, "pktRcvLoss": 1,
      "bytesRcvDrop": 2632, "bytesRcvLoss": 1316, "uptime": 3600
    }
  }
}

bitrate jest w Kbps; RTT i bufor odbioru w milisekundach; szybkość odbioru i przepustowość w Mbps; czas działania w sekundach; wartości strat/odrzuceń to liczby pakietów lub bajty.

NGINX RTMP

Adres musi zwracać XML statusu NGINX RTMP. SSN dopasowuje skonfigurowaną aplikację i strumień. Odczytuje bw_video jako bajty na sekundę i dzieli przez 1024 dla bitrateKbps. Odczytuje również czas transmisji i opcjonalne metadane kodeków wideo/audio.

Node Media Server

SSN odpytuje STATS_URL/APPLICATION/STREAM_NAME. Pola mogą znajdować się na najwyższym poziomie lub wewnątrz data.

{ "data": { "isLive": true, "bitrate": 4500, "viewers": 3, "duration": 3600 } }

Bitrate jest w Kbps, viewers to liczba, a duration jest w sekundach.

Znormalizowane zdarzenie SSN

{
  "type": "generic",
  "event": "video_stats",
  "meta": {
    "provider": "srt-live-server", "source": "srt-live-server",
    "label": "SRT", "online": true,
    "updatedAt": "2026-07-13T14:45:00.000Z",
    "bitrateKbps": 4500, "rttMs": 32.5, "bufferMs": 120,
    "summary": "4500 Kbps, 33 ms, 120 ms"
  }
}
PoleJednostka/typ
bitrateKbpsKbps, liczba całkowita
rttMs / bufferMsMilisekundy
recvRateMbps / bandwidthMbpsMbps
Pola strat/odrzuceńLiczba pakietów lub bajty
uptimeSeconds / durationSecondsSekundy
onlineWartość logiczna; false ukrywa wartość w doku

Dok przyjmuje meta.bitrateKbps, z meta.bitrate i meta.kbps jako wartości zapasowe. Wartości poniżej 1000 są wyświetlane jako zaokrąglone Kbps; większe jako Mbps zaokrąglone do jednego miejsca po przecinku. Adres statystyk, klucz strumienia i dane uwierzytelniające nigdy nie są wysyłane do nakładek.
