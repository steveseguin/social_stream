Co robi to narzędzie

Ten stronę Create Test Message wysyła syntetyczne dane Social Stream do doku, nakładek, alertów lub konfiguracji Event Flow. Użyj go do testowania bez czekania na prawdziwą wiadomość czatu, wpłatę, członkostwo, najazd, nagrodę lub inne zdarzenie.

W miarę możliwości używaj sesji testowej. Przesłana wiadomość zachowuje się jak przychodzący ruch sesji i może uruchamiać alerty, dźwięki, webhooki, akcje OBS lub inne automatyzacje.

Szybki start dla SSApp lub rozszerzenia

  1. Otwórz Social Stream Ninja i upewnij się, że usługa jest aktywna.
  2. W sekcji Ustawienia globalne i narzędzia → Mechanika, włącz zdalne sterowanie rozszerzeniem przez API. SSApp używa tej samej nazwy ustawienia.
  3. Skopiuj identyfikator sesji z Social Stream lub z wartości session= w adresie URL doku lub nakładki.
  4. Otwórz Utwórz wiadomość testową (Create Test Message) i wpisz ten identyfikator sesji.
  5. Pozostaw Wyślij przez (Send Via) ustawione na Odbiór przez API rozszerzenia (Extension API ingest) do zwykłych testów.
  6. Wybierz preset, dostosuj jego pola i wybierz Wczytaj preset (Load Preset).
  7. Sprawdź Payload JSON, a następnie wybierz Wyślij (Submit).
  8. Potwierdź, że element pojawia się w doku lub docelowej nakładce oraz że oczekiwana automatyzacja działa.

Możesz umieścić sesję w adresie URL: createtestmessage.html?session=YOUR_SESSION_ID.

Przykład: jedna sztuczna wiadomość o 1 000 KICKs

Tworzy to jedną wiadomość wsparcia w stylu Kicka o wartości 1 000 KICKs. Nie tworzy 1 000 oddzielnych wiadomości.

  1. Wybierz Wiadomość czatu (Chat Message) preset.
  2. Ustaw Wpisz na Kick.
  3. Wpisz testową nazwę i wiadomość.
  4. Ustaw Kwota wsparcia (Has Donation) na 1000 KICKs.
  5. Wybierz Zaktualizuj JSON z pól (Update JSON from Fields), sprawdź JSON i wyślij go.

Minimalne dane to:

{
  "type": "kick",
  "chatname": "Test Supporter",
  "chatmessage": "Thanks for the stream!",
  "hasDonation": "1000 KICKs"
}

Użyj Wiadomość czatu (Chat Message) w tym przykładzie. Preset Wpłata / Cheer (Donation / Cheer) zawiera pola cheer właściwe dla Twitcha.

Używanie presetów i własnego JSON-u

Presety dostarczają początkowych danych dla typowych przypadków, takich jak wpłaty, subskrybenci, subskrypcje w prezencie, najazdy, nagrody, aktualizacje liczby widzów, osoby piszące pierwszy raz i zdarzenia pociągów.

  • Wczytaj preset (Load Preset) zastępuje JSON wybranym presetem i bieżącymi wartościami pól.
  • Zaktualizuj JSON z pól (Update JSON from Fields) tworzy podstawową wiadomość na podstawie widocznych pól.
  • Możesz edytować Dane JSON (Payload JSON) bezpośrednio podczas testowania konkretnego pola lub struktury zdarzenia.
  • hasDonation zawiera widoczną kwotę wsparcia, na przykład 1000 KICKs lub $10.00.
  • Dodawaj event tylko podczas testowania rzeczywistego nazwanego zdarzenia. Zwykły wiersz czatu z wpłatą może używać hasDonation samodzielnie.

Definicje pól i rzeczywiste przykłady platform znajdziesz w Dokumentacja wydarzeń.

Typowe rozwiązania

  • Nic się nie pojawia: potwierdź, że strona docelowa jest otwarta i używa tego samego identyfikatora sesji.
  • Odbiór przez API rozszerzenia nie działa: włącz zdalne sterowanie rozszerzeniem przez API, a następnie przeładuj dok lub nakładkę i spróbuj ponownie.
  • Tryb bezpośredni zgłasza wysłanie, ale nic się nie pojawia: użyj Extension API ingest, chyba że docelowy adres URL ma pasujący &server lub &server2 tryb.
  • Uruchamia się niewłaściwe zdarzenie: sprawdź Payload JSON pod kątem pól pozostałych z innego presetu.
  • Test Kicka zachowuje się jak Twitch: użyj presetu Chat Message i ustaw type i hasDonation jak pokazano powyżej.
  • Automatyzacja uruchamia się więcej niż raz: sprawdź, czy w tej samej sesji nie jest otwartych kilka doków, stron akcji lub instancji Event Flow.
