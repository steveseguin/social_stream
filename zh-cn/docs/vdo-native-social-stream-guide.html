VDO.Ninja 原生应用 + Social Stream Ninja

在 VDO.Ninja 原生移动应用内接收 Social Stream Ninja 聊天。

此设置的作用

Social Stream Ninja 在电脑上运行，从 Twitch、YouTube、Kick 或其他来源捕获聊天，再将消息转发到手机上的 VDO.Ninja 原生应用。

手机是接收方，不直接连接 Twitch 或你的聊天平台。

1. 启动 Social Stream 来源

  1. 在负责收集聊天的电脑上打开 Social Stream Ninja。
  2. 设置 Social Stream Ninja 会话 ID。
  3. 打开所需平台来源，例如 Twitch、YouTube、Kick 或 TikTok。
  4. 检查手机前，先确认消息已出现在 Social Stream 来源窗口或停靠面板中。

可以使用 Twitch WebSocket 来源模式。该模式仅控制 SSN 如何捕获 Twitch 聊天，与手机的 Peer-to-Peer 或 Server 模式相互独立。

2. 在手机上打开发布设置

  1. 打开 VDO.Ninja 原生应用。
  2. 选择想使用的摄像头、屏幕或麦克风模式。
  3. 在 Publishing Settings 屏幕中向下滚动至 Social Stream Ninja Integration。

3. 使用相同的会话 ID

启用 Social Stream，并粘贴与电脑上 SSN 完全相同的会话 ID。

4. 选择一种连接模式

手机模式SSN 设置适用情况
点对点（Peer-to-Peer） 使用普通 SSN P2P 输出。不要仅通过 API 服务器路由聊天。 建议首先选择。无需本地服务器，可通过普通互联网连接使用。
服务器 启用 将聊天消息发送到 API 服务器 ，位置为 SSN Global > Mechanics。 P2P 被阻止或不可靠时使用此模式。

不要混用模式。如果手机使用 Peer-to-Peer，而 SSN 仅通过 Server 模式发送，手机将无法接收聊天。如果手机使用 Server 模式，但 SSN 未向 API 服务器发送聊天，手机也无法接收。

5. 连接并测试

  1. 点击 连接 ，在 VDO.Ninja 原生应用中操作。
  2. 发送一条真实聊天消息，或使用 SSN 测试消息。
  3. 查看手机。如果手机显示 Social Stream 未连接（Social Stream not connected），则聊天来源可能仍在工作，但 SSN 到手机的传输未连接。

常见失败情况

症状实际原因解决方法
SSN 中出现聊天，但手机显示 Social Stream not connected。 平台来源工作正常，但 SSN 到手机的输出路径未连接。 检查会话 ID、连接模式及 SSN 输出设置。
同一会话 ID 在一台电脑上可用，在另一台上不可用。 在 Peer-to-Peer 模式下，SSN 使用会话 ID 作为 VDO.Ninja 流 ID 发布。同一时刻只能有一个 SSN 实例发布该 ID。 关闭或禁用第一台电脑上的 Social Stream，再重启第二台电脑上的 SSN；或使用不同的会话 ID。
Server 模式始终收不到聊天。 手机正在监听 SSN API 服务器频道，但 SSN 未在那里发布聊天。 启用 将聊天消息发送到 API 服务器 ，位置为 SSN Global > Mechanics。
来源窗口显示聊天，但没有转发任何内容。 来源可能处于仅回复或不捕获模式。 禁用 机器人仅回复（不捕获） 为该来源设置。
远程手机无法使用本地服务器模式。 本地服务器模式仅限电脑或局域网，通常无法穿过防火墙访问。 使用 Peer-to-Peer，或使用公共 Server 模式并启用 SSN 的 API 服务器聊天输出。

BTTV、7TV 和 FFZ 表情

转发聊天前，在 SSN 中启用 BTTV、7TV 或 FFZ 表情选项。SSN 会在消息到达手机前丰富其内容。

如果应用版本不渲染内嵌聊天图片，原生应用的聊天显示可能仍使用图片表情的备用文字。
