在平台之间转发聊天

有计划地设置 Twitch 和 YouTube 聊天转发，选择发送账号，并排查消息重复问题。

所有指南 1. 确认两个聊天室都能接收回复 2. 在 Event Flow 中创建 Twitch → YouTube 转发 3. 添加反向转发 4. 了解回流消息 5. 缩小转发范围 故障排除

1. 确认两个聊天室都能接收回复

将 Twitch 和 YouTube Live 聊天室连接到同一个 SSN 会话。确认两者都出现在停靠面板中，然后分别选取来源标签页已知的消息，手动回复一次。请使用自己的测试频道。只读的捕获源无法发送转发消息。

此配置中只应打开预期的目标聊天室。同一平台的目标可能包含该平台上多个符合条件的来源标签页。如果使用独立的 Twitch 机器人账号，请先完成 用于回复的机器人账号 。

2. 在 Event Flow 中创建 Twitch → YouTube 转发

打开 Event Flow 编辑器 ，可从 SSN 菜单进入（“Actions 叠加层”区域也有链接）。创建一个流程，并赋予清楚的名称，例如 Twitch 转 YouTube.

  1. 添加一个 来自来源（From Source） 触发器，位于 用户与来源。选择 Twitch 作为来源。
  2. 添加一个 转发聊天（Relay Chat） 操作，并将触发器输出连接到该操作的输入。
  3. 选择该操作。将以下选项设为 转发目标 为 YouTube，并将消息模板保持为 [{source}] {username}: {message}.
  4. 选择 保存流程 并启用已保存的流程。保持 SSN 运行。
  5. 在自己的 Twitch 测试聊天室发送一条新的普通消息。确认 YouTube 收到一份带标签的副本。

YouTube Shorts 有独立的来源类型和目标。请按需选择 YouTube Shorts ；它与 YouTube 不能互换。

3. 添加反向转发

创建第二个流程，命名为 YouTube 转 Twitch: From Source: YouTube → Relay Chat: Twitch。保存并启用。从两端各发送一条新消息，确认每条消息都只在另一平台出现一份副本。

保持 转发所有消息（不推荐！） 关闭，以免另一个转发系统重复执行相同操作。也请检查是否已有其他机器人或多平台直播服务在连接这些聊天室。

4. 了解回流消息

回流消息是指 SSN 发送后，又从目标聊天室捕获到的消息。目前的 Relay Chat 操作会自动跳过已识别的回流消息，也会排除原始来源标签页。

如需在停靠面板和叠加层中隐藏捕获到的回流消息，请添加一个 回流过滤器（Reflection Filter） 操作，放在相关流程的前部，并选择 全部阻止. 允许第一条 会在配置的时间窗口内保留一条匹配的回流消息； 全部允许 会显示它们。此设置控制捕获后的显示，不决定转发目标。

目前 Relay Chat 的属性中没有“No Reflections”复选框。请使用独立的 Reflection Filter 控制显示。如果外部服务改写了转发消息，自动识别可能无法捕捉到它。

5. 缩小转发范围

如需筛选命令，请添加一个 消息开头匹配（Message Starts With） 触发器，设为 ! ，将其连接到一个 非（NOT） 逻辑门；再使用以下逻辑门将结果与来源条件组合： 与（AND） ，放在 Relay Chat 之前。有关连接逻辑门的说明，请参阅 Event Flow 指南 。请分别测试普通消息和命令。

如果改用较简单的全局转发，请使用 全局设置和工具 → 命令 → 选择转发目标 并输入 twitch,youtube。列表留空表示所有符合条件的目标。此列表控制接收目标，不限制哪些传入平台可以触发转发。启用此替代方案前，请先停用 Event Flow 中的双向转发。

SSApp 在同一“命令”区域提供账号角色允许/阻止字段，可限制哪些账号发送转发消息。请使用分配给预期发送账号的角色；角色不匹配可能导致没有符合条件的目标。

故障排除

  • 没有发送任何消息： 重试手动回复，验证登录状态和发言权限，启用已保存的流程，并检查目标和账号角色限制。
  • 消息不断增多： 先停用转发流程。检查重复的捕获源、全局“转发所有消息”和外部转发机器人，然后再单向重试。
  • 只有停靠面板显示重复消息： 检查 Reflection Filter 的显示策略，以及全局“消息 - 可见性”中的回流显示设置。
  • YouTube 目标不正确： 检查 YouTube 与 YouTube Shorts 的选择，并关闭不需要的、符合转发条件的聊天室。

Test Flow 操作可以发送真实消息。请使用受控的目标；模拟测试无法证明实际来源的账号路由正确。
