事件和提醒兼容性

将捕获到的平台事件连接到 Multi Alerts，避免混淆普通聊天、打赏和事件载荷。

从事件来源开始

Multi Alerts 展示的是 Social Stream 已经捕获到的事件。它本身不会登录 Twitch、Kick、YouTube、TikTok 或其他平台。

  1. 连接并激活提供该事件的平台来源。
  2. 保持该来源页面或独立应用的来源窗口活跃。
  3. 在来源、弹出菜单、停靠面板和 Multi Alerts URL 中使用相同的 Social Stream 会话 ID。
  4. 排查平台连接前，先从提醒叠加层的选项中测试它。

预览成功证明提醒布局正常。 这不能证明平台来源有权接收该真实事件。

标准模式与 WebSocket 模式

平台标准捕获WebSocket / API 捕获
YouTube 付费消息、会员、会员赠礼、观众更新，以及有限的页面检测事件。 共同支持的付费/会员事件，以及会员里程碑、近期公开订阅者提醒和受支持的计数更新。
Twitch 在聊天中呈现的奖励、赠送订阅通知、观众更新，以及一些仅在页面中出现的通知。 在账号和权限范围允许时，EventSub 会增加关注、订阅、续订、cheers、raids、奖励，以及受支持的计数/状态事件。
Kick 聊天，以及礼物、奖励和观众更新的轻量页面标记。 身份验证后可接收官方的关注、订阅、礼物、奖励兑换、KICKs、管理和直播状态事件。

对于由事件触发的提醒，WebSocket 模式通常是合适的选择。当仅需要页面中显示的聊天，或无法进行身份验证时，标准捕获仍然有用。

启用所需的提醒类型

从 Social Stream 设置中打开 Multi Alerts 选项。关注、订阅、打赏、Bits 和 raid 都有各自的启用、样式、声音和外观控件。拍卖和 Hype Train 提醒需要通过专用选项主动启用。

  • 使用 提醒排队 ，适用于可能同时到达多个事件的情况。
  • 事件在停靠面板正常，但在 Multi Alerts 中不正常时，请检查来源过滤器。
  • 缺少小额打赏或 cheers 时，请检查最低现金/打赏过滤器。
  • 如果自定义提醒音频被自动播放规则阻止，请先与浏览器页面互动一次。

真实提醒缺失时

  1. 确认在来源自身的日志、停靠面板或 API 输出中收到了该事件。
  2. 确认来源和 Multi Alerts 页面使用相同的会话 ID 和密码。
  3. 确认该类别已启用，且未被来源或频道过滤器排除。
  4. 检查打赏和 Bits 的最低金额过滤器。
  5. 对于 Twitch 或 Kick，如果聊天正常但受保护的事件不正常，请重新登录。
  6. 让来源窗口保持活跃，足够长时间以观察到真实事件；仅有预览不算平台的端到端测试。

如果涉及多个设备或连接模式，请查看 会话、密码与中继模式.
