本地服务器和服务说明

Social Stream Ninja 使用几种不同的本地服务。请选择与你的目标相符的一种。

1. 启用本地服务器

此“文件”菜单选项会在桌面应用内启动支持房间和频道的 WebSocket 中继。受支持的 Social Stream 页面可用它在同一台电脑上交换聊天和命令。它是页面专用服务器路由的替代端点。

它不会托管 Social Stream 网站、独立捕获平台，或提供 HTTP 自动化 API。请先阅读 启用本地服务器指南.

2. 本地控制 API 与 MCP

此可选启用的回环 API 让 SSApp 电脑上的程序管理受支持的来源和设置、读取状态和诊断、检查应用或来源窗口，以及跟踪捕获事件。随附的 MCP 适配器将这些操作作为工具提供给兼容的 AI 客户端。

在以下位置启用： 文件 > 本地 AI / 自动化。它与以下功能分开： 启用本地服务器。请参阅 本地控制 API 与 MCP 指南.

3. 无头家庭服务器或 VPS

无头模式运行完整的 Electron 桌面应用，同时隐藏来源窗口。在 Linux 上仍需要 Xvfb 等显示后端。它适合让专用电脑在不连接显示器的情况下持续捕获聊天。

无头模式不会创建公开控制 API。远程控制使用 Social Stream 的常规 WebRTC 或 WebSocket 传输。参阅 无头托管指南.

4. 本地媒体服务器

当本地 Event Flow 媒体可用时，桌面应用会自动启动此服务。它通过每个配置独有的随机令牌路径，仅提供经 SSApp 批准的文件和选定的运行时资源。

它不是通用 Web 或文件服务器。参阅 Event Flow 媒体文件 ，在本地文件、上传和云端托管之间选择。

服务器备用模式有所不同

例如这些设置： 将聊天消息发送到 API 服务器 和 停靠面板通过服务器向扩展发送命令 用于选择聊天和命令的路由方式。生成的 URL 标志包括 server, server2，以及 server3.

这些设置通常使用 Social Stream 的托管 WebSocket 服务。如果受支持的页面还带有 localserver，则改用桌面应用的本地中继。参阅 会话、密码、中继与服务器模式 ，查看路由控件。

使用刚生成的链接。 路由标志因页面而异。不要将一个页面的服务器标志复制到另一个页面，并假定含义相同。

其他临时本地端口

某些登录和账号关联流程会短暂打开回环回调端口，并在流程结束后关闭。这些临时监听器不是通用 SSN 服务器或自动化 API。
