独立应用模式

了解来源窗口、标准模式、WebSocket 模式和 TikTok 预设。

应用的用途

桌面应用在普通浏览器之外管理 Social Stream 来源窗口。它可帮助整理来源并解决一些浏览器标签页限速问题。它与 Chrome 不同，不会自动共享 Chrome 登录状态或 Cookie。

模式名称

有些来源有多种连接模式。正确模式取决于平台、登录状态，以及您需要更丰富的事件还是简单页面捕获。

模式通俗含义适用情况
标准应用打开普通平台／来源页面并读取已渲染的页面。您需要最简单的可见页面捕获、登录或手动验证。
WebSocket/API来源通过平台 API、套接字或 Social Stream 来源页面连接。平台支持该模式，且您希望获得更可靠的后台运行或更丰富的事件数据。
轮询／旧版通过检查更新来工作的兼容路径，而不是使用首选的实时套接字路径。新连接器失败，或需要平台专用回退方式。
TikTok 自动应用选择最佳 TikTok 路径，并可能在某条路径失败时回退。您不确定使用哪种 TikTok 模式。

适合使用标准模式的情况

  • 在能看到直播页面或弹出聊天时，平台可以正常工作。
  • 网站要求您登录、完成提示验证，或保持聊天面板可见。
  • 您正在比较应用与 Chrome 扩展的行为。
  • 您需要最熟悉的排查路径：打开页面、看到聊天、测试停靠面板，然后测试 OBS。

如果平台更改页面布局、阻止嵌入式／应用浏览器、要求验证码或将聊天藏在登录之后，标准模式仍可能失败。

适合使用 WebSocket 或 API 模式的情况

  • 来源明确支持 WebSocket／API 模式。
  • 您希望来源在后台也能更稳定地工作。
  • 您需要普通页面抓取可能无法提供的事件类别。
  • 您能处理提供商令牌、账号权限、API 范围或来源页面设置。

WebSocket／API 模式不一定更好。如果身份验证、令牌、提供商访问或平台 API 失败，标准模式可能更便于快速测试。

应用中的 TikTok

桌面应用中的 TikTok 不只有一种模式。故障排查前，请始终记录当前启用的预设。

TikTok 路径使用场景常见故障点
自动大多数用户应首先尝试。应用可能回退，请检查状态文字。
标准捕获可见 TikTok 页面。登录、验证码、重定向页面或隐藏聊天。
本地签名器应用原生的读取和回复支持路径。应用中的 TikTok 会话／Cookie 必须有效。
轮询／兼容套接字／签名路径失败时的回退方式。信息不如首选连接器丰富。
代理或自定义签名高级设置。提供商可用性、API 密钥、房间 ID 或速率限制。

首次常规尝试时，添加 TikTok，将预设保留为自动，启用来源，并观察应用状态文字。

使用 OBS 前要检查什么

  1. 确认应用来源已启用。
  2. 如果平台需要登录，确认来源窗口已登录。
  3. 确认停靠面板通过相同会话 ID 收到聊天。
  4. 只有停靠面板正常后，才添加或刷新 OBS 叠加层 URL。
  5. 如果 Chrome 正常但应用不正常，请记住应用会话和 Chrome 会话是分开的。

常见解决办法

  • Chrome 已登录但应用未登录： 在应用来源窗口内登录平台，或使用扩展作为捕获方式。
  • 来源显示活动，但没有聊天到达： 检查模式、来源窗口、直播 URL／用户名和停靠面板会话。
  • 应用正在使用错误的来源文件： 检查应用使用的是打包、缓存、远程、beta、稳定版还是本地 Social Stream 资源。
  • TikTok 失败： 记录当前预设、状态文字、应用版本，以及来源是否切换到回退模式。
  • OBS 空白： 先测试停靠面板。如果停靠面板为空，问题还不在 OBS。
