抽奖、票券和积分奖品

初次使用抽奖工具？请先阅读 你的第一次抽奖：附截图的操作指南.

使用一台主机运行抽奖。弹出菜单、Stream Deck 和 Event Flow 控制该主机；观众显示页面展示其已提交的结果。

进行第一次免费抽奖

  1. 在弹出菜单中打开 抽奖选项。将 ID 保持为 default，关键词设为 !enter，票价和积分奖品都设为零。
  2. 选择获胜者卡片、姓名滚轴或社群转盘。预览显示效果，然后将链接复制到 OBS 浏览器源。
  3. 选择 开放报名。观众在被捕获的聊天中发送关键词即可报名。
  4. 选择 关闭报名，然后 抽出获胜者。即使忘记先关闭报名，抽奖也会自动关闭它。
  5. 选择 新一轮 开始另一次抽奖。之前的获胜者会保留在主机历史记录中。

保持 SSN 主机运行，无需与 OBS 浏览器源交互。社群独立转盘仍可在没有以下参数时使用： &managed；积分和远程控制使用受管理模式。

用 SSN 积分支付的票券

  1. 启用现有的 忠诚度积分系统 ，位于弹出菜单中。这些是 SSN 积分，与 Twitch 频道积分和各游戏分数彼此独立。
  2. 位于 票券和积分奖品，设置每张票的积分和每位观众可购买的最大票数。价格为 1 表示每个积分可买一张票。
  3. 开放报名。对于名为以下 ID 的抽奖： friday，观众可以用以下命令购买五张票： !ticket friday 5.
  4. 在以下位置检查参与者： 管理抽奖和历史记录。购买成功时，扣费和报名会同时完成。余额不足时不会生成票券。

购买票券会立即预留积分，因此同一批积分不能同时购买贴纸或参加另一个付费抽奖。开奖会消耗这些积分。 取消并退款 会退回预留积分。在抽奖前移除某位参与者，会退回该参与者的预留。付费轮次不能通过“新一轮”默默丢弃。

第一份报名后规则即锁定。关闭/开放可用现有规则暂停或恢复该轮。要更改价格或资格，请取消并创建另一轮。观众加入后不能切换钱包，也不能更改在奖池中选择的一方。

赠送积分

设置 每位获胜者的积分奖品 和 奖品数量 ，请在开放前设置。每个奖品会向所选观众的现有账号增加指定数量的 SSN 积分。这会创造积分，不会从票券收入或操作员钱包中扣除。总发放量受配置的奖品金额和获胜人数限制。

多个奖品需逐个抽出。每位确定的获胜者都会先被记录，再播放显示动画。已完成的抽奖无法通过取消来撤销已知结果。应通过有意识的主机积分调整来纠正错误；更改显示或重新连接绝不会再次发奖。

带积分奖励的游戏

受管理的数字寻踪

选择 数字寻踪（主播控制），票价为 0、奖品数为 1，并可设置积分奖品。主播选择 1–100 之间的数字。玩家使用 !guess friday 50，将其中的抽奖 ID 替换为实际值。猜对后会奖励第一位符合资格的解题者一次；猜错则为所有人缩小范围。每位观众每五秒可猜一次。

使用受管理的抽奖显示，或 games/numberhunt.html?session=YOUR_SESSION&managed&giveaway=friday。普通“数字寻踪”和其他现有游戏保留原来的本地行为。它们的本地分数和获胜者标签不会自动发放 SSN 积分。

抛硬币奖池

这是一个概率游戏。选择 抛硬币奖池，价格设为 1、结果数设为 1、额外奖品设为 0。观众使用以下命令下注： !ticket friday 3 heads 或 !ticket friday 3 tails。两边都需要有参与者。关闭报名并开奖：主机会以相同概率选择正面或反面，不受两边下注总额影响。

获胜观众收回自己的下注，并按各自下注比例分享输方的下注。整数积分分配后的余数优先分给小数部分最大的份额，若相同则按报名顺序决定。不收取费用，也不创造额外积分。例如获胜方下注为 2 和 1、输方共 5 分时，8 分奖池分别支付 5 和 3。开奖前取消可为所有人退款。如果一边没有人，开奖会被拒绝，此时可取消并退款。

多个抽奖

使用字母、数字、连字符或下划线，为每个抽奖设置简短 ID。观众在所有 ID 下的购买共享同一个钱包可用余额。每个 OBS URL 都包含 &giveaway=ID。购票和猜数字命令会明确指定抽奖。并行的免费抽奖应使用不同关键词：含糊的免费关键词不会意外同时报名多个抽奖。

弹出菜单字段是配置值。请刷新或打开管理器，查看主机实际提交的规则。更改观众链接只会改变显示设置，不会重写正在运行的轮次的票券规则。

OBS 与展示

受管理显示的默认背景透明。可按需选择主题面板。卡片、滚轴和社群转盘共享同一结果和六种配色。减少动态效果的偏好会跳过揭晓动画。转盘最多预览 120 个名字；它只是揭晓动画，不完整代表每张票的中奖概率。实际选择使用完整的合资格票券池。

重新连接时，显示页面会展示已保存的结果。显示页面连接成功并不能告诉 SSN 该 OBS 场景当前是否可见。请保密控制器 URL、会话 ID 和备份文件。

Event Flow

添加 抽奖 / 票券 ，位于积分操作中。选择“报名免费抽奖”、“购买票券”、“赠送免费票券”、“关闭报名”、“抽出获胜者”、“取消并退款”或“查询状态”。选择 ID 和票数；购买奖池下注时选择正面/反面。该操作使用捕获到的观众身份。赠送票券或执行操作员控制前，请使用受信任的触发器/过滤器。

“购买票券”本身已经花费积分。 不要在它之前放置 Spend Points。失败会停止依赖的后续操作，但不会隐藏原始聊天。结果可在以下位置获取： meta.giveawayControlResult。Event Flow 测试面板会模拟此操作，而不购买真实票券。涉及实际轮次变化的端到端测试，请使用独立的主机/配置文件。

购买资格以操作执行时已提交的余额为准。不要依赖报名消息本身赚取最后一个所需积分。原生来源消息 ID 可提供持久的重放保护；没有这种 ID 的来源，在跨重启身份识别方面保证较弱。没有捕获到观众/消息 ID 的通用定时事件，不能代表某人购买。

Stream Deck 与 API

原生插件包含“开放抽奖”、“关闭抽奖”、“抽奖”、“取消并退款”、“新一轮抽奖”和“抽奖状态”。默认 ID 为 default。将 {"giveawayId":"friday"} 到 value 字段中，以选择另一轮。Open 也可接受一个 config 对象；否则，已有轮次会保留已提交的规则，新 ID 则使用弹出菜单默认值。

使用现有 P2P 连接或已配置的 WebSocket 传输。按键报告的是 SSN 的响应，不表示 OBS 正在直播。响应超时时，请先查询状态，再尝试新的抽奖。

{"protocol":2,"action":"buygiveawaytickets","get":"callback-1","value":{"giveawayId":"friday","roundId":"ROUND_ID","operationId":"purchase-123","count":5,"actor":{"chatname":"Avery","type":"youtube","userid":"SOURCE_USER_ID"}}}

操作 ID 标识一项业务操作；回调 ID 标识一次响应。重试时保留操作 ID。用同一个 ID 搭配不同参数会失败。有意进行新购买时，请使用新的操作 ID。操作员 API 访问权限可替所提供的参与者消费：不要将其暴露为无需身份验证的公开购买表单。

历史记录、备份与恢复

管理器列出轮次、参与者和获胜历史。可将获胜历史导出为 JSON，或保存完整的版本 2 积分/抽奖备份。完整备份一起包含余额、预留、轮次和操作收据。不会向服务器上传任何内容。

主机重启后，已保存的开放轮次会变为关闭状态以供检查。票券仍保持预留。可按相同规则重新开放、抽奖，或取消并退款。中断的数据库事务要么完整提交，要么不留下部分购买/派奖。没有已提交交付确认的贴纸预留，会在超时后恢复。

完整恢复可用于 没有现有余额或抽奖记录的全新主机。它会恢复整个快照，并保持恢复的轮次关闭。它拒绝覆盖已有数据的主机。恢复轮次前，请先在弹出菜单中恢复原始直播/会话 ID；恢复结果会列出备份中的会话。此备份不替代常规弹出菜单设置。切勿将旧主机和恢复后的主机作为同一经济系统的两个独立权威同时运行。备份是快照，无法包含保存之后发生的交易。

仅导入余额无法恢复未结算的预留。当受影响的资金已被预留时，积分重置和手动覆盖会被拒绝。重置积分不会删除抽奖收据/历史。余额属于当前浏览器/应用配置，轮次则按会话划分。不同配置/设备不会自动同步。清除浏览器数据可能删除本地记录，因此请将备份保存在该配置之外。

可选的服务器备份/同步是未来功能，不包含在此版本中。此实现不会添加上传、服务器凭据、购买的货币或提现功能。

出现问题时

  • 没有报名： 检查 ID/关键词、会员限制、开放状态和所捕获的平台。机器人、私密、历史、重播和带测试标记的报名会被排除。
  • 账号发生变化： 名称/身份变化可能导致钱包归属不明确。请在主机上检查；系统绝不会默默合并跨平台账号。
  • 没有响应： 确保预期的 SSN 主机正在运行，且主机控制已启用。重试前请刷新已提交的状态。
  • 无法重置/导入： 先结算或取消已预留的购买。包含未履行义务的备份，请使用完整恢复。
  • 未知奖励： !spend 要求匹配已配置的奖励和价格；不再因为任意奖励名称而消耗积分。

逐步恢复备份

  1. 保持旧主机停止运行。在新的浏览器配置文件中打开 SSN，并打开抽奖管理器。
  2. 位于 在全新主机上恢复，选择完整备份。等待恢复消息，并记下其中列出的原始会话 ID。
  3. 在弹出菜单的 会话选项，输入该原始会话 ID。
  4. 返回管理器，选择抽奖 ID，然后选择 刷新。检查其规则、参与者和获胜历史。恢复的开放轮次会保持关闭以供检查。
  5. 按相同规则重新开放、抽奖，或选择 取消并退款 退回预留票券。检查结果后保存新的备份。

在 OBS 中，起始浏览器源尺寸使用 1280 × 720。受管理的转盘会适配剩余的来源高度。默认背景透明，无需自定义 CSS；所有常规控件都保留在弹出菜单、管理器或 Stream Deck 中。
