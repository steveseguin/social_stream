会话、密码、中继与服务器模式

同一个匹配的会话将来源、停靠面板、叠加层、提醒和 API 页面连接起来。路由标志也必须匹配。

连接模型

  1. 来源捕获聊天或事件，并发布到 Social Stream 会话。
  2. 停靠面板、精选叠加层、多类型提醒、Event Flow 和其他页面加入同一会话。
  3. 如果设置了密码，每个加入的页面都必须使用相同密码。
  4. 如果启用了服务器路由，活动页面必须使用带有匹配路由参数的新生成 URL。
Source → same session ID + password + routing mode → Dock / overlay / API consumer

会话 ID 和密码

打开 全局设置与工具 → 会话选项 以查看当前会话 ID 并设置可选密码。

值规则
会话 ID保持不变，除非您打算替换所有使用它的来源、停靠面板、叠加层和集成 URL。
密码可选，但设置后必须在所有位置一致。添加或更改后，复制新生成的链接。
生成的链接链接包含密码或其他敏感参数时，应将整个链接视为私密信息。

优先复制生成的 URL。 它们已包含当前会话、密码、页面版本和受支持的路由选项。手动编辑链接是页面空白的常见原因。

启用读取和回复的服务器回退

停靠面板或统一聊天已连接却收不到消息，或因正常点对点路径被阻止或不可靠而回复失败时，使用此功能。

两个回退控件需配合使用： 将聊天消息发送到 API 服务器（供外部监听器使用） 将传入聊天送往服务器路径，而 停靠面板通过服务器向扩展发送命令 将回复和停靠面板命令传回。

快速方法

  1. 打开或重新加载生成的停靠面板链接。
  2. 从 Social Stream Ninja 发送一条模拟测试消息。
  3. 如果 启用服务器备用模式 提示出现时，选择并确认。Social Stream Ninja 会同时启用传入聊天和回复命令的服务器路径。
  4. 复制新生成的停靠面板和叠加层链接。重新打开普通浏览器窗口，并 替换所有已保存的 OBS 浏览器来源 URL.

桌面应用中的手动方法

  1. 打开 Social Stream 桌面应用。在右侧的 来源与设置 面板中，展开 全局设置和工具.
  2. 展开 工作机制 - 连接与集成.
  3. 开启 将聊天消息发送到 API 服务器（供外部监听器使用）。这是传入聊天／读取路径。
  4. 开启 停靠面板通过服务器向扩展发送命令。这是回复／控制路径。
  5. 复制并重新打开新生成的链接。已打开的旧页面和保存的 OBS URL 不会自行更新。

不要启用所有服务器选项。 启用远程 API 控制, 允许停靠面板通过 API 服务器使用和发布以及临时附加投递选项，都不是正常读写回退所必需的。附加投递可能产生重复消息。

默认、中继和 API 服务器模式

控制更改内容何时使用
默认链接 正常的 Social Stream 对等／会话传输，不添加服务器标志。 大多数单机和普通 OBS 设置。
启用通过远程 API 控制扩展 启用扩展 HTTP／WebSocket 控制和传入 Webhook 处理。 外部应用、Stream Deck／API 控制，或受支持的传入打赏 Webhook。
允许停靠面板通过 API 服务器使用和发布 添加页面的 server 路由（在支持时）。 停靠面板／精选工作流程需要远程 API 服务器控制，而非正常路径。
将聊天消息发送到 API 服务器 将捕获的聊天路由到 API 服务器监听器路径，并添加 server2 到受支持的生成链接中。 停靠面板需要服务器回退来接收传入聊天，或 Python、Node 等外部 WebSocket 监听器必须接收聊天。
同时正常发送通过 API 路由的聊天 通过两条路径进行临时附加投递。 仅用于有意进行的混合模式过渡；它可能产生重复消息。
通过服务器发送停靠面板命令 添加 server3 （在支持时），使停靠面板命令通过服务器路径返回。 对等连接被阻止或不可靠，且停靠面板到扩展的命令需要通过服务器。

关于 localserver

某些页面接受 localserver 并使用位于以下地址的本地 WebSocket 端点： ws://127.0.0.1:3000。添加 localserverport=PORT 选择 1024 到 65535 之间的其他端口。无效或省略的值会安全回退到端口 3000。请注意，Social Stream 桌面应用的新安装改用端口 3003 运行本地服务器，并将 localserverport=3003 到生成的链接中，因此若为新安装手写 URL，请自行添加该参数。只有本地服务器实际运行且该页面支持这些参数时，才添加它们。

有关托管 WebSocket 或高级本地服务器设置的截图和分步说明，请参见 托管 WebSocket 与本地服务器模式.

路由参数因页面而异。 server, server2, server3, localserver，以及 localserverport 在各叠加层上并非具有统一行为。请使用该具体页面生成的 URL，不要从其他工具复制标志。

更改会话或路由开关后

  1. 复制新生成的停靠面板或叠加层 URL。
  2. 关闭并重新打开使用旧 URL 的活动浏览器页面。
  3. 替换已保存 OBS 浏览器来源中的 URL，并刷新其缓存.
  4. 会话 ID 或密码更改后，请重新加载或重新启用来源页面。
  5. 发送一条模拟测试消息，并在测试最终叠加层前确认其到达停靠面板。

停靠面板或叠加层空白检查清单

  1. 比较完整的 session= 值，分别在来源、停靠面板和叠加层中检查。
  2. 检查是否有某个 URL 缺少当前的 password=.
  3. 检查旧 OBS URL 是否缺少当前服务器路由标志。
  4. 如果模式不明确，请移除手动添加的路由标志，并复制新生成的 URL。
  5. 先测试停靠面板。如果停靠面板收到消息，再排查叠加层的事件筛选器和 URL 选项。
  6. 参阅 OBS 故障排查 以及 命令与 API 参考 进行进一步检查。
