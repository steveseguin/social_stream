本地控制API和MCP

让同一台电脑上的 AI 工具或脚本检查和控制 Social Stream Ninja 桌面应用。

何时选择此服务

当 SSApp 电脑上的软件需要获准的应用和来源控制时，使用本地控制 API。当兼容的 AI 客户端需要将这些控制作为工具使用时，使用随附的 MCP 适配器。

这与以下功能不同： 文件 > 启用本地服务器，后者会为 Social Stream 页面启动 WebSocket 中继。参阅 本地服务器和服务说明 ，帮助你确定需要哪种服务。

1. 下载常规桌面应用

从以下位置安装当前 Social Stream Ninja 版本： Windows、macOS 或 Linux 下载。下载的应用已包含 MCP 支持。无需源代码仓库、Node、Python 或单独的 MCP 软件包。

2. 启用本地 AI 控制

  1. 打开 文件 > 本地 AI / 自动化.
  2. 启用 本地控制 API ，并让应用重启。
  3. 返回同一菜单并选择 复制 MCP 配置.
  4. 将复制的 JSON 粘贴到 AI 工具使用的 MCP 设置中，然后重启该工具。

复制的配置包含实际安装的可执行文件路径、端口和平台专用参数。AI 客户端使用以下参数启动下载的 Social Stream Ninja 可执行文件时，它会启动自身的轻量 MCP 适配器： --ssapp-mcp.

3. 让 MCP 自动发现能力

连接后，MCP 客户端会自动向 Social Stream Ninja 查询工具。适配器读取运行中应用的实时能力，并向 LLM 提供受支持的工具结构、应用/API 版本和操作说明。代理应先调用 capabilities，再调用 status，并使用应用返回的稳定来源 ID。

常规 MCP 使用无需抓取网站或安装技能。用户只需让已连接的代理检查或控制 Social Stream Ninja。

可用的本地控制

  • 列出、检查、添加、更新和移除来源。
  • 启动、停止或重新加载一个来源，或筛选出的一组来源。
  • 更改来源可见性、静音状态和连接模式。
  • 读取和更新能力发现返回的受支持全局设置。
  • 读取应用、会话、来源、进程、捕获和本地媒体状态。
  • 跟踪有界的已捕获来源事件，以及可恢复的操作或状态事件。
  • 捕获并安全检查受支持的来源页面和 SSApp 自有窗口。
  • 经确认后，执行获准的页面、窗口和对话框交互。
  • 明确确认后，重新加载或正常关闭应用。

以运行中应用报告的能力为准。旧版本可能提供较少的控制项。

本地脚本的直接 HTTP 访问

同一台电脑上的脚本可不经 MCP 使用回环 API。它仅监听 127.0.0.1 ，无需令牌。

GET http://127.0.0.1:17777/api/v1/capabilities
GET http://127.0.0.1:17777/api/v1/status
GET http://127.0.0.1:17777/api/v1/events
POST http://127.0.0.1:17777/api/v1/command

请使用应用公布的能力，不要假定所有版本都有相同控件。可复制粘贴的 curl 示例涵盖添加、列出、启动、检查和停止来源，请参阅 服务器 HTTP API 操作指南.

Ubuntu VPS 上的本地 AI

此 API 也可服务于与无头 SSApp 实例运行在同一台 Linux 服务器上的 AI 工具。请保持绑定到回环地址，并使用下载的 AppImage 作为 MCP 命令。

关注 以无头模式运行 Social Stream Ninja ，了解 Xvfb、持久配置文件、启动命令、systemd 和独立的远程控制路径。其中还包含 Linux AppImage MCP 配置 ，可粘贴到 VPS 上运行的客户端中。

可选的代理技能

支持可安装技能的代理可以 下载完整的 Control Social Stream 技能。你也可以 在线阅读其说明，其中包含 API 参考 和 版本日志。该技能提供工作流程指导，但 MCP 连接本身不需要它。

机器可读的发现链接也列在 llms.txt.

仅限本地

此接口供与 SSApp 运行在同一台电脑上的 AI 和自动化使用。不要将其暴露或通过隧道用作云端远程控制 API。远程用户和 Stream Deck 应使用 Social Stream 现有的 WebRTC 或 WebSocket 连接。本地 API 不提供任意 JavaScript 执行、Cookie、登录机密、不受限的设置或原始文件系统访问。

完整的端点、命令结构、版本发现和安全边界，请参阅 技术自动化参考.
