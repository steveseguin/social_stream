滚动致谢名单指南

收集参与直播的人，并在直播结束时用滚动致谢名单感谢他们。

结束场景的推荐设置

使用 后台收集 ，适用于致谢名单浏览器源仅存在于结束场景，或隐藏时可能被卸载的情况。应用或扩展会在直播期间收集活动，因此致谢名单页面无需一直打开。

  1. 保持 Social Stream Ninja 活跃，并让正常的聊天来源在整个直播期间持续捕获。
  2. 打开 滚动致谢名单 → 启用并自定义.
  3. 选择显示样式并设置 触发模式 为 后台收集 ，请在直播开始前设置。
  4. 复制更新后的致谢名单链接，在 OBS 的结束场景中将其添加为浏览器源。
  5. 使用 测试致谢名单 ，在浏览器源已加载时确认连接和外观。
  6. 直播结束时切换到结束场景，让 OBS 加载或显示致谢名单源。
  7. 选择 开始致谢名单，或触发 creditsStart ，可通过 Stream Deck 或 API 触发。
顺序很重要： 如果 OBS 在浏览器源隐藏时关闭它，请先显示结束场景，再选择 开始致谢名单。“后台”模式仍可收集，但来源必须已连接才能接收开始命令。

选择正确的触发模式

模式活动在哪里收集滚动如何开始最适合的用途
自动在已加载的致谢名单页面内当 OBS 或浏览器使页面可见时自动开始来源在整个直播期间保持加载
手动在已加载的致谢名单页面内开始按钮、Stream Deck 或 API页面保持加载，但你希望精确控制开始时间
后台收集在 Social Stream 应用或扩展内开始按钮、Stream Deck 或 API独立的结束场景，或直播期间关闭/卸载的来源
在直播前设置模式。 “自动/手动”页面数据与“后台收集”数据彼此独立。直播中途切换模式，不会转移另一种模式已经收集的名字。

四个控件的作用

控制结果
开始致谢名单播放实际收集的名单。在“自动/手动”模式下，除非启用了保存或循环，否则滚动结束时会移除已显示的条目。滚动期间收到的新活动会保留至下一次播放。后台数据会一直保留，直到重置。
预览播放当前真实名单，但不消耗它。可在正式开播前检查布局。
测试致谢名单发送内置的参与者、会员和打赏者示例。不会添加、替换或清除真实的已保存名单。
重置已保存的致谢名单清除已保存的后台名单，并通知已连接的致谢名单页面清除其本地名单。

如果 测试致谢名单 提示没有连接致谢名单源时，请加载或显示 OBS 浏览器源后重试。

谁会出现在名单中

致谢名单可识别捕获到的聊天参与者、会员/订阅和打赏类活动。每个人都需要有带名字和平台类型的捕获事件；Social Stream 无法列出平台从未报告的沉默观众。

  • 参与者： 捕获到消息或带名字的活动事件。
  • 会员/订阅者： 捕获到会员字段，或受支持的订阅/会员事件。
  • 打赏者： 捕获到带有打赏值的条目。受支持的币种金额会标准化，用于排序和可选的金额显示。TikTok 连击更新只计算同一次连击内的增量。价格未知的礼物仍会将赠送者列为打赏者，但不会加入猜测的美元金额。TikTok 金币/钻石换算属于估算，不保证实际到账金额。
  • 身份： 同一个显示名称在两个不同平台上会被视为两个来源身份。

默认排名规则中，每次捕获到的活动加 1 分，会员加 50 分，标准化后的打赏金额每美元加 100 分。名单分为 VIP 支持者、常规支持者和直播参与者。启用 优先显示打赏者 ，即可改用更清晰的“直播打赏者”、“频道会员”和“直播参与者”分组。

快速设置、过滤器与已保存数据

  • 循环支持者名单： 会启用循环、保存叠加层数据、仅支持者过滤、打赏优先和打赏金额显示。
  • 仅打赏者： 会启用循环、保存叠加层数据、仅打赏者过滤和打赏金额显示。
  • 仅包含支持者： 包含打赏者和已识别的会员/订阅者，但不包含仅参与聊天的人。
  • 仅包含打赏者： 要求捕获到打赏信号。
  • 在此叠加层中保存致谢名单： 会在刷新和来源切换时保留“自动/手动”的页面收集数据，并防止完成一次“开始”播放后消耗名单。
  • 持续循环致谢名单： 会重新开始动画，并在下一次循环中加入新收集的活动。
后台收集的数据已由应用/扩展针对当前会话保存。关闭致谢名单页面后仍会保留，直到使用 重置已保存的致谢名单 。

OBS 设置详情

  1. 先完成致谢名单选项设置，再复制 URL，以包含所选 URL 参数。
  2. 将该 URL 添加为 OBS 浏览器源。常规的 1920 × 1080 尺寸适合全屏样式。
  3. 使用“自动”或“手动”时，保持来源在整个直播期间加载。在每个场景中重复使用同一个 OBS 源，比创建互不相关的副本更稳妥。
  4. 使用“后台收集”时，来源可以在直播期间不存在或未加载。只需在发送“开始”、“预览”或“测试”前连接即可。
  5. 正式开播前，使用“预览”或“测试”检查字号、速度、类别、透明度和结束语。
OBS 选项： “不可见时关闭源”会停止“自动/手动”收集，因为它们的收集器在页面中运行。此选项与“后台收集”兼容，只要在发送开始命令前先显示来源即可。

Stream Deck 与 API 控制

官方 Stream Deck 插件提供致谢名单的“开始”、“预览”、“测试”和“重置”操作。同样的命令也可通过 Social Stream 的远程控制 API 使用：

操作HTTP 示例
creditsStarthttps://io.socialstream.ninja/SESSION_ID/creditsStart
creditsPreviewhttps://io.socialstream.ninja/SESSION_ID/creditsPreview
creditsTesthttps://io.socialstream.ninja/SESSION_ID/creditsTest
creditsResethttps://io.socialstream.ninja/SESSION_ID/creditsReset

替换 SESSION_ID 为当前活动的 Social Stream 会话。启用 扩展的远程 API 控制 ，位于“全局设置 → 机制”。致谢名单浏览器源必须已连接，“开始”、“预览”或“测试”才能显示在屏幕上。

常见问题

  • 测试正常，但真实名单为空： 测试条目是内置的，不能证明已经收集到活动。确认直播前已选择预期的触发模式，并且聊天来源正在捕获。
  • 重新打开设置后没有控件： “手动”和“后台”模式会显示“开始”和“预览”。“自动”模式则通过可见性触发。
  • 没有连接致谢名单源： 加载/显示 OBS 源，确认使用的是当前复制的 URL 和会话，然后重试。
  • 缺少聊天参与者： “自动/手动”要求致谢名单页面一直保持加载。独立的结束场景请使用“后台收集”。
  • 缺少会员或打赏者： 确认平台来源发出了带名字的会员或打赏事件，并且没有被“仅打赏者/仅支持者”排除。
  • 一次滚动播放结束后名字消失： 启用 在此叠加层中保存致谢名单，使用“预览”，或使用“后台”模式。对于由页面收集的名单，若未启用保存和循环，正常的“开始”运行会消耗已显示条目。
  • 旧名字仍然保留： 选择 重置已保存的致谢名单 ，在下一场直播前执行。后台数据按 Social Stream 会话保存，直到重置。
