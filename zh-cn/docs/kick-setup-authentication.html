Kick 设置与身份验证

使用准确的频道 URL slug，然后选择简单的页面捕获，或更丰富的 WebSocket 提醒来源。

选择 Kick 来源模式

模式最适合登录
标准 从普通聊天页或弹出聊天页读取可见的 Kick 聊天。 公开聊天捕获通常不需要。页面仍必须能加载并显示聊天。
WebSocket 结构化聊天，以及官方的关注、订阅、奖励、KICKs、管理和直播状态事件。 公开聊天可以单独连接，但官方事件订阅、发送聊天以及频道/管理控制需要 OAuth。

使用 URL Slug，而非显示名称

对于 https://kick.com/example-channel，来源值为 example-channel。可以粘贴完整 URL，也可以只输入该 slug。

Kick 显示名称可能与 URL slug 不同。 显示名称可能包含下划线，而 URL 使用连字符。请从地址栏复制 slug，不要根据显示名称重新输入。

桌面应用设置

  1. 选择 添加来源 → Kick.
  2. 粘贴完整 Kick 频道 URL，或输入其 URL slug。
  3. 将 WebSocket 保持选中状态，以使用结构化提醒。应用中的 Kick 目前默认使用 WebSocket 模式。
  4. 选择 激活来源.
  5. 在 Kick 来源窗口中选择 使用 Kick 登录 并批准所请求的权限。
  6. 保持来源窗口打开，并检查“频道”、“聊天套接字”、“桥接”和“订阅”状态标签。

浏览器扩展 WebSocket 设置

  1. 安装并启用当前版本的 Social Stream Ninja 扩展。
  2. 打开 Kick WebSocket 来源页面.
  3. 替换 example-channel 为频道准确的 URL slug。
  4. 选择 连接频道 ，适用于页面未自动连接的情况。
  5. 选择 使用 Kick 登录 ，启用官方事件订阅和账号控制。
  6. 直播期间保持页面打开。

标准捕获模式下，打开 https://kick.com/CHANNEL_SLUG 或其弹出聊天页，并保持聊天可见。

当前 Kick 登录请求的权限

权限组用途
用户与频道读取解析登录用户、频道、分类和当前频道信息。
频道写入从“高级控制”更新直播标题/分类。
奖励读取频道奖励信息，并标准化奖励兑换。
聊天写入从来源发送主播或机器人聊天消息。
事件订阅订阅 Kick 官方实时事件。
管理账号有权限时，封禁/解封用户并管理聊天消息。
KICKs读取 KICKs 相关支持信息。

Kick 当前的 OAuth 流程使用带 PKCE 的授权码登录。不要将访问令牌、刷新令牌、客户端密钥或浏览器 Cookie 粘贴到指南、聊天或支持工单中。

官方参考： OAuth 2.1, 权限范围，以及 Kick API 参考.

当前来源订阅的官方事件

  • 聊天： chat.message.sent.
  • 关注： channel.followed → Social Stream new_follower.
  • 订阅： 新订阅、续订和赠送 → new_subscriber, resub，以及 subscription_gift.
  • 奖励： channel.reward.redemption.updated → reward.
  • KICKs 礼物： kicks.gifted → donation ，并带有 KICKs 数量。
  • 管理： moderation.banned.
  • 直播状态： livestream.status.updated → stream_online 或 stream_offline.

Raid/host 说明： Kick 当前官方 webhook 列表没有发布 raid/host 事件。如果 Kick 通过已连接的数据源暴露此事件，Social Stream 提供兼容处理，但不能认为 Kick raid 提醒保证可用。

请参阅 Kick 当前官方的 webhook 事件列表 以及 Social Stream 的 事件与提醒兼容性指南.

修复无法连接的 Kick 来源

  1. 从 Kick URL 复制准确的频道 slug。
  2. 检查 频道 显示预期的 slug，并且 聊天套接字 从断开状态变为已连接。
  3. 如果聊天正常但官方提醒无效，请重新登录并等待 桥接 和 订阅 进行连接。
  4. 如果内嵌登录或 CAPTCHA 失败，请使用 外部浏览器 ，位于桌面应用中。
  5. 测试发送/管理控件前，确认登录账号拥有该频道，或具有其管理权限。
  6. 排查 OBS 前先检查 Social Stream 停靠面板。如果停靠面板能收到 Kick 数据，剩余问题就在叠加层或 OBS URL。
