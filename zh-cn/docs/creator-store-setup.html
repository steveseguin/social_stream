连接商店，展示商品。

商品与提醒彼此独立

使用 变现 ，在 SSN 中推广公开商品和支持页面、接收活动，或同时执行两者。本指南涵盖 Fourthwall、Ko-fi 和 Buy Me a Coffee。有关 NinjaBacker、Throne、Amazon 和 eBay，请参阅 变现指南.

连接提醒 · Fourthwall · Ko-fi · Buy Me a Coffee · 导入商品 · OBS 与二维码 · 故障排除

连接活动提醒

  1. 打开 变现 → Fourthwall、Ko-fi 与 Buy Me a Coffee 提醒 并选择提供商。
  2. 点击 接收器设置。启用现有的 扩展的远程 API 控制 开关，然后保持 SSN 开启。
  3. 返回“变现”并点击 复制 webhook URL。将此私密地址粘贴到下方对应提供商的 webhook 设置中。
  4. 检查接收器状态。 接收器已连接 表示 SSN 正在监听，不表示提供商配置已通过验证。当经过解析且不重复的提供商事件到达当前运行的应用时，“最后事件”一行会更新；重启后会重置。
  5. 使用 预览示例提醒 ，在单独的示例页面中检查外观。这不会发送付款、更新总额、运行 Event Flow 或验证 webhook 投递。

这三个现有的会话 URL 端点依赖于 URL 保密；SSN 当前的设置不接受它们的签名密钥。它们适合直播提醒，不能作为履约所需的付款证明。请勿公开 webhook 地址，也不要将其用作面向观众的二维码目标。

Fourthwall

  1. 在 Fourthwall 中打开 设置 → 开发者选项 → Webhooks.
  2. 创建 webhook，并粘贴从 SSN 复制的 Fourthwall URL。
  3. 选择所需的受支持事件： ORDER_PLACED, GIFT_PURCHASE, DONATION 和 SUBSCRIPTION_PURCHASED.
  4. 保存 webhook，并保持 SSN 运行。

订单显示为购买，商品赠礼显示为礼物，新订阅显示为会员。为保持兼容，普通 Fourthwall 订单仍保留原有的打赏值。礼品卡兑换订单不会再次增加预付价值。标记为测试的事件会被跳过。

Fourthwall webhook 文档 · 预览示例购买

Ko-fi

  1. 打开 Ko-fi Webhooks.
  2. 将从 SSN 复制的 Ko-fi URL 粘贴到 Webhook URL，然后保存/更新。
  3. 保持 SSN 运行。公开小费、会员付款、商店订单和委托订单使用同一个连接。

私密付款会被排除。会员付款显示为会员活动；商店订单和委托订单显示为购买，不增加打赏总额。Ko-fi 不会通过此 webhook 提供会员取消通知。

测试： 先使用 SSN 的独立示例预览。Ko-fi 示例付款可能与真实付款相似，若发送到活动接收器，可能触发提醒、总额更新和操作。请勿在启用付费奖励的会话中使用提供商测试。

Buy Me a Coffee

  1. 打开 集成 ，在创作者控制台中选择 新建 webhook.
  2. 为其命名，并粘贴 SSN 的 Buy Me a Coffee URL 作为端点。
  3. 选择 donation.created, extra_purchase.created, commission_order.created, wishlist_payment.created 和 membership.started ，按需使用。
  4. 保存并保持投递启用。使用提供商的事件投递历史调查失败原因。

商店和委托订单属于购买。愿望清单付款属于礼物支持。会员开始属于会员公告，不是单独确认的扣款。隐藏备注保持隐藏，匿名支持者保持匿名。控制台中标记为以下类型的测试： live_mode: false 会被跳过，不产生付款提醒。退款和生命周期更新不会创建付款，也不会冲减已有总额。

Buy Me a Coffee webhook 文档 · 预览示例支持

导入 Fourthwall 商品

  1. 在 Fourthwall 的 设置 → 开发者选项，创建一个 Storefront 令牌。请使用店面令牌访问公开商品目录，不要使用管理 API 密钥。
  2. 在 SSN 中打开 商品与支持链接 → 设置商品和链接 → 导入 Fourthwall 商品.
  3. 粘贴公开商品 URL 和令牌，然后点击 加载商品详情.
  4. 检查已加载的名称、图片、价格和公开 URL。确认 URL 与令牌属于同一个商店，包括使用自定义域名的情况。令牌决定查询哪个商店的商品目录。
  5. 选择“购买”、“赠礼”、“支持”或“加入”，说明观众将执行的操作。点击 添加商品或链接，启用“商品与支持链接”，然后 保存设置.

此功能通过 Fourthwall 的 Storefront API，每次导入一个可用的公开商品。令牌仅用于该次请求，之后会被清除，不会保存或发送到叠加层。不同规格的价格和组合商品价格会留空，以免误导为固定结账总额。导入只是当时的快照：价格、库存和图片不会自动刷新。发生变化时请重新导入或编辑。目录最多保存 20 个条目；再次添加会创建另一个条目。

创建 Storefront 令牌 · Fourthwall 商品字段

显示商品、公开链接和二维码

你也可以手动输入任何网站的公开商品或支持链接，包括 Shopify、Tiltify 或 Patreon。添加图片 URL 和可选价格，选择用途，启用目录并保存。添加链接不会连接付款数据源。

  1. 选择 商品与支持链接 ；对应的设置项： 叠加层链接：.
  2. 打开 叠加层链接选项。选择“商品展示”、“支持卡片”、“活动提醒”或组合视图。
  3. 点击 复制 OBS 链接 并将其粘贴到 OBS 浏览器源。初始尺寸使用 800 × 600。如需分开的推广和活动图层，请为每种视图分别创建来源。
  4. 使用“显示选项”固定展示第一个商品或轮播条目。启用二维码，让观众扫描公开目标地址。使用 复制公开链接 ，该按钮位于条目旁，方便你自行在聊天中分享其可点击地址。

商品展示会包含所提供的商品图片；较小的支持卡片会隐藏图片。活动提醒独立运行，不会附上无关的轮播商品二维码。保持公开链接清晰可读，并在最终 OBS 布局下用手机测试二维码。更改 OBS 链接的缩放比例或裁剪过紧，可能导致难以扫码。

对于多重提醒或活动动态，使用它们现有的叠加层链接，并保持相同的 SSN 会话。这些现有活动叠加层不需要启用商品目录。通用的“变现”活动视图则需要启用目录。在 Event Flow 中，对于带有以下字段的条目，仍使用 Donation 触发器： hasDonation；购买或礼物完成事件请使用 Event Type。参阅 事件映射.

如果没有显示任何内容

  • 接收器已关闭： 启用扩展的远程 API 控制。其他 API 开关用于不同用途。
  • 已断开连接： 保持 SSN 开启并检查网络访问。此状态是共享接收器的连接状态，不是提供商控制台中的投递状态。
  • 未收到事件： 检查所选提供商、私密 URL 和提供商的投递设置。本地预览成功仅能验证外观。
  • 事件被跳过： 标记的测试、私密付款、不受支持的事件类型或无效金额会被排除。状态中不会显示买家详情。
  • 收到事件但没有叠加层： 检查会话/密码、来源过滤器、事件类别、SSN 规则和 OBS 可见性。购买不是订阅；大多数购买也不是打赏。
  • 重复内容： 避免同时通过提供商直连和聚合服务传入同一笔付款。重试去重使用提供商的投递 ID。
  • 导入失败： 检查商品 slug、Storefront 令牌，以及商品是否公开且可用。仍可手动输入。

这是直播活动动态，不是订单账本。确认付款、退款和履约请使用提供商控制台。 Shopify 现已提供独立的商品导入和带签名的已付款订单设置。Tiltify 活动动态和 Patreon 付费会员仍是未来计划集成的功能。
