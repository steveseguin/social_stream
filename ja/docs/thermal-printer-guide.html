感熱プリンターと配信ラベル

購入、寄付、チャットイベントを、実物のレシート、ステッカー、チケット、受け取りタグに変えます。

何を印刷できる？

Windows単体アプリは、Windowsにインストールされたプリンターへ、確認ダイアログなしでジョブを送信できます。フローでは、視聴者名、寄付、商品、メッセージ、カウンター値など、利用可能な値を組み合わせ、文字サイズと配置を調整できます。

互換性の条件： プリンターは、動作するWindowsプリンターキューとして表示される必要があります。Social Streamはインストール済みのWindowsドライバーを通じて印刷し、生のESC/POS、ZPL、メーカーSDKのコマンドは送信しません。

簡単な設定

  1. プリンターをUSBで接続して電源を入れ、Windowsドライバーをインストールします。先にWindowsのテストページを印刷してください。
  2. Social Streamで次を開きます： 全体設定とツール（Global settings and tools） → プリンター制御（Printer Control）.
  3. 選択する項目： プリンターを検索（Find printers） を選び、Windowsに表示される正確なキュー名を指定します。
  4. 実際の用紙幅を入力します。よく使う幅は 58, 80、または 62 mmで、機器と用紙によって異なります。
  5. 次はそのままにします： 固定ラベル長（Fixed label length） の値を 0 にすると内容に合わせたレシートになります。ダイカット用紙の場合は、送り方向のラベル長をミリメートルで入力してください。
  6. 選択する項目： 位置合わせテストを印刷（Print alignment test）。端が欠ける場合は、その側の安全余白を増やして再テストしてください。

左右2 mmの初期安全余白は、多くの低価格な58 mmレシートプリンターに適していますが、実際の印刷可能領域を決めるのはドライバーです。次を 印刷可能領域を使用（Use printable area） 選択したままにしてください。別の設定はテストしてから使用してください。

レシートロール、連続ステッカー、ダイカットラベルのどれを使う？

レシートロール

長さが変わる購入明細、整理券、支援者向けレシートに適しています。固定ラベル長を0にして、内容に応じて用紙の長さを決めます。

連続ステッカーロール

文字量が変わる、粘着式の名前ラベルに適しています。レシート紙と同じように動作しますが、切断はプリンターまたはドライバーが処理する必要があります。

ダイカットラベル

同じ形式のバッジや商品ラベルに適しています。正確な固定長を設定し、Windowsの印刷設定でも同じ用紙を指定してください。

プリンターの例適した用途接続と用紙について
汎用「POS-58」低価格な58 mm連続レシート通常はUSB接続の感熱式です。モデル名やドライバーは販売者によって異なります。Social Streamの実機開発テストでは、基本的なPOS-58キューを使用しました。
Epson TM-T20III実績のあるレシートプリンターの選択肢USBモデル。80 mm用紙と、付属の幅調整アダプターを使用した58 mm用紙に対応します。
Brother QL-800USBで印刷するステッカー、宛名/名前ラベル感熱式で最大62 mm幅の用紙に対応し、ダイカットまたは連続ロールを使用できます。自動カッター付きです。
Brother QL-820NWB共有またはネットワーク接続のラベル印刷所USB、Ethernet、Wi-Fi、Bluetoothに対応し、Brotherのダイカットラベルと連続ラベルを使用できます。
Zebra ZD220幅広の商品、配送、リストバンド、耐久ラベル約25〜112 mm幅の用紙に対応するUSBデスクトップラベルプリンター。感熱式と熱転写式の構成があります。

これらは例であり、互換性を保証する一覧ではありません。購入前に、その正確なモデルに現行のWindowsドライバーがあり、使用するラベル寸法に対応し、通常のWindowsプリンターとして表示されることを確認してください。

Event Flowで寄付ラベルを印刷する

💰 寄付 / 投げ銭（Donation / Tip）最低金額（Minimum Amount）： 10
→
🖨️ 感熱ラベルを印刷（Print Thermal Label）{username}
{donation}
24 pt · 太字 · 中央揃え
  1. 開く項目： Event Flowエディター を開き、フローを作成します。
  2. 次を追加します： 寄付 / 投げ銭（Donation / Tip） トリガーを追加します。次を設定します： 最低金額（Minimum Amount） を設定すると、一定額以上の寄付だけを印刷できます。
  3. 追加する項目： 感熱ラベルを印刷（Print Thermal Label） をIntegrationsから追加し、トリガーを接続します。
  4. ラベルのテキストを次に設定します： {username}の後に改行し、次を入力します： {donation}。文字サイズ、太さ、配置、部数を選んでください。
  5. 通常、アクションのプリンターと固定長の上書き設定は空欄または0にし、全体のPrinter Control設定を適用してください。
  6. 開く項目： フローをテスト（Test Flow）を選び、名前を入力して、次を有効にします： 寄付額（Has Donation）を選び、金額を入力してテストを実行します。単体アプリでは実際の印刷ジョブが送信されます。

他にも便利なプレースホルダーがあります： {message}, {source}, {donationAmount}、および {counterValue}。前のノードで作成した値も印刷テンプレートに使用できます。

購入者を太字、商品を通常の太さにする

選ぶ項目： 太さ（Weight）→ 選択したテキスト（Selected text）（**太字**）を選び、次を入力します：

**{username}**
{subtitle}

波括弧は1組だけ使ってください。最近のコマース連携では、商品タイトルは次に入ります： subtitle。数量は次の値で得られる場合があります： {meta.commerce.quantity}。前のノードが次を作成する場合、 buyerでは、次を使用します： **{buyer}** を使用してください。ShopifyとeBayには購入者情報がないため、これらのソースではローカルの注文カウンターか商品だけのタグを使ってください。次で囲んだテキストだけが、 ** で囲んだ部分だけが太字になります。独自のJavaScriptやHTMLは不要です。既存のAll boldとNormalのラベルは、その書式を維持します。

販売にはEvent Typeで次を使います： purchase。Donation / Tipには次が必要です： hasDonation が必要なので、多くの販売には一致しません。代わりに次を使用します： gift または giftfunded を、完了したギフトを示すラベルに使用し、必要に応じてプロバイダーで絞り込みます。配信全体で連番の注文番号を付けたい場合は、印刷アクションの前にCounterを追加してください。参照： コマースイベントのフィールド.

このアクションは次を公開します： meta.thermalPrintResult.success と、後続のフローステップで使える任意のエラー/コード。成功はジョブを送信したことを意味し、紙が出たことは確認していません。不確かなジョブを再試行する前にWindowsのキューを確認し、ラベルの重複印刷を避けてください。

Counterが数えるのは購入件数であり、重複を除いた購入者数ではありません。同じ購入者のすべての購入に同じIDを使うには、購入者とIDの対応表を別に用意し、配信開始時に明示的にリセットする必要があります。User Memoryのreasonフィールドは説明文であり、購入者ID専用のカウンターではありません。

Whatnotの商品ラベル

Whatnotのサンプルフローをダウンロード。購入者を太字で印刷し、商品名と、提供されていれば注文IDを印刷します。支払い失敗通知は、別の次のラベルを印刷します： 支払い失敗 ラベルを、その通知に含まれる詳細とともに印刷します。

  1. 単体アプリで、次を設定します： プリンター制御（Printer Control） でプリンターと用紙サイズを設定し、位置合わせテストを実行してください。
  2. 開く項目： Event Flowエディターで、次を選択します： インポート（Import）を選び、ダウンロードしたJSONファイルを指定します。
  3. 選択する項目： Whatnot：商品ラベルと支払い警告。両方の印刷アクションを確認してください。全体設定のプリンターとラベル長を引き継ぎます。
  4. フローを有効にして保存します。配信イベントの取得を有効にしたWhatnotソースを開いたままにしてください。

サンプルは無効な状態で取り込まれます。使用するもの： イベントタイプ（高度）（Event Type (Advanced)）→ カスタムイベント（Custom Event） のための product_sold および payment_failedを使い、ソースをWhatnotで絞り込みます。入札とオークション終了間近の通知ではラベルを印刷しません。

販売ラベルは支払いの確認ではありません。この例は通知が届くたびに印刷し、支払いを待ったり、前のラベルを修正したり、購入者番号を割り当てたりしません。欠けたフィールドは空欄になります。購入者、商品、注文情報のない失敗通知では、以前のラベルを特定できません。参照： Whatnotのイベントフィールド.

固定長ラベルを意図したとおりに印刷する

3 × 1インチのラベル（Munbyn BT320の設定を含む）： 1インチ側が送り方向の場合、幅76.2 mm、固定長25.4 mmを使用します。Windowsの印刷設定でも同じ用紙と向きにしてください。まず12〜14 ptの文字で、長い購入者名と商品名をテストします。

位置合わせテストの左右の枠線は、印刷可能領域の設定と安全余白を適用した後の安全な幅を示します。枠の高さはテスト文に合わせて決まり、ラベル全体の輪郭や実際の用紙の端を示すものではありません。

  • 送り方向の長さを測ります。 62 × 29 mmのラベルでは、通常、用紙幅を62 mm、固定ラベル長を29 mmにします。
  • Windows側も合わせます。 プリンタードライバーの印刷設定で、正確なラベル用紙、向き、隙間/マークの検出、カッター動作を選んでください。
  • 固定長は伸びません。 Social Streamは、固定長ジョブにレシート用の紙送り余白を追加しません。内容が縦に長すぎる場合、ドライバーによっては切れたり、次の紙へはみ出したりします。
  • 想定される最長のデータでテストします。 長い視聴者名、商品のバリエーション、通貨表記、複数行の内容には、広い領域か小さなフォントが必要です。
  • ドライバーの制限は引き続き適用されます。 Windowsまたはプリンタードライバーが、非常に短いカスタム用紙を制限する場合があります。Social Streamは最小20 mmを要求します。

配信のアイデア

  • 壁、小道具、地図、実物の進捗ボードに貼る、支援者の名前ステッカーを印刷できます。
  • 購入が届くたびに、グッズ注文、制作依頼、飲み物、受け取り用のタグを作成できます。
  • 印刷アクションの前にレート制限と参加条件の確認を置き、くじ券や抽選参加券を印刷できます。
  • VIPバッジ、チーム分け、チャレンジ用トークン、寄付達成ラベルを作成できます。
  • 配信者の隣で作業する担当者向けに、短いモデレーションや注文処理の待ち行列を印刷できます。
個人情報を印刷する前に検討してください。 住所、メールアドレス、支払い情報、非公開メッセージは印刷しないでください。感熱紙は熱、光、時間の経過で薄くなるため、長期保存にも適していません。

よくある問題の対処

  • プリンターが表示されない： Windowsでテストページを印刷できることを確認し、Social Streamを再起動してFind printersをもう一度選んでください。
  • ジョブは成功と表示されるが印刷されない： そのプリンターのWindowsキューを開き、一時停止、オフライン、用紙、ドライバー、ポートのエラーを確認してください。
  • 端が切れる： Use printable areaを有効にしたまま、その側の安全余白を増やしてください。
  • 余白の紙が多すぎる： レシートは固定長0にし、下余白と紙送りを減らすか、ラベル用紙には正確な長さを設定してください。
  • 1枚のラベルが2枚になる： 内容が固定ラベルより高いか、Windowsで違う用紙サイズが使われています。テキスト量、文字サイズ、行間、余白を減らしてください。
  • Test Flowで違うプリンターが使われる： Print Thermal Labelノードでプリンターの上書きを指定してください。エディタ内で直接テストする場合、空欄ではWindowsの既定のプリンターを使用します。
