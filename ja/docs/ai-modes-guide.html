「ChatGPT」の2つの意味

選択肢概要会話
ChatGPT APIプロバイダーSSNは自分のAPIキーと選択したモデルを使い、OpenAIにプロンプトを送信します。chatgpt.comとは別の、SSNとAPIによる会話です。
ChatGPTブラウザソース拡張機能は、開いている次のタブに表示された新しいユーザー発言とChatGPTの応答を読み取ります： chatgpt.com のタブです。ブラウザで開いた会話です。APIキーは使いません。

重要： OpenAI APIを接続しても、既存のChatGPTウェブ会話や音声会話にSSNが接続されるわけではありません。OpenAIのAPIは独自の会話状態を管理します。

選択肢1：ChatGPTブラウザ連携（実験的）

ChromeですでにChatGPTを使っていてAPIキーを用意したくない場合は、この選択肢が最も近いものです。SSNはページの新しいテキスト発言を次のソース種類として取り込めます： openaiとして、チャットソースと同様に取り込みます。

ChatGPTの会話を取り込む

  1. Social Stream NinjaのChrome拡張機能をインストールし、有効にします。
  2. ポップアップで、利用時に明示的な有効化が必要な次の機能をオンにします： ChatGPT のソースです。
  3. 開く項目： https://chatgpt.com/ を有効にし、ソースをオンにした後でページを再読み込みします。
  4. 同じセッションでSSNドックを開きます。
  5. ChatGPTで新しいメッセージを送信します。新しいユーザー発言とChatGPTの応答がドックに表示されるはずです。過去の履歴は意図的に無視されます。

開いているChatGPTタブへライブチャットを送る

  1. 非公開または限定公開の配信と、通常のChatGPTテキスト会話でテストしてください。
  2. 次のセクションで： 管理で、次を有効にします： すべてのメッセージを転送（Relay all messages）.
  3. 設定する項目： 転送先を選択（Pick relay destinations） → openai として、取り込んだ視聴者メッセージをChatGPTタブだけに送ります。
  4. ChatGPTのタブを開いたままにしてください。新しい返信は、SSNに次の形式で戻ります： openai メッセージ。
  5. ChatGPTの音声、またはSSNの読み上げ・オーバーレイ出力を使い、その返信を配信に載せます。

実験的機能： ウェブページの操作要素は変わることがあり、全件転送では会話に大量のメッセージが流れ込みます。また、ChatGPTの音声モードは通常のテキストページのように注入した文字を受け付けない場合があります。すべての視聴者メッセージを送る前に、フィルターまたはテスト配信を使ってください。

AIウェブサイトの取り込み対応状況

ウェブサイト現在の対応状況
ChatGPT新しいテキスト発言を実験的に取り込みます。過去の履歴は無視します。汎用ブラウザ転送でプロンプト入力欄を送信先にできます。
Claude会話の取り込みには非対応です。同梱のClaudeスクリプトはページのスタイルを調整する補助機能だけです。
Gemini、Copilot、PerplexityなどのAIサイト現在のSSNには専用のウェブサイト取り込みソースは含まれていません。ただし、SSNプロバイダーの一覧にあるサービスではAPIを使える場合があります。

選択肢2：SSN内でAIプロバイダーを設定

SSNで返信生成、メッセージのモデレーション、チャット翻訳、ナレッジベース検索、オーバーレイ作成を行う場合にプロバイダーを使います。

プロバイダーの種類設定補足
ローカルOllama、Local Gemma、Local QwenクラウドAPIキーは不要です。性能はコンピューターとモデルアセットによって異なります。
独自・ローカルサーバー独自のOpenAI互換APIllama.cpp、LM Studio、vLLM、互換ゲートウェイ向けです。Ollamaには専用の選択肢を使ってください。
クラウドOpenAI、Gemini、DeepSeek、xAI、AWS Bedrock、OpenRouter、Groq、OpenCode Zenキー、アクセス権、料金、利用枠、モデル名は各プロバイダーが管理します。
試用SSNホスト型試用LLM（SSN Hosted Trial LLM）実験的な機能で、無効化またはレート制限される場合があります。
  1. 開く項目： チャットボットとAIサービス（Chat Bots and AI services） をSSNポップアップで設定します。
  2. 開く項目： LLMサービスプロバイダーの設定（Configure LLM Service Provider） で、実際に使うプロバイダーを選択します。
  3. エンドポイント、モデル、APIキー、またはローカルアセットの設定を入力します。
  4. 選択する項目： 選択したチャットボットをテスト。Connectedという結果は、プロバイダーがテストに応答したことだけを示します。
  5. それを使う機能を別途有効にします。メインボット、非公開ボット、共同司会、モデレーション、翻訳、RAG、ビルダーから選んでください。

選択肢3：音声AI共同司会

共同司会は「ライブチャットも見ているAIと話す」という用途のために設計されています。マイクと選択したライブチャットメッセージが同じ共同司会セッションに入り、応答を配信上で読み上げられます。

  1. 開く項目： cohost.html?session=YOUR_SESSION.
  2. 音声・Realtimeプロバイダー、またはSSNポップアップで設定したLLMを選びます。
  3. マイクと次の項目を明示的に選択します： 音声応答（Audio Response）、続いて押すボタン： 共同司会を開始（Start Co-host）.
  4. OpenAI Realtimeでは、Live Chatを次の設定にします： コンテキストのみ — 尋ねられたときに回答（Context only - answer when asked） にすると、AIは割り込まずに最近の視聴者メッセージを記憶します。自動応答には次を選びます： 質問とメンション（Questions and mentions） または すべてのメッセージ（Every message） で自動応答を音声再生できます。これらのモードはプラットフォームのチャットには投稿しません。
  5. OpenAI Realtimeでは共同司会のブラウザ・アプリの音声をOBSで取り込み、次を使います： cohost-overlay.html?session=YOUR_SESSION をステージのアバターと吹き出しに使います。オーバーレイには同じWebRTC音声ストリームは届きません。対応している場合は共同司会の出力デバイス選択欄で仮想ケーブルを選べます。 &forcetts は、別のオーバーレイ音声を意図的に追加します。
  6. 任意の配信ツールは初期状態ではオフです。SSNポップアップでSpotify、許可したOBSシーン名の一覧、注目チャットの操作を有効にし、次の場所でも同じツールを使用可能にします： 共同司会の配信操作 を共同司会ページで設定します。
  7. OpenAIの遅延を抑えるには、モデルをMini、推論をLow、発話交代をFastにします。Full qualityや高い推論設定は難しい回答を改善できますが、遅延とAPI料金が増えます。Fastでは自然な間を遮ることがあります。Diagnosticsに最初の出力までの実測遅延が表示されます。
  8. OpenAIのカメラ入力とScreen Shareは任意で、初期設定は 映像なし（No Video）。選択すると、SSNは直接の音声・文字による依頼ごとに現在の画像を1枚送ります。連続した映像ストリームではなく、API料金と遅延が増える場合があります。
  9. AIの声を聞かなくても視聴者が会話を追えるよう、吹き出しを表示するか字幕を用意してください。

OpenAI Realtimeは、次の場所に設定したOpenAIプロジェクトキーを使います： ChatGPT API をSSNポップアップで設定します。通常のキーはSSN拡張機能・デスクトップアプリのバックグラウンドに保持され、共同司会ページ向けに短時間だけ有効なRealtimeクライアントシークレットを生成します。その後、マイクとAI音声はWebRTCで送受信されます。応答は最大512出力トークンで、Diagnosticsに累計使用量と遅延が表示されます。SSNは静かなセッションの状態を確認し、失敗した接続を再接続します。復旧したセッションには指示と性能設定が再適用されますが、以前の音声会話は復元できません。これはSSN共同司会セッションを作成するもので、ChatGPTサイトやChatGPTデスクトップアプリの既存の会話を引き継ぐものではありません。

選択肢4：メインのライブチャットボット

メインボットは取り込んだ視聴者メッセージを判断し、オーバーレイ、読み上げ、対応プラットフォームのチャットへの投稿で回答できます。

  1. AIプロバイダーを設定してテストします。
  2. 有効にする項目： メインAIチャットボット（Primary AI chat bot）.
  3. トリガーワード、モデレーター限定の動作、レート制限、履歴、プロンプトの指示を設定します。
  4. 最初は安全にテストするため、次を有効にします： ボットの返信をボットオーバーレイページだけに送る（Bot replies ONLY go to the bot overlay page）.
  5. 開く項目： bot.html?session=YOUR_SESSION を有効にし、返信を読み上げる場合はTTSも有効にします。
  6. 送信先プラットフォームが投稿に対応していることを確認してから、オーバーレイ専用モードを解除してください。

プラットフォームへの返信は通常、ログイン中のアカウントを使います。別の名義を使うには、対応しているYouTube、Twitch、Kickで専用のボットアカウントを使ってください。

AIチャットボット設定ガイドを開く

選択肢5：1対1の非公開ボット

chatbot.html は、非公開アシスタントとプロンプトテスト用のページです。有効にする項目： チャットボット - 非公開インターフェース（Chat Bot - Private Interface）を有効にし、自分のセッションでページを開いて、設定済みLLMプロバイダーを使います。

非公開ボットはメインのライブチャットボットとは別で、現在はRAGデータセットや他のチャット履歴を共有しません。

選択肢6：AI処理ツール

ツールできること安全に始める
検閲ボット受信メッセージを分類、修正、ブロックします。最初はブロックしないモードで使い、結果を確認してください。
翻訳受信チャットと、任意で送信する配信者のメッセージを翻訳します。まず1つの言語でテストし、安定して動くまではブロックモードを避けてください。
RAGナレッジベースアップロードした資料ファイルから、メインボットが関連する文章を検索できます。最新で、内容を絞ったテキストまたはMarkdownファイルを使ってください。
チャットの要約ユーザーが次のコマンドでAI要約を呼び出せます： !summary.履歴の量、費用、非公開の内容を確認してください。

選択肢7：AIオーバーレイビルダー

使う項目： aiprompt.html でオーバーレイを説明し、生成、プレビュー、保存します。使うページ： aioverlay.html を、保存後にOBSの出力ページとして使います。

AIオーバーレイビルダーのガイドを開く

よくある問題の対処

  • 接続済みなのにライブチャットへ応答しない場合： メインボット、または使いたいAI機能を有効にしてください。プロバイダーを設定しただけではチャットは処理されません。
  • 共同司会がチャットを見ているのに話さない場合： Context onlyは、配信者がチャットについて尋ねるまで意図的に待ちます。自動返信にはQuestions and mentionsまたはEvery messageへ切り替えてください。
  • ChatGPTブラウザソースから何も届かない場合： ChatGPTの利用設定をオンにし、次のページを再読み込みします： chatgpt.comを確認し、過去の履歴ではなく新しい発言でテストしてください。
  • ボットがほとんどのメッセージを無視する場合： トリガーワード、モデレーター限定モード、レート制限、選択的に返信するようモデルに与えた指示を確認してください。
  • テキストは出るのに音が出ない場合： 読み上げを生成するページが開いていて、OBSがそのページの音声を取り込んでいることを確認してください。
  • ボットが投稿できない場合： プラットフォームの返信対応、ログイン状態、アカウント権限、レート制限を確認してください。

その他の資料： 読み上げ設定, ローカルAI読み上げ、および コマンドとAPIのAI連携.
