テストメッセージを作成

制御した架空のメッセージとイベントをSocial Streamセッションへ送ります。

このツールの機能SSAppまたは拡張機能でのクイックスタート例：1,000 KICKsの架空メッセージを1件送るプリセットとカスタムJSONを使う適切な配信モードを選ぶよくある問題の対処

このツールの機能

対象の テストメッセージ作成ページ は、人工的に作成したSocial Streamペイロードをドック、オーバーレイ、アラート、Event Flowへ送信します。実際のチャット、寄付、メンバー登録、レイド、報酬などのイベントを待たずにテストできます。

可能ならテスト用セッションを使ってください。 送信したメッセージは、セッションで受信するデータと同じように動作し、アラート、音声、Webhook、OBS操作、その他の自動処理を起動する可能性があります。

SSAppまたは拡張機能でのクイックスタート

  1. Social Stream Ninjaを開き、サービスが有効であることを確認します。
  2. 次のセクションで： 全体設定とツール（Global settings and tools） → 仕組み（Mechanics）で、次を有効にします： 拡張機能のリモートAPI制御（remote API control of extension）。SSAppでも同じ設定名を使用します。
  3. Social Streamまたは次からセッションIDをコピーします： session= の値をドックまたはオーバーレイURLで確認してください。
  4. 開く項目： テストメッセージを作成（Create Test Message） を開き、そのセッションIDを入力します。
  5. 次はそのままにします： 送信経路（Send Via） 設定する値： 拡張機能API経由（Extension API ingest） 。通常のテストにはこれを使います。
  6. プリセットを選び、フィールドを調整して、次を選択します： プリセットを読み込み（Load Preset）.
  7. Payload JSONを確認し、次を選択します： 送信（Submit）.
  8. ドックまたは対象オーバーレイに項目が表示され、期待した自動処理が実行されることを確認します。

URLにセッションを含めることもできます： createtestmessage.html?session=YOUR_SESSION_ID.

例：1,000 KICKsの架空メッセージを1件送る

これは1,000 KICKs相当のKick形式の支援メッセージを1件作成します。1,000件の別々のメッセージを作るわけではありません。

  1. 次を選択します： チャットメッセージ（Chat Message） プリセットです。
  2. 設定する項目： 入力するコマンド： → Kick.
  3. テスト用の名前とメッセージを入力します。
  4. 設定する項目： 寄付額（Has Donation） → 1000 KICKs.
  5. 選択する項目： フィールドからJSONを更新（Update JSON from Fields）を選択し、JSONを確認して送信します。

最小限のペイロード：

{
  "type": "kick",
  "chatname": "Test Supporter",
  "chatmessage": "Thanks for the stream!",
  "hasDonation": "1000 KICKs"
}

使う項目： チャットメッセージ（Chat Message） にしてください。この例では、 寄付 / Cheer（Donation / Cheer） プリセットには、Twitch固有のCheerフィールドが含まれます。

プリセットとカスタムJSONを使う

プリセットは、寄付、サブスクライバー、ギフトサブスク、レイド、報酬、視聴者数更新、初回チャット、トレインイベントなど、よく使うケースのひな形ペイロードを提供します。

  • プリセットを読み込み（Load Preset） は、選択したプリセットと現在のフィールド値でJSONを置き換えます。
  • フィールドからJSONを更新（Update JSON from Fields） は表示中のフィールドから基本的なメッセージを作成します。
  • 次を直接編集できます： ペイロードJSON（Payload JSON） 。特定のフィールドやイベント構造をテストする場合に使用します。
  • hasDonation は、次のような表示用の支援額を保持します： 1000 KICKs または $10.00.
  • 次のフィールドを含めるのは、 event 実際の名前付きイベントをテストする場合だけです。通常の寄付形式のチャット行には、 hasDonation だけを使用できます。

フィールドの定義と実際のプラットフォームの例は、次をご覧ください： イベントリファレンス.

適切な配信モードを選ぶ

送信経路（Send Via）適した用途必要な設定
拡張機能API経由（Extension API ingest）通常のドック、オーバーレイ、アラート、Event Flow、SSAppのテスト。同じセッションIDを使い、次を 拡張機能のリモートAPI制御（remote API control of extension） 有効にします。
チャネル1へ直接（Direct to channel 1）対象ドックが次を付けて開かれている場合： &server.対象は、一致するサーバーチャネルで待ち受けている必要があります。
チャネル4へ直接（Direct to channel 4）次を使用する対象のテスト： &server2を使用する対象をテストする場合。対応するイベントページも含みます。対象は、一致するサーバーチャネルで待ち受けている必要があります。

迷う場合は、次を使ってください： 拡張機能API経由（Extension API ingest）.

よくある問題の対処

  • 何も表示されない： 対象ページが開いていて、同じセッションIDを使用していることを確認してください。
  • Extension API ingestが失敗する： 有効にする項目： 拡張機能のリモートAPI制御（remote API control of extension）を確認し、ドックまたはオーバーレイを再読み込みして試してください。
  • 直接モードで送信済みと表示されるが何も出ない： 対象URLに一致する次の値がない限り、Extension API ingestを使ってください： &server または &server2 モードです。
  • 別のイベントが起動する： Payload JSONに別のプリセットのフィールドが残っていないか確認してください。
  • KickのテストがTwitchのように動く： Chat Messageプリセットを使い、次を設定してください： type および hasDonation を上の例のとおりに設定します。
  • 自動処理が複数回実行される： 同じセッションで複数のドック、アクションページ、Event Flowが開いていないか確認してください。
