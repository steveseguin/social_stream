5. 受信チャットがコードにならないようにする

メッセージ、名前、タイトル、金額、メタデータ、およびメディア リンクは、視聴者または外部サービスから発信される可能性があります。カスタム レンダラーがそれらを挿入する時点でサニタイズします。 SSN を通じて受信した文字列には、それを実行する権限がありません。プレーンフィールドにはプレーン DOM テキストを使用します。メッセージ本文のサポートされている HTML に対してパッケージ化されたサニタイザーを使用します。参照 OWASP による安全なシンクと HTML サニタイズについての説明.

SSNでは、 textonly にのみ適用されます。 chatmessage。 true の場合、その本文をリテラル テキストとしてレンダリングします。それ以外の場合は、エモートや許可された書式設定が含まれる可能性があります。他の通常のフィールドをテキストとしてレンダリングします。メディア分野など chatimg および contentimg は URL/データであり、HTML スニペットではありません。

<!-- Example for a copied page at the repository root. -->

<script>
function renderChatBody(element, data) {
    var message = String(data.chatmessage == null ? "" : data.chatmessage);
    if (data.textonly) {
        element.textContent = message;
    } else {
        element.innerHTML = SocialStreamChatHTML.sanitize(message);
    }
}
// Names, amounts, titles, and other plain fields use textContent:
// nameElement.textContent = String(data.chatname || "");

6. レイアウト、接続、OBS を個別にテストする

  1. レイアウト: 可能な場合はページの文書化されたプレビュー/デモ モード、または架空のローカル サンプルを使用します。長い名前/メッセージ、欠落しているアバター、空のデータ、および予想される行数をテストします。
  2. SSN 配信: SSN をアクティブのままにして使用します テストメッセージを作成（Create Test Message） 同じセッションで。通常の拡張 API 取り込みモードには次のものが必要です 拡張機能のリモートAPI制御（remote API control of extension） が有効になります。独立したテスト設定を使用します。送信されたテストは、構成された自動化をトリガーできます。
  3. 実際のトリガー: 注目のカードのドック メッセージを機能させたり、アンケートの投票を送信したり、プレゼントの勝者を選択したり、ティッカーのテキストを変更したり、タイマーのタイマーを開始したりします。単純なチャットは普遍的なテストではありません。
  4. 実際のキャプチャ: 実際のソースメッセージ/イベントが元の編集済みページに到達することを確認します。モック イベントは、プラットフォーム キャプチャではなくレンダリングを証明します。
  5. OBS： ソースの最終的なサイズ、透明度、アニメーション、オーディオ、フォント、レイヤーを確認します。表示/非表示、クリア/リセット、リフレッシュを実行します。ブラウザと OBS には別のストレージとセッションがあります。ブラウザのログインまたは localStorage は自動的に共有されません。
