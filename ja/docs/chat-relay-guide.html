プラットフォーム間でチャットを転送する

TwitchとYouTube間の転送を意図した形で設定し、送信アカウントを選び、メッセージの繰り返しを調べます。

すべてのガイド 1. 両方のチャットへ返信できることを確認する 2. Event FlowでTwitch → YouTubeを作成する 3. 逆方向を追加する 4. 反射メッセージを理解する 5. 転送する内容を絞る トラブル対処

1. 両方のチャットへ返信できることを確認する

TwitchとYouTube Liveのチャットを同じSSNセッションに接続します。両方がドックに表示されることを確認し、元のソースタブがわかるメッセージから、それぞれに手動で1回返信します。自分のテスト用チャンネルを使ってください。読み取り専用の取り込みソースでは転送を送信できません。

この設定では、意図した転送先チャットだけを開いてください。プラットフォームを宛先にすると、そのプラットフォームの送信可能な複数ソースタブが含まれる場合があります。別のTwitchボットアカウントを使う場合は、次を完了してください： 返信用ボットアカウント を先に設定します。

2. Event FlowでTwitch → YouTubeを作成する

開く項目： Event Flowエディター をSSNメニューから開きます（Actionsオーバーレイのセクションにもリンクがあります）。フローを作り、次のようなわかりやすい名前を付けます： TwitchからYouTubeへ.

  1. 追加する項目： ソース指定（From Source） トリガーを次のカテゴリから追加します： ユーザーとソース（User & Source）。ソースとしてTwitchを選択します。
  2. 追加する項目： チャット転送（Relay Chat） アクションを追加し、トリガーの出力をアクションの入力につなぎます。
  3. そのアクションを選び、次を設定します： 転送先（Relay Destination） → YouTubeに設定し、メッセージテンプレートは次のままにします： [{source}] {username}: {message}.
  4. 選択する項目： フローを保存（Save Flow） を実行し、保存したフローを有効にします。SSNは有効のままにしてください。
  5. 自分のTwitchテスト用チャットで、新しい通常メッセージを送信します。YouTubeにラベル付きのコピーが1件届くことを確認してください。

YouTube Shortsには独自のソース種類と送信先があります。選択する項目： YouTube Shorts を必要に応じて選んでください。YouTubeと同じものではありません。

3. 逆方向を追加する

2つ目のフローを作り、次の名前にします： YouTubeからTwitchへ: From Source: YouTube → Relay Chat: Twitch。保存して有効にします。両側から新しいメッセージを送り、それぞれ相手のプラットフォームに1件だけコピーされることを確認します。

次の項目は維持します： すべてのメッセージを転送（非推奨）（Relay all messages (!NOT RECOMMENDED!)） は、これらのフローを使う間はオフにし、別の転送システムが同じ処理をしないようにしてください。他のボットやマルチ配信サービスがすでにチャットを接続していないかも確認します。

4. 反射メッセージを理解する

反射メッセージとは、SSNが送信したメッセージを送信先のチャットから再び取り込んだものです。現在のRelay Chatアクションは、認識した反射メッセージを自動で除外します。また、元のタブも送信先から除外します。

再び取り込んだメッセージをドックやオーバーレイで隠すには、次を追加します： 反射フィルター（Reflection Filter） アクションを該当フローの前半に追加し、次を選択します： すべてブロック（Block All）. 最初の1件を許可（Allow First） は設定した時間内に一致した反射メッセージを1件だけ残します。 すべて許可（Allow All） はそれらを表示します。これは取り込み後の表示を制御するもので、転送先を決めるものではありません。

現在のRelay Chatのプロパティに「No Reflections」チェックボックスはありません。表示の制御には、別のReflection Filterを使います。外部サービスが転送メッセージを書き換えると、自動認識できない場合があります。

5. 転送する内容を絞る

コマンドを扱う場合に追加する項目： メッセージの先頭一致（Message Starts With） トリガーの設定値： ! を追加し、次のゲートを通して接続します： NOT ゲートを通し、ソース条件とその結果を次で組み合わせます： AND をRelay Chatの前に置きます。参照先： Event Flowガイド に論理ゲートの接続方法があります。通常の文とコマンドの両方をテストしてください。

代わりに簡単な全体転送を使う場合は、次を使います： 全体設定とツール → コマンド → 転送先を選択（Global settings and tools → Commands → Pick relay destinations） を選び、次を入力します： twitch,youtube。一覧が空欄なら、送信可能なすべての宛先が対象です。この一覧は送信先を決めるもので、転送のきっかけになる受信元のプラットフォームを決めるものではありません。この代替方法を有効にする前に、Event Flowの双方向転送を無効にしてください。

同じCommandsセクションにあるSSAppのアカウントロール許可・ブロック欄で、転送を送信するアカウントを制限できます。送信に使いたいアカウントに割り当てたロールを指定してください。一致しないロールを指定すると、送信可能な宛先がなくなる場合があります。

トラブル対処

  • 何も送られない場合： 手動返信をもう一度試し、ログイン・投稿権限を確認して保存済みフローを有効にし、送信先とアカウントロールの制限を確認してください。
  • メッセージが増殖する場合： まず転送フローを無効にします。重複した取り込みソース、全体のRelay all、外部の転送ボットを確認してから、片方向だけを再テストしてください。
  • ドックだけに重複が表示される場合： Reflection Filterの表示ポリシーと、全体設定のMessage - Visibilityにある重複・反射設定を確認してください。
  • YouTubeの送信先が違う場合： YouTubeとYouTube Shortsの違いを確認し、意図しない送信可能なチャットを閉じてください。

Test Flowのアクションは、実際のメッセージを送信することがあります。管理できる送信先を使ってください。疑似テストでは、実際のソースのアカウント経路までは確認できません。
