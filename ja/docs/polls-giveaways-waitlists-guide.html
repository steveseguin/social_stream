投票、抽選、待機リスト

初めての抽選：スクリーンショット付きの詳しい手順

プレゼント企画、有料チケット、ゲーム景品、復旧ガイド

チャット投票を行い、当選者を抽選し、次に参加する視聴者を順番に管理します。

1. ツールを選ぶ

目的 SSNで開く
次のアクティビティをチャット投票で決める Graphical Poll → Poll Options
参加者をランダムに選ぶ 待機リスト／当選者抽選（Wait List / Winner Draw）を使い、当選者抽選モードを有効にします
待機順に視聴者を案内する 待機リスト／当選者抽選（Wait List / Winner Draw）を使い、当選者抽選モードを無効にします

そのセクションで生成されたリンクをOBSのブラウザーソースに使用します。SSNとチャットソースを有効にしたまま、リンク内のセッション、パスワード、サーバー設定を保持してください。 抽選ツール（Giveaway Tool） は、当選者カード、名前のリール、コミュニティホイールで表示できる、独立した応募一覧を提供します。専用の抽選操作にはGiveaway Optionsパネルを使用してください。Wait List / Winner Drawも独立して引き続き利用できます。

2. 選択式の投票を行う

  1. 開く項目： Graphical Poll → Poll Options。次を設定します： 投票の種類（Poll Type） → 選択式（Multiple Choice）.
  2. 入力する内容： 次は何をプレイしますか？ を質問にし、次を Adventure, Puzzle をカンマ区切りの選択肢として設定します。次を設定します： 投票の照合（Vote Matching） → 投票の完全一致のみ（Exact vote only）.
  3. 次はそのままにします： ユーザーごとの複数投票を許可（Allow multiple votes per user） および 寄付額で重み付けする投票（Donation-weighted voting） を、単純な1人1票の投票ではオフにします。次を有効にします： 投票を有効化（Enable Poll）.
  4. 生成された投票リンクをOBSにコピーします。視聴者に次を送ってもらいます： 1 または 2 をメッセージ全体として送ってもらいます。選択肢のテキストと一致する場合も有効です。
  5. 選択する項目： 投票を終了（End Poll） で投票を締め切ります。結果を控えてから、次を選択してください： 投票をリセット（Reset Poll） で次のラウンドを開始します。

自由形式の投票ではハッシュタグで投票できます。 ハッシュタグの位置は任意（Hashtag anywhere） は、長いメッセージ内のハッシュタグも受け付けます。 現在の投票を保存（Save Current Poll） は再利用用のプリセットを保存し、視聴者の結果を永続的に記録するものではありません。複数投票を有効にしていない限り、同じ人の繰り返し投票は無視されます。

独自の色、フォント、ロゴ、レイアウトが必要ですか?参照 グラフィカル投票をカスタマイズする OBS CSS、AI 編集プロンプト、および編集したファイルを実行するための手順 poll.html ローカル。

専用の抽選ツール

スクリーンショット付きの手順は、次を参照してください： 初めてのプレゼント抽選。開く項目： Giveaway Tool → Giveaway Optionsを開きます。応募キーワード、メッセージ完全一致または独立した単語としての一致を設定し、必要に応じてメンバー限定にします。次をクリックします： 応募を開始（Open entries）、次に 当選者を抽選（Draw winner） を準備できたらクリックします。抽選すると、応募は自動で締め切られます。抽選前なら、同じルールで応募を締め切り、再開できます。 新しいラウンド（New round） は現在の応募一覧をクリアし、過去の結果を履歴に残して、応募を締め切った状態にします。

選ぶ項目： 当選者カード（Winner card）, 名前のリール（Name reel）、または コミュニティホイール（Community wheel）、および6つのスタイルのいずれかを選択します。プレビューでは架空の名前を使い、実際のセッションには接続しません。生成された次のリンクをコピーします： giveaway.html?session=YOUR_SESSION&managed リンクをOBSにコピーします。管理型の視聴者向け表示には、操作用のコントロールやセッション情報は含まれません。スタイルとタイトルはリンクの設定で、応募ルールは応募開始時に適用されるホストの設定です。

同じ抽選IDの管理型表示は、ホストの応募一覧と選ばれた当選者を共有します。無料のキーワード応募は同じ確率で、有料抽選はチケット数に応じて重み付けされます。識別情報は、提供されたユーザーID、ユーザー名、表示名を使い、プラットフォーム内で重複排除されます。異なるプラットフォームは別の識別情報として扱います。複数回当選がオフの場合、当選者は現在のラウンドの抽選対象から除かれます。新しいラウンドでは、再び参加できます。参加者は最大10,000人です。人数が多い場合、ホイールには最大120人のサンプルを表示しますが、選択には常に有効なチケット全体を使用します。

SSNを起動したままにしてください。ラウンドはセッションごとに分けて、ローカルのブラウザー／アプリプロファイルへ保存されます。再起動すると受付中のラウンドは確認のため締め切られますが、削除されません。視聴者向けページを更新すると、現在の結果を受け取ります。メンバー制限には、メンバーシップ情報を提供するソースが必要です。履歴、再生、非公開、Bot、イベントだけのメッセージは除外されます。無料応募のテキストは設定したキーワードと一致する必要があり、寄付額で当選確率は変わりません。

API、Stream Deck、Event Flow

同じホストアクションを、ポップアップのボタン、既存のHTTP／WebSocket API、Stream Deckで使用します。応募の収集や抽選のために、抽選の表示ページを開いておく必要はありません。Event Flowでは、次を使用します： 抽選／チケット（Giveaway / Tickets） アクションを使用します。参照： ポイントと自動化のガイド で、有料チケット、ゲーム賞品、連携を確認できます。

操作効果
startgiveaway抽選前に応募を開始または再開します。任意の値： {"giveawayId":"default","config":{"keyword":"!enter","match":"exact","membersOnly":false,"removeWinner":true}}。ルールを明示しない場合、既存ラウンドは元のルールを維持し、新しいラウンドにはポップアップの設定を使用します。
closegiveaway応募を締め切り、一覧を保持します。
drawgiveaway応募を締め切り、有効な当選者を1人選びます。応募一覧が空の場合はエラーを返します。
resetgiveaway応募を締め切った状態で空のラウンドを作成し、古いラウンドと当選者を履歴に保存します。未処理の有料予約は、先にキャンセルして返金してください。
getgiveawaystate応募数、受付／締め切り状態、応募ルール、最近の当選者を読み取ります。
{"action":"drawgiveaway","get":"draw-1"}

Protocol 2のStream Deckリクエストは同じアクション名を使用し、対応付けられたホストの応答を受け取ります。応答が示すのは抽選の状態であり、OBSでの表示状態ではありません。従来の単体コミュニティホイールは、次を省略することで引き続き利用できます： managedを省略すると使えます。これは独自のローカル応募一覧を持ち、これらのホスト操作では制御されません。ローカル保存はセッションとパスワードごとに分かれ、完全一致はメッセージ全体の一致を意味し、抽選には安全な乱数を使用します。

3. 当選者を抽選する

  1. 開く項目： Wait List / Winner Draw → Enable and customizeを開きます。トリガーを有効にし、次のような明確なコマンドを設定します： !join.
  2. オンにする項目： キューではなく当選者抽選モードにする（Configure as winner-draw mode instead of queue）を設定します。更新されたリンクをOBSブラウザーソースにコピーしてください。
  3. 参加コマンドと参加資格のルールを視聴者に伝えます。次を使う場合： メンバーだけが応募可能（Only members can enter）を使う場合、まずソースがメンバーシップ情報を提供していることを確認してください。
  4. 応募数が増えることを確認します。次を選びます： 参加受付を停止（Stop entries） を受付終了時に選び、次に 当選者を選択（Select winner）.
  5. 使う項目： 一覧をダウンロード（Download list） で項目を保存してから、次を実行します： 抽選をリセット（Reset draw） はラウンドをクリアします。

4. 視聴者の待機列を管理する

同じ待機リスト設定を使い、当選者抽選モードをオフにして、更新されたURLをコピーします。視聴者は設定したコマンドで参加します。

ボタン 操作内容
先頭の項目を強調表示（Highlight top entry） 次の視聴者を目立たせます。
先頭の項目を削除（Remove top entry） その視聴者の番が終わったら、次へ進みます。
名前を選ぶ 待機列の順番ではなく、ランダムに選びます。
参加受付を停止（Stop entries） 待機列への新規参加を停止します。
一覧をダウンロード／キューをリセット（Download list / Reset queue） TSVのコピーを保存し、アクティビティが終わったら項目をクリアします。

再参加のオプションで、削除された視聴者が再び参加できるか選びます。任意の 待機リストの操作コマンド はモデレーター／ホスト／管理者に限定されます： !wlstop, !wlremove, !wlreset, !wlpick、および !wlhighlight。これらは明示的に有効にしてください。視聴者の参加コマンドだけでは有効になりません。

5. リハーサルと復元

異なる架空のユーザーを、次で使用します： テストメッセージ で投票と参加の動作を確認します。同じ人が2つのプラットフォームを使っても、確実に同一人物として扱われるわけではありません。視聴者に参加を呼びかける前に、OBSに結果が表示されることを確認してください。

  • 投票がない場合： Enable Poll、投票が終了していないか、完全一致、そのユーザーがすでに投票済みでないかを確認してください。
  • 応募がない場合： 待機リストのトリガー、正確なコマンド、参加停止の状態、メンバー限定設定を確認してください。
  • 件数はあるが一覧がない場合： 当選者抽選モードは、通常の待機列ではなく、応募一覧と当選者を表示します。
  • OBSの表示が一致しない場合： 保存済みURLを置き換え、セッション／パスワードを確認し、独立して設定した投票ページを重複実行しないでください。

機器やOBS内のボタンについては、次を参照してください： Stream Deckの設定 および OBS操作ドック.
