イベントとアラートの互換性

通常のチャット、寄付、イベントペイロードを区別して、取得したプラットフォームのイベントをMulti Alertsにつなぎます。

イベントソースから始める

Multi Alertsは、Social Streamがすでに取得したイベントを表示します。Twitch、Kick、YouTube、TikTokなどのプラットフォームに自動でサインインする機能はありません。

  1. イベントを提供するプラットフォームのソースを接続し、有効にします。
  2. そのソースページまたは単体アプリのソースウィンドウを動作させたままにしてください。
  3. ソース、ポップアップ、ドック、Multi AlertsのURLで、同じSocial StreamセッションIDを使用してください。
  4. プラットフォームの接続を調べる前に、設定からアラートオーバーレイをテストしてください。

プレビューが成功すれば、アラートのレイアウトが動作することを確認できます。 これは、プラットフォームのソースに実際のイベントを受信する権限があることを示すものではありません。

標準モードとWebSocketモードの比較

プラットフォーム標準キャプチャWebSocket／APIキャプチャ
YouTube 有料メッセージ、メンバーシップ、メンバーシップギフト、視聴者数更新、およびページで検出できる一部のイベント。 共通の有料／メンバーイベントに加えて、メンバーのマイルストーン、最近の公開登録者アラート、および対応する個数更新。
Twitch チャットに表示される報酬、ギフトサブスクの通知、視聴者数更新、および一部のページ限定の通知。 EventSubは、アカウントとスコープで許可されている場合に、フォロワー、サブスク、更新、Cheer、レイド、報酬、および対応する個数／状態イベントを追加します。
Kick チャットに加えて、ページ上の簡単なマーカーからギフト、報酬、視聴者数更新を取得します。 認証済みの場合の、公式のフォロー、サブスク、ギフト、報酬引き換え、KICKs、モデレーション、ライブ状態イベント。

イベントに連動するアラートには、通常WebSocketモードが適しています。表示されたチャットだけが必要な場合や、認証が利用できない場合には、標準キャプチャも便利です。

必要なアラートタイプを有効にする

Social Streamの設定からMulti Alertsのオプションを開きます。フォロー、サブスク、寄付、Bits、レイドには、それぞれ有効化、スタイル、音、表示の設定があります。オークションとHype Trainのアラートは、専用の設定で有効にする必要があります。

  • 使う項目： アラートをキューに入れる 複数のイベントが同時に届く可能性がある場合。
  • イベントがドックには表示されるのにMulti Alertsには表示されない場合、ソースフィルターを確認してください。
  • 少額のチップやCheerが表示されない場合は、最低金額／寄付フィルターを確認してください。
  • 自動再生の制限によってカスタムアラート音がブロックされる場合、ブラウザーページを一度クリックするなどして操作してください。

配信前にプレビューする

プレビュー操作で、選択したカテゴリ、テキスト、金額、メディア、音、アニメーション、およびキューの動作を確認してください。

各ツールが使用するフィールド

ツール互換性のルール
Multi Alerts正式な値を分類します： event 名前、別名、 hasDonation、メンバーシップのフィールド、および選択した meta の値を共通のカテゴリに分類します。
Event Flow次の値を正確に一致させてください： type, eventおよびソースが出力するフィールドを確認してください。実際のイベントに頼る前に、テストメッセージツールを使用してください。
TTSイベントの行は、寄付形式でない限り既定でスキップされます。次を追加します： &readevents を使用すると、寄付以外のイベントメッセージも読み上げます。そのうえで通常のTTSフィルターを適用してください。
チップジャー／目標メーター通常モードは寄付金額を使用します。Hypeモードでは、メンバーシップ、更新、メンバーシップギフトのフィールドもスコアに使用できます。
カスタムオーバーレイ／API利用側イベントリファレンスに記載された正式なペイロードフィールドを使用してください。記載された別名は、後方互換性のためにのみ受け付けてください。

使う項目： テストメッセージを作成 で、想定するイベントと次の値を確認してください： Event Flowレシピ で、動作する自動化の例を確認できます。

プラットフォーム設定の注意点

プラットフォーム最初に確認することガイド
Twitch配信者または許可されたモデレーターとしてサインインし、EventSubの接続を維持してください。Twitch EventSubの設定
Kick目的に応じてソースモードを選び、必要な公式イベントで認証が求められる場合は認証を完了してください。公式のレイドイベントは提供されません。Kickの設定と認証
その他のソース選択したソースが、チャットメッセージだけでなく、実際にそのイベントタイプを出力することを確認してください。対応サイト

実際のアラートが表示されない場合

  1. ソース自身のログ、ドック、またはAPIの出力で、イベントを受信したことを確認してください。
  2. ソースとMulti Alertsページで、同じセッションIDとパスワードを使用していることを確認してください。
  3. そのカテゴリが有効で、ソースまたはチャンネルのフィルターによって除外されていないことを確認してください。
  4. 寄付とBitsの最低金額フィルターを確認してください。
  5. TwitchまたはKickでチャットは動作するのに権限が必要なイベントが動作しない場合、サインインし直してください。
  6. 実際のイベントを確認できるまでソースウィンドウを動作させてください。プレビューだけでは、プラットフォームから表示までの一連のテストにはなりません。

複数のデバイスや接続モードを使用する場合、次を確認してください： セッション、パスワード、リレーモード.
