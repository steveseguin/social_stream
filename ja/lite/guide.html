オーバーレイにチャットを表示する

Liteは、対応するチャットソースにブラウザーまたはOBSから接続します。通常のオーバーレイリンクを使う場合は、タブまたはOBSドックでLiteを起動したままにします。実験的なスタンドアロンOBSモードでは、1つのブラウザーソースでチャットの取得と表示を行います。

設定 · OBSだけで使う設定 · ソース · 既存の設定 · トラブル対処

1. オーバーレイを設定する

  1. Liteを開きます。セッションIDとオーバーレイURLが自動的に生成され、このブラウザーに保存されます。
  2. 以下のいずれかのソースに接続します。次を使用します： 設定 ボタンでチャンネルを設定します。
  3. 選ぶ項目： リンクをコピーをコピーします。OBSで次を追加します： ブラウザ ソースを追加し、URL欄にリンクを貼り付けます。次も利用できます： ドックオーバーレイを開く でブラウザーから確認できます。
  4. 選ぶ項目： テストメッセージを送信 をLiteで実行し、開いているオーバーレイに表示されることを確認します。LiteのActivityフィードにメッセージがあるだけでは、オーバーレイが受信した確認にはなりません。

透明なオーバーレイや別のメッセージ順序を使うには、次の横にある設定を開きます： チャットオーバーレイのリンク。これらの設定を変更した後は、更新されたURLをOBSにコピーしてください。

2. ソースを選ぶ

OBSだけで使う場合は、以下の2つの方法から選びます。OBS内で取得する場合、デスクトップブラウザーのタブを別に開く必要はありません。

ソース操作内容
YouTubeYouTubeでサインインします。Liteは自分のライブ配信を検索します。Optionsでは、特定の配信のVideo IDまたはLive Chat IDを指定できます。既定ではポーリングを使い、任意のストリーミングAPIはベータ扱いです。配信でライブチャットが利用可能になっている必要があります。
TwitchTwitchでサインインします。Liteは既定で自分のチャンネルを使います。別のチャンネルはOptionsで設定できます。認証の有効期限が切れた場合は、再度サインインしてください。
KickOptionsでチャンネル名を入力して接続します。自動検索に失敗する場合はチャンネル名の綴りを確認し、必要に応じてチャットルームの手動設定を使ってください。
TikTokこの連携は現在、標準のLiteパネルでは非表示です。対応するTikTok Chat Readerプロキシが必要で、アドレスが入力済みでもサービスが利用可能とは限りません。利用できるTikTokの取得方法については、フルアプリを使ってください。

接続を解除 は、そのソースを停止します。YouTubeとTwitchではサインイン状態を保持するため、次を使用できます： 接続（Connect） をもう一度選びます。 サインアウト は、このブラウザーに保存された認証情報を削除します。

3. 既存のSocial Stream設定を使う

既存のドックやオーバーレイに送信するには、Liteのセッション設定を開き、そのセッションIDを入力します。次を選択します： セッションIDを保存 を選ぶかEnterキーを押します。IDを変更するとLiteのメッセージ送信先が切り替わります。追従させるブラウザーソースのURLも更新してください。

同じセッションでは、チャンネルごとに取得方法を1つだけ使ってください。Liteと拡張機能やデスクトップアプリで同じチャットを同時に取得すると、重複する場合があります。1つのチャンネルをLiteで、ほかのソースをフルアプリで扱うことはできます。

Liteが生成するリンクは既定のセッションパスワードを使います。パスワード保護やカスタムサーバーを使う設定では、フルアプリの接続設定が必要になる場合があります。Liteは、フルアプリの取得、自動処理、モデレーション、オーバーレイのカスタマイズ機能を置き換えるものではありません。

Activityの 寄付のみ および テキスト読み上げ の操作はLiteのアクティビティ表示に適用されます。アクティビティのポップアウトを使うときは、Liteのメインページを開いたままにしてください。他人にセッションへ参加されたくない場合は、オーバーレイURLを非公開にしてください。

すべてをOBS内で実行する

方法A：Liteドック＋通常のオーバーレイ

  1. 開く項目： すべてをOBS内で実行する をLiteで開き、次をコピーします： OBSカスタムドックのURL (lite/index.html?view=dock).
  2. OBSの次の項目から追加します： カスタムブラウザードック（Custom Browser Docks）。そのドックでサインインし、ソースを設定します。Source Optionsとセッション設定も、引き続きそこで利用できます。
  3. ドックの通常のオーバーレイURLを、OBSのブラウザーソースにコピーします。取得中はLiteドックを読み込んだままにしてください。このソースはメッセージの表示だけを行うため、プロバイダーに別途サインインする必要はありません。

OBSだけで使う最も簡単な方法です。ドックで取得し、ブラウザーソースで表示します。ドックを閉じると取得が止まります。設定後はデスクトップブラウザーを開いておく必要はありません。

方法B：1つのブラウザーソースで取得と表示（実験的）

  1. 次を追加します： スタンドアロンの取得＋オーバーレイURL (lite/index.html?view=overlay）をOBSのブラウザーソースとして追加します。
  2. 開く項目： 対話（Interact） でソースを設定します。設定済みの場合は、次のキーを押します： Escape をInteractで押すと設定を開き直せます。このソースにはサインインページや設定操作が表示されるため、配信に映さずに設定してください。
  3. 選ぶ項目： オーバーレイを表示。ページ自身が受信したチャットを透明な背景に表示します。別のLiteタブ、ドック、中継接続は不要で、同じセッションのほかのオーバーレイには送信しません。
  4. 次はそのままにします： 表示されていないときにソースをシャットダウンする（Shutdown source when not visible） および シーンがアクティブになったときにブラウザーソースを更新する（Refresh browser source when scene becomes active） をオフにすると、シーン変更時に取得が中断されません。参照： OBSブラウザーソースのプロパティ.

保存されたYouTube／Twitchの認証情報が有効であれば、起動時に再接続します。Kickでは次を有効にします： OBSモードでこのKickチャンネルに自動再接続する をOptionsで有効にします。先にチャンネルを設定してください。TikTokは非表示のままです。レイアウトは、通常のアクティビティ表示に保存した設定とは別に、すべてのメッセージを表示し、読み上げをオフにした状態で始まります。

OBSドック、OBSブラウザーソース、デスクトップブラウザーでは、Cookieやストレージのプロファイルが異なる場合があります。ドックを設定しても、独立したブラウザーソースでサインイン済みになるとは限りません。OBSブラウザーソース内でサインインできない場合は方法Aを使ってください。OBS内でのプロバイダー認証は実環境での検証が必要なため、このモードは実験的な機能です。

チャンネルごとに取得場所を1つにしてください。スタンドアロンの取得・表示ソースと同じチャンネルを、ドックでも取得し続けないでください。同じ取得ソースを複数のシーンで使う場合は、OBSの既存ソースを追加する機能を使用します。

トラブル対処

オーバーレイが空白になる
Liteが開いたままで、オーバーレイが同じセッションIDを使っていることを確認します。テストメッセージを送信してください。テストは届くのに実際のチャットが届かない場合は、ソースの状態とチャンネルを確認します。どちらも届かない場合は、オーバーレイURLと、ネットワークが中継接続をブロックしていないかを確認します。
リンクのコピーがブロックされる
表示されているオーバーレイURLをクリックし、選択されたテキストをキーボード操作または端末のコピーメニューでコピーします。
ソースが待機状態かエラーになる
Optionsとエラー文を確認します。設定を修正してから再接続してください。YouTubeとTwitchは、認証の有効期限が切れると再サインインが必要になる場合があります。
メッセージが重複する
別のLiteタブ、拡張機能、デスクトップアプリが、同じチャンネルとセッションのチャットを取得していないか確認します。意図した取得方法だけを起動してください。
設定が消えた
設定は、このブラウザーのローカルストレージに保存されます。別のブラウザーやプライベートウィンドウを使った場合、またはサイトデータを消去した場合は、別の設定になります。
