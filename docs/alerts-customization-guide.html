Design custom alerts and event feeds

Restyle Multi-Alerts and event rows for donations, subscriptions, gifts, follows, and other supported actions.

To keep recent alerts visible in OBS or Streamlabs Desktop, start with the illustrated event overlay guide.

Choose the right starting page

Use multi-alerts.html for timed alert presentations and events.html or themes/events/index.html for a running event list. They have different rendering and queue behavior. Begin with the URL generated for the tool you already use.

Choose an activity feed style

Open Activity Feed / Events → Enable and customize → Feed style, choose a layout, then copy the updated link into your browser or OBS Browser Source. Open Customize feed appearance to adjust colors and spacing. Leave a field empty to use the style's default.

Add these options to your existing events.html?session=YOUR_SESSION_ID link with &. Preserve your session, password, and connection options.

  • accent, pagebg, cardbg, textcolor, and mutedcolor: CSS colors. Encode a hex color's # as %23 in the URL, or omit the #.
  • fontsize=14: text size, 10–40 pixels. padding=8, gap=4, and radius=6: row padding, space between events, and corner radius, each 0–40 pixels.
  • noheader hides the page heading; noanimation disables entry animation.
  • Combine styles with lightmode, transparent, font, googlefont, scale, notime, and hidemeta. Transparent mode overrides the page background; card backgrounds remain separately adjustable.

For example, append &style=twitch&accent=%23e5b94f&padding=8&fontsize=14 for a denser activity list with a gold accent.

Choose what appears in the activity feed

In Activity Feed / Events → Enable and customize, open Choose which events appear or Row contents and behavior. Leave the controls off and fields empty to keep the default view. Copy the updated link after changing them. These controls affect this feed only; ordinary chat remains excluded.

Each row belongs to one category based on its event name. Named memberships, gifts and purchases keep their category even when they include an amount. Tips with hasDonation and no recognized event name belong to the paid-message category, including Twitch DOM bits. Membership badges on ordinary chat do not turn it into a membership event.

For finer control, use filterevents=supersticker,watch_streak to hide exact event names. Matching ignores case and uses the feed's existing event aliases; it does not search message text. Category and exact-name exclusions combine with the existing source, donations-only, gifted-subs-only and minimum-value filters. Enabling several filters can leave no matching events. See the event reference for source-specific payloads.

  • hidemessage, hidecontentimg, hideplatformicons, hideeventlabels and hideamounts hide the corresponding row elements. They do not discard the event or change what click-to-feature sends. Inline emotes are part of message text. Amounts or names written into message text, metadata or Hype Train details are not redacted by these controls.
  • nofeature disables click-to-feature in this feed. Metadata details can still be opened.
  • hidecategorytag hides only the generic category tag, such as Donation or Event, while keeping the descriptive event label. In the popup, enable Hide category tag under Row contents and behavior.
  • eventduration=60 removes a row from this feed after 60 seconds. Blank or 0 keeps the existing retention behavior; positive values range from 1 to 86,400 seconds. Hype Train updates restart their timer; ended trains still disappear after at most 30 seconds. Removal does not clear an event already sent to a featured overlay.
  • hideempty hides the waiting message when no events are visible.

Download and keep the file structure

  1. Download the source ZIP and extract it. These guides use the beta source; keep the files from one download together.
  2. Copy multi-alerts.html to my-alerts.html beside the original. If choosing a different page or theme, keep its copy in that file's original folder.
  3. Open the copied HTML and its referenced CSS/JS in your editor or AI tool. Add supplied artwork/fonts to the same project and use relative paths. Start with CSS overrides; include the renderer when changing generated markup.

The following files help you find the design and behavior. This is a reading list, not a complete dependency bundle: keep the extracted folder intact, including images, fonts, scripts, and any data files.

Connect your copy and open it in OBS

Start SSN and make the original generated overlay URL work first. The session= value connects to that SSN session; it is not your channel name or this file's name. Keep SSN, the relevant feature, and its data sources running.

  1. Drag your edited HTML file into Chrome or Edge. Copy its address from the address bar; it starts with file:///.
  2. Copy everything from ? onward in your working SSN overlay link and add it to the end of that file address. Keep all settings, including the session, password, and any # ending.
  3. Open the result in a browser, then set an OBS Browser Source's URL to the same address with Local file unchecked. Match the source dimensions to your intended design.

For the starting file above, the local address looks like this; your actual link may contain additional required options:

file:///C:/SSN/social_stream-beta/my-alerts.html?session=YOUR_SESSION

Use the actual file address on your computer. OBS saves it with the source; keep the downloaded folder in the same place. After saving design changes, refresh the Browser Source. The shared setup guide includes Mac examples and an optional launcher for the Local file checkbox.

Where to change the design

Change the alert frame, typography, icon placement, progress/timing decoration, and motion. In Multi-Alerts, much of the layout is created in multi-alerts.js; include it when asking AI to change the structure. For an isolated fork, copy that script too and update only your copied HTML's script reference.

Preserve event classification and filters. A paid chat row may use hasDonation without event: "donation"; platforms also have specific event names. Use the event reference and compatibility guide to choose samples. Keep the original display amount and any numeric USD override separate.

Test this overlay type

Use a preview or test setup first. The test-message guide explains how to send fictional payloads through SSN; a test submitted to your production session can trigger its existing automations.

  1. Use the test-message tool to send the specific follow, subscription, gift, raid, or paid message your source supports; check which fields are actually present.
  2. Send two alerts close together to check the queue and exit animations. Test an empty message with a donation label and a long name.
  3. For event feeds, check scrolling, filtering, and any feature-on-click behavior. For sound effects, check source audio in OBS as well as the picture.

Also run the input-rendering checks against the render paths you changed. After saving edits, refresh the OBS Browser Source between rehearsals and repeat the visible interaction. Browser previews do not establish live capture or OBS behavior.
