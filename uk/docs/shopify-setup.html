Shopify у Social Stream Ninja

Просувайте публічні товари із зображеннями, цінами, читабельними посиланнями й QR-кодами. Отримуйте підписані сповіщення про оплачені замовлення як purchase сповіщення в стрічці активності, мультисповіщеннях і Event Flow. Просування товарів працює незалежно від платіжних сповіщень.

Доступність: автоматичні сповіщення потребують розгорнутого й увімкненого приймача Shopify в API SSN. Якщо він недоступний, Save setup повідомляє про помилку й не вмикає Shopify. Публічний імпорт товарів і ручне просування працюють незалежно. Цей посібник описує код інтеграції; перед твердженням про перевірку живого сервісу все ще потрібен тест зі справжнім продавцем.

Підключіть оплачені покупки

  1. У Shopify відкрийте Settings → Notifications → Webhooks. Знайдіть секрет підпису для вручну створених вебхуків. Він відрізняється від токена Storefront.
  2. У SSN відкрийте Monetization → Shopify purchases → Setup. Введіть постійний your-store.myshopify.com домен і секрет підпису вебхука. Увімкніть покупки Shopify, а потім натисніть Зберегти налаштування.
  3. Натисніть Скопіювати URL приймача. У Shopify створіть вебхук із подією Оплата замовлення (Order payment), формат JSONі цей URL приймача. Виберіть підтримувану стабільну версію API вебхуків; цю інтеграцію розроблено за контрактом замовлень 2026-07.
  4. Збережіть вебхук Shopify. Залишайте SSN увімкненим для обробки покупок. Приймач перевіряє HMAC сирого тіла й відповідність магазину перед прийманням даних замовлення.

Секрет підпису шифрується на приймачі SSN і очищується з поля після збереження. Окремий приватний ключ читання залишається на цьому пристрої. Жоден із них не входить до посилань OBS чи глядацьких QR-кодів. Shopify використовує власний приймач; старий перемикач дистанційного керування API не потрібен.

Згенерований URL означає, що конфігурацію збережено, а не що Shopify щось доставив. Стан розрізняє очікування, перевірений тест, пропущену подію та отриману покупку. Для зміни магазину спочатку потрібен Disconnect. Вимкнення Shopify призупиняє локальну обробку; Disconnect видаляє приймач і події в черзі. Під час відключення видаліть відповідний вебхук Shopify.

Імпортуйте публічний товар

  1. Введіть свій myshopify.com домен у налаштуванні Shopify. Для імпорту товарів не потрібно вмикати сповіщення про покупки або вводити секрет підпису.
  2. Розгорніть Імпортувати товар, вставте публічний URL товару й натисніть Завантажити дані товару.
  3. Якщо доступ без токена не надає товар, укажіть публічний токен Storefront. Канал Headless Shopify може його створити. Опублікуйте товар у цьому storefront і в Online Store. Не вставляйте токен Admin API або приватний токен Storefront.
  4. SSN відкриває наявний Товари та посилання підтримки редактор із назвою, зображенням, ціною й канонічним публічним посиланням від Shopify. Перевірте їх, натисніть Додати товар або посилання, увімкніть каталог і Зберегти налаштування.

Імпорт читає по одному товару через Storefront API. Токен необов’язковий, використовується лише для цього запиту й потім очищується. Канонічний URL Online Store Shopify стає публічним посиланням, зокрема з власним доменом, якщо Shopify його повертає. Недоступні товари та товари без публічного посилання Online Store виключаються.

Ціна заповнюється лише тоді, коли мінімальна й максимальна ціни варіантів товару збігаються. Інакше вона залишається порожньою; самостійно виберіть конкретну ціну, лише якщо вона точно описує пропозицію. Імпортована інформація — це знімок, а не безперервна синхронізація запасів або цін. Перевіряйте її після змін у магазині. Завжди можна натомість додати товар вручну.

Використовуйте наявні оверлеї

У розділі Посилання оверлею для, виберіть Товари та посилання підтримки. Використовуйте Лише вітрина товарів для зображень, цін і QR-кодів, Лише картка підтримки для невеликого постійного або періодичного посилання на магазин, або Лише сповіщення про активність для покупок. Скопіюйте кожне потрібне посилання OBS в окреме браузерне джерело, починаючи з 800 × 600.

Установіть необов’язковий фільтр джерела сповіщень на shopify , щоб показувати лише активність Shopify у загальному оверлеї монетизації. Увімкніть Products & support links для цього загального вигляду. Наявні мультисповіщення й стрічка активності отримують покупки Shopify незалежно від каталогу товарів.

Картки товарів посилаються на публічні сторінки товарів. Використовуйте Копіювати публічне посилання , щоб поділитися клікабельною адресою в чаті, і перевірте QR-код із телефона в кінцевому розмірі стріму. Сповіщення про покупку ніколи не бере QR-код або зображення з непов’язаного товару в ротації. Вебхуки замовлень не надають надійних URL зображень товарів, тому сповіщення про покупки використовують текст; імпортовані рекламні картки можуть показувати зображення.

Для Event Flow виберіть Event Type purchase та відфільтруйте джерело/тип до shopify. Порівняйте meta.commerce.orderTotal для правил суми замовлення та перевіряйте meta.commerce.currency перед порівнянням сум. Це покупки: жодна подія hasDonation або donoValue не надсилається, а цілі донатів не збільшуються. Рекламна картка з позначкою Gift не змінює класифікацію подій замовлень. Доставка іншій людині не є доказом подарунка автору.

Безпечний перегляд і перевірка

Переглянути приклад відкриває ізольований приклад оверлею без підключення до сесії. Він ніколи не запускає Event Flow, не змінює підсумків і не перевіряє платіж.

Замовлення Shopify, явно позначені test: true підтверджуються й показуються як тести у стані приймача без сповіщень про покупки чи дій. Відсутні тестові прапорці, неоплачені/частково оплачені замовлення, скасовані замовлення, нульові суми та застарілі або неприпустимі часові позначки також пропускаються. Для наскрізної перевірки використовуйте магазин розробки. Адміністративний приклад без надійного тестового прапорця не слід надсилати в активний процес нагород; перегляд SSN є безпечним способом перевірити вигляд.

Що ми перевірили без магазину

Ізольовані тести охоплюють справжню HTTP-доставку з підписаним Unicode JSON, змінені підписи, повторні доставки, ізоляцію тестових замовлень, точність валюти, завеликі запити, видалення приватних даних клієнтів і відновлення після офлайну через справжнє середовище виконання SSApp. Ці перевірки не оформлюють замовлень і не потребують облікового запису продавця.

Робочий приймач Shopify залишається вимкненим до перевірки доставки зі справжнього магазину. Ручне просування товарів доступне незалежно. Приклади вебхуків Shopify CLI можуть допомогти перевірити обробку даних, але не підтверджують підписок або повторних спроб і все одно потребують облікових даних застосунку. Див. Обмеження доставки й усунення несправностей

  • Приймач недоступний: оператор SSN API повинен розгорнути та ввімкнути приймач Shopify. Не використовуйте застарілу непідписану URL-адресу вебхуку сеансу як заміну.
  • Очікування події: перевірте Order payment, JSON, точний URL приймача, відповідний постійний домен магазину й секрет підпису цього вебхука. Вебхук власного застосунку використовує секрет підпису цього застосунку, а не ручний секрет Notifications.
  • Підписану подію пропущено: цій інтеграції потрібне повністю оплачене замовлення з додатною сумою, test: false і підписане тіло updated_at протягом останніх семи днів (із допуском майбутнього часу на п’ять хвилин). Вона не визначає оплату за створенням замовлення, його виконанням чи запасами.
  • SSN був офлайн: прийняті події залишаються в черзі до семи днів. Перезапустіть SSN, щоб продовжити. Стан і незавершена робота зберігаються після перезапуску приймача. Сервіс має обмежене сховище й просить Shopify повторити спробу, якщо не може надійно поставити роботу в чергу.
  • Дублікати: приймач дедуплікує за магазином/замовленням, навіть якщо ID доставок Shopify відрізняються. Записи дедуплікації зберігаються сім днів. SSN зберігає оброблені ID перед підтвердженням. Збій між зовнішньою дією та цим збереженням усе одно може повторити дію; використовуйте власний захист ідемпотентності для автоматизації з важливими наслідками.
  • Ім’я покупця відсутнє: навмисно. SSN виключає імена клієнтів, електронну пошту, адреси, примітки замовлень, власні властивості позицій, URL оформлення покупки й сирі ID замовлень. Публічні назви товарів залишаються звичайним текстом.
  • Повернення коштів або зміни замовлень: це жива стрічка сповіщень, а не система обліку чи виконання замовлень. Повернення коштів, скасування та змінені суми не скасовують попередніх сповіщень. Зіставлення історії замовлень або автоматичне видалення товарів не передбачені.
