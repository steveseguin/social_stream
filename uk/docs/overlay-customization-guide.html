Створіть власні накладки Social Stream

Завантажуйте, налаштовуйте, підключайтеся та тестуйте локальні дизайни накладень у OBS із посібниками для кожної сімейства накладень.

Виберіть накладання, дизайн якого потрібно змінити

Завантажте файли→Змінити дизайн→Відкрити в OBS

Ви можете змінити кольори, шрифти, макет, ілюстрації та рух наявної сторінки. The Файл HTML – сторінка; в URL-адреса OBS вказує на нього та надає налаштування сесії та відображення. Для невеликої редакції використовуйте OBS Custom CSS на розміщеній сторінці. Для глибших змін завантажте джерело та запустіть власну копію.

Ці посібники охоплюють сімейства накладень, включаючи їхні теми. Виберіть отримувача для функції, яку ви використовуєте: сторінка чату, сторінка вибраних повідомлень і опитування не всі споживають однаковий вхід.

Для початку готового дизайну в Галерея оверлеїв або Галерея шаблонів. Для існуючої оболонки чату StreamElements/Streamlabs дотримуйтесь посібник з імпорту. Імпортований самодостатній HTML має власні інструкції з експорту/налаштування.

1. Завантажте фактичні файли

  1. Завантажити код beta у ZIPабо відкрийте бета-репозиторій і виберіть Код → Завантажити ZIP.
  2. Розпакуйте ZIP у папку, яку ви можете зберегти, наприклад C:\SSN\social_stream-beta\. Не редагуйте всередині стисненого архіву. Це вихідні файли сторінки; редагування окремої копії не вимагає перевстановлення SSN.
  3. Знайдіть файл, показаний у таблиці вище. Скопіюйте його поруч з оригіналом: наприклад poll.html стає my-poll.html. Для themes/featured-styles/featured-modern.html, збережіть копію themes/featured-styles/.
  4. Відкрийте копію в редакторі тексту/коду. Надайте своєму інструменту штучного інтелекту доступ до цього файлу та потрібних йому стилів/скриптів, на які посилаються. Зберегти HTML як .html, ні .html.txt.

Зберегти витягнуту структуру папок. Один завантажений файл HTML може завантажувати поряд сценарії, таблиці стилів, шрифти, зображення, аудіо або JSON. Перегляд сторінки GitHub і «Зберегти сторінку» браузера не є повним надійним пакетом. Кожен тип посібника визначає корисні файли, але повна витягнута папка є найпростішим способом зберегти залежності.

social_stream-beta/
    poll.html
    my-poll.html
    currency.js
    js/
    libs/
    shared/
    thirdparty/
    media/
    sources/images/
    themes/
        featured-styles/
            featured-modern.html
            my-featured.html
    docs/
        event-reference.html

Посилання, наприклад ../../shared/utils/chatHtml.js відносно сторінки, яка його завантажує. Переміщення цієї сторінки до кореня порушує шлях. Також скопіюйте локальні ілюстрації та шрифти в проект, а потім використовуйте відносні URL-адреси. Зберігайте завантажені версії разом; ваша відредагована копія не отримає автоматично майбутні виправлення SSN.

2. Збережіть налаштування сеансу та підключення

Запустіть SSN, підключіть джерело та переконайтеся, що оригінальне накладання працює. Скопіюйте повне згенероване посилання з відповідного інструменту SSN. Значення після session= ідентифікує вашу сесію SSN; це не канал YouTube, ім’я користувача Twitch, ім’я файлу чи назва опитування.

https://socialstream.ninja/poll.html?session=YOUR_SESSION&password=YOUR_PASSWORD&server2

У прикладі використовуються заповнювачі. SSN і сторінка повинні використовувати той самий фактичний сеанс і будь-який налаштований пароль. Зміна імені файлу не змінює сеанс. Підтримуйте роботу SSN і захоплення: накладення отримує дані; він не захоплює чат платформи сам по собі.

  • ? запускає запит; використання наступних налаштувань &. Копіюйте значення, а не вводьте їх повторно. В атрибуті джерела HTML напишіть &amp;; у полі URL-адреси браузера/OBS використовуйте звичайний амперсанд.
  • Зберегти налаштування транспортування: server, server2, server3, локальні кінцеві точки, мітки та значення версії залежать від сторінки. Не додавайте позначку сервера лише тому, що це підтримує інше накладання.
  • Збережіть також фрагменти: все після # може мати значення. Наприклад, AI Event Overlay використовує приватний #aieventauth=... маркер відображення.
  • Використовуйте заповнювачі в спільних прикладах. Зберігайте своє справжнє посилання на сеанс, пароль і приватні маркери відображення подалі від загальнодоступних скріншотів, сховищ і прикладів підказок AI.

Якщо копія залишається порожньою, спочатку перевірте оригінальне згенероване посилання. Деякі сторінки запитують про відсутні налаштування; інші залишаються прихованими або перенаправляються. Надання правильного сеансу явно уникає покладатися на ці специфічні для сторінки значення за замовчуванням.

3. Відкрийте свій файл у OBS

Відкрийте відредагований HTML безпосередньо зі свого комп’ютера. Немає сервера для встановлення чи запуску.

  1. Перетягніть скопійований файл HTML у Chrome або Edge. Скопіюйте його повну адресу з адресного рядка; це починається з file:///.
  2. Копіювати все з ? далі у вашому робочому накладеному посиланні SSN і додайте його в кінець цієї адреси файлу. Це зберігає ваш сеанс, пароль, інші налаштування тощо # закінчення.
  3. Відкрийте комбіновану адресу у своєму браузері, щоб перевірити її.
  4. В OBS додайте Джерело браузера (Browser Source). Залиште Локальний файл зніміть прапорець і вставте повну адресу URL. Встановіть ширину та висоту для вашого дизайну.

Наприклад, це посилання SSN:

https://socialstream.ninja/poll.html?session=YOUR_SESSION&password=YOUR_PASSWORD&server2

стає цією адресою для завантаженої копії опитування у Windows:

file:///C:/SSN/social_stream-beta/my-poll.html?session=YOUR_SESSION&password=YOUR_PASSWORD&server2

Використовуйте фактичну адресу файлу та скопійовані налаштування. На macOS адреса починається з file:///Users/...; у Linux це зазвичай починається з file:///home/.... Копіювання адреси браузера обробляє пробіли та косі риски за вас.

Налаштуйте це один раз. OBS зберігає адресу з джерелом. Зберігайте завантажену папку в тому самому місці та продовжуйте працювати SSN і джерело чату під час використання накладання. Після збереження зміни дизайну використовуйте Оновити кеш поточної сторінки (Refresh cache of current page) у властивостях джерела.

Чому не відмічено позначку «Локальний файл»? Поле URL-адреси дозволяє включити ?session=.... Вибір HTML лише за допомогою засобу вибору файлів не додає ці налаштування.

Додатково: використовуйте прапорець «Локальний файл» із засобом запуску

Засіб вибору файлів OBS вибирає файл; він не додає згенеровані параметри запиту. Для немодифікованого приймача на основі запитів невеликий локальний засіб запуску може переходити до редагованої сторінки з доданими налаштуваннями:

  1. Збережіть наступне як launch-my-poll.html біля my-poll.html.
  2. Замініть розміщену URL-адресу-заповнювач на повністю скопійоване посилання SSN. Зміна ./my-poll.html до фактичної відредагованої назви файлу. Зберігайте посилання всередині лапок, звичайними & символи.
  3. Двічі клацніть програму запуску, щоб перевірити її. У OBS виберіть Локальний файл і виберіть пускова установка. Він перенаправляє до локального оверлею із запитом і фрагментом.
<!DOCTYPE html>
<html lang="en">
<meta charset="utf-8">
<title>My local overlay launcher</title>
<p>Opening the local overlay...</p>
<script>
var copiedLink = new URL("https://socialstream.ninja/poll.html?session=YOUR_SESSION");
var localPage = new URL("./my-poll.html", window.location.href);
localPage.search = copiedLink.search;
localPage.hash = copiedLink.hash;
window.location.replace(localPage.href);
</script>
</html>

Для вкладеної теми розмістіть панель запуску поруч із цією копією теми. Зберігайте панель запуску приватною, оскільки вона містить ваше посилання на підключення. Завантажений самостійний експорт, який уже вбудовано в конфігурацію, натомість дотримується власних інструкцій щодо експорту.

OBS документує свої режими файлу/URL, розміри, користувацький CSS і елементи керування оновленням у Посилання на джерело браузера.

4. Змініть дизайн або попросіть штучний інтелект зробити це

Щоб змінити лише CSS, збережіть розміщене посилання та використовуйте OBS Власний CSS поле. Це стосується лише цього джерела, тому звичайний браузер, який відкриває ту саму URL-адресу, не відображатиме ці перевизначення. Для відредагованого HTML-файлу додайте перевизначення після існуючих стилів або зв’яжіть локальну таблицю стилів після них. Надайте свій логотип, файли шрифтів, фірмові кольори, розмір полотна та візуальне посилання.

Деякі сторінки підтримуються &css= або &b64css=; підтримка надається на сторінку. poll.html, наприклад, читається ні. Перевірте аналізатор сторінки перед використанням параметрів URL-адреси. Веб-сторінка зазвичай не може завантажити довільний шрифт або зображення з локального диска іншого комп’ютера.

Змінюючи розмітку, зберігайте ідентифікатори/класи, на які посилаються сценарії. Якщо JavaScript перебудовує елемент під час кожного оновлення, постійна ілюстрація має бути за межами цього елемента або відтворюватися рендерером. Скопіюйте спільну таблицю стилів/сценарій і змініть посилання на свою сторінку, якщо ви хочете, щоб редагування вплинуло лише на ваш дизайн.

Використовуйте підказку для конкретного типу в посібниках вище або почніть із цієї загальної підказки:

Customize [copied overlay filename] to match [reference/design].
Canvas: [width x height]. Placement: [position]. Colors/fonts: [details].
Use the existing page and its supporting files, rather than replacing its
connection and event logic. Read docs/event-reference.html and the relevant
overlay design guide. Preserve query parameters, session/password, URL
fragments, bridge labels, transport channels, settings, and controls.
Use CSS first. Keep relative paths and package all executable dependencies
locally. Use classic scripts compatible with Chrome 80.
Keep operator controls, private links, and credentials off the audience view.

Treat all incoming messages, names, labels, donations, and metadata as untrusted.
Prevent HTML/JavaScript injection in every renderer you change. Use textContent
for plain fields and for chatmessage when textonly is true. For HTML-mode
chatmessage, keep supported emotes/formatting through the packaged
SocialStreamChatHTML.sanitize helper (libs/objects.js loaded first).
Do not concatenate raw input into innerHTML, attributes, CSS, or JavaScript.
Validate media/link URLs with the page's existing URL policy and assign DOM
properties; do not enable javascript: URLs or executable embedded content.

probe in an isolated preview; verify the probe cannot execute.

Make the edited overlay work directly from disk using a file:/// URL,
without requiring a local web server. Return the edited files and assets,
file URL and OBS setup steps, and tests
for this overlay's real trigger. Use session placeholders in shared examples.

Посібники з типів описують справжній тригер для збереження. Не приймайте дизайн, який працює лише тому, що він жорстко кодує зразки повідомлень. Збережіть копію оригінального файлу та порівняйте відредагований дисплей, використовуючи ті самі тестові вхідні дані.

5. Не допускайте, щоб вхідний чат став кодом

Повідомлення, імена, заголовки, суми, метадані та медіа-посилання можуть надходити від глядачів або зовнішніх служб. Дезінфікуйте в тому місці, куди їх вставляє спеціальний рендерер. Рядок, отриманий через SSN, не є дозволом на його виконання. Використовуйте звичайний текст DOM для звичайних полів; використовуйте запакований дезінфікуючий засіб для HTML, що підтримується тілом повідомлення. див Пояснення OWASP щодо безпечних прийомів і очищення HTML.

У SSN, textonly стосується лише chatmessage. Якщо істина, відобразити це тіло як буквальний текст. Інакше він може містити емоції та дозволене форматування. Виводити інші звичайні поля як текст; медіа поля, такі як chatimg і contentimg – це URL-адреси/дані, а не фрагменти HTML.

<!-- Example for a copied page at the repository root. -->
<script src="./libs/objects.js"></script>
<script src="./shared/utils/chatHtml.js"></script>
<script>
function renderChatBody(element, data) {
    var message = String(data.chatmessage == null ? "" : data.chatmessage);
    if (data.textonly) {
        element.textContent = message;
    } else {
        element.innerHTML = SocialStreamChatHTML.sanitize(message);
    }
}
// Names, amounts, titles, and other plain fields use textContent:
// nameElement.textContent = String(data.chatname || "");
</script>

Залиште існуючий еквівалентний дезінфікуючий засіб, а не додайте другий. Для вкладених файлів налаштуйте відносні шляхи сценаріїв. Створюйте аватари та посилання за допомогою властивостей DOM після перевірки URL-адреси відповідно до існуючої політики медіа/посилань сторінки. Не вставляйте необроблені імена в рядки атрибутів або необроблені кольори в розмітку стилю; перевірити стилі перед встановленням окремих властивостей. Дезінфекція HTML не робить рядок безпечним для виконання як JavaScript або інструкції ШІ.

Перевірте рендерер в ізольованому попередньому перегляді

  • Використовуйте просту назву, наприклад Guest <b>One</b>: у дужках має залишитися текст.
  • Спробуйте chatmessage: "<b>Hello</b>" з textonly: true, тоді false. Літеральна розмітка та дозволений форматований вміст повинні мати відповідні шляхи.
  • Перевірте підтримувану емоцію та повідомлення лише із зображенням, щоб зміни безпеки не видаляли ці функції.
  • Попросіть ШІ перевірити нешкідливий зонд, наприклад <img src=x onerror="window.__ssnInjectionProbe=1"> у зміненому рендерері. Він не повинен виконуватися, встановлювати маркер або залишати виконувані атрибути події. Перевірте також посилання на схему сценарію. Запускайте зонди локально, а не в публічному чаті.

Прохідний зонд перевіряє лише визначені шляхи. Тримайте тести зосередженими на рендерерах і полях, змінених дизайном.

6. Перевірте макет, підключення та OBS окремо

  1. Макет: використовуйте задокументований попередній/демонстраційний режим сторінки, якщо доступний, або вигадані місцеві зразки. Перевірте довгі імена/повідомлення, відсутні аватари, порожні дані та очікувану кількість рядків.
  2. Доставка SSN: залишайте SSN активним і використовуйте Створити тестове повідомлення з тією ж сесією. Потрібен звичайний режим прийому API розширення віддалене керування розширенням через API увімкнено. Використовуйте ізольовану тестову установку; подані тести можуть запускати налаштовану автоматизацію.
  3. Фактичний тригер: показувати повідомлення Dock для пропонованої картки, надсилати голосування для опитування, вибирати переможця для розіграшу, змінювати текст тикера для тикера або запускати таймер для таймера. Звичайний чат не є універсальним тестом.
  4. Справжнє захоплення: підтвердити, що повідомлення/подія фактичного джерела потрапляє на оригінальну та відредаговану сторінку. Фіктивна подія підтверджує рендеринг, а не захоплення платформи.
  5. OBS: перевірити джерело на його кінцевий розмір, прозорість, анімацію, звук, шрифти та шари. Вправа показати/сховати, очистити/скинути та оновити. Браузер і OBS мають окреме сховище та сеанси; логін браузера або localStorage не надається автоматично.

Для сторінок, які збирають дані в пам’яті, вивантаження або оновлення може втратити стан. Перш ніж увімкнути автоматичне оновлення або вимкнення, коли приховано, перевірте посібник із типів. Дисплеї, керовані хостом, мають різну поведінку відновлення. видалити demo/preview позначки перед очікуванням живих даних.

Корисні файли та довідкові матеріали для вашого ШІ

  • docs/event-reference.html: канонічні поля, іменовані події, метадані, медіа та значення пожертв.
  • docs/customoverlays.md: спеціальні приймачі та приклади підключення.
  • Сумісність подій і сповіщень: які події/поля проект може очікувати від джерела.
  • Керівництво з тестового повідомлення і createtestmessage.html: зразки корисних навантажень і режимів доставки.
  • libs/objects.js і shared/utils/chatHtml.js: пакетна дезінфекція дисплея.
  • shared/utils/chatBadges.js і shared/utils/contentImage.js: існуючий бейдж і обробка зображень.
  • js/transport-dedupe.js, js/local-server-url.js, і shared/overlay-control-transport.js: наявна транспортна підтримка під час завантаження вашої сторінки.
  • currency.js: зберегти hasDonation для відображення та врахування дійсного цифрового долара США donoValue, включаючи нуль.
  • Потоки подій і Команди й API: повторне використання наявних елементів керування, коли дизайну потрібен тригер.

Надайте фактичне джерело накладення та посилання на CSS/JS, а також ці документи. Одне лише посилання на подію не описує контрольний стан опитування або приватну структуру візуалізації кожного накладання.

СимптомПеревірте
Файл не знайденоЗнову перетягніть HTML у свій браузер і скопіюйте поточну адресу файлу. Переконайтеся, що назва файлу закінчується на .html, а не на .html.txt.
Відсутній сценарій, шрифт або зображенняЗберігайте вилучену структуру папок без змін, з відредагованою копією поруч з оригіналом. Перевірте, чи всі додані ілюстрації та шрифти знаходяться в очікуваних папках.
Порожній або «очікуючий» дисплейПеревірте сеанс, пароль, повний запит/фрагмент, стан роботи SSN, увімкнену функцію та відповідний вхід. Порівняйте вихідну згенеровану URL-адресу.

Скидання стану або дії спрацьовують двічіПеревірте параметри оновлення/вивантаження, повторювані екземпляри виведення/контролю та існуючу поведінку дедуплікації/стану сторінки.
Особливий випадок: сторінки, які читають окремі файли даних

Карта читає локальні файли JSON за допомогою fetch(), які браузер може блокувати під час відкриття з диска. Для простого зміни стилю карти скористайтеся її розміщеним посиланням із OBS Custom CSS. Для відредагованої HTML-копії попросіть свій ШІ включити необхідні дані карти на сторінку, щоб вона відкривалася безпосередньо з диска. Хостинг — це розширена опція для сторінки, яка особливо потребує цього, а не звичайний крок налаштування для цих накладень.

Зупиніться на найменшій підтвердженій проблемі. Рестайлінг не повинен вимагати зміни сценаріїв захоплення або створення нових полів подій. Якщо ви користуєтеся загальнодоступним форком, додайте його допоміжні ресурси та не допускайте приватні програми запуску до цього завантаження.
