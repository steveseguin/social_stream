Створити тестові повідомлення

Надсилайте контрольовані вигадані повідомлення й події в сесію Social Stream.

Що робить цей інструмент

Цей Сторінка створення тестового повідомлення надсилає синтетичні дані Social Stream у док, оверлеї, сповіщення або Event Flow. Використовуйте його для перевірки, не чекаючи справжнього повідомлення чату, донату, членства, рейду, нагороди чи іншої події.

За можливості використовуйте тестову сесію. Надіслане повідомлення поводиться як вхідний трафік сесії та може запускати сповіщення, звуки, вебхуки, дії OBS або інші автоматизації.

Швидкий старт для SSApp або розширення

  1. Відкрийте Social Stream Ninja й переконайтеся, що сервіс активний.
  2. У розділі Загальні налаштування та інструменти → Механіка, увімкніть віддалене керування розширенням через API. SSApp використовує ту саму назву налаштування.
  3. Скопіюйте ID сесії із Social Stream або з session= значення в URL дока або оверлею.
  4. Відкрити Створити тестове повідомлення і введіть цей ID сесії.
  5. Залиште Надсилати через задається як Приймання через API розширення (Extension API ingest) для звичайної перевірки.
  6. Виберіть готовий приклад, змініть його поля та натисніть Завантажити готовий приклад (Load Preset).
  7. Перевірте Payload JSON, а потім виберіть Надіслати.
  8. Переконайтеся, що елемент з’являється в доку або цільовому оверлеї, а очікувана автоматизація виконується.

Сесію можна включити в URL: createtestmessage.html?session=YOUR_SESSION_ID.

Приклад: одне вигадане повідомлення на 1 000 KICKs

Це створює одне повідомлення підтримки у стилі Kick на 1 000 KICKs. Це не створює 1 000 окремих повідомлень.

  1. Виберіть Повідомлення чату (Chat Message) готовий приклад.
  2. Установіть Введіть до Kick.
  3. Введіть тестове ім’я та повідомлення.
  4. Установіть Містить донат (Has Donation) до 1000 KICKs.
  5. Виберіть Оновити JSON із полів, перевірте JSON і надішліть його.

Мінімальні дані:

{
  "type": "kick",
  "chatname": "Test Supporter",
  "chatmessage": "Thanks for the stream!",
  "hasDonation": "1000 KICKs"
}

Використовуйте Повідомлення чату (Chat Message) для цього прикладу. Донат / Cheer готовий приклад містить поля cheer, специфічні для Twitch.

Використання готових прикладів і власного JSON

Готові приклади надають початкові дані для поширених випадків: донатів, підписників, подарованих підписок, рейдів, нагород, оновлень глядачів, перших повідомлень і подій потягів.

  • Завантажити готовий приклад (Load Preset) замінює JSON вибраним готовим прикладом і поточними значеннями полів.
  • Оновити JSON із полів створює базове повідомлення з видимих полів.
  • Можна редагувати JSON даних (Payload JSON) безпосередньо під час перевірки конкретного поля або структури події.
  • hasDonation містить видиму суму підтримки, наприклад 1000 KICKs або $10.00.
  • Додавайте event лише під час перевірки справжньої іменованої події. Звичайний рядок чату з донатом може використовувати hasDonation сам по собі.

Визначення полів і справжні приклади платформ див. у Довідник подій.

Виберіть правильний режим доставки

Приймання через API розширення (Extension API ingest)Перевірка звичайних доків, оверлеїв, сповіщень, Event Flow або SSApp.Той самий ID сесії та віддалене керування розширенням через API увімкнено.
Безпосередньо на канал 1Цільовий док відкрито з &server.Ціль має прослуховувати відповідний канал сервера.

Якщо не впевнені, використовуйте Приймання через API розширення (Extension API ingest).

Поширені рішення

  • Нічого не з’являється: переконайтеся, що цільова сторінка відкрита й використовує той самий ID сесії.
  • Приймання через API розширення не працює: увімкніть віддалене керування розширенням через API, а потім перезавантажте док або оверлей і повторіть спробу.
  • Прямий режим повідомляє про надсилання, але нічого не з’являється: використовуйте Extension API ingest, якщо URL цілі не містить відповідного &server або &server2 режим.
  • Спрацьовує неправильна подія: перевірте Payload JSON на залишкові поля іншого готового прикладу.
  • Тест Kick поводиться як Twitch: використовуйте готовий приклад Chat Message й установіть type і hasDonation , як показано вище.
  • Автоматизація запускається кілька разів: перевірте, чи в одній сесії не відкрито кілька доків, сторінок дій або екземплярів Event Flow.
