1. Enable Local Server

Цей пункт меню File запускає всередині настільного застосунку ретранслятор WebSocket з урахуванням кімнат і каналів. Підтримувані сторінки Social Stream можуть через нього обмінюватися чатом і командами на одному комп’ютері. Це альтернативна кінцева точка для серверної маршрутизації окремих сторінок.

Він не розміщує сайт Social Stream, сам не захоплює платформу та не надає HTTP API автоматизації. Почніть із Посібник з Enable Local Server.

2. Локальний API керування та MCP

Цей API зворотної петлі, який вмикається за бажанням, дає програмам на комп’ютері SSApp змогу керувати підтримуваними джерелами й налаштуваннями, читати стан і діагностику, перевіряти вікна застосунку чи джерел і стежити за захопленими подіями. Вбудований адаптер MCP представляє ці операції як інструменти сумісним клієнтам ШІ.

Увімкніть його в File > Local AI / Automation. Це окремо від Enable Local Server. Дивіться Посібник API локального керування та MCP.

3. Домашній сервер або VPS без графічного інтерфейсу

Режим без графічного інтерфейсу запускає повний настільний застосунок Electron із прихованими вікнами джерел. У Linux йому все одно потрібна система відображення, наприклад Xvfb. Це корисно, коли окремий комп’ютер має продовжувати захоплення чату без підключеного монітора.

Режим без графічного інтерфейсу не створює публічного API керування. Дистанційне керування використовує звичайний транспорт Social Stream через WebRTC або WebSocket. Див. посібник із хостингу без графічного інтерфейсу.

4. Локальний медіасервер

Настільний застосунок запускає його автоматично, коли доступні локальні медіа Event Flow. Він надає лише файли, схвалені через SSApp, і вибрані ресурси середовища виконання через шлях із випадковим токеном для кожного профілю.

Це не універсальний вебсервер чи файловий сервер. Див. Медіафайли для Event Flow , щоб вибрати між локальними файлами, завантаженнями та хмарним хостингом.

Резервний сервер — інша функція

Налаштування на кшталт Send chat messages to API server і Dock sends its commands to Extension via server визначають маршрутизацію чату й команд. Їхні згенеровані прапорці URL включають server, server2, і server3.

Ці налаштування зазвичай використовують розміщений сервіс WebSocket Social Stream. Коли підтримувана сторінка також має localserver, натомість вона використовує локальний ретранслятор настільного застосунку. Див. Сесії, паролі, пересилання й режими сервера щодо елементів керування маршрутизацією.

Використовуйте щойно згенеровані посилання. Прапорці маршрутизації залежать від сторінки. Не копіюйте прапорець сервера з однієї сторінки на іншу, припускаючи, що він має те саме значення.

Інші тимчасові локальні порти

Деякі процеси входу й прив’язування облікових записів ненадовго відкривають порт зворотного виклику на адресі зворотної петлі та закривають його після завершення. Ці тимчасові слухачі не є універсальними серверами SSN або API автоматизації.
