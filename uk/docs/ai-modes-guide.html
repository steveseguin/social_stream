Браузерне джерело ChatGPTРозширення читає нові репліки User і ChatGPT, відображені у відкритій chatgpt.com вкладці.Розмова в браузері, яку ви відкрили; ключ API не використовується.

Важливо: підключення OpenAI API не приєднує SSN до наявної веброзмови або голосової розмови ChatGPT. API OpenAI керує власним станом розмови.

Варіант 1: браузерний компаньйон ChatGPT (експериментально)

Це найближчий варіант, якщо ви вже користуєтеся ChatGPT у Chrome й не хочете ключ API. SSN може захоплювати нові текстові репліки зі сторінки як джерело типу openai, так само як джерело чату.

Захоплення розмови ChatGPT

  1. Установіть і ввімкніть розширення Social Stream Ninja для Chrome.
  2. У спливному вікні ввімкніть необов’язкову функцію ChatGPT джерело.
  3. Відкрити https://chatgpt.com/ та перезавантажте сторінку після ввімкнення джерела.
  4. Відкрийте док SSN із тією самою сесією.
  5. Надішліть нове повідомлення ChatGPT. Нові репліки User і ChatGPT мають з’явитися в доку; наявна історія навмисно ігнорується.

Надсилати живий чат у відкриту вкладку ChatGPT

  1. Перевіряйте в приватній трансляції або трансляції за посиланням і у звичайній текстовій розмові ChatGPT.
  2. У розділі Керування, увімкніть Пересилати всі повідомлення.
  3. Установіть Виберіть цілі пересилання до openai щоб захоплені повідомлення глядачів надходили лише у вкладку ChatGPT.
  4. Тримайте вкладку ChatGPT відкритою. Її нові відповіді повертаються до SSN як openai повідомлення.
  5. Використовуйте аудіо ChatGPT або озвучення/оверлей SSN, щоб вивести ці відповіді на трансляцію.

Експериментально: елементи керування вебсторінкою можуть змінюватися, пересилання всіх повідомлень може переповнити розмову, а голосовий режим ChatGPT може не приймати вставлений текст так, як звичайна текстова сторінка. Використовуйте фільтри або тестову трансляцію, перш ніж надсилати кожне повідомлення глядача.

Варіант 2: налаштувати постачальника ШІ всередині SSN

Використовуйте постачальника, коли SSN має генерувати відповіді, модерувати повідомлення, перекладати чат, шукати в базі знань або створювати оверлеї.

Власний/локальний серверВласний API, сумісний з OpenAIДля llama.cpp, LM Studio, vLLM і сумісних шлюзів. Для Ollama слід використовувати його власну опцію.

ПробнийРозміщена пробна LLM SSNЕкспериментально; може бути вимкнено або обмежено за частотою запитів.
  1. Відкрити Чат-боти та сервіси ШІ у спливному вікні SSN.
  2. Відкрити Налаштувати постачальника сервісу LLM і виберіть постачальника, яким справді користуєтеся.
  3. Введіть його кінцеву точку, модель, ключ API або параметри локальних ресурсів.
  4. Виберіть Перевірити вибраний чат-бот. Результат Connected підтверджує лише те, що постачальник відповів на перевірку.
  5. Увімкніть окрему функцію, яка має його використовувати: основного бота, приватного бота, співведучого, модерацію, переклад, RAG або конструктор.

Варіант 3: голосовий співведучий на базі ШІ

Співведучий створений саме для сценарію «розмовляти з ШІ, який також бачить живий чат». Ваш мікрофон і вибрані повідомлення живого чату надходять в одну сесію співведучого, а відповідь можна озвучувати на трансляції.

  1. Відкрити cohost.html?session=YOUR_SESSION.
  2. Виберіть голосового постачальника/постачальника реального часу або LLM, налаштовану в спливному вікні SSN.
  3. Явно виберіть свій мікрофон і Голосова відповідь, потім натисніть Запустити співведучого.
  4. З OpenAI Realtime залиште Live Chat у режимі Лише контекст — відповідати на запит якщо хочете, щоб ШІ пам’ятав останні повідомлення глядачів, не перебиваючи. Виберіть Запитання та згадки або Кожне повідомлення для автоматичних голосових відповідей; ці режими не публікують повідомлення в чаті платформи.
  5. Для OpenAI Realtime захоплюйте аудіо браузера/застосунку співведучого в OBS і використовуйте cohost-overlay.html?session=YOUR_SESSION для сценічного аватара й бульбашки мовлення. Оверлей не отримує той самий голосовий потік WebRTC. Виберіть віртуальний кабель у списку вихідних пристроїв співведучого, якщо це підтримується; &forcetts навмисно додає окремий голос оверлею.
  6. Необов’язкові інструменти трансляції типово вимкнено. Увімкніть Spotify, список дозволених назв сцен OBS або керування вибраним чатом у спливному вікні SSN, потім активуйте ті самі інструменти в Керування трансляцією через співведучого на сторінці співведучого.
  7. Щоб зменшити затримку OpenAI, виберіть модель Mini, Low reasoning і Fast turn-taking. Full quality і вищий рівень міркування можуть покращити складні відповіді ціною більшої затримки та вартості API; Fast turn-taking може переривати природні паузи. Diagnostics показує виміряну затримку до першого виводу.
  8. Камера та демонстрація екрана для OpenAI необов’язкові й типово мають значення Без відео. Якщо вибрано, SSN надсилає одне поточне зображення з кожним прямим голосовим або текстовим запитом; це не безперервний відеопотік і може збільшити вартість API та затримку.
  9. Залишайте бульбашку мовлення видимою або додайте субтитри, щоб глядачі могли стежити за розмовою, не чуючи голосу ШІ.

OpenAI Realtime використовує ключ проєкту OpenAI, налаштований у ChatGPT API у спливному вікні SSN. Стандартний ключ залишається у фоновому процесі розширення/настільного застосунку SSN, який створює короткочасний клієнтський секрет Realtime для сторінки співведучого. Аудіо мікрофона й голосу ШІ потім передається через WebRTC. Відповіді обмежено 512 вихідними токенами, а Diagnostics показує сумарне використання та затримку. SSN перевіряє тихі сесії й відновлює розірвані транспортні з’єднання; відновлена сесія знову застосовує інструкції та параметри продуктивності, але не може відновити попередню голосову розмову. Це створює сесію співведучого SSN, а не перебирає на себе наявну розмову на сайті ChatGPT або в настільному застосунку ChatGPT.

Варіант 4: основний бот живого чату

Основний бот оцінює захоплені повідомлення глядачів і може відповідати в оверлеї, через озвучення або в підтримуваних чатах платформ.

  1. Налаштуйте та перевірте постачальника ШІ.
  2. Увімкніть Основний чат-бот ШІ.
  3. Виберіть слова-тригери, режим лише для модераторів, обмеження частоти, історію та інструкції запиту.
  4. Для безпечної першої перевірки ввімкніть Відповіді бота надходять ЛИШЕ на сторінку оверлею бота.
  5. Відкрити bot.html?session=YOUR_SESSION та ввімкніть озвучення, якщо відповіді мають звучати вголос.
  6. Вимикайте режим лише оверлею тільки після перевірки, що цільова платформа підтримує публікацію.

Відповіді на платформах зазвичай використовують обліковий запис, у який виконано вхід. Для окремого імені використовуйте спеціальний обліковий запис бота YouTube, Twitch або Kick, якщо це підтримується.

Відкрити посібник із налаштування чат-бота ШІ

Варіант 5: приватний особистий бот

chatbot.html — сторінка приватного помічника та перевірки запитів. Увімкніть Чат-бот — приватний інтерфейс, відкрийте сторінку зі своєю сесією та використовуйте налаштованого постачальника LLM.

Приватний бот відокремлений від основного бота живого чату й наразі не використовує його набір даних RAG або іншу історію чату.

Варіант 7: конструктор оверлеїв ШІ

Використовуйте aiprompt.html щоб описати, згенерувати, переглянути й зберегти оверлей. Використовуйте aioverlay.html як сторінку виводу OBS після збереження.

Відкрити посібник із конструктора оверлеїв ШІ

Поширені рішення

  • Підключено, але відповіді наживо немає: увімкніть основного бота або потрібну функцію ШІ; саме лише налаштування постачальника не обробляє чат.
  • Співведучий бачить чат, але мовчить: Context only навмисно чекає, поки стример запитає про чат. Перейдіть на Questions and mentions або Every message для автоматичних відповідей.
  • Браузерне джерело ChatGPT мовчить: увімкніть необов’язкове джерело ChatGPT, перезавантажте chatgpt.com, і перевіряйте новою реплікою, а не наявною історією.
  • Бот пропускає більшість повідомлень: перевірте слова-тригери, режим лише для модераторів, обмеження частоти та інструкцію моделі відповідати вибірково.
  • Текст з’являється, але звуку немає: переконайтеся, що сторінка, яка створює озвучення, відкрита й OBS захоплює її аудіо.
  • Бот не може публікувати: перевірте підтримку надсилання відповідей платформою, стан входу, дозволи облікового запису та обмеження частоти.

Додаткові матеріали: Налаштування озвучення, Локальне озвучення за допомогою ШІ, і Інтеграція ШІ через команди та API.
