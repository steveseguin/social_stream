Термопринтери та етикетки стріму

Перетворюйте покупки, донати й події чату на фізичні чеки, наліпки, квитки або етикетки видачі.

Що він може друкувати?

Окремий застосунок Windows може надсилати завдання без діалогу друку на встановлений у Windows принтер. Потік може поєднувати будь-які доступні значення, як-от ім’я глядача, донат, товар, повідомлення або лічильник, і керувати розміром та вирівнюванням тексту.

Правило сумісності: принтер має відображатися як робоча черга принтера Windows. Social Stream друкує через встановлений драйвер Windows; він не надсилає сирі команди ESC/POS, ZPL або SDK виробника.

Швидке налаштування

  1. Підключіть принтер через USB, увімкніть його й установіть драйвер Windows. Спочатку надрукуйте тестову сторінку Windows.
  2. У Social Stream відкрийте Загальні налаштування та інструменти → Керування принтером (Printer Control).
  3. Виберіть Знайти принтери і виберіть точну назву черги, показану Windows.
  4. Уведіть фізичну ширину паперу, зазвичай 58, 80, або 62 мм залежно від пристрою й матеріалу.
  5. Залиште Фіксована довжина етикетки на 0 для чека за розміром вмісту. Для висічених етикеток укажіть довжину в напрямку подавання в міліметрах.
  6. Виберіть Надрукувати тест вирівнювання. Якщо краю бракує, збільште безпечний відступ із цього боку й перевірте знову.

Стандартні безпечні відступи 2 мм зліва й справа підходять багатьом недорогим чековим принтерам 58 мм, але справжню область друку визначає драйвер. Залишайте Використовувати область друку (Use printable area) вибраним, якщо не перевірили інше налаштування.

Рулон чеків, безперервні наліпки чи висічені етикетки?

Рулон чеків

Найкраще для квитанцій покупок змінної довжини, талонів черги й чеків підтримки. Залиште фіксовану довжину 0, щоб довжину паперу визначав вміст.

Безперервний рулон наліпок

Підходить для клейких смужок з іменами й різним обсягом тексту. Поводиться як чековий папір, але принтер або драйвер має керувати розрізанням.

Друк етикетки донату через Event Flow

  1. Відкрийте Редактор потоків подій і створіть потік.
  2. Додайте Донат / чайові тригер. Установіть Мінімальна сума , якщо друкувати слід лише більші донати.
  3. Додайте Надрукувати термоетикетку (Print Thermal Label) з Integrations і підключіть до нього тригер.
  4. Установіть текст етикетки {username}, додайте новий рядок, потім {donation}. Виберіть розмір шрифту, насиченість, вирівнювання та кількість копій.
  5. Зазвичай залишайте перевизначення принтера й фіксованої довжини дії порожніми або 0, щоб застосовувалися глобальні налаштування Printer Control.
  6. Відкрити Перевірити потік (Test Flow), введіть назву, увімкніть Містить донат (Has Donation), введіть суму й запустіть перевірку. Це надсилає справжнє завдання друку в окремому застосунку.

Інші корисні заповнювачі: {message}, {source}, {donationAmount}, і {counterValue}. Значення, створені попередніми вузлами, також можна використовувати в шаблоні друку.

Покупця — жирним, товар — звичайним

Виберіть Weight → Selected text (**жирний**), а потім введіть:

**{username}**
{subtitle}

Використовуйте одинарні фігурні дужки. Нові торгові інтеграції розміщують назву товару в subtitle; кількість може бути доступна як {meta.commerce.quantity}. Якщо попередній вузол створює buyer, використовуйте **{buyer}** натомість. Shopify та eBay не надають особу покупця, тому використовуйте для цих джерел локальний лічильник замовлень або етикетку лише з товаром. Лише текст, обгорнутий у ** стає жирним; власний JavaScript або HTML не потрібен. Наявні етикетки All bold і Normal зберігають форматування.

Для продажів використовуйте Event Type зі purchase; Donation / Tip потребує hasDonation і не відповідатиме більшості продажів. Використовуйте gift або giftfunded , коли етикетка позначає завершений подарунок, і за потреби відфільтруйте постачальника. Додайте Counter перед дією друку, якщо потрібен один послідовний номер замовлення протягом стріму. Див. поля торгових подій.

Дія надає meta.thermalPrintResult.success і необов’язкову помилку/код для наступних кроків потоку. Успіх означає надсилання завдання, а не вихід паперу. Перевірте чергу Windows перед повтором непевного завдання, щоб уникнути дублікатів етикеток.

Counter нумерує покупки, а не унікальних покупців. Щоб використовувати один ID для всіх покупок того самого покупця, потрібні окреме зіставлення покупців з ID та явне скидання на початку кожного стріму. Поле reason у User Memory — описовий текст, а не спеціальний лічильник ID покупців.

Етикетки товарів Whatnot

Завантажити приклад потоку Whatnot. Він друкує покупця жирним, назву товару й ID замовлення, якщо наданий. Повідомлення про збій оплати друкує окрему ОПЛАТА НЕ ВДАЛАСЯ етикетку з відомостями, доступними в цьому повідомленні.

  1. В окремому застосунку налаштуйте Керування принтером (Printer Control) для свого принтера й розміру паперу та виконайте тест вирівнювання.
  2. Відкрийте Редактор потоків подій, виберіть Імпортуватиі виберіть завантажений JSON-файл.
  3. Виберіть Whatnot: етикетки товарів + попередження про оплату. Перевірте обидві дії друку; вони успадковують глобальний принтер і довжину етикетки.
  4. Увімкніть і збережіть потік. Залишайте джерело Whatnot відкритим із увімкненим захопленням подій стріму.

Приклад імпортується вимкненим. Він використовує Event Type (Advanced) → Custom Event для product_sold і payment_failed, із фільтром джерела Whatnot. Ставки й повідомлення про завершення аукціону не друкують етикеток.

Етикетка продажу не підтверджує оплату. Цей приклад друкує кожне повідомлення одразу після надходження; він не чекає оплати, не змінює попередню етикетку й не призначає номери покупцям. Відсутні поля друкуються порожніми. Повідомлення про збій без покупця, товару чи замовлення не може визначити попередню етикетку. Див. поля подій Whatnot.

Етикетки фіксованої довжини без сюрпризів

Етикетки 3 × 1 дюйм (зокрема для Munbyn BT320): використовуйте ширину 76,2 мм і фіксовану довжину 25,4 мм, коли сторона 1 дюйм є напрямком подавання. Узгодьте цей матеріал і орієнтацію у Windows Printing Preferences. Почніть із тексту 12–14 пт і перевірте довгі ім’я покупця та назву товару.

Бічні рамки тесту вирівнювання позначають безпечну ширину після застосування вибраної області друку й безпечних відступів. Висота рамки відповідає тестовому тексту; вона не окреслює всю етикетку й не торкається фізичних країв паперу.

  • Вимірюйте в напрямку подавання. Етикетка 62 × 29 мм зазвичай використовує папір завширшки 62 мм і фіксовану довжину етикетки 29 мм.
  • Узгодьте також Windows. Виберіть точний матеріал етикеток, орієнтацію, визначення проміжків/міток і поведінку різака в Printing Preferences драйвера принтера.
  • Фіксоване означає фіксоване. Social Stream не додає простір подавання чека до завдання фіксованої довжини. Зависокий вміст може обрізатися або переноситися залежно від драйвера.
  • Перевірте найдовші реалістичні дані. Довгим іменам глядачів, варіантам товарів, позначенням валюти й кільком рядкам потрібно більше місця або менший шрифт.
  • Обмеження драйвера все одно діють. Windows або драйвер принтера може обмежувати дуже короткі власні сторінки; Social Stream запитує мінімум 20 мм.

Ідеї для стріму

  • Друкуйте наліпки з іменами тих, хто підтримав, для стіни, реквізиту, карти або фізичної дошки прогресу.
  • Створюйте етикетки замовлень мерчу, творчих робіт, напоїв або видачі під час надходження покупок.
  • Друкуйте лотерейні квитки або талони участі в розіграші з обмеженням частоти й перевірками допуску перед дією друку.
  • Створюйте VIP-бейджі, призначення команд, жетони випробувань або етикетки досягнень донатів.
  • Друкуйте коротку чергу модерації або виконання замовлень для продюсера, який працює поруч зі стрімером.
Подумайте перед друком особистих даних. Уникайте адрес, електронної пошти, платіжних даних або приватних повідомлень. Термопапір також вицвітає від тепла, світла й часу, тому не підходить для архіву.

Поширені рішення

  • Жоден принтер не з’являється: переконайтеся, що Windows може надрукувати тестову сторінку, потім перезапустіть Social Stream і знову виберіть Find printers.
  • Завдання повідомляє про успіх, але нічого не друкується: відкрийте чергу Windows цього принтера й перевірте паузу, офлайн, папір, драйвер або помилки порту.
  • Край обрізано: залишайте Use printable area ввімкненим і збільште безпечний відступ із цього боку.
  • Забагато порожнього паперу: використовуйте фіксовану довжину 0 для чеків, зменште нижній відступ і подавання або задайте точну довжину для етикеток.
  • Одна етикетка стає двома: вміст вищий за фіксовану етикетку або Windows використовує неправильний розмір матеріалу. Зменште текст, шрифт, міжрядковий інтервал і відступи.
  • У Test Flow використовується неправильний принтер: виберіть перевизначення принтера у вузлі Print Thermal Label. Порожнє перевизначення використовує принтер Windows за замовчуванням під час перевірки безпосередньо в редакторі.
