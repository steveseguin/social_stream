테스트 메시지 만들기

가짜 메시지와 이벤트를 통제된 방식으로 Social Stream 세션에 보내세요.

이 도구의 역할

다음 항목: 테스트 메시지 만들기 페이지 는 가상 Social Stream 페이로드를 도크, 오버레이, 알림 또는 이벤트 흐름 설정으로 보냅니다. 실제 채팅 메시지, 후원, 멤버십, 레이드, 보상 또는 기타 이벤트를 기다리지 않고 시험할 수 있습니다.

가능하면 테스트 세션을 사용하세요. 제출한 메시지는 수신 세션 트래픽처럼 작동하며 알림, 소리, 웹훅, OBS 동작 또는 다른 자동화를 실행할 수 있습니다.

SSApp 또는 확장 프로그램 빠른 시작

  1. Social Stream Ninja를 열고 서비스가 활성화되어 있는지 확인하세요.
  2. 다음 항목 아래에서: 전체 설정 및 도구 → 동작 (Mechanics), 활성화하세요: 확장 프로그램 원격 API 제어를 활성화하세요. SSApp도 같은 설정 이름을 사용합니다.
  3. Social Stream 또는 다음에서 세션 ID를 복사하세요: session= 값을 도크 또는 오버레이 URL에서 복사하세요.
  4. 열기 테스트 메시지 만들기 (Create Test Message) 를 열고 해당 세션 ID를 입력하세요.
  5. 유지: 전송 경로 (Send Via) 설정값: 확장 프로그램 API 수신 (Extension API ingest) 를 일반 테스트에 사용하세요.
  6. 프리셋을 선택하고 필드를 조절한 뒤 다음을 선택하세요: 프리셋 불러오기 (Load Preset).
  7. 페이로드 JSON을 검토한 뒤 다음을 선택하세요: 제출 (Submit).
  8. 항목이 도크 또는 대상 오버레이에 나타나고 예상한 자동화가 실행되는지 확인하세요.

URL에 세션을 포함할 수 있습니다: createtestmessage.html?session=YOUR_SESSION_ID.

예제: 가짜 1,000 KICKs 메시지 하나

1,000 KICKs에 해당하는 Kick 방식 후원 메시지 하나를 만듭니다. 별도의 메시지 1,000개를 만들지는 않습니다.

  1. 선택할 항목: 채팅 메시지 (Chat Message) 프리셋입니다.
  2. 설정: 입력: 대상: Kick.
  3. 테스트 이름과 메시지를 입력하세요.
  4. 설정: 후원 금액 (Has Donation) 대상: 1000 KICKs.
  5. 선택: 입력란에서 JSON 업데이트 (Update JSON from Fields)를 선택하고 JSON을 확인한 뒤 제출하세요.

최소 페이로드:

{
  "type": "kick",
  "chatname": "Test Supporter",
  "chatmessage": "Thanks for the stream!",
  "hasDonation": "1000 KICKs"
}

사용: 채팅 메시지 (Chat Message) 를 이 예제에 사용하세요. 후원 / 응원 (Donation / Cheer) 프리셋에는 Twitch 전용 응원 필드가 포함됩니다.

프리셋 및 사용자 지정 JSON 사용

프리셋은 후원, 구독자, 구독 선물, 레이드, 보상, 시청자 수 업데이트, 첫 채팅 참여자, 트레인 이벤트 같은 일반적인 사례의 시작 페이로드를 제공합니다.

  • 프리셋 불러오기 (Load Preset) 는 JSON을 선택한 프리셋과 현재 입력란 값으로 교체합니다.
  • 입력란에서 JSON 업데이트 (Update JSON from Fields) 는 표시된 입력란으로 기본 메시지를 만듭니다.
  • 편집할 수 있는 항목: 페이로드 JSON (Payload JSON) 을 직접 편집하여 특정 필드나 이벤트 형식을 시험할 수 있습니다.
  • hasDonation 는 표시할 후원 금액을 담습니다. 예: 1000 KICKs 또는 $10.00.
  • 포함할 필드: event 는 실제로 이름이 지정된 이벤트를 시험할 때만 포함하세요. 일반 후원형 채팅 행에는 다음을 사용할 수 있습니다: hasDonation 만 단독으로 사용합니다.

필드 정의와 실제 플랫폼 예제는 다음을 참고하세요: 이벤트 참고 문서.

올바른 전달 모드 선택

채널 1로 직접 전송대상 도크를 다음으로 열었을 때: &server.대상이 일치하는 서버 채널을 수신하고 있어야 합니다.
채널 4로 직접 전송다음을 사용하는 대상 테스트: &server2을 사용하는 대상(호환 이벤트 페이지 포함)을 시험할 때.대상이 일치하는 서버 채널을 수신하고 있어야 합니다.

잘 모르겠다면 다음을 사용하세요: 확장 프로그램 API 수신 (Extension API ingest).

일반적인 해결 방법

  • 아무것도 나타나지 않음: 대상 페이지가 열려 있고 같은 세션 ID를 사용하는지 확인하세요.
  • 확장 프로그램 API 수신 실패: 활성화: 확장 프로그램 원격 API 제어를 확인한 뒤 도크나 오버레이를 다시 로드하고 재시도하세요.
  • 직접 모드에서 전송되었다고 하지만 아무것도 나타나지 않음: 대상 URL에 일치하는 다음 옵션이 없다면 확장 프로그램 API 수신을 사용하세요: &server 또는 &server2 모드입니다.
  • 잘못된 이벤트가 실행됨: 페이로드 JSON에 다른 프리셋의 필드가 남아 있는지 확인하세요.
  • Kick 테스트가 Twitch처럼 작동함: Chat Message 프리셋을 사용하고 다음을 설정하세요: type 그리고 hasDonation 를 위와 같이 설정하세요.
  • 자동화가 두 번 이상 실행됨: 같은 세션에 여러 도크, 동작 페이지 또는 이벤트 흐름 인스턴스가 열려 있는지 확인하세요.
