상품과 알림은 별개입니다

사용: 수익화 에서 공개 상품과 후원 페이지를 홍보하거나 활동을 수신하거나 둘 다 할 수 있습니다. 이 가이드는 Fourthwall, Ko-fi, Buy Me a Coffee를 다룹니다. NinjaBacker, Throne, Amazon, eBay는 다음을 참조하세요: 수익화 가이드.

알림 연결 · Fourthwall · Ko-fi · Buy Me a Coffee · 상품 가져오기 · OBS 및 QR 코드 · 문제 해결

활동 알림 연결

  1. 열기 Monetization → Fourthwall, Ko-fi & Buy Me a Coffee alerts 그리고 제공자를 선택하세요.
  2. 클릭: 수신기 설정. 기존의 다음 기능을 활성화하세요: 확장 프로그램 원격 API 제어 스위치를 활성화한 다음 SSN을 켜 두세요.
  3. Monetization으로 돌아가 다음을 클릭하세요: 웹훅 URL 복사. 이 비공개 주소를 아래의 제공자 웹훅 설정에 붙여넣으세요.
  4. 수신기 상태를 확인하세요. 수신기 연결됨 은 SSN이 수신 대기 중임을 뜻하며 제공자 설정을 검증했다는 뜻이 아닙니다. 마지막 이벤트 행은 파싱되었고 중복이 아닌 제공자 이벤트가 실행 중인 앱에 도달하면 업데이트되며 재시작 시 초기화됩니다.
  5. 사용: 샘플 알림 미리보기 로 별도 샘플 페이지에서 모양을 확인하세요. 이는 결제 전송, 총액 업데이트, Event Flow 실행 또는 웹훅 전송 검증을 수행하지 않습니다.

이 세 기존 세션 URL 엔드포인트는 URL을 비공개로 유지하는 데 의존합니다. SSN의 현재 설정은 해당 서명 비밀 키를 받지 않습니다. 방송 알림에 적합하지만 주문 이행을 위한 결제 증명은 아닙니다. 웹훅 주소를 공개하거나 시청자용 QR 목적지로 사용하지 마세요.

Fourthwall

  1. Fourthwall에서 다음을 여세요: Settings → For Developers → Webhooks.
  2. 웹훅을 만들고 SSN에서 복사한 Fourthwall URL을 붙여넣으세요.
  3. 필요한 지원 이벤트를 선택하세요: ORDER_PLACED, GIFT_PURCHASE, DONATION 그리고 SUBSCRIPTION_PURCHASED.
  4. 웹훅을 저장하고 SSN을 계속 실행하세요.

주문은 구매로, 상품 선물은 선물로, 새 구독은 멤버십으로 표시됩니다. 호환성을 위해 일반 Fourthwall 주문은 기존 후원 값을 계속 포함합니다. 기프트 카드 사용 주문은 선불 금액을 다시 더하지 않습니다. 테스트로 표시된 이벤트는 건너뜁니다.

Ko-fi

  1. 열기 Ko-fi Webhooks.
  2. SSN에서 복사한 Ko-fi URL을 다음에 붙여넣으세요: 웹훅 URL, 그런 다음 저장/업데이트하세요.
  3. SSN을 계속 실행하세요. 공개 팁, 멤버십 결제, 스토어 주문, 의뢰는 같은 연결을 사용합니다.

비공개 결제는 제외됩니다. 멤버십 결제는 멤버십 활동으로 표시되며 스토어 주문과 의뢰는 후원 총액에 더하지 않고 구매로 표시됩니다. Ko-fi는 이 웹훅으로 멤버십 취소 알림을 제공하지 않습니다.

테스트: 먼저 SSN의 격리된 샘플 미리보기를 사용하세요. Ko-fi 샘플 결제는 실제 결제와 비슷할 수 있으며 활성 수신기로 보내면 알림, 총액, 동작을 실행할 수 있습니다. 유료 보상이 활성화된 세션에서 제공자 테스트를 사용하지 마세요.

Buy Me a Coffee

  1. 열기 통합(Integrations) 을 크리에이터 대시보드에서 열고 다음을 선택하세요: 새 웹훅(New webhook).
  2. 이름을 지정하고 엔드포인트에 SSN Buy Me a Coffee URL을 붙여넣으세요.
  3. 선택: donation.created, extra_purchase.created, commission_order.created, wishlist_payment.created 그리고 membership.started 를 필요에 따라 사용하세요.
  4. 저장하고 전송을 활성화한 상태로 두세요. 실패 원인은 제공자의 이벤트 전송 기록에서 조사하세요.

스토어 및 의뢰 주문은 구매입니다. 위시리스트 결제는 선물 기여입니다. 멤버십 시작은 멤버십 알림이며 별도로 확인된 결제가 아닙니다. 숨긴 메모는 계속 숨겨지고 익명 후원자는 익명으로 유지됩니다. 대시보드 테스트 중 다음으로 표시된 것은: live_mode: false 유료 알림 없이 건너뜁니다. 환불 및 수명 주기 업데이트는 결제를 생성하거나 기존 총액을 되돌리지 않습니다.

Fourthwall 상품 가져오기

  1. Fourthwall의 Settings → For Developers, 다음을 만드세요: Storefront 토큰. 공개 카탈로그 접근에는 관리자 API 키 대신 Storefront 토큰을 사용하세요.
  2. SSN에서 다음을 여세요: Products & support links → Set up products and links → Import a Fourthwall product.
  3. 공개 상품 URL과 토큰을 붙여넣고 다음을 클릭하세요: 상품 세부 정보 불러오기.
  4. 불러온 이름, 이미지, 가격, 공개 URL을 검토하세요. 사용자 지정 도메인을 포함해 URL이 토큰과 같은 상점에 속하는지 확인하세요. 토큰에 따라 조회할 상점 카탈로그가 결정됩니다.
  5. 시청자가 할 행동에 맞춰 Shop, Gift, Support 또는 Join을 선택하세요. 클릭: 상품 또는 링크 추가, 상품 및 후원 링크를 활성화한 다음 설정 저장.

Fourthwall Storefront API를 통해 사용 가능한 공개 상품을 한 번에 하나씩 가져옵니다. 토큰은 해당 요청에 사용된 뒤 지워지며 저장되거나 오버레이로 전송되지 않습니다. 고정 결제 총액으로 오해하지 않도록 서로 다른 옵션 가격과 묶음 가격은 비워 둡니다. 가져오기는 현재 상태의 복사본이며 가격, 재고, 이미지는 자동으로 새로고침되지 않습니다. 변경되면 다시 가져오거나 수정하세요. 카탈로그에는 최대 20개 항목을 담을 수 있으며 다시 추가하면 새 항목이 생성됩니다.

상품, 공개 링크, QR 코드 표시

Shopify, Tiltify, Patreon 등 어떤 사이트의 공개 상품 또는 후원 링크든 수동으로 입력할 수도 있습니다. 이미지 URL과 선택적 가격을 추가하고 용도를 선택한 뒤 카탈로그를 활성화하고 저장하세요. 링크 추가만으로 결제 피드가 연결되지는 않습니다.

  1. 선택: 상품 및 후원 링크 — 선택 위치: 다음용 오버레이 링크:.
  2. 열기 오버레이 링크 옵션. 상품 쇼케이스, 후원 카드, 활동 알림 또는 통합 보기를 선택하세요.
  3. 클릭: OBS 링크 복사 그리고 OBS 브라우저 소스에 붙여넣으세요. 800 × 600으로 시작하세요. 홍보와 활동 레이어를 분리하려면 보기별로 소스를 만드세요.
  4. 표시 옵션으로 첫 상품을 고정하거나 항목을 순환하세요. 시청자가 공개 목적지를 스캔할 수 있도록 QR 코드를 활성화하세요. 사용: 공개 링크 복사 를 항목 옆에서 눌러 클릭 가능한 주소를 직접 채팅에 공유하세요.

쇼케이스는 이미지가 제공되면 상품 이미지를 포함하며 더 작은 후원 카드는 이미지를 숨깁니다. 활동 알림은 독립적으로 작동하고 관련 없는 순환 상품의 QR 코드를 붙이지 않습니다. 공개 링크를 읽을 수 있게 유지하고 최종 OBS 레이아웃을 보면서 휴대전화로 QR을 테스트하세요. OBS 링크의 배율을 바꾸거나 너무 좁게 자르면 스캔이 어려워질 수 있습니다.

Multi-Alerts나 활동 피드에는 같은 SSN 세션으로 기존 오버레이 링크를 사용하세요. 이 기존 활동 오버레이에는 상품 카탈로그를 활성화할 필요가 없습니다. 일반 Monetization 활동 보기에는 카탈로그 활성화가 필요합니다. Event Flow에서는 다음 필드가 있는 행에 계속 Donation 트리거를 사용합니다: hasDonation; 구매 또는 선물 완료에는 Event Type을 사용하세요. 참고: 이벤트 매핑.

아무것도 나타나지 않을 때

  • 수신기 꺼짐: 확장 프로그램 원격 API 제어를 활성화하세요. 다른 API 스위치는 다른 용도로 사용됩니다.
  • 연결 끊김: SSN을 켜 두고 네트워크 접근을 확인하세요. 이 상태는 공유 수신기 연결 상태이며 제공자 대시보드의 전송 상태가 아닙니다.
  • 이벤트를 받지 못함: 선택한 제공자, 비공개 URL, 제공자 전송 설정을 확인하세요. 로컬 미리보기 성공은 모양만 확인합니다.
  • 이벤트 건너뜀: 표시된 테스트, 비공개 결제, 지원되지 않는 이벤트 유형, 유효하지 않은 금액은 제외됩니다. 상태에는 구매자 정보를 표시하지 않습니다.
  • 이벤트는 받았지만 오버레이에 없음: 세션/비밀번호, 소스 필터, 이벤트 카테고리, SSN 규칙, OBS 표시 상태를 확인하세요. 구매는 구독이 아니며 대부분의 구매는 후원도 아닙니다.
  • 중복: 같은 결제를 직접 제공자와 통합 수집 서비스 양쪽으로 전달하지 마세요. 재시도 중복 제거에는 제공자의 전달 ID를 사용합니다.
  • 가져오기 실패: 상품 슬러그와 Storefront 토큰을 확인하고 상품이 공개되어 있으며 판매 가능한지 확인하세요. 수동 입력도 사용할 수 있습니다.

이는 생방송 활동이며 주문 장부가 아닙니다. 결제 확인, 환불, 주문 이행에는 제공자 대시보드를 사용하세요. 이제 Shopify에는 전용 상품 가져오기와 서명된 결제 완료 주문 설정이 있습니다. Tiltify 캠페인 활동과 Patreon 유료 멤버십은 향후 통합 예정입니다.
